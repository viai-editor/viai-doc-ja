                          複数のファイルを編集する


いくつファイルがあっても、Vim を離れずにそれらを編集できます。作業するファイル
のリストを定義し、あるファイルから別のファイルへジャンプします。あるファイルか
らテキストをコピーし、別のファイルに貼り付けます。

07.1  別のファイルを編集する

これまでは、編集したいファイルごとに Vim を起動しなければなりませんでした。もっ
と簡単な方法があります。別のファイルの編集を始めるには、このコマンドを使います:


        :edit foo.txt

"foo.txt" の代わりに任意のファイル名を使えます。Vim はカレントファイルを閉じ、
新しいファイルを開きます。しかし、カレントファイルに保存されていない変更がある
場合、Vim はエラーメッセージを表示し、新しいファイルを開きません:

        E37: No write since last change (use ! to override)

        Note:
        Vim は各エラーメッセージの先頭にエラー ID を付けます。メッセージ、また
        はその原因が理解できない場合、ヘルプシステムでこの ID を探してくださ
        い。この場合:

                :help E37

この時点で、いくつかの選択肢があります。このコマンドを使ってファイルを書き込め
ます:

        :write

または、強制 (!) 文字を使って、Vim にあなたの変更を破棄させて新しいファイルを
編集させることができます:

        :edit! foo.txt

別のファイルを編集したいが、カレントファイルの変更はまだ書き込みたくない場合、
それを隠すことができます:

        :hide edit foo.txt

変更されたテキストはまだそこにありますが、見えません。これはセクション 22.4:
バッファリスト でさらに説明されています。

07.2  ファイルのリスト

一連のファイルを編集するために Vim を起動できます。例えば:

        vim one.c two.c three.c

このコマンドは Vim を起動し、3 つのファイルを編集することを Vim に伝えます。
Vim は最初のファイルだけを表示します。このファイルであなたのやることを済ませた
後、次のファイルを編集するには、このコマンドを使います:

        :next

カレントファイルに保存されていない変更がある場合、エラーメッセージが表示され、
":next" は動作しません。これは前のセクションで述べた ":edit" と同じ問題です。
変更を破棄するには:

        :next!

しかし、たいていは変更を保存して次のファイルに移りたいでしょう。このための特別
なコマンドがあります:

        :wnext

これは 2 つの別々のコマンドを使うのと同じことをします:

        :write
        :next


私はどこにいるのか?

引数リストのどのファイルを編集しているかを知るには、ウィンドウのタイトルを見て
ください。"(2 of 3)" のようなものが表示されているはずです。これは、3 つのファ
イルのうち 2 番目のファイルを編集していることを意味します。
   ファイルのリストを見たい場合、このコマンドを使います:

        :args

これは "arguments" の短縮形です。出力はこのようになるかもしれません:

        one.c [two.c] three.c

これらは Vim を起動したときのファイルです。現在編集しているもの、"two.c" は角
括弧で囲まれています。


他の引数に移動する

1 つ前のファイルに戻るには:

        :previous

これは ":next" コマンドとまったく同じですが、逆方向に移動する点が異なります。
ここでも、先にファイルを書き込みたいときのためのショートカットコマンドがありま
す:

        :wprevious

リストの一番最後のファイルに移動するには:

        :last

そして、再び最初のファイルに戻るには:

        :first

ただし、":wlast" または ":wfirst" コマンドはありません!

":next" および ":previous" にはカウントを使えます。2 つ先のファイルにスキップ
するには:

        :2next


自動書き込み

ファイル間を移動して変更を加えるときは、":write" を使うことを覚えておかなけれ
ばなりません。そうしないと、エラーメッセージが表示されます。変更されたファイル
を常に書き込みたいと確信している場合、自動的に書き込むように Vim に指示できま
す:

        :set autowrite

書き込みたくないかもしれないファイルを編集しているときは、それを再びオフにして
ください:

        :set noautowrite


別のファイルのリストを編集する

Vim を終了して再び起動する必要なしに、ファイルのリストを再定義できます。他の 3
つのファイルを編集するには、このコマンドを使います:

        :args five.c six.c seven.h

または、シェルで使われるようにワイルドカードを使います:

        :args *.txt

Vim はリストの最初のファイルに移動します。ここでも、カレントファイルに変更があ
る場合、まずファイルを書き込むか、または変更を破棄するために ":args!" (! を付
加) を使うことができます。


最後のファイルを編集しましたか?
                                                        arglist-quit
ファイルのリストを使うとき、Vim はそれらすべてを編集したいと仮定します。早すぎ
る終了から保護するために、リストの最後のファイルをまだ編集していないときは、こ
のエラーが表示されます:

        E173: 46 more files to edit

本当に終了したい場合、もう一度終了するだけです。そうすると動作します (ただし、
間に他のコマンドを実行したときは動作しません)。

07.3  ファイルからファイルへジャンプする

2 つのファイル間を素早くジャンプするには、CTRL-^ を押します (英語-US キーボー
ドでは ^ は 6 キーの上にあります)。例:

        :args one.c two.c three.c

これで one.c にいます。

        :next

これで two.c にいます。ここで CTRL-^ を使って one.c に戻ります。もう 1 回
CTRL-^ で two.c に戻ります。もう 1 回 CTRL-^ で再び one.c にいます。ここでこう
した場合:

        :next

three.c にいます。CTRL-^ コマンドは、ファイルのリスト内でどこにいるかという認
識を変えないことに注意してください。":next" および ":previous" のようなコマン
ドだけがそれを行います。

以前に編集していたファイルは "代替" ファイルと呼ばれます。Vim を起動したばかり
のときは、以前のファイルがないので CTRL-^ は動作しません。


定義済みのマーク

別のファイルにジャンプした後、とても便利な 2 つの定義済みのマークを使えます:

        `"

これは、ファイルを離れたときにカーソルがあった位置に移動します。記憶されている
もう 1 つのマークは、最後に変更を加えた位置です:

        `.

ファイル "one.txt" を編集しているとします。ファイルの途中のどこかで、"x" を使っ
て 1 文字削除します。それから "G" で最後の行に行き、":w" でファイルを書き込み
ます。他のいくつかのファイルを編集し、それから ":edit one.txt" を使って
"one.txt" に戻ってきます。ここで `" を使った場合、Vim はファイルの最後の行に
ジャンプします。`. を使うと、文字を削除した位置に移動します。ファイル内を移動
しても、`" および `. は記憶された位置に連れていってくれます。少なくとも、別の
変更を加えるか、またはファイルを離れるまでは。


ファイルマーク

セクション 03.10 では、"mx" でファイルにマークを置き、"`x" でその位置にジャ
ンプする方法が説明されました。それは 1 つのファイル内で機能します。別のファイ
ルを編集してそこにマークを置いた場合、それらはそのファイルに固有です。したがっ
て、各ファイルは独自のマークのセットを持ち、それらはファイルにローカルです。
   これまでは小文字のマークを使っていました。大文字のマークもあります。これら
はグローバルで、どのファイルからでも使えます。例えば、ファイル "foo.txt" を編
集しているとします。ファイルの半分 ("50%") まで行き、そこに F マークを置きます
(foo の F):

        50%mF

ここでファイル "bar.txt" を編集し、その最後の行に B マーク (bar の B) を置きま
す:

        GmB

これで "'F" コマンドを使って foo.txt の半分のところに戻ることができます。また
は、さらに別のファイルを編集し、"'B" とタイプすると、再び bar.txt の最後にいま
す。

ファイルマークは、どこか他の場所に置かれるまで記憶されます。したがって、マーク
を置いて、何時間も編集をしても、まだそのマークに戻ってジャンプできます。
   マークの文字と、それが置かれる場所の間に、単純な関連を考えると便利なことが
よくあります。例えば、ヘッダーファイルでは H マーク、Makefile では M、および C
コードファイルでは C を使います。

特定のマークがどこにあるかを見るには、":marks" コマンドに引数を与えます:

        :marks M

いくつかの引数を与えることもできます:

        :marks MCP

CTRL-O および CTRL-I を使って、そこにマークを置かなくても、より古い位置および
より新しい位置にジャンプできることを忘れないでください。

07.4  バックアップファイル

通常、Vim はバックアップファイルを作成しません。作成したい場合は、以下のコマン
ドを実行するだけです:

        :set backup

バックアップファイルの名前は、元のファイルの末尾に  ~  を付加したものです。例
えば、あなたのファイルの名前が data.txt の場合、バックアップファイルの名前は
data.txt~ です。
   バックアップファイルが ~ で終わるという事実が気に入らない場合、拡張子を変更
できます:

        :set backupext=.bak

これは data.txt~ の代わりに data.txt.bak を使います。
   ここで重要なもう 1 つのオプションは 'backupdir' です。これはバックアップファ
イルが書き込まれる場所を指定します。バックアップを元のファイルと同じディレクト
リに書き込むという既定値は、たいていは正しいでしょう。

        Note:
        'backup' オプションが設定されていなくても 'writebackup' が設定されてい
        る場合、Vim はそれでもバックアップファイルを作成します。しかし、ファイ
        ルの書き込みが正常に完了するとすぐに、それは削除されます。これは、書き
        込みが何らかの理由で失敗したときにあなたの元のファイルを失わないための
        安全策として機能します (ディスクがいっぱいになるのが最も一般的な原因で
        す; 雷に打たれるのも、それほど一般的ではありませんが、別の原因かもしれ
        ません)。


元のファイルを保持する

ソースファイルを編集している場合、何か変更を加える前のファイルを保持したいかも
しれません。しかし、バックアップファイルはファイルを書き込むたびに上書きされま
す。したがって、それには最初のバージョンではなく、直前のバージョンだけが含まれ
ます。
   Vim に元のファイルを保持させるには、'patchmode' オプションを設定します。こ
れは、変更されたファイルの最初のバックアップに使われる拡張子を指定します。通常
は、このようにします:

        :set patchmode=.orig

ここで初めてファイル data.txt を編集し、変更を加えてファイルを書き込むと、Vim
は変更されていないファイルのコピーを "data.txt.orig" という名前で保持します。
   ファイルにさらに変更を加えた場合、Vim は "data.txt.orig" がすでに存在するこ
とに気付き、それをそのままにします。それ以降のバックアップファイルは、
"data.txt~" (または 'backupext' で指定したもの) と呼ばれます。
   'patchmode' を空のままにした場合 (それが既定です)、元のファイルは保持されま
せん。

07.5  ファイル間でテキストをコピーする

ここでは、あるファイルから別のファイルへテキストをコピーする方法を説明します。
簡単な例から始めましょう。コピーしたいテキストを含むファイルを編集します。カー
ソルをテキストの先頭に移動して "v" を押します。これでビジュアルモードが開始さ
れます。ここでカーソルをテキストの末尾に移動して "y" を押します。これで選択さ
れたテキストがヤンク (コピー) されます。
   上の段落をコピーするには、こうします:

        :edit thisfile
        /This
        vjjjj$y

ここで、テキストを貼り付けたいファイルを編集します。その後ろにテキストを表示さ
せたい文字にカーソルを移動します。"p" を使ってテキストをそこに貼り付けます。
        :edit otherfile
        /There
        p

もちろん、テキストをヤンクするのに他の多くのコマンドを使えます。例えば、行全体
を選択するには "V" でビジュアルモードを開始します。または、CTRL-V を使って矩形
ブロックを選択します。または、"Y" を使って 1 行をヤンクする、"yaw" を使って
yank-a-word する、など。
   "p" コマンドはカーソルの後にテキストを貼り付けます。カーソルの前にテキスト
を貼り付けるには "P" を使います。Vim は、行全体をヤンクしたのか、またはブロッ
クをヤンクしたのかを記憶していて、そのとおりに貼り付けることに注意してくださ
い。


レジスタを使う

あるファイルから別のファイルへ複数のテキスト片をコピーしたいとき、ファイル間を
切り替えて対象ファイルを書き込まなければならないのは、多くの時間がかかります。
これを避けるには、各テキスト片をそれぞれ専用のレジスタにコピーします。
   レジスタは、Vim がテキストを格納する場所です。ここでは a から z という名前
のレジスタを使います (他にもあることが後でわかるでしょう)。文を f レジスタ
(First の f) にコピーしましょう:

        "fyas

"yas" コマンドは以前と同様に文をヤンクします。テキストを f レジスタに置くべき
ことを Vim に伝えるのは "f です。これはヤンクコマンドの直前に来なければなりま
せん。
   次に、3 行全体を l レジスタ (line の l) にヤンクします:

        "l3Y

カウントは "l の前に置いても同じです。テキストのブロックを b (block の b) レジ
スタにヤンクするには:

        CTRL-Vjjww"by

レジスタ指定 "b は "y" コマンドの直前にあることに注意してください。これは必須
です。"w" コマンドの前に置いていた場合、動作しなかったでしょう。
   これで f、l、および b レジスタに 3 つのテキスト片があります。別のファイルを
編集し、移動して、望む場所にテキストを置きます:

        "fp

ここでも、レジスタ指定 "f は "p" コマンドの前に来ます。
   レジスタは任意の順序で貼り付けることができます。そして、テキストは何か他の
ものをヤンクするまでレジスタに残ります。したがって、好きなだけ何回でも貼り付け
ることができます。

テキストを削除するときも、レジスタを指定できます。これを使って複数のテキスト片
を移動します。例えば、delete-a-word して、それを w レジスタに書き込むには:

        "wdaw

ここでも、レジスタ指定は削除コマンド "d" の前に来ます。


ファイルに追加する

テキストの行を 1 つのファイルに集めるとき、このコマンドを使えます:

        :write >> logfile

これは、カレントファイルのテキストを "logfile" の末尾に書き込みます。したがっ
て、それは追加されます。これにより、行をコピーし、ログファイルを編集して、そこ
に貼り付けなければならないことが避けられます。したがって、2 つの手順を省けま
す。しかし、ファイルの末尾にしか追加できません。
   数行だけを追加するには、":write" とタイプする前にビジュアルモードでそれらを
選択します。第 10 章では、行の範囲を選択する他の方法を学びます。

07.6  ファイルを閲覧する

ときどき、書き戻すつもりはまったくなく、ファイルに何が含まれているかを見たいだ
けのことがあります。考えずに ":w" とタイプして、結局元のファイルを上書きしてし
まう危険があります。これを避けるには、ファイルを読み込み専用で編集します。
   Vim を読み込み専用モードで起動するには、このコマンドを使います:

        vim -R file

Unix では、このコマンドも同じことをするはずです:

        view file

これで "file" を読み込み専用モードで編集しています。":w" を使おうとすると、エ
ラーメッセージが表示され、ファイルは書き込まれません。
   ファイルに変更を加えようとすると、Vim は警告を出します:

        W10: Warning: Changing a readonly file

ただし、変更は行われます。これにより、例えば、ファイルを読みやすくするために整
形することができます。
   ファイルに変更を加え、それが読み込み専用だったことを忘れていた場合でも、書
き込むことができます。書き込みを強制するには、書き込みコマンドに ! を付けます。

ファイルへの変更を本当に禁止したい場合、こうします:

        vim -M file

これで、テキストを変更しようとする試みはすべて失敗します。例えば、ヘルプファイ
ルはこのようになっています。変更しようとした場合、このエラーメッセージが表示さ
れます:

        E21: Cannot make changes, 'modifiable' is off

-M 引数を使って、Vim をビューアーモードで動作するように設定できます。ただし、
これらのコマンドは保護を解除するので、これは任意のものにすぎません:

        :set modifiable
        :set write

07.7  ファイル名を変更する

新しいファイルの編集を始める賢い方法は、必要なもののほとんどを含んでいる既存の
ファイルを使うことです。例えば、ファイルを移動する新しいプログラムを書き始める
とします。ファイルをコピーするプログラムがすでにあることがわかっているので、こ
う始めます:

        :edit copy.c

不要なものは削除できます。ここで、ファイルを新しい名前で保存する必要がありま
す。これには ":saveas" コマンドを使えます:

        :saveas move.c

Vim はファイルを指定された名前で書き込み、そのファイルを編集します。したがっ
て、次に ":write" を実行すると、"move.c" に書き込みます。"copy.c" は変更されな
いままです。
   編集しているファイルの名前を変更したいが、ファイルは書き込みたくないときは、
このコマンドを使えます:

        :file move.c

Vim はファイルに "not edited" という印を付けます。これは、これが編集を始めた
ファイルではないことを Vim が知っていることを意味します。ファイルを書き込もう
とすると、このメッセージが表示されるかもしれません:

        E13: File exists (use ! to override)

これは、誤って別のファイルを上書きすることから保護します。
