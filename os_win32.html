                                                win32 Win32 MS-Windows
このファイルは、Vim の Win32 版の特異な点を説明する。

Vim の Win32 版は Windows 7、8、10、および 11 で動作する。コンソール版および
GUI 版の両方がある。

Windows XP または Vista を持っている場合は、patch レベル 495 までの Vim 9.0 を
使える。

32 ビット版は 64 ビットの MS-Windows システムでも動作する。

1. 既知の問題                                           win32-problems

ファイル名補完を行う時、Vim は短いファイル名に対する一致も見つける。しかし、
Vim はそれでも対応する長いファイル名を見つけて使う。例えば、短いファイル名
"this_i~1" を持つ長いファイル名 "this_is_a_test" がある場合、コマンド ":e *1"
は "this_is_a_test" の編集を開始する。

2. 起動                                                 win32-startup

カレントディレクトリ                                    win32-curdir

Vim が単一のファイル名引数で起動され、それがフルパス ("x:\" で始まる) を持つ場
合、Vim はファイルエクスプローラーから起動されたとみなし、カレントディレクトリ
をそのファイルのある場所に設定する。Vim を起動するコマンドを入力する時にこれを
避けるには、バックスラッシュの代わりにスラッシュを使うこと。例:

        vim c:\text\files\foo.txt

"C:\text\files" ディレクトリに移動する。

        vim c:/text\files\foo.txt

カレントディレクトリを使う。


term オプション                                         win32-term

Vim の Win32 版が理解する端末タイプの種類は、組み込みである "win32" だけであ
る。'term' を他の何かに設定すると、おそらく Vim から非常に奇妙な動作が得られ
る。したがって、Vim は 'term' のデフォルト値を環境変数 "TERM" から取得しない。

端末色                                                  win32-term-colors

Win32 コンソールはデフォルトで 16 色をサポートする dos-colors。Windows 10
バージョン 1703 (Creators Update) 以降、'termguicolors' が設定され、かつ Vim
が Virtual Terminal Processing (VTP) +vtp のサポート付きでビルドされている場
合、コンソールは 256 色および true color (24 ビット) をサポートする。

'termguicolors' オプションが設定されているか、または 't_Co' オプションが 256
に設定されている場合、Virtual Terminal Processing は自動的に有効になる。これは
色のための ANSI エスケープシーケンスを有効にし、マルチバイト文字の描画を改善
し、Windows コンソールでその他の端末機能を有効にする。

実際の色の描画は、端末が VTP をサポートしているかどうか (Windows Terminal また
は最新の Windows 10/11 コンソールなど) による。

$PATH                                                   win32-PATH

Vim の実行可能ファイルのディレクトリが $PATH に追加される。これは主に、Tools
メニューにある "!xxd" を動作させるためである。そしてそれは、executable() が 1
を返した時にその実行可能ファイルを実際に実行できることも意味する。

コマンドライン引数                                      win32-cmdargs

コマンドラインをパラメーターに解析することは、MS-Windows では標準化されていな
い。Vim および gvim は、かつて (7.4.432 より前) それを解析するために異なるロ
ジックを使っており、そのロジックは何でコンパイルされたかにも依存していた。現
在、Vim および gvim はどちらも CommandLineToArgvW() Win32 API を使っているの
で、同じように動作する。

基本的なルールは:                                       win32-backslashes
      a) パラメーターは図形文字の並びである。
      b) パラメーターは空白で区切られる。
      c) 空白を含めるために、パラメーターをダブルクォートで囲むことができる。
      d) 0 個以上のバックスラッシュ (\) およびダブルクォート (") の並びは特別
        である。有効なバックスラッシュの数は半分にされ、切り捨てられる。偶数個
        のバックスラッシュはスペースおよびタブの受理を反転させ、奇数個のバック
        スラッシュはリテラルのダブルクォートを生成する。

つまり:
        "       特別なダブルクォートである
        \"      リテラルのダブルクォートである
        \\"     リテラルのバックスラッシュおよび特別なダブルクォートである
        \\\"    リテラルのバックスラッシュおよびリテラルのダブルクォートである
        \\\\"   2 つのリテラルのバックスラッシュおよび特別なダブルクォートである
        \\\\\"  2 つのリテラルのバックスラッシュおよびリテラルのダブルクォートである
        など

例:
        vim "C:\My Music\freude" +"set ignorecase" +/"\"foo\\" +\"bar\\\"

は "C:\My Music\freude" を開き、行モードコマンドを実行する:
        set ignorecase; /"foo\ and /bar\"

これらのルールは CommandLineToArgvW API のリファレンスにも記述されている:
    https://msdn.microsoft.com/en-us/library/windows/desktop/bb776391.aspx

                                                        win32-quotes
クォートには追加のルールがある (それらはよく文書化されていない)。
上記のとおり、ファイル名 (または他のコマンドライン引数) の中のクォートはバック
スラッシュでエスケープできる。例えば
        vim -c "echo 'foo\"bar'"

あるいは、1 つを得るために 3 つのクォートを使う:
        vim -c "echo 'foo"""bar'"

クォートのルールは:

1. " はクォートを開始する。
2. 別の " または "" はクォートを終了する。クォートが "" で終わる場合は、
   クォートされた文字列の終わりに " が生成される。

例、引数を [] で囲んで:
        "foo"           -> [foo]
        "foo""          -> [foo"]
        "foo"bar        -> [foobar]
        "foo" bar       -> [foo], [bar]
        "foo""bar       -> [foo"bar]
        "foo"" bar      -> [foo"], [bar]
        "foo"""bar"     -> [foo"bar]

3. 画面内容の復元                                       win32-restore

'restorescreen' が設定されている (これがデフォルト) 場合、Vim は終了する時、ま
たは外部コマンドを実行する時に、コンソールの元の内容を復元する。これを望まない
場合は、":set nors" を使うこと。        'restorescreen'

4. マウスの使用                                         win32-mouse

Vim の Win32 版はマウスの使用をサポートする。2 ボタンマウスを持っている場合、
左および右のボタンを同時に押すことで中ボタンをエミュレートできる - ただし、
Win32 GUI で右マウスボタンのポップアップメニューが有効になっている ('mouse' を
参照) 場合は、左ボタンを先に押すように心がけるべきであることに注意。
                                                mouse-using

マウスが動作しない時は、コンソールの "Quick Edit Mode" 機能を無効にしてみるこ
と。

7. インストールパッケージ                               win32-installer

windows 用のインストーラのナイトリービルドは次の場所で入手できる
https://github.com/viai-editor/viai-win32-installer/releases/

ナイトリービルドは 32bit および 64bit のビルドを含み、ほとんどの機能が有効に
なっていて、そして通常は、Windows が文句を言わないように、暗号署名された追加の
インストーラも含んでいる。

インストーラを使うには、単に exe ファイルを実行する。例えば、
"gviai_1.0.0033_x64.exe"。以下のスイッチもサポートされている:

    {installer} /S            -> ダイアログ無しのサイレントインストール
    {installer} /D=C:\viai    -> ディレクトリ c:\viai にインストール
                              -> /D は最後の引数でなければならない
    {installer} /S /D=c:\viai -> c:\viai へのサイレントインストール

デフォルトのインストールディレクトリは、代わりに $VIM 環境変数を設定することで
与えることもできる。

8. Win32 ミニ FAQ                                       win32-faq

Q. フォントを変更するには?
A. GUI 版では、'guifont' オプションを使える。例:
        :set guifont=Lucida_Console:h15:cDEFAULT
   コンソール版では、コンソール自体のフォントを設定する必要がある。これは Vim
   の中からは行えない。

Q. Windows NT でデッドキーを入力するには?
A. デッドキーは NT 3.51 で動作する。単に他のアプリケーションと同じように入力す
   ること。
   NT 4.0 では、デフォルトのロケール (コントロールパネルのキーボードの部分で設
   定する) が現在アクティブなロケールと同じであることを確認する必要がある。そ
   うでないと、NT のコードが混乱してクラッシュする! これは NT 4.0 の問題であ
   り、実際には Vim の問題ではない。

Q. Unix NFS ファイルサーバー上のシンボリックリンクされたファイルを Vim で編集
   している。ファイルを書き込む時、Vim はシンボリックリンクを "通して書き込む"
   ことをしない。代わりに、シンボリックリンクを削除し、その場所に新しいファイ
   ルを作成する。なぜか?
A. Unix では、Vim はリンク (シンボリックまたはハード) に対応している。元のファ
   イルのバックアップコピーが作られ、それから元のファイルが上書きされる。これ
   により、ファイルのすべての属性が同じままであることが保証される。非 Unix シ
   ステムでは、元のファイルの名前が変更され、新しいファイルが書き込まれる。保
   護ビットだけが元のファイルと同じように設定される。しかし、これはリンクおよ
   びその他のものが存在する NFS マウントされたファイルシステム上で作業する時は
   正しく動作しない。現在のバージョンでこれを修正する唯一の方法は、
   ":set nobackup nowritebackup" によってバックアップファイルを作らないことで
   ある     'writebackup'

Q. Samba を通して Unix ファイルサーバー上のファイルを Vim で編集している。ファ
   イルを書き込むと、ファイルの所有者が変更される。なぜか?
A. ファイルを書き込む時、Vim は元のファイルの名前を変更し、これはバックアップ
   である (ファイルの書き込みが途中で失敗した場合のため)。それから、ファイルは
   新しいファイルとして書き込まれる。そして、Samba はそれにファイルシステムの
   デフォルトの所有者を与え、それは元の所有者と異なることがある。
   これを避けるには、'backupcopy' オプションを "yes" に設定すること。そうする
   と、Vim はバックアップのためにファイルのコピーを作り、元のファイルを上書き
   する。その場合、所有者は変更されない。

Q. ":make" の実行中にその出力を見るには?
A. 基本的に必要なのは、その入力 (make からの出力) を stdout およびエラーファイ
   ルの両方にコピーする tee プログラムを置くことである。tee (およびその他多数
   の GNU ツール) のコピーは次の場所で見つけられる
   http://gnuwin32.sourceforge.net または http://unxutils.sourceforge.net
   あるいは、次の場所にある GNU ツールのより新しい Cygnus 版を試すこと
   http://www.cygwin.com
   tee のコピーを実際に手に入れたら、次を
        :set shellpipe=\|\ tee
   _vimrc に追加する必要がある。

Q. VisionFS で動作するリモートマシンにファイルを保存していると、ファイルが消え
   る!
A. VisionFS は、ある種のドット (.) 3 文字拡張子のファイル名を扱えない。SCO は、
   この動作は 16bit DOS/Windows 環境との後方互換性のために必要であると宣言して
   いる。以下の 2 つのコマンドがこの動作を実演する:

        echo Hello > file.bat~
        dir > file.bat

   結果として、"dir" コマンドは、新しい "file.bat" ファイルを作成する代わりに
   "file.bat~" ファイルを更新する。"foo.bat" という名前の既存のファイルを編集
   する時、Vim でもこれと同じ動作が示される。なぜなら、Vim のデフォルトの動作
   は、名前に '~' 文字を付け加えた一時ファイルを作成することだからである。ファ
   イルが書き込まれると、それは結局削除されることになる。

   解決策: このコマンドを _vimrc ファイルに追加する:
        :set backupext=.temporary

Q. カーソルの点滅速度を変更するには?
A. できない! これは NT コンソールの制限である。NT 5.0 では、すべてのコンソール
   ウィンドウの点滅速度を同時に設定できると報告されている。

                                                        :!start
Q. 外部コマンドまたはプログラムを非同期に実行するか、またはドキュメントまたは
   URL をそのデフォルトのプログラムで開くには?
A. :! を使って外部コマンドを実行する時、"start" 付きで実行できる。例えば、
   notepad を実行するには:
        :!start notepad
    デフォルトの画像ビューアで "image.jpg" を開くには:
        :!start image.jpg
    Windows エクスプローラーで現在のファイルのフォルダを開くには:
        :!start %:h
    デフォルトのブラウザーで Vim のホームページを開くには:
        :!start http://www.vim.org/

   "start" を使うと、Vim は別の画面への切り替え、新しいコンソールのオープン、
   またはプログラムの完了の待機をしなくなる。それは、編集中のファイルに影響し
   ないプログラムを実行していることを示す。:!start で開始されたプログラムには
   Vim の開いているファイルハンドルが渡されないので、それらは Vim より前に閉じ
   る必要が無い。
   この特別な扱いを避けるには、":! start" を使うこと。
   2 つのオプション引数がある (次の Q を参照):
       /min  ウィンドウが最小化される
       /b    コンソールウィンドウが開かれない
   これらのフラグは同時に 1 つしか使えない。2 つ目のものはコマンドの開始として
   扱われる。
                                                windows-asynchronously
Q. 非同期に実行するプログラムのウィンドウが表示されるのを避けるには?
A. 望むことに応じて、3 つの可能な解決策がある:
   1) /min フラグを使って、他の変更なしにプログラムを最小化状態で実行できる。
      これはコンソールおよび GUI アプリケーションで同様に動作する。
   2) /b フラグを使って、コンソールアプリケーションを、そのためのコンソールウィ
      ンドウを作成せずに実行できる (GUI アプリケーションは影響を受けない)。し
      かし、このフラグは、実行するアプリケーションが入力を何も必要としない場合
      にのみ使うべきである。そうでないと、その入力ストリーム (stdin) が
      \\.\NUL にリダイレクトされる (stdout および stderr も) ので、EOF エラー
      が発生する。
   3) 'guioptions' オプションの '!' フラグを設定する 'go-!'。これにより、Vim
      は "start" コマンドを Vim の端末ウィンドウ内で実行し、コンソールウィンド
      ウを開かなくなる。

   コンソールアプリケーションの例、Exuberant ctags を実行する:
        :!start /min ctags -R .
    完了すると、カレントディレクトリに "tags" という名前のファイルが見えるはず
   である。タスクバーでウィンドウタイトルが点滅するのに気づくはずである。これ
   は時間が長くかかるコマンドの方がより目立つ。
   次に、"tags" ファイルを削除して、このコマンドを実行する:
        :!start /b ctags -R .
    同じ "tags" ファイルができるはずだが、今回はタスクバーでの点滅は無い。
   GUI アプリケーションの例:
        :!start /min notepad
        :!start /b notepad
    最初のコマンドは notepad を最小化して実行し、2 つ目のものはそれを通常どお
   り実行する。

                                                windows-icon
Q. ViAI のアイコンが気に入らない。変更できるか?
A. はい、'runtimepath' のディレクトリ内の bitmaps/viai.ico にお気に入りのアイ
   コンを置くこと。例えば ~/vimfiles/bitmaps/viai.ico。


 vim:tw=78:ts=8:noet:ft=help:norl:
