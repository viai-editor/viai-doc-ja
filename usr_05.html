                              設定を行う

なる値に設定された状態で Vim を起動させる方法を示します。Vim の機能を拡張する
ためにプラグインを追加します。または、あなた自身のマクロを定義します。

05.1  vimrc ファイル                                  vimrc-intro

あなたはおそらく、とてもよく使うコマンドをタイプすることに疲れたでしょう。あな
たのお気に入りのオプション設定およびマッピングをすべて使って Vim を起動するに
は、それらを vimrc ファイルと呼ばれるものに書きます。Vim は起動するときにこの
ファイル内のコマンドを実行します。

すでに vimrc ファイルがある場合 (例えば、あなたのシステム管理者があなたのため
にそれを用意しているとき)、この方法でそれを編集できます:

        :edit $MYVIMRC

まだ vimrc ファイルがない場合、vimrc ファイルをどこに作成できるかを調べるには
vimrc を参照してください。また、":version" コマンドは、Vim が探す
"user vimrc file" の名前を挙げます。

Unix および Macintosh では、このファイルが常に使われ、推奨されます:

        ~/.vimrc

MS-Windows では、これらのうちの 1 つを使えます:

        $HOME/_vimrc
        $VIM/_vimrc

初めて vimrc ファイルを作成する場合、一番上にこの行を置くことが推奨されます:

        source $VIMRUNTIME/defaults.vim

これは、新しいユーザー (伝統的な Vi ユーザーとは対照的に) のために Vim を初期
化します。詳細については defaults.vim を参照してください。

vimrc ファイルには、コロンの後にタイプするすべてのコマンドを含めることができま
す。最も単純なものは、オプションを設定するためのものです。例えば、Vim を常に
'incsearch' オプションがオンの状態で起動させたい場合、この行をあなたの vimrc
ファイルに追加します:

        set incsearch

この新しい行を有効にするには、Vim を終了して再び起動する必要があります。後で、
Vim を終了せずにこれを行う方法を学びます。

この章では、最も基本的な項目だけを説明します。Vim script ファイルの書き方につ
いてのさらなる情報: usr_41.txt。

05.2  vimrc ファイルの例の解説                        vimrc_example.vim

最初の章で、vimrc (Vim の配布物に含まれている) ファイルの例を使って Vim を非互
換モードで起動させる方法が説明されました (not-compatible を参照)。このファイ
ルはここで見つけられます:

        $VIMRUNTIME/vimrc_example.vim

この節では、このファイルで使われているさまざまなコマンドを説明します。これによ
り、あなた自身の好みを設定する方法についてのヒントが得られます。とはいえ、すべ
てが説明されるわけではありません。さらに調べるには ":help" コマンドを使ってく
ださい。


        " ほとんどのユーザーが望む既定値を得る。
        source $VIMRUNTIME/defaults.vim

これは、$VIMRUNTIME ディレクトリ内の "defaults.vim" ファイルを読み込みます。こ
れは、ほとんどのユーザーが好むように Vim を設定します。あなたがそうではない少
数の一人である場合、この行をコメントアウトしてください。コマンドは以下で説明さ
れています: defaults.vim-explained


        if has("vms")
          set nobackup
        else
          set backup
          if has('persistent_undo')
            set undofile
          endif
        endif

これは、ファイルを上書きするときにそのバックアップコピーを保持するよう Vim に
指示します。しかし、すでにファイルの古いバージョンを保持しているので、VMS シス
テム上ではそうではありません。バックアップファイルは、元のファイルと同じ名前に
"~" を付け加えたものになります。07.4 を参照してください

これは、使用可能な場合、'undofile' オプションも設定します。これは、複数レベル
の undo 情報をファイルに保存します。その結果、ファイルを変更し、Vim を終了し、
それからそのファイルを再び編集するときに、以前に行った変更を undo できます。こ
れは、ファイルを保存するという代償を伴う、とても強力で便利な機能です。さらなる
情報については undo-persistence を参照してください。

"if" コマンドは、何らかの条件が満たされたときだけオプションを設定するのにとて
も便利です。それについての詳細は usr_41.txt で。


        if &t_Co > 2 || has("gui_running")
          set hlsearch
        endif

これは 'hlsearch' オプションをオンにし、最後に使った検索パターンのマッチをハイ
ライトするよう Vim に指示します。


        augroup vimrcEx
          au!
          autocmd FileType text setlocal textwidth=78
        augroup END

これは、行が 78 文字より長くなるのを避けるために、Vim にテキストを改行させま
す。ただし、プレーンテキストであると検出されたファイルに対してだけ。ここには実
際には 2 つの部分があります。"autocmd FileType text" は自動コマンドです。これ
は、ファイルタイプが "text" に設定されたときに、以下のコマンドが自動的に実行さ
れることを定義します。"setlocal textwidth=78" は 'textwidth' オプションを 78
に設定しますが、1 つのファイル内でローカルにだけです。

"augroup vimrcEx" および "augroup END" によるラッパーは、"au!" コマンドで自動
コマンドを削除することを可能にします。:augroup を参照してください。


        if has('syntax') && has('eval')
          packadd! matchit
        endif

これは、必要な機能が使用可能な場合、"matchit" プラグインを読み込みます。
これは % コマンドをより強力にします。これについては matchit-install で説明
されています。

05.3  defaults.vim ファイルの解説             defaults.vim-explained

defaults.vim ファイルは、ユーザーが vimrc ファイルを持っていないときに読み込
まれます。新しい vimrc ファイルを作成するとき、それを使い続けるために、この行
を先頭近くに追加してください:

        source $VIMRUNTIME/defaults.vim

または、上で説明したように vimrc_example.vim ファイルを使ってください。

以下は、defaults.vim が何をしているかを説明します。


        if exists('skip_defaults_vim')
          finish
        endif

defaults.vim の読み込みは、このコマンドで無効にできます:
        let skip_defaults_vim = 1
これはシステムの vimrc ファイルで行わなければなりません。system-vimrc を参照
してください。ユーザーの vimrc がある場合、defaults.vim は自動的には読み込まれ
ないので、これは必要ありません。


        set nocompatible

最初の章で述べたように、これらのマニュアルは、改良された方法で動作する、した
がって完全には Vi 互換ではない Vim を説明しています。'compatible' オプションを
オフに、したがって 'nocompatible' に設定することがこれを処理します。


        set backspace=indent,eol,start

これは、挿入モードで <BS> がカーソルの前の文字を削除できる場所を指定します。コ
ンマで区切られた 3 つの項目は、行頭のホワイトスペース、改行、および挿入モード
が開始された位置の前の文字を削除するよう Vim に指示します。'backspace' を参照
してください。


        set history=200

200 個のコマンドおよび 200 個の検索パターンを履歴に保持します。より少ないまた
はより多くの行を記憶したい場合、別の数値を使ってください。'history' を参照して
ください。


        set ruler

Vim ウィンドウの右下隅に、現在のカーソル位置を常に表示します。'ruler' を参照し
てください。


        set showcmd

不完全なコマンドを、Vim ウィンドウの右下隅の、ルーラーの左に表示します。例え
ば、"2f" とタイプしたとき、Vim は検索する文字をあなたがタイプするのを待ってお
り、"2f" が表示されます。次に "w" を押すと、"2fw" コマンドが実行され、表示され
ていた "2f" は消去されます。

        +-------------------------------------------------+
        |text in the Vim window                           |
        |~                                                |
        |~                                                |
        |-- VISUAL --                   2f     43,8   17% |
        +-------------------------------------------------+
         ^^^^^^^^^^^                  ^^^^^^^^ ^^^^^^^^^^
          'showmode'                 'showcmd'  'ruler'



        set wildmenu

補完のマッチをステータスラインに表示します。それは、<Tab> をタイプし、マッチが
2 つ以上あるときです。'wildmenu' を参照してください。


        set ttimeout
        set ttimeoutlen=100

これにより、Esc のタイプがより速く効果を持つようになります。通常、Vim は Esc
がエスケープシーケンスの開始かどうかを調べるために 1 秒待ちます。とても遅いリ
モート接続がある場合、その数値を増やしてください。'ttimeout' を参照してくださ
い。


        set display=truncate

切り詰められている場合、行全体を隠す代わりに、最終行に @@@ を表示します。
'display' を参照してください。


        set incsearch

検索パターンをタイプしている途中で、そのマッチを表示します。'incsearch' を参照
してください。


        set nrformats-=octal

ゼロで始まる数値を 8 進数として認識しません。'nrformats' を参照してください。


        map Q gq

これはキーマッピングを定義します。それについての詳細は次の節で。これは、"gq"
オペレータで整形を行う "Q" コマンドを定義します。これは、Vim 5.0 より前に動作
していた方法です。そうでなければ、"Q" コマンドは Ex モードを開始しますが、あな
たはそれを必要としないでしょう。


        inoremap <C-U> <C-G>u<C-U>

挿入モードでの CTRL-U は、現在の行で入力されたすべてのテキストを削除します。改
行を挿入した後に CTRL-U を undo できるように、まず undo を区切るために CTRL-G
u を使います。":iunmap <C-U>" で元に戻します。


        if has('mouse')
          set mouse=a
        endif

使用可能な場合、マウスの使用を有効にします。'mouse' を参照してください。


        vnoremap _g y:exe "grep /" .. escape(@", '\\/') .. "/ *.c *.h"<CR>

このマッピングは、ビジュアル選択されたテキストをヤンクし、それを C ファイル内
で検索します。マッピングがかなり複雑なことを行うのに使えることがわかるでしょ
う。それでも、それはあなたがタイプしたかのように実行される一連のコマンドにすぎ
ません。


        syntax on

ファイルを色付きでハイライトすることを有効にします。syntax を参照してくださ
い。

                                                        vimrc-filetype 
        filetype plugin indent on

これは 3 つのとても賢い仕組みをオンにします:
1. ファイルタイプ検出。
   ファイルの編集を開始するたびに、Vim はそれがどんな種類のファイルかを突き止
   めようとします。"main.c" を編集するとき、Vim は ".c" 拡張子を見て、これを
   "c" ファイルタイプとして認識します。"#!/bin/sh" で始まるファイルを編集する
   とき、Vim はそれを "sh" ファイルタイプとして認識します。
   ファイルタイプ検出は、構文ハイライトおよび以下の他の 2 つの項目に使われま
   す。
   filetypes を参照してください。

2. ファイルタイププラグインファイルを使う
   多くの異なるファイルタイプは、異なるオプションで編集されます。例えば、"c"
   ファイルを編集するとき、行を自動的にインデントするために 'cindent' オプショ
   ンを設定するのはとても便利です。これらの一般的に便利なオプション設定は、ファ
   イルタイププラグインで Vim に含まれています。あなた自身のものを追加すること
   もできます、write-filetype-plugin を参照してください。

3. インデントファイルを使う
   プログラムを編集するとき、行のインデントはしばしば自動的に計算できます。Vim
   には、いくつものファイルタイプのためのこれらのインデント規則が付属していま
   す。:filetype-indent-on および 'indentexpr' を参照してください。


                                restore-cursor last-position-jump 

    augroup RestoreCursor
      autocmd!
      autocmd BufReadPost *
        \ let line = line("'\"")
        \ | if line >= 1 && line <= line("$") && &filetype !~# 'commit'
        \      && index(['xxd', 'gitrebase'], &filetype) == -1
        \      && !&diff
        \ |   execute "normal! g`\""
        \ | endif
    augroup END

もう 1 つの自動コマンド。今回は、任意のファイルを読み込んだ後に使われます。そ
の後ろの複雑なものは、'" マークが定義されているかどうかを調べ、そうである場合、
そこへジャンプします。次のときには、それを行いません:
 - おそらく前回とは異なるものである、コミットまたはリベースのメッセージを編集
   しているとき、
 - 入力ファイルを行ったり来たり変換し、いわば二重の性質を持たせる、バイナリファ
   イルをフィルタして編集するために xxd(1) を使っているとき (using-xxd も参
   照)、および
 - Vim が diff モードであるとき

行頭のバックスラッシュは、前の行からコマンドを継続するために使われます。これに
より、行がとても長くなるのを避けられます。line-continuation を参照してくださ
い。これは Vim script ファイルの中でだけ機能し、コマンドラインでコマンドをタイ
プするときには機能しません。


        command DiffOrig vert new | set bt=nofile | r ++edit # | 0d_
                  \ | diffthis | wincmd p | diffthis

これは ":DiffOrig" コマンドを追加します。それが読み込まれた元のファイルとの差
分を見るには、変更されたバッファでこれを使ってください。diff および
:DiffOrig を参照してください。


        set nolangremap

マッピングの結果として生じる文字に langmap オプションが適用されるのを防ぎます。
設定されている場合 (既定)、これはプラグインを壊すことがあります (しかし後方互
換です)。'langremap' を参照してください。

05.4  簡単なマッピング

マッピングにより、一連の Vim コマンドを 1 つのキーに割り当てることができます。
例えば、特定の単語を波括弧で囲む必要があるとします。言い換えると、"amount" の
ような単語を "{amount}" に変更する必要があります。:map コマンドを使えば、F5
キーがこの仕事をすることを Vim に伝えることができます。コマンドは以下のとおり
です:

        :map <F5> i{<Esc>ea}<Esc>

        Note:
        このコマンドを入力するとき、<F5> は 4 文字をタイプして入力しなければな
        りません。同様に、<Esc> は <Esc> キーを押すことで入力するのではなく、5
        文字をタイプして入力します。マニュアルを読むときは、この違いに注意して
        ください!

これを分解してみましょう:
    <F5>        F5 ファンクションキー。これは、キーが押されたときにコマンドが
                実行されるきっかけとなるトリガーキーである。

    i{<Esc>     { 文字を挿入する。<Esc> キーは挿入モードを終了する。

    e           単語の末尾へ移動する。

    a}<Esc>     単語に } を付け加える。

":map" コマンドを実行した後は、単語の周りに {} を置くためにしなければならない
ことは、カーソルを最初の文字に置いて F5 を押すことだけです。

この例では、トリガーは 1 つのキーです; それは任意の文字列にできます。しかし、
既存の Vim コマンドを使うと、そのコマンドはもう使用できなくなります。それは避
けたほうがよいでしょう。
   マッピングで使えるキーの 1 つはバックスラッシュです。あなたはおそらく 2 つ
以上のマッピングを定義したいので、別の文字を追加します。例えば、"\p" を単語の
周りに丸括弧を追加するように、"\c" を波括弧を追加するようにマップできます:

        :map \p i(<Esc>ea)<Esc>
        :map \c i{<Esc>ea}<Esc>

Vim がそれらが一緒のものだとわかるように、\ および p を素早く続けてタイプする
必要があります。

":map" コマンド (引数なし) は、あなたの現在のマッピングを一覧表示します。少な
くともノーマルモード用のものを。マッピングについての詳細は 40.1 節で。

05.5  パッケージの追加  add-package

パッケージは、Vim に追加できるファイルの集まりです。2 種類のパッケージがありま
す: 任意のもの、および起動時に自動的に読み込まれるもの。

Vim の配布物には、任意で使用できるいくつかのパッケージが付属しています。

あなたの vimrc では :packadd! を使ってください: これはパッケージを
'runtimepath' に追加するだけで、読み込みは通常の起動処理に任せます。"!" なしで
は、パッケージは直接読み込まれ、それは 1 つを試してみるときに望むものです。
:packadd を参照してください。パッケージについてのさらなる情報はここで見つけ
られます: packages。

------------------------------------------------------------------------------
matchit パッケージの追加                matchit-install package-matchit
------------------------------------------------------------------------------
例えば、matchit パッケージ このプラグインは、"%" コマンドを、マッチする HTML
タグ、Vim script 内の if/else/endif などへジャンプさせます。後方互換ではありま
せんが (それが既定で有効になっていない理由です)、とても便利です。

このプラグインを使い始めるには、あなたの vimrc ファイルに 1 行を追加します:
        packadd! matchit

これだけです! Vim を再起動した後、このプラグインについてのヘルプを見つけられま
す:
        :help matchit

これは、:packadd! がパッケージディレクトリを 'runtimepath' に追加し、ヘルプ
ファイルが見つかるようにしたので、機能します。

パッケージはインターネット上のさまざまな場所で見つけられます。それは通常、アー
カイブまたはリポジトリとして提供されます。アーカイブの場合は、これらの手順に従
うことができます:
        1. パッケージディレクトリを作成します:
                mkdir -p ~/.vim/pack/fancy
           "fancy" はあなたの好みの任意の名前にできます。パッケージを表すもの
           を使ってください。
        2. そのディレクトリにアーカイブを展開します。これは、アーカイブ内の最
           上位のディレクトリが "start" であることを想定しています:
                cd ~/.vim/pack/fancy
                unzip /tmp/fancy.zip
           アーカイブのレイアウトが異なる場合、最終的にこのようなパスになるよ
           うにしてください:
                ~/.vim/pack/fancy/start/fancytext/plugin/fancy.vim
           ここで "fancytext" はパッケージの名前です、それは他の何にでもできま
           す。

------------------------------------------------------------------------------
editorconfig パッケージの追加 editorconfig-install package-editorconfig
------------------------------------------------------------------------------

このプラグインを使い始めるには、あなたの vimrc ファイルに 1 行を追加します:
        packadd! editorconfig

Vim を再起動した後、プラグインは有効になっており、それについては以下で読むこと
ができます:
        :h editorconfig.txt

comment パッケージの追加                comment-install package-comment
------------------------------------------------------------------------------

このプラグインを使い始めるには、あなたの vimrc ファイルに 1 行を追加します:

nohlsearch パッケージの追加     nohlsearch-install package-nohlsearch

このプラグインを使い始めるには、あなたの vimrc ファイルに 1 行を追加します:
        packadd! nohlsearch

'updatetime' の後、または Insert モードに入った後に、自動的に :nohlsearch
を実行します。
したがって、既定の updatetime を想定すると、hlsearch は 4 秒間のアイドル時間の

プラグインが読み込まれた後にその効果を無効にするには:
        au! nohlsearch

highlight-yank パッケージの追加         hlyank-install package-hlyank
------------------------------------------------------------------------------

このプラグインを使い始めるには、あなたの vimrc ファイルに 1 行を追加します:
        packadd! hlyank

このパッケージは、最後の yank コマンドの影響を受けた領域を短時間ハイライトし
ます。getregionpos() 関数を使った簡略化された実装については 52.6 を参照し
てください。

このプラグインは以下の設定変数を理解します (設定は既定値を示しています)。

別のハイライトグループを指定するには、以下を使います:
        :let g:hlyank_hlgroup = 'IncSearch'

別のハイライトの持続時間を使うには、以下を使います:
        :let g:hlyank_duration = 300
単位はミリ秒で、上限は 3000 ms です。これより大きな値を設定した場合、ハイライ
トの持続時間は 3000 ms になります。

ビジュアルモードでハイライトするには、以下を使います:
        :let g:hlyank_invisual = v:true

プラグインが読み込まれた後にその効果を無効にするには:
        au! hlyank

さらに、このプラグインは、put された領域も TextPutPost 自動コマンドを使って
ハイライトできます。これは既定では無効で、以下を使って有効にできます:
        :let g:hlput_enable = v:true

使用できる以下の設定変数は "g:hlput_hlgroup" および "g:hlput_duration" で、こ
れらは yank 側の対応するものと同じ効果を持ちます:
        :let g:hlput_hlgroup = 'IncSearch'
        :let g:hlput_duration = 300

viai.mcp パッケージの追加               viaimcp-install package-viai.mcp
------------------------------------------------------------------------------

viai.mcp は、AI ツールに ViAI のヘルプおよび Vim script のチェックを提供する、
Model Context Protocol (MCP) のサーバーです。AI ツールはパッケージ内のコマンド
でサーバーを起動し、したがって、そのためにパッケージが読み込まれる必要はありま

        claude mcp add viaimcp -- {runtime}/pack/dist/opt/viai.mcp/bin/viaimcp
{runtime} は ViAI での $VIMRUNTIME の値です。MS-Windows では、コマンドは

実行するには、$VIAIMCP_VIM にその名前を設定してください。

そのヘルプを読むには、これらの行をあなたの vimrc ファイルに追加します:
        if has('viai')
          packadd! viai.mcp
        endif

パッケージが読み込まれたら、それについては以下で読んでください:
        :h viaimcp.txt

05.6  プラグインの追加                                add-plugin plugin

Vim の機能はプラグインを追加することで拡張できます。プラグインは、Vim が起動す
るときに自動的に読み込まれる Vim script ファイルにすぎません。プラグインは、そ
れをあなたのプラグインディレクトリに置くことで、とても簡単に追加できます。
{Vim が +eval 機能なしでコンパイルされたときは使用できない}

2 種類のプラグインがあります:

    グローバルプラグイン: すべての種類のファイルに使われる
  ファイルタイププラグイン: 特定の種類のファイルにだけ使われる

最初にグローバルプラグインについて説明し、それからファイルタイプのもの
add-filetype-plugin について説明します。


グローバルプラグイン                   standard-plugin distributed-plugins

Vim を起動すると、Vim はいくつものグローバルプラグインを自動的に読み込みます。
このためにあなたは何もする必要はありません。それらは、ほとんどの人が使いたいと
思うが、Vim にコンパイルされる代わりに Vim script として実装された機能を追加し
ます。それらはヘルプの索引 standard-plugin-list に一覧になっているのを見つけ
られます。

ローカルにインストールされたプラグインおよびパッケージ (分離されたヘルプファイ
ルが付属するもの) については、同様の一覧がヘルプの節 local-additions で見つ
けられます。

load-plugins も参照してください。

                                                        add-global-plugin
Vim を使うときに常に存在する機能を追加するために、グローバルプラグインを追加で
きます。グローバルプラグインを追加するには 2 つのステップしかありません:
1. プラグインのコピーを入手します。
2. それを正しいディレクトリに置きます。


グローバルプラグインを入手する

プラグインはどこで見つけられますか?
- いくつかは常に読み込まれ、それらはディレクトリ $VIMRUNTIME/plugin で見ること
  ができる。
- いくつかは Vim に付属している。それらはディレクトリ $VIMRUNTIME/macros およ
  びそのサブディレクトリの中、および $VIM/vimfiles/pack/dist/opt/ の下で見つけ
  られる。
- ネットからダウンロードする。http://www.vim.org に大規模なコレクションがある。
- それらは時々 Vim の maillist に投稿される。
- あなた自身で 1 つ書くこともできる、write-plugin を参照。

いくつかのプラグインは vimball アーカイブとして提供されます、vimball を参照
してください。
いくつかのプラグインは自動的に更新できます、getscript を参照してください。


グローバルプラグインを使う

まず、何か特別な条件がないかを確認するために、プラグイン自体の中のテキストを読
んでください。それから、そのファイルをあなたのプラグインディレクトリにコピーし
ます:

        システム                プラグインディレクトリ
        Unix            ~/.vim/plugin/
        PC              $HOME/vimfiles/plugin または $VIM/vimfiles/plugin
        Amiga           s:vimfiles/plugin
        Macintosh       $VIM:vimfiles:plugin
        Mac OS X        ~/.vim/plugin/

Unix での例 (まだプラグインディレクトリを持っていなかったと仮定して):

        mkdir ~/.vim
        mkdir ~/.vim/plugin
        cp /tmp/yourplugin.vim ~/.vim/plugin

これだけです! これで、このプラグインで定義されたコマンドを使用できます。

プラグインを plugin/ ディレクトリに直接置く代わりに、plugin/ の下のサブディレ
クトリに置くことで、それらをよりうまく整理してもよいでしょう。
例として、あなたのすべての Perl プラグインに "~/.vim/plugin/perl/*.vim" を使う
ことを検討してください。


ファイルタイププラグイン               add-filetype-plugin ftplugins

Vim の配布物には、さまざまなファイルタイプのためのプラグイン一式が付属してお
り、このコマンドでそれを使い始めることができます:

        :filetype plugin on

これだけです! vimrc-filetype を参照してください。

あなたが使っているファイルタイプのプラグインが欠けている場合、またはより良いも
のを見つけた場合、それを追加できます。ファイルタイププラグインを追加するには 2
つのステップがあります:
1. プラグインのコピーを入手します。
2. それを正しいディレクトリに置きます。


ファイルタイププラグインを入手する

それらはグローバルプラグインと同じ場所で見つけられます。ファイルの種類が述べら
れているかどうかに注意してください、それでそのプラグインがグローバルなものか、
またはファイルタイプのものかがわかります。$VIMRUNTIME/macros 内のスクリプトは
グローバルなもので、ファイルタイププラグインは $VIMRUNTIME/ftplugin にありま
す。


ファイルタイププラグインを使う                 ftplugin-name

ファイルタイププラグインは、正しいディレクトリに置くことで追加できます。この
ディレクトリの名前は、上でグローバルプラグインについて述べたのと同じディレクト
リにありますが、最後の部分が "ftplugin" です。"stuff" ファイルタイプのプラグイ
ンを見つけ、Unix を使っているとします。その場合、このファイルを ftplugin ディ
レクトリに移動できます:

        mv thefile ~/.vim/ftplugin/stuff.vim

そのファイルがすでに存在する場合、すでに "stuff" 用のプラグインがあります。既
存のプラグインが、追加しようとしているものと衝突しないかを確認したいかもしれま
せん。問題ない場合、新しいものに別の名前を付けることができます:

        mv thefile ~/.vim/ftplugin/stuff_too.vim

アンダースコアは、ファイルタイプの名前を、何でもかまわない残りの部分から区切る
ために使われます。"otherstuff.vim" を使った場合、それは機能しないでしょう、そ
れは "otherstuff" ファイルタイプに対して読み込まれるでしょう。

MS-DOS のようなファイルシステムでは、長いファイル名を使えません。2 つ目のプラ
グインを追加し、そのファイルタイプが 6 文字より多い場合、問題にぶつかるでしょ
う。これを回避するために、追加のディレクトリを使えます:

        mkdir $VIM/vimfiles/ftplugin/fortran
        copy thefile $VIM/vimfiles/ftplugin/fortran/too.vim

ファイルタイププラグインの汎用的な名前は:

        ftplugin/<filetype>.vim
        ftplugin/<filetype>_<name>.vim
        ftplugin/<filetype>/<name>.vim

ここで "<name>" は、あなたが好む任意の名前にできます。
Unix での "stuff" ファイルタイプの例:

        ~/.vim/ftplugin/stuff.vim
        ~/.vim/ftplugin/stuff_def.vim
        ~/.vim/ftplugin/stuff/header.vim

filetype> の部分は、プラグインが使われる対象のファイルタイプの名前です。この
ファイルタイプのファイルだけが、プラグインからの設定を使います。プラグインファ
イルの <name> の部分は重要ではなく、同じファイルタイプに対して複数のプラグイン
を持つためにそれを使えます。Note それは ".vim" で終わらなければならないことに
注意してください。


さらなる読み物:
filetype-plugins      ファイルタイププラグインのドキュメント、およびマッピン
                        グが問題を起こすのを避ける方法についての情報。
load-plugins          起動中にグローバルプラグインが読み込まれるとき。
ftplugin-overrule     グローバルプラグインからの設定を覆す。
write-plugin          プラグインスクリプトの書き方。
plugin-details        プラグインの使用についてのさらなる情報、またはあなたの
                        プラグインが機能しないとき。
new-filetype          新しいファイルタイプを検出する方法。

05.7  ヘルプファイルの追加                            add-local-help

運が良い場合、あなたがインストールしたプラグインにはヘルプファイルも付属してい
ます。あなたの新しいプラグインのヘルプを簡単に見つけられるように、ヘルプファイ
ルをインストールする方法を説明します。
   例として "doit.vim" プラグインを使いましょう。このプラグインにはドキュメン
トが付属しています: "doit.txt"。まず、プラグインを正しいディレクトリにコピーし
ましょう。今回は Vim の中から行います。(すでにディレクトリがある場合、"mkdir"
コマンドのいくつかは省略してもかまいません。)

        :!mkdir ~/.vim
        :!mkdir ~/.vim/plugin
        :!cp /tmp/doit.vim ~/.vim/plugin

"cp" コマンドは Unix 用です、MS-Windows では "copy" を使えます。

今度は、'runtimepath' 内のディレクトリの 1 つに "doc" ディレクトリを作成しま
す。

        :!mkdir ~/.vim/doc

ヘルプファイルを "doc" ディレクトリにコピーします。

        :!cp /tmp/doit.txt ~/.vim/doc

さて、新しいヘルプファイル内の主題へジャンプできるようにする仕掛けの番です:
:helptags コマンドでローカルのタグファイルを生成します。

        :helptags ~/.vim/doc

これで、

        :help doit

コマンドを使って、今追加したヘルプファイル内の "doit" についてのヘルプを見つけ
られます。以下を行うと、ローカルヘルプファイルの項目を見ることができます:

        :help local-additions

ローカルヘルプファイルからのタイトル行は、この節に魔法のように自動的に追加され
ます。そこで、どのローカルヘルプファイルが追加されたかを見て、タグを通じてそれ
らへジャンプできます。

ローカルヘルプファイルを書くには、write-local-help を参照してください。

05.8  オプションウィンドウ

望むことを行うオプションを探している場合、ここでヘルプファイルを検索できます:
options。別の方法は、このコマンドを使うことです:

        :options

これは、1 行の説明付きのオプションの一覧がある新しいウィンドウを開きます。オプ
ションは主題ごとにグループ化されています。そこへジャンプするには、カーソルを主
題に移動して <Enter> を押します。戻るには、もう一度 <Enter> を押します。または
CTRL-O を使います。

オプションの値を変更できます。例えば、"displaying text" の主題に移動します。そ
れからカーソルをこの行まで下に移動します:

        set wrap        nowrap

<Enter> を押すと、その行は以下に変わります:

        set nowrap      wrap

これでオプションはオフに切り替えられました。

この行のすぐ上に、'wrap' オプションの短い説明があります。カーソルをこの行に置
くために、カーソルを 1 行上に移動します。ここで <Enter> を押すと、'wrap' オプ
ションについての完全なヘルプへジャンプします。

数値または文字列の引数を取るオプションについては、値を編集できます。それから新
しい値を適用するために <Enter> を押します。例えば、カーソルを数行上のこの行に
移動します:

        set so=0

"$" でカーソルをゼロの上に置きます。"r5" でそれを 5 に変更します。それから新し
い値を適用するために <Enter> を押します。ここでカーソルを動き回らせると、ボー
ダーに到達する前にテキストがスクロールし始めることに気づくでしょう。これが
'scrolloff' オプションの行うことです、それはスクロールが始まるウィンドウのボー
ダーからのオフセットを指定します。

05.9  よく使われるオプション

ひどくたくさんのオプションがあります。そのほとんどを、あなたはめったに使わない
でしょう。より便利なもののいくつかをここで述べます。これらのオプションについて
のさらなるヘルプは、オプション名の前後に単一引用符を付けて ":help" コマンドで
見つけられることを忘れないでください。例えば:

        :help 'wrap'

オプションの値をめちゃくちゃにしてしまった場合、オプション名の後ろにアンパサン
ド (&) を付けることで既定値に戻せます。例:

        :set iskeyword&


行を折り返さない

Vim は通常、テキストのすべてを見られるように、長い行を折り返します。ときには、
テキストをウィンドウの右へ続けさせるほうがよいこともあります。その場合、長い行
のすべてを見るには、テキストを左右にスクロールする必要があります。このコマンド
で折り返しをオフに切り替えます:

        :set nowrap

表示されていないテキストへ移動すると、Vim は自動的にテキストをスクロールしま
す。10 文字の文脈を見るには、これを行います:

        :set sidescroll=10

これはファイル内のテキストを変更せず、それが表示される方法だけを変更します。


折り返す移動コマンド

移動のためのほとんどのコマンドは、行の先頭および末尾で移動を止めます。これは
'whichwrap' オプションで変更できます。これはそれを既定値に設定します:

        :set whichwrap=b,s

これにより、<BS> キーは、行の最初の位置で使われたときに、カーソルを前の行の末
尾へ移動できるようになります。そして、<Space> キーは行の末尾から次の行の先頭へ
移動します。

カーソルキー <Left> および <Right> も折り返すようにするには、このコマンドを使
います:

        :set whichwrap=b,s,<,>

これはまだノーマルモードだけのものです。<Left> および <Right> に挿入モードでも
これをさせるには:

        :set whichwrap=b,s,<,>,[,]

追加できる他のフラグがいくつかあります、'whichwrap' を参照してください。


タブを表示する

ファイル内にタブがあるとき、それらがどこにあるかは見えません。それらを見えるよ
うにするには:

        :set list

これで、すべてのタブは ^I として表示されます。そして、各行の末尾に $ が表示さ
れるので、そうでなければ気づかれないままになる行末の空白を見つけることができま
す。
   欠点は、ファイル内にたくさんのタブがあると見た目が醜くなることです。カラー
端末がある場合、または GUI を使っている場合、Vim は空白およびタブをハイライト
された文字として表示できます。'listchars' オプションを使います:

        :set listchars=tab:>-,trail:-

これで、すべてのタブは ">---" (より多いまたはより少ない "-" 付きで) として、行
末の空白は "-" として表示されます。ずっと良く見えますね?


キーワード

'iskeyword' オプションは、単語にどの文字が現れることができるかを指定します:

        :set iskeyword
          iskeyword=@,48-57,_,192-255

"@" はすべてのアルファベット文字を表します。"48-57" は ASCII 文字 48 から 57
を表し、それは数字 0 から 9 です。"192-255" は印字可能なラテン文字です。
   ときには、"w" のようなコマンドが "upper-case" を 1 つの単語とみなすように、
キーワードにダッシュを含めたいでしょう。このようにしてそれを行えます:

        :set iskeyword+=-
        :set iskeyword
          iskeyword=@,48-57,_,192-255,-

新しい値を見ると、Vim があなたのためにコンマを追加したことがわかるでしょう。
   文字を削除するには "-=" を使います。例えば、アンダースコアを削除するには:

        :set iskeyword-=_
        :set iskeyword
          iskeyword=@,48-57,192-255,-

今回は、コンマが自動的に削除されます。


メッセージのための余地

Vim が起動するとき、一番下にメッセージに使われる 1 行があります。メッセージが
長いとき、それは切り詰められ、したがってその一部しか見られないか、またはテキス
トがスクロールし、続けるには <Enter> を押さなければなりません。
   'cmdheight' オプションに、メッセージに使われる行数を設定できます。例:

        :set cmdheight=3

これは、テキストを編集する余地が少なくなることを確かに意味し、したがって妥協で
す。
