                             他のファイルを編集する


この章は、普通のファイルではないファイルを編集することについてです。Vim では、
圧縮または暗号化されたファイルを編集できます。インターネット越しにアクセスする
必要があるファイルもあります。いくつかの制限付きで、バイナリファイルも編集でき
ます。

23.1  DOS、Mac および Unix のファイル

昔、古いテレタイプ端末は新しい行を始めるのに 2 つの文字を使っていました。1 つ
はキャリッジを最初の位置に戻すため (キャリッジリターン、<CR>)、もう 1 つは紙を
上に送るためです (ラインフィード、<LF>)。
   コンピュータが登場したとき、記憶装置は高価でした。行末に 2 つの文字は必要な
いと判断した人々がいました。UNIX の人々は、行末に <New Line> または <NL> だけ
を使えると判断しました。Apple の人々は <CR> に標準化しました。Microsoft
Windows の人々は、古い <CR><NL> を維持することに決めました (ヘルプテキストで
は、ラインフィードに <NL> を使います)。
   これは、あるシステムから別のシステムにファイルを移そうとすると、改行の問題
が起きることを意味します。Vim エディタは、異なるファイル形式を自動的に認識し、
あなたの知らないところで適切に処理します。
   オプション 'fileformats' には、新しいファイルを編集するときに試される様々な
形式が含まれています。例えば、以下のコマンドは、まず UNIX 形式を試し、次に
MS-DOS 形式を試すよう Vim に指示します:

        :set fileformats=unix,dos

ファイルを編集するときに表示されるメッセージで、形式に気付くでしょう。ネイティ
ブのファイル形式を編集する場合は何も表示されません。そのため、Unix 上で Unix
ファイルを編集しても何も言及されません。しかし、dos ファイルを編集すると、Vim
はこれを通知します:

        "/tmp/test" [dos] 3L, 71C

Mac ファイルの場合は "[mac]" と表示されます。
   検出されたファイル形式は 'fileformat' オプションに保存されます。どの形式を
持っているかを見るには、以下のコマンドを実行します:

        :set fileformat?

Vim が使う 3 つの名前は:

        unix            <NL>
        dos             <CR><NL>
        mac             <CR>


Mac 形式を使う

Unix では、行を区切るのに <NL> が使われます。行の途中に <CR> 文字があるのは珍
しくありません。ちなみに、これは Vi (および Vim) スクリプトでかなりよく起こり
ます。
   <CR> が改行文字である Macintosh では、行の途中に <NL> 文字を持つことができ
ます。
   その結果、<CR> および <NL> 文字の両方を含むファイルが Mac ファイルまたは
Unix ファイルのどちらであるかを 100% 確実に知ることはできません。そのため、Vim
は、Unix 上ではおそらく Mac ファイルは編集しないと仮定し、この種類のファイルは
チェックしません。それでもこの形式をチェックするには、'fileformats' に "mac"
を追加します:

        :set fileformats+=mac

そうすると、Vim はファイル形式を推測します。Vim が間違って推測する状況に気を付
けてください。


形式を上書きする

古き良き Vi を使って MS-DOS 形式のファイルを編集しようとすると、各行が ^M 文字
で終わっていることに気付くでしょう。(^M は <CR> です)。自動検出はこれを避けま
す。本当にそのようにファイルを編集したいとしたら?  その場合は、形式を上書きす
る必要があります:

        :edit ++ff=unix file.txt

"++" 文字列は、オプション名が続くことを Vim に伝える項目で、この 1 つのコマン
ドについてデフォルトを上書きします。"++ff" は 'fileformat' に使われます。
"++ff=mac" または "++ff=dos" も使えます。
   これはどのオプションでも動作するわけではなく、現在は "++ff" および "++enc"
だけが実装されています。完全な名前 "++fileformat" および "++encoding" も動作し
ます。


変換

'fileformat' オプションを使って、あるファイル形式から別の形式に変換できます。
例えば、README.TXT という名前の MS-DOS ファイルがあり、それを UNIX 形式に変換
したいとします。まず MS-DOS 形式のファイルを編集します:
        vim README.TXT

Vim はこれを dos 形式のファイルとして認識します。ここで、ファイル形式を UNIX
に変更します:

        :set fileformat=unix
        :write

ファイルは Unix 形式で書き込まれます。

23.2  インターネット上のファイル

誰かがあなたに電子メールのメッセージを送ってきて、それは URL でファイルを参照
しています。例えば:

        You can find the information here:
                https://ftp.nluug.nl/pub/vim/README

ファイルをダウンロードするプログラムを起動して、ローカルディスクに保存し、それ
から Vim を起動して編集することもできます。
   もっとずっと簡単な方法があります。URL のどれかの文字にカーソルを移動します。
それからこのコマンドを使います:

        gf

運がよければ、Vim はファイルのダウンロードにどのプログラムを使うかを判断し、そ
れをダウンロードして、そのコピーを編集します。新しいウィンドウでファイルを開く
には CTRL-W f を使います。
   何かがうまくいかないと、エラーメッセージが表示されます。URL が間違っている、
それを読む権限が無い、ネットワーク接続がダウンしている、などの可能性がありま
す。残念ながら、エラーの原因を見分けるのは難しいです。手動でファイルをダウン
ロードする方法を試してみるとよいかもしれません。

インターネット越しのファイルへのアクセスは netrw プラグインで動作します。現在、
これらの形式の URL が認識されます:

        ftp://        ftp を使う
        rcp://        rcp を使う
        scp://        scp を使う
        http://       wget を使う (読み込みのみ)

Vim は通信を自分自身では行わず、上記のプログラムがコンピュータで使用できること
に頼っています。ほとんどの Unix システムには "ftp" および "rcp" があるでしょ
う。"scp" および "wget" はインストールが必要かもしれません。

Vim は、新しいファイルの編集を始める各コマンドについてこれらの URL を検出しま
す。例えば ":edit" および ":split" でもです。書き込みコマンドも、http:// を
除いて動作します。

詳しい情報は、パスワードについても、netrw を参照してください。

23.3  暗号化

自分だけにしておきたい情報もあります。例えば、学生も使うコンピュータでテストを
書いている場合です。賢い学生に、試験が始まる前に問題を読む方法を見つけられたく
はありません。Vim はファイルを暗号化でき、それによってある程度の保護が得られま
す。
   暗号化した新しいファイルの編集を始めるには、Vim を起動するときに "-x" 引数
を使います。例:

        vim -x exam.txt

Vim は、ファイルの暗号化および復号に使う鍵の入力を求めます:

        Enter encryption key:

ここで秘密の鍵を注意深くタイプしてください。タイプした文字は見えず、星印に置き
換えられます。タイプミスが問題を起こす状況を避けるため、Vim はもう一度鍵を入力
するよう求めます:

        Enter same key again:

これで、このファイルを普通に編集して、秘密をすべて書き込めます。ファイルの編集
を終えて Vim に終了するよう指示すると、ファイルは暗号化されて書き込まれます。
   Vim でファイルを編集するとき、同じ鍵をもう一度入力するよう求められます。
"-x" 引数を使う必要はありません。普通の ":edit" コマンドも使えます。Vim はファ
イルにマジック文字列を追加し、それによってファイルが暗号化されていることを認識
します。
   別のプログラムを使ってこのファイルを見ようとしても、得られるのはゴミだけで
す。また、Vim でファイルを編集して間違った鍵を入力しても、ゴミが得られます。
Vim には鍵が正しいかをチェックする仕組みはありません (これにより、鍵を破るのが
ずっと難しくなります)。


暗号化をオンおよびオフに切り替える

ファイルの暗号化を無効にするには、'key' オプションを空文字列に設定します:
        :set key=

次にファイルを書き込むとき、それは暗号化なしで行われます。
   暗号化を有効にするために 'key' オプションを設定するのはよい考えではありませ
ん。パスワードが平文で表示されるからです。肩越しにのぞき見する人は誰でもパス
ワードを読めます。
   この問題を避けるために、":X" コマンドが作られました。これは、"-x" 引数がし
たのと同じように、暗号化の鍵を尋ねます:

        :X
        Enter encryption key: ******
        Enter same key again: ******


暗号化の制限

Vim が使う暗号化アルゴリズムはあまり強くありません。何気なくうろつく者を締め出
すには十分ですが、時間をたっぷり持っている暗号学の専門家を締め出すには十分では
ありません。スワップファイルおよび undo ファイルの中のテキストも暗号化されま
す。しかし、これはブロックごとに行われ、パスワードを解読するのに必要な時間を減
らすかもしれません。スワップファイルを無効にできますが、その場合は、Vim はすべ
てのテキストをメモリにだけ保持するので、クラッシュすると作業が失われます。undo
ファイルは無効にでき、その唯一の欠点はバッファをアンロードした後にアンドゥでき
なくなることです。
   スワップファイルを使わないようにするには、コマンドラインで -n 引数を指定し
ます。例えば、暗号化されたファイル "file.txt" をスワップファイルなしで編集する
には、以下のコマンドを使います:

        vim -x -n file.txt

すでにファイルを編集しているときは、スワップファイルはこれで無効にできます:

        :setlocal noswapfile

スワップファイルが無いので、復旧は不可能になります。変更を失う危険を避けるた
め、ファイルを少しより頻繁に保存してください。

ファイルがメモリ上にある間は、それは平文です。特権を持つ人は誰でも、エディタの
メモリを見てファイルの内容を発見できます。
   viminfo ファイルを使っている場合は、テキストレジスタの内容も平文で書き出さ
れることに注意してください。
   本当にファイルの内容を保護したい場合は、ネットワークに接続されていないポー
タブルコンピュータ上でだけ編集し、よい暗号化ツールを使い、使っていないときはコ
ンピュータを大きな金庫に閉じ込めておいてください。

23.4  バイナリファイル

Vim でバイナリファイルを編集できます。Vim は本当はこのために作られたわけではな
いので、いくつかの制限があります。しかし、ファイルを読み込み、文字を変更して書
き戻すことができ、その結果、その 1 文字だけが変更され、それ以外はファイルは同
一になります。
   Vim がその賢い仕掛けを間違った方法で使わないようにするには、Vim を起動する
ときに "-b" 引数を追加します:

        vim -b datafile

これは 'binary' オプションを設定します。この効果は、予期しない副作用がオフにな
ることです。例えば、行の自動整形を避けるため、'textwidth' は 0 に設定されます。
そして、ファイルは常に Unix ファイル形式で読み込まれます。

バイナリモードは、プログラムの中のメッセージを変更するのに使えます。文字を挿入
または削除しないように注意してください。プログラムが動作しなくなります。置換
モードに入るには "R" を使います。

ファイルの中の多くの文字は表示できないでしょう。それらを 16 進形式で見るには:


        :set display=uhex

あるいは、"ga" コマンドを使って、カーソルの下の文字の値を見ることができます。
カーソルが <Esc> の上にあるときの出力は、このようになります:

        <^[>  27,  Hex 1b,  Octal 033

ファイルにはあまり改行が無いかもしれません。全体を見渡すには、'wrap' オプショ
ンをオフにします:

        :set nowrap


バイト位置

ファイルの中のどのバイトにいるかを見るには、このコマンドを使います:

        g CTRL-G

出力は冗長です:

    Col 9-16 of 9-16; Line 277 of 330; Word 1806 of 2058; Byte 10580 of 12206

最後の 2 つの数は、ファイルの中のバイト位置およびバイトの総数です。これは、
'fileformat' が改行に使うバイト数をどのように変えるかを考慮に入れています。
    ファイルの中の特定のバイトに移動するには、"go" コマンドを使います。例えば、
バイト 2345 に移動するには:

        2345go


xxd を使う

本物のバイナリエディタは、テキストを 2 つの方法で表示します: そのままの形およ
び 16 進形式です。Vim では、まずファイルを "xxd" プログラムで変換することで、
これができます。これは Vim に付属しています。
   まず、ファイルをバイナリモードで編集します:

        vim -b datafile

では、xxd でファイルを 16 進ダンプに変換します:

        :%!xxd

テキストはこのようになります:

        0000000: 1f8b 0808 39d7 173b 0203 7474 002b 4e49  ....9..;..tt.+NI
        0000010: 4b2c 8660 eb9c ecac c462 eb94 345e 2e30  K,.`.....b..4^.0
        0000020: 373b 2731 0b22 0ca6 c1a2 d669 1035 39d9  7;'1.".....i.59.

これで、好きなようにテキストを表示および編集できます。Vim はその情報を普通のテ
キストとして扱います。16 進を変更しても表示可能な文字は変更されず、その逆も同
様です。
   最後に、これで元に戻します:

        :%!xxd -r

16 進部分の変更だけが使われます。右側の表示可能なテキスト部分の変更は無視され
ます。

詳しい情報は xxd のマニュアルページを参照してください。

23.5  圧縮ファイル

これは簡単です: 圧縮ファイルは、他のファイルとまったく同じように編集できます。
"gzip" プラグインが、ファイルを編集するときに伸長を処理します。そして、書き込
むときに再び圧縮するのも。
   現在、これらの圧縮方式がサポートされています:

        .Z      compress
        .gz     gzip
        .bz2    bzip2

Vim は、上記のプログラムを使って実際の圧縮および伸長を行います。先にプログラム
をインストールする必要があるかもしれません。
