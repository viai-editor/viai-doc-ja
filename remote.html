Vim クライアントサーバー通信                            client-server

1. 共通機能                     clientserver
2. X11 特有の項目               x11-clientserver
3. MS-Windows 特有の項目        w32-clientserver
4. ソケットサーバー特有の項目   socketserver-clientserver

==============================================================================
1. 共通機能                                             clientserver

+clientserver オプション付きでコンパイルされた場合、Vim はコマンドサーバーと
して動作できる。それはクライアントからメッセージを受け付けて、それらを実行す
る。同時に、Vim はクライアントとして機能し、Vim サーバーにコマンドを送ることが
できる。

以下のコマンドライン引数が使用できる:

    引数                        意味

   --remote [+{cmd}] {file} ...                                 --remote
                                リモート Vim でファイルリストを開く。Vim サー
                                バーが無い時は、ローカルで実行する。オプション
                                の初期コマンドが 1 つある: +{cmd}。これは "|"
                                を後に続けられる Ex コマンドでなければならな
                                い。
                                コマンドラインの残りはファイルリストとして扱わ
                                れる。したがって、ファイルでない引数はすべてこ
                                れより前に来なければならない。
                                この方法で標準入力を編集することはできない
                                --。
                                リモート Vim は前面に出される。これを望まない
                                場合は以下を使う
                                 vim --remote-send "<C-\><C-N>:n filename<CR>"

   --remote-silent [+{cmd}] {file} ...                  --remote-silent
                                上記と同様だが、サーバーが無くてファイルがロー
                                カルで編集される場合に文句を言わない。
   --remote-wait [+{cmd}] {file} ...                            --remote-wait
                                --remote と同様だが、リモート Vim でファイルが
                                完了 (アンロード) するのを待つ。
   --remote-wait-silent [+{cmd}] {file} ...             --remote-wait-silent
                                --remote-wait と同様だが、サーバーが無い場合に
                                文句を言わない。
                                                        --remote-tab
   --remote-tab                 --remote と同様だが、各ファイルを新しいタブペー
                                ジで開く。
                                                        --remote-tab-silent
   --remote-tab-silent          --remote-silent と同様だが、各ファイルを新しい
                                タブページで開く。
                                                        --remote-tab-wait
   --remote-tab-wait            --remote-wait と同様だが、各ファイルを新しいタ
                                ブページで開く。

                                                --remote-tab-wait-silent
   --remote-tab-wait-silent     --remote-wait-silent と同様だが、各ファイルを
                                新しいタブページで開く。
                                                                --servername
   --servername {name}          サーバー {name} になる。--remote コマンドのど
                                れかと一緒に使われた時は、デフォルト (以下を参
                                照) の代わりにサーバー {name} に接続する。使わ
                                れる名前は大文字になる。ソケットサーバーを使う
                                場合は、パスを指定できる。詳細は
                                socketserver-name を参照。
                                                                --remote-send
   --remote-send {keys}         {keys} をサーバーに送り、終了する。{keys} は
                                マップされない。特殊キー名は認識される。例え
                                ば、"<CR>" は CR 文字になる。
                                                                --remote-expr
   --remote-expr {expr}         {expr} をサーバーで評価し、結果を stdout に出
                                力する。
                                                                --serverlist
   --serverlist                 サーバー名のリストを出力する。
                                                                --clientserver
   --clientserver {method}      クライアントサーバー機能のバックエンドとして、
                                指定されたメソッド {method} を使う。"socket"、
                                "x11"、または "mswin" のどれかにできる。
                                                            $VIM_CLIENTSERVER
                                "$VIM_CLIENTSERVER" 環境変数が設定されている場
                                合、Vim はその値を --clientserver 引数とまった
                                く同じように解釈する。それが設定されていて、か
                                つコマンドラインで --clientserver が与えられた
                                場合は、--clientserver が優先される。
                                {+X11 および +socketserver の両方の機能付
                                き、または MS-Windows では +socketserver 付
                                きでコンパイルされた時のみ使用可能}

例

既に実行中の GVIAI サーバーで "file.txt" を編集する:
    gviai --remote file.txt

既に実行中の FOOBAR というサーバーで "file.txt" を編集する:
    gviai --servername FOOBAR --remote file.txt

サーバー "FILES" が存在すればそこで "file.txt" を編集し、そうでなければサーバー
"FILES" になる:
    gviai --servername FILES --remote-silent file.txt

これは動作しない、--remote の後のすべての引数がファイル名として使われる:
    gviai --remote --servername FOOBAR file.txt

リモートサーバーでファイル "+foo" を編集する (先頭のプラスの特別な意味を避ける
ための "./" の使用に注意):
    vim --remote ./+foo

リモートサーバー "BLA" に、すべてのファイルを書き込んで終了するよう伝える:
    vim --servername BLA --remote-send '<C-\><C-N>:wqa<CR>'


サーバー名                                             client-server-name

デフォルトでは、Vim は起動された時の名前 (gviai, egviai ...) を登録しようとす
る。これは --servername 引数で上書きできる。指定された名前が使用できない場合
は、空いている名前が見つかるまで接尾辞が付けられる。すなわち、特定の X サーバー
での gviai の 2 回目の起動では "gviai1" となる。結果の名前は servername 組み込
み変数 v:servername で使用できる。サーバー名の大文字小文字は無視されるので、
"gviai" および "GVIAI" は等しいとみなされる。Note ソケットサーバーが使われてい
る場合は、いくつかの違いがある。socketserver-differences を参照。

Vim が --remote、--remote-wait、または --remote-send 付きで起動されると、上記
のとおり、起動名および --servername 引数によって決まるサーバー名を探そうとす
る。完全に一致するものが無い場合は、番号の接尾辞が付いた最初のサーバーが使われ
る。番号の接尾辞が付いた名前が --servername 引数で指定された場合は、完全に一致
しなければならない。

サーバーが見つからず、--remote または --remote-wait が使われた場合、Vim はコマ
ンドラインの残りに従って起動し、自分で編集を行う。こうすれば、コマンドを送る時
に gviai が既に起動しているかどうかを知る必要は無い。

--serverlist 引数は、Vim に、登録されているコマンドサーバーのリストを標準出力
(stdout) に表示させて終了させる。ソケットサーバーが使われている場合は、注意点
がある。socketserver-differences を参照。
                                                        {server}
{server} 引数はいくつかの関数で使われる。これが空文字列の時は、Unix ではデフォ
ルトのサーバー名が使われ、それは "GVIAI" である。MS-Windows では空文字列は動作
しない。

Win32 Note: Vim サーバーを前面に出すことは常に動作するわけではない。MS-Windows
がそれを許可しないためである。--remote または --remote-wait 引数を使っていて、
サーバー名が "g" で始まる時は、クライアントはサーバーを前面に移動する。


リモート編集

--remote 引数は、コマンドラインの残りから :drop コマンドを組み立てさせ、上記
のとおりに送らせる。
--remote-wait 引数は同じことを行い、さらに各ファイルが編集されるのを待つように
設定する。これは BufUnload イベントを使うので、ファイルがアンロードされるとす
ぐに、Vim はあなたがその編集を終えたとみなす。
Note --remote および --remote-wait 引数はコマンドラインの残りを消費することに
注意。すなわち、残りのすべての引数はファイル名とみなされる。そこにオプションを
置くことはできない!


関数
                                                                E240 E573
コマンドサーバーをスクリプトで操作するための Vim の関数がいくつかある。
builtin.txt の説明を参照するか、または関数名の上で CTRL-] を使って完全な説明
へジャンプすること。

    概要                                     説明
    remote_startserver( name)                サーバーを実行する
    remote_expr( server, string, idvar)      式を送る
    remote_send( server, string, idvar)      キーシーケンスを送る
    serverlist()                             使用可能なサーバーのリストを得る
    remote_peek( serverid, retvar)           返信文字列を確認する
    remote_read( serverid)                   返信文字列を読む
    server2client( serverid, string)         返信文字列を送る
    remote_foreground( server)               サーバーを前面に出す

CTRL-\_CTRL-N の説明も参照。先頭のキーシーケンスとしてとても便利である。
server2client() の {serverid} は expand("<client>") で取得できる

2. X11 特有の項目                                       x11-clientserver
                                    E247 E248 E251 E258 E277

クライアントとサーバーの間の通信は X サーバーを通る。Vim サーバーのディスプレ
イを指定しなければならない。X サーバーの通常の保護が使われ、通信が動作するには
X サーバー上にウィンドウを開けなければならない。異なるシステム間で通信すること
も可能である。

デフォルトでは、GUI Vim は X サーバー上に名前を登録し、その名前によって、注入
された文字列の後続の実行のためにアドレス指定できる。Vim はクライアントとしても
動作し、同じ X11 ディスプレイ上の他の Vim のインスタンスに文字列を送ることがで
きる。

X11 GUI Vim (gviai) が起動されると、ルートウィンドウの 'VimRegistry' プロパティ
に send-server 名を登録しようとする。

X11 ディスプレイにアクセスできる非 GUI Vim (xterm-clipboard が有効) も、
--servername 引数でサーバー名が明示的に与えられた場合、または Vim が
+autoservername 機能付きでビルドされた場合は、コマンドサーバーとして動作でき
る。

空の --servername 引数はコマンドサーバーを無効にする。

他のアプリケーションから Vim サーバーにコマンドを送るには、ソースファイル
src/if_xcmdsrv.c を読むこと。それには使われているプロトコルについてのヒントが
いくつか含まれている。

3. Win32 特有の項目                                     w32-clientserver

すべての Win32 Vim はサーバーとして動作でき、コンソールでもそうである。OLE 付
きでコンパイルされたバージョンは必要無い。Windows メッセージが使われ、これはど
のバージョンの MS-Windows でも動作する。しかし、1 つのシステム内での通信のみが
可能である。

MS-Windows メッセージが使われるので、他のどのアプリケーションも Vim サーバーと
通信できるはずである。代替は OLE 機能 ole-interface を使うことである。

gviai を使う場合、--remote-wait はこの方法でのみ正しく動作する:

        start /w gviai --remote-wait file.txt

4. ソケットサーバー特有の項目                       socketserver-clientserver
                                                    E1564 E1565 E1566

NOTE: patch 9.2.511 より前の Vim バージョンは異なるソケットサーバーバックエン
ドを使っており、それはチャネルおよび JSON に基づく新しいものと互換性が無い。

クライアントとサーバーの間の通信は内部的にチャネルを使って行われる。伝統的/汎
用的なクライアントサーバーの命名 (Unix でのみ使用可能) を使う場合、ソケットは
以下の使用可能性の順で、これらのディレクトリに置かれる:
    1. 環境で $XDG_RUNTIME_DIR が設定されている場合は "$XDG_RUNTIME_DIR/vim"。
    2. "$TMPDIR/vim-$UID"。"$UID" はユーザーの uid である。$TMPDIR が設定され
       ていない場合は、"/tmp" が使われる。
                                                        E1589
ディレクトリはパーミッション 700 で作成される。既に存在する場合は、それはディ
レクトリ (シンボリックリンクでない) で、ユーザーが所有し、グループまたは他者か
らアクセスできないものでなければならない。そうでなければ E1589 が出され、そこ
ではソケットは作成も使用もされない。ソケット自体はパーミッション 700 で作成さ
れる。

                                                    socketserver-name
サーバー id/名前を指定する時、それは汎用名、または絶対パスまたは相対パスとして
扱われることがある。サーバー id が "/" (絶対) または "./" | "../" (相対) のど
ちらかで始まる場合は、ソケットへのパスとして扱われる。そうでなければ、サーバー
id はソケットのファイル名になり、ソケットは上記の共通ディレクトリに置かれる。
Note サーバー id/名前は、パスとして扱われる場合にのみスラッシュ "/" を含むこと
ができ、したがって "abc/dir" のような名前は無効になることに注意。この機能は
Unix でのみ使用可能である。

                                                    socketserver-address
さらに、ソケットサーバーは channel-address として作成することもできる。そう
するには、アドレスの前に "channel:" (これは無視される) を付ける。これは Unix
および MS-Windows の両方で使用可能であり、MS-Windows ではソケットサーバーバッ
クエンドの唯一の使用可能な命名である。ただし、ch_listen() の制限が適用される
ことに注意。つまり、TCP ソケットにはポート番号しか使えない。その場合、サーバー
はループバックインターフェイス (localhost) でのみ待ち受ける。

名前の前に "name:" が付いている場合は、旧来のサーバー名の動作が使われるので、
"name:VIM" は "VIM" と同じである。

Vim が +autoservername 機能付きでコンパイルされていない限り、X11 GUI Vim が
使われている場合を除いて、ソケットサーバーは X11 と同様に明示的に開始する必要
がある。

Vim がクラッシュするか、または正常に終了しなかった場合、ソケットサーバーはソ
ケットファイルを削除せず、それは残されたままになる。これは一般に問題ではない。
なぜなら、ソケット名が使われている場合、Vim はその場所にあるソケットが死んでい
る (どのプロセスにも接続されていない) かを確認し、新しい名前を見つける代わりに
それを置き換えられるからである。これは Unix にのみ関係する。

                                                    socketserver-security
WARNING: TCP ソケットサーバーにはアクセス制御が無い。同じマシン上のどのプロセ
スも、他のユーザーのものも含めて、ポートに接続してキーまたは式を送ることがで
き、それにより Vim サーバーを実行しているユーザーとして任意のコマンドを実行で
きる。TCP アドレスは信頼できるシングルユーザー環境でのみ使うこと。Unix では、
ソケットのパスまたは名前 (socketserver-name を参照) を優先すること。それは
ファイルパーミッションで保護される。

                                                    socketserver-differences
機能のほとんどは他のクライアントサーバーバックエンドと同じである。

ただし、サーバー id またはクライアント id は X11 または MS-Windows のような数
値 (16 進表現で表示される) にはならず、代わりにソケットへの絶対パスになる。こ
れは v:servername 変数で見ることができる。名前がチャネルアドレスの場合は、
"a/" プリフィックスも付いたアドレスになる。

Note --remote-wait を使う場合、クライアント id は "t/<some number>" のように
なる。この命名はこのコマンド専用であり、それをアドレスとして使おうとすると失敗
する。

Unix の場合、--serverlist 引数は X11 とまったく同じように動作するが、上記の
与えられた共通ディレクトリのみを確認する。ソケットにカスタムパスが使われている
場合、それは検出されない。例えば、--serverlist の Vim プロセスの
$XDG_RUNTIME_DIR/vim または $TMPDIR/vim-$UID ($TMPDIR が設定されていない場合は
/tmp/vim-$UID へのフォールバック付き) のどちらにも無いパスなどである。
MS-Windows の場合は、--serverlist 引数は何も出力しない。

+socketserver 機能は、+channel 機能が使用可能な場合、Unix および
MS-Windows で自動的に有効になる。

                                                    socketserver-x11
Vim が +socketserver および別のクライアントサーバーバックエンド付きでコンパ
イルされている場合、どのバックエンドを使うかの決定は、起動時に
--clientserver 引数によって行われる。デフォルトでは、それが指定されていない
場合、ネイティブのバックエンド (X11 または MS-Windows メッセージ) が、使用可能
な場合、使われる。ソケットサーバーを使う Vim インスタンスは、別のクライアント
サーバーバックエンドを使うものとは通信できない。
