1. タグへのジャンプ                                     tag-commands

                                                        tag tags
タグとは "tags" ファイルに現れる識別子である。それはジャンプできるラベルの一種
である。例えば: C プログラムでは各関数名をタグとして使用できる。タグコマンドを
使用する前に、"tags" ファイルを ctags のようなプログラムで生成しておかなければ
ならない。

":tag" コマンドを使うと、カーソルはタグの上に置かれる。CTRL-] コマンドを使う
と、カーソルが置かれているキーワードがタグとして使用される。カーソルがキーワー
ドの上にない場合、カーソルの右にある最初のキーワードが使用される。

":tag" コマンドは C プログラムに対して非常にうまく働く。関数の呼び出しを見て、
その関数が何をするのかを知りたいと思った場合、その関数名の中にカーソルを置いて
CTRL-] を押す。これで関数定義へ移動する。
簡単に戻る方法は CTRL-T コマンドである。以下のタグスタックについても読むこと。

                                                :ta :tag E426 E429
:[count]ta[g][!] {name}
                        タグファイルの情報を使用して、{name} の定義へジャンプ
                        する。{name} をタグスタックに入れる。[!] については
                        tag-! を参照。
                        {name} には正規表現パターンを指定できる。tag-regexp
                        を参照。{name} にマッチするタグが複数ある場合、[count]
                        番目へジャンプする。[count] が省略された場合、最初のも
                        のへジャンプする。他のマッチするタグへジャンプするには
                        tag-matchlist を参照。

g<LeftMouse>                                            g<LeftMouse>
<C-LeftMouse>                                   <C-LeftMouse> CTRL-]
CTRL-]                  カーソルの下のキーワードの定義へジャンプする。
                        ":tag {name}" と同じで、{name} はカーソルの下またはカー
                        ソルの後のキーワードである。
                        {name} にマッチするタグが複数ある場合、[count] 番目へ
                        ジャンプする。[count] が指定されない場合、最初のものへ
                        ジャンプする。他のマッチするタグへジャンプするには
                        tag-matchlist を参照。

                                                        v_CTRL-]
{Visual}CTRL-]          ":tag {name}" と同じで、{name} はハイライトされたテキ
                        ストである。

                                                        telnet-CTRL-]
CTRL-] は telnet のデフォルトのエスケープキーである。タグへジャンプするために
CTRL-] をタイプすると、代わりに telnet プロンプトが表示される。たいていのバー
ジョンの telnet では、デフォルトのエスケープキーを変更または無効化できる。
telnet の man ページを参照。'telnet -E {Hostname}' でエスケープ文字を無効にす
るか、または 'telnet -e {EscapeCharacter} {Hostname}' で別のエスケープ文字を指
定できる。可能な場合、この問題を避けるために "telnet" の代わりに "ssh" を使用
するようにすること。

                                                        tag-priority
1 つのタグに複数のマッチがある場合、この優先順位が使用される:
1. "FSC"  カレントファイルに対する、完全にマッチする static タグ。
2. "F C"  カレントファイルに対する、完全にマッチする global タグ。
3. "F  "  別のファイルに対する、完全にマッチする global タグ。
4. "FS "  別のファイルに対する、完全にマッチする static タグ。
5. " SC"  カレントファイルに対する、大文字小文字を無視してマッチする static タグ。
6. "  C"  カレントファイルに対する、大文字小文字を無視してマッチする global タグ。
7. "   "  別のファイルに対する、大文字小文字を無視してマッチする global タグ。
8. " S "  別のファイルに対する、大文字小文字を無視してマッチする static タグ。

Note カレントファイルが変わっても、":tnext" を使用する時の混乱を避けるために、
優先順位リストはほとんど変更されないことに注意。":tag {name}" を使用した時には
変更される。

大文字小文字を無視したマッチは、":tag" コマンドでは以下の場合に見つからない:
- 'tagcase' が "followic" で、'ignorecase' オプションがオフ
- 'tagcase' が "followscs" で、'ignorecase' オプションがオフで、'smartcase' オ
  プションがオフであるか、またはパターンに大文字が含まれる。
- 'tagcase' が "match"
- 'tagcase' が "smart" で、パターンに大文字が含まれる。

大文字小文字を無視したマッチは以下の場合に見つかる:
- パターンが使用された時 ("/" で始まる)
- ":tselect" に対して
- 'tagcase' が "followic" で、'ignorecase' がオンの時
- 'tagcase' が "followscs" で、'ignorecase' がオンであるか、または 'smartcase'
  オプションがオンでパターンに大文字が含まれない時
- 'tagcase' が "ignore" の時
- 'tagcase' が "smart" で、パターンに大文字が含まれない時

Note 大文字小文字を無視したタグ検索を使用すると、タグファイル内の二分探索が無
効になり、速度が低下することに注意。これはタグファイルを fold-case ソートする
ことで回避できる。説明については 'tagbsearch' オプションを参照。

2. タグスタック                         tag-stack tagstack E425

タグスタックには、どのタグへ、どこからジャンプしたかが記憶される。
タグは 'tagstack' オプションが設定されている場合にのみスタックに積まれる。

g<RightMouse>                                           g<RightMouse>
<C-RightMouse>                                  <C-RightMouse> CTRL-T
CTRL-T                  タグスタック内の [count] 個古いエントリへジャンプする
                        (デフォルトは 1)。

                                                :po :pop E555 E556
:[count]po[p][!]        タグスタック内の [count] 個古いエントリへジャンプする
                        (デフォルトは 1)。[!] については tag-! を参照。

:[count]ta[g][!]        タグスタック内の [count] 個新しいエントリへジャンプす
                        る (デフォルトは 1)。[!] については tag-! を参照。

                                                        :tags
:tags                   タグスタックの内容を表示する。アクティブなエントリには
                        '>' の印が付く。

":tags" の出力はこのようになる:

   # TO tag      FROM line  in file/text
   1  1 main             1  harddisk2:text/vim/test
 > 2  2 FuncA           58  i = FuncA(10);
   3  1 FuncC          357  harddisk2:text/vim/src/amiga.c

この一覧は、ジャンプしたタグ、およびそのジャンプの前のカーソル位置を示す。古い
タグが上に、新しいタグが下にある。

'>' はアクティブなエントリを指す。これは次の ":tag" コマンドで使用されるタグで
ある。CTRL-T および ":pop" コマンドはアクティブなエントリの上の位置を使用する。

"TO" の下にあるのは、マッチリスト内の現在のマッチの番号である。Note これは
":pop" または ":tag" を使用しても変わらないことに注意。

行番号およびファイル名は、タグコマンドの前にいた場所へ戻れるように記憶される。
行を削除/挿入した場合も、行番号は正しい。ただし、それが別のプログラム (例: 別
の Vim のインスタンス) によって行われた場合は除く。

カレントファイルについては、"file/text" カラムはその位置のテキストを表示する。
インデントは除去され、長い行はウィンドウに収まるように切り詰められる。

いくつかのコマンドで、以前に使用したタグへジャンプできる。いくつかの例:

        ":pop" または CTRL-T    直前のタグの前の位置へ
        {count}CTRL-T           {count} 個古いタグの前の位置へ
        ":tag"                  より新しいタグへ
        ":0tag"                 最後に使用したタグへ

これを使用する最もわかりやすい方法は、プログラムのコールグラフを見て回っている
時である。以下のコールグラフを考える:

        main  --->  FuncA  --->  FuncC
              --->  FuncB

(説明: main は FuncA および FuncB を呼び、FuncA は FuncC を呼ぶ)。
FuncA の呼び出しの上で CTRL-] を使用することで、main から FuncA へ移動できる。
それから CTRL-] で FuncC へ移動できる。ここで main へ戻りたい場合、CTRL-T を 2
回使用できる。それから CTRL-] で FuncB へ移動できる。

":ta {name}" または CTRL-] コマンドを発行した場合、このタグはスタックの現在の
位置に挿入される。スタックがいっぱいだった場合 (最大 20 エントリ保持できる)、
最も古いエントリが削除され、より古いエントリが 1 つ上の位置へずれる (それらの
インデックス番号は 1 減る)。最後に使用したエントリが一番下になかった場合、最後
に使用したエントリより下のエントリは削除される。これは、コールグラフの古い分岐
が失われることを意味する。上で説明したコマンドの後では、タグスタックはこのよう
になる:

   # TO tag     FROM line  in file/text
   1  1 main            1  harddisk2:text/vim/test
   2  1 FuncB          59  harddisk2:text/vim/src/main.c

gettagstack() 関数は指定されたウィンドウのタグスタックを返す。
settagstack() 関数はウィンドウのタグスタックを変更する。

                                                        tagstack-examples
:tag とまったく同じように、ただしユーザー定義の jumper#jump_to_tag 関数を使
用して、タグスタックに書き込む:
        " ジャンプする前に、ジャンプ元を保存する。
        let tag = expand('<cword>')
        let pos = [bufnr()] + getcurpos()[1:]
        let item = {'bufnr': pos[0], 'from': pos, 'tagname': tag}
        if jumper#jump_to_tag(tag)
                " ジャンプ成功、前の位置をタグスタックに書き込む。
                let winid = win_getid()
                let stack = gettagstack(winid)
                let stack['items'] = [item]
                call settagstack(winid, stack, 't')
        endif

タグスタックの現在のインデックスを 4 に設定する:
        call settagstack(1005, {'curidx' : 4})

新しい項目をタグスタックに積む:
        let pos = [bufnr('myfile.txt'), 10, 1, 0]
        let newtag = [{'tagname' : 'mytag', 'from' : pos}]
        call settagstack(2, {'items' : newtag}, 'a')

                                                        E73
タグスタックが何も含んでいない時にタグスタックを使用しようとすると、エラーメッ
セージが表示される。

3. タグマッチリスト                             tag-matchlist E427 E428

マッチするタグが複数ある時、これらのコマンドでそれらの間をジャンプできる。Note
これらのコマンドはタグスタックを変更せず、同じエントリを保持することに注意。

                                                        :ts :tselect
:ts[elect][!] [name]    タグファイルの情報を使用して、[name] にマッチするタグ
                        を一覧表示する。
                        [name] が指定されない場合、タグスタックの最後のタグ名
                        が使用される。
                        [!] については tag-! を参照。
                        最初のカラムの '>' で、一覧内の現在の位置が示される
                        (ある場合)。[name] には正規表現パターンを指定できる。
                        tag-regexp を参照。
                        一覧表示で使用される優先順位については tag-priority
                        を参照。
                        出力例:


          # pri kind tag                file
          1 F   f    mch_delay          os_amiga.c
                        mch_delay(msec, ignoreinput)
        > 2 F   f    mch_delay          os_msdos.c
                        mch_delay(msec, ignoreinput)
          3 F   f    mch_delay          os_unix.c
                        mch_delay(msec, ignoreinput)
        Type number and <Enter> (empty cancels):

                        "pri" カラムについては tag-priority を参照。Note こ
                        れはカレントファイルに依存するので、":tselect xxx" を
                        使用すると異なる結果になりうることに注意。
                        タグの種類がタグファイルに含まれていた場合、"kind" カ
                        ラムはその種類を示す。
                        "info" カラムはタグファイル内で見つかった情報を表示す
                        る。それはタグファイルを生成したプログラムに依存する。
                        一覧が長い場合、more-prompt が表示されることがある。
                        使用したいタグがすでに見えている場合、'q' をタイプして
                        番号を入力できる。

                                                        :sts :stselect
:sts[elect][!] [name]   ":tselect[!] [name]" を実行し、選択したタグのためにウィ
                        ンドウを分割する。

                                                        g]
g]                      CTRL-] と同様だが、":tag" の代わりに ":tselect" を使用
                        する。

                                                        v_g]
{Visual}g]              "g]" と同じだが、ハイライトされたテキストを識別子とし
                        て使用する。

                                                        :tj :tjump
:tj[ump][!] [name]      ":tselect" と同様だが、マッチが 1 つだけの場合はタグへ
                        直接ジャンプする。

                                                        :stj :stjump
:stj[ump][!] [name]     ":tjump[!] [name]" を実行し、選択したタグのためにウィ
                        ンドウを分割する。

                                                        g_CTRL-]
g CTRL-]                CTRL-] と同様だが、":tag" の代わりに ":tjump" を使用す
                        る。

                                                        v_g_CTRL-]
{Visual}g CTRL-]        "g CTRL-]" と同じだが、ハイライトされたテキストを識別
                        子として使用する。

                                                        :tn :tnext
:[count]tn[ext][!]      [count] 個先のマッチするタグへジャンプする (デフォルト
                        は 1)。[!] については tag-! を参照。

                                                        :tp :tprevious
:[count]tp[revious][!]  [count] 個前のマッチするタグへジャンプする (デフォルト
                        は 1)。[!] については tag-! を参照。

                                                        :tN :tNext
:[count]tN[ext][!]      ":tprevious" と同じ。

                                                        :tr :trewind
:[count]tr[ewind][!]    最初のマッチするタグへジャンプする。[count] が指定され
                        た場合、[count] 番目のマッチするタグへジャンプする。[!]
                        については tag-! を参照。

                                                        :tf :tfirst
:[count]tf[irst][!]     ":trewind" と同じ。

                                                        :tl :tlast
:tl[ast][!]             最後のマッチするタグへジャンプする。[!] については
                        tag-! を参照。

                                                        :lt :ltag
:lt[ag][!] [name]       タグ [name] へジャンプし、マッチするタグをカレントウィ
                        ンドウの新しい location リストに追加する。[name] には
                        正規表現パターンを指定できる。tag-regexp を参照。
                        [name] が指定されない場合、タグスタックの最後のタグ名
                        が使用される。タグ行を見つけるための検索パターンには、
                        全ての特殊文字をエスケープするために "\V" が前置される
                        (very nomagic)。マッチするタグを表示する location リス
                        トはタグスタックから独立している。[!] については
                        tag-! を参照。

他のメッセージがない時、Vim はどのマッチするタグへジャンプしたか、およびマッチ
するタグの数を表示する:
        tag 1 of 3 or more
" or more" は、Vim がまだ全てのタグファイルを試していないことを示すために使用
される。":tnext" を数回使用するか、または ":tlast" を使用すると、さらにマッチ
が見つかるかもしれない。

他のメッセージのためにこのメッセージを見なかった時、または単に今どこにいるのか
を知りたい時、このコマンドでもう一度表示できる (そして前回と同じタグへジャンプ
する):
        :0tn

                                                        tag-skip-file
ファイルが存在しないマッチするタグが見つかった時、そのマッチはスキップされ、次
のマッチするタグが使用される。Vim はファイルが見つからないことを知らせるため
に、これを報告する。マッチのリストの最後に達した時、エラーメッセージが表示され
る。

                                                        tag-preview
タグマッチリストはプレビューウィンドウでも使用できる。コマンドは上記と同じで、
先頭に "p" が付く。
{+quickfix 機能なしでコンパイルされた時は使用できない}

                                                        :pts :ptselect
:pts[elect][!] [name]   ":tselect[!] [name]" を実行し、新しいタグを "Preview"
                        ウィンドウに表示する。詳しくは :ptag を参照。

                                                        :ptj :ptjump
:ptj[ump][!] [name]     ":tjump[!] [name]" を実行し、新しいタグを "Preview"
                        ウィンドウに表示する。詳しくは :ptag を参照。

                                                        :ptn :ptnext
:[count]ptn[ext][!]     プレビューウィンドウでの ":tnext"。:ptag を参照。

                                                        :ptp :ptprevious
:[count]ptp[revious][!] プレビューウィンドウでの ":tprevious"。:ptag を参照。

                                                        :ptN :ptNext
:[count]ptN[ext][!]     ":ptprevious" と同じ。

                                                        :ptr :ptrewind
:[count]ptr[ewind][!]   プレビューウィンドウでの ":trewind"。:ptag を参照。

                                                        :ptf :ptfirst
:[count]ptf[irst][!]    ":ptrewind" と同じ。

                                                        :ptl :ptlast
:ptl[ast][!]            プレビューウィンドウでの ":tlast"。:ptag を参照。

4. タグ詳細                                             tag-details

                                                        static-tag
static タグとは、特定のファイルに対して定義されたタグである。C プログラムでは、
これは static 関数であろう。

Vi では、タグへジャンプすると現在の検索パターンが設定される。これは、タグへジャ
ンプした後の "n" コマンドが、タグへジャンプする前と同じパターンを検索しないこ
とを意味する。我々はこれをバグだと考えているので、Vim はこれを行わない。本当に
昔の Vi の動作が欲しい場合、'cpoptions' に 't' フラグを設定する。

                                                        tag-binary-search
Vim は目的のタグを素早く見つけるために、タグファイル内で二分探索を使用する (コ
ンパイル時に有効にされている場合 +tag_binary)。しかしこれは、タグファイルが
ASCII のバイト値でソートされている場合にのみ動作する。そのため、マッチが見つか
らなかった場合、線形探索でもう一度試す。線形探索だけが欲しい場合、'tagbsearch'
オプションをリセットする。あるいはもっと良いのは: タグファイルをソートすること!

Note 特定の名前を持つタグを探していない時は、二分探索が無効になることに注意。
これは、大文字小文字を無視する時、および固定文字列で始まらない正規表現が使用さ
れた時に起こる。その場合、タグ検索はかなり遅くなることがある。前者はタグファイ
ルを case-fold ソートすることで回避できる。詳細は 'tagbsearch' を参照。

                                                        tag-regexp
":tag" および ":tselect" コマンドは正規表現の引数を受け付ける。使用できる特殊
文字については pattern を参照。
引数が '/' で始まる時、それはパターンとして使用される。引数が '/' で始まらない
場合、それは完全なタグ名として文字どおりに解釈される。
例:
    :tag main
        最も優先度が高い "main" タグへジャンプする。
    :tag /^get
        "get" で始まり、最も優先度が高いタグへジャンプする。
    :tag /norm
        "id_norm" を含め、"norm" を含む全てのタグを一覧表示する。
引数が文字どおりに存在し、かつ正規表現として使用した時にもマッチする時、文字ど
おりのマッチの方が優先度が高い。例えば、":tag /open" は "open_file" および
"file_open" より前に "open" にマッチする。
パターンを使用する時、大文字小文字は無視される。大文字小文字を区別してマッチさ
せたい場合、パターン内で "\C" を使用する。

                                                        tag-!
タグがカレントファイル内にある場合、これは常に動作する。そうでない場合、実行さ
れる動作は、カレントファイルが変更されているかどうか、コマンドに ! が付加され
ているかどうか、および 'autowrite' および 'winfixbuf' オプションに依存する:

  タグが      ファイル      winfixbuf   autowrite       
カレントファイル内 変更 !   オプション  オプション    動作
 -----------------------------------------------------------------------------
    yes         x       x      off        x         タグへ移動
    no          no      x      off        x         他のファイルを読み込み、タグへ移動
    no          yes     yes    off        x         カレントファイルを破棄し、
                                                    他のファイルを読み込み、タグへ移動
    no          yes     no     off        on        カレントファイルを書き込み、
                                                    他のファイルを読み込み、タグへ移動
    no          yes     no     off        off       失敗
    yes         x       yes    x          x         タグへ移動
    no          no      no     on         x         失敗
    no          yes     no     on         x         失敗
    no          yes     no     on         on        失敗
    no          yes     no     on         off       失敗
 -----------------------------------------------------------------------------

- タグがカレントファイル内にある場合、コマンドは常に動作する。
- タグが別のファイル内にあり、カレントファイルが変更されていない場合、別のファ
  イルがカレントファイルになり、バッファに読み込まれる。
- タグが別のファイル内にあり、カレントファイルが変更されていて、コマンドに !
  が付加されている場合、カレントファイルへの変更は失われ、別のファイルがカレン
  トファイルになり、バッファに読み込まれる。
- タグが別のファイル内にあり、カレントファイルが変更されていて、'autowrite' オ
  プションがオンの場合、カレントファイルは書き込まれ、別のファイルがカレント
  ファイルになり、バッファに読み込まれる。
- タグが別のファイル内にあり、カレントファイルが変更されていて、'autowrite' オ
  プションがオフの場合、コマンドは失敗する。変更を保存したい場合、":w" コマン
  ドを使用し、それから引数なしで ":tag" を使用する。これは、タグはいずれにせよ
  スタックに積まれるので動作する。変更を捨てたい場合、":tag!" コマンドを使用で
  きる。
- タグが別のファイル内にあり、ウィンドウが 'winfixbuf' を含む場合、コマンドは
  失敗する。タグが同じファイル内にある場合、それは成功するかもしれない。

                                                        tag-security
Note Vim はセキュリティ上の理由から、いくつかのコマンドを禁止していることに注
意。これは、カレントディレクトリにある exrc/vimrc ファイルに対して 'secure' オ
プションを使用するのと同じように動作する。trojan-horse および sandbox を参
照。
{tagaddress} がバッファを変更した時、警告メッセージが表示される:
        "WARNING: tag command changed a buffer!!!"
将来のバージョンでは、バッファを変更することは不可能になる。これは全てセキュリ
ティ上の理由による: 誰かがタグファイルに悪意のあるコマンドを隠すかもしれず、そ
うでなければそれは気付かれないままになるだろう。例:
        :$d|/tag-function-name/

Vi では、":tag" コマンドはタグを検索する時に最後の検索パターンを設定する。Vim
ではこれは行われず、'cpoptions' に 't' フラグが含まれていない限り、以前の検索
パターンが記憶されたままになる。

                                        emacs-tags emacs_tags E430
Emacs スタイルのタグファイルは、Vim が +emacs_tags 機能を有効にしてコンパイ
ルされた場合にのみサポートされる。申し訳ないが、ここには Emacs のタグファイル
についての説明はない。後方互換性のためだけにサポートされている :-)。

Emacs のタグファイルの行は非常に長くなることがある。Vim は約 510 バイトまでの
行しか扱わない。行が無視されているかどうかを見るには、'verbose' を 5 以上に設
定する。Emacs 以外のタグファイルの行は任意の長さにできる。

                                                        tags-option
'tags' オプションはファイル名のリストである。これらの各ファイルでタグが検索さ
れる。これは、デフォルトのファイル "tags" とは異なるタグファイルを使用するため
に使用できる。共通のタグファイルにアクセスするためにも使用できる。

リスト内の次のファイルは、以下の場合には使用されない:
- カレントバッファに対する、マッチする static タグが見つかった。
- マッチする global タグが見つかった。
これは、大文字小文字が無視されるかどうかにも依存する。大文字小文字は以下の場合
に無視される:
- 'tagcase' が "followic" で、'ignorecase' が設定されている
- 'tagcase' が "ignore"
- 'tagcase' が "smart" で、パターンが小文字のみを含む。
- 'tagcase' が "followscs" で、'smartcase' が設定されていて、パターンが小文字
  のみを含む。
大文字小文字が無視されず、タグファイルに大文字小文字がマッチしないマッチしかな
い場合、次のタグファイルで大文字小文字がマッチするマッチが検索される。大文字小
文字がマッチするタグが見つからない場合、大文字小文字がマッチしない最初のマッチ
が使用される。大文字小文字が無視され、大文字小文字がマッチするかどうかにかかわ
らず、マッチする global タグが見つかった場合、それが使用され、それ以上タグファ
イルは検索されない。

タグファイル名が "./" で始まる時、'.' はカレントファイルのパスに置き換えられ
る。これにより、カレントファイルがあるディレクトリにあるタグファイルを使用でき
る (カレントディレクトリがどこであっても)。"./" を使用する考え方は、どのタグ
ファイルを最初に検索するかを定義できるということである: カレントディレクトリ内
("tags,./tags") またはカレントファイルのディレクトリ内 ("./tags,tags")。

例えば:
        :set tags=./tags,tags,/home/user/commontags

この例では、タグはまずカレントファイルがあるディレクトリのファイル "tags" で検
索される。次にカレントディレクトリの "tags" ファイル。そこで見つからない場合、
ファイル "/home/user/commontags" でタグが検索される。

これは、Vi 互換にするために、'cpoptions' に 'd' フラグを含めることでオフにでき
る。そうすると "./tags" は、カレントファイルがあるディレクトリのタグファイルで
はなく、カレントディレクトリのタグファイルになる。

コンマの代わりにスペースを使用してもよい。その場合、スペースを文字列オプション
に含めるためにバックスラッシュが必要になる:
        :set tags=tags\ /home/user/commontags

ファイル名にスペースを含めるには、3 つのバックスラッシュを使用する。ファイル名
にコンマを含めるには、2 つのバックスラッシュを使用する。例えば、以下を使用する:

        :set tags=tag\\\ file,/home/user/common\\,tags

ファイル "tag file" および "/home/user/common,tags" のために。'tags' オプショ
ンは "tag\ file,/home/user/common\,tags" という値になる。

'tagrelative' オプションがオン (これがデフォルトである) で、別のディレクトリに
あるタグファイルを使用する場合、そのタグファイル内のファイル名は、そのタグファ
イルがあるディレクトリからの相対パスになる。

5. タグファイルの書式                           tags-file-format E431

                                                ctags
タグファイルは外部コマンド、例えば "ctags" で作成できる。それは各関数に対する
タグを含む。"ctags" のいくつかのバージョンは、各 "#defined" マクロ、typedef、
enum などに対してもタグを作成する。

タグファイルを生成するいくつかのプログラム:
ctags                   ほとんどの Unix システムで見つかるもの。C のみをサポー
                        トする。基本的な作業のみを行う。
universal ctags         exuberant ctags をベースとした、メンテナンスされている
                        ctags のバージョン。https://ctags.io を参照。
                                                        Exuberant_ctags
exuberant ctags         これはとても良いものだ。C、C++、Java、Fortran、Eiffel、
                        およびその他で動作する。多くの項目に対してタグを生成で
                        きる。http://ctags.sourceforge.net を参照。
                        2009 年以降、新しいバージョンはない。
etags                   Emacs に関連するもの。多くの言語をサポートする。
:helptags             Vim の help ファイル用
ptags.py                Python 用、Python 製。Python のソースディレクトリの
                        Tools/scripts/ptags.py にある。
ptags                   Perl 用、Perl 製。これは
                        https://metacpan.org/pod/Vim::Tag で見つけられる
gnatxref                Ada 用。http://www.gnuada.org/ を参照。gnatxref は
                        gnat パッケージの一部である。


タグファイルの行は、これら 2 つの形式のどちらかでなければならない:

1.  {tagname}           {TAB} {tagfile} {TAB} {tagaddress}
2.  {tagname}           {TAB} {tagfile} {TAB} {tagaddress} {term} {field} ..

以前は古い形式がサポートされていた。tag-old-static を参照。

1 つ目の形式は通常のタグで、Vi と完全に互換性がある。これは従来の ctags の実装
が生成する唯一の形式である。これは、global な関数で、他のファイルからも参照さ
れるものに対してよく使用される。

タグファイルの行は <NL> または <CR><NL> で終わることができる。Macintosh では
<CR> も動作する。<CR> および <NL> 文字は、決して行の中に現れることはできない。

2 つ目の形式は新しい。これは、各行の末尾のオプションのフィールドに追加の情報を
含む。これは Vi と後方互換性がある。これは新しいバージョンの ctags (Universal
ctags または Exuberant ctags など) でのみサポートされている。

{tagname}       識別子。通常は関数名だが、任意の識別子にできる。<Tab> を含むこ
                とはできない。
{TAB}           1 つの <Tab> 文字。Note: 以前のバージョンではここに任意の空白
                を許していた。これは {tagfile} にスペースを含められるようにす
                るために廃止された。
{tagfile}       {tagname} の定義を含むファイル。絶対パスまたは相対パスを持つこ
                とができる。環境変数およびワイルドカードを含んでもよい (ただ
                し、ワイルドカードの使用は疑わしい)。<Tab> を含むことはできな
                い。
                                                                E1576
                ネットワークプロトコル経由でリモートファイルを使用すること (例:
                http://remote/file.txt を使用) は、'tagsecure' がリセットされ
                ていない限り許されない。
{tagaddress}    タグの位置にカーソルを置く Ex コマンド。任意の Ex コマンドにで
                きるが、制限が適用される (tag-security を参照)。Posix では行
                番号および検索コマンドのみが許されており、それらが主に使用され
                る。
{term}          ;" セミコロンおよびダブルクォートの 2 文字。これは Vi によって
                コメントの開始として解釈され、以下が無視されることになる。これ
                は Vi との後方互換性のためで、Vi は以下のフィールドを無視する。
                例:
                        APP     file    /^static int APP;$/;"   v
                {tagaddress} が行番号または検索パターンでない場合、{term} は
                |;" でなければならない。ここでバーはコマンドを終了させ (バーは
                含まない)、;" は Vi に行の残りを無視させるために使用される。例:

                        APP     file.c  call cursor(3, 4)|;"    v

{field} ..      オプションのフィールドのリスト。各フィールドは以下の形式を持つ:

                        <Tab>{fieldname}:{value}

                {fieldname} はフィールドを識別し、アルファベット文字 [a-zA-Z]
                のみを含むことができる。
                {value} は任意の文字列だが、<Tab> を含むことはできない。
                これらの文字は特別である:
                        "\t" は <Tab> を表す
                        "\r" は <CR> を表す
                        "\n" は <NL> を表す
                        "\\" は 1 つの '\' 文字を表す

                ':' を持たないフィールドが 1 つある。これはタグの種類である。
                これは "kind:" が前置されているかのように扱われる。上の例では、
                これは "kind:v" (一般的には変数) であった。ctags が生成する種
                類については ctags のドキュメントを参照。ctags では
                ctags --list-kinds を使用できる。

                Vim が現在認識する他の唯一のフィールドは "file:" (空の値を持つ)
                である。これは static タグに使用される。


タグファイルの最初の行には、以下で始まる行を含むことができる
        !_TAG_
これらは最初の行にソートされ、"!" で始まるまれなタグだけがそれらより前にソート
されうる。Vim は 2 つの項目を認識する。1 つ目は、ファイルがソートされているか
どうかを示す行である。この行が見つかった時、Vim はタグファイルに対して二分探索
を使用する:
        !_TAG_FILE_SORTED<Tab>1<Tab>{anything}

大文字小文字が無視される時に線形探索を避けるために、タグファイルは case-fold
ソートされていてもよい。(大文字小文字は、'ignorecase' が設定されていて
'tagcase' が "followic" の時、または 'tagcase' が "ignore" の時に無視される。)
詳細は 'tagbsearch' を参照。その場合は値 '2' を使用すること:
        !_TAG_FILE_SORTED<Tab>2<Tab>{anything}

Vim が認識するもう 1 つのタグは、タグファイルのエンコーディングである:
        !_TAG_FILE_ENCODING<Tab>utf-8<Tab>{anything}
ここで "utf-8" はタグに使用されるエンコーディングである。その場合、Vim は検索
されるタグを 'encoding' からタグファイルのエンコーディングへ変換する。そしてタ
グを一覧表示する時は逆が起こる。変換に失敗した時、変換されていないタグが使用さ
れる。

                                                        tag-search
コマンドは任意の Ex コマンドにできるが、多くの場合は検索コマンドである。例:
        tag1    file1   /^main(argc, argv)/
        tag2    file2   108

コマンドは常に 'magic' が設定されていない状態で実行される。検索パターン内の特
殊文字は "^" (行頭) および "$" (<EOL>) だけである。
pattern を参照。Note 検索テキスト内の各バックスラッシュの前にバックスラッシュ
を置かなければならないことに注意。これは Vi との後方互換性のためである。

                                                        E434 E435
コマンドが通常の検索コマンドである (それが "/" または "?" で始まり、終わる) 場
合、いくつかの特別な処理が行われる:
- 検索はファイルの 1 行目から開始する。
  検索の方向は "/" では前方、"?" では後方である。
  Note 'wrapscan' は関係なく、常にファイル全体が検索されることに注意。
- 検索が失敗した場合、大文字小文字を無視してもう一度試す。それも失敗した場合、
  以下に対して検索が行われる:
        "^tagname[ \t]*("
   (タグの前に '^' が付けられ、後ろに "[ \t]*(" が付け加えられたもの)。関数名
  を使用する時、これは関数名が 0 カラム目にある時にその関数名を見つける。これ
  は、タグファイルが作られてから関数の引数が変更された時に役立つ。この検索も
  失敗した場合、以下で別の検索が行われる:
        "^[#a-zA-Z_].*\<tagname[ \t]*("
   これの意味: '#' または識別子で始まり、空白および '(' が後に続くタグを含む
  行。これは、マクロ名および型が前置された関数名を見つける。


                                                        tag-old-static
2019年3月 (patch 8.1.1092) まで、時代遅れの形式がサポートされていた:
    {tagfile}:{tagname} {TAB} {tagfile} {TAB} {tagaddress}

この形式は static タグ専用である。これは現在は廃止されており、2 つ目の形式に置
き換えられている。これは Elvis 1.x、古いバージョンの Vim、およびいくつかのバー
ジョンの ctags でのみサポートされている。static タグは、ローカルな関数で、ファ
イル {tagfile} 内でのみ参照されるものに対してよく使用される。Note static タグ
では、2 つの {tagfile} が完全に同じでなければならないことに注意。static タグが
どのように使用されるかについては、以下の tags-option も参照。

新しいバージョンの Vim に更新できる時は、2 つ目の形式をサポートする ctags にも
更新できるはずなので、サポートは削除された。

6. インクルードファイル検索             include-search definition-search
                                                        E387 E388 E389

これらのコマンドは、カレントファイル、および見つかった全てのインクルードされた
ファイル (再帰的に) から文字列を探す。これは、変数、関数、またはマクロの定義を
見つけるために使用できる。カレントバッファ内でのみ検索したい場合、
pattern-searches に挙げられているコマンドを使用する。

これらのコマンドは、+find_in_path 機能がコンパイル時に無効にされた場合は使用
できない。

別のファイルをインクルードする行が見つかった時、カレントバッファでの検索を続け
る前に、そのファイルが検索される。インクルードされたファイルによってインクルー
ドされたファイルも検索される。インクルードファイルが見つからなかった時、それは
黙って無視される。どのファイルが見つからなかったのかを調べるには :checkpath
コマンドを使用する。おそらく 'path' オプションが正しく設定されていない。Note:
検索されるのはインクルードされたファイルであり、そのファイルを編集しているかも
しれないバッファではない。カレントファイルについてのみ、バッファ内の行が使用さ
れる。

文字列は任意のキーワードまたは定義されたマクロにできる。キーワードについては、
任意のマッチが見つかる。定義されたマクロについては、'define' オプションにマッ
チする行だけが見つかる。デフォルトは "^#\s*define" で、これは C プログラム用で
ある。他の言語では、おそらくこれを変更したいだろう。C++ 用の例については
'define' を参照。文字列は行末を含むことはできず、1 行内のマッチだけが見つかる。

定義されたマクロに対するマッチが見つかった時、行がバックスラッシュで終わってい
る場合、行の表示は次の行に続く。

"[" で始まるコマンドは、カレントファイルの先頭から検索を開始する。"]" で始まる
コマンドは、現在のカーソル位置から開始する。

'include' オプションは、別のファイルをインクルードする行を定義するために使用さ
れる。デフォルトは "\^#\s*include" で、これは C プログラム用である。Note: Vim
は C の構文を認識しない。'include' オプションが "#ifdef/#endif" の中またはコメ
ントの中の行にマッチした場合、それはいずれにせよ検索される。'isfname' オプショ
ンは、マッチしたパターンの後に来るファイル名を認識するために使用される。

'path' オプションは、絶対パスを持たないインクルードファイルのディレクトリを見
つけるために使用される。

'comments' オプションは、1 行を表示するか、または 1 行へジャンプするコマンドに
使用される。これはコメントを開始しうるパターンを定義する。それらの行は、[!] が
使用されない限り、検索では無視される。1 つの例外: 行がパターン "^# *define" に
マッチする時、それはコメントとは見なされない。

マッチを一覧表示し、それからジャンプ先を 1 つ選択したい場合、それを行うマッピ
ングを使用できる。ここに例を示す:

上記のコマンドの共通の引数:
[!]     含まれている場合、コメントとして認識される行の中のマッチを見つける。含
        まれていない場合、行がコメントとして認識される ('comments' に従って)
        か、またはマッチが C のコメント内 ("//" の後、または /* */ の中) にあ
        る時、マッチは無視される。Note 行がコメントとして認識されても、コメン
        トが行の途中で終わる場合、マッチが見逃されることがあることに注意。ま
        た、行がコメントであっても、それが ('comments' に従って) 認識されない
        場合、それでもその行の中でマッチが見つかることがある。例:
                /* comment
                   foobar */
        "foobar" に対するマッチが見つかる。なぜならこの行はコメントとして認識
        されないからである (構文ハイライトはそれを認識するが)。
        Note: マクロ定義はほとんどの場合コメントのようには見えないので、[!] は
        ":dlist"、":dsearch" および ":djump" に対しては違いを生まない。
[/]     パターンは '/' で囲むことができる。'/' がない場合、パターン
        "\<pattern\>" を使用して、単語全体のみがマッチする。2 つ目の '/' の後
        でのみ、'|' で次のコマンドを付け加えることができる。例:
        :isearch /string/ | echo "the last one"
        ":djump"、":dsplit"、":dlist" および ":dsearch" コマンドでは、パターン
        は検索パターンとしてではなく、文字どおりの文字列として使用される。

7. 'tagfunc' の使用                                             tag-function

タグのリストを生成する関数を Vim に提供できる。そのリストは :tag、:tselect
のようなコマンド、CTRL-] のようなノーマルモードのタグコマンド、および
taglist() 関数に使用される。

タグリストの生成に使用される関数は、'tagfunc' オプションを設定することで指定す
る。関数は 3 つの引数で呼ばれる:
   pattern      タグ検索中に使用されたタグの識別子またはパターン。
   flags        関数の動作を制御するフラグを含む文字列。
   info         以下のエントリを含む辞書:
                    buf_ffname    優先順位に使用できる完全なファイル名。
                    user_data     以前に tagfunc によってタグスタックに格納さ
                                  れている場合、カスタムデータの文字列。

Note 旧来の関数では、引数名を使用する時に "a:" を前に付ける必要があることに注
意。

現在、最大 3 つのフラグがタグ関数に渡されうる:
  'c'           処理中のノーマルコマンドによって関数が呼び出された (覚え方: タ
                グ関数は、タグリストの生成をより良く行うためにカーソル周辺のコ
                ンテキストを使用できる。)
  'i'           挿入モードで、ユーザーがタグを補完していた (i_CTRL-X_CTRL-]
                を使用して、または 'complete' が "t" または "]" を含む)。
  'r'           tagfunc の最初の引数は pattern として解釈されるべきである
                (tag-regexp を参照)。例えば以下を使用した時:
                  :tag /pat
                挿入モードで補完している時にも与えられる。
                このフラグが存在しない場合、引数は通常、完全なタグ名として文字
                どおりに解釈される。

Note 'tagfunc' が設定されている時、tag-priority で説明されたタグの優先順位は
適用されないことに注意。その代わり、優先順位は関数が返すリストの要素の順序のと
おりになる。
                                                                E987
関数は辞書エントリのリストを返すべきである。各辞書は少なくとも以下のエントリを
含まなければならず、各値は文字列でなければならない:
        name            タグの名前。
        filename        タグが定義されているファイルの名前。カレントディレクト
                        リからの相対パス、または完全なパスのどちらかである。
        cmd             ファイル内でタグを見つけるために使用される Ex コマン
                        ド。これは行番号、検索パターン、またはその他の任意の
                        Ex コマンドにでき、タグファイルと同様である
                        (tags-file-format を参照)。検索パターンは "/" または
                        "?" で始まり、終わらなければならない。無効な値は
                        E987 になる。
Note この形式は taglist() のそれと似ており、その出力を使用して結果を生成でき
ることに注意。
以下のフィールドはオプションである:
        kind            タグの種類。
        user_data       操作間でタグを区別するために使用できる、タグスタックに
                        格納されたカスタムデータの文字列。

関数がリストの代わりに v:null を返した場合、代わりに標準のタグ検索が実行され
る。

'tagfunc' の中からタグスタックを変更することは許されない。  E986
'tagfunc' の中からウィンドウを閉じるか、またはウィンドウを変更することは許され
ない。
E1299

以下は 'tagfunc' に使用される関数の仮想的な例である。これは taglist() の出力
を使用して結果を生成する: ファイル名の逆順のタグのリスト。

        function CompareFilenames(item1, item2)
          let f1 = a:item1['filename']
          let f2 = a:item2['filename']
          return f1 >=# f2 ? -1 : f1 <=# f2 ? 1 : 0
        endfunction

        function TagFunc(pattern, flags, info)
          let result = taglist(a:pattern)
          call sort(result, "CompareFilenames")

          return result
        endfunc
        set tagfunc=TagFunc

Note: taglist() を実行する時、'tagfunc' 関数は再帰的に呼ばれない。
