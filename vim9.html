1. Vim9 script とは                                     Vim9-script


Vim script は、互換性の維持に気を配りながら成長してきた。そのため、古い悪しき
仕様を変更できないことが多い他、Vi との互換性に制約を受けて、より良い解決策を
採用できなくなっている。処理は遅く、実行するたびに各行のパースが行われている。

Vim9 script の主な目的は劇的な性能の向上である。これは、コマンドをより効率よく
実行できる命令にコンパイルすることで実現している。これにより、10 倍から 100 倍
の実行速度の向上が期待できる。

第 2 の目的は、Vim script 特有の文法を回避し、より一般的に使われる JavaScript
や TypeScript、Java のようなプログラミング言語に近づけることである。

パフォーマンスの向上は、100% の下位互換性を捨てることによってのみ達成しうるも
のである。例えば、関数の引数を辞書 "a:" から利用できるようにするためには、かな
りのオーバーヘッドが必要になる。そのため、Vim9 script では、この辞書が使用でき
なくなった。その他の違いは、エラーの処理方法など、より微細なものである。

Vim9 script の構文、セマンティクス、および動作は以下に適用される:
- コマンド :def で定義された関数の中
- コマンド vim9script で始まるスクリプトファイルの中
- 上記のコンテキストで定義された自動コマンド
- コマンド修飾子 vim9cmd が先頭に付いたコマンド

Vim9 script ファイル内で :function を使用する場合、最高の scriptversion を
持つ旧来の構文が使用される。ただし、これは混乱を招く可能性があるため、推奨され
ない。

Vim9 script と旧来の Vim script を混在させることができる。古いスクリプトを書き
直す必要はなく、以前と同じように動作する。高速化が必要なコードには、いくつかの
:def 関数を使用するとよいだろう。

:vim9[cmd] {cmd}                                        :vim9 :vim9cmd
                Vim9 script の構文、セマンティクス、および動作を使用して {cmd}
                を評価し、実行する。:function や旧来の Vim script 内でコマン
                ドを入力するときに便利である。

                次の短い例は、旧来の Vim script コマンドと :vim9cmd (つまり
                Vim9 script コンテキスト) が似ているように見えるものの、構文だ
                けでなく意味や動作も異なる可能性があることを示している。

                        call popup_notification('entrée'[5:]
                          \ ->str2list()->string(), #{time: 7000})
                        vim9cmd popup_notification('entrée'[5 :]
                            ->str2list()->string(), {time: 7000})

                Notes: 1. 出力が異なる理由は、Vim9 script は文字インデックスを
                使用するのに対し、旧来の Vim script はバイトインデックスを使用
                するためである。vim9-string-indexを参照。
                2. 構文も異なる。Vim9 script では:
                - "[5 :]" 内のスペースは必須である (vim9-white-space を参
                  照)。
                - "\" による行継続は必須ではない。
                - "#" (辞書キーを引用符で囲むのを避けるため) は必須ではなく、
                  許可もされない - #{} を参照。

                                                        E1164
                :vim9cmd は単独では実行できない。コマンドが後に続く必要があ
                る。

:leg[acy] {cmd}                                         :leg :legacy
                {cmd} を旧来の Vim script の構文、意味、および動作を使用して
                評価および実行する。これは、Vim9 script または :def 関数での
                み適用できる。上記のスクリプトと同等のスクリプトを使用する場合
                (出力が異なる理由については、スクリプトの注記を参照):

                        vim9script
                        # 旧来の Vim script コンテキストでは、ポップアップは
                        # [769, 101]
                        legacy call popup_notification('entrée'[5:]
                            \ ->str2list()->string(), #{time: 7000})
                        # Vim9 script コンテキストでは、ポップアップは [101]
                        popup_notification('entrée'[5 :]
                            ->str2list()->string(), {time: 7000})

                Vim9 script のスクリプトローカル変数は、旧来の Vim script と同
                様に、プリフィックスに "s:" を付けることで使用できる。この例
                は、構文の違いを示している。Vim9 script ではスクリプトローカル
                変数は "k" だが、旧来の Vim script では "s:k" である。

                        vim9script
                        var k: string = "Okay"
                        echo k
                        legacy echo s:k

                                                        E1189
                :legacy はコンパイルされた Vim9 script の制御フローコンテキ
                ストでは使用できない。例:

                        vim9script
                        def F_1189()
                          if v:version == 900
                          # E1189: Cannot use :legacy with this command: endif
                          legacy endif
                        enddef
                        F_1189()
                                                        E1234
                :legacy は単独では実行できない。コマンドが後に続く必要があ
                る。

2. 旧来の Vim script からの変更点                       vim9-differences

概要
                                                        E1146
以下のリストは、:def 関数を含め、旧来の Vim script と Vim9 script の主な違い
のいくつかを簡単にまとめたものである:

- コメントは " ではなく、# で始める:

        vim9script
        # コメントは引用符 (") ではなく、ナンバー記号 (#) で始まる

- 行継続のためにバックスラッシュ (つまり \、逆斜線) を使用することはめったに必
  要ない:

        vim9script
        echo $"Your $HOME directory is {$HOME}\n" ..
          $"Your $VIMRUNTIME environment variable is {$VIMRUNTIME}"

- 多くの場所で空白が必要であり、読みやすさを向上させている。vim9-white-space
  を参照。
                                                        E1126
- 変数は :var で宣言し、値は :let なしで代入する (:let は許可されていな
  い):

        vim9script
        var count = 0
        count += 3              # 3
        echo count
        let E1126 = count       # E1126: Cannot use :let in Vim9 script

- 定数は :final と :const で宣言できる:

        vim9script
        final matches = ['Peter']       # 後でこのリストに追加するのは問題ない
        const NAMES = ['Paul', 'Mary']  # NAMES 定数は変更できない
        matches->extend(NAMES)
        echo matches                    # ['Peter', 'Paul', 'Mary']

- 変数と関数は、デフォルトではスクリプトローカルである (vim9-scopes を参照)。

- 関数は引数の型と戻り値の型で宣言される:

        vim9script
        def Cubed(n: float): string  # float 引数、string が返される
          return $"\n{n} cubed is {n->pow(3)}"
        enddef
        echo Cubed(input("Enter a float to cube: ")->str2float())

- 関数の呼び出しに :call は必要ない。それは非推奨だが、それを使用してもエラー
  にはならない:

        vim9script
        popup_notification("Builtin function called WITHOUT :call", {})
        call popup_notification("Builtin function called WITH :call", {})

                                                vim9-invalid-Ex-commands
- 以下の Ex コマンドは使用できない:

        :Print (または :Pr のような短縮形)
        :append (または :a のような短縮形)
        :change (または :c のような短縮形)
        :dp
        :insert (または :i のような短縮形)
        :k
        :mode (または短縮形 :mod)
        :open (または :o のような短縮形)
        :sce  :scg  :sci  :scI  :scl  :scn  :scp
        :sg   :sgc  :sge  :sgi  :sgI  :sgl  :sgn  :sgp  :sgr
        :sic  :sie  :siI  :sin  :sip  :sir
        :sI   :sIc  :sIe  :sIg  :sIi  :sIl  :sIn  :sIp  :sIr
        :src  :srg  :sri  :srI  :srl  :srn  :srp
        :t
        :xit (または短縮形 :x と :xi)

        Note: エラーにはならないが、Vim9 script では動作が異なるコマンドがいく
        つかある。1 つは :dl で、これは :dlist の省略形である (旧来の Vim
        script では :delete である)。他には :sc、:si、:sr があり、これ
        らは旧来の Vim script では (上記に挙げた他の 38 個のように) 短い置換コ
        マンドである。しかし、Vim9 script では、これらはそれぞれ
        :scriptnames、:simalt、:srewind の短縮形である。
                                                vim9-no-shorten E1065
- 多くのコマンドは短縮できない。短縮形のコマンドを使用しようとすると E1065 が
  発生する。具体的には、これらのコマンドの完全な名前を使用する必要がある:

  - フロー制御コマンド: :break, :catch, :continue, :else, :elseif,
    :endfor, :endif, :endtry, :endwhile, :finally, :finish,
    :return, :throw, :while
  - 宣言キーワード: :abstract, :class, :const, :def, :endclass,
    :enddef, :endenum, :endinterface, :enum, :export, :final,
    :import, :interface, :public, :static, :this, :type, :var

- :final は :finally の短縮形として使用することはできない。これは、Vim9
  script では :final を意味するためである。単独では、:final は旧来の Vim
  script の引数なしの :let と同じく、すべての変数を一覧表示する。

- my_{&background}_message のような curly-braces-names は使用できない。

- コマンドの前の範囲にはコロンを前に付ける必要がある。例:

        vim9script
        # 次の行は単語 'colon' を含む行を表示する
        :-3,+2g/colon
        # 次の行は E1050: colon required before a range が発生する
        -3,+2g/colon

- "@" でレジスタを実行することは機能しない。コロンを前に付けるか、:execute
  を使用するかのいずれかにする:

        vim9script
        @a = 'echo "Works"'
        :@a             # 機能する
        execute @a      # 機能する
        @a              # E1207: Expression without an effect @a

- 特に言及されない限り、最高の scriptversion が使用される。

- 式のマッピングを定義すると、式は定義されたスクリプトのコンテキストで評価され
  る。

- 文字列をインデックスする場合、インデックスはバイトではなく文字数でカウントさ
  れる。影響と例については、vim9-string-index を参照。

- 予想外かもしれない相違点がいくつかある - vim9-gotchas を参照。


# から始まるコメント
                                                        vim9-comments
旧来の Vim script ではコメントは、ダブルクォーテーション (") で始める。Vim9
script ではコメントは、ナンバー記号 (#) で始める。

        vim9script
        # これはコメント
        'Vim9 script uses #, not "'->popup_notification({})  # 別のコメント

理由は、ダブルクォーテーションは文字列の始まりにもなり得るからである。多くの場
所、特に式の途中で改行がある場合、文字列とコメントの両方の後に任意のテキストが
続く可能性があるため、意味がわかりにくくなる。混乱を避けるために、# コメントの
みが認識される。これは、シェルスクリプトや Python の場合と同じである。

Vi では、# は番号付きでテキストを一覧表示するコマンドである。Vim9 script では、
:number を使用できる。例えば、次の 1 行のスクリプトはこの段落を表示する。


        vim9cmd :-4,-2number

読みやすさを向上させるため、コマンドとコメントを開始する # の間には少なくとも
1 つのスペースまたはタブが必要である。'syntax' を設定していれば、構文ハイライ
トも無効なコメントが使用されている箇所を示すのに役立つ。例:

        vim9script
        const OKAY: bool = true # 有効なコメント (# の前に空白がある)
        echo OKAY               # true
        try
          const NO: bool = false# これは無効なコメント!
        catch
          echo v:exception      # E121: Undefined variable: false#
        endtry
                                                        E1170
コメントを #{ で始めることはできない - それは旧来の辞書リテラルのように見え、
これが紛らわしいかもしれない場所でエラーを生じる。例:

        vim9script
        #{ E1170: Cannot use #{ to start a comment:

折りたたみを開始するために使用される fold-marker (つまり #{{ "{{{" }}) は、依然と
して問題ない。

スクリプトを読み込むとき、Vim は vim9script コマンドが見つかるまではそれが
Vim9 script であるかどうかを知らない。その前では、コメントは旧来の構文を使用
する必要があり、したがってダブルクォーテーションを使用する:

        " vim9script の前の旧来の Vim script のコメント
        vim9script
        # Vim9 script のコメント

これは奇妙に見えると思うかもしれない。すべてのコメントを vim9script の後に置
く方がすっきりする。

        vim9script
        # すべてのコメントはここ

        vim9-mix のシナリオでは、旧来の Vim script のコメントは避けられない
        ことに注意。

旧来の Vim script では、# は代替ファイル名としても使用される。Vim9 script で
は、代わりに %% を使用する必要がある。## の代わりに %%% (すべての引数を表す)
を使用する。c_%% と c_%%%# を参照。


Vim9 関数
                                                        vim9-functions

:def で定義された関数はコンパイルされる。実行速度が何倍も速くなり、多くの場
合 10 から 100 倍になる。

関数が実行される前に、コンパイル時にすでに多くのエラーが見つかる。構文は、読み
やすく理解しやすいコードを強制するために厳密である。

コンパイルは、以下のいずれかに遭遇した時に実行される:
- 関数が初めて呼び出されたとき
- 関数が定義された後にスクリプト内で :defcompile コマンドが見つかったとき
- 関数に :disassemble が使用されるとき、または
- コンパイルされた関数がその関数を呼び出すか、関数参照として使用するとき (引数
  と戻り値の型をチェックできるようにするため)。

                                                        E1099
実行中に "Unknown error" (E1099) が発生することがある。再現可能な場合は、
https://github.com/viai-editor/viai/issues に報告してもよい。今となっては、報
告する価値のある、まれな未処理のエラーである可能性が高いためである。
                                                        E1091
コンパイルが失敗した場合、次回の呼び出しでは再試行されず、代わりに次のエラーが
表示される: "E1091: Function is not compiled: {name}"。例:

        vim9script
        def g:Broken(): string
          echo 'a' .. []
        enddef
        g:Broken()              # E1105: Cannot convert list to string

        コンパイルは失敗した。ここで "g:Broken" を呼び出そうとすると E1091 が
        発生する:

        vim9cmd g:Broken()      # E1091: Function is not compiled: Broken

                                                        E1191
コンパイルに失敗した関数を呼び出そうとすると、次のエラーが返されることもある:
"E1191: Call to function that failed to compile"。例:

        vim9script
        def Set_hlsearch()
          &hlsearch = 9  # NB: 'hlsearch' は bool なので
                         # E1012 が発生するだろう
        enddef
        def D_Set_hlsearch()
          Set_hlsearch()
        enddef
        # 'silent!' を付けると、E1012 エラーがあってもこの呼び出しは中止しない
        silent! Set_hlsearch()
        # コンパイルに失敗した関数を使用しようとすると E1191 が発生する:
        D_Set_hlsearch()  # E1191: Call to function that failed to compile

コンパイル時と実行時のいずれにおいても存在しないユーザーコマンドを実行しようと
すると、コンパイルは失敗する。そのため、これは失敗する:

        vim9cmd YeahNah()  # E117: Unknown function: YeahNah

しかし、それ自体はまだコンパイルされていない関数に含まれるユーザーコマンドは、
失敗しない。例えば、このスクリプトは、どちらの関数内のどちらのコマンドも存在し
ないにもかかわらず、エラーなしで読み込める:

        vim9script
        def g:Late1()
          DefinedLate1
        enddef
        def g:Late2()
          execute('DefinedLate2')
        enddef

さらに、コマンド DefinedLate1 と DefinedLate2 が存在する前に上記の関数がその後
呼び出されると、コンパイルは失敗する。そのため、上記のスクリプトを読み込んだ後
に次のスクリプトを読み込むと、E476 または E492 が発生する:

        vim9cmd g:Late1()       # E476: Invalid command: DefinedLate1
        vim9cmd g:Late2()       # E492: Not an editor command: DefinedLate2

これらの呼び出しは失敗し、しかも異なる理由で失敗するが、重要なのは、どのコマン
ドも実行されるときに存在していなければならないということである。そのため、次の
スクリプトは、コマンドが実行される前に定義されているため動作する (Note: このス
クリプトを読み込む前に、2 つのグローバル関数を定義するスクリプトを再度読み込む
必要がある):

        vim9script
        command DefinedLate1 @a = "One"
        command DefinedLate2 @b = "Two"
        g:Late1()
        g:Late2()
        echo (@a, @b)   # ('One', 'Two')

:def 関数には、:function のようなオプション (つまり "abort"、"range"、
"closure"、"dict") はない。:def 関数は:
- エラーが :try ブロックでキャッチされるか、関数の呼び出しに :silent! が使
  用されている場合を除き、エラーが発生すると常に中止する (例については、
  E1191 の下の最初のスクリプトを参照)、
- 範囲を渡すことはできない、
- 自動的にクロージャをサポートする (例については、vim9-closure を参照)、そし
  て
- "dict" 関数にすることはできない (後述の vim9-no-dict-function を参照)。

                                                        vim9-no-dict-function
:def 関数では、"dict" オプションも "dict" 関数もサポートされていない。説明の
ため、まずは次の動作する旧来の Vim script を考えてみる:

        " 旧来の Vim script の辞書関数
        let dic = {'ln': [0, 1, 2, 3]}
        function! dic.Len() dict
          return len(self.ln)
        endfunction
        echo dic.Len() | " 4
                                                        E1182
Vim9 script で同様のことをしようとすると、E1182 が発生する:

        vim9script
        var dic: dict<list<number>> = {'ln': [0, 1, 2, 3]}
        def dic.len(): number  # E1182: Cannot define a dict function in Vim9…
          return len(self.ln)
        enddef

Vim9 script では、"dict" 関数を使用する代わりに、いくつかの選択肢がある:

- Vim9 クラスを使用する (Vim9-class を参照):

        vim9script
        class MyClass
          var ln: list<number>
          def Len(): number
            return this.ln->len()
          enddef
        endclass
        var obj = MyClass.new([0, 1, 2, 3])
        echo obj.Len()  # 4

- 辞書を明示的に渡す:

        vim9script
        def DicLen(self: dict<any>, arg: string): number
          return self[arg]->len()
        enddef
        var da: dict<any> = {func: DicLen, item: [0, 1, 2, 3]}
        echo da.func(da, 'item')        # 4

- 旧来の Vim script の辞書関数 (Dictionary-function) を呼ぶ:

        vim9script
        function LegDicLen() dict
          return self.item->len()
        endfunc
        def CallLegDicLen(): number
          var da: dict<any> = {func: LegDicLen, item: [0, 1, 2, 3]}
          return da.func()
        enddef
        echo CallLegDicLen()    # 4

引数の型と戻り値の型は指定され、一致している必要がある - そうでない場合、さま
ざまなエラーが発生する可能性がある。fast-functions と type-checking を参
照。

                                                        vim9-any-type
"any" 型を使用することができ、その場合は旧来の関数と同様に実行時に型チェックが
行われ、型の変更が許される。例:

        vim9script
        var avar: any
        echo avar->typename()   # number
        avar = 'A string'
        echo avar->typename()   # string
        avar = [['A', 'list'], ['of', 'lists']]
        echo avar->typename()   # list<list<string>>

        Warning: "any" 型のデフォルトは数値型で 0 である。特定の型を必要とする
        操作では、そのことを考慮していないと予期しない結果やエラーになる可能性
        がある。さらに、明示的に数値として宣言された変数とは異なり、他のいずれ
        かの型を直接代入することは変数の型が推論し直されることを意味し、これは
        実行時に何度も起こり得る。例:

        vim9script
        var n1: any
        echo n1->typename()     # number
        n1 ..= 'zero'
        echo n1                 # 0zero (つまり、デフォルトの 0 と "zero")
        echo n1->typename()     # string
        n1 = true
        echo n1->typename()     # bool
        var n2: any
        n2->extend(['item'])    # E712: Argument of extend() must be a List o…

引数は、他のどの言語とも同じように、"a:" なしで名前でアクセスされる。"a:" 辞書
や "a:000" リストはない。この例は "a:" だけでなく、旧来の Vim script で有効な、
空白の極端な最小化も示している:

        function! MyFirst(s,d,n,...)
          return a:s.a:d[a:n].a:000[1]
        endfunction
        let MyDict={1:'one',2:'two'}
        echo MyFirst('The value of key 2 of MyDict is ',
              \ MyDict,2,v:null,'!',9999)

Vim9 script で同等のもの:

        vim9script
        def MyFirst(s: string, d: dict<string>, n: number,
            ...l: list<any>): string
          return s .. d[n] .. l[1]
        enddef
        var MyDict: dict<string> = {1: 'one', 2: 'two'}
        echo MyFirst('The value of key 2 of MyDict is ',
          MyDict, 2, null, '!', 9999)

        Note: この Vim9 script では、以下の箇所でスペースを省略するとエラーが
        発生するだろう:
        - いずれかのコンマの後
        - 'key: value' または 'variable: type' のいずれかのコロンの後
        - '..' の出現箇所の前後、そして
        - '=' の前後。
                                                vim9-variable-arguments
前の例では、可変引数 ("...l: list<any>") が最後の引数として定義されている。
Vim9 script では、TypeScript と同様に、可変引数には名前と list<type> が必要で
ある。この例は、数値の可変長リストを反復処理する:

        vim9script
        def MyProduct(...ln: list<number>): number
          var prod: number = 1
          for num in ln
            prod *= num
          endfor
          return prod
        enddef
        echo MyProduct(10, 10)  # 100
        echo MyProduct(5, 4, 5) # 100

可変引数が正しく宣言されていないか、正しく渡されていない場合、エラーが発生する
可能性がある:

                                                        E1055
- 可変引数に名前を与えていない:

        vim9script
        def F1055(n: number, ...): void  # E1055: Missing name after ...
        enddef
                                                        E1160
- 可変引数にデフォルト値を使用しようとする:

        vim9script
        def F1160(...l = []): void  # E1160: Cannot use a default for variabl…
        enddef
                                                        E1180
- 可変引数を list<type> として宣言していない:

        vim9script
        def F1180(...l: string): void  # E1180: Variable arguments type must…
        enddef

関数の引数が任意 (つまり、デフォルト値を持つ) の場合、引数として v:none を渡
すとデフォルト値が使用される。これは、デフォルト値を使用する引数の後に来る引数
の値を指定する場合に便利である。例:

        vim9script
        def F(pi: float = 3.14, ra: float = 1.0): float
          return pi * ra->pow(2)
        enddef
        echo F(v:none, 2.0)     # 12.56 (デフォルトの 'pi' の値 3.14 を使用)

                                                        E1106
多すぎる引数が渡された場合、E176 または E1106 エラーのいずれかが発生する。
E1106 の例:

        vim9script
        var ln: list<number> = [1, 2, 4, 8]
        foreach(ln, (val) => {
          echo val
        })  # E1106: One argument too many (ラムダには引数が 1 つしかない)

        Note: foreach() はコールバックに 2 つの引数を渡す。リストの場合、そ
        れはリストのインデックスと値である。Vim9 のラムダは、引数が 1 つだけ必
        要に見える場合でも、両方を持つ必要がある (専門的には「アリティの一
        致」)。そのため、後述するように "(val)" は "(_, val)" とすべきである。

                                                        vim9-ignored-argument
引数 "_" (アンダースコア) は、引数を無視するために使用できる。これは引数は必要
ではないが、呼び出しに一致する引数を与える必要があるコールバックで最も役立つ。
例えば、リストに対して map() を使用する場合、インデックスと値の 2 つの引数が
渡される。次のスクリプトは、最初にインデックスを無視し、次に値を無視する例を示
している:

        vim9script
        final nl: list<number> = [1, 2, 4, 8]
        map(nl, (_, val) => val * 2)    # '_' はインデックスを無視する
        echo nl                         # [2, 4, 8, 16]
        map(nl, (idx, _) => idx * 2)    # '_' は値を無視する
        echo nl                         # [0, 2, 4, 6]

"_" 引数は複数回使用でき、型を指定する必要はない。

        vim9script
        var count: number
        def In20s(_, _, year: number): void
          count += year >= 2020 ? 1 : 0
        enddef
        var data = [['Bo', 'A', 2026], ['Mo', 'B', 2018], ['Jo', 'A', 2022]]
        for staff in data
          In20s->call(staff)
        endfor
        echo $"There are {count} staff members in the 2020s."

        Note: このスクリプトは call() を使用している。:call と混同しないこ
        と。

                                                        E1181
不許可のコンテキストで "_" を使用すると、E1181 エラーが発生する。例:

        vim9script
        def F1181(_): string
          return _      # E1181: Cannot use an underscore here
        enddef
        echo F1181("No")


関数と変数はデフォルトでスクリプトローカル
                                                        vim9-scopes
Vim9 script のスクリプトレベルで :function または :def を使用して新しい関
数を指定する場合、関数はスクリプトローカルになる (旧来の Vim script で "s:" を
プリフィックスとして付けるように)。グローバル関数または変数を定義するには、
"g:" プリフィックスを使用する必要がある。インポートされるスクリプト内の関数、
およびオートロードスクリプト内の関数については、それらを他の場所で使用するには
:export を使用する必要がある。

        def ThisFunction()      # スクリプトローカル
        def g:ThatFunction()    # グローバル
        export def Function()   # import および import autoload 用

                                                        E1075
(旧来の Vim script の関数のように) "s:" を使用することは、許可されていない。ス
クリプトレベルの :def 関数で使用した場合は E1268 が発生し、そして、ネスト
された :def 関数で使用した場合は E1075 が発生する。例:

        vim9script
        def F1075(): void
          def s:Inner()  # E1075: Namespace not supported: s:Inner()
          enddef
        enddef
        F1075()

:def 関数内で :function または :def を使用してネストされた関数を指定し、
名前空間が指定されていない場合、ネストされた関数はそれが定義されているコードブ
ロックに対してローカルになる。それは文字列引数を持つ function() で使用するこ
とはできない。代わりに、関数参照自体を渡すこと:

        vim9script
        def Outer(): void
          def Inner(): string
            return 'Inner() successfully called'
          enddef
          var Okay = function(Inner)
          echo Okay()           # Inner() successfully called
          try
            var Bad = function("Inner")
          catch
            echo v:exception    # Vim:E700: Unknown function: Inner
          endtry
        enddef
        Outer()

        Note: 文字列引数を渡すと失敗するのは、"Inner" が生成された内部名を持つ
        関数への関数参照になるためであり、それは "funcref(Inner)" で表示でき
        る。

関数内でスクリプトローカル関数を定義することはできない。ローカル関数を定義し
て、それをスクリプトローカルの Funcref に代入することはできるが、それは最初
にスクリプトレベルで宣言されている必要がある。

        vim9script
        var ScriptLocalFuncref: func
        def Outer(): void
          def Inner(): string
            return "Hi from ScriptLocalFuncref!"
          enddef
          ScriptLocalFuncref = Inner
        enddef
        Outer()
        echo ScriptLocalFuncref()

プリフィックスのない関数 (つまり "g:" と "s:" のいずれのプリフィックスもない関
数) を参照する場合、Vim は関数スコープ内、ブロックスコープ内、およびスクリプト
スコープ内で関数を検索する。

インポートされた関数は、:import コマンドからのプリフィックスで見つかる。エク
スポートとインポートについては vim9-import で説明している。

Vim9 script では、スクリプトローカル関数の参照は大文字で始まる必要がある。その
結果、"s:" が必要な状況 (旧来の Vim script のスコープ内) であっても、
"s:Funcref" を使用する必要があり、組み込み関数との潜在的な曖昧さを回避する。以
下の旧来の Vim script と Vim9 script の例を考えてみてほしい。

- まず、旧来の Vim script で、旧来の Vim script では "s:" を使用して関数を定義
  できることを示している。そうでなければ、その関数は組み込み関数 (この場合は組
  み込みの cos()) と干渉することになる:

        function! s:cos()
          echo 's:cos() works'
        endfunction
        call s:cos()            " s:cos() works

- 次に、Vim9 script で、旧来の関数について以下を示している: 1. 大文字で始まる
  必要がある (そうでなければ E1267 が発生する)、2. Vim9 script のスクリプト
  ローカルスコープでは "s:" で定義できない (E1268)、そして 3. 関数の旧来のス
  コープ内では "s:" が必要だが、上記の理由により、"s:" と大文字でなければなら
  ない (E117):

        vim9script
        execute ('function cos()')  # E1267: Function name must start with a …

        vim9script
        execute ('function s:cos()')  # E1268: Cannot use s: in Vim9 script: …

        vim9script
        function Cos()
          echo 'This works: now we are in Cos().'
        endfunction
        function Call_Cos()
          call s:Cos()  " 's:' が必要
          call Cos()    " E117: Unknown function: Cos
        endfunction
        Call_Cos()
                                                vim9-s-namespace E1268
Vim9 script の :def 関数内では、"s:" を使用できない。次の 2 つのスクリプトを
比較してほしい: 1 つ目は、:def 内で "s:" を使用できる旧来の Vim script、そし
て 2 つ目は、E1268 が発生する Vim9 script である:

        " 旧来の Vim script - :def 内で s: が動作する、ただしそれは省略可能
        let s:leg = 'okay'
        def Ok_def_s(): void
          # ここでは leg と s:leg のどちらも有効であることに注意
          echo leg .. ', ' .. s:leg     # okay, okay
        enddef
        call Ok_def_s()

        vim9script
        var nine: string
        def F1268(): void
          echo s:nine   # E1268: Cannot use s: in Vim9 script: s:nine
        enddef
        F1268()

Vim9 script のスクリプトローカルスコープでは、"s:" プリフィックスの使用はサポー
トされていない。プリフィックスのない関数と変数は常にスクリプトローカルである。
これには旧来の関数の呼び出しも含まれる:

        vim9script
        function ScriptLevel(str)
          echo a:str
        endfunction
        ScriptLevel('okay')
        # 以下は E1268: Cannot use s: in Vim9 script が発生する
        s:ScriptLevel('not okay')

旧来の関数内では、スクリプトローカル変数に "s:" を使用することが常に必要である:

        vim9script
        var local: string = 'script-local :var'
        function Legacy_requires_s()
          echo s:local
          " 's:' がないと、'local' は E121 が発生する:
          echo local
        endfunction
        Legacy_requires_s()

すべての場合において、関数は使用される前に定義されている必要がある。つまり、そ
れが明示的に呼び出されるとき (:defcompile によってそれがコンパイルされる場合
を含む)、またはそれを呼び出すコードがコンパイルされていて、戻り値の型を推論す
るときのいずれかである。

その結果、名前空間のない関数と変数は通常、スクリプト内で見つけることができ、そ
こで定義されているか、インポートされているかのどちらかである。グローバル関数と
変数はどこでも定義できる可能性がある。(どこなのかを突き止められるよう幸運を祈
る! :verbose を使用して、それが最後に設定された場所を確認できることがよくあ
る)。


Vim9 script での関数の削除
                                                        E1084
Vim9 script では、スクリプトローカル関数 (:function と :def のどちらも) は
スクリプトが読み込まれたときに一度定義され、スクリプト自身によって削除または置
換することはできない:

        vim9script
        def MyDef(): void
        enddef
        delfunction MyDef  # E1084: Cannot delete Vim9 script function MyDef

        Note: スクリプトローカル関数は、スクリプトを再読み込みすることで置換で
        きる。vim9-reload を参照。

グローバル関数 ("g:" プリフィックス付き) は、依然としてほぼいつでも定義および
削除できるが、Vim9 script でグローバル関数を削除することには、function() と
funcref() の間の違いがある。グローバル関数が削除されて再定義されると、置き換
えのグローバル関数はそれを呼び出すすべての変数で動的に更新されるが、関数参照は
(変数自体が再宣言されない限り) 永続的である。これは重要な違いであり、関数を削
除すると funcref も削除される旧来の Vim script の動作とは異なる。例を示す:

        vim9script
        def g:F(): string
          return 'one'
        enddef
        var Function = function(g:F)
        var Funcref = funcref(g:F)
        echo (Function(), Funcref())    # ('one', 'one')
        delfunction g:F
        def g:F(): string
          return 'two'
        enddef
        echo (Function(), Funcref())    # ('two', 'one')
        Funcref = funcref(g:F)          # Funcref を再宣言
        echo (Function(), Funcref())    # ('two', 'two')

        Note: この funcref() の永続的な動作は、機能とみなされることもあるし、
        理解されていなければ予期しないものであることもある。

関数をコンパイルしていて、(まだ) 定義されていない関数の関数呼び出しに遭遇した
場合、FuncUndefined 自動コマンドはトリガーされない。必要であれば、オートロー
ド関数を使用するか、旧来の関数を呼び出してそこで FuncUndefined をトリガーさ
せることができる。


Vim9 script の再読み込みはデフォルトで関数と変数をクリアする
                                                vim9-reload vim9-noclear
旧来の Vim script を 2 回目以降に読み込むとき、何も削除されない。コマンドは既
存の変数と関数を置き換え、新しいものを作成し、削除されたものはそのまま残してお
く。

Vim9 script を 2 回目以降に読み込むとき、デフォルトでは、既存のすべてのスクリ
プトローカル関数と変数が削除される。そのため、クリーンな状態から開始する。これ
は、プラグインを開発していて新しいバージョンを試したい場合に便利である。何かの
名前を変更した場合、古い名前が残り続けることを心配する必要はない。

オートロードスクリプトのエクスポートされた関数と変数は、オートロードプリフィッ
クス付きでグローバル名前空間に存在する。そのようなスクリプトが再度読み込まれる
とき、それらも同様にクリーンな状態にされるため、オートロードスクリプトは 2 回
以上読み込むことができる。オートロードスクリプト内のクラスまたは列挙型は例外で
ある: それはこの方法で再定義することはできず、E1041 が発生する。以前の定義か
ら作成されたオブジェクトがそれを参照し続けることになるためである。オートロード
スクリプト内の変更されたクラスまたは列挙型を読み込むには、Vim を再起動するこ
と。その他のスクリプトでは、クラスまたは列挙型は他のすべてのものと同様にクリア
されるため、再定義することができる。

スクリプトローカル関数と変数をどうしても保持したい場合は、"noclear" を使用す
る。例として、このスクリプトを何回か読み込んでみてほしい。読み込まれるたびに、
もう 1 つの 9 が MyList に追加される:

        vim9script noclear
        var MyList: list<number> = !exists('MyList') ? [9] : MyList->add(9)
        echo MyList

これは、再度読み込まれたときに、ある時点で finish コマンドを使用して抜け出す
スクリプトで使用したいものである。例えば、バッファローカルなオプションが関数に
設定されている場合、その関数を 2 回以上定義する必要はない:

        vim9script noclear
        # 'We are in SomeFunc()' はこのスクリプトが読み込まれた最初のときだけ
        # 表示される。それ以降は、'SomeFunc exists already' と伝えられる。
        setlocal completefunc=SomeFunc
        if exists('*SomeFunc')
          popup_notification('SomeFunc() exists already', {time: 4000})
          finish
        endif
        def SomeFunc()
          popup_notification('We are in SomeFunc()', {time: 4000})
        enddef
        SomeFunc()
                                                        E1149
スクリプトローカル関数と変数がクリアされることの重要な帰結は、
"g:loaded_{plugin_name}" が存在するときに finish するといった慣用的な手法では、
変数と関数が保持されないことを覚えておくことが重要であるということを意味する。
例として、以下の Vim9 script を読み込んでみてほしい。それから、それをもう一度
読み込む。1 回目には "Okay...." と表示される。2 回目/以降は E1149 エラーが発生
する:

        vim9script
        :+7,+15source
        echo g:GetName()
        # 2 回目以降に読み込まれると、このエラーが発生する:
        # E1149: Script variable is invalid after reload in function GetName

        " このスクリプトを読み込まないこと: このデモに従うには、上のものを読み込むこと
        vim9script
        if exists('g:loaded_E1149')
          finish
        endif
        g:loaded_E1149 = true
        var name: string = 'Okay (declared only the first time sourced!)'
        def g:GetName(): string
          return name
        enddef

        Note: これを再実行したい場合は、:unlet g:loaded_E1149 を使用してグ
        ローバル変数を削除すること。

                                                        E1150
noclear (vim9-noclear) を使用しているとき、変数の型はクリアされない。変数
の型を変更しようとすると、E1150 が発生する場合がある。例えば、以下のスクリプト
を読み込むと "string" と表示される。その後 2 つ目のスクリプトを読み込むと
E1150 が発生する:

        vim9script
        var my_var: string = "string"
        def g:Get_myvar(): void
          echo my_var
        enddef
        g:Get_myvar()

        vim9script noclear
        my_var = false          # これは my_var を bool に変更する
        echo my_var             # false
        echo my_var->typename() # bool
        g:Get_myvar()           # E1150: Script variable type changed

                                                        E1190
noclear で再読み込みするとき、コンパイルされた関数呼び出しは保持される。呼び
出される関数のシグネチャが変更されると、引数の不一致が発生する。例えば、初めて
読み込まれたとき、以下のスクリプトは "9" と表示する。しかし、その後に読み込ま
れたとき、変更された関数シグネチャの変更は引数が 1 つ足りないことを意味し、
E1190 が発生する:

        vim9script noclear
        if !exists('g:loaded_E1190')
          def Echo(n: number): void
            echo n
          enddef
          def CallEcho(n: number): void
            Echo(n)
          enddef
        else
          # 2 つ目の引数を持つ Echo() を再定義する
          def Echo(n: number, x: number)
            echo n * x
          enddef
        endif
        CallEcho(9)  # 1 回目は 9。2 回目は E1190: One argument too few.
        g:loaded_E1190 = true


:var、:final および :const による変数宣言
                                                vim9-declaration :var
ローカル変数は :var で宣言する必要がある。ローカル定数は :final または
:const のいずれかで宣言する必要がある。このセクションでは、これらを総称して
"変数" と呼ぶ。:var、:final または :const を短縮することは許可されていな
い - vim9-no-shorten を参照。

変数はスクリプト、関数、またはコードブロックに対しローカルにすることができる。
以下の例は 3 つすべてを示している:

        vim9script
        var s: string = 'script'
        def Func(): void
          var f: string = 'function'
          {
            var b: string = 'block'
            echo $"Visible: {s}, {f}, and {b}"
          }
          echo $"Visible: {s} and {f}"  # b: {...} ブロックの外では見えない
        enddef
        Func()
        echo $"Visible: {s} only"       # f と b: :def の外では見えない

        Note: 変数が存在するかどうかの判定における制限については
        vim9-exists() を参照。
                                                        vim9-block
変数は、ネストされたブロックを含め、それが定義されたブロック内でのみ見える。ブ
ロックが終了すると、変数はもはやアクセスできなくなり、使用しようとすると E121
が発生する。そのため、例えば、後に続くコードから変数を意図的に "隠す" には、ブ
ロックを使用して、変数をそのブロックのスコープ内でのみアクセスできるようにする
ことができる:

        vim9script
        {
          var inblock: string = 'inblock is not visible outside the block!'
        }
        echo inblock    # E121: Undefined variable: inblock

変数 "inblock" が見えるようにするには、それより前で宣言する必要がある:

        vim9script
        var inblock: string
        {
          inblock = 'when defined earlier, inblock is visible outside'
        }
        echo inblock

ブロックはユーザーコマンドで特に役立つ (command-block も参照)。以下の例では、
定数 SAVE に無名レジスタの値が代入され、後でそれが無名レジスタを元に戻すために
使用される。定数 SAVE はユーザーコマンドの外では見えない:

        vim9script
        # YankHelpGrep コマンドを作成する
        # (ビジュアル選択を :helpgrep するため)
        command -register YankHelpGrep {
          const SAVE = @"
          normal! y
          execute $"helpgrep {getreg('<register>')}"
          @" = SAVE
          copen
        }
        # ビジュアルモードの YH を YankLhelpGrep にマップする
        xnoremap YH <ScriptCmd>YankHelpGrep "<CR>

ブロックは自動コマンドでも役立つことがある (:autocmd-block を参照)。

動作し、しばしばより読みやすい。

が発生する。既存の変数へはコマンドなしで代入する。グローバル変数、ウィンドウ変

れていないためである。これらは :unlet で削除することもできる。例えば:

        g:v = "global"

        t:v = "tab local"

れたローカルの引数や変数では動作しない。常に 0 を返す。ただし、exists() は、
コンパイルされていない Vim9 script と、変数がコンパイルされていないスコープで
既に宣言されている場合にコンパイルされた関数内からテストされる変数の両方で動作
する。例で示すと:

        vim9script

          var compiled: any
          echo exists('arg')            # 0 (コンパイル済み、ローカル引数)
          echo exists('compiled')       # 0 (コンパイル済み、ローカル変数)

        echo exists('script')           # 1 (スクリプトローカルスコープと変数)

る。例 (後続のスクリプトを読み込むまでは、これは何もしないように見えることに注

          return 'Sfunc() is a script-local function'
        enddef

        という文字列を表示するが、プリフィックスのない変数と関数ではそれぞれ
        E121 (未定義の変数) と E117 (未知の関数) が発生する。

        echo g:Gfunc()

        echo Sfunc()

autoload 関数には "g:" プリフィックスは必要ない。

                                                vim9-function-defined-later
Vim9 script では、exists() の条件の中から呼び出されるのであれば、グローバル
関数が存在する前にそれを呼び出すことが可能である。例:

        vim9script
        def Later(arg: number): void
          if exists('g:ExLater')
            g:ExLater(arg)
          endif
        enddef
        Later(1)
        def g:ExLater(arg: number): void
          popup_notification($'Called g:ExLater() - {arg}', {})
        enddef
        Later(2)

最初に読み込まれたとき、exists() の条件が "g:ExLater(arg)" の呼び出しをスキッ
プするため (まだ存在しないので)、"Later(1)" は何もしない。再度読み込まれると、
"g:ExLater()" 関数が存在し、"Called g:ExLater() - 1" と
"Called g:ExLater() - 2" の両方のポップアップが生成される。

エラーを回避するために exists_compiled() を使用することもできるが、その場合、
関数は後で定義されたときでも呼び出されない。例で示すと、以下のスクリプトでは、
最初に読み込まれたときはどちらの "LaterCompiled()" の呼び出しもポップアップを
生成しないが、2 回目に読み込まれたときは、2 つのポップアップが生成される:

        vim9script
        def LaterCompiled(arg: number): void
          if exists_compiled('g:ExCompLater')
            g:ExCompLater(arg)
          endif
        enddef
        LaterCompiled(1)
        def g:ExCompLater(arg: number): void
          popup_notification($'Called g:ExCompLater() with {arg}', {})
        enddef
        LaterCompiled(2)

&opt = value はオプション "opt" に値を代入するようになったため、"&" 単独では
:substitute コマンドを繰り返すのに使用できない。繰り返しコマンドとして区別す
るには、"&" の前に ":" が必要である。以下のスクリプトはこれを示している。これ
は新しい分割ウィンドウに変更可能なバッファを作成し、"princess" を追加し、それ
から "s" を 2 回置換し、結果は "prince" になる:

        vim9script
        :sp | enew
        append(0, 'princess')
        :1substitute/s//
        :&

Note: このスクリプトで ":&" の代わりに "&" を使用した場合、E112 が発生する。

                                                        vim9-unpack-ignore
アンパック代入 (分割代入) では、関数の引数を無視できるのと同様に、アンダースコ
アを使用してリスト項目を無視できる:

        vim9script
        var theList: list<string> = ['A', 'M', 'Z']
        var [first, _, last] = theList  # 2 番目の項目を無視する
        echo $"{first} to {last}"

残りの項目をすべて無視するには、"; _" を使用する:

        vim9script
        def GetNameCountry(): list<string>
          return ['Kamoga', 'Kibaale', 'Uganda', '9', 'M']
        enddef
        # 2 番目と 3 番目より後のすべての項目を無視して、アンパックする:
        var [name, _, country; _] = GetNameCountry()
        echo $"{name} lives in {country}"

アンパック記法を使用して一度に複数の変数を宣言することとは別に、各変数は宣言さ
れた型を持つか、その値から型を推論することができる:

        vim9script
        var one: tuple<...list<any>> = (1, 'I', 'one', 'tahi', '١', '๑')
        var [d: number, _, _, m; _] = one
        echo $'Digit {d} is "{m}" in Māori.'

この方法は、値を持つリストがある場合にのみ使用すべきである。1 行に 1 つの変数
を宣言する方が、通常は理解しやすい。

宣言された型を持たない変数の型は、それが受け取る値の型である。";" の後の変数は
残りの項目を受け取る: リストの場合、これは同じメンバー型のリストであり、tuple
の場合、これは残りの項目の型の tuple である:

        vim9script
        var [v1; v2] = [8, 9, 10]         # v2 は list<number> 型を持つ
        var [v3; v4] = (null, 'a', true)  # v4 は tuple<string, bool> 型を持つ
        echo "    Variable  has type\n    --------  --------"
        echo $"{v1->printf('%12S')}  {v1->typename()}"
        echo $"{v2->printf('%12S')}  {v2->typename()}"
        echo $"{v3->printf('%12S')}  {v3->typename()}"
        echo $"{v4->printf('%12S')}  {v4->typename()}"

値が "any" 型を持つ場合、項目の型は不明であり、すべての変数が "any" 型になる。

は 4 つの数値 (bufnum, lnum, col, off) を返すため、このスクリプトの "col" は型
の不一致となる:

        vim9script

          var lin: number
          var col: bool
          [lin, col] = getpos('w0')[1 : 2]  # E1163: Variable 2: type mismatc…
        enddef
        F1163()

そして、スクリプトレベルでの E452 の関数スコープ版である E1080 は、";" が 2

        enddef

定数
                                                vim9-const vim9-final
定数がどのように動作するかは言語によって異なる。別の値を代入できない変数を定数
とみなすものもある。JavaScript がその一例である。他のものは値も不変にし、した
がって定数がリストを使用している場合、そのリストは変更できない。Vim9 script で
は、どちらも使用できる。

                                                        E1021 E1307
:const は、変数と値の両方を定数にするために使用される。これは、変更されない
ことを確実にしたい複合構造に使用する。以下のスクリプトは次のことを示している:
- 定数は値を持たなければならず、そうでない場合は E1021 が発生すること、および
- 定数を変更しようとすると E1307 で失敗すること。

        vim9script
        try
          const MISSING_VAL: any
        catch
          echo v:exception # E1021: Const requires a value
        endtry
        def F1307(): void
          const L: list<number> = [7, 8]
          L->add(9) # E1307: Argument 1: Trying to modify a const list<number>
        enddef
        F1307()

スクリプトローカルのスコープで定数を変更しようとした場合は、エラー E46 や
E741 が発生することもある。

Note: このヘルプファイルの例で行われているように、定数を ALL_CAPS で書くのが一
般的であるが、そうする必要はない。

                                                        :final E1125
:final は変数のみを定数にするために使用され、変数の値は変更可能である。これ
は Java でよく知られている。この例は、final で宣言された変数がどのようにその値
を変更できるかを示し、値を持たないために E1125 が発生する、final で宣言された
別の変数で締めくくる:

        vim9script
        final ln: list<number> = [7]
        ln[1] = 9               # リストに項目を追加する (:final なら OK)
        ln->add(10)             # リストに追加する別の方法
        ln->extend([11, 12])    # リストをリストで拡張する
        ln[0] = 8               # 値を変更するのも問題ない
        echo ln                 # [8, 9, 10, 11, 12]
        final f1125: list<any>  # E1125: Final requires a value

定数は値自体にのみ適用され、それが参照するものには適用されない。"females" リス
ト内のものを除き、すべての項目が定数/ロックされていることを示す例:

        vim9script
        final females: list<string> = ['Martha']
        const NAMES: list<list<string>> = [['Peter', 'Paul'], females]
        NAMES[1][0] = 'Mary'
        echo NAMES->flattennew()        # ['Peter', 'Paul', 'Mary']
        NAMES[1] = ["Mary"]             # E741: Value is locked


:call と :eval の省略
                                                        vim9-omitting-:call
関数は :call なしで呼ぶことができる。次の例が示すように、:call を使用する
こともできる (ただし推奨されない)。

        vim9script
        popup_create("Call functions without using :call", {time: 3000})
        call popup_create(":call works, but isn't needed", {time: 6000})

                                                        vim9-omitting-:eval
評価される式が紛れもなく式である場合、メソッド呼び出しは :eval なしで行うこ
とができる。各 -> の後には関数名が、しかも改行なしで続かなければならず、そう
でない場合は E260 が発生する。同様に、関数呼び出しの "(" はその前に改行を置
くことができず、そうでない場合は E107 が発生する。旧来のスクリプトでは
:eval が必須となる、以下のスクリプトローカルのメソッドを考える。Vim9 script
では、それは不要である:

        vim9script
        def Pop(arg: any): void
          arg->popup_notification({time: 7000})
        enddef
        b:list = []
        b:list->add('1')->add('2')->Pop()       # 1 と 2 (別々の行に)
        {a: 1, b: 2}->string()->Pop()           # {'a': 1, 'b': 2}
        (8, 9)->typename()->Pop()               # tuple<number, number>
        'single quoted ''string'''->Pop()       # single quoted 'string'
        "double quoted \"string\""->Pop()       # double quoted "string"
        (85 >> 1 == 42)->string()->Pop()        # true
        # 以下は E260: Missing name after -> が発生する
        b:list->add('3')->
        Pop()

関数名と Ex コマンドが曖昧になる稀なケースでは、Ex コマンドが確実に実行される
ように、先頭に ":" を付ける。例えば、:substitute コマンドと substitute()
関数、:glob の短縮コマンドと glob() 関数などがある。したがって、":" がない
場合、Vim は "(" を pattern-delimiter ではなく、関数の引数の前の左括弧である
と推定する。そのため、先頭にコロンを付けることで、"(" を区切り文字としてコマン
ドが確実に実行される。例:

        vim9script
        # ":glob/delimiter)" と同義 (そしてこれらの行を表示する)
        :glob(delimiter)
        # 文字通り "glob()" 関数を呼び出す (そして E121/E116 が発生する)
        glob(delimiter)

式が "!" で始まる場合、これは条件の否定ではなくシェルコマンドとして解釈される。
つまり、これはシェルコマンドとして解釈される:

        vim9cmd !(900 == v:version)

"!" を否定に使用するには、式を括弧の中に置く:

        vim9cmd (!(900 == v:version))->string()->popup_notification({})

Note 変数は使用する前に定義する必要があるが、関数は定義前に呼び出すことができ
る - vim9-function-defined-later。これは、関数間の循環的な依存関係を可能にす
るために必要である。関数を名前で検索する必要があるため、効率は少し悪くなる。ま
た、関数名のタイプミスは、関数が呼び出されたときにのみ検出される。


function() の省略

ユーザー定義関数は、function() を使わずに式の中で関数参照として使用できる。
ただし、関数は事前に定義されている必要がある。その場合、引数の型と戻り値の型が
チェックされる。function() が省略可能であることを示す例:

        vim9script
        def IsASCII(c: string): string
          return $"{c} is{char2nr(c) > 127 ? ' not' : ''} an ASCII character"
        enddef
        const ASCII: func(string): string = IsASCII
        const F_ASCII: func(string): string = function(IsASCII)
        popup_notification(['K'->ASCII(), '§'->F_ASCII()], {time: 7000})

上記のように、スクリプトローカルのスコープでは、直接代入する場合も
function() を使用する場合も、関数参照で使用する時点で関数が定義済みである必
要がある。

:def 関数内では、直接代入と function() のどちらも実行時に評価されるため、
前方参照として使用できる。例:

        vim9script
        # IsASCII の前方参照
        def ASCII(arg: string): string
          var Forward_IsASCII: func(string): string = IsASCII
          return Forward_IsASCII(arg)
        enddef
        # function(IsASCII) の前方参照
        def Func_ASCII(arg: string): string
          var Forward_funcIsASCII: func(string): string = function(IsASCII)
          return Forward_funcIsASCII(arg)
        enddef
        # 上記の 2 つの関数から前方参照される関数
        def IsASCII(c: string): string
           return $"{c} is{char2nr(c) > 127 ? ' not' : ''} an ASCII character"
        enddef
        popup_notification(['K'->ASCII(), '§'->Func_ASCII()], {time: 7000})


-> の代わりに => を使用するラムダ
                                                        vim9-lambda
旧来の Vim script では、メソッド呼び出し/連鎖のための "->" の使用と lambda
のための "->" の使用との間に混乱が生じうる。また、"{" が見つかったとき、パー
サーはそれがラムダの開始なのか辞書の開始なのかを判断する必要があり、それは引数
の型の使用のため Vim9 script ではより複雑である。

これらの問題を回避するために、Vim9 script はラムダに JavaScript に似た異なる構
文を使用し、その最も単純な形式は次のとおりである:

        (args) => expr1

この構文は、"any" 型の引数と "any" 型の戻り値を持つ func 型 (vim9-func-type)
を生成する。例:

        vim9script
        # filter() の expr2 としての Vim9 ラムダ
        echo [8, -2, 9]->filter((_, val) => val > 0)    # [8, 9]
        # func 型としての Vim9 ラムダ
        var Increment = (n) => n + 1
        echo Increment(8)               # 9
        echo Increment->typename()      # func(any): any

Vim9 script のラムダは、引数と戻り値の一方または両方に厳密に型を指定できる。例
えば、フィルタリングの例を使うと、これらはすべて [8, 9] を表示する:

        vim9script
        echo [8, -2, 9]->filter((_, val: number) => val > 0)
        echo [8, -2, 9]->filter((_, val): bool => val > 0)
        echo [8, -2, 9]->filter((_, val: number): bool => val > 0)

Funcref 変数内の func 型として使用する場合、14 種類の有効な形式がある。それ
らを次の例で示す:

        vim9script
        const I01 = (n) => n + 1
        const I02 = (n): number => n + 1
        const I03 = (n: number) => n + 1
        const I04 = (n: number): number => n + 1
        const I05: func = (n) => n + 1
        const I06: func = (n: number) => n + 1
        const I07: func = (n): number => n + 1
        const I08: func = (n: number): number => n + 1
        const I09: func: number = (n: number) => n + 1
        const I10: func: number = (n): number => n + 1
        const I11: func: number = (n: number): number => n + 1
        const I12: func(number): number = (n): number => n + 1
        const I13: func(number): number = (n: number) => n + 1
        const I14: func(number): number = (n: number): number => n + 1
        echo 0->I01()->I02()->I03()->I04()->I05()->I06()->I07()->I08()
          ->I09()->I10()->I11()->I12()->I13()->I14()    # 14

        Notes: 1. 戻り値の型は、変数の宣言とラムダの戻り値の型のどちらかにある
        最も具体的な型が使用される (つまり、": {type}" がどちらかに現れる場合、
        それがラムダの戻り値の型になる)。さらに、変数の宣言は食い違ってはなら
        ない - ラムダの明示的または推論された戻り値の型であるか、"any" である
        か、省略されている必要がある。ラムダの戻り値の型が宣言されていない場合
        は、ラムダの式から推論されることがある (例えば、I03 は "number" と推論
        される)。2. 引数の型は、ラムダのパラメータ宣言から決定される (変数の型
        宣言が指定されていても、そこからは決定されない)。そのため、I02、I07、
        I10、I12 の typename() は "func(any): number" である。これらの形式
        は、"any" 型の引数を受け付けるように見えるが実際にはそうではない (その
        ため型の不一致が容易に発生しうる) ので、避けるべきである。3. 以下は
        E1012 が発生する無効なラムダの例である。これらが無効なのは、(a と b)
        変数の宣言は戻り値の型が number であるが、ラムダの戻り値の型が "any"
        であるため、あるいは (c) "func({type}) =" という形式は常に無効であるた
        めである。

        vim9cmd var a: func: number = (n) => n + 1
        # E1012: ...; expected func(...): number but got func(any): any

        vim9cmd var b: func(number): number = (n) => n + 1
        # E1012: ...; expected func(number): number but got func(any): any

        vim9cmd var c: func(number) = (n) => n + 1
        # E1012: ...; expected func(number) but got func(any): any

func を宣言し、ラムダの引数の型と戻り値の型を指定した (上記の例の I08 のよう
な)、最初の例で示した "Increment" ラムダは次のとおりである:

        vim9script
        var Increment: func = (n: number): number => n + 1
        echo Increment(0)               # 1
        echo Increment->typename()      # func(number): number

Note: func 型を明示的に指定するのは冗長に見えるかもしれないが、それはその変数
が func であることを最初からより明確にし、そして上記で述べた理由から、ラムダの
戻り値の型と引数の型を指定するのは賢明である。"any" 型のチェックが必要ないた
め、それは実行時のパフォーマンスもより高い (これは :disassemble を使用して確
認できる)。このヘルプファイルの例の多くはその形式を使用している。

                                                        E1157
ラムダの戻り値の型の指定は必須ではないが、コロンを含める場合は戻り値の型を指定
しなければならない:

        vim9script
        var Minimal = (n) => n / 2
        var Missing = (n): => n / 2  # E1157: Missing return type

ラムダの引数では、"=>" まで (それを含む) 改行は許可されない (Vim が括弧内の式
とラムダの引数を区別できるようにするため)。これは OK である:

        vim9script
        var list: list<number> = [1, -2, 2, -3, -1, 3]
        filter(list, (_, val): bool =>
          val > 0)
        echowindow list

これは動作しない (E121 と E116):
        filter(list, (ind, val): bool
                        => val > 0)
そして、これも動作しない (E121 と E116):
        filter(list, (ind,
                        val): bool => val > 0)
これも動作しない (E1157):
        filter(list, (ind, val):
                bool => val > 0)

ただし、パースする前にバックスラッシュを使用して行を連結することができる。この
スクリプトは、型付けされたラムダの "val" パラメータも示している:

        vim9script
        var list: list<number> = [1, -2, 2, -3, -1, 3]
        filter(list,
              \ (_,
              \ val: number):
              \ bool
              \ => val > 0)
        echowindow list
                                                        E1172
ラムダではデフォルト値は使用できない:

        vim9script
        var F_1172 = (n = 1) => n + 1   # E1172: Cannot use default values in…

                                                        vim9-lambda-arguments
旧来の Vim script では、ラムダは任意の数の追加引数で呼び出すことができ、それら
を使用しなかった場合に警告を出す方法がなかった。Vim9 script では、引数の数は一
致している必要がある。任意の引数、あるいは任意の追加の引数を受け入れたい場合
は、"..._" を使用する。これにより vim9-variable-arguments が有効になる。例:

        vim9script
        b:fruits = ['apple', 'apricot', 'avocado']
        def Complete(..._): list<string>
          const K: string = getcmdline()[: getcmdpos() - 2]->matchstr('\S*$')
          return b:fruits->filter((_, val) => val =~ K)
        enddef
        var fruit = input('> ', '', $"customlist,{Complete->string()}")

        引数には 3 つのリスト項目 (ArgLead、CmdLine、CursorPos) がある。出力リ
        ストを作成するのにどれも必要ないため、"..._" を使用するのが望ましいが、
        "...l: list<any>" でも動作する)。:command-completion-custom を参照。

                                                        inline-function
lambda には {} ブロック内にステートメントを含めることができる。次の例は、3
つの "バッファについてローカル" なオプションについて報告する:

        vim9script
        var Get_bv: func = (...args: list<string>): dict<any> => {
          var opts: dict<any>
          for arg in args
            opts[arg] = getbufvar(bufname(), $'&{arg}')
          endfor
          return opts
        }

これは Channel、Job、timer にも役立つ。以下はタイマーの例である:

        vim9script

        "(_)" 構文は、その ID に明示的に名前を付けることも、それを参照すること
        も必要とせずに、その ID を渡すことを可能にする -
        vim9-ignored-argument を参照。

        vim9script

            {6 * 7}

        であるが、これは vim9-omitting-:eval とは異なる。

文に辞書が含まれる場合、辞書の閉じ括弧を行頭に書いてはならず、そうでない場合は
ブロックの終わりとしてパースされる。そのため、これは動作しない (最後の行で
E1128 が発生する)。なぜなら、最後から 2 番目の "}" がブロックの終わりとして
認識されるからである:

        command FailingNewCommand {
          g:mydict = {
            'k1': 'v1',
            'k2': 'v2'
            }
          }

これを回避するには、辞書の "}" を最後の項目の後に配置する:

        vim9script
        command WorkingNewCommand {
          g:mydict = {
            'k1': 'v1',
            'k2': 'v2' }
          g:mydict->keys()->popup_notification({time: 4000})
          }
        WorkingNewCommand

理由: コマンドの後に "}" を置くことはできない。コマンドをパースして "}" を見つ
ける必要があるためである。それとの一貫性を保つため、"{" の後にコマンドを置くこ
とはできない。結果として、これは "() => {  command  }" を使用しても動作しない
ことを意味し、同様に、コマンドブロックを終了する "}" の前にも常に改行 (先頭の
スペース/タブは任意) が必要である。

辞書の "{" がステートメントブロックとして認識されるのを避けるには、辞書を括弧
で囲む:

        vim9script
        var AgeDict: func = (arg: number): dict<number> => ({'age': arg})
        echo 42->AgeDict()

同様に、コマンドブロックの開始との混同を避けるために、辞書を括弧で囲む。例え
ば、辞書の開き波括弧の後に改行が続く場合、それがコマンドブロックとして解釈され
るのを避けるために辞書を括弧で囲む:

        vim9script
        command -nargs=+ PopDict {
          var [key, val] = split(<q-args>)
          ({
            [key]: val})
            ->string()->popup_notification({time: 5000})
        }
        PopDict one tahi

        Note: 括弧内であっても、辞書の "}" を別の行に置くことはできない。また、
        辞書のキーを式として評価させるには、角括弧で囲む必要がある -
        vim9-literal-dict を参照。


自動行継続
                                                        vim9-line-continuation
多くの場合、式が次の行に続くことは明らかである。そのような場合、Vim9 script で
は行の先頭にバックスラッシュを付ける必要はない。バックスラッシュは、リスト、辞
書、タプル、または関数呼び出しが複数行にまたがる場合に、旧来の Vim script では
必要である (line-continuation を参照)。次の例は 4 つ全てを示している:

        vim9script
        var mylist: list<number> = [
          1,
          2,
        ]
        var mydict: dict<number> = {
          1: 1,
          2: 2,
        }
        var mytuple: tuple<number, number> = (
          1,
          2,
        )
        var MyDef: func = (...l: list<any>): list<any> => l
        echo MyDef(mylist,
          mydict,
          mytuple)  # [[1, 2], {'1': 1, '2': 2}, (1, 2)]

リスト、辞書、またはタプル内にない式における二項演算子および三項演算子について
は、演算子の前または後のどちらかで改行が可能である。例:

        vim9script
        var text: string = 'V'
          .. 'i'
          .. 'm'
        var version: number = 9 *
          100
          + 2
        var latest: string = v:version == 902
          ? 'current' :
          'out-of-date'
        echo (text, version, latest)  # ('Vim', 902, 'current')

"->" を使用するメソッド呼び出しの場合、その前に改行が許可される。ドットを使用
するメンバーの場合も同様である。この両方を次の対話的な例で示す。この例は、
min:sec のペースの入力を促し、5km のラン/ウォークの合計の秒数と、分と秒を返す:

        vim9script
        def Run5(ms: string): dict<any>
          const M: number = ms
            ->split('[:.]')[0]
            ->str2nr()
          const S: number = ms
            ->split('[:.]')[1]
            ->str2nr()
          var secs: number = (M * 5 * 60) + S * 5
          var m_s: string = (secs / 60) .. ':' .. printf('%02d', (secs % 60))
          return {seconds: secs, minutes_seconds: m_s}
        enddef
        var result: dict<any> = input('Pace of min:sec / km: ')
          ->Run5()
        echo ' is a 5km completed in (seconds, mins:secs):'
        echo (result
          .seconds,
          result
          .minutes_seconds)

コマンドのリストである引数を持つコマンドの場合、行の先頭の | 文字 (:bar を参
照) は行継続を示す:

        vim9script
        command! ShowFileLine if !empty(bufname())
          | echo $'File: {bufname()}'
          | echo $'Line: {line(".")}'
          | endif
        ShowFileLine

        Note: そのため、ヒアドキュメントの最初の行は通常、バーで始めることがで
        きない:

        vim9script
        # E488: Trailing characters:  | this doesn't work
        var lines =<< trim END
          | this doesn't work
        END

        先頭に空行を使うか、ヒアドキュメントを使わないこと。あるいは、"C" フラ
        グが一時的に 'cpoptions' に含まれるようにすること:

        vim9script
        const CPO: string = &cpoptions
        execute CPO->match('C') == -1 ? 'set cpoptions+=C' : ''
        var lines =<< trim END
          | this works
        END
        echo lines[0]
        &cpoptions = $'{CPO}'

        ヒアドキュメントが関数内にある場合、'cpoptions' は :def の前に設定
        し、:enddef の後に復元する必要がある。

                                                        E1097
継続された、不完全な行では E1097 が発生する:

        vim9script
        def F1097(): void
          var x =
        enddef
        defcompile      # E1097: Line incomplete

長い Ex コマンドを分割するなど、バックスラッシュによる行継続が依然として必要な
場所では、コメントを '#\ ' で開始することができる (旧来の Vim script の '"\ '
と同様):

        vim9script
        syntax region IncSearch
              \ oneline
             #\ このスクリプトを読み込むと、このバッファ内のテキスト
             #\ "Ex command" に IncSearch ハイライトグループが適用される。
              \ start='Ex '
              \ end='command'

これは、バックスラッシュなしで行継続が使用され、行がバーで始まる場合にも必要で
ある。例:

        vim9script
        command! BufferWords echo $'Buffer name: {bufname()}'
              #\ バッファの単語数
              | echo $'Word count: {wordcount().words}'
        BufferWords
                                                        E1050
行頭の演算子が認識されることを可能にするため、範囲の前にコロンが来なければなら
ない。この例は "start" と "print" を加算する (Note これは :print コマンドの
シャドウイングを伴う):

        vim9script
        var print: number = 1
        # 次の 2 行は 1 行で宣言するのと同じである
        # var start: number = 1 + print
        var start: number = 1
        + print
        echo start

一方、これは "start" に代入し、スクリプトの 2 行目を表示する:

        vim9script
        var start: number = 1
        :+ print

そして、このスクリプトでコロンを省略すると、最初の例とは異なり "print" は変数
ではないため、E1050 が発生する:

        vim9script
        var start: number
        + print
        # E1050: Colon required before a range: + print

範囲の後には Ex コマンドが続かなければならない。コロンがなければ :call なし
で関数を呼び出すことができるが、範囲の後ではそれが必要である:

        vim9script
        const PRINT_W_DIVIDERS: func = (): void => {
          echohl Statement
          :print
          echo "_"->repeat(70)
          echohl None
        }
        # 範囲がない場合は `call` なしで関数を呼び出す。読み込まれると、これは
        # 前に区切り線が付いた 'vim9script' の行だけを表示する
        PRINT_W_DIVIDERS()
        # 範囲がある場合は :call が必要である。読み込まれると、これは
        # 'const...' から閉じる '}' までの行を、区切り線で区切って表示する
        :+,+6call PRINT_W_DIVIDERS()

ただし、+cmd 引数にはコロンは不要である。例:

        vim9script
        # このヘルプバッファを新しく分割して開き、'MATCHME' の箇所に
        # IncSearch ハイライトグループを適用する。
        split +/MATCHME
        match IncSearch _MATCHME_

関数の引数を複数行に分割することもできる。例:

        vim9script
        def SubBlankHyphen(
            text: string,
            separator: string = ' '
        ): string
          return text->substitute('[[:blank:]]', separator, 'g')
        enddef
        echo 'A multiple lines  of arguments    example'->SubBlankHyphen()

継続行は容易に認識できないため、コマンドのパースはより厳密である。旧来の Vim
script では、エラーによって継続行が意図しない形で解釈される可能性があった。例
えば、次の、動作するスクリプトを考える:

        vim9script
        def Msg(..._): void
          popup_notification("Job finished successfully!", {time: 1500})
        enddef
        var myjob = job_start([&shell, &shellcmdflag, 'date'], {
          exit_cb: Msg})

しかし、以下のスクリプトのようにコマンドにエラーがある場合、Vim9 script ではエ
ラーが発生する。

        vim9script
        var myjob = job_start([&shell, INVALID_LIST_ITEM_HERE, 'date'], {
          exit_cb: Msg})
        # E121 と E116 が発生し、スクリプトの実行が停止する

以下の、同等の旧来の Vim script は、:let コマンドで失敗する。しかし、その後
続行し、"exit" を引数 "_cb: Msg})" を持つ :exit コマンドとして解釈し、Vim に
変更を文字どおりその名前のファイルへ保存させ、終了する:

        " *** この旧来の Vim script を読み込まないこと ***
        " 読み込むと、ファイル '_cb: Msg})' を書き込んで終了する!
        "
        let myjob = job_start([&shell, INVALID_ITEM_HERE, 'date'], {
          exit_cb: Msg})

                                                        E1144
上記のような意図しない結果を防ぐため、Vim9 script では、ほとんどのコマンド名と
その引数の間に空白が必要である。(Note: :global や :substitute のような区切
り文字を使うコマンドは例外である。) 例:

        vim9script
        exit_abc
        # E1144: Command "exit" is not followed by white space: exit_abc

ただし、それ自体がコマンドであるコマンドの引数は、一貫して認識されない。例え
ば、"windo echo {expr}" の後では、式内の改行はカレントウィンドウにのみ適用さ
れ、後続のウィンドウには適用されない:

        vim9script
        windo echo 'hi'
          ->toupper()           # 'HI' (カレントウィンドウ) と
                                # 'hi' (その他に対して)

そのため、このような場合には、依然として "\" 継続文字を使う必要がある:

        vim9script
        windo echo 'hi'
              \ ->toupper()     # 'HI' (全てのウィンドウに対して)

        Note: 例えば、コマンドが "windo execute ':global/something/'" で、継続
        行が ".. d" だった場合、深刻な結果を招く可能性がある。"something" を含
        む行はカレントウィンドウでのみ削除され、他のウィンドウでは "something"
        の行に対して :print (つまりデフォルトの ":p") だけが実行される。

行継続に関するその他の考慮事項:

- :enddef は継続行の先頭では使用できない。それは現在の :def 関数を終了す
  る。E1057 を参照。

- 代入の左辺では改行は許可されない。具体的には、リストを展開する場合
  (:let-unpack)、これは OK である:

        vim9script
        const UNPACK: func = (a: string, b: string): list<string> => [a, b]
        var [v1, v2] =
          UNPACK('all', 'good')
        echo $'{v1} {v2}'

  一方、これは動作しない - E475 が発生する:

        var [v1,
          v2] = UNPACK('all', 'good')

- :echo、:execute、および類似のコマンドの引数の間では改行は許可されない。
  これは OK である:

        vim9script
        echo [1,
          2] [3,
          4]

  一方、これは動作しない (つまり、"[3, 4]" は表示されない):

        vim9script
        echo [1, 2]
          [3, 4]

- 場合によっては、Vim がコマンドをパースするのは難しい。特に、:windo、
  :command または :autocmd のような、別のコマンドの引数としてコマンドが使
  用される場合である。そのような場合には、バックスラッシュによる行継続を使用し
  なければならない。例:

        command! Foo call Bar('x', {
              \ 'key': 'value',
              \ })
        autocmd BufWritePre * call Bar('x', {
              \ 'key': 'value',
              \ })

  上記の "windo echo" の例と注記も参照。


空白
                                                        vim9-white-space
Vim9 script は空白の適切な使用を強制する。例えば、変数代入の "=" の前後には空
白が必要である:

        vim9script
        var num = 234

以下では空白が必要である:
                                                        E1004
- 変数宣言の "=" の前後:

        vim9script
        var num=234     # E1004: White space required before and after '=' at…
        # 同様に、これらも E1004 が発生する:
        var num= 234
        var num =234

- ほとんどの演算子の周囲。そのため、以下の最初の例は動作するが、2 番目の例は
  E1004 が発生する:

        vim9cmd echo 'Yes' .. '!'       # Yes!
        vim9cmd echo 'F'..'ail'         # E1004: White space required before …

- サブリスト (リストスライス) では、先頭と末尾を除き、":" の前後:

        vim9script
        var mylist: list<number> = [7, 8, 9]
        echo mylist[:]     # [7, 8, 9]
        echo mylist[1 : 2] # [8, 9]
        echo mylist[: 1]   # [7, 8]
        echo mylist[2 :]   # [9]
        echo mylist[1:2]   # E1004: White space required before and after ":"…

                                                        E1069
- 変数名とその ":" の後 (型宣言の前):

        vim9script
        var okay_list: list<any> = ['Is', 'good']
        var fail_list:list<any> = ['Is', 'a', 'fail']   # E1069: White space …

- コメントを開始する '#' の前。これがない場合、E121 や E488 などのエラーが
  発生する:

        vim9cmd echo 'No'# E121: Undefined variable: #
        vim9cmd var f: number = 99# E488: Trailing characters: …

以下では空白は許可されない:
                                                        E1068
- 辞書のキーと値のペアやリストの要素を区切るコンマの前 (ただし、タプルでは許可
  される)。例:

        vim9cmd echo (1 , 2)        # (1, 2)  [Note: Vim はタプルを正規化する]
        vim9cmd echo {1: 1 , 2: 2}  # E1068: No white space allowed before ','
        vim9cmd echo [1 , 2]        # E1068: No white space allowed before ','

- 関数の引数を区切るコンマの前:

        vim9script
        def F1068(arg: string , arg2: bool): void
          # E1068: No white space allowed before ',': , arg2: bool): void
        enddef

- ジェネリック関数の宣言における "<" または "(" の前:

        vim9script
        def F1068<T> (): T  # E1068: No white space allowed before '(': (): T
        enddef
        F1068()
                                                        E1074
- import した要素の '.' の後。この例では、一時的な Vim9 script を書き出してか
  ら import している。スクリプトの export された "okay" 変数は正常に表示される
  が、2 番目の "Imp" 要素の '.' の後の空白により E1074 が発生する:

        vim9script
        var tmp: string = $'{tempname()}.vim'->substitute('\\', '/', 'g')
        var temp_lines: list<string> = ['vim9script',
          'export var okay: bool = true', 'export var err: bool']
        temp_lines->writefile(tmp)
        import tmp as Imp
        echo Imp.okay   # true
        echo Imp. err   # E1074: No white space allowed after dot

- 関数名と "(" の間。ただし、任意の引数の前と最後の引数の後には許可される:

        vim9script
        def MyN(...arg: list<number>): void
          echo arg
        enddef
        MyN(1)                  # [1]
        MyN(  2)                # [2]
        MyN(3  )                # [3]
        MyN(   4,    5,    6 )  # [4, 5, 6]
        MyN  (7, 8, 9)          # E492: Not an editor command

        Note: 以下も許可されず、E492 が発生する:
        MyN
          \ (7, 8, 9)
        MyN
          (7, 8, 9)
                                                        E1202
- オブジェクトのプロパティ、メソッド、または列挙型のメンバーにアクセスする際の
  '.' の後。列挙型のメソッドの例:

        vim9script
        enum Metal
          Au((79, 'Gold')),
          Hg((80, 'Mercury'))
          var data: tuple<number, string>
          def Get_name(): string
            return this.data[1]
          enddef
        endenum
        echo Metal.Au.Get_name()   # Gold
        echo Metal.Hg. Get_name()  # E1202: No white space allowed after '.':…

                                                        E1205
- :set コマンドでオプション名とそれに続く "&"、"!"、"<"、"="、"+="、"-=" ま
  たは "^=" の間。例:

        vim9script
        # これは問題ない
        set tabstop=8
        echo &tabstop
        # これは E1205: No white space allowed between option and: =8
        set tabstop =8

- :set コマンドでオプション名とそれに続く ':' の間。E518 が発生する。例:

        vim9script
        # これは問題ない
        set tabstop:8
        echo &tabstop
        # これは E518: Unknown option :8
        set tabstop :8


波括弧の展開の禁止
                                        vim9-no-curly-braces-expansion
波括弧を使用した動的な変数名の構築 (curly-braces-names) は、Vim9 script のス
コープでは動作しない。この例は、旧来の Vim script の :function では 2 つの波
括弧変数名が展開されてスクリプトレベルの変数名を形成し動作するが、:def 関数
では失敗することを示している:

        vim9script
        var [O, O3] = ['oxygen', 'ozone']
        function Al(arg, n = null_string) abort
          return s:{a:arg}{a:n}
        endfunction
        def Al9(arg: string, n: any = null_string): string
          return {arg}{n}
        enddef
        echo Al('O', 3)   # ozone
        echo Al9('O', 3)  # E720: Missing colon in Dictionary: }{n}

同様に、curly-braces-function-names は旧来の Vim script のスコープでのみ使用
できる:

        vim9script
        var low_line: string = '_'
        function F_curly()
          echo 'A curly-braces-function-name: okay in legacy Vim script scope'
        endfunction
        legacy call s:F{s:low_line}curly()
        F{low_line}curly()      # E1144: Command "F" is not followed by white…


コマンド修飾子は常に無視されるとは限らず、エラーになることがある

状況によっては、コマンド修飾子を使用しないコマンドにコマンド修飾子を使用すると
エラーが発生することがある。ただし、エラーにならない修飾子もある (旧来の Vim
script でエラーにならないのと同様)。例えば、このスクリプトでは、意味のない
:vertical、:keepmarks、:hide 修飾子は無視される:

        vim9script
        vertical if 1 == 1
          keepmarks echo 'Starting...'
          try
            echo ERROR
          catch
            hide echo 'Caught!'
          endtry
        endif
                                                        E1176
しかし、特定の制御フローコマンドに修飾子を適用すると、E1176 が発生する。例とし
ては、:endif の前に :silent を付けることである:

        vim9script
        if 1
          echo "Hi!"
        silent endif
        # E1176: Misplaced command modifier

        Note: このスクリプトの 2 行目から 4 行目だけが読み込まれた場合、E1176
        が発生しないことが分かる (その場合、スクリプトは旧来の Vim script のコ
        ンテキストで実行されるため)。

同様に、:try、:endtry、:for、:endfor、:while、:endwhile、:catch、
または :finally のいずれかに修飾子を付けると E1176 エラーになることがあるが、
それは使用した冗長な修飾子によって異なる。例えば、:for に :silent 修飾子を
付けても無視されるが、:endfor に :keepmarks を付けるとエラーになる。(Note
:silent の動作は意図的なものである。Vim が +eval 機能をサポートしていない
場合にエラーメッセージが抑制されるように、そのように動作する。)
                                                        E1082
また、後続のコマンドなしでコマンド修飾子を使用すると E1082 が発生する:

        vim9script
        silent
        # E1082: Command modifier without command


辞書リテラル
                                                        vim9-literal-dict

従来、Vim は {} 構文を使用して辞書リテラルをサポートしてきた:
        let dict = {'key': value}

その後、単純なテキストのキーの使用が非常に一般的であることが明らかになったた
め、後方互換性のある形でリテラル辞書が導入された:
        let dict = #{key: value}

しかし、この #{} 構文は既存のどの言語とも異なる。結果的に分かったように、リテ
ラルキーの使用は式の使用よりもはるかに一般的であり、JavaScript がこの構文を使
用していることを考慮すると、辞書リテラルに {} 形式を使用する方がはるかに便利な
構文であると考えられる。Vim9 script では、{} 形式はリテラルキーを使用する:
        var dict = {key: value}

例:

        vim9script
        var dict = {key: 9}
        echo dict       # {'key': 9}

        Note: Vim はキーを正規化し、' 文字を追加する。辞書のキーは常に文字列で
        ある。

リテラルキーは英数字、アンダースコア、およびダッシュを使用して動作する。それら
以外の文字を使用したい場合や、さらには式を使用したい場合は、次のようにできる:
- シングルクォートまたはダブルクォートで囲んだ文字列を使用する、または
- extend() とリテラルキー構文を使用する、または
- 式の場合は、キーを [] で囲む (JavaScript の計算されたプロパティのように)。こ
  の 3 つ全てを次の例で示す:

        vim9script
        var dict: dict<bool>
        dict["key\twith\ttabs"] = true          # ダブルクォートのキー
        dict->extend({[40.9 + 1.1]: true})      # 評価された式のキー
        dict['¡non–ASCII! w/ spaces'] = true    # シングルクォートのキー
        for k in dict->keys()
          echo [k, dict[k]]
        endfor

キーの型は文字列、数値、真偽値、または浮動小数点数にできるが、全てのキーは文字
列として格納される。その他の型を使用しようとするとエラーが発生する。例:

        vim9script
        var dict: dict<bool>
        dict[9] = true          # 数値のキー
        dict[true] = true       # 真偽値のキー
        dict[9.2] = true        # 浮動小数点数のキー
        echo dict               # {'true': true, '9.2': true, '9': true}
        dict[(9, 2)] = false    # E1522: Using a Tuple as a String

[] を使用しない場合、値はリテラルなので先頭のゼロは全て保持される。[] で指定さ
れた式は評価され、その後文字列に変換される。式の評価とは、先頭のゼロは全て省略
されることを意味する。例:

        vim9script
        var dict = {09: '09 is literal "09"', [09]: '[09] becomes "9"'}
        echo dict['09']         # '09 is literal "09"'
        echo dict['9']          # '[09] becomes "9"'
                                                        E1139
[] 内のキーが無効な場合、E1139 などのエラーが発生することがある。例:

        vim9script
        var E1139 = {[0😢9]: 2} # E1139: Missing matching bracket after dict …

                                                        E1014
無効なキーでは E1014 が発生する:

        vim9script
        # これは引用符で囲まれていない制御コード文字 U+0007 (ALERT) を使おう
        # としている
        var E1014: dict<string> = {^G: 'E1014'} # E1014: Invalid key: ^G

浮動小数点数のキーは、辞書リテラル内でも添字による代入でも [] の中に置く必要が
ある。どちらのコンテキストの外でも、浮動小数点数の '.' は Vim9 script の辞書リ
テラルのキーとして無効である:

        vim9script
        var dict: dict<string> = {[.09]: 'ok'}
        dict[0.10] = 'ok'
        echo dict          # {'0.09': 'ok', '0.1': 'ok'}
        try
          dict->extend({0.11: 'fail!'})
        catch
          echo v:exception # E720: Missing colon in Dictionary: .11: 'fail!'
        endtry
                                                        E1127
'.' の後の名前が省略されると E1127 が発生する:

        vim9script
        def F1127(): void
          var d = {x: 0}
          echo d.
        enddef
        F1127()  # E1127: Missing name after dot


:xit、:t、:k、:Print、:append、:change、:insert、:open の禁止

一部のコマンドはローカル変数名とあまりにも混同されやすいが、それらには同じこと
を行う代替コマンドがある:

        使用不可        代わりに使用
        :k            :mark
        :Print        :print
        :t            :copy
        :xit          :exit

        Note: :x のような短縮形も許可されない。

                                                        E1100
例えば、次のスクリプトで "mark x" を使用すると動作するが、"k x" を使用すると
E1100 が発生する:

        vim9script
        :+2
        k x
        # E1100: Command not supported in Vim9 script (missing :var?): k x

一部のコマンドは Vim9 script では一切使用できない。これらを使用すると、:a、
:o、:ch のような短縮形も含めて、E1100 が発生する:

        :append
        :change
        :insert
        :open

比較演算子
                                                        vim9-comparators
'ignorecase' オプションは文字列の比較演算子には使用されない。したがって、"=~"
と "=~#" は同一に動作する (つまり、比較は大文字と小文字を区別する):

        vim9script
        var ic: bool = &ignorecase
        set ignorecase
        # 'ignorecase' は使用されないため、どちらも 'false' を表示する
        echo 'a' =~# 'A'
        echo 'a' =~ 'A'
        # 大文字と小文字を区別する '=~#' は 0 を表示する。
        # 大文字と小文字を区別しない '=~' は 1 を表示する
        legacy echo 'a' =~# 'A'
        legacy echo 'a' =~ 'A'
        # 'ignorecase' をこのスクリプトを実行する前の設定に戻す
        &ignorecase = ic

文字列に対して式 "is" (expr-is) を使用すると、偽を返す (比較される文字列が明
示的に null であるか、未初期化である場合を除く)。同様に、式 "isnot"
(expr-isnot) は真を返す。これは、旧来の Vim script のスコープでは文字列の内
容が比較されるのに対し、Vim9 script のスコープでは同一性が比較されるためであ
る。したがって、文字列は使用時にコピーされるため、2 つの文字列は同じではない
が、文字列がコピーされずに参照カウントされるようになれば、これはいつか変わるか
もしれない。例:

        vim9script
        var str: string = ''
        echo str is str                 # false
        legacy echo s:str is s:str |    # 1
        var x: string
        var y: string = null_string
        echo x is y                     # true

真偽値型、数値型、浮動小数点数型の場合、旧来の Vim script では "is" と "isnot"
は文字列の比較と同じように動作する。Vim9 script では、数値と浮動小数点数を比較
する場合を除き、"is" を使用すると E1037 または E1072 が発生する。例:

        vim9cmd var [boo: bool, num: number, flo: float] = [true, 9, 9.2]
        legacy echo s:boo is v:true     | " 1
        legacy echo s:num is 9          | " 1
        legacy echo s:flo is 9.2        | " 1
        legacy echo s:boo is 9          | " 0
        legacy echo s:boo is 9.2        | " 0
        legacy echo s:num is 9.2        | " 0
        vim9cmd echo boo is true  # E1037: Cannot use "is" with bool
        vim9cmd echo num is 9     # E1037: Cannot use "is" with number
        vim9cmd echo flo is 9.2   # E1037: Cannot use "is" with float
        vim9cmd echo boo is 9     # E1072: Cannot compare bool with number
        vim9cmd echo boo is 9.2   # E1072: Cannot compare bool with float
        vim9cmd echo num is 9.2   # false

同様に、"is" と "isnot" はジョブ型とチャネル型の比較には使用できない。この例で
は、ジョブの比較は旧来の Vim script のスコープでは "is" で動作するが、Vim9
script のスコープでは E1072 が発生することを示している:

        vim9script
        var job1: job
        var job2: job = job1
        legacy echo s:job1 is s:job2  | # 1
        echo job1 is job2               # E1072: Cannot compare job with job

コンテナ型であるリスト、辞書、タプル、Blob を "is" と "isnot" を使用して比較す
る場合、Vim9 script でも旧来の Vim script と同じように動作する。比較ではインス
タンスを確認し、内容は確認しない。動作が同様であるため、この例では Vim9 script
のリストの例のみを提供し、同じ動作を示すために旧来の Vim script のスコープでの
比較を付けている:

        vim9script
        var l1: list<any>
        var l2: list<any> = l1
        echo l1 is l2                   # true (同じインスタンス)
        legacy echo s:l1 is s:l2 |      # 1
        echo l1 is []                   # false (異なるインスタンス)
        legacy echo s:l1 is [] |        # 0
        echo l1 is null_list            # false (異なるインスタンス)

Funcref 変数の比較はコンテナ変数の比較とほぼ同じだが、未初期化の Funcref
変数を Vim9 script の null_function と比較した場合は動作が異なる:

        vim9script
        var F1: func
        var F2: func = F1
        echo F1 is F2                   # true (同じ未初期化のインスタンス)
        echo F1 is null_function        # true

Vim9 script では、クラスオブジェクトの比較も同様に動作する:

        vim9script
        class C
        endclass
        # 未初期化のクラスオブジェクト
        var O1: C
        var O2: C
        echo O1 is O2           # true (同じ未初期化のクラスオブジェクト)
        echo O1 is null_object  # true
        # 初期化済みのクラスオブジェクト
        var O4: C = C.new()
        var O5: C = O4
        var O6: C = C.new()
        echo O4 is O5           # true (同じ初期化済みのクラスオブジェクト)
        echo O5 is O6           # false (異なるクラスオブジェクト)

        Note: クラス自体は比較できない:

        vim9script
        class C
        endclass
        echo C is null_class    # E1401: Class "C" cannot be used as a value

enum オブジェクトの比較はクラスオブジェクトとは異なる。各 enum 値はシングルト
ンであるため、同じ enum 値が代入された変数は常に同一のインスタンスを参照する。
enum 値の変更可能なインスタンス変数が変更された場合でも、その変更はその enum
値へのすべての参照に影響する:

        vim9script
        enum Switch
          On(['active', true]),
          Off(['inactive', false])
          final state: list<any>
        endenum
        var on1: Switch = Switch.On
        var on2: Switch = Switch.On
        on2.state[0] = 'engaged'
        # on1 と on2 は同じ enum 値であるため、変更は on1 と on2 に影響する
        echo on1 is on2                         # true
        # 未初期化の enum 値 (そして null_enumvalue は存在しない):
        var uninitialized: Switch
        echo uninitialized is null_object       # true

まとめると、比較演算子 "is" と "isnot" に関して:

- Vim9 script は旧来の Vim script よりも厳格なルールを導入しており:
        - 文字列では動作が異なり、
        - リスト、辞書、タプル、Blob では動作は同じであり、
        - 真偽値、数値、浮動小数点数、ジョブ、チャネルの比較を許可せず (数値と
          浮動小数点数の比較を除く)、そして
        - 関数参照では動作は同じである (ただし、Vim9 script の null_function
          は動作が異なる)。

- 完全に Vim9 script のみに存在するもの:
        - クラスオブジェクトの比較は関数参照の比較と同様であり、そして
        - enum オブジェクトの場合、"is" と "isnot" は常に指定された enum 値の
          同一のインスタンスを比較する。


エラー後の中断

旧来の Vim script ではエラーが発生すると、Vim はエラーの後に続く行の実行を継続
する。これは、長いエラーの連続と、それを停止するために CTRL-C を入力する必要に
つながる可能性がある。例えば、このスクリプトは 2 つの E121 エラーを発生させ
る:

        " 旧来の Vim script
        let x = does_not_exist
        let y = does_not_exist_too

しかし、Vim9 script では、コマンドの実行は最初のエラーで停止する:

        vim9script
        var x = does_not_exist  # E121: Undefined variable: does_not_exist
        # 実行は停止し、次の行は実行されない
        var y = does_not_exist_too


For ループ

ループ変数はまだ宣言されていてはいけない:

        vim9script
        var it: list<number>
        for it in [1, 2, 3]     # E1041: Redefining script item: "it"

ただし、プリフィックス付きの変数、例えばバッファローカル変数を使用することは可
能である:

        vim9script
        b:i = []
        for b:i in [1, 2, 3]
          echo b:i
        endfor
                                                        E1254
:def 関数内のループ変数を s: 変数にすることはできない:

        vim9script
        def F()
          for s:n in range(9) # E1254: Cannot use script variable in for loop
          endfor
        enddef
        defcompile

旧来の Vim script には、リストに対する for ループが現在の項目または前の項目で
の項目の削除を処理できるようにするトリックがいくつかある。Vim9 script では、コ
ンパイルされないスコープで同じトリックが適用される。しかし、コンパイルされた
Vim9 script のスコープでは、項目が削除されるとリスト内の次の項目がスキップされ
("イテレータの無効化")、Python や Ruby で見られるのと同じ結果になる。以下のス
クリプトは、コンパイルされない Vim9 script のスコープとコンパイルされた Vim9
script のスコープでの異なる動作を示している:

        vim9script
        echo 'Removing items from a list in a Vim9 script non-compiled scope:'
        # これは 10、次に 20、30、40、そして [] を表示する
        var list_one: list<number> = [10, 20, 30, 40]
        for n in list_one
          echo n
          list_one->remove(index(list_one, n))
        endfor
        echo list_one
        echo 'Removing items from a list in a Vim9 script compiled scope:'
        # これは 10、次に 30、そしてリスト [20, 40] を表示する
        # これは、10 が削除されると 20 がインデックス 0 に移動するが、
        # イテレータはインデックス 1 に移動し、そのインデックスが今は
        # 30 であるためだ!
        var list_two: list<number> = [10, 20, 30, 40]
        var Remove_items: func = (): void => {
          for n in list_two
            echo n
            list_two->remove(index(list_two, n))
          endfor
          echo list_two
        }
        Remove_items()

この例が示しているのは、通常は、反復処理されるリストは変更しない方がよいという
ことである。まずコピーを作成する方が安全なことが多い。

リストのリストをループ処理する場合、ネストされたリストは変更できる。ループ変数
は "final" であり、つまり変更できないが、その値は変更できる。例:

        vim9script
        var lst: list<list<number>> = [[1, 2], [3, 4], [5, 6]]
        for subl in lst
          subl[0] = 9
        endfor
        echo lst  # [[9, 2], [9, 4], [9, 6]]
        for subl in lst
          subl = [9, subl[1]] # E46: Cannot change read-only variable "subl"
        endfor
                                                        E1306
:for ループと :while ループを合わせたループの深さは、10 を超えることはでき
ない。


条件と式

Vim9 script では、真偽値のコンテキストにおいて旧来の Vim script よりも厳格な型
チェックが行われる。ほとんどの演算子は、真偽値、0/1、または Special 型のいず
れかを必要とする。Falsy 演算子 (??) と論理否定演算子 (expr-!) は真偽性の
ルールを使用する。

– 厳格な真偽値式
                                                        vim9-boolean
Vim9 script では、条件式 :if、ternary、:while、|| (expr-barbar)、
&& (expr-&&) には厳格な真偽値型が必要である。これは、0 以外の数値をすべて
1 として扱い、文字列や Special を暗黙的に同等の数値として推論する旧来の Vim
script とは異なる。例示すると、旧来の Vim script では、これらの条件式はすべて
動作する:

        " 旧来の Vim script
        " これらは 1 と評価される:
        echo 1 ? 1 : 0
        echo 0 || 1
        echo 1 || v:false
        echo 1 && v:true
        echo v:null || 1
        echo 99 ? 1 : 0
        echo "99" ? 1 : 0
        " これらは 0 と評価される:
        echo 0 || v:none
        echo 0 && 1
        echo "text" ? 1 : 0

Vim9 script では、条件式 (?? と ! を除く) はより厳格な type-checking を
持つ。つまり:
- 数値の場合、0 (偽値) または 1 (真値) のみが許可され、それ以外の場合は
  E1023 が発生し、
- 文字列は許可されない (E1135)。

        vim9cmd echo 1 ? 1 : 0          # 1
        vim9cmd echo 0 || 1             # true
        vim9cmd echo 1 || false         # true
        vim9cmd echo 1 && true          # true
        vim9cmd echo null || 1          # true
        vim9cmd echo 0 || v:none        # false
        vim9cmd echo 0 && v:true        # false
        vim9cmd echo 9 ? 1 : 0          # E1023: Using a Number as a Bool: 9
        vim9cmd echo "9" ? 1 : 0        # E1135: Using a String as a Bool: "9"
        vim9cmd echo "x" ? 1 : 0        # E1135: Using a String as a Bool: "x"

– Falsy 演算子
                                                        vim9-falsy
ほとんどの型では、?? (falsy-operator) を使用してもエラーは発生しない。値は
偽値か真値のいずれかであり、偽値は以下のように評価される:

        型              偽値となるとき
        Number          ゼロ
        String          空
        Funcref         null
        List            空
        Dictionary      空
        Float           ゼロ
        Boolean         false (Special の v:false も)
        None            常に (v:null と v:none)
        Job             null
        Channel         null
        Blob            空
        Class           該当なし (E1405 を参照)
        Object          null
        Typealias       該当なし (E1403 を参照)
        Enum            該当なし (E1421 を参照)
        EnumValue       null
        Tuple           空
        void            常に

例として、エラーが発生する型を除くすべての型の偽値を示すスクリプト:

        vim9script
        echo "Number: \t0\t\t"                  0 ?? 'is falsy'
        echo "String: \t''\t\t"                 '' ?? 'is falsy'
        echo "Funcref:\tnull_function\t"        null_function ?? 'is falsy'
        echo "List:   \t[]\t\t"                 [] ?? 'is falsy'
        echo "Dictionary:\t{}\t\t"              {} ?? 'is falsy'
        echo "Float:  \t0.0\t\t"                0.0 ?? 'is falsy'
        echo "Boolean:\tfalse\t\t"              false ?? 'is falsy'
        echo "        \tv:false\t\t"            v:false ?? 'is falsy'
        echo "None:   \tv:none\t\t"             v:none ?? 'is falsy'
        echo "        \tv:null\t\t"             v:null ?? 'is falsy'
        echo "Job:    \tnull_job\t"             null_job ?? 'is falsy'
        echo "Channel:\tnull_channel\t"         null_channel ?? 'is falsy'
        echo "Blob:   \t0z\t\t"                 0z ?? 'is falsy'
        echo "Object: \tnull_object\t"          null_object ?? 'is falsy'
        enum Enum
        endenum
        var null_enumval: Enum  # NB: 固有の "null_enumvalue" は存在しない
        echo "EnumValue:\t'null_enumval'\t"     null_enumval ?? 'is falsy'
        echo "Tuple:  \t()\t\t"                 () ?? 'is falsy'
        echo "void:   \t\t\t"                   test_void() ?? 'is falsy'

Note: Vim9 script の偽値性は Python のものとほぼ同じである (例えば、Python の
"if []:" は偽であり、Vim9 script の "if []" と同じである。JavaScript も同様だ
が、空のオブジェクト/配列に対する独特な真値の評価において異なる。

– 型変換と例外
                                                        vim9-!
論理否定演算 "!" (expr-!) を反転に使用する場合、エラーは発生せず (クラス -
E1405、enum - E1421、型エイリアス - E1403 の場合を除く)、結果は常に真偽
値になる。この例では、偽値が反転され、すべての評価が "true" を返す:

        vim9script
        echo [!0, !'', !null_function, ![], !{}, !0.0, !false,
          !v:false, !v:none, !v:null, !null_job, !null_channel, !0z,
          !null_object, !(), !test_void()]
                                                        vim9-!!
同様に、"!!" を使用して値を真偽値に変換すると、この例が示すように、すべての評
価が "false" を返す:

        vim9script
        echo [!!0, !!'', !!null_function, !![], !!{}, !!0.0, !!false,
          !!v:false, !!v:none, !!v:null, !!null_job, !!null_channel, !!0z,
          !!null_object, !!(), !!test_void()]

Note: これは、Vim9 script が旧来の Vim script よりも寛容な稀なケースである。以
下の例が示すように、旧来の Vim script では、多くの型 (Funcref、List、
Dictionary、Blob、Job、Tuple を含む) で "!" または "!!" を使用するとエラーが発
生する:

        " 旧来の Vim script: !! でエラーになる例
        let F = {x -> x}
        let j = job_start([&shell, &shellcmdflag, 'date'], {})
        echo !!F  |     " E703: Using a Funcref as a Number
        echo !![] |     " E745: Using a List as a Number
        echo !!{} |     " E728: Using a Dictionary as a Number
        echo !!0z |     " E974: Using a Blob as a Number
        echo !!j  |     " E910: Using a Job as a Number
        echo !!() |     " E1520: Using a Tuple as a Number

文字列の連結に ".." を使用する場合、数値型、浮動小数点数型、真偽値型、
Special 型は常に文字列に変換される:

        vim9script
        var mystr = 8 .. ', ' .. 9.2 .. ', ' .. true .. ' and ' .. v:none
        echo [mystr, mystr->typename()]

        Notes: 1. true (および、ここでは示していないが v:true) はどちらも
        "true" に文字列化されるが、旧来の Vim script では v:true は "v:true"
        に文字列化される。2. Vim9 script では '..' による文字列の連結は浮動小
        数点数を一貫して扱う。旧来の Vim script はそうではなく、最初の "." ま
        たは ".." の後では小数点が連結の "." として解釈される。以下の旧来の
        Vim script では、9.2 の小数点が失われる:

        let s:my8str = 8 .. ', ' .. 9.2 .. ', ' .. v:true .. ' and ' .. v:none
        echo s:my8str | " 8, 92, v:true and v:none

これは、プリミティブ (v:t_number、v:t_float、v:t_bool) と Special 型は
"==" で直接比較できることを示している。その他のすべての型には string() を使
用する必要がある。例:

        vim9script
        echo 'This is a list: ' .. [1, 2, 3]->string()
        # 一方、こうすると E730: Using a List as a String: が発生する
        echo 'This does not work! ' .. [1, 2, 3]

同様に、"==" による比較には string() を使用すべきである。そうしないと
E1072 が発生する。例:

        vim9script
        var l: list<any> = [9, '9.2']
        echo string(l) == "[9, '9.2']"  # true
        echo l == "[9, '9.2']"  # E1072: Cannot compare List with String

WARNING: OR 式がすべてのオペランドを評価しなくても true であると判断できる場
合、短絡評価によって真偽値式のエラーが隠される可能性がある。評価が早期に停止す
るため、不正なコードが実行されないことがあり、Vim9 script の型関連のエラーを含
め、本来は実行時に発生するはずのエラーが隠される。例えば、クラス自体は比較に使
用できないが、ここでは "t" が既に true と評価されているため、最初の三項式で
はエラーが発生しない:

        vim9script
        var t: bool = true
        echo t || null_class ? true : false  # true
        echo null_class || t ? true : false  # E1405: Class "" cannot be used…


定義済みの値
                        false true null null_blob null_channel
                        null_class null_dict null_function null_job
                        null_list null_object null_partial null_string
Vim9 script には、真、偽、および null の状態を表す定義済みの値がある。以下の表
は、それらの定義済みの値を、その type()、typename()、および string() の
表現とともに列挙する:

 定義済みの値      type()         typename()            string()
 null_string       v:t_string   string                ''
 null_function     v:t_func     func(...): unknown    function()
 null_partial      v:t_func     func(...): unknown    function('')
 null_list         v:t_list     list<any>             []
 null_dict         v:t_dict     dict<any>             {}
 true              v:t_bool     bool                  true
 false             v:t_bool     bool                  false
 null              v:t_none     special               null
 null_job          v:t_job      job                   no process
 null_channel      v:t_channel    channel             channel fail
 null_blob         v:t_blob     blob                  0z
 null_class        v:t_class    class<Unknown>        class [unknown]
 null_object       v:t_object   object<any>           object of [unknown]
 null_tuple        v:t_tuple    tuple<any>            ()

定義済みの値 true は v:true と同じ、false は v:false と同じ、null は
v:null と同じである。

"null_<type>" の値は、一部の場合にのみ空の値と同じように扱われる。
null-details を参照。

以下の型には、定義済みの "null_<type>" 値はない:
- Number (代わりに 0 を使用する。ただし、これは null ではない)
- Float (代わりに 0.0 を使用する。ただし、数値の 0 と同様に、これも null で
  はない)
- Typealias (値として使用することはできない。E1403 が発生する)
- Enum (値として使用することはできない。E1421 が発生する)
- EnumValue (ただし、null_object にはなりうる - vim9-comparators の
  "Switch" の例を参照)

"null_<type>" の値は、スクリプトローカル変数をクリアするのに役立つことがある。
それらは :unlet では削除できないためである。例:

        vim9script
        var myvar: string = "not null_string"
        try
          unlet myvar
        catch
          echo v:exception  # E1081: Cannot unlet myvar
        finally
          myvar = null_string
          echo $"'myvar' is {myvar->string()}"
        endtry

これらの値は引数のデフォルト値としても役立つことがある:

        vim9script
        def CheckMyList(l: list<number> = null_list): string
          if l == null
            return 'No list was passed'
          elseif l->empty()
            return 'An empty list was passed'
          else
            return $"List {l->string()} was passed"
          endif
        enddef
        echo CheckMyList()
        echo CheckMyList([])
        echo CheckMyList([8, 9])

        Note: この例では、リスト "l" を null_list ではなく null と比較して
        いる。これは、デフォルト値の null_list と空リスト [] を区別できるよう
        にするので便利である。null に対するテストについての詳細は
        null-compare および null-anomalies を参照。

null を任意の値と比較することは可能であり、型エラーは発生しない。ただし、
null を数値、浮動小数点数、または真偽値と比較すると、常に false になる。こ
れは、v:null を 0 または 0.0 と比較すると 1 が返される旧来の Vim script の数
値および浮動小数点数とは異なる。例:

        vim9script
        echo [0 == null, 0.0 == null]              # [false, false]
        legacy echo [0 == v:null, 0.0 == v:null] | # [1, 1]

                                                        vim9-false-true
真偽値を文字列に変換する場合、false と true が使用される。Vim9 script で
は、v:false は false と等しく、v:true は true と等しい。

        vim9script
        echo $'{v:none} has no "none" equivalent, but'
        echo $'"v:true" is stringified to "{v:true}" in a string, and'
        echo 'Q: "v:false" and "false" can be used interchangeably?'
        echo $'A: {v:false == false}'

Note: v:none に対する "none" はない。他の言語に同等のものがないためである。

                                                        vim9-string-index
[idx] による文字列のインデックス指定、または [idx : idx] によるスライスの取得
では、バイトインデックスではなく文字インデックスが使用される。合成文字も含まれ
る。例:

        vim9script
        echo 'très'[2]          # è (U+00E8)
        legacy echo 'très'[2] | # <c3> (不正なバイト 0xc3)

負のインデックスは末尾からカウントし、"[-1]" は最後の文字である。

        vim9script
        echo 'fenêtre'[-4 : -1]          # être
        legacy echo 'fenêtre'[-5 : -1] | # être (ê は 2 バイトなので -5)

組み込み関数 slice() を使用するのは良い選択になりうる。旧来の Vim script の
スコープと Vim9 script のスコープの両方で文字インデックスを使用するためである:

        vim9script
        echo 'fenêtre'->slice(-4)          # être
        legacy echo 'fenêtre'->slice(-4) | # être

合成文字を個別にカウントするには strcharpart() を使用する。以下の例では、"a"
(U+0061) と結合マクロン (U+0304) を使用している:

        vim9script
        echo 'Ngā mihi'->strcharpart(2, 1)  # a (結合マクロンを除く)
        echo 'Ngā mihi'[2]                  # ā (結合マクロンを含む)

インデックスが範囲外の場合、結果は空文字列になる。

        vim9script
        echo ['In range'[0 : 1]]        # ['In']
        echo ['Out of range'[19 : ]]    # ['']
                                                        E1148
インデックスを使用して文字列に代入したり変更したりしようとすると、エラーが発生
する。例:

        vim9script
        def F1148(): void
          b:s = 'Fails'
          b:s[4] = '!'  # E1148: Cannot index a string
        enddef
        F1148()

        Note: スコープや、変数にプリフィックスが付いているかどうかによって、他
        のエラーが発生する場合がある。例えば、この例の変数がバッファ変数ではな
        く :var で宣言されていた場合は E1141 が発生し、スコープが :def
        ではなくスクリプトローカルであった場合は E689 が発生する。

旧来の Vim script では、文字インデックス内で "++var" (:++) または "--var"
(:--) が使用された場合、それらは無視される。Vim9 script では、これらは無効で
ある:

        vim9script
        var int: number = 1
        var str: string = 'hear'
        legacy echo s:str[++s:int : ] | # ear
        echo str[++int : ]              # E15: Invalid expression: "++int : ]

0 で始まる数値は 8 進数とはみなされず、"0o" で始まる数値のみが 8 進数である:
"0o744"。(scriptversion-4 を参照。) 例:

        vim9script
        echo 017          # 17 (10 進数と推定)
        legacy echo 017 | # 15 (8 進数と推定)
        echo 0o17         # 15 (明示的な 8 進数)

気をつけるべきこと
                                                        vim9-gotchas
Vim9 script は、現代のプログラミング言語により近くなるように設計されたが、同時
に旧来の Vim コマンドもサポートしようとしている。いくつかの妥協をしなければな
らなかった。以下は、予期しないかもしれないことの要約である。

Ex コマンドの範囲指定には、多くの場合コロンを前置する必要がある:

- 旧来の Vim script では "%" で始まる行は「すべての行」(:%) を意味するが、
  Vim9 script では剰余 (expr-%) を意味するか、E1050 が発生する場合がある。
  例:

        " 旧来の Vim script
        let g = 97
        echo 1000
          % g / 9.7
        " 1000 (その後、'9.7' を含むすべての行をメッセージに表示する)

  一方:

        vim9script
        var g = 97
        echo 1000
          % g / 9.7
        # 3.092784 (これは 1000 % 97 / 9.7 である)
        echo 1000
        :%g/9.7
        # 1000 (その後、'9.7' を含むすべての行をメッセージに表示する)
        % g / 9.7
        # E1050: Colon required before a range: % g / 9.7

- 旧来の Vim script では、先頭のアポストロフィはマークへの移動 (') を意味す
  る。Vim9 script では、引用符で囲まれた文字列の開始であるか、E115 が発生す
  る:

        " 旧来の Vim script
        :normal! mt
        " コメント " 旧来の Vim script の行にマーク t を設定する
        't
        " マーク t にジャンプする (このスクリプトを読み込んだ後はこの行にある)

  一方:

        vim9script
        :normal! mt
        # vim9script コマンドの行にマーク t を設定する
        't'->popup_notification({time: 4000})  # Vim9 script の
                                               # メソッドチェーン
        :'t
        # マーク t にジャンプする (このスクリプトを読み込んだ後はこの行にある)
        # 't 単独だと E115: Missing single quote となる

- 旧来の Vim script では、"->" は前の行を、'shiftwidth' 個のスペース分右にシフ
  トする。その前の行は、読み込まれたスクリプトの場合は範囲の前にある。Vim9
  script では、それはチェーンされたメソッドの継続行である:

        vim9script
        const mine: string = 'MINE'
          ->toupper()
        echo mine       # MINE
        # 変更可能なバッファでは、:-> を単独の行で使用すると、このスクリプト
        # を読み込んだときに、vim9script の前の行が 'shiftwidth'
        # 個のスペース分右にシフトされる。

いくつかの Ex コマンドは、Vim9 script の代入と混同される可能性がある:

        " 旧来の Vim script
        let let = 8
        echo let | " 8
        :g:let = 8
        " 'let = 8' にマッチする行をメッセージに表示する
一方:
        vim9script

        :g:let = 9  # E1241: Separator not supported: :let = 9

:global または :substitute コマンドと式または代入との混同を避けるため、こ
れらのコマンドが 1 文字に省略されている場合、いくつかの区切り文字は使用できな

        vim9cmd g-pattern-cmd   # E1241: Separator not supported: -pattern-cm…
        vim9cmd g:pattern:cmd   # E1069: White space required after ':': :cmd…
        vim9cmd g.pattern.cmd   # E121: Undefined variable: g

また、旧来の Vim script とは異なり、コマンドと区切り文字の間にスペースを入れる
ことはできない。例:

        g /[-:.]pattern/p | " これは上記の 3 つの vim9cmd の行を表示する

一方、Vim9 script では:

        vim9cmd g /[-:.]pattern/p  # E1242: No whitespace allowed before sepa…

:def で定義された関数は関数全体をコンパイルするため、あらゆる構文エラーや型
エラーは、実行経路に関係なくコンパイル中に検出される。旧来の関数には静的な型
チェックがないため、型に関連する問題 (もしあれば) は、実際に実行されるコードで
のみ表面化しうる。例えば、以下の旧来の Vim script の :function は "yes" を返
す (z/OS UNIX でこれを読み込むという、非常にありそうにないシナリオを除く):

        vim9script
        func Maybe()
          if !has('ebcdic')
            return 'yes'
          endif
          return [] + 'yes'
        endfunc
        echo Maybe()  # yes

同等の Vim9 script では E1051 が発生する:

        vim9script
        def Maybe(): any
          if !has('ebcdic')
            return 'yes'
          endif
          return [] + 'yes'  # E1051: Wrong argument type for +
        enddef
        echo Maybe()

回避策として、サポートされていないコードを、偽と評価される定数式を含む条件文の
中に記述する。そうすると、コンパイラはサポートされていないコードのコンパイルを
スキップする。例:

        vim9script
        def Maybe(): any
          if has('ebcdic')
            return [] + 'yes'
          endif
          return 'yes'
        enddef
        echo Maybe()    # yes

別の選択肢は、2 つの関数に分割することである:

        vim9script
        if has('ebcdic')
          # これは EBCDIC システム上でない限りまったくコンパイルされない
          def MaybeInner(): any
            return [] + 'yes'
          enddef
        endif
        func Maybe()
          if has('ebcdic')
            return MaybeInner()
          else
            return 'yes'
          endif
        endfunc
        echo Maybe()    # yes

さらに別の選択肢は、今回は異なるシナリオを使用しているが、exists_compiled()
を使用することである。ここでは、組み込み関数 luaeval() は利用可能な場合にの
み使用される:

        vim9script
        def Version(): string
          if !exists_compiled('*luaeval')
            return $"Version using v:version: {v:version}"
          else
            return $"Version via Lua: {luaeval('900 + 2')}"
          endif
        enddef
        echo Version()

          let X = "Although this is unreachable, it's ignored."

        }
                                                        vim9-user-command
関数をコンパイルする際のもう一つの副作用は、コンパイル時にユーザーコマンドの存
在がチェックされることである。ユーザーコマンドが後から定義されている場合、エ
ラーが発生する。これは動作する:

        vim9script
        command -nargs=1 MyCommand echomsg <q-args>
        def Works()
          MyCommand 'this works'
        enddef
        Works()

これは、"MyCommandFails" がコンパイル時に定義されていないため、E476 が発生す
る:

        vim9script
        def Fails()
          command -nargs=1 MyCommandFails echomsg <q-args>
          MyCommandFails 'this fails'
        enddef
        Fails()

回避策は、このように、:execute を使用してコマンドを間接的に呼び出すことであ
る:

        vim9script
        def Works_Using_Execute()
          command -nargs=1 MyCommandUsingExecute echomsg <q-args>
          execute "MyCommandUsingExecute 'this works'"
        enddef
        Works_Using_Execute()

条件文内の認識されないコマンドについては、打ち切りはない。そのため、条件が偽と
評価される場合、無効なコマンドは E171 が発生し、条件が真と評価される場合、無
効なコマンドは E476 が発生する。例:

        vim9script
        def F171()
          if has('ebcdic') | Nah | endif
        enddef
        F171()  # E171: Missing :endif

        vim9script
        def F476()
          if !has('ebcdic') | Nah | endif
        enddef
        F476()  # E476: Invalid command: Nah | endif

3. 新しいスタイルの関数                                 fast-functions

                                                        :def
:def[!] {name}([arguments])[: {return-type}]
                        {name} という名前で新しい関数を定義する。関数本体は、
                        対応する :enddef まで、次の行に記述する。
                                                        E1073
                        {name} はスクリプトローカルレベルでは再利用できない:

                          vim9script
                          def F_1073()
                          enddef
                          def F_1073()  # E1073: Name already defined: <SNR...
                          enddef
                                                        E1011
                        {name} の長さは 100 バイト未満である必要がある。

                                                        E1077
                        {arguments} は、0 個以上の引数宣言の並びである。以下の
                        3 つの形式がある:
                                {name}: {type}
                                {name} = {value}
                                {name}: {type} = {value}
                        最初の形式は必須の引数である。そのため、宣言では型を指
                        定する必要がある。例:

                          vim9script
                          def F_1077(x): void
                            # E1077: Missing argument type for x
                          enddef

                        2 番目の形式の場合、宣言で型が指定されていないため、
                        Vim は型を推測する。2 番目と 3 番目の形式の両方におい
                        て、呼び出し側で {value} が省略された場合はデフォルト
                        の {value} が適用される。例:

                          vim9script
                          def SecondForm(arg = "Hi"): void
                            echo $'2. arg is a "{arg->typename()}" type ' ..
                                 $'and the default value of arg is "{arg}"'
                          enddef
                          SecondForm()
                          def ThirdForm(arg2: number = 9): void
                            echo $'3. default value of arg2 is {arg2}'
                          enddef
                          ThirdForm()
                                                        E1123
                        :def 関数で呼び出される組み込み関数の引数は、引数間
                        にコンマが必要である:

                          vim9script
                          def F_1123(a: number, b: number): void
                            echo max(a b)  # E1123: Missing comma before ar...
                          enddef
                          F_1123(1, 2)
                                                        E1003 E1027 E1096
                        :return で使用される値の型は {return-type} と一致す
                        る必要がある。{return-type} が省略されているか "void"
                        の場合、関数は何も返せない。例:

                          vim9script
                          def F_1003(): bool
                            return  # E1003: Missing return value
                          enddef
                          F_1003()

                          vim9script
                          def F_1027(): bool
                            echo false  # E1027: Missing return statement
                          enddef
                          F_1027()

                          vim9script
                          def F_1096(): void
                            return false  # E1096: Returning a value in a f...
                          enddef
                          F_1096()
                                                        E1056 E1059
                        ": {return-type}" が指定されている場合、{return-type}
                        は省略できない (ぶら下がりコロンが残る)。また、": " の
                        前に空白文字を置くこともできない。例:

                          def F_1056():
                          # E1056: Expected a type:
                          enddef
                          def F_1059() : bool
                          # E1059: No white space allowed before colon: ... 
                          enddef

                        関数は、呼び出されたとき、または :defcompile または
                        :disassemble が使用されたときに命令にコンパイルされ
                        る。(例については、:disassemble を参照。) その際に構
                        文エラーと型エラーが生成される。

                                                        E1058
                        :def を別の :def または :function 内にネストでき
                        るのは最大 49 レベルまでである。50 レベルを超えると
                        E1058 エラーが発生する。

                                                        E1117
                        [!] は、関数の再定義 (:function! と同様) を許可する
                        ため、旧来の Vim script でのみ使用できる。Vim9 script
                        では、スクリプトローカルな関数は削除または再定義できな
                        いため、! は使用できない。ただし、スクリプトを再読み込
                        みすることで削除できる。また、ネストされた関数では、再
                        定義に ! は使用できない。例:

                          " 旧来の Vim script の :def! の例
                          def! LegacyFunc()
                            echo "def! is allowed in a legacy Vim script"
                          enddef
                          call LegacyFunc()

                          vim9script
                          def F1117()
                            def! InnerFunc()
                              # E1117: Cannot use ! with nested :def
                            enddef
                          enddef
                          F1117()

                          vim9script
                          def! F_477(): void  # E477: No ! allowed
                          enddef

                          vim9script
                          def F_1084(): void
                          enddef
                          delfunction! F_1084
                          # E1084: Cannot delete Vim9 script function F_1084

                        Note: 一般的なエラー E1028 ("Compiling :def function
                        failed") は、コンパイル中に発生した原因不明のエラーを
                        示す。再現可能な場合は、Vim のエラー報告に欠陥がある可
                        能性があるため、
                        https://github.com/viai-editor/viai/issues に報告して
                        ほしい。

                                                        :enddef
                                                        E1057 E1152 E1173
:enddef                 :def で定義された関数の終了。単独の行に記述する必要
                        がある。例:

                          vim9script
                          def MyFunc()
                          echo 'Do Something' | enddef
                          # E1057: Missing :enddef

                          vim9script
                          def F_1173()
                          enddef echo 'X'
                          # E1173: Text found after enddef: echo 'X'

                          vim9script
                          def F_1152()
                            function X()
                            enddef  # E1152: Mismatched enddef
                          enddef

                                                        vim9-s:var
スクリプトローカル変数を参照する際、"s:" プリフィックスの使用が必須か、任意か、
あるいは E1268 エラーになるかは、コンテキストによって決まる。コンテキストを
左右する要因は、スクリプトのバージョンが Vim9 script か旧来の Vim script か、
そして参照箇所がスクリプトローカルなレベルか、:def 関数内か、それとも
:function 内か、という点である。そのルールは以下の 3 つである。

 1. :function 内では、常に "s:" が必須となる。これはスクリプトの種類や関数の
    親コンテキスト (別の関数内にネストされている場合など) にかかわらず同様であ
    る。同様に、旧来の Vim script のスクリプトローカルスコープにおいても、"s:"
    は必須である。
 2. Vim9 script では、:def 関数内で "s:" を使用すると、その関数の親コンテキ
    ストにかかわらず、常に E1268 エラーが発生する。同様に、Vim9 script のス
    クリプトローカルスコープで使用した場合も、E1268 エラーとなる。
 3. 旧来の Vim script では、:def 関数内の "s:" は、その関数の親コンテキスト
    にかかわらず省略可能である。

以下の 3 つのスクリプトは、これらのルールを実証するものである:

        " 1. :function 内では、"s:" は常に必須である。また、旧来の Vim script
        " のスクリプトローカルスコープにおいても必須となる
        let s:MyVar = v:true
        echo s:MyVar            | " v:true
        " echo MyVar              (Would give E121: Undefined variable: MyVar)
        vim9cmd echo MyVar        # true
        function! MyFunc()
          echo s:MyVar          | " v:true
          " echo MyVar            (Would give E121: Undefined variable: MyVar)
          vim9cmd echo MyVar      # true
        endfunction
        call MyFunc()

        vim9script
        # 2. Vim9 script では、:def 関数内またはスクリプトローカルスコープで
        # "s:" を使用すると、E1268 エラーが発生する
        var MyVar: bool = true
        echo MyVar                # true
        # echo s:MyVar            (Would give E1268: Cannot use s: in Vim9...)
        legacy echo s:MyVar     | # v:true
        def MyFunc()
          echo MyVar            # true
          # echo s:MyVar          (Would give E1268: Cannot use s: in Vim9...)
          legacy echo s:MyVar   | # v:true
        enddef
        MyFunc()

        " 3. 旧来の Vim script では、:def 関数内の "s:" は省略可能である
        let s:MyVar = v:true
        function! Outer()
          def! MyFunc()
            echo MyVar          # true
            echo s:MyVar        # true
          enddef
          call MyFunc()
        endfunction
        call Outer()

実行時に評価される exists() は、未宣言の変数をスキップするような条件付きの使
用には適していないが、コンパイル時に評価される exists_compiled() であれば使
用可能である。例:

        vim9script
        def MyDef()
          if exists_compiled('MyVar')   # コンパイル時に評価される
            echo $"MyVar = {MyVar}"     # MyVar = 1
          endif
          if exists_compiled('MyVar2')  # コンパイル時に評価される
            echo $"MyVar2 = {MyVar2}"   # not reached
          else
            echo "MyVar2 does not exist at compile time"
          endif
          if exists('MyVar')            # 実行時に評価される
            echo $"MyVar = {MyVar}"     # MyVar = 1
          endif
          if exists('MyVar2')           # 実行時に評価される
            # 以下の場合、E1001: Variable not found: MyVar2 が発生する
             echo MyVar2
          else
            echo "MyVar2 does not exist at runtime"
          endif
        enddef
        var MyVar: number = 1   # MyDef() がコンパイルされる前に宣言される
        MyDef()
        var MyVar2: number = 2  # MyDef() がコンパイルされた後に宣言される

                                                        E1269
Vim9 script 内のスクリプトローカル変数は、スクリプトレベルで宣言する必要があ
る。:def 関数内では作成できず、また "s:" プリフィックスを持つ旧来の関数内で
も宣言できない。例:

        vim9script
        function F_1269()
          let s:i_wish = v:true
        endfunction
        F_1269()
        # E1269: Cannot create a Vim9 script variable in a function: s:i_wish

                                                        :defc :defcompile
:defc[ompile]           現在のスクリプトで定義されていてまだコンパイルされてい
                        ない関数とクラス (class-compile) をコンパイルする。
                        これにより、コンパイル中に見つかったエラーが報告され
                        る。

                        例: (enddef までの) 3 行がソースコードに読み込まれる
                        と、Vim9 の :def 関数がコンパイルされないためエラー
                        は発生しない。しかし、4 行すべてがソースコードに読み込
                        まれると、コンパイルは失敗する:

                          vim9script
                          def F_1027(): string
                          enddef
                          defcompile F_1027  # E1027: Missing return statement

:defc[ompile] MyClass   クラス内のすべてのメソッドをコンパイルする。(例につい
                        ては :disassemble を参照。)

:defc[ompile] {func}
:defc[ompile] debug {func}
:defc[ompile] profile {func}
                        必要に応じて関数 {func} をコンパイルする。コンパイル
                        モードを指定するには、"debug" と "profile" を使用する。
                        これにより、コンパイル中に見つかったエラーが報告され
                        る。

:def 関数のローカル変数は文字列評価では参照できない。
以下の例は、スクリプトローカル定数 "SCRIPT_LOCAL" は参照できるが、関数ローカル
定数 "DEF_LOCAL" は参照できないことを示している:

        vim9script
        const SCRIPT_LOCAL = ['A', 'script-local', 'list']
        def MapList(scope: string): list<string>
          const DEF_LOCAL: list<string> = ['A', 'def-local', 'list']
          if scope == 'script-local'
            return [1]->map('SCRIPT_LOCAL[v:val]')
          else
            return [1]->map('DEF_LOCAL[v:val]')
          endif
        enddef
        echo 'script-local'->MapList()  # ['script-local']
        echo 'def-local'->MapList()     # E121: Undefined variable: DEF_LOCAL

map 引数は文字列式であり、関数スコープ外で評価される。Vim9 script では、代わり
にラムダ式を使用する:

        vim9script
        def MapList(): list<string>
          const DEF_LOCAL: list<string> = ['A', 'def-local', 'list']
          return [1]->map((_, v): string => DEF_LOCAL[v])
        enddef
        echo MapList()                  # ['def-local']

き、ローカルスコープを使用できる。例:

                                                        vim9-closure
ループ内で定義されたクロージャは、変数の宣言場所に応じて、変数を共有するか、そ
れぞれ独自のコピーを持つかを選択できる。ループ外で変数を宣言した場合、すべての
クロージャは同じ共有変数を参照する。
以下の例は、"outloop" 変数が 1 つだけ存在する場合の結果を示している:

        vim9script
        var flist: list<func>
        def ClosureEg(n: number): void
          var outloop: number = 0  # outloop がループの外で宣言されている!
          for i in range(n)
            outloop = i
            flist[i] = (): number => outloop  # クロージャは同じ変数を参照する
          endfor
          echo range(n)->map((i, _): number => flist[i]())
        enddef
        ClosureEg(4)    # [3, 3, 3, 3]

リストに置かれたすべてのクロージャは同じインスタンスを参照し、最終的には 3 に
なる。

ただし、変数がループ内で宣言されると、以下の例に示すように各クロージャは独自の
コピーを取得する:

        vim9script
        var flist: list<func>
        def ClosureEg(n: number): void
          for i in range(n)
            var inloop: number = i  # inloop はループ内で宣言されている
            flist[i] = (): number => inloop  # クロージャは各 inloop を参照する
          endfor
          echo range(n)->map((i, _): number => flist[i]())
        enddef
        ClosureEg(4)    # [0, 1, 2, 3]

各クロージャに個別のコンテキストを設定する別の方法は、関数を呼び出してそれを定
義することである:

        vim9script
        def GetClosure(i: number): func
          var infunc: number = i
          return (): number => infunc
        enddef
        var flist: list<func>
        def ClosureEg(n: number): void
          for i in range(n)
            flist[i] = GetClosure(i)
          endfor
          echo range(n)->map((i, _): number => flist[i]())
        enddef
        ClosureEg(4)    # [0, 1, 2, 3]
                                                        E1271
クロージャは、それが定義されているコンテキストでコンパイルされなければならな
い。そうすることで、そのコンテキスト内の変数を参照できるようになる。これはほと
んどの場合正しく実行されるが、関数がコンパイル後に :breakadd でデバッグ用に
マークされている場合は例外である。外側の関数をコンパイルする前に、必ずブレーク
ポイントを定義すること。

ど、状況によってはエラーが発生する。これは、文字列実行コンテキストが、クロー
ジャが定義された元のコンテキストからローカル変数にアクセスできないために発生す

例えば、このタイマーは 0 から 2 までを別々の行にエコーする。しかし、:endfor

:function を :def に変換する
                                        convert_legacy_function_to_vim9
                                        convert_:function_to_:def
:function を :def 関数に変換するには、多くの変更が必要である。以下にいくつ
か例を挙げる。

- 変数宣言に使用されている let を var、const、または final のいずれか
  に変更し、各 script-variable から "s:" を削除する。
- func または function を def に変更する。
- endfunc または endfunction を enddef に変更する。
- 各関数の引数に適切な型（または "any"）を追加する。
- 各 function-argument から "a:" を削除する。
- :func-range、:func-abort、:func-dict、:func-closure などの不適切なオ
  プションを削除する。
- 関数が何かを返す場合は、戻り値の型を追加する。(理想的には、何も返さない場合
  は "void" を追加する。)
- 不要な場所から行継続のバックスラッシュを削除する。
- g:、b:、w:、t:、または l: 変数に値を代入するための let を削除す
  る。
- グローバル (g:)、バッファ (b:)、ウィンドウ (w:)、タブ (t:)、および
  ローカル (l:) 変数に値を代入する際は、let を削除する。
- Vim9 script 構文の lambda 式を書き直す (vim9-lambda を参照)。
- コメントを " ではなく # (先頭に空白文字) で始めるように変更する。
- 必要に応じて式に空白文字を挿入する (vim9-white-space を参照)。
- 文字列連結に使用される "." を " .. " に変更する。(または、
  interpolated-string を使用する。)

以下の旧来の Vim script と Vim9 script の例は、これらの違いをすべて示している。
まず、旧来の Vim script:

        let s:lnum=0
        function Leg8(arg) abort
          let l:pre=['Result',
            \': ']
          let b:arg=a:arg
          let s:lnum+=2
          let b:arg*=4
          let l:result={pre->join(pre,'')}(l:pre)
          return l:result.(b:arg+s:lnum)"no space before comment
        endfunction
        call Leg8(10)->popup_notification(#{time: 3000})" 'Result: 42' をポッ
                                                        " プアップする

Vim9 script で同等のもの:

        vim9script

        def Vim9(arg: number): string
          final pre = ['Result',
            ': ']
          b:arg = arg
          lnum += 2
          b:arg *= 4
          const RESULT: string = ((lpre) => join(lpre, ''))(pre)
          return RESULT .. (b:arg + lnum)  # # コメントの前にスペースが必要
        enddef
        Vim9(10)->popup_notification({time: 3000})  # 'Result: 42' をポップアッ
                                                    # プする

        Note: この例では、(:def 関数の外側で) 以下のことも示している:
        - 旧来の #{} から "#" を削除する - vim9-literal-dict を参照、および
        - :call の省略 (Vim9 script では不要だが許可されている)

func(...list<{type}>): {type}
                - 可変個引数に対する型付きリスト
                - 型付きの戻り値を返す

                vim9script
                def L(...l: list<number>): number
                  return l->reduce((x, y) => x + y)
                enddef
                const F: func(...list<number>): number = L->function()
                echo F(8, 0, 0, 1)

func({type}, ...list<{type}>)[: void]
                - 型付きの必須引数
                - 可変個引数に対する型付きリスト
                - 戻り値を返さない

                vim9script
                def D(a: float, ...l: list<number>): void
                  echo (a + l->reduce((x, y) => x + y))->float2nr()
                enddef
                const F: func(float, ...list<number>): void = D->function()
                F(8.0, 0, 0, 1)

func({type}, ...list<{type}>): {type}
                - 型付きの必須引数
                - 可変個引数に対する型付きリスト
                - 型付きの戻り値を返す

                vim9script
                def D(a: float, ...l: list<number>): number
                  return (a + l->reduce((x, y) => x + y))->float2nr()
                enddef
                const F: func(float, ...list<number>): number = D->function()
                echo F(8.0, 0, 0, 1)

参照は Partial にすることもできる。この場合、追加の引数や辞書が格納されるが、
これらは呼び出し元からは参照できない。これらは同じ方法で呼び出されるため、宣言
も同じである。この対話型の例では、円の半径を入力すると、partial を使用して面積
を返す:

        vim9script
        def CircleArea(pi: float, radius: float): float
          return pi * radius->pow(2)
        enddef
        const AREA: func(float): float = CircleArea->function([3.14])
        const RADIUS: float = "Enter a radius value: "->input()->str2float()
        echo $"\nThe area of a circle with a radius of {RADIUS} is " ..
          $"{AREA(RADIUS)} (π to two d.p.)"

                                                        E1005
Funcref で使用できる引数の型は最大 19 個までである (これは、:def やラムダを
含む通常の関数で許容される数より 1 つ少ない数である。E740 を参照)。以下の例
のように、引数の型が 20 個以上になると、E1005 エラーが発生する:

        vim9script
        var X: func
        X = (a, b, c, d, e, f, g, h, i, j, k, l, m, n, o, p, q, r, s, t) => 0
        var F: func(any, any, any, any, any, any, any, any, any, any, any,
          \ any, any, any, any, any, any, any, any, any): any = X->function()
        # E1005: Too many argument types

                                                        E1007
Funcref において、必須引数はオプション引数の後に指定することはできない:

        vim9script
        def I(n: number, f: float): void
          echo n + f
        enddef
        const F: func(?number, float) = I->function()
        # E1007: Mandatory argument after optional argument

                                                vim9-typealias-type
カスタム型 (typealias) は :type で定義できる。ユーザー関数と同様に、大文字
で始める必要がある (これにより、現在または将来の組み込み型との名前の衝突を回避
できる)。この例は、完全平方のリストを作成し、type() (14、typealias)と
typename() について報告する:

        vim9script
        type Ln = list<number>
        final perfect_squares: Ln = [1, 4, 9, 16, 25]
        echo "Typename (Ln): " ..
          $"type() is {Ln->type()} and typename() is {Ln->typename()}"

                                                        E1105
typealias 自体は文字列に変換できない:

        vim9script
        type Ln = list<number>
        const FAILS: func = (): string => {
          echo $"{Ln}"  # E1105: Cannot convert typealias to string
        }
                                    vim9-class-type  vim9-interface-type
                                    vim9-object-type
class、object、interface はすべて型として使用できる。以下の対話型の例は、
float 値の入力を促し、2 つの異なる図形の面積を返す。また、クラス、オブジェク
ト、インターフェイスの type() と typename() も報告する:

        vim9script
        interface Shape
          def InfoArea(): tuple<string, float>
        endinterface
        class Circle implements Shape
          var radius: float
          def InfoArea(): tuple<string, float>
            return ('Circle (π × r²)', 3.141593 * this.radius->pow(2))
          enddef
        endclass
        class Square implements Shape
          var side: float
          def InfoArea(): tuple<string, float>
            return ('Square (s²)', this.side->pow(2))
          enddef
        endclass
        const INPUT: float = "Enter a float value: "->input()->str2float()
        echo "\nAreas of shapes:"
        var myCircle: object<Circle> = Circle.new(INPUT)
        var mySquare: object<Square> = Square.new(INPUT)
        final shapes: list<Shape> = [myCircle, mySquare]
        for shape in shapes
          const [N: string, A: float] = shape.InfoArea()
          echo $"\t- {N} has area of {A}"
        endfor
        echo "\n\t\ttype()\ttypename()\n\t\t------\t----------"
        echo $"Circle\t\t{Circle->type()}\t{Circle->typename()}"
        echo $"Square\t\t{Square->type()}\t{Square->typename()}"
        echo $"Shape\t\t{Shape->type()}\t{Shape->typename()}"
        echo $"MyCircle\t{myCircle->type()}\t{myCircle->typename()}"
        echo $"MySquare\t{mySquare->type()}\t{mySquare->typename()}"
        echo $"shapes\t\t{shapes->type()}\t{shapes->typename()}"

                                        vim9-enum-type  vim9-enumvalue-type
enum は型 (v:t_enum) として使用できる。enum 値を保持する変数は、実行時に
enumvalue 型 (v:t_enumvalue) を持つ。以下の対話型の例は、文字の入力を促し、
正方形または菱形に関する情報を返す。また、enum と enumvalue の type() と
typename() も報告する:

        vim9script
        enum Quad
          Square('four', 'only'),
          Rhombus('opposite', 'no')
          var eq: string
          var ra: string
          def string(): string
            return $"\nA {this.name} has " ..
              $"{this.eq} equal sides and {this.ra} right angles\n\n"
          enddef
        endenum
        echo "Rhombus (r) or Square (s)?"
        var myQuad: Quad = getcharstr() =~ '\c^R' ? Quad.Rhombus : Quad.Square
        echo myQuad.string() .. "\ttype()\ttypename()"
        echo $"Quad  \t{Quad->type()}  \t{Quad->typename()}"
        echo $"myQuad\t{myQuad->type()}\t{myQuad->typename()}"

        Notes: ここでは組み込みメソッド "string()" が使用されている。
        object-string() を参照。Quad と myQuad の typename() は同じ
        ("enum<Quad>") だが、type() は区別される (myQuad は 16、つまり
        EnumValue を返すが、Quad は 15、つまり Enum を返す)。

変数の型と型キャスト
                                                        variable-types
Vim9 script 内または :def 関数内で宣言された変数には、明示的に指定されるか、
初期化から推測される型がある。

グローバル変数、バッファ変数、ウィンドウ変数、タブページ変数には特定の型がな
い。そのためこれらの変数の値はいつでも変更される可能性があり、その結果、型も変
更される可能性がある。そのため、コンパイルされたコードでは "any" 型が想定され
る。

これは、リストを宣言する場合など、より厳密な型指定が必要な場合に問題になる可能
性がある:
        var l: list<number> = [1, b:two]
Vimは "b:two" の型を知らないため、式は list<any> となる。実行時チェックでは、
代入前にリストが宣言された型と一致するかどうかが検証される。

                                                        type-casting
より具体的な型チェックを行うには、型キャストを使用する。これは、リスト項目が宣
言された型と一致するかどうかをチェックするのではなく、リストを構築する前に変数
の型をチェックする。例:
        var l: list<number> = [1, <number>b:two]

したがって、ここでの型キャストは "b:two" が数値であるかどうかをチェックし、そ
うでない場合はエラーを返す。

違いは以下の例で示されている。funcref 変数 "NTC" の場合、Vim は式型
"[1, b:two]" を list<any> と推論し、次にそれが list<number> の戻り値型に代入可
能かどうかを検証する。funcref 変数 "TC" の場合、型キャストによって Vim はま
ず "b:two" が <number> 型であるかどうかを確認する:

        vim9script
        b:two = '2'
        const NTC: func = (): list<number> => {
          return [1, b:two]
        }
        disassemble NTC  # 3 CHECKTYPE list<number> stack [-1]
        try
          NTC()
        catch
          echo v:exception .. "\n\n"  # E1012: Type mismatch; Expected list...
        endtry
        const TC: func = (): list<number> => {
          return [1, <number>b:two]
        }
        disassemble TC  # 2 CHECKTYPE number stack [-1]
        try
          TC()
        catch
          echo v:exception  # E1012: Type mismatch; Expected number but got...
        endtry

        Note: 型チェックがいつ行われるかを示すエラーメッセージがどのように異な
        るかに注意。

                                                        E1104
型キャストの構文は "<{type}>" である。開始 "<" (E121) または終了 ">" (E1104)
のいずれかが省略された場合、エラーが発生する。また、"<" の後 (E15) と ">" の
前 (E1068) には空白文字を入れることはできない。これは、小なり および 大なり
演算子との曖昧さを回避するためである。

型キャストは明示的な型チェックを強制するが、変数の値や型は変更されない。型を変
更する必要がある場合、文字列に変換するには string() を、文字列を数値に変換す
るには str2nr() などの関数を使用する。

連鎖式に型キャストを適用する場合、最終結果と互換性がある必要がある。例:

        vim9script
        # これらの型キャストは動作する
        echo <list<any>>[3, 2, 1]->extend(['Go!'])
        echo <string>[3, 2, 1]->extend(['Go!'])->string()
        echo <tuple<...list<number>>>[3, 2, 1]->list2tuple()
        # この型キャストは失敗する
        echo <number>[3, 2, 1]->extend(['Go!'])->string()

                                                        E1272
型が予期されないコンテキストにて型が使用されると、E1272 が発生する可能性がああ
る。例:
        :vim9cmd echo islocked('x: string')
   Note: エラーを見るには、このコマンドは読み込むのではなく、Vim のコマンドラ
  インから実行する必要がある。

                                                        E1363 E1395
オブジェクトのクラスが不明な場合など、型が不完全な場合は、E1363 または E1395
が発生する。例:

        vim9script
        var E1363 = null_class.member   # E1363: Incomplete type

        vim9script
        def F1395(): void
          echo null_class.member
        enddef
        F1395()  # E1395: Using a null class

もう 1 つの null オブジェクト関連のエラーは E1360 である:

        vim9script
        var obj = null_object
        var E1360 = obj.MyMethod()      # E1360: Using a null object


型推論
                                                        type-inference
型を明示的に宣言すると、対象を絞った型チェックやエラーメッセージの明確化など、
多くの利点がある。しかし、Vim は型が省略された場合でも、多くの場合自動的に型を
推論する。例えば、以下の変数の型は推論されており、type() と typename() は
推論された型を示している:

        vim9script
        echo "\t type()\t typename()"
        var b = true   | echo $"{b} \t {b->type()} \t {b->typename()}"
        var f = 4.2    | echo $"{f} \t {f->type()} \t {f->typename()}"
        var l = [1, 2] | echo $"{l} \t {l->type()} \t {l->typename()}"
        var n = 42     | echo $"{n} \t {n->type()} \t {n->typename()}"
        var s = 'yes'  | echo $"{s} \t {s->type()} \t {s->typename()}"
        var t = (42, ) | echo $"{t} \t {t->type()} \t {t->typename()}"

リスト、Tuple、または辞書の型は、その値の共通の型から推論される。値がすべて同
じ型の場合、その型が使用される。
複数の型が混在する場合は、"any" 型が使用される。以下の例では、各リテラルに対し
て表示された typename() がこれらのポイントを示している:

        vim9script
        echo [1, 2]->typename()                         # list<number>
        echo [1, 'x']->typename()                       # list<any>
        echo {ints: [1, 2], bools: [false]}->typename() # dict<list<any>>
        echo (true, false)->typename()                  # tuple<bool, bool>

関数参照の一般的な型では、引数の数が異なる場合、"(...)" で示される。これは引数
の数が不揃いであることを意味する。このスクリプトは "list<func(...): void>" の
例である:

        vim9script
        def Foo(x: bool): void
        enddef
        def Bar(x: bool, y: bool): void
        enddef
        var funclist = [Foo, Bar]
        echo funclist->typename()

Vim9 script 内のスクリプトローカル変数は型チェックされる。また、旧来の関数内で
宣言された変数についても型チェックが行われる。例:

        vim9script
        var my_local = (1, 2)
        function Legacy()
          let b:legacy = [1, 2]
        endfunction
        Legacy()
        echo $"{my_local} is type {my_local->type()} ({my_local->typename()})"
        echo $"{b:legacy} is type {b:legacy->type()} ({b:legacy->typename()})"

                                                        E1013
リスト、Tuple、または辞書の型が宣言されると、その型が関連付けられる。同様に、
型が宣言されていない場合は、Vim が推論した型が関連付けられる。どちらの場合も、
式によって型が変更されると、E1013 が発生する。以下の例では、型が推論され、
E1013 が発生する:

        vim9script
        var lb = [true, true]   # 2 つの bool なので Vim は list<bool> 型と推測
        echo lb->typename()     # list<bool>
        lb->extend([0])         # E1013 Argument 2: type mismatch, ...

許容的なリストが必要な場合は、<any> を明示的に使用するか、最初に空のリストを宣
言する (または両方、つまり list<any> = [])。例:

        vim9script
        final la: list<any> = []
        echo la->extend(['two', 1])
        final le = []
        echo le->extend(la)

許容的な辞書の場合も同様:

        vim9script
        final da: dict<any> = {}
        echo da->extend({2: 2, 1: 'One'})
        final de = {}
        echo de->extend(da)->string()

また、Tuple 自体は不変だが、空の Tuple を使用して、許容的な Tuple の連結を実現
できる (可変長の Tuple は同じ型の Tuple とのみ連結できる。E1540 を参照):

        vim9script
        var t_dec_empty = ()
        t_dec_empty = t_dec_empty + (3, '2', true)
        echo t_dec_empty

リストリテラルまたは辞書リテラルが変数にバインドされていない場合、以下の例に示
すように、その型が変更される場合がある:

        vim9script
        echo [3, 2, 1]->typename()                      # list<number>
        echo [3, 2, 1]->extend(['Zero'])->typename()    # list<any>
        echo {1: ['One']}->typename()                   # dict<list<string>>
        echo {1: ['One']}->extend({2: [2]})->typename() # dict<list<any>>


より厳密な型チェック
                                                        type-checking
旧来の Vim script では、数値が期待される文字列は自動的に数値に変換されていた。
これは "123" のような実際の数値であれば便利だったが、文字列が数値で始まってい
ない場合、予期せぬ問題が発生する (エラーメッセージも表示されない)。これは多く
の場合、見つけにくいバグにつながる。例えば、旧来の Vim script では、これは "1"
と表示される:

        echo 123 == '123'

ただし、意図しないスペースが含まれている場合は、"0" が表示される:

        echo 123 == ' 123'

                                                        E1206
Vim9 script では、この制限がより厳格になった。ほとんどの箇所では、使用される値
が期待される型と一致する場合、以前と同じように動作する。例えば、旧来の Vim
script と Vim9 script の両方で、辞書以外の値が必要なときに、辞書以外の値を使用
しようとすると、以下のようになる:

        echo [8, 9]->keys()
        vim9cmd echo [8, 9]->keys()     # E1206: Dictionary required

                                                        E1023 E1024 E1029
                                                        E1030 E1174 E1175
                                                        E1210 E1212
しかし、Vim9 script ではエラーが発生し、後方互換性が損なわれることがある。以下
の例は、この問題が発生する様々な場所を示している。まず、旧来の Vim script の動
作 (エラーは発生しない) を示す。次に同じコマンドを Vim9 script で使用した場合
に発生するエラーを示す。

- bool が期待される場所で数値 (0 または 1 以外) を使用する:

        echo v:version ? v:true : v:false
        vim9cmd echo v:version ? true : false   # E1023: Using a Number as ...

- 文字列が期待される場所で数値を使用する:

        echo filter([1, 2], 0)
        vim9cmd echo filter([1, 2], 0)  # E1024: Using a Number as a String

- 環境変数、レジスタまたは文字列型の v: 変数に数値を代入する:

        let $FOO = 123
        vim9cmd $FOO = 123      # E1012: Type mismatch; expected string but ...

- 数字が期待されるところで数字を使用していない:

        " この例では、旧来の Vim script は v:false を 0 として扱う
        function Not1029()
            let b:l = [42] | unlet b:l[v:false]
        endfunction
        call Not1029() | echo b:l

        vim9script
        def E1029(): void
            b:l = [42] | unlet b:l[false]
        enddef
        E1029()  # E1029: Expected number but got bool

- 文字列を数値として使用する:

        let b:l = [42] | unlet b:l['#'] | echo b:l
        vim9cmd b:l = [42] | vim9cmd unlet b:l['#']  # E1030: Using a string

- 引数に文字列が必要な場合に文字列を使用しない:

        echo substitute('Hallo', 'a', 'e', v:true)
        vim9cmd echo substitute('Hallo', 'a', 'e', true)  # E1174: String ...

- 空でない文字列を必要とする引数で空の文字列を使用する:

        echo exepath('')
        vim9cmd echo exepath('')  # E1175: Non-empty string required for ar...

- 必要なときに数字を使用しない:

        echo gettabinfo('a')
        vim9cmd echo gettabinfo('a')  # E1210: Number required for argument 1

- 必要なときに真偽値を使用しない:

        echo char2nr('¡', 2)
        vim9cmd echo char2nr('¡', 2)  # E1212: Bool required for argument 2

- 数字が必要なときに数字を使用しない (E521):

        let &laststatus='2'
        vim9cmd &laststatus = '2'

- 文字列が必要なときに文字列を使用しない (E928):

        let &langmenu = 42

- Special と "is" の比較はしばしば失敗する (E1037, E1072):

        " 旧来の Vim script では両方とも真なので 1 が表示される
        echo v:null is v:null && v:none is v:none
        " 同様に、これらでは 0 が表示される (旧来の Vim script では偽)
        echo v:none is v:null || v:none is 8 || v:true is v:none
        " All these are errors in Vim9 script
        " これらはすべて Vim9 script のエラー

        vim9cmd echo v:none is v:none   # E1037: Cannot use 'is' with special
        vim9cmd echo v:none is v:null   # E1037: Cannot use 'is' with special
        vim9cmd echo v:none is 8        # E1072: Cannot compare special wit...
        vim9cmd echo v:true is v:none   # E1072: Cannot compare bool with s...

        発生するが、v:null では false が返される (これは null と同じであ
        る - v:null を参照):

        vim9script
        echo v:null is 8        # false
        echo true is v:null     # false

- 真偽値が必要な場所で文字列を使用する (E1135):

        echo '42' ? v:true : v:false
        vim9cmd echo '42' ? true : false  # E1135: Using a String as a Bool

- 真偽値を数値として使用する (E1138):

        let &laststatus=v:true

結果として、map() に渡されるリストまたは辞書の項目の型は、その型が宣言または
推論された場合でも変更してはいけない。例えば、このリストの型は旧来の Vim
script では問題なく変更される:

        " 旧来の Vim script でリスト [0, 1] を ['item 0', 'item 1'] に変更する
        let s:mylist = [0, 1]
        call map(s:mylist, {i -> $"item {i}"})
        echo s:mylist

一方、Vim9 script では E1012 が発生する:

        vim9script
        var mylist = [0, 1]                # Vim は mylist が list<number> で
                                           # あると推測する
        map(mylist, (i, _) => $"item {i}") # E1012: Type mismatch; expected...

このエラーは、map() がリスト要素を文字列に変更しようとし、宣言された型と衝突
するために発生する。

代わりに mapnew() を使用する。これは新しいリストを作成し、型が指定されていな
い場合は Vim がその型を推測する。推測された型と宣言された型は以下の例のとおり
である:

        vim9script
        var mylist = [0, 1]
        var infer = mylist->mapnew((i, _) => $"item {i}")
        echo [infer, infer->typename()]
        var declare: list<string> = mylist->mapnew((i, _) => $"item {i}")
        echo [declare, declare->typename()]

ここで重要な概念は、宣言型または推論型を持つ変数では、コンテナ内の要素の型は変
更できないということである。ただし、以下のいずれかの場合は型の "変更" が許容さ
れる:
- コンテナリテラル (変数に束縛されていない)、または
- メソッドチェーンで copy() または deepcopy() が使用されているコンテナ。
この例では、どちらも示されている:

        vim9script
        # 文字列のリスト
        echo [1, 2]->map((_, v) => $"#{v}")
        echo [1, 2]->map((_, v) => $"#{v}")->typename()
        # メソッドチェーン内の deepcopy()
        var mylist = [1, 2]
        echo mylist->deepcopy()->map((_, v) => $"#{v}")
        echo mylist->deepcopy()->map((_, v) => $"#{v}")->typename()
        echo mylist

この理由は、型が宣言または推論され、リストが渡されたり変更されたりする場合、宣
言/推論は常に成立していなければならないためである。そうすることで、型が宣言/推
論された型と一致することを保証できる。文字列のリストでも完全にコピーされたリス
トでも、元のリストは変更されないため、型安全性は必要ない (上記の "echo mylist"
が示すように)。

項目の型が "<any>" と宣言または決定されていない場合、後ですべての項目が同じ型
になったとしても、項目の型は変更されない。ただし、mapnew() を使用する場合、
推論とは、新しいリストが既存の型を反映することを意味する。例えば、以下のように
なる:

        vim9script
        # list<any>
        var mylist = [1, '2']                   # 混合型、つまり list<any>
        echo (mylist, mylist->typename())       # ([1, '2'], 'list<any>')
        mylist->map((_, v) => $"item {v}")      # では、すべての項目が文字列に
        echo (mylist, mylist->typename())       # なる。両方とも文字列だが、
                                                # list<any> である
        # mapnew()
        var newlist = mylist->mapnew((_, v) => v)
        echo (newlist, newlist->typename())     # newlist は list<string>

extend() と extendnew() の使い方は似ている。つまり、文字列のリストでは前者
を使用できるので、以下のようにして問題ない:

        vim9cmd echo [1, 2]->extend(['3'])      # [1, 2, '3']

一方、これはそうではない:

        vim9script
        var mylist: list<number> = [1, 2]
        echo mylist->extend(['3'])      # E1013: Argument 2: type mismatch

既存の型付きリストを拡張するには、extendnew() を使用する必要がある。ただし、
拡張がリストの型と一致する場合 (または "any" の場合) は除く。例えば、最初に同
じ型の要素で拡張し、次に異なる型で拡張する場合である:

        vim9script
        var mylist: list<number> = [1, 2]
        mylist->extend([3])
        echo mylist->extendnew(['4'])   # [1, 2, 3, '4']

Vim9 script では flatten() の使用は許可されていない。これは常に型を変更する
ことを意図しているためである。これは文字列のリストにも適用される (map() や
extend() とは異なる)。代わりに flattennew() を使用すること:

        vim9cmd [1, [2, 3]]->flatten()          # E1158: Cannot use flatten

引数の数が可変である場合、以下の例のように、引数は同じ型である必要がある:

        vim9script
        var Fproduct: func(...list<number>): number

        echo Fproduct(3, 2, 4)  # 24

また、混合型に対応するために <any> を使用することもできる:

        vim9script

変数、デフォルト、および null 処理のカテゴリ
                                        variable-categories null-variables
変数には 3 つのカテゴリがある:
        プリミティブ型  数値、浮動小数点数、ブール値
        コンテナ型      文字列、blob、リスト、tuple、辞書
        特殊型          関数、ジョブ、チャネル、ユーザー定義オブジェクト

初期化子なしで変数を宣言する場合は、明示的に型を指定する必要がある。各カテゴリ
には異なるデフォルトの初期化セマンティクスがある。

プリミティブ型は、デフォルトで型固有の値になる。すべてのプリミティブ型は空だ
が、null と等しくはない:

        vim9script
        var n: number | echo [n, n->empty(), n == null]  # [0, 1, false]
        var f: float  | echo [f, f->empty(), f == null]  # [0.0, 1, false]
        var b: bool   | echo [b, b->empty(), b == null]  # [false, 1, false]

コンテナ型はデフォルトで空のコンテナになる。空の文字列のみが null と等しくな
る:

        vim9script
        var s: string       | echo [s, s->empty(), s == null] # ['', 1, true]
        var z: blob         | echo [z, z->empty(), z == null] # [0z, 1, false]
        var l: list<string> | echo [l, l->empty(), l == null] # [[], 1, false]
        var t: tuple<any>   | echo [t, t->empty(), t == null] # [(), 1, false]
        var d: dict<number> | echo [d, d->empty(), d == null] # [{}, 1, false]

特殊型はデフォルトで null になる:

        vim9script
        var F: func    | echo [F, F == null]  # [function(''), true]
        var j: job     | echo [j, j == null]  # ['no process', true]
        var c: channel | echo [c, c == null]  # ['channel fail', true]
        class Class
        endclass
        var o: Class   | echo [o, o == null]  # [object of [unknown], true]
        enum Enum
        endenum
        var e: Enum    | echo [e, e == null]  # [object of [unknown], true]

        Notes: (1) 空のジョブ、空のチャネル、空のオブジェクト型の説明について
        は、empty() を参照。(2) class、enum、typealias 型は値として使
        用できないため、null と比較できない (それぞれ E1405、E1421、
        E1403 を参照)。

Vim にはお馴染みの null 値はない。代わりに、null_string、null_list、
null_job など、様々な null_<type> 型の定義済み値がある。プリミティブ型には
null_<type> 型はない。null_<type> 型の典型的な使用例は以下のとおりである:
- 変数をクリアしてリソースを解放する。
- 関数定義のパラメータのデフォルトとして使用する (例については null_blob を
  参照)。
- コンテナ型または特殊型に割り当てて、後の比較のために null に設定する (例につ
  いては null-compare を参照)。

job のような特殊な変数の場合、リソースをクリアするために null_<type> が使用
される。例:

        vim9script
        var mydate: list<string>
        def Date(channel: channel, msg: string): void
          mydate->add(msg)
        enddef
        var myjob = job_start([&shell, &shellcmdflag, 'date'], {out_cb: Date})
        echo [myjob, myjob->job_status()]
        sleep 2
        echo $"The date and time is {mydate->join('')}"
        echo [myjob, myjob->job_status()]
        myjob = null_job  # 変数をクリアし、ジョブのリソースを解放する。
        echo myjob

コンテナ変数の場合、変数に空のコンテナを割り当てることによってリソースをクリア
することもできる。例:

        vim9script
        var perfect: list<number> = [1, 4]
        perfect->extend([9, 16, 25])
        perfect = []
        echo perfect

null_<type> ではなく空のコンテナを使用してコンテナ変数をクリアすると、null の
複雑さを回避できる場合がある - null-anomalies を参照。

コンテナ変数と特殊変数の初期化セマンティクスは異なる。コンテナの場合:
- 初期化されていないコンテナはデフォルトで空になるが、null と等しくない (初
  期化されていない文字列を除く)。
- []、()、{}、""、または 0z に初期化されたコンテナは空だが、null と等しくな
  い。
- null_<type> として初期化されたコンテナはデフォルトで空になり、null とも等
  しくなる。

以下の例では、初期化されていないリスト ("lu") と [] 初期化されたリスト ("li")
は同等であり区別できないが、"ln" は null コンテナであり、空のコンテナに似てい
るが同等ではない (null-anomalies を参照)。

        vim9script
        # 初期化されていない: 空のコンテナ、null ではない
        var lu: list<any>
        echo ['lu', $"empty={lu->empty()}", $"null={lu == null}"]
        # 初期化済み: 空のコンテナ、null ではない
        var li: list<any> = []
        echo ['li', $"empty={li->empty()}", $"null={li == null}"]
        # 初期化済み: 空のコンテナ、null
        var ln: list<any> = null_list
        echo ['ln', $"empty={ln->empty()}", $"null={ln == null}"]

特殊変数はデフォルトで null になる。以下のジョブ初期化は同等であり、区別できな
い:

        vim9script
        var j1: job
        var j2: job = null_job
        var j3 = null_job
        echo (j1 == j2) == (j2 == j3)  # true (同等、区別不能)

リスト、tuple、または辞書を宣言する際に、項目の型が指定されていない場合は推論
できない。したがって、項目の型はデフォルトで "any" になる:

        vim9script
        var [t1, t2] = [(), null_tuple]
        echo $'t1 is {t1->typename()} and t2 is {t2->typename()} too'

Tuple と関数 (または部分関数) は様々な方法で宣言できる。tuple-type、
variadic-tuple、および vim9-func-declaration を参照。

                                                        null-compare
空のコンテナと null コンテナが等しくないという、おなじみの null 比較セマンティ
クスでは、比較に null_<type> を使用してはならない。これは、Vim9 script では
null_<type> == null であっても、以下の比較が成立するからである:
- 空のコンテナを null にすると false だが、
- 空のコンテナを null_<type> にすると true になる。

したがって、null_<type> ではなく null と比較すること。例:

        vim9script
        var bonds: dict<list<string>> = {g: ['007', '008'], o: ['007', '009']}
        def Search(query: string): list<string>
          return query == "\r" ? null_list : bonds->get(query, [])
        enddef
        echo "Goldfinger (g) or Octopussy (o)?: "
        const C: string = getcharstr()
        var result: list<string> = C->Search()
        if result == null  # <<< DO NOT USE null_list HERE!
          echo "Error: Nothing was entered"
        else
          echo result->empty() ? $"No matches for '{C}'" : $"{result}"
        endif

        Note: "result == null" の代わりに "result == null_list" を使用すると、
        [] != null であるのに対し [] == null_list であるため、エラー (何も入力
        されていない) と有効な結果 (何も一致していない) を区別できなくなる。

概念的には、null_<type> 構文は、汎用的な null と型付きの empty コンテナと
の中間に位置するハイブリッド/ブリッジのようなものと考えるとよく、両者の性質を
併せ持っている。比較結果の詳細については、以下の節で説明する。

                                                null-details null-anomalies
このセクションでは、null と null_<type> の使用に関する問題について説明する。以
下に、null 比較の列挙結果を示す。場合によっては、vim9 の null のセマンティクス
に精通しているプログラマは、比較やその他の状況で null_<type> を使用することを
選択する場合がある。

ドキュメントの別の箇所では、"多くの場合、null 値は空の値と同じように扱われる
が、常にそうとは限らない」と書かれている。例えば、null コンテナにデータを追加
することはできない:

        vim9script
        var le: list<any> = []
        le->add('Okay')         # le は ['Okay']
        var ln = null_list
        ln->add("E1130")        # E1130: Cannot add to null list

null-compare で説明したように、null、null_<type> コンテナ、empty の間に
は非推移的な関係がある。まとめると、例えば以下のようになる:

        vim9cmd echo (null_dict == {}, null_dict == null, {} != null)

例外は未初期化の文字列である。これは null と等しく (null_string と同じイン
スタンスである)。文字列が未初期化かどうかを判断するには、"is" 演算子
(expr-is) を使用できる:

        vim9script
        var s: string
        echo s == null_string   # true
        echo s is null_string   # true (同じインスタンス)
        echo s == null          # true (意外かもしれない)
        echo s is null          # false (同じインスタンスではない)

ただし、他のコンテナについては同じことを行ってはならない。対応する null_<type>
に対して "is" で評価すると、false が返されるためである:

        vim9script
        var d: dict<any>
        echo d == null_dict     # true
        echo d is null_dict     # false (同じインスタンスではない)
        echo d == null          # false (期待通り)
        echo d is null          # false (同じインスタンスではない)

ここでの重要な違いは、初期化されていない文字列は null_string として実装され
るのに対し、初期化されていないリスト、辞書、tuple、または blob は空のコンテナ
(それぞれ []、{}、()、および 0z) として実装されることである。
したがって、これらの初期化されていない型は、以下の例に示すように、対応する
null_<type> と同等であるが、同じインスタンスではない:

        vim9script
        var t: tuple<any>
        echo t == null_tuple    # true
        echo t is null_tuple    # false

ただし、null_<type> に初期化された変数は、null_<type> と等しいだけでなく、null
とも等しくなる。例:

        vim9script
        var t: tuple<any> = null_tuple
        echo t == null_tuple    # true
        echo t is null_tuple    # true
        echo t == null          # true

初期化されていないコンテナ変数は、上記の例で説明したように、初期化されていない
文字列を除き、null と等しくない。したがって、以下の式はすべて true を表示す
る:

        vim9script
        var b: blob       | echo b != null
        var d: dict<any>  | echo d != null
        var l: list<any>  | echo l != null
        var t: tuple<any> | echo t != null
        var s: string     | echo s == null

初期化されていない特殊変数は null に等しい。したがって、これらはすべて true
を表示する:

        vim9script
        var c: channel  | echo c == null
        var F: func     | echo F == null
        var j: job      | echo j == null
        class Class
        endclass
        var nc: Class   | echo nc == null
        enum Enum
        endenum
        var ne: Enum    | echo ne == null

        Note: job のような特殊な変数はデフォルトで null に設定され、対応する空
        の値を持つ特殊な変数はない。

空に初期化されたコンテナ変数は null_<type> に等しいため、これらはすべて true
になる:

        vim9script
        var s: string = ""      | echo s == null_string
        var b: blob = 0z        | echo b == null_blob
        var l: list<any> = []   | echo l == null_list
        var t: tuple<any> = ()  | echo t == null_tuple
        var d: dict<any> = {}   | echo d == null_dict

ただし、空に初期化されたコンテナ変数は null と等しくないため、これらはすべて
true になる:

        vim9script
        var s: string = ""      | echo s != null
        var b: blob = 0z        | echo b != null
        var l: list<any> = []   | echo l != null
        var t: tuple<any> = ()  | echo t != null
        var d: dict<any> = {}   | echo d != null

5. ジェネリック関数                                     generic-functions

ジェネリック関数は、引数と戻り値の型チェックを維持しながら、同じ関数を異なる型
の引数で使用できる。これにより、型安全性とコードの再利用性が確保される。


宣言
                                                generic-function-declaration
                                                E1553 E1554
ジェネリック関数の型変数は、関数名の直後に山括弧 ("<" と ">") で囲まれた型パ
ラメータとして宣言される。複数の型パラメータはコンマで区切られる:

        def[!] {funcname}<{type} [, {types}]>([arguments])[: {return-type}]
          {function body}
        enddef
                                                generic-function-example
これらの型パラメータは、他の型と同様に、関数シグネチャとその本体内で使用でき
る。以下の例では、2 つのリストを tuple のリストに結合している:

        vim9script
        def Zip<T, U>(first: list<T>, second: list<U>): list<tuple<T, U>>
          const LEN: number = ([first->len(), second->len()])->min()
          final result: list<tuple<T, U>> = []
          for i in range(LEN)
            result->add((first[i], second[i]))
          endfor
          return result
        enddef
        var n: list<number> = [61, 62, 63]
        var s: list<string> = ['a', 'b', 'c']
        echo $"Zip example #1: {Zip<number, string>(n, s)}"
        echo $"Zip example #2: {Zip<string, number>(s, n)}"

                                                type-variable-naming E1552
                                                type-parameter-naming
前の例と同様に、名前には大文字を 1 文字だけ使用するのが慣例である (例えば、T、
U、Aなど)。複数の文字で構成されている場合もあるが、名前は必ず大文字で始まる必
要がある。この例では、"Ok" は有効だが、"n" は無効である:

        vim9script
        def MyFail<Ok, n>(): void
        enddef
        # E1552: Type variable name must start with an uppercase letter: n>...

                                                        E1558 E1560
関数は、ジェネリック関数または通常の関数のいずれかとして宣言および使用する必要
がある。両方を同時に使用することはできない。以下の Vim9 script は、これらのエ
ラーを示している:

        vim9script
        My1558<number>()
        # E1558: Unknown generic function: My1558

        vim9script
        def My1560(): void
        enddef
        My1560<string>()
        # E1560: Not a generic function: My1560

                                                        E1561
型パラメータ名は他の識別子と競合してはならない:

        vim9script
        def My1561<D, E, D>(): D
        enddef
        # E1561: Duplicate type variable name: D

        vim9script
        enum E
          Yes, No
        endenum
        def My1041<E>(): E
        enddef
        # E1041: Redefining script item: "E"


ジェネリック関数の呼び出し
                                                        generic-function-call
ジェネリック関数を呼び出すには、関数名と引数リストの間に "<" と ">" で具体的な
型を指定する:

        MyFunc<number, string, list<number>>()

        Note: このセクションには、generic-function-example など、読み込むこ
        とができる実用的な例がいくつかある。

                                                E1555 E1556 E1557 E1559
関数に渡される型引数の数は、宣言された型パラメータの数と一致している必要があ
る。空の型リストは許可されない。例:

        vim9script
        def My1555<>(): void
        enddef  # E1555: Empty type list specified for generic function '<S...

        vim9script
        def My1556<T>(): void
        enddef
        My1556<bool, bool>()  # E1556: Too many types specified for generic...

        vim9script
        def My1557<T, U>(): void
        enddef
        My1557<bool>()  # E1557: Not enough types specified for generic fun...

        vim9script
        def My1559<T>(): T
        enddef
        My1559()  # E1559: Type arguments missing for generic function '<SN...

任意の Vim9 型 (vim9-types) は、ジェネリック関数内の具体的な型として使用でき
る。

スペースは使用できない:
- 関数名と "<" の間 (E1068)
- ">" と "(" の間 (E1068)、または
- "<" と ">" 内。ただし、型を区切るコンマの後に必須の箇所を除く (E1202)。

ジェネリック関数は通常の関数と同様に export および import できる。:export お
よび :import を参照。

ジェネリック関数は、別の通常関数またはジェネリック関数内で定義できる。
例:

        vim9script
        def Outer(): void
          # Returns either the first item of a list or a default value
          def FirstOrDefault<T, U>(lst: list<T>, default: U): any
            return lst->len() > 0 ? lst[0] : default
          enddef
          echo FirstOrDefault<string, bool>(['B', 'C'], false)  # B
          echo FirstOrDefault<number, number>([], 42)           # 42
        enddef
        Outer()

入れ子にしたジェネリック関数は、再帰的に呼び出すことや、ラムダや別の入れ子の関
数などのクロージャ内で使用することもできる。

型変数を型引数として使用する

型変数は型引数として渡すこともできる。例:

        vim9script
        # T は型パラメータとして宣言されている
        # これは 'value' パラメータと戻り値の型に使用される
        def Id<T>(value: T): T
          return value
        enddef
        # U は型パラメータとして宣言されている
        # これは 'value' パラメータと戻り値の型に使用される
        def CallId<U>(value: U): U
          # U は型引数として渡される/使用される型変数である
          return Id<U>(value)
        enddef
        echo CallId<string>('I am') .. ' ' .. CallId<number>(42)

これは、リストの辞書や、以下の例のように辞書のリストのような複雑なデータ構造に
役立つ:

        vim9script
        def Flatten<T>(x: list<list<T>>): list<T>
          final result: list<T> = []
          for inner in x
            result->extend(inner)
          endfor
          return result
        enddef
        const ENGLISH: list<dict<string>> = [{1: 'one'}, {2: 'two'}]
        const MANDARIN: list<dict<string>> = [{1: '壹'}, {2: '贰'}]
        const ARABIC_N: list<dict<number>> = [{1: 1}, {2: 2}]
        echo Flatten<dict<string>>([ENGLISH, MANDARIN])
        echo Flatten<dict<any>>([ENGLISH, ARABIC_N])

"Flatten<T>" では、"T" は宣言された型パラメータである。関数内の他の場所では、
"T" はその型パラメータを参照する型変数である。


ジェネリッククラスメソッド

Vim9 クラスのメソッドはジェネリック関数になることができる:

        vim9script
        class Config
          var settings: dict<any>
          def Get<T>(key: string): T
            return this.settings[key]
          enddef
        endclass
        var c: Config = Config.new({timeout: 30, debug: true})
        echo c.Get<number>('timeout')
        echo c.Get<bool>('debug')

                                                        E1432 E1433 E1434
基底クラスのジェネリッククラスメソッドは、子クラスのジェネリックメソッドでオー
バーライドできる。型変数の数は両方のメソッド間で一致している必要がある。具象ク
ラスメソッドをジェネリックメソッドでオーバーライドすることはできない。逆もまた
同様である。
                                                        E1438
インターフェイスメソッドを実装するメソッドは、インターフェイスメソッドと同じ数
の型変数を持たなければならない。ジェネリックメソッドは通常のメソッドを実装でき
ない。逆もまた同様である。


ジェネリック関数参照

関数参照 (Funcref) はジェネリック関数として使用できる。これにより、特定の型
を操作する関数のファクトリーを作成できる:

        vim9script
        # 文字列内の指定された文字、またはリスト内の文字の 10 進数値と一致す
        # る。Note: '*' は 10 進数の 42 (U+002A)
        var c: string = "*"
        var char_dec: tuple<string, string> = (c, c->char2nr()->string())
        def Matcher<T>(pattern: string): func(T): bool
          return (value: T): bool => match(value, pattern) >= 0
        enddef
        var StringMatch = Matcher<string>(char_dec[0])
        echo "*+"->StringMatch()        # true (has *)
        echo ",-"->StringMatch()        # false
        var ListMatch = Matcher<list<number>>(char_dec[1])
        echo [42, 43]->ListMatch()      # true (has 42)
        echo [44, 45]->ListMatch()      # false


ジェネリック関数のコンパイルと逆アセンブル

:defcompile コマンドは、具体的な型の特定のリストを持つジェネリック関数をコン
パイルするために使用できる:

        defcompile MyFunc<number, list<number>, dict<string>>

:disassemble コマンドを使用すると、ジェネリック関数に対して生成された命令を
一覧表示できる:

        disassemble MyFunc<string, dict<string>>
        disassemble MyFunc<number, list<blob>>


制限事項と今後の課題

現在、Vim は以下をサポートしていない:
- 型変数の型推論: ジェネリック関数を呼び出す際は、すべての型を明示的に指定する
  必要がある。
- 型制約: 型変数を特定のクラスまたはインターフェイスに制限することはできない
  (例: T extends SomeInterface)。
- デフォルト型引数: 型パラメータが明示的に指定されていない場合に、デフォルトの
  型を提供する。

6. 名前空間、Import と Export                           vim9script
                                                vim9-export vim9-import
Vim9 script は、import されるように書くことができる。これは、いくつかの項目が
意図的に export され、他のスクリプトで利用できるようになることを意味する。
export したスクリプトが他のスクリプトで import されると、これらの export され
た項目はそのスクリプトで使用することができる。その他の項目は、export したスク
リプトのスクリプトローカルのままであり、import スクリプトからアクセスすること
はできない。

この機構は、他のスクリプトがソース (import される) されうるスクリプトを書くた
めに存在し、他のスクリプトがあなたが望むものだけにアクセスできるようにする。ま
た、名前衝突の危険性があるグローバル名前空間を使用することも避けられる。例え
ば、似たような機能を持つ2つのプラグインがある場合である。

グローバル名前空間を明示的に使用することで、ごまかすことができる。これは、本当
にグローバルなものだけに行うべきことである。


名前空間
                                                        vim9-namespace
import 可能なファイルを認識するためには、vim9script コマンドがファイルの最初
のコマンドとして現れる必要がある (ただし、例外については vim9-mix を参照)。
これは Vim に、グローバルな名前空間ではなく、独自の名前空間でスクリプトを解釈
するように指示する。次のスクリプトを考えてみる:

        vim9script
        var myvar = 'yes'

変数 "myvar" はこのスクリプトのスコープの中にしか存在しないことになる。これは、
"let myvar" によって "myvar" が他のスクリプトや関数から (g:myvar として) 利
用できるようになる旧来の Vim script とは異なる。
                                                        E1101
ファイルレベルの変数は、旧来のVim script のスクリプトローカル変数 "s:" と非常
によく似ているが、"s:" は省略されている。そして、それらは削除することができな
い。
                                                        E1304
Vim9 script では、グローバル (g:)、バッファ (b:)、ウィンドウ (w:)、タブ
(t:) の名前空間を旧来の Vim script と同じように使用できる。Vim9 script では、
名前空間がプリフィックスとして付いた変数は:
- 宣言されない
- 特定の型を持たない、そして
- 削除できる。
名前空間がプリフィックスとして付いた変数を宣言すると、E1016 が発生する。ま
た、型を指定すると E1304 が発生する:

        vim9cmd var b:fails: bool       # E1016: Cannot declare a buffer va...
        vim9cmd b:fails: bool = false   # E1304: Cannot use type with this ...

:vim9script の副作用として、'cpoptions' オプションが Vim のデフォルト値に設
定されることが挙げられる:

        :set cpo&vim

効果の1つは、line-continuation が常に有効であることである。'cpoptions' の元
の値はスクリプトの最後に復元され、スクリプトで追加または削除されたフラグも元の
値に追加または削除されて同じ効果を得ることができる。フラグの順序は変更されるこ
とがある。起動時に読み込まれる vimrc ファイルでは、このようなことは起こらな
い。

                                                        vim9-mix
1 つのスクリプトファイルで、旧来と Vim9 の両方の構文を使用する方法がある:

        " _legacy Vim script_ comments are placed here
        if !has('vim9script')
          " _legacy Vim script_ comments and commands are placed here
          finish
        endif
        vim9script
        # _Vim9 script_ commands/commands from here onwards
        echowindow $"has('vim9script') == {has('vim9script')}"

これにより、可能であれば Vim9 script 構文を活用するスクリプトを作成できるよう
になり、Vim9 script のないバージョンの Vim で vim9script コマンドを使用した
場合にエラーが発生するのを防ぐことができる。

Note Vim9 の構文は Vim 9 より前に変更されたため、現在の構文 ("import" ではなく
"import from" など) を使用するスクリプトはエラーが発生する可能性がある。
これを防ぐには、代わりに v:version >= 900 というチェックを行う方が安全である
("has('vim9script')" はパッチ 3965 を適用した Vim 8.2 では v:true を返すた
め)。
場合によっては、さらに後で切り捨てるのが賢明なこともある。Vim9 script の機能
セットは増え続けているため、例えば tuple が使用される場合 (Vim 9.1 パッチ 1232
で導入)、より適切な条件は以下のとおりである:

        if !has('patch-9.1.1232')
          echowindow $"Fail: Vim does not have patch 9.1.1232"
          finish
        endif
        vim9script
        echowindow $"Pass: version {v:versionlong}.  Continuing ..."

どちらの vim-mix 条件が使用されても、以下の 2 つの方法のいずれかでのみ機能す
る:
  1. "if" ステートメントが false と評価されると、endif までのコマンドはス
     キップされ、vim9script が実際に実行される最初のコマンドになる。
  2. "if" ステートメントは true と評価され、endif までのコマンドが実行され、
     finish は vim9script に到達する前に終了する。


Export
                                                        :export
項目の export は次のように記述できる:
        export var myvar ...
        export const MYCONST ...
        export final myvar ...
        export def MyDef() ...
        export function MyFunc() ...
        export class MyClass ...
        export abstract class MyAbstractClass ...
        export interface MyInterface ...
        export enum MyEnum ...
        export type MyType ...
                                                        E1043
このことからわかるように、変数、定数、関数、クラス (抽象クラスを含む)、インター
フェイス、列挙型、型を export できる。それ以外のものを export しようとすると
E1043 が発生する:

        vim9cmd export echo 0  # E1043: Invalid command after :export

                                                        E1042
:export は Vim9 script のスコープでのみ使用できる。そのため、例えば
:function を export することは問題ないが、そのような関数内で項目を export し
ようとすると E1042 が発生する:

        vim9script
        export function F1042()
          export var b: bool
        endfunction
        F1042() # E1042: Export can only be used in vim9script

                                                        E1044
無効な引数で E1044 が発生することがある:

        vim9script
        export def /a1044(): void
        enddef  # E1044: Export with invalid argument: ...


Import
                                                        :import
export された項目は、別のスクリプトで import することができる。import 構文に
は、2つの形式がある。より単純な形式は:
        import {filename}

ここで {filename} は文字列として評価される式でなければならない。この形式では、
ファイル名は ".vim" で終わる必要があり、".vim" より前の部分が名前空間のスクリ
プトローカル名となる。例:
        import "myscript.vim"

これにより、"myscript.vim" に export された各項目は、"myscript.item" 等として
利用可能になる。

                                                        E1094
import はスクリプトローカルのスコープでのみ許可されている。それ以外の場所、例
えば :function や :def のスコープから import しようとすると E1094 が発生す
る:

        vim9script
        def F1094(): void
          import 'nah.vim'  # E1094: Import can only be used in a script
        enddef
        F1094()

                                                        E1053 E1071
{filename} が見つからないか、無効な場合はエラーが発生する:

        vim9cmd import 'e1053.vim'  # E1053: Could not import "e1053.vim"
        vim9cmd import false  # E1071: Invalid string for :import: false

                                                        :import-as
ファイル名が長い場合、曖昧な場合 (別のディレクトリにある同じファイル名など)、
または単に名前に別の構造を使いたい場合は、この形式を使用できる:
        import {longfilename} as {name}

この長い形式では、{name} が import された名前空間の特定のスクリプトローカル名
となる。したがって、{name} は internal-variables のように、文字、数字または
'_' で構成されなければならず、数字で始めることはできない。{longfilename} 式は、
存在するファイル名に評価されなければならない。

以下のスクリプトは :import-as の使用例である。これは:
- import する一時的な Vim9 script ファイルの {longfilename} として、定数 "TMP"
  を作成する
- 2 行の Vim9 script を TMP に書き込む
- その Vim9 script ファイルを {name} "that" として ("as") import する、そして
- import した Vim9 script ファイルの {longfilename} と、別の行に "that.myvar"
  の内容 ("myvar" は import したスクリプトで export された変数) を示す結果を表
  示する。

        vim9script
        const TMP: string = tempname()
        ['vim9script', 'export var myvar: string = "YES!"']->writefile(TMP)
        import TMP as that
        echo $"Exported var 'myvar' in 'that' ({TMP}):\n" .. that.myvar

この例は、"that.myvar" などを使用できることを示している。"that" という名前、ま
たは import したスクリプトを指していると認識されるようなものを自由に選んでよ
い。コマンド名、コマンド修飾子、組み込み関数名は避けるのが最善である。{name}
がそれらのいずれも隠してしまうからである。また、名前は小文字で始める方がよい。
そうすれば、グローバルなユーザーコマンドや関数を隠してしまう可能性を避けられる
からである。{name} は、関数名や変数名など、スクリプト内の他の何かに使用するこ
とはできず (E1213 を参照)、他の何かを代入することもできない (E1258 を参
照)。

名前の "." が望ましくない場合は、関数のローカル参照を作成できる:
        var LongDef = that.LongDefName

これは定数に対しても機能する:
        const MAXLEN = that.MAXIMUM_LENGTH_OF_NAME

これは変数には使えない。なぜなら、値は一度コピーされ、変数を変更するときは元の
変数ではなく、コピーが変更されるからである。完全な名前 (つまり '.' を含む) を
使用する必要がある。

import された項目はスクリプトレベルに存在し、一度だけ import されることを意図
している。また、:import は :function や :def の中では使用できない -
E1094 を参照。

:import の後のスクリプト名は次のようになる:
- "." または ".." で始まる相対パス。スクリプトファイル自体の位置から相対的に
  ファイルを検索する。大きなプラグインを複数のファイルに分割して使用する場合に
  便利である。
- 絶対パス。Unixでは "/"、MS-Windowsでは "D:/" で始まる。これはほとんど使用さ
  れない。
- 相対パスでも絶対パスでもないパス。これは、'runtimepath' エントリの "import"
  サブディレクトリで見つかる。間違ったファイルを読み込まないようにするため、通
  常、名前は長く、一意であるべきである。
  Note "after/import" は使われない。

Vim9 script ファイルを一度 import すると、その結果はキャッシュされ、再度読み込
まれることはない。

import 時には、多くの構文エラーやその他のエラーが発生する可能性がある。例:

                                                        E1047
- 無効な "as" {name} を使用する:

        vim9script
        import $'{$VIMRUNTIME}/autoload/ccomplete.vim' as i-cc
        # E1047: Syntax error in import: i-cc

                                                        E1048
- import したスクリプト内の存在しない項目を使おうとする:

        vim9script
        import $'{$VIMRUNTIME}/autoload/ccomplete.vim' as i_cc
        echo i_cc.absent_item  # E1048: Item not found in script: absent_item

                                                        E1049
- import したスクリプト内の、宣言されているが export されていない項目を使おう
  とする:

        vim9script
        import $'{$VIMRUNTIME}/autoload/ccomplete.vim' as i_cc
        echo i_cc.prepended  # E1049: Item not exported in script: prepended

                                                        E1060
import した名前を使用する場合、'.' と項目名は連続していなければならない。その
ため、空白も改行も入れることはできない:
- '.' の後 (E1074 を参照)、または
- '.' の前。例:

        vim9script
        import $'{$VIMRUNTIME}/autoload/ccomplete.vim' as i_cc
        echo i_cc .GetPath()    # E1060: Expected dot after name: i_cc .Get...

                                                        E1088
- import したスクリプトに自分自身を import させようとする:

        vim9script
        const TMP: string = $'{tempname()}.vim'->substitute('\\', '/', 'g')
        var lines: list<string> = ['vim9script', $'import "{TMP}" as e1088']
        lines->writefile(TMP)
        import TMP  # E1088: Script cannot import itself

                                                        E1236
- スクリプトそのものを使おうとする:

        vim9script
        import $'{$VIMRUNTIME}/autoload/ccomplete.vim' as cc
        cc()  # E1236: Cannot use cc itself, it is imported

                                                        E1257
- import するファイル名が ".vim" で終わらないときに "as {name}" を使用しない:

        vim9script
        const TMP: string = tempname()
        ['vim9script']->writefile(TMP)
        import TMP  # E1257: Imported script must use "as" or end in .vim: ...

                                                        E1258
- import した名前の後の '.' を省略する:

        vim9script
        import $'{$VIMRUNTIME}/autoload/ccomplete.vim' as i_cc
        def F1258(): void
          i_cc =
        enddef
        defcompile  # E1258: No '.' after imported name: i_cc =

                                                        E1259
- import した名前の後の名前を省略する:

        vim9script
        import $'{$VIMRUNTIME}/autoload/ccomplete.vim' as i_cc
        def F1259(): void
          i_cc.8 = 0
        enddef
        defcompile  # E1259: Missing name after imported name: i_cc.8 = 0

                                                        E1260
- import した項目を :unlet しようとする:

        vim9script
        const TMP: string = tempname()
        ['vim9script', 'export var b: bool']->writefile(TMP)
        import TMP as e_unlet
        unlet e_unlet.b  # E1260: Cannot unlet an imported item: b

                                                        E1261
- "as" を使用せずにファイル名 ".vim" を import しようとする。このスクリプトは、
  オペレーティングシステムの該当する一時ディレクトリに一時ファイル '.vim' を書
  き込み、それを import しようとする:

        vim9script
        const TMPDIR: string = tempname()
          ->substitute('\\', '/', 'g')          # Windows の \ 文字を確実に
                                                # / にする
          ->substitute('/[^/]\+$', '/', '')     # ファイル名を取り除く
        ['vim9script']->writefile($'{TMPDIR}.vim')
        echo $"Temporary import file name is: {TMPDIR}.vim"
        import $'{TMPDIR}.vim'  # E1261: Cannot import .vim without using "as"

                                                        E1262
- 同じスクリプトを複数回 import しようとする (異なる "as" 名を使用する場合も含
  む):

        vim9script
        import $'{$VIMRUNTIME}/autoload/ccomplete.vim' as i_cc1
        import $'{$VIMRUNTIME}/autoload/ccomplete.vim' as i_cc2
        # E1262: Cannot import the same script twice: .../ccomplete.vim

                                                        import-map
あるスクリプトから Vim9 script に関数を import した場合、import した関数の前に
<SID> を付けることで、マッピングで参照することができる:
        noremap <silent> ,a :call <SID>name.Function()<CR>

マッピングが定義されると、"<SID>name." は <SNR> とimport されたスクリプトのス
クリプトIDに置き換えられる。

さらに簡単な方法として、<ScriptCmd> を使用することができる:
        noremap ,a <ScriptCmd>name.Function()<CR>

Note これは変数には効かず、関数にしか効かないということである。
この自己完結した例は、<ScriptCmd> を使用し、一時的なスクリプトを作成して書き込
み、それを import して関数 "exported.MyDef()" を <leader>a にマップする様子を
示している:

        vim9script
        const TMP: string = tempname()
        ['vim9script',
        'export def MyDef(): void',
        '  popup_notification("exported.MyDef() was called", {time: 4000})',
        'enddef']->writefile(TMP)
        import TMP as exported
        nnoremap <leader>a <ScriptCmd>exported.MyDef()<CR>
        # これで、<leader>a を押すと exported.MyDef() が呼ばれ、
        # ポップアップが生成される

                                        import-legacy legacy-import :imp
:import は、短縮形の :imp を含め、旧来の Vim script でも使用することができ
る。"s:" というプリフィックスがない場合でも、import された名前空間はスクリプト
ローカルとなる。例:
        import "myfile.vim"
        call s:myfile.MyFunc()

"as name" 形式を使用する場合、名前空間を単独で解決することはできない (E1060
も参照)。この例は、as を付けた :imp をうまく使い、その後エラーになることを
示している:

        let s:tmp = $'{tempname()}.vim'->substitute('\\', '/', 'g')
        call writefile(['vim9script',
                \ 'export function L()',
                \ '  return "Vim9 script exporting a :function"',
                \ 'endfunction'], s:tmp)
        imp s:tmp as iLegacy
        echo s:iLegacy.L()      |" 'Vim9 script exporting a :function'
                                 " を表示する
        echo s:iLegacy          |" E1060: Expected dot after name: s:iLegacy

これは、旧来のマッピングコンテキストにおける <SID> の使用にも影響する。
<SID> は関数に対してのみ有効なプリフィックスであり、名前空間に対しては有効で
はない、スクリプトローカルな名前空間内の関数をスコープするために使用することは
できない。関数の前に <SID> を付ける代わりに、<ScriptCmd> を使用する必要が
ある。例:

        noremap ,a <ScriptCmd>:call s:that.OtherFunc()<CR>

                                                        :import-cycle
import コマンドは、遭遇したときに実行される。スクリプト A がスクリプト B を
import し、B が (直接または間接的に) A を import した場合、これはスキップされ
る。この時点では、"import B" 以降の A 内の項目はまだ処理されておらず、定義され
ていない。したがって、循環的な import が存在しても、直接的にはエラーにならない
が、"import B" 以降の A 内の項目が定義されていないためにエラーになる可能性があ
る。これはオートロード import には適用されない。次項参照。


オートロードスクリプトを import する
                                        vim9-autoload import-autoload
起動速度を最適化するために、スクリプトの読み込みは実際に必要になるまで延期する
必要がある。オートロード機構を使用することを推奨する:
                                                        E1264
     1. プラグインでは、オートロードスクリプトから import された項目を参照する
        ユーザーコマンド、関数、マッピングを定義する。

        import autoload 'for/search.vim'
        command -nargs=1 SearchForStuff search.Stuff(<f-args>)

        これは、.../plugin/anyname.vim に入る。"anyname.vim" は自由に選ぶこと
        ができる。"SearchForStuff" コマンドが利用できるようになった。

        import の引数 "autoload" は、項目の1つが実際に使用されるまでスクリプ
        トがロードされないことを意味する。スクリプトは "import" ディレクトリ
        ではなく、'runtimepath' の "autoload" ディレクトリの下に見つかる。
        あるいは、相対名または絶対名のいずれかを使用することもできる。以下を参
        照。

     2. オートロードスクリプトに、コードの大部分を置く。

        vim9script
        export def Stuff(arg: string): void
          ...

        これは、.../autoload/for/search.vim に入る。

        "search.vim" スクリプトを "/autoload/for/" ディレクトリに置くと、
        export された項目に "for#search#" というプリフィックスが付くようにな
        る。プリフィックスは、旧来のオートロードスクリプトで手動で追加するのと
        同じように、ファイル名から取得される。したがって、export された関数は
        "for#search#Stuff" で見つけることができるが、通常は import autoload
        を使用し、プリフィックスを使用しない (この名前に遭遇した関数をコンパイ
        ルするときにオートロードスクリプトをロードするという副作用が発生する)。

        機能を分割して、オートロードスクリプトから他のスクリプトを好きなように
        import することができる。こうすることで、プラグイン間でコードを共有す
        ることができる。

'runtimepath' のすべてのエントリからオートロードスクリプトを検索するのは、少し
時間がかかることがある。プラグインがスクリプトの場所を知っている場合、多くの場
合、相対パスが使用される。これにより、検索が回避され、かなり速くなるはずであ
る。また、スクリプト名が一意である必要がないことも利点である。絶対パスも可能で
ある。例:
        import autoload '../lib/implement.vim'
        import autoload MyScriptsDir .. '/lib/implement.vim'

import したオートロードスクリプトを使用するマッピングを定義するには、特殊キー
<ScriptCmd> が便利である。これは、マッピングのコマンドで、マッピングが定義さ
れた場所のスクリプトコンテキストを使用することを可能にする。

:def 関数をコンパイルしているときに、オートロードスクリプトの関数に遭遇する
と、:def 関数が呼び出されるまでスクリプトはロードされない。これは、引数や戻
り値の型がまだ分かっていないため、実行時にのみエラーが発生することも意味する。
もし、'#' 文字を含む名前を使用するのであれば、そのオートロードスクリプトはロー
ドされる。

オートロードスクリプトの中で、意図せずロードのきっかけとなる項目を参照しないよ
うに注意すること。例えば、関数名を取るオプションを設定する場合、関数参照ではな
く、必ず文字列を使用すること:
        import autoload 'qftf.vim'
        &quickfixtextfunc = 'qftf.Func'  # オートロードスクリプトはロードされ
                                         # ない
        &quickfixtextfunc = qftf.Func    # オートロードスクリプトはロードされる
一方で、スクリプトを早めに読み込むことで、エラーが発生した場合に、その旨を伝え
ることができるようになり便利である。

test_override() のテスト用関数を使用して、import autoload にスクリプトをす
ぐにロードさせることができる。これにより、項目と型が実際に使用されるのを待たず
にチェックできるようになる:
        test_override('autoload', 1)
後でリセットする:
        test_override('autoload', 0)
または:
        test_override('ALL', 0)

旧来の Vim script では、関数であるメンバーを追加することで、辞書を一種のオブ

(vim9-class-type、vim9-enum-type、およびその他の場所)。

8. 理論的根拠                                           vim9-rationale

:def コマンド

プラグインの作者から、Vim script をもっと速くしたいとの要望があった。関数呼び
出しの既存のセマンティクスを維持することは、関数の呼び出し、ローカル関数スコー
プの設定、行の実行に伴うオーバーヘッドのため、不可能に近いことが調査により判明
した。エラーメッセージや例外など、処理しなければならない細部はたくさんある。a:
および l: スコープ用の辞書を作成する必要性、a:000 のリスト、その他いくつかの回
避できないオーバーヘッドを追加しすぎている。

したがって、新しいスタイルの関数を定義するための :def メソッドを追加する必要
があり、これにより異なるセマンティクスを持つ関数を定義することができるように
なった。ほとんどのことは以前と同じように動作するが、そうでない部分もある。関数
を定義する新しい方法は、旧来のスタイルのコードとVim9スタイルのコードを分離する
ための最良の方法であると考えられていた。

"def" を使用して関数を定義するのは、Python に由来する。他の言語は、従来の Vim
script と競合する "function" を使用する。


型チェック

Vim コマンドの行を命令にコンパイルする場合、可能な限りコンパイル時に行うべきで
ある。これを実行時に先送りすると、実行速度が遅くなり間違いに気づくのが遅くな
る。例えば、"+" 文字に遭遇し、これを一般的な加算命令にコンパイルする場合、実行
時に引数の型を検査し、どのような加算を行うかを決定する必要がある。そして、その
型が辞書であった場合には、エラーを出す。もし、型が数値であることが分かっていれ
ば、「数値の加算」命令を使うことができ、その方が高速である。エラーはコンパイル
時に発生し、2 つの数値の加算が失敗することはほとんどないため、実行時にエラー処
理は必要ない。

Note: 余談だが、例外として整数オーバーフローがある。これは、結果が整数の最大値
を超える場合である。例えば、64 ビット符号付き整数に加算した結果が 2^63 を超え
る場合を考える:

        vim9script
        echo 9223372036854775807 + 1     # -9223372036854775808
        echo 2->pow(63)->float2nr() + 1  # -9223372036854775808

複合型に <type> を使った型の構文は、Javaと似ている。理解しやすく、広く使われて
いる。型名は、以前 Vim で使われていたものに、"void" や "bool" などが追加されて
いる。


乱雑と奇妙さを取り除く

:def 関数が旧来の関数と異なる構文であることが決まれば、一般的なプログラミン
グ言語を知っているユーザーにとってより馴染みやすいコードにするための改良を加え
ることは自由である。言い換えれば、Vim でしかしないような奇妙なことは削除する。

また、Vim script に古き良きViコマンドと後方互換性を持たせるために行われたもの
を中心に、雑多なものを取り除くことができる。


例:
- 関数を呼び出すための :call と式を評価するための :eval を削除する。
- 行の継続のための先頭のバックスラッシュを使用しない。式がどこで終わるかを自動
  的に把握する。

しかし、そのためには、いくつかのことを変える必要がある:
- コメントは、文字列と混同しないように、" の代わりに # で始まるようにした。こ
  れはとにかく良いことで、いくつかの人気のある言語でも使用されている。
- Ex コマンドの範囲は、式との混同を避けるため、先頭にコロンを付ける必要がある
  (シングルクォートは文字列またはマーク、"/" は割り算または検索コマンド、等)。


目標は、違いを制限することである。良い基準は、古い構文を誤って使用した場合に、
エラーメッセージが表示される可能性が非常に高いことである。


人気のある言語から構文とセマンティクスを学ぶ

スクリプトの作成者は、Vim script の構文が慣れ親しんでいるものとは予想外に異な
ると不満を漏らしている。この不満を軽減するために、人気のある言語を例として使用
する。同時に、旧来の Vim script のよく知られた部分を放棄することは避けたい。

いろいろなことで TypeScript が踏襲されている。これは最近人気が出てきた言語で、
Vim script に似ている。また、静的型付け (変数は常に既知の値型を持つ) と動的型
付け (変数は異なる型を持つことができ、これは実行時に変更される) が混在してい
る。旧来の Vim script は動的型付けされており、既存の多くの機能 (特に組み込み関
数) は動的型付けに依存しているが、静的型付けはより高速に実行できるため、Vim9
script でもこの混ぜ合わせが必要である。

TypeScript の構文やセマンティクスに完全に合わせるつもりはない。私たちはただ、
Vim に使える部分、Vim ユーザーが喜ぶと予想される部分を取り出したいだけである。
TypeScript は、独自の歴史、利点と欠点を持つ複雑な言語である。デメリットを知る
には、この本を読むこと: "JavaScript: The Good Parts"。または、
"TypeScript: the good parts" という記事を見つけて、"Things to avoid" セクショ
ンを読むこと。

他の言語 (Java、Pythonなど) に慣れている人も、TypeScript の中で気に入らないこ
とや理解できないことを見つけるだろう。そういったものを避けるようにする。

TypeScript から避ける特定の項目:
- "+" をオーバーロードして、加算と文字列連結の両方に使用する。これは旧来の Vim
  script に反しており、しばしば間違いにつながる。そのため、文字列の連結には
  ".." を使い続けることにする。Lua もこの方法で ".." を使っている。そして、よ
  り多くの値のために文字列に変換することができる。
- TypeScript では、'99 || "yes"' のような式を条件として使うことができるが、そ
  の値を真偽値に代入することができない。これは一貫性がなく、迷惑なことである。
  Vim は && や || を使った式を認識し、その結果を bool として使うことができる。
  デフォルト値を使う仕組みとして、falsy-operator が追加された - vim9-falsy
  を参照。
- TypeScript では、空の文字列を Falsy と見なすが、空のリストや辞書を Truthy と
  見なしている。これは矛盾している。Vimでは、空のリストや辞書も Falsy となる。
- TypeScript にはさまざまな "読み出し専用" 型があるが、型キャストによって不変
  な性質を取り除くことができるため、有用性は限定的である。Vim は値をロックする
  ので、より柔軟性があるが、実行時にしかチェックされない。
- TypeScript には複雑な "import" 文があり、Vim の import の仕組みとマッチしな
  い。代わりに、import されたスクリプトが一度だけ読み込まれることにマッチする、
  よりシンプルなメカニズムが使用されている。


宣言

旧来の Vim script では、すべての代入に :let を使用するが、Vim9 では宣言が使
用される。これは異なるので、別のコマンドを使うのがよいだろう。var である。こ
れは多くの言語で使用されている。セマンティクスは若干異なるかもしれないが、宣言
として簡単に認識することができる。

定数に :const を使うのは一般的だが、そのセマンティクスは様々である。変数だけ
を不変にする言語もあれば、値も不変にする言語もある。Java では "final" が変数だ
けを不変にするためによく知られているので、これを使うことにした。そして、
:const を使うことで、両方を不変にすることができる。これは旧来の Vim script
でも使われていたもので、意味はほぼ同じである。

最終的に得られるものは、Dart と非常によく似ている:
        :var name       # 可変な変数と値
        :final name     # 不変な変数、可変な値
        :const name     # 不変な変数と値

旧来と Vim9 script が混在し、グローバル変数が共有されるため、オプションで型
チェックを行うことが望ましい。また、型推論により、多くの場合、型を指定する必要
がなくなる。宣言に型を追加するには、TypeScript の構文が最も適している:

        vim9script
        var name: string                # 文字列型が指定される
        name = 'John'
        const GREETING = 'Hello'        # 文字列型が推測される
        echo $'{GREETING} {name}'

これは、型を宣言に入れる方法である:

        vim9script
        var vlist: list<number>
        final flist: list<string> = ['Vim']
        def Func(arg1: string, arg2: number): string
            return $'{arg1}{arg2}'
        enddef
        vlist[0] = 9
        echo Func(flist[0], vlist[0])   # Vim9

これらの選択肢を検討した:

  1. Dart のように名前の前に型を置く:

        var list<string> mylist
        final list<string> mylist = ['foo']
        def Func(number arg1, string arg2) bool

  2. 変数名の後に型を入れるが、Go のようにコロンを使わない:

        var mylist list<string>
        final mylist list<string> = ['foo']
        def Func(arg1 number, arg2 string) bool

C や Java に慣れている人には1つ目の方が馴染みやすいと思う。2つ目は1つ目に対し
ての優位性があまりないので、2つ目は捨ててしまおう。

型推論を使うので、値から推論できる場合は型は省くことができる。つまり、var の
後に型が続くのか名前が続くのかが分からないのである。そのため、Vim だけでなく人
間にとっても構文解析が難しくなる。また、型名になりうる変数名を使うことは許され
ないだろう。var string string を使うのはあまりにも紛らわしい。

コロンを使用して名前と型を区切る選ばれた構文は、句読点を追加するが、実際には、
宣言の部分を認識しやすくする。


式

式の評価は、すでに他の言語が行っているものに近いものだった。いくつかの細部は予
期せぬものであり、改善することができる。例えば、真偽値条件では、文字列を受け取
り、それを数値に変換して、その数値が0でないかどうかをチェックする。これは予想
外のことで、しばしば間違いにつながる。なぜなら、数字で始まらないテキストはゼロ
に変換され、これは偽とみなされるからである。このように、条件に文字列を使うと、
エラーが出ず、偽とみなされることが多いのである。これは紛らわしい。

Vim9 では、間違いを避けるために型チェックがより厳しくなっている。例えば :if
コマンドや || 演算子など、条件が使われる場所では、真偽値のような値しか受け付
けない:
        true:  true, v:true, 1, 0 < 9
        false: false, v:false, 0, 0 > 9
Note 数字の 0 は偽で、数字の 1 は真である。これは、他の多くの言語よりも寛容で
ある。これは、多くの組み込み関数がこれらの値を返すため、それを変更すると、解決
するよりも多くの問題を引き起こすからである。これをしばらく使ってみると、うまく
いくことが分かった。

任意の型を持つ値について、それを真偽値として使いたい場合は、!! 演算子を使う
(vim9-!! も参照):

        vim9script
        # 以下はすべて true:
        echo [!!'text', !![1], !!{'x': 1}, !!1, !!1.1]
        # そしてこれらはすべて false:
        echo [!!'', !![], !!{}, !!0, !!0.0]

        true: !!'text'   !![99]   !!{'x': 1}   !!99
        false: !!''   !![]   !!{}

JavaScript のような言語には、このような便利な構文がある:
        GetName() || 'unknown'
ただし、これは、条件に真偽値のみを許可することと競合する。したがって、"??" 演
算子が追加された:
        GetName() ?? 'unknown'
ここでは、値をそのまま使用し、真偽値にしないという意図を明示的に表すことができ
る。これは falsy-operator と呼ばれる - vim9-falsy を参照。


Import と Export

旧来の Vim script の問題点は、デフォルトですべての関数と変数がグローバルである
ことである。スクリプトローカルにすることは可能だが、そうすると他のスクリプトで
利用できなくなる。これは、選択された項目のみをエクスポートし、残りをローカルに
保つパッケージの概念に反している。

Vim9 script では、JavaScript の import および export 機構に非常によく似た機構
がサポートされている。これは既存の :source コマンドの亜種で、期待通りに動作
する:
- デフォルトですべてをグローバルにするのではなく、すべてをスクリプトローカルに
  することで、その一部をエクスポートすることができる。
- スクリプトの import 時には、import されるシンボルが明示的にリストされるため、
  名前の衝突や、後から機能を追加した場合の失敗を回避することができる。
- この機構により、export された関数、変数、クラスという非常に明確なAPIを持つ巨
  大で長いスクリプトを書くことができる。
- 相対パスを使用することで、パッケージ内のインポートのロードが非常に速くなり、
  多くのディレクトリを検索する必要がない。
- 一度インポートを使用すると、その項目はキャッシュされ、再ロードする必要はな
  い。
- スクリプトローカルにするための Vim 特有の "s:" の使用をやめることができる。

(Vim9 script または旧来の Vim script から) Vim9 script を読み込む場合、グロー
バルに定義された項目のみが使用可能で、export された項目は使用できない。代替案
を検討した:
- export された項目は、すべてスクリプトローカル項目として利用できるようにする。
  これにより、どの項目が定義されるかは制御できず、すぐにトラブルに発展する可能
  性がある。
- export された項目を使用し、それらをグローバルにする。デメリットは、グローバ
  ルな名前空間での名前の衝突を避けることができなくなることである。
- Vim9 script を読み込むことを完全に禁止し、:import を使うことを要求する。こ
  れにより、スクリプトをテストに使用したり、コマンドラインからスクリプトを取得
  して試したりすることが難しくなる。
Note 上記の通り、旧来の Vim script でも :import を使用することができる。


関数を早期にコンパイルする

関数は、呼び出されたとき、または :defcompile が使用されたときにコンパイルさ
れる。なぜ、早期にコンパイルして、構文エラーや型エラーが早期に報告されるように
しないのだろうか？

なぜなら、後に定義される関数への前方参照が存在する可能性があるからである。例え
ば、A、B、C という関数を定義し、A が B を呼び出し、B が C を呼び出し、C がまた
A を呼び出すとする。前方参照を避けるために関数を並べ替えることは不可能である。

別の方法としては、まずファイルをスキャンして項目を見つけ、そのタイプを把握し、
前方参照が見つかるようにしてから、スクリプトを実行し、関数をコンパイルする方法
がある。この場合、スクリプトを2回解析する必要があり、遅い。また、機能がサポー
トされているかどうかのチェックなど、スクリプトレベルでの条件もあるため、使いに
くい。うまくいくかどうか試行錯誤したが、うまく動作させることは不可能であること
が判明した。

スクリプトの最後にすべての関数をコンパイルすることは可能だろう。しかし、ある関
数が一度も呼び出されない場合、その関数をコンパイルするためのオーバーヘッドが、
いずれにせよカウントされてしまうという欠点がある。起動速度は非常に重要なので、
ほとんどの場合、コンパイルは後回しにした方がよく、構文や型のエラーはその時にし
か報告されないことを受け入れることができる。例えばテスト時など、これらのエラー
を早期に発見する必要がある場合は、スクリプトの最後の :defcompile コマンドが
効果的である。


なぜ既存の組み込み言語を使わないのか?

Vim は Perl、Python、Lua、Tcl、その他いくつかへのインターフェイスをサポートし
ている。しかし、これらのインターフェイスは様々な理由で広く使われるようになるこ
とはなかった。Vim9 が設計されたとき、これらのインターフェイスの優先順位を下げ、
Vim script に集中させることが決定された。

それでも、プラグイン作成者は他の馴染みのある言語を探したり、既存のライブラリを
使用したり、性能の恩恵を確認したりするかもしれない。我々は、プラグインの作者が
任意の言語でコードを書き、ジョブやチャネルを使って外部プロセスとして実行するこ
とを推奨する。我々は、これをどうにかして簡単にできるように努力することができ
る。

外部ツールの使用にもデメリットがある。代替案として、ツールを Vim Script に変換
する方法がある。これを実現するには、余分な翻訳作業を避けつつコードの高速性を維
持する必要があり、ツールの構造をサポートする必要がある。Vim9 Script ではクラ
ス、オブジェクト、インターフェイス、列挙型がサポートされているため、これはます
ます実現可能になっている。
