端末情報                                                terminal-info

Vim は、画面を埋め、押されたキーを認識するために、使用している端末についての情
報を使用する。この情報が正しくない場合、画面が乱れるか、またはキーが認識されな
いことがある。画面上で実行されなければならない動作は、文字列を出力することに
よって行われる。特殊キーは文字列を生成する。これらの文字列は端末オプションに格
納される。terminal-options を参照。

NOTE: これのほとんどは GUI の実行時には使用されない。

1. 起動                         startup-terminal
2. 端末オプション               terminal-options
3. ウィンドウサイズ             window-size
4. 低速と高速の端末             slow-fast-terminal
5. マウスの使用                 mouse-using

==============================================================================
1. 起動                                                 startup-terminal

Vim が起動される時、デフォルトの端末タイプが仮定される。Amiga では標準の CLI
ウィンドウ、MS-Windows では pc 端末、Unix では ansi 端末である。他のいくつかの
端末タイプは常に使用可能である。以下の builtin-terms を参照。

'-T' Vim 引数で端末名を与えることができる。それが与えられない場合、Vim は TERM
環境変数から名前を取得しようとする。

                                termcap terminfo E557 E558 E559
Unix では terminfo データベースまたは termcap ファイルが使用される。これは全て
のドキュメントで "termcap" と呼ばれる。コンパイル時、configure を実行する時に、
terminfo または termcap のどちらを使用するかの選択は自動的に行われる。Vim を実
行している時、terminfo が使用されている場合は ":version" の出力に +terminfo
が表示される。xterm-screens も参照。

Unix 以外のシステムでは、Vim が TERMCAP を定義してコンパイルされた場合にのみ
termcap が使用可能である。

                                        builtin-terms builtin_terms
多数の組み込み端末が使用可能である。パッチ 9.0.0280 以降、Vim のバージョンの間
で違いはない。使用可能な組み込み端末の一覧は、:set term=xxx に対して得られる
エラーメッセージで見ることができる (GUI を実行していない時)。++builtin_terms
も参照。

termcap のコードが含まれている場合、Vim は使用している端末の文字列を termcap
ファイルおよび組み込み termcap から取得しようとする。使用している端末のエント
リが存在する場合、両方とも常に使用される。どちらが最初に使用されるかは
'ttybuiltin' オプションに依存する:

'ttybuiltin' オン       1: 組み込み termcap     2: 外部 termcap
'ttybuiltin' オフ       1: 外部 termcap         2: 組み込み termcap

オプションがそれらの一方に無い場合、もう一方から取得される。オプションが両方に
存在する場合、最初に見つかったものが使用される。

どの外部 termcap ファイルが使用されるかはシステムによって異なり、環境変数
"TERMCAP" および "TERMPATH" に依存することがある。"man tgetent" を参照。

端末に依存する設定                              term-dependent-settings

端末名に応じてオプションまたはマッピングを設定したい場合、.vimrc で行うのが最
良である。例:

   if &term == "xterm"
     ... xterm のマッピングおよび設定 ...
   elseif &term =~ "vt10."
     ... vt100、vt102 のマッピングおよび設定 ...
   endif

                                                raw-terminal-mode
通常の編集では、端末は "raw" モードにされる。't_ti'、't_TI' および 't_ks' で定
義された文字列が端末に送られる。通常、これにより端末は termcap のコードが有効
な状態になり、カーソルキーおよびファンクションキーが有効になる。
Vim が終了する時、端末は Vim が起動する前のモードに戻される。't_te'、't_TE' お
よび 't_ke' で定義された文字列が端末に送られる。Amiga では、外部コマンドを実行
するコマンド (例えば "!!") で、端末は一時的にノーマルモードにされる。これは、
印字可能なキーを押すことで画面への出力を止められることを意味する。<BS> を押す
と出力が再開する。

Note: 't_ti' が空でない場合、Vim はそれが代替スクリーンへの切り替えを引き起こ
すと仮定する。これにより、シェルコマンドを実行する時または Vim を終了する時に
起きることが少し変わることがある。これを避けるには 't_TI' および 't_TE' を使用
する (ただし、上書きではなく、それらに追加するようにすること)。

Vim は 't_RK' termcap エントリで、端末がどのキーボードプロトコルを使用している
かを検出しようとする。これは 't_TI' の後に送られるが、行うべき作業が無い時 (先
行入力が無く、保留中のコマンドが無い時) だけである。これは、応答がシェルコマン
ドに入ってしまうこと、または Vim の終了後に到着することを避けるためである。

                                                xterm-bracketed-paste
't_BE' オプションが設定されている場合、"raw" モードに入る時に 't_BE' が、"raw"
モードを離れる時に 't_BD' が端末に送られる。その場合、端末は貼り付けられたテキ
ストの前に 't_PS' を、後に 't_PE' を置くことが期待される。こうして Vim は貼り
付けられたテキストと入力された文字を区別できる。貼り付けられたテキストはマウス
の中ボタンが使用された時のように扱われ、文字どおりに挿入され、コマンドとして解
釈されない。

注意: bracketed paste は貼り付けによる厄介な副作用 (CTRL-C キーまたは <ESC>
キーのような) を防ごうとしているが、端末によってこのモードの実装が少し異なるこ
とがあるため、保証されたセキュリティ対策ではない。それでも、Vim に何を貼り付け
るかには注意するべきである。

カーソルが最初の桁にある場合、貼り付けられたテキストはその前に挿入される。そう
でない場合、貼り付けられたテキストはカーソル位置の後に追加される。これは、最初
の桁の後に貼り付けることはできないことを意味する。残念ながら Vim にはマウスポ
インタがどこにあったかを知る方法が無い。

Note いくつかの状況では Vim は bracketed paste を認識せず、生のテキストが得ら
れることに注意。他の状況では、Vim は最初に貼り付けられた文字だけを受け取り、残
りを捨てる。例えば "r" コマンドを使用する時である。これで問題がある場合、
.vimrc に以下を書いて bracketed paste を無効にする:
        set t_BE=
Vim の実行中にこれが行われた場合、bracketed paste を無効にするために 't_BD' が
端末に送られる。

t_PS または t_PE が設定されていない場合、t_BE は使用されない。これは、貼
り付けられたテキストを囲むエスケープコードを認識できない時に bracketed paste
が有効にならないようにするためである。

Note: 'esckeys' オプションが設定されていない場合 ('compatible' オプションが設
定されている場合も)、bracketed paste モードは無効になる。

端末が bracketed paste をサポートしているが、オプションが自動的に設定されない
場合、このようなものを使用してみることができる:

        if &term =~ "screen"
          let &t_BE = "\e[?2004h"
          let &t_BD = "\e[?2004l"
          exec "set t_PS=\e[200~"
          exec "set t_PE=\e[201~"
        endif

terminfo エントリ "BE"、"BD"、"PS" および "PE" は、ncurses バージョン 6.4、
2023年初頭に、いくつかの端末に対して追加された。このバージョンを使用している場
合、端末を手動で設定する必要はないかもしれない。

                                                        tmux-integration
Vim を tmux 内で実行する時に問題が起きる場合、ここにいくつかのヒントがある。何
かが動作しない場合は部分的にコメントアウトしてよい (tmux が実行されている端末
に依存するかもしれない):

    if !has('gui_running') && &term =~ '^\%(screen\|tmux\)'
        " より良いマウスサポート、:help 'ttymouse' を参照
        set ttymouse=sgr

        " トゥルーカラーを有効化、:help xterm-true-color を参照
        let &termguicolors = v:true
        let &t_8f = "\<Esc>[38;2;%lu;%lu;%lum"
        let &t_8b = "\<Esc>[48;2;%lu;%lu;%lum"

        " bracketed paste モードを有効化、:help xterm-bracketed-paste を参照
        let &t_BE = "\<Esc>[?2004h"
        let &t_BD = "\<Esc>[?2004l"
        let &t_PS = "\<Esc>[200~"
        let &t_PE = "\<Esc>[201~"

        " フォーカスイベント追跡を有効化、:help xterm-focus-event を参照
        let &t_fe = "\<Esc>[?1004h"
        let &t_fd = "\<Esc>[?1004l"
        execute "set <FocusGained>=\<Esc>[I"
        execute "set <FocusLost>=\<Esc>[O"

        " 修飾子付きの矢印キーを有効化、:help arrow_modifiers を参照
        execute "silent! set <xUp>=\<Esc>[@;*A"
        execute "silent! set <xDown>=\<Esc>[@;*B"
        execute "silent! set <xRight>=\<Esc>[@;*C"
        execute "silent! set <xLeft>=\<Esc>[@;*D"
    endif

                                                        cs7-problem
Note: Vim を実行した後に端末設定が変更された場合、不正な設定の組み合わせになる
ことがある。これは Solaris 2.5 で "stty cs8 parenb" について報告されており、そ
れは "stty cs7 parenb" として復元される。代わりに "stty cs8 -parenb -istrip"
を使用すること。これは正しく復元される。

いくつかの termcap エントリは、't_ks' を送った後にカーソルキーが termcap で定
義されたコードとは異なるコードを送るという意味で間違っている。これを避けるには
't_ks' (および 't_ke') を空文字列に設定する。これは初期化中に行わなければなら
ない (initialization を参照)。そうしないと手遅れになる。

いくつかの termcap エントリは最上位ビットが常にリセットされていると仮定してい
る。例えば: Amiga のカーソル上のエントリは ":ku=\E[A:" かもしれない。しかし
Amiga は実際には "\233A" を送る。これは、例えばシリアル回線越しに Amiga を使用
する時のように、最上位ビットがリセットされる場合はうまく動作する。カーソルキー
が動作しない場合、エントリ ":ku=\233A:" を試すこと。

いくつかの termcap エントリは ":ku=\E[A:" というエントリを持っている。しかし
Amiga は実際には "\233A" を送る。出力では "\E[" と "\233" はしばしば等価だが、
入力ではそうではない。これを修正するには、termcap エントリを変更するか、または
:set コマンドでキーコードを変更しなければならない。

多くのカーソルキーのコードは <Esc> で始まる。Vim は、これが <Esc> キーの単独の
押下なのか、カーソルキーシーケンスの開始なのかを判別しなければならない。Vim は
次の文字が到着するのを待つ。1 秒以内に到着しない場合、単独の <Esc> と仮定され
る。非常に遅いシステムではこれが失敗し、カーソルキーが時々動作しない原因となる
ことがある。この問題を発見した場合、'timeout' オプションをオフにすること。Vim
は <Esc> の後に次の文字が到着するのを待つようになる。単独の <Esc> を入力したい
場合は 2 回入力しなければならない。'esckeys' オプションをオフにすると挿入モー
ドでのこの問題は回避されるが、挿入モードでカーソルキーおよびファンクションキー
を使用できなくなる。

Amiga では、端末名が "amiga" または "builtin_amiga" の場合にのみ、ウィンドウの
リサイズの認識が有効になる。

いくつかの端末はカーソルキーに紛らわしいコードを持つ。televideo 925 はそのよう
な端末である。それはカーソル左に CTRL-H を送る。これではバックスペースとカーソ
ル左を区別できなくなる。この問題を避けるため、CTRL-H がカーソル左として認識さ
れることは決してない。

                                        vt100-cursor-keys xterm-cursor-keys
他の端末 (例えば vt100 および xterm) は <Esc>OA、<Esc>OB などを送るカーソルキー
を持っている。残念ながら、これらは挿入モードで有効なコマンドである: 挿入を停止
し、新しい行の上に新しい行を開き、'A'、'B' などの挿入を開始する。これらのコマ
ンドを実行する代わりに、Vim はこの入力されたキーシーケンスを誤ってカーソルキー
の移動として認識する。これを避け、どちらの場合でも Vim にあなたが望むことをさ
せるには、以下の設定を使用できる:
        :set notimeout          " マッピングではタイムアウトしない
        :set ttimeout           " 端末のキーコードではタイムアウトする
        :set timeoutlen=100     " 100 ミリ秒後にタイムアウトする
これにより、キーコードをカーソルキーとして認識するには、それらが 100 ミリ秒以
内に送られる必要がある。入力する時は通常それほど速くないので、Vim が同じバイト
シーケンスを受け取っても、それらは個別に入力されたコマンドとして認識される。

                                vt100-function-keys xterm-function-keys
xterm はファンクションキー F1 から F4 を 2 つのモードで送ることができる: vt100
互換か、またはそうでないか。Vim は xterm が何を送っているか分からないかもしれ
ないので、両方の種類のキーが認識される。<Home> キーおよび <End> キーについても
同様である。
                        通常                    vt100
        <F1>    t_k1    <Esc>[11~       <xF1>   <Esc>OP     <xF1>-xterm
        <F2>    t_k2    <Esc>[12~       <xF2>   <Esc>OQ     <xF2>-xterm
        <F3>    t_k3    <Esc>[13~       <xF3>   <Esc>OR     <xF3>-xterm
        <F4>    t_k4    <Esc>[14~       <xF4>   <Esc>OS     <xF4>-xterm
        <Home>  t_kh    <Esc>[7~        <xHome> <Esc>OH     <xHome>-xterm
        <End>   t_@7    <Esc>[4~        <xEnd>  <Esc>OF     <xEnd>-xterm

Vim が起動する時、<xF1> は <F1> に、<xF2> は <F2> に、などとマップされる。これ
は、デフォルトでは両方のコードが同じことを行うことを意味する。端末に 2 つのキー
があるために <xF2> のマッピングを作成すると、デフォルトのマッピングは上書きさ
れるので、<F2> キーおよび <xF2> キーを別々のことに使用できる。

                                                        xterm-shifted-keys
新しいバージョンの xterm は、シフト付きのファンクションキーおよび特殊キーをサ
ポートしている。Vim はそれらのほとんどを認識する。どれがサポートされていて、
コードが何であるかを確認するには ":set termcap" を使用する。ほとんどの場合、こ
れらは termcap には無く、builtin_xterm termcap でのみサポートされる。

                                                        xterm-modifier-keys
新しいバージョンの xterm は、ほとんどのファンクションキーで Alt および Ctrl を
サポートしている。全てのキーについて Alt、Ctrl および Shift の全ての組み合わせ
を追加しなくて済むように、termcap エントリの末尾で特殊なシーケンスが認識される:
";*X"。"X" には任意の文字を使用でき、'~' がよく使われる。";*" は省略可能な修飾
子引数を表す。";2" は Shift、";3" は Alt、";5" は Ctrl、";9" は Meta (Alt と異
なる場合) である。これらは組み合わせることができる。例:
        :set <F8>=^[[19;*~
        :set <Home>=^[[1;*H
これらのコードに関するもう 1 つの特別な点は、他のコードによって上書きされない
ことである。これは、xterm から直接得られたコード t_RV がそれらを上書きするの
を避けるためである。

もう 1 つの特殊な値は、"@;*X" で終わる termcap エントリである。これはカーソル
キー用で、"CSI X" または "CSI 1 ; modifier X" のどちらかを使用する。したがって
"@" は、修飾子が続く場合は "1" を表すか、または何も表さない。
                                                        arrow_modifiers
いくつかの端末エミュレーター (alacritty、gnome、konsole など) は修飾子付きの
キーに対して特殊なコードを送るが、それらは termcap/terminfo データベースにエン
トリが無い。vimrc に数行追加することで、それらを動作させることができる。例え
ば、gnome 端末で Control 修飾子を矢印キーで動作させるには:
        if &term =~ 'gnome'
           execute "set <xUp>=\<Esc>[@;*A"
           execute "set <xDown>=\<Esc>[@;*B"
           execute "set <xRight>=\<Esc>[@;*C"
           execute "set <xLeft>=\<Esc>[@;*D"
        endif
                                                        xterm-scroll-region
Sun および他のプラットフォームの xterm のデフォルトの termcap エントリには、ス
クロール領域のエントリが含まれていない。/etc/termcap の xterm エントリに
":cs=\E[%i%d;%dr:" を追加すれば、全てうまく動作するはずである。

                                                        xterm-end-home-keys
いくつかのシステム (少なくとも XFree86 3.1.2 の FreeBSD) では、<End> キーおよ
び <Home> キーが送るコードに <Nul> 文字が含まれる。これらのキーが適切なキーコー
ドを送るようにするには、~/.Xdefaults ファイルに以下の行を追加する:

        *VT100.Translations:            #override \n\
                        <Key>Home: string("0x1b") string("[7~") \n\
                        <Key>End: string("0x1b") string("[8~")

                                                xterm-8bit xterm-8-bit
Xterm は 8 ビットのエスケープシーケンスを使用するモードで実行できる。<Esc>[ の
代わりに CSI コードが使用される。利点は、特殊キーの開始と混同されることが無い
ので、挿入モードで <Esc> を素早く認識できることである。
組み込み termcap エントリについて、Vim は 'term' オプションのどこかに "8bit"
が含まれているかを確認する。その場合、termcap エントリ、マウスおよびいくつかの
他のものに 8 ビット文字を使用する。通常はシェルで $TERM を "xterm-8bit" に設定
し、Vim はこれを拾って自動的に 8 ビットの設定に調整する。
Vim が t_RV (バージョン要求) シーケンスへの応答を受け取り、それが CSI で始ま
る場合、端末は 8 ビットモードであると仮定し、全てのキーシーケンスを 8 ビットの
変種に変換する。

                                                xterm-terminfo-entries
しばらくの間、terminfo エントリは Vim が使用できる全ての機能を記述するには不十
分だった。組み込みの xterm termcap エントリにはこれらがあり、その結果、xterm
に十分似ているいくつかの端末は、$TERM の端末名の前に "xterm-" を付けることでこ
れらを利用した。

これは問題につながる。なぜなら、これらの端末はかなり頻繁に xterm と 100% 互換
ではないからである。2023年の初めに、"xterm" の回避策を使用せずにこれらの機能を
使用できるようにするため、いくつかのエントリが terminfo データベースに追加され
た。以下が関連するエントリである (今のところ):

        名前    xterm の値      説明
        RV      "\033[>c"       バージョンを要求する t_RV

        BE      "\033[?2004h"   bracketed paste モードを有効にする t_BE
        BD      "\033[?2004l"   bracketed paste モードを無効にする t_BD
        PS      "\033[200~"     貼り付けられたテキストの開始 t_PS
        PE      "\033[201~"     貼り付けられたテキストの終了 t_PE

        XM      "\033[?1006;1004;1000%?%p1%{1}%=%th%el%;"
                                マウスの有効化 / 無効化 t_XM
        FE      "\033[?1004h"   フォーカスイベント追跡を有効にする t_fe
        FD      "\033[?1004l"   フォーカスイベント追跡を無効にする t_fd

"XM" エントリには、SGR スタイルのマウス報告を有効にするための "1006" が含まれ
る。これは 223 より大きい桁をサポートする。また、フォーカス報告を有効にする
"1004" も含まれる。
Note: 2023年の時点で、"1004" は現在 Vim 自身では使用されておらず、代わりに、最
新バージョンの ncurses も使い始めているように、t_fe および t_fd エントリに
よってマウス追跡とは独立してフォーカス報告を設定することが推奨される (そして、
それはやがて terminfo/termcap にも入ることになる)。

                                                xterm-kitty kitty-terminal
Kitty 端末は特殊なケースである。主な理由は、他のほとんどの端末とは異なる動作を
するためだが、デフォルトで他の端末と同じように振る舞うように合わせようとする代
わりに、Kitty を使用する時にアプリケーションがどのように動作する必要があるかを
指示するためでもある。このため Vim が Kitty 端末で動作するのは非常に困難であ
る。いくつかの例外はハードコードされているが、ある特定の端末のために例外を作ら
なければならないのは全く好ましくない。

問題の 1 つは、$TERM の値が "xterm-kitty" に設定されることである。Vim にとっ
て、これは端末が xterm 互換であり、組み込みの xterm termcap エントリを使用する
べきであることを示す。他の多くの端末がこれに依存している。しかし、Kitty は完全
には xterm 互換ではない。作者は "xterm-" プリフィックスを無視して、とにかく
terminfo エントリを使用することを提案したので、現在はそのようになっており、組
み込みの xterm termcap エントリは使用されない。しかし、t_RV は設定される。そう
しないと、'ttymouse' を自動的に "sgr" に設定することなど (少なくとも t_XM が
このために使用されるようになるまでは)、他のことが動作しないからである。

kitty がなぜ $TERM を "xterm-kitty" に設定するのかは明らかではない。その端末は
実際には xterm 互換ではない。"kitty" の方が適切だろうが、その名前の terminfo
エントリは普及していない。

Note kitty キーボードプロトコルの使用は別の機能であることに注意。
kitty-keyboard-protocol を参照。

2. 端末オプション               terminal-options termcap-options E436

端末オプションは通常のオプションと同じように設定できる。しかし、それらは
":set all" コマンドでは表示されない。代わりに ":set termcap" を使用する。

適切なオプションを設定することで、個々の文字列をいつでも変更できる。例:

ソル移動、't_cm'。

空でない任意の文字列はフラグが設定されていることを意味する。空文字列はフラグが
設定されていないことを意味する。't_CS' もこのように動作するが、termcap のフラ

                                                        xterm-codes
現在 xterm でのみ動作する、キーコードを取得するための特別な仕掛けがある。
t_RV が定義されていて、パッチレベル 141 以上の xterm であることを示す応答を
受け取った場合、Vim は xterm から直接キーコードを要求するために特別なエスケー
プシーケンスを使用する。応答は様々な t_ コードを調整するために使用される。これ
により、xterm がそのモード (8 ビット、VT102、VT220 など) に応じて異なるコード
を生成することがあるという問題が回避される。その結果、<xF1> のようなコードはも
はや必要ない。

変更されうるコードの 1 つは、色の数である 't_Co' である。これは再描画を引き起
こす。これが問題になる場合、できるだけ早く 'xtermcodes' オプションをオフにする:

        set noxtermcodes

Note: キーコードの要求は起動時にのみ行われる。Vim の起動後に xterm のオプショ
ンが変更された場合、エスケープシーケンスはもはや認識されないかもしれない。

                                                        xterm-true-color
Vim は、端末がこれをサポートしていることを前提として、端末でトゥルーカラー
(highlight-guifg および highlight-guibg から取られる) を使用することをサ
ポートしている。これを動作させるには 'termguicolors' オプションを設定する必要
がある。
トゥルーカラーをサポートする端末の一覧については
https://github.com/termstandard/colors を参照。

"xterm-direct" のようなダイレクトカラー端末のエントリは 16777216 色を持つ。そ
の場合、't_Co' は 16777216 となり、terminalprops() は "rgb" を 'y' と報告す
る。Vim は 'termguicolors' を自分では設定しない。そのような端末でそれを設定さ
せるには、vimrc に以下を書く:
        if get(terminalprops(), 'rgb', 'n')  == 'y'
          set termguicolors
        endif


端末にどの RGB 色を使用するかを伝えるために、t_8f、t_8b および t_8u
termcap エントリが使用される。これらはデフォルトで、ほとんどの端末で動作する値
に設定されている。それが端末で動作しない場合、それらを手動で設定できる。デフォ
ルト値はこのように設定されている:
         let &t_8f = "\<Esc>[38;2;%lu;%lu;%lum"
         let &t_8b = "\<Esc>[48;2;%lu;%lu;%lum"
         let &t_8u = "\<Esc>[58:2::%lu:%lu:%lum"

いくつかの端末は t_8f および t_8b について、セミコロンがコロンに置き換えら
れ、数字 2 の後に余分なコロンがある、似たシーケンスを受け付ける (これは ISO
8613-6 標準に準拠しているが、あまり広くサポートされていない):
         let &t_8f = "\<Esc>[38:2::%lu:%lu:%lum"
         let &t_8b = "\<Esc>[48:2::%lu:%lu:%lum"

下線および波線の色 (t_8u および t_AU) にはコロン形式が使用される。下線の色
をサポートする端末はそれを受け付けるはずである。いくつかはそれを必要とさえす
る。xterm のような、下線の色をサポートしていない端末では、下線はテキストの色を
保ち、他の属性はそのままである。

これらのオプションには printf 文字列が含まれ、printf() (実際には、それと同等
の C の関数、そのため l 修飾子) が、t_ オプションの値と、それぞれ赤、緑およ
び青の色を表す、0 と 255 の間 (両端を含む) の任意の値を取りうる 3 つの
unsigned long 整数で呼び出される。

                                                        xterm-resize
xterm でのウィンドウのリサイズは、allowWindowOps リソースが有効な場合にのみ動
作する。いくつかのシステムおよびバージョンの xterm では、誰かがセキュリティ上
の問題になると考えたため、デフォルトで無効になっている。実際にそうなのかは明ら
かではない。

デフォルトを覆すには、~/.Xdefaults または ~/.Xresources に以下の行を書く:

        XTerm*allowWindowOps:           true

そして "xrdb -merge .Xresources" を実行して有効にする。コンテキストメニュー
(CTRL キーを押しながらマウスの右ボタン) で値を確認できる。allow-window-ops に
チェックが付いているはずである。

                                                        xterm-focus-event
xterm を含むいくつかの端末は、フォーカスイベント追跡機能をサポートしている。
この機能が 't_fe' シーケンスによって有効にされている場合、端末がフォーカスを得
るか、または失うたびに、特殊なキーシーケンスが端末から Vim に送られる。Vim は
それらを適切に処理することでフォーカスイベント (FocusGained/FocusLost) を
発生させる。フォーカスイベント追跡は、"raw" モードを抜ける時に 't_fd' シーケン
スによって無効にされる。この機能を無効にしたい場合は、.vimrc に以下を追加する:

        set t_fd=
        set t_fe=
端末がこれをサポートしているが Vim がその端末を認識しない場合、オプションを自
分で設定する必要があるかもしれない:
        let &t_fe = "\<Esc>[?1004h"
        let &t_fd = "\<Esc>[?1004l"
        execute "set <FocusGained>=\<Esc>[I"
        execute "set <FocusLost>=\<Esc>[O"
これにより Vim の起動時にゴミが表示される場合、それは動作していない。

                                                        termcap-colors
色についての注意: 't_Co' オプションは使用可能な色の数を Vim に伝える。これが 0
でない場合、色を設定するために 't_AB' および 't_AF' オプションが使用される。こ
れらの一方が使用可能でない場合、't_Sb' および 't_Sf' が使用される。デフォルト
の色にリセットするには 't_me' が使用される。'termguicolors' も参照。
GUI の実行中は 't_Co' は 16777216 に設定される。

                                termcap-cursor-shape termcap-cursor-color
Vim が挿入モードに入る時、't_SI' エスケープシーケンスが送られる。Vim が置換モー
ドに入る時、't_SR' エスケープシーケンスが設定されている場合はそれが送られ、そ
うでない場合は 't_SI' が送られる。挿入モードまたは置換モードを抜ける時は
't_EI' が使用される。Note: 't_EI' が設定されていない場合、't_SI' および 't_SR'
は送られない。そして 't_SI' または 't_SR' が設定されていない場合、't_EI' は 1
回だけ送られる。

これは挿入モードまたは置換モードでカーソルの形状または色を変更するために使用で
きる。これらは標準の termcap/terminfo エントリではないので、自分で設定する必要
がある。
xterm の例、これはカーソルの色を変更する:
    if &term =~ "xterm"
        let &t_SI = "\<Esc>]12;purple\x7"
        let &t_SR = "\<Esc>]12;red\x7"
        let &t_EI = "\<Esc>]12;blue\x7"
    endif
NOTE: Vim が終了する時、ノーマルモードの形状が残る。Vim が起動する前の形状は復
元されない。

Windows Terminal では、このようなものを使用できる:
    " Note: これは `set termguicolors` または `set t_Co=256` の後に
    " 設定するべきである。
    if &term =~ 'xterm' || &term == 'win32'
        " DECSCUSR エスケープシーケンスを使用する
        let &t_SI = "\e[5 q"    " 点滅するバー
        let &t_SR = "\e[3 q"    " 点滅する下線
        let &t_EI = "\e[1 q"    " 点滅するブロック
        let &t_ti ..= "\e[1 q"  " 点滅するブロック
        let &t_te ..= "\e[0 q"  " デフォルト (端末に依存する、通常は点滅
                                " ブロック)
    endif

{+cursorshape 機能なしでコンパイルされた場合は使用できない}

                                                        termcap-title
端末が文字列を送ることによるタイトル設定を許可している場合、ウィンドウタイトル
を設定するために 't_ts' および 't_fs' オプションが使用される。それらはそれぞれ
タイトル文字列の前および後に送られる。同様の 't_IS' および 't_IE' が、アイコン
テキストを設定するために使用される。これらは Unix termcap に対する Vim 内部の
拡張なので、外部の termcap から取得することはできない。しかし、組み込み
termcap には xterm および iris-ansi 用の適切なエントリが含まれているので、ここ
でそれらを設定する必要はない。
                                                        hpterm
反転または他のハイライトが正しく動作しない場合、't_xs' オプションを空でない文
字列に設定してみること。これにより、行からハイライトを取り除くために 't_ce'
コードが使用されるようになる。これは "hpterm" で必要である。'weirdinvert' オプ
ションを設定することは 't_xs' を空でなくすることと同じ効果を持ち、逆も同様であ
る。

                                                        scroll-region
端末が "cs" (スクロール領域) をサポートしているにもかかわらず、いくつかの
termcap にはそのエントリが含まれていない。例えば: Sun 上の xterm。
builtin_xterm を使用するか、または t_cs を自分で定義できる。例えば:
        :set t_cs=^V^[[%i%d;%dr
ここで ^V は CTRL-V、^[ は <Esc> である。

垂直スクロール領域 t_CV は標準の termcap コードではない。Vim は GUI の内部でそ
れを使用する。しかし、それをサポートする端末を見つけることができる場合、端末に
対しても定義できる。2 つの引数は、スクロールを制限する領域の左桁および右桁であ
る。t_cs が上の行および下の行を定義するのと同様である。t_CV を定義すると、垂直
分割されたウィンドウでのスクロールがかなり速くなる。t_da または t_db が設定さ
れている時は t_CV を設定しないこと (スクロールする時にテキストがクリアされな
い)。

残念ながら、スクロール領域を使用する時にカーソル位置指定をどのように行うべきか
を termcap から推測することはできない: 画面の先頭からの相対か、またはスクロー
ル領域の先頭からの相対か。ほとんどの端末は最初の方法を使用する。カーソル位置指
定がスクロール領域の開始からの相対である場合、't_CS' オプションには任意の文字
列を設定するべきである。そうでない場合は空文字列を設定するべきである。

xterm ユーザーへの注意: シフト付きカーソルキーは通常は動作しない。xmodmap コマ
ンドおよび Vim のいくつかのマッピングでそれらを動作させることができる。

        xterm で以下のコマンドを与える:
                xmodmap -e "keysym Up = Up F13"
                xmodmap -e "keysym Down = Down F16"
                xmodmap -e "keysym Left = Left F18"
                xmodmap -e "keysym Right = Right F19"

        そして Vim で以下のマッピングを使用する:
                :map <t_F3> <S-Up>
                :map! <t_F3> <S-Up>
                :map <t_F6> <S-Down>
                :map! <t_F6> <S-Down>
                :map <t_F8> <S-Left>
                :map! <t_F8> <S-Left>
                :map <t_F9> <S-Right>
                :map! <t_F9> <S-Right>

例えば <S-Up> の代わりに、シフトカーソル上キーに使用したい他の任意のコマンドを
使用できる。(Note: 左側にキーがある Sun キーボードを持つ人々を助けるため、F14
は undo キーと混同されるので使用されない。F15 はウィンドウを前面に出すので使用
されない。F17 はウィンドウを閉じるので使用されない。他のシステムではおそらくそ
れらを使用できる。)

3. ウィンドウサイズ                                     window-size

[これは Vim が使用しているウィンドウ全体のサイズについてであり、":split" コマ
ンドで作成されるウィンドウについてではない。]

Amiga で Vim を実行していて、端末名が "amiga" または "builtin_amiga" の場合、
Amiga 固有のウィンドウのリサイズが有効になる。Unix システムでは、ウィンドウサ
イズを取得するために 3 つの方法が試される:

- ioctl 呼び出し (TIOCGSIZE または TIOCGWINSZ、システムに依存する)
- 環境変数 "LINES" および "COLUMNS"
- termcap エントリ "li" および "co" から

全てが失敗した場合、24 行および 80 桁のデフォルトのサイズが仮定される。ウィン
ドウリサイズのシグナルを受け取った場合、サイズが再設定される。ウィンドウサイズ
が間違っている場合、'lines' および 'columns' オプションを使用して正しい値を設
定できる。

画面サイズを設定するために 1 つのコマンドを使用できる:
                                                :mod :mode E359
:mod[e] [mode]

引数が無い場合、これは画面サイズを検出して画面を再描画するだけである。[mode]
は MS-DOS で使用されていたが、もはや動作しない。Vim9 ではこのコマンドはサポー
トされていない。

4. 低速と高速の端末                             slow-fast-terminal
                                                slow-terminal

高速な端末を使用している場合、'ruler' オプションを設定したいかもしれない。カー
ソル位置がステータス行に表示される。水平スクロール ('wrap' オプションがオフ)
を使用している場合、'sidescroll' を小さな数値に設定することを検討すること。

低速な端末を使用している場合、'showcmd' オプションをオフにしたいかもしれない。
コマンド文字はステータス行に表示されなくなる。端末のスクロールが非常に遅い場
合、'scrolljump' を 5 程度に設定する。カーソルが画面外に移動された場合 (例えば
"j" で)、Vim は一度に 5 行スクロールする。もう 1 つの可能性は、コマンド
"z{height}<CR>" で Vim が使用する行数を減らすことである。

端末からの文字が 1 秒以上の間隔で到着している場合、'timeout' および/または
'ttimeout' オプションを設定したいかもしれない。"Options" の章 options を参
照。

端末がスクロール領域をサポートしていないが、行の挿入/削除コマンドはサポートし
ている場合、複数のウィンドウでのスクロールにより行が上下に跳ねることがある。こ
れは 'ttyfast' オプションがオフにされている場合に起こる。以下でそれを確認する:

        verbose set ttyfast?

端末のスクロールが非常に遅いが、再描画は遅くない場合、'ttyscroll' オプションを
小さな数値、例えば 3 に設定する。これにより、スクロールする行が 3 行より多い
時、Vim はスクロールする代わりに画面を再描画する。

低速なカラー端末を使用している場合、以下のコマンドを使用する:
        hi NonText cterm=NONE ctermfg=NONE
これにより、異なる属性を持つ時にスペースが送られるのが避けられる。ほとんどの端
末ではいずれにしてもこれは見えない。

低速なシリアル回線越しに Vim を使用している場合、"screen" プログラムの中で Vim
を実行してみたいかもしれない。Screen は端末 I/O をかなり最適化する。

termcap オプションをテストしているが、何が起きているのかが見えない場合、
'writedelay' オプションを設定したいかもしれない。0 でない場合、一度に 1 文字ず
つ端末に送られる。これにより画面の更新がかなり遅くなり、何が起きているのかを見
ることができるようになる。

5. マウスの使用                                         mouse-using

このセクションは、端末または端末ウィンドウでのマウスの使用についてである。GUI
ウィンドウでのマウスの使い方は gui-mouse で説明されている。マウスホイールで
のスクロールについては scroll-mouse-wheel を参照。

以下のコマンドでマウスを有効にすることを忘れないこと:
        :set mouse=a
そうしないと Vim は全てのモードでマウスを認識しない ('mouse' を参照)。

現在、マウスは、Unix の xterm ウィンドウ、sysmouse を使った *BSD コンソール、
Linux コンソール (GPM gpm-mouse を使用) および Windows コンソールでサポート
されている。
マウスクリックは、カーソルの位置指定、領域の選択および貼り付けに使用できる。

'mouse' オプションの以下の文字は、Vim がどの状況でマウスを使用するかを示す:
                n       ノーマルモード
                v       ビジュアルモード
                i       挿入モード
                c       コマンドラインモード
                h       ヘルプファイル内にいる時の、上記の全てのモード
                a       上記の全てのモード
                r       hit-enter プロンプト用

'mouse' のデフォルトは空で、マウスは使用されない。通常は以下を実行する:
        :set mouse=a
として、マウスの使用を開始する (これは 'mouse' を "nvich" に設定することと等価
である)。マウスをいくつかのモードでだけ使用したい場合、またはマウスを 2 つの質
問にも使用したい場合、それらのモードの文字を連結する必要がある。例えば:
        :set mouse=nv
これにより、マウスはノーマルモードおよびビジュアルモードで動作するようになる。

        :set mouse=h
これにより、マウスはヘルプファイルでのみ動作するようになる (そのため
"g<LeftMouse>" を使用してタグへジャンプできる)。

マウスで開始された選択がビジュアルモードまたは選択モードのどちらになるかは、
'selectmode' オプションに "mouse" が含まれているかどうかに依存する。
                                                        terminal-mouse
xterm では、現在アクティブなモードが 'mouse' オプションに含まれている場合、通
常のマウスクリックは Vim によって使用され、シフトキーまたはコントロールキーを
押しながらのマウスクリックは xterm に送られる。現在アクティブなモードが
'mouse' に含まれていない場合、全てのマウスクリックは xterm に送られる。

修飾キーを使用してマウスイベントを端末自身に使用させることができない端末では、
回避策として、コマンドラインモードでは Vim のためにマウスイベントを使用しない
ようにする:
        :set mouse=nvi
そして、端末でテキストを選択するには、":" を使用してコマンドラインモードに移
り、テキストを選択してシステムにコピーし、Esc を押す。

もう 1 つの方法は、一時的に ":sh" を使用してシェルを実行し、テキストをコピーし
てからシェルを終了することである。その場合、'mouse' は "a" に設定したままにで
きる。
                                                        xterm-clipboard
Motif GUI 版では、端末で実行していて X サーバーへのアクセスがある (DISPLAY が
設定されている) 場合、コピーおよび貼り付けは GUI と同じように動作する。そうで
ない場合、マウスの中ボタンは無名レジスタを挿入する。その場合、テキストの一部を
コピーして貼り付ける方法は以下のとおりである:

マウスおよびビジュアルモードでのコピー/貼り付け ('mouse' オプションが設定され
ている必要がある。上記を参照):
1. テキストの最初の文字の上でマウスの左ボタンを押し、マウスポインタをテキスト
   の最後の文字に移動して、ボタンを離す。これによりビジュアルモードが開始され、
   選択された領域がハイライトされる。
2. "y" を押して、ビジュアルテキストを無名レジスタにヤンクする。
3. 挿入位置でマウスの左ボタンをクリックする。
4. マウスの中ボタンをクリックする。

ショートカット: 挿入位置がビジュアルテキストと同時に画面上にある場合、2、3 お
よび 4 を一度に全て行うことができる: 挿入位置でマウスの中ボタンをクリックする。

Note: -X コマンドライン引数が使用された場合、Vim は X サーバーに接続せず、X
クリップボード (セレクション) へのコピー/貼り付けは動作しない。xterm に選択を
行わせるには、マウスボタンと一緒にシフトキーを使用する。

                                                        xterm-command-server
X サーバーのクリップボードが使用可能な場合、x11-clientserver で説明されてい
るコマンドサーバーを --servername コマンドライン引数で有効にできる。

                                                        xterm-copy-paste
NOTE: いくつかの (古い) xterm では、95 桁目または 223 桁目より先にカーソルを移
動できない。これは xterm の問題であり、Vim の問題ではない。より新しい xterm を
入手すること color-xterm。'ttymouse' も参照。

xterm でのコピー/貼り付け (現在のモードが 'mouse' に含まれていない場合):
1. テキストの最初の文字の上でマウスの左ボタンを押し、マウスポインタをテキスト
   の最後の文字に移動して、ボタンを離す。
2. 通常の Vim コマンドを使用して、カーソルを挿入位置に置く。
3. "a" を押して挿入モードを開始する。
4. マウスの中ボタンをクリックする。
5. ESC を押して挿入モードを終了する。
(マウスを使用する間シフトキーを押したままにする場合、'mouse' に何が含まれてい
ても同じことができる。)

Note: 貼り付け時に 8 番目のビットが失われる (特殊文字が他の文字に変換される)
場合、Vim を起動する前にシェルで "stty cs8 -istrip -parenb" を実行する必要があ
るかもしれない。

したがって、xterm ではシフトキーおよびコントロールキーをマウスと一緒に使用でき
ない。CTRL 修飾子を必要とするマウスコマンドは、マウスを使用する前に "g" キーを
入力することでシミュレートできる:
        "g<LeftMouse>"  は "<C-LeftMouse>       (マウスクリック位置のタグへジャンプ)
        "g<RightMouse>" は "<C-RightMouse>      ("CTRL-T")

(1) 押してからマウスポインタが移動した場合のみ

マウスの左ボタンをクリックすると、カーソルが位置付けられる。クリックが他のウィ
ンドウ内の場合、そのウィンドウがアクティブウィンドウになる。コマンドラインを編
集している時は、カーソルはコマンドライン上にしか位置付けられない。挿入モードの
時は、Vim は挿入モードのままである。'scrolloff' が設定されていて、カーソルが
ウィンドウの境界から 'scrolloff' 行以内に位置付けられた場合、テキストがスクロー
ルされる。

選択は、最初の文字の上でマウスの左ボタンを押し、マウスを最後の文字に移動してか
ら、マウスボタンを離すことで開始できる。ボタンを離すまで選択が見えるとは限ら
ず、いくつかのバージョン (GUI、Win32) でのみドラッグがすぐに表示される。Note
'scrolloff' が 0 でない時、ウィンドウの最初/最後の行でマウスを少なくとも 1 文
字移動することで、テキストをスクロールさせることができることに注意。

ノーマル、ビジュアルおよび選択モードでは、マウスの右ボタンをクリックするとビ
ジュアル領域が拡張される。'mousemodel' が "popup" の場合、シフトキーを押したま
ま左ボタンを使用しなければならない。他のバッファを編集しているウィンドウ内でク
リックすると、ビジュアルモードまたは選択モードは停止される。

ノーマル、ビジュアルおよび選択モードでは、オルトキーを押しながらマウスの右ボタ
ンをクリックすると、ビジュアル領域が矩形になる。'mousemodel' が "popup" の場
合、オルトキーと一緒に左ボタンを使用しなければならない。Note これは、オルトキー
が押されている時にウィンドウマネージャーがマウスイベントを消費するシステムでは
動作しないことに注意 (ウィンドウを移動することがある)。

                                                        double-click
ダブル、トリプルおよびクアドラプルクリックは、GUI がアクティブな時、Win32、お
よび xterm (gettimeofday() 関数が使用可能な場合) でサポートされている。テキス
トを選択する場合、追加のクリックで選択が拡張される:
        クリック        選択
        ダブル          単語または % の対応     <2-LeftMouse>
        トリプル        行                      <3-LeftMouse>
        クアドラプル    矩形ブロック            <4-LeftMouse>
例外: ヘルプウィンドウでは、ダブルクリックはクリックされた単語のヘルプへジャン
プする。
単語の上でダブルクリックすると、その単語が選択される。単語にどの文字が含まれる
かを指定するには 'iskeyword' が使用される。対応するものがある文字の上でダブル
クリックすると、その対応するものまで選択される ("v%" を使用するのと同様)。対応
するものが #if/#else/#endif ブロックの場合、選択は行単位になる。
MS-Windows および xterm では、ダブルクリックの時間は 'mousetime' オプションで
設定できる。他のシステムでは、この時間は Vim の外部で定義される。
カーソル下のタグへジャンプするためにダブルクリックを使用する例:
        :map <2-LeftMouse> :exe "tag " .. expand("<cword>")<CR>

ダブルクリックでマウスをドラッグすると (ボタンを押し、ボタンを離し、ボタンを押
してからドラッグ)、単語全体が選択される。これはボタンが離されるまで続き、その
時点で選択は再び文字単位になる。

マウスでのスクロールについては scroll-mouse-wheel を参照。

                                                        gpm-mouse
GPM マウスは、コンパイル時に +mouse_gpm 機能が有効にされた場合にのみサポート
される。GPM マウスドライバ (Linux コンソール) はクアドラプルクリックをサポート
していない。

挿入モードで選択が開始されると、Vim は一時的にノーマルモードに移る。ビジュアル
モードまたは選択モードが終了すると、挿入モードに戻る。これは挿入モードで
CTRL-O を使用するのと同様である。'selectmode' オプションに "mouse" が含まれて
いる場合、選択モードが使用される。
                                                        sysmouse
sysmouse は、コンパイル時に +mouse_sysmouse 機能が有効にされた場合にのみサ
ポートされる。sysmouse ドライバ (*BSD コンソール) はキーボード修飾子をサポート
していない。

                                                        drag-status-line
複数のウィンドウで作業している時、マウスでステータス行をドラッグすることでウィ
ンドウのサイズを変更できる。マウスでステータス行を指し、左ボタンを押し、マウス
をステータス行の新しい位置に移動し、ボタンを離す。ステータス行でマウスをクリッ
クするだけで、カーソルを移動せずにそのウィンドウがカレントウィンドウになる。
ウィンドウを選択することでそのウィンドウの位置またはサイズが変わる場合、ステー
タス行のドラッグは紛らわしく見えるが、動作する (とにかく試してみること)。

                                        <MiddleRelease> <MiddleDrag>
マウスクリックはマップできる。マウスクリックのコードは以下である:
     コード         マウスボタン              通常の動作
 <LeftMouse>     左を押した                 カーソル位置を設定
 <LeftDrag>      左を押したまま移動         選択を拡張
 <LeftRelease>   左を離した                 選択の終端を設定
 <MiddleMouse>   中を押した                 カーソル位置にテキストを貼り付け
 <MiddleDrag>    中を押したまま移動         -
 <MiddleRelease> 中を離した                 -
 <RightMouse>    右を押した                 選択を拡張
 <RightDrag>     右を押したまま移動         選択を拡張
 <RightRelease>  右を離した                 選択の終端を設定
 <X1Mouse>       X1 ボタンを押した          -                   X1Mouse
 <X1Drag>        X1 を押したまま移動        -                   X1Drag
 <X1Release>     X1 ボタンを離す            -                   X1Release
 <X2Mouse>       X2 ボタンを押した          -                   X2Mouse
 <X2Drag>        X2 を押したまま移動        -                   X2Drag
 <X2Release>     X2 ボタンを離す            -                   X2Release

X1 ボタンおよび X2 ボタンは、いくつかのマウスにある追加のボタンを指す。
'Microsoft Explorer' マウスでは、これらのボタンは右手の親指で使用可能である。
現在、X1 および X2 は、Win32 および X11 環境、および xterm のようなマウス機能
をサポートする端末でのみ動作する。

例:
        :noremap <MiddleMouse> <LeftMouse><MiddleMouse>
マウスの中ボタンをクリックした位置に貼り付ける (そうしないと、貼り付けはカーソ
ル位置で行われる)。

        :noremap <LeftRelease> <LeftRelease>y
ビジュアルモードを使用している時、選択をすぐにヤンクする。

Note 再帰的なマッピングを避けるために、"map" の代わりに ":noremap" を使用して
いることに注意。

        :map <X1Mouse> <C-O>
        :map <X2Mouse> <C-I>
X1 ボタンおよび X2 ボタンを、ジャンプリスト内で前方および後方へ移動するように
マップする。CTRL-O および CTRL-I を参照。

                                                mouse-swap-buttons
マウスの左ボタンと右ボタンの意味を入れ替えるには:
        :noremap        <LeftMouse>     <RightMouse>
        :noremap        <LeftDrag>      <RightDrag>
        :noremap        <LeftRelease>   <RightRelease>
        :noremap        <RightMouse>    <LeftMouse>
        :noremap        <RightDrag>     <LeftDrag>
        :noremap        <RightRelease>  <LeftRelease>
        :noremap        g<LeftMouse>    <C-RightMouse>
        :noremap        g<RightMouse>   <C-LeftMouse>
        :noremap!       <LeftMouse>     <RightMouse>
        :noremap!       <LeftDrag>      <RightDrag>
        :noremap!       <LeftRelease>   <RightRelease>
        :noremap!       <RightMouse>    <LeftMouse>
        :noremap!       <RightDrag>     <LeftDrag>
        :noremap!       <RightRelease>  <LeftRelease>
