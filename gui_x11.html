1. X11 GUI の起動                                       gui-x11-start E665

それから、これらのいずれかの方法で GUI 版の Vim を実行できる:
    gvim [options] [files...]
    vim -g [options] [files...]

そのため、実行可能ファイルを "gvim" と呼ぶか、または "gvim" を実行可能ファイル
へのリンクにすると、GUI 版が自動的に使われる。"gvim" の後に文字を追加してもよ
い。例えば "gvim-5"。

端末版の中から、これらのコマンドのいずれかを使って GUI を起動することもできる:
        :gui [++opt] [+cmd] [-f|-b] [files...]                  :gu :gui
        :gvim [++opt] [+cmd] [-f|-b] [files...]                 :gv :gvim
"-f" オプションは Vim をフォアグラウンドで実行する。
"-b" オプションは Vim をバックグラウンドで実行する (これが既定である)。
++opt および +cmd も参照。

                                                        gui-fork
GUI が起動されると、fork() を行い、現在のプロセスを終了する。
gvim がシェルから起動された場合、これによりシェルはさらなるコマンドを受け付け
るようになる。これを望まない場合 (例えば、gvim の終了を待つメールプログラムに
gvim を使う場合)、"gvim -f"、"vim -gf" で gvim を起動するか、または ":gui -f"
を使う。"-fg" は前景色を指定するので、"vim -fg" は使わないこと。

"vim -f" を使い、その後 ":gui" を使った場合、Vim はフォアグラウンドで実行され
る。"-f" 引数は記憶される。Vim を強制的にバックグラウンドで実行するには
":gui -b" を使う。

"gvim --nofork" は "gvim -f" と同じことをする。

プロセスがもはや子プロセスではなくなるため、実行中のジョブがある場合、Vim は
fork しない。
                                                                E851 E852
GUI の起動に失敗した場合、Vim は端末で実行を続けようとする。

GUI を常にフォアグラウンドで実行したい場合、'guioptions' に 'f' フラグを含め
る。-f。

2. GUI リソース                         gui-resources .Xdefaults

GUI の Motif 版を使っている場合 (KDE、GTK+ または Win32 版ではない)、いくつか
の X リソースが使用可能である。これらを設定する時は Vim のクラス "Vim" を使う
べきである。それらは次のとおりである:

    リソース名          意味    

    reverseVideo        ブール値: 反転表示を使うか?
    background          背景の色。
    foreground          通常テキストの色。
    scrollBackground    スクロールバーの溝の部分の色。
    scrollForeground    スクロールバーのスライダーおよび矢印の部分の色。
    menuBackground      メニュー背景の色。
    menuForeground      メニュー前景の色。
    tooltipForeground   ツールチップおよびバルーンの前景の色。
    tooltipBackground   ツールチップおよびバルーンの背景の色。

    font                通常テキストに使われるフォントの名前。
    boldFont            太字テキストに使われるフォントの名前。
    italicFont          斜体テキストに使われるフォントの名前。
    boldItalicFont      太字、斜体テキストに使われるフォントの名前。
    menuFont            メニューに使われるフォントの名前で、+xfontset 機能な
                        しでコンパイルされた時に使われる
    menuFontSet         メニューに使われるフォントセットの名前で、+xfontset
                        機能付きでコンパイルされた時に使われる
    tooltipFont         ツールチップおよびバルーンに使われるフォントの名前。
                        +xfontset 機能付きでコンパイルされた場合、これはフォ
                        ントセット名である。

    geometry            gvim のウィンドウに使う初期ジオメトリ (既定は起動元の
                        端末と同じサイズ)。
    scrollbarWidth      スクロールバーの太さ。
    borderWidth         テキスト領域の周りのボーダーの太さ。

斜体、太字、および斜体太字テキスト用の特別なフォントは、ユーザーがリソースでそ
れを指定した場合にのみ使われる。通常テキストのフォントを元に、これらにどのフォ
ントを使うべきかを推測することはしない。

Note 色は、"Normal"、"Menu"、"Tooltip"、および "Scrollbar" グループを使って、
":highlight" コマンドでも設定できることに注意。例:
        :highlight Menu guibg=lightblue
        :highlight Tooltip guibg=yellow
        :highlight Scrollbar guibg=lightblue guifg=blue
        :highlight Normal guibg=grey90

                                                        font-sizes
Note: 全てのフォント (メニューおよびツールチップを除く) は同じサイズでなければ
ならない!!! そうしないと、テキストが消えるか、または表示が乱れる。Vim はフォン
トサイズをチェックしない。同じでなければならないのは、スクリーン上のピクセル単
位のサイズである。Note 同じポイントサイズのフォントでも、同じピクセルサイズで
ないものがあることに注意! さらに、フォントの位置 (ascent および descent) も同
じでなければならない。これは "xlsfonts -l {fontname}" で確認できる。

これらのいずれかが Vim のコマンド、例えば
":set guifont=Screen15" でも設定された場合、それが X リソースを上書きする (現
在、サポートされているオプションは 'guifont' だけである)。

以下は ~/.Xdefaults ファイルに書くかもしれないものの例である:

        Vim*useSchemes:                 all
        Vim*sgiMode:                    true
        Vim*useEnhancedFSB:             true
        Vim.foreground:                 Black
        Vim.background:                 Wheat
        Vim*fontList:                   7x13

これらの最初の 3 つは Silicon Graphics マシンの標準リソースで、Motif アプリケー
ションの見た目をさらに良くする。強く推奨!

"Vim*fontList" は Motif のメニューフォントを設定するためのものである。例:
        Vim*menuBar*fontList:        -*-courier-medium-r-*-*-10-*-*-*-*-*-*-*

NOTE: Motif でメニューフォントを指定するための、より移植性が高く、そして実のと
ころより正しい方法は、このリソースを使うことである:
        Vim.menuFont:        -*-courier-medium-r-*-*-10-*-*-*-*-*-*-*
または、+xfontset 機能付きでコンパイルされた場合:
        Vim.menuFontSet:     -*-courier-medium-r-*-*-10-*-*-*-*-*-*-*

defaults で "Vim*geometry" を使わないこと。これはメニューを壊す。代わりに
"Vim.geometry" を使う。

"Cannot allocate colormap entry for "gray60" というエラーメッセージが出た場合、
Vim のリソースにこれを追加してみること (色は好みに合わせて変える):

        Vim*scrollBackground:           Black
        Vim*scrollForeground:           Blue

リソースは Vim への引数で設定することもできる:

    引数                意味
                                                        -gui
   -display {display}   {display} で vim を実行する     -display
   -iconic              vim をアイコン化して起動する    -iconic
   -background {color}  背景に {color} を使う           -background
   -bg {color}          同上                            -bg
   -foreground {color}  通常テキストに {color} を使う   -foreground
   -fg {color}          同上                            -fg
   -ul {color}          同上                            -ul
   -font {font}         通常テキストに {font} を使う    -font
   -fn {font}           同上                            -fn
   -boldfont {font}     太字テキストに {font} を使う    -boldfont
   -italicfont {font}   斜体テキストに {font} を使う    -italicfont
   -menufont {font}     メニュー項目に {font} を使う    -menufont
   -menufontset {fontset} メニュー項目に {fontset} を使う       -menufontset
   -mf {font}           同上                            -mf
   -geometry {geom}     初期ジオメトリに {geom} を使う  -geometry
   -geom {geom}         同上、-geometry-example を参照        -geom
   -borderwidth {width} {width} のボーダー幅を使う      -borderwidth
   -bw {width}          同上                            -bw
                                                        -scrollbarwidth
   -scrollbarwidth {width}      {width} のスクロールバー幅を使う
   -sw {width}          同上                            -sw
   -menuheight {height} {height} のメニューバーの高さを使う -menuheight
   -mh {height}         同上                            -mh
                        NOTE: Motif ではこの値は無視され、メニューの高さはメ
                        ニューに合うように計算される。
   -reverse             反転表示を使う                  -reverse
   -rv                  同上                            -rv
   +reverse             反転表示を使わない              -+reverse
   +rv                  同上                            -+rv
   -xrm {resource}      指定したリソースを設定する      -xrm

反転表示についての注意: Vim は、結果が実際に暗い背景に明るいテキストになってい
るかをチェックする。その理由は、色を入れ替える X11 のバージョンもあれば、入れ
替えないものもあるためである。これら 2 つの例は、どちらも青い背景に黄色いテキ
ストになる:
    gvim -fg Yellow -bg Blue -reverse
    gvim -bg Yellow -fg Blue -reverse

                                                        -geometry-example
geometry 引数の例:
        gvim -geometry 80x63+8+100
これは、画面の左から 8 ピクセルおよび上から 100 ピクセルの位置に、80 桁および
63 行のウィンドウを作成する。

3. シェルコマンド                                       gui-pty

警告: GUI から外部コマンドを実行することは、常に動作するとは限らない。"ls"、
"grep" および "make" のような "通常の" コマンドはほとんどうまく動作する。
"less" および "ispell" のような賢い端末を必要とするコマンドは動作しない。ハン
グして、別の端末から kill する必要があるものさえある。だから注意すること!

シェルコマンドとの I/O を行うには 2 つの方法がある: パイプおよび疑似 tty であ
る。既定では疑似 tty を使う。これはほとんどのシステムで最もうまく動作するはず
である。

残念ながら、疑似 tty の実装は Unix システムごとに異なる。そして、root 権限を必
要とするシステムもある。最も予期しない時に疑似 tty の問題に遭遇するのを避ける
ため、ファイルを編集していない時にテストすること。起動したコマンドまたは Vim
を "kill" する準備をしておくこと。":r !cat" のようなコマンドはハングするかもし
れない!

疑似 tty を使うのがうまく動作しない場合、'guipty' オプションをリセットする:

        :set noguipty

パイプを使うのはどの Unix システムでも動作するはずだが、欠点がある:
- パイプが使われていることに気付き、異なる動作をするシェルコマンドがある。例え
  ば、":!ls" はファイルを 1 列で一覧表示する。
- ":sh" コマンドは、一応動作はするが、プロンプトを表示しない。
- ":make" を使っている時、CTRL-C で中断することはできない。

外部コマンドの実行中の先行入力は、しばしば失われる。これはパイプおよび疑似 tty
の両方で起こる。これは既知の問題だが、修正できないようである (または少なくと
も、非常に難しい)。

                                                        gui-pty-erase
外部コマンドで消去文字が間違っている場合、"~/.cshrc" ファイル、またはシェルが
初期化に使うファイルで、これを修正するべきである。例えば、文字を削除するのに
バックスペースを使いたいが、バックスペースを押すと代わりに "^H" が出る場合、
"~/.cshrc" にこれを追加してみること:
        stty erase ^H
この ^H は本物の CTRL-H であり、CTRL-V CTRL-H として入力する。

4. その他                                               gui-x11-various

                                                        gui-x11-printing
"File/Print" メニューは単に現在のバッファを "lpr" に送るだけである。オプション
などは無い。他のことをしたい場合、独自の印刷コマンドを定義できる。例えば:

  :10amenu File.Print :w !lpr -Php3
  :10vmenu File.Print :w !lpr -Php3

                                                        X11-icon
Motif でコンパイルされた場合、Vim は既定で白黒のアイコンを使う。カラーの ViAI
アイコンが $VIMRUNTIME/viai32x32.xpm として含まれている。GTK+ では、これが使わ
れる組み込みのアイコンである。残念ながら、それをどのようにインストールするべき
かは、ウィンドウマネージャーによって異なる。これを使う場合、白黒のアイコンを除
去するために、'guioptions' から 'i' フラグを除去する:
  :set guioptions-=i

fvwm* ファミリーのウィンドウマネージャーのいずれかを使っている場合、単にこの行
を .fvwm2rc 設定ファイルに追加する:

  Style "vim"           Icon viai32x32.xpm

アイコンファイルの場所がウィンドウマネージャーの ImagePath 文と一致しているこ
とを確認すること。.fvwm2rc の中から ImagePath を変更するか、または定義済みの
ディレクトリの 1 つにアイコンを置く:

  ImagePath /usr/X11R6/include/X11/pixmaps:/usr/X11R6/include/X11/bitmaps

Note: 古いバージョンの fvwm は "ImagePath" の代わりに "IconPath" を使う。

CDE "dtwm" (Motif の派生) では、.Xdefaults にこの行を追加する:
   Dtwm*Vim*iconImage: /usr/local/share/viai/viai32x32.xpm

"mwm" (Motif ウィンドウマネージャー) では、その行は次のようになる:
   Mwm*Vim*iconImage: /usr/local/share/viai/viai32x32.xpm


X11 で使用可能なマウスポインター
                                                X11_mouse_shapes
'mouseshape' オプションを使うことで、Vim が様々なモード (例えば、挿入またはコ
マンド) のいずれかに入るたびに、マウスポインターを自動的に変更できる。現在、使
用可能なポインターは次のとおり:

        arrow                   北西を指す矢印
        beam                    I のような縦棒
        size                    上下を指す矢印
        busy                    腕時計
        blank                   見えないポインター
        crosshair               細い "+" 記号
        hand1                   北東を指す暗い色の手
        hand2                   北西を指す明るい色の手
        pencil                  南東を指す鉛筆
        question                question_arrow
        right_arrow             北東を指す矢印
        up_arrow                上を指す矢印

さらに、X11 に組み込まれているマウスポインターはどれも、X11/cursorfont.h イン
クルードファイルの整数を指定することで使える。

他のシステムには存在するが X11 には存在しない名前が使われた場合、既定の
"arrow" ポインターが使われる。

5. GTK 版                               gui-gtk GTK+ GTK GTK3 GTK4

GUI の GTK 版は少し異なる動作をする。

GTK は従来の X リソース設定を _使わない_。したがって、~/.Xdefaults または
app-defaults ファイルの項目は使われない。
従来の X のコマンドライン引数の多くはサポートされていない。(例えば、-bg、-fg
などのもの)。サポートされているものは次のとおり:

    コマンドライン引数  リソース名      意味
    -fn  または  -font          .font           テキストのフォント名
    -geom  または  -geometry    .geometry       gvim ウィンドウのサイズ
    -rv  または  -reverse       *reverseVideo   黒い背景に白いテキスト
    -display                                    使用するディスプレイ
    -fg -foreground {color}                     前景色
    -bg -background {color}                     背景色

GTK4 GUI を使っている場合、以下のものだけがサポートされる:
    -fn  または  -font
    -geom  または  -geometry    (ウィンドウの位置指定はサポートされない)
    -fg -foreground {color}
    -bg -background {color}

GTK4 固有のコマンドライン引数:
    コマンドライン引数    意味
    --prg-name {name}       g_set_prgname() に渡される引数。それ以外の場合は
                            "gviai" が使われる。Wayland では、これはアプリ id
                            を設定する。それは X11 の WM_CLASS と同等である

フォントを設定するには、'guifont' を参照。GTK では、これを行うメニューオプショ
ンもある。

さらに、GTK によって内部で処理される、これらのコマンドライン引数がある (GTK4
を除く。以下を参照)。それらがどのように使われるかは、GTK のドキュメントを見る
こと:
        --sync
        --gdk-debug
        --gdk-no-debug
        --no-xshm       (GTK+ 2 には無い)
        --xim-preedit   (GTK+ 2 には無い)
        --xim-status    (GTK+ 2 には無い)
        --gtk-debug
        --gtk-no-debug
        --g-fatal-warnings
        --gtk-module
        --display       (-display の GTK+ での対応物。同じように動作する。)
        --screen        (スクリーン番号。GTK+ 2.2 のマルチヘッドサポート用。)

+netbeans_intg 機能が使われている場合、これらの引数は無視される:
        -xrm
        -mf

GTK4 GUI を使っている場合、GTK 固有のコマンドライン引数はサポートされない。代
わりに環境変数で GTK を設定する:
https://docs.gtk.org/gtk4/running.html

色については、Vim の色設定 (構文ハイライト用) は今でも従来の Vim の方法で行わ
れる。さらなるヘルプは :highlight を参照。

残りの gui コンポーネント (例えば、メニューバー、スクロールバー、その他何でも)
の色を設定したい場合、それらは GTK 固有の設定であり、何らかの gtkrc ファイルで
設定する必要がある。その方法については、わずかしかないにしても、GTK のドキュメ
ントを参照しなければならない。
詳しくは
https://www.manpagez.com/html/gtk2/gtk2-2.24.24/gtk2-Resource-Files.php を参
照。
                                                        gtk3-slow
GTK3 GUI が遅い場合、これを試すこと:

    $ GDK_RENDERING=image gvim

小さいフォント、高解像度、多くの 'lines' (縦長の画面)、および UI スケーリング
は、全て遅い再描画の一因となる。

                                                        gtk4-slow
GTK4 GUI が遅いか、フリーズするか、または起動直後にキーボード入力を受け付けな
い場合、OpenGL レンダラーまたは GPU ドライバが原因の可能性がある。以下の環境変
数のいずれかを付けて gvim を起動してみること。$GSK_RENDERER を "cairo" に設定
すると、GSK OpenGL レンダラーが無効になる。$LIBGL_ALWAYS_SOFTWARE を "true" に
設定すると、OpenGL レンダラーは維持されるが、Mesa にソフトウェアレンダリングの
使用を強制する:

    $ GSK_RENDERER=cairo gvim
    $ LIBGL_ALWAYS_SOFTWARE=true gvim

ツールチップ色
                                                        gtk-tooltip-colors
ツールチップの色を、明るい黄色の上の黒に設定する例:

        style "tooltips"
        {
                bg[NORMAL] = "#ffffcc"
                fg[NORMAL] = "#000000"
        }

        widget "gtk-tooltips*"          style "tooltips"

これを ~/.gtkrc ファイルに書くと、GTK+ で使われる。GTK+ 2 では、ディストリ
ビューションによっては、代わりに ~/.gtkrc-2.0 ファイルを使う必要があるかもしれ
ない。

GTK+ 3 では、以下の CSS コードの断片を $XDG_HOME_DIR/gtk-3.0/gtk.css に追加す
ることで、上記と同様の効果が得られる (次の節を参照):

GTK+ 3 < 3.20 では:

        .tooltip {
                background-color: #ffffcc;
                color: #000000;
        }

GTK+ 3 >= 3.20 では:

        tooltip {
            background-color: #ffffcc;
            text-shadow: none;
        }

        tooltip label {
            color: #2e3436;
        }


GTK+ CSS をざっと見る
                                                        gtk-css
この小節の内容は、GTK+ CSS の安定したサポートを提供する GTK+ 3.20 以降に当ては
まる:

        https://developer.gnome.org/gtk3/stable/theming.html

GTK+ はウィジェットのスタイルおよびレイアウトに CSS を使う。この小節では、簡単
で説明的な例を通じて GTK+ CSS をざっと見ていく。

通常、これで設定を編集できる:
        vim $HOME/.config/gtk-3.0/gtk.css


例 1.  空きスペースの調整

既定では、GTK+ 3 GUI のツールバーおよびタブラインは、GTK+ 2 GUI のものよりもい
くらか大きい。それらを GTK+ 2 GUI と同じような大きさに見せたい人もいるだろう。

そうするために、アイコンおよびラベルの周りの、明らかに余分に見える空きスペース
を減らしてみる。

以下の行を $XDG_HOME_DIR/gtk-3.0/gtk.css (通常は $HOME/.config/gtk-3.0/gtk.css)
に追加する:

        toolbar button {
            margin-top: -2px;
            margin-right: 0px;
            margin-bottom: -2px;
            margin-left: 0px;

            padding-top: 0px;
            padding-right: 0px;
            padding-bottom: 0px;
            padding-left: 0px
        }

        notebook tab {
            margin-top: -1px;
            margin-right: 3px;
            margin-bottom: -1px;
            margin-left: 3px;

            padding-top: 0px;
            padding-right: 0px;
            padding-bottom: 0px;
            padding-left: 0px
        }

CSS なので、それらは省略記法を使って書き直せる:

        toolbar button {
            margin: -2px 0px;
            padding: 0px;
        }

        notebook tab {
            margin: -1px 3px;
            padding: 0px
        }

Note: アイコンサイズを調整するために 'toolbariconsize' も使いたいかもしれない。

Note: 使用しているアイコンテーマおよび/またはフォントによっては、満足のいく結
果を得るために、追加の微調整が必要になるかもしれない。

Note: margin および padding に加えて、border も使える。詳細は、CSS のボックス
モデルを参照。例えば、

        https://www.w3schools.com/css/css_boxmodel.asp

例 2.  単なる色以上のもの

GTK+ CSS はグラデーションもサポートしている:

        tooltip {
            background-image: -gtk-gradient(linear,
                                            0 0, 0 1,
                                            color-stop(0, #344752),
                                            color-stop(0.5, #546772),
                                            color-stop(1, #243742));
        }

        tooltip label {
            color: #f3f3f3;
        }

グラデーションを使うと、高いコントラストに頼らずに、GUI 要素を他の要素と視覚的
に区別できるようにできる。したがって、それを効果的に使うことは、テーマに色およ
び輝度の統一感を与える有用な手法である。

Note: テーマ作成は、全てのアプリケーションを等しく良く見せなければならないの
で、難しいことがある。1 つのアプリケーションをより魅力的にすると、しばしば他の
アプリケーションが予想外に魅力的でなくなるか、またはその使い勝手を悪化させるこ
とさえある。テーマを改善しようとする時は、常にこのことを心に留めておくこと。


例 3.  ボーダー色

最大化した時にボーダーを無くすには:

    @define-color bg_color #1B2B34;
    #vim-main-window {
        background-color: @bg_color;
    }


Vim を GTK+ プラグインとして使う
                                                        gui-gtk-socketid
Vim の GTK+ 版が普通に起動すると、自身のトップレベルウィンドウ (技術的には
'GtkWindow') を作成する。GTK+ は GtkSocket および GtkPlug ウィジェットによる埋
め込み機能を提供している。ある GTK+ アプリケーションがそのウィンドウの 1 つに
GtkSocket ウィジェットを作成すると、全く別の GTK+ アプリケーションが、そのソ
ケットの ID を使ってトップレベルの GtkPlug ウィジェットを作成することで、最初
のアプリケーションに自身を埋め込むことができる。

Vim にコマンドラインオプション '--socketid' を 10 進数または 16 進数の値で渡す
と、Vim は通常の GtkWindow の代わりに、その値を使って GtkPlug ウィジェットを作
成する。これにより、Vim は GTK+ プラグインとして動作できる。

これは実際にはプログラマ向けのインターフェイスであり、Vim を正しく起動する対応
アプリケーションが無ければ役に立たない。GTK+ ソケットについての詳細は、
https://www.gtk.org/docs/apis/index を参照。

Note この機能は最新の GTK バージョンを必要とすることに注意。GTK 1.2.10 にはま
だ小さな問題がある。ソケット機能は GTK+ 2 ではまだテストされていない -- 気軽に
名乗り出てほしい。

6. GNOME 版                                     gui-gnome Gnome GNOME

GNOME GUI は GTK+ 版とまったく同じように動作する。どのように動作するかは上記の
GTK+ を参照。ただし、見た目は少し異なり、素の GTK+ GUI では使用可能でない重
要な機能を 1 つ実装している: セッションマネージャーとの相互作用である。
gui-gnome-session

これらが異なる見た目である:
- GNOME ダイアログを使う (GNOME 1 のみ)。GNOME 2 GUI は GTK+ 2 版と同じ素敵な
  ダイアログを使う。
- GNOME ドックを使うので、ツールバーおよびメニューバーを最上部以外の別の場所に
  移動できる (例えば、ツールバーは左、右、上、または下に配置できる)。メニュー
  バーおよびツールバーの配置は GNOME 2 版でのみ保存される。
- つまり、メニューバーおよびツールバーのハンドルが戻ってきた! やった! そして、
  サイズ変更グリッドもまだ動作する。

configure によって見つかり、--enable-gnome-check 引数が使われた場合、GNOME は
一緒にコンパイルされる。

Note: GTK+ 3 GUI のビルドでは --enable-gnome-check の使用を避けること。上記の
機能は GTK+ 3 に統合されている。


GNOME セッションサポート
                                        gui-gnome-session gnome-session
ログアウト時に、いずれかのバッファが変更されている場合、Vim はおなじみの終了確
認ダイアログを表示する。[Cancel] をクリックするとログアウト処理が中止される。
それ以外の場合、現在のセッションは :mksession コマンドを使ってディスクに保存
され、次回ログインした時に復元される。

GNOME セッションサポートは KDE セッションマネージャーでも動作するはずである。
何か問題が発生した場合、バグとして報告してほしい。

Note: 自動セッション保存は、自分のセッションファイル、スクリプト、および自動コ
マンドとの衝突を避けるため、完全に透過的に動作する。詳細には、これは次のことを
意味する:
- セッションファイルは別のディレクトリ (通常は $HOME/.gnome2) に保存される。
- 'sessionoptions' は無視され、代わりに適切なフラグのハードコードされたセット
  が使われる:
        blank,curdir,folds,globals,help,options,tabpages,winsize
- 内部変数 v:this_session はセッションの保存時に変更されない。また、再度ログ
  インした時に元の値に復元される。

GUI ウィンドウの位置およびサイズは、それがウィンドウマネージャーの仕事であるた
め、Vim では保存されない。しかし、GTK+ 2 サポート付きでコンパイルされた場合、
Vim はウィンドウロールを復元することで (--role コマンドライン引数を使って)、
WM がウィンドウを識別するのを助ける。

8. コンパイル                                           gui-x11-compiling

X11 を使っている場合、Vim の configure は既定でまずシステム上の必要な GTK+ ファ
イルを探そうとする。GTK+ 2 および GTK+ 3 の両方が使用可能な場合、configure に
--enable-gui=gtk3 が明示的に渡されない限り、GTK+ 2 が選ばれる。

GTK+ ファイルが見つからない場合、Motif ファイルが探される。両方とも失敗した場
合、GUI は無効になる。

GTK+ については、Vim の構成処理は、指定したビルドに必要な GTK+ が正しくインス
トールされて使用可能かどうかをチェックするために pkg-config(1) を使う。したがっ
て、configure を実行する前に、システムに動作する pkg-config および必要な GTK+
の .pc ファイルがあることを確認するのがよい。そのためには、例えば、コマンドラ
インで以下を実行して、pkg-config が GTK+ 2 で動作するかを確認する:

    $ pkg-config --modversion gtk+-2.0

GTK+ 3 の場合は gtk+-2.0 を gtk+-3.0 に置き換える。GTK+ の正しいバージョン番号
が得られた場合、先に進める。そうでない場合、pkg-config および GTK+ を正しく設
定するために、何らかのシステム管理の作業を行う必要があるだろう。

GTK+ 2 GUI は既定でビルドされる。したがって、通常は、それをビルドするために
--enable-gui=gtk2 などのオプションを configure に渡す必要はない。

オプションで、GTK+ 2 GUI は GNOME 2 サポートを統合できる。このサポートは
configure に --enable-gnome-check を渡すことで有効になる。

GNOME 2 サポートの機能は既に GTK+ 3 に統合されているので、GTK+ 3 GUI をビルド
したい場合、configure に --enable-gui=gtk3 を明示的に渡し、それに
--enable-gnome-check を渡すのは避けなければならない。

そうでなく、Motif を使っている場合、configure が探さないディレクトリに Motif
ファイルがある時は、Makefile を編集してディレクトリの名前を入力する。Motif ディ
レクトリを設定する例については "GUI_INC_LOC" を検索すること。

                                                        gui-x11-gtk
現在、Vim は GTK+ 2 および GTK+ 3 の両方をサポートしている。

GTK+ 2 GUI には GTK+ 2.2 以降が必要である。

GTK+ 3 GUI は、ソースコードが 3.x 系列の全てのバージョンでコンパイルできるよう
に書かれているが、そのバージョンで行われた再描画における大幅な実装変更のため、
GTK+ 3.10 以降を推奨する。

                                                        gui-x11-motif
Motif では、少なくとも Motif バージョン 1.2 および/または X11R5 が必要である。
Motif 2.0 および X11R6 は問題ない。Motif 1.1 および X11R4 は動作するかもしれな
いが、保証はない (いくつか問題があるかもしれないが、少しの作業でコンパイルし、
実行できるようにできるかもしれない。そうした場合はパッチを送ってほしい)。
LessTif の最新のリリースもうまく動作すると報告されている。

                                            gui-x11-athena gui-x11-neXtaw
Athena GUI および neXtaw のサポートはパッチ 8.2.4677 で削除された。

                                                        gui-x11-misc
一般に、異なる GTK+、Motif、および X11 のバージョンのファイルを混在させようと
しないこと。これは問題を引き起こす。例えば、X11R5 のヘッダーファイルを X11R6
のライブラリと共に使うと、おそらく動作しない (リンクではエラーメッセージは出な
いが、Vim は後でクラッシュする)。

                                                        gui-wayland
Wayland ディスプレイサーバープロトコルのサポートは、GTK3 GUI 向けにパッチ
9.1.0064 で導入された。ただし、GTK3 GUI は X11 固有の機能および API 呼び出しを
中心に大きく作られているため、より良い Wayland 体験を望む場合、GTK4 GUI を使う
ことを推奨する。


Note: Wayland プロトコルにはいくつかの制限があるため、以下の関数は動作しない:
getwinpos()、getwinposx()、getwinposy() および v:windowid 変数は使用可
能にならない。

9. X11 セレクション機構                                 x11-selection

X11 を使っている場合、GUI または X11 対応の Vim を使った xterm のいずれかで、
Vim は X11 のセレクションおよびクリップボードへの様々なアクセスを提供する。こ
れらは 2 つのセレクションレジスタ "* および "+ を使ってアクセスされる。

X11 は 2 つの基本的な種類のグローバルな格納場所、セレクションおよびカットバッ
ファを提供しており、それらは 1 つの重要な点で異なる: セレクションはアプリケー
ションによって "所有" され、そのアプリケーション (例えば、Vim) が終了すると消
えてデータが失われるのに対し、カットバッファは X サーバー自身の中に格納され、
上書きされるか、または X サーバーが終了する (例えば、ログアウト時) まで残る。

セレクションの内容は、元のアプリケーションによって保持され (例えば、コピー時)、
他のアプリケーションがそれを要求した時 (例えば、貼り付け時) にだけ、そのアプリ
ケーションに渡される。

カットバッファの内容は即座に書き込まれ、その後、元のアプリケーションに接触する
ことなく、X サーバーから直接アクセスできる。

                                                        quoteplus quote+
文書化された X セレクションは 3 つある: PRIMARY (現在のビジュアル選択を表すも
のとされる - Vim のビジュアルモードのように)、SECONDARY (定義が曖昧) および
CLIPBOARD (切り取り、コピー、および貼り付け操作に使われるものとされる)。

これら 3 つのうち、Vim は "* レジスタの読み込みおよび書き込みの時に PRIMARY を
使い (そのため、X11 セレクションが使用可能な場合、Vim は 'clipboard' の既定値
に "autoselect" を設定する)、"+ レジスタの読み込みおよび書き込みの時に
CLIPBOARD を使う。Vim は SECONDARY セレクションにはアクセスしない。

これは GUI および端末版の両方に当てはまる。X11 以外のシステムでは、プラスおよ
びスターレジスタは両方ともシステムのクリップボードを使う。

例: (既定のオプション値を仮定)
- Vim でビジュアルモードで URL を選択する。ブラウザーに移動し、URL テキスト
  フィールドでマウスの中ボタンをクリックする。選択したテキストが挿入される (う
  まくいけば!)。Note: Firefox では about:config で middlemouse.contentLoadURL
  設定を true に設定でき、そうするとウィンドウ内のほとんどの場所でマウスの中ボ
  タンを押した時に、選択した URL が使われる。
- マウスでドラッグしてブラウザーでテキストを選択する。Vim に移動し、マウスの中
  ボタンを押す: 選択したテキストが挿入される。
- Vim でテキストを選択し、"+y を実行する。ブラウザーに移動し、マウスでドラッグ
  してテキストフィールド内のテキストを選択する。次にマウスの右ボタンを使い、
  ポップアップメニューから "Paste" を選択する。選択したテキストが Vim からのテ
  キストで上書きされる。
Note "* レジスタで別のテキストを使用可能にするビジュアル選択を行った時、"+ レ
ジスタのテキストは使用可能なままであることに注意。これにより、選択したテキスト
を上書きできる。

                                                                W23
"* または "+ レジスタにヤンクしようとしていて、Vim が X11 セレクション (または
クリップボード) への接続を確立できない場合、Vim はレジスタ 0 を使い、警告を出
力する:

  Warning: Clipboard register not available, using register 0

Note: これは Wayland クリップボード機能にも同様に当てはまる。

                                                                W24
Vim には、元の Vi との互換性を保とうとするだけの tiny ビルドから、多くの改良
(GUI など) を含む拡張ビルドまで、様々な種類がある。しかし、サーバーおよび組み
込みシステムでは、この機能は X11 ライブラリが存在することを必要とするため、Vim
は通常クリップボードサポートなしでコンパイルされる。":version" の出力で
+clipboard または -clipboard フラグを確認すること。前者はクリップボードサポー
トがあることを意味し、後者は Vim にクリップボードサポートが含まれていないこと
を意味する。

"* または "+ レジスタにアクセスしようとしていて、Vim にクリップボードサポート
が無い場合、この警告が表示される:

  Warning: Clipboard register not available. See :h W24

クリップボードサポートの無い vim を持っているが、クリップボードを使いたい場合、
vim-enhanced または vim-gtk3 のような、より拡張された Vim パッケージをインス
トールしてみること (gui パッケージには通常、クリップボードサポートが含まれた端
末 Vim も付属している)。

                                                        x11-cut-buffer
既定では、CUT_BUFFER0 から CUT_BUFFER7 までの 8 つのカットバッファがある。Vim
は CUT_BUFFER0 だけを使う。これは xterm が既定で使うものである。

Vim が使用可能でなくなろうとしていて (終了するか、または一時停止することによっ
て)、そのため他のアプリケーションのセレクション要求に応答できなくなる時は常に、
Vim は所有しているセレクションの内容を CUT_BUFFER0 に書き込む。"+ CLIPBOARD セ
レクションが Vim によって所有されている場合、これが優先して書き込まれ、そうで
なく "* PRIMARY セレクションが Vim によって所有されている場合、それが書き込ま
れる。

同様に、Vim が "* または "+ から貼り付けようとした時 (明示的に、または "* レジ
スタの場合はマウスの中ボタンがクリックされた時)、要求された X セレクションが空
であるか、または使用可能でない場合、Vim は CUT_BUFFER0 の現在の値を読み込むこ
とに戻る。

Note この方法でテキストが CUT_BUFFER0 にコピーされた時、それを後で貼り付けるの
が Vim であっても、選択の種類 (文字、行、または矩形) は常に失われることに注意。

Xterm は既定で、常に可視のセレクションを PRIMARY および CUT_BUFFER0 の両方に書
き込む。貼り付ける時は、PRIMARY が使用可能な場合はそれを使い、そうでない場合は
CUT_BUFFER0 にフォールバックする。このため、Vim と xterm の間で切り取りおよび
貼り付けをする時は、"* レジスタを使うべきである。Xterm は CLIPBOARD を使わない
ので、"+ は xterm では動作しない。

ほとんどの新しいアプリケーションは、現在のセレクションを PRIMARY ("*) 経由で提
供し、切り取り/コピー/貼り付け操作には CLIPBOARD ("+) を使う。したがって、"*
または "+ レジスタのいずれかを使うことを選ぶことで、両方にアクセスできる。

                                                        gtk4-menu-navigation
GTK 4 GUI では、これらのキーボードマッピングでメニュー項目を移動することもでき
る:
    キー                意味
    <Tab> <Down>        次の項目へ移動
    <S-Tab> <Up>        前の項目へ移動
    <Left>              親サブメニューへ移動
    <Right>             現在の項目のサブメニューへ移動
    <C-Left>            次のメニューバー項目へ移動
    <C-Right>           前のメニューバー項目へ移動
