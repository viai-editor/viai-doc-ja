1. ファイルタイプ                               filetypes file-types

Vim は編集されるファイルのタイプを検出できる。これはファイル名をチェックし、時
にはファイルの内容を特定のテキストについて調べることで行われる。

                                                        :filetype :filet
ファイルタイプ検出を有効にするには、vimrc でこのコマンドを使う:
        :filetype on
新規または既存のファイルが編集されるたびに、Vim はファイルのタイプを認識しよう
とし、'filetype' オプションを設定する。これは FileType イベントを発生させ、こ
のイベントは構文ハイライトの設定、オプションの設定などに使用できる。

NOTE: Vi 互換であることはオプションがグローバルであることを意味するので、ファ
イルタイプと 'compatible' は一緒にはうまく動作しない。まだそうしていない場合
は、'compatible' をリセットすることを推奨する。

詳細: ":filetype on" コマンドは、これらのファイルのうちの 1 つを読み込む:
                Amiga       $VIMRUNTIME/filetype.vim
                Mac         $VIMRUNTIME:filetype.vim
                MS-Windows  $VIMRUNTIME\filetype.vim
                Unix        $VIMRUNTIME/filetype.vim
                VMS         $VIMRUNTIME/filetype.vim
        このファイルは、BufNewFile および BufRead イベントに対する自動コマンド
        を定義する Vim script である。ファイルタイプが名前で見つからない場合、
        ファイルの内容からそれを検出するために、ファイル
        $VIMRUNTIME/scripts.vim が使用される。
        GUI が実行中であるか、またはすぐに開始する場合、menu.vim スクリプト
        も読み込まれる。それを避けることについては 'go-M' を参照。

自分のファイルタイプを追加するには、以下の new-filetype を参照。ファイルタイ
プに関するヘルプを検索するには、"ft-" を前に付け、必要に応じて "-syntax"、
"-indent" または "-plugin" を後ろに付ける。例:
        :help ft-vim-indent
        :help ft-vim-syntax
        :help ft-man-plugin

ファイルタイプが自動的に検出されない場合、または間違ったタイプを検出した場合、
'filetype' オプションを手動で設定するか、またはファイルにモードラインを追加す
ることができる。例、IDL ファイルの場合は以下のコマンドを使う:
        :set filetype=idl

またはファイルにこの modeline を追加する:
        /* vim: set filetype=idl : */

                                                :filetype-plugin-on
特定のファイルタイプに対するプラグインファイルの読み込みを、以下で有効にできる:

        :filetype plugin on
ファイルタイプ検出がまだオンにされていない場合、それもオンにされる。
これは実際には 'runtimepath' 内のファイル "ftplugin.vim" を読み込む。
その結果、ファイルが編集されたときに、そのプラグインファイルが読み込まれる (検
出されたファイルタイプに対するものがある場合)。filetype-plugin

                                                :filetype-plugin-off
以下でそれを再び無効にできる:
        :filetype plugin off
そのとき、ファイルタイプ検出はオフにされない。しかし、ファイルタイプ検出をオフ
にした場合は、プラグインも読み込まれない。
これは実際には 'runtimepath' 内のファイル "ftplugof.vim" を読み込む。

                                                :filetype-indent-on
特定のファイルタイプに対するインデントファイルの読み込みを、以下で有効にできる:

        :filetype indent on
ファイルタイプ検出がまだオンにされていない場合、それもオンにされる。
これは実際には 'runtimepath' 内のファイル "indent.vim" を読み込む。
その結果、ファイルが編集されたときに、そのインデントファイルが読み込まれる (検
出されたファイルタイプに対するものがある場合)。indent-expression

                                                :filetype-indent-off
以下でそれを再び無効にできる:
        :filetype indent off
そのとき、ファイルタイプ検出はオフにされない。しかし、ファイルタイプ検出をオフ
にした場合は、インデントファイルも読み込まれない。
これは実際には 'runtimepath' 内のファイル "indoff.vim" を読み込む。
これは、これから開くファイルに対する自動インデントを無効にする。すでに開かれて
いるファイルでは動作し続ける。開かれているファイルでインデントを無効にするに
は、'autoindent'、'cindent'、'smartindent' および/または 'indentexpr' をリセッ
トする。

                                                :filetype-off
ファイルタイプ検出を無効にするには、このコマンドを使う:
        :filetype off
これは "plugin" および "indent" のフラグを保持するが、ファイルタイプが検出され
なくなるので、次の ":filetype on" まではそれらは動作しない。


概要:                                           :filetype-overview

コマンド                        検出            プラグイン      インデント
:filetype on                    on              変更なし        変更なし
:filetype off                   off             変更なし        変更なし
:filetype plugin on             on              on              変更なし
:filetype plugin off            変更なし        off             変更なし
:filetype indent on             on              変更なし        on
:filetype indent off            変更なし        変更なし        off
:filetype plugin indent on      on              on              on
:filetype plugin indent off     変更なし        off             off

現在の状態を見るには、以下を入力する:
        :filetype
出力はおおよそこのようになる:
        filetype detection:ON  plugin:ON  indent:OFF

ファイルタイプは構文ハイライトにも使用される。":syntax on" コマンドが使用され
た場合、ファイルタイプ検出もインストールされる。":syntax on" の後に
":filetype on" を実行する必要はない。

ファイルタイプの 1 つを無効にするには、自分のファイルタイプファイルに 1 行を追
加する、remove-filetype を参照。

                                                        filetype-detect
ファイルタイプを再度検出するには:
        :filetype detect
空のファイルで開始し、ファイルタイプの検出を可能にするテキストを入力した場合
に、これを使う。例えば、シェルスクリプトでこれを入力したとき: "#!/bin/csh"。
   ファイルタイプ検出がオフだった場合、"on" 引数が使用されたかのように、まずそ
   れが有効にされる。

                                                        filetype-overrule

ファイルかを推測しようとする。これは常にうまくいくとは限らない。特定の拡張子に
使用されるファイルタイプを上書きするために、いくつかのグローバル変数を使用でき
る:

いくつかのファイルタイプでは、ファイルタイプが検出できなかった場合にのみ、グ
ローバル変数が使用される:
        *.r             g:filetype_r    ft-rexx-syntax

                                                        filetype-ignore
特定のファイルが調べられるのを避けるために、g:ft_ignore_pat 変数が使用される。
デフォルト値はこのように設定される:
        :let g:ft_ignore_pat = '\.\(Z\|gz\|bz2\|zip\|tgz\)$'
これは、圧縮されたファイルの内容は調べられないことを意味する。

                                                        new-filetype
使用したいファイルタイプがまだ検出されない場合、それを追加する方法は 4 つある。
いずれの方法でも、$VIMRUNTIME/filetype.vim ファイルは変更しないほうがよい。そ
れは Vim の新しいバージョンをインストールするときに上書きされる。

A. すべてのデフォルトのファイルタイプチェックを上書きしたい場合。
   これは、ファイルタイプごとに 1 つのファイルを書くことで動作する。欠点は、多
   くのファイルが存在しうることである。利点は、このファイルを正しいディレクト
   リに置くだけで動作させられることである。
                                                        ftdetect
   1. ユーザーランタイムディレクトリを作成する。通常は 'runtimepath' オプショ
      ンの最初の項目を使用することになる。それから、その中にディレクトリ
      "ftdetect" を作成する。Unix での例:
        :!mkdir ~/.vim
        :!mkdir ~/.vim/ftdetect

   2. ファイルタイプを検出する自動コマンドを含むファイルを作成する。例:
        au BufRead,BufNewFile *.mine            set filetype=mine
      Note "augroup" コマンドが無いことに注意、これはファイルを読み込むときに
      すでに行われている。パターン "*" を使用し、それからファイルの内容をチェッ
      クしてそれを認識することもできる。
      このファイルを "mine.vim" として、ユーザーランタイムディレクトリ内の
      "ftdetect" ディレクトリに書き込む。例えば Unix の場合:
        :w ~/.vim/ftdetect/mine.vim

   3. 新しいファイルタイプ検出を使用するには、Vim を再起動しなければならない。

   "ftdetect" ディレクトリ内のファイルはすべてのデフォルトのチェックの後に使用
   されるので、以前に検出されたファイルタイプを上書きできる。しかし、以前に検
   出されたファイルタイプを保持するために、:setfiletype を使用することもでき
   る。

B. デフォルトのファイルタイプチェックの後に自分のファイルを検出したい場合。

   これは上記の A のように動作するが、'filetype' を無条件に設定する代わりに
   ":setfiletype" を使用する。これはまだファイルタイプが検出されていない場合に
   のみ 'filetype' を設定する。例:
        au BufRead,BufNewFile *.txt             setfiletype text

   コマンド内で、すでに検出されたファイルタイプを使用することもできる。例えば、
   "pascal" が検出されたときにファイルタイプ "mypascal" を使用するには:
        au BufRead,BufNewFile *         if &ft == 'pascal' | set ft=mypascal
                                                                       | endif

C. ファイルタイプがファイル名で検出できる場合。
   1. ユーザーランタイムディレクトリを作成する。通常は 'runtimepath' オプショ
      ンの最初の項目を使用することになる。Unix での例:
        :!mkdir ~/.vim

   2. ファイルタイプを検出する自動コマンドを含むファイルを作成する。例:
        " 自分のファイルタイプファイル
        if exists("did_load_filetypes")
          finish
        endif
        augroup filetypedetect
          au! BufRead,BufNewFile *.mine         setfiletype mine
          au! BufRead,BufNewFile *.xyz          setfiletype drawing
        augroup END
      このファイルを "filetype.vim" としてユーザーランタイムディレクトリに書き
      込む。例えば Unix の場合:
        :w ~/.vim/filetype.vim

   3. 新しいファイルタイプ検出を使用するには、Vim を再起動しなければならない。

   自分の filetype.vim は、デフォルトの FileType 自動コマンドがインストールさ
   れる前に読み込まれる。自分の自動コマンドが先にマッチし、":setfiletype" コマ
   ンドが、この後に他の自動コマンドが 'filetype' を設定しないことを保証する。
                                                        new-filetype-scripts
D. ファイルタイプがファイルの内容を調べることでしか検出できない場合。

   1. ユーザーランタイムディレクトリを作成する。通常は 'runtimepath' オプショ
      ンの最初の項目を使用することになる。Unix での例:
        :!mkdir ~/.vim

   2. これを行うための Vim script ファイルを作成する。例:
        if did_filetype()       " ファイルタイプはすでに設定済み..
          finish                " ..これらのチェックは行わない
        endif
        if getline(1) =~ '^#!.*\<mine\>'
          setfiletype mine
        elseif getline(1) =~? '\<drawing\>'
          setfiletype drawing
        endif
      さらなる例は $VIMRUNTIME/scripts.vim を参照。
      このファイルを "scripts.vim" としてユーザーランタイムディレクトリに書き
      込む。例えば Unix の場合:
        :w ~/.vim/scripts.vim

   3. 検出はすぐに動作し、Vim を再起動する必要はない。

   自分の scripts.vim はファイルタイプのデフォルトのチェックの前に読み込まれ
   る。これは、自分のルールが $VIMRUNTIME/scripts.vim 内のデフォルトのルールを
   上書きすることを意味する。

                                                remove-filetype
自分にとって間違ったファイルタイプが検出される場合、それを捕らえるために
filetype.vim または scripts.vim をインストールする (上記を参照)。後でいずれに
せよ設定されるのを避けるために、'filetype' を存在しない名前に設定できる:
        :set filetype=ignored

多くのユーザーがいるシステムを設定していて、各ユーザーに同じファイルタイプを追
加/削除させたくない場合、全員に使用されるランタイムディレクトリに filetype.vim
および scripts.vim ファイルを書くことを検討すること。使用するディレクトリにつ
いては 'runtimepath' を確認すること。それが無い場合、system-vimrc で
'runtimepath' を設定する。デフォルトのディレクトリを保持するよう注意すること!


                                                autocmd-osfiletypes
NOTE: RISC OS の実装が削除されたので、このコードは現在無効になっている。将来、
これは 'filetype' オプションを使用するようになる。

ファイルと一緒にファイルタイプを格納することをサポートするオペレーティングシス
テムでは、ファイルが特定のタイプの場合にのみ自動コマンドが実行されるべきである
ことを指定できる。

実際のタイプチェックは、どのプラットフォームで Vim を実行しているかに依存する。
詳細はシステムのドキュメントを参照。

自動コマンドで osfiletype チェックを使用するには、パターンの代わりに、マッチす
るタイプのリストを山括弧で囲んで置くべきである、このように:

        :au BufRead *.html,<&faf;HTML>  runtime! syntax/html.vim

これは以下にマッチする:

- 名前が ".html" で終わるすべてのファイル
- タイプが "&faf" または "HTML" であるすべてのファイル、ここで、これらのタイプ
  の意味はどのバージョンの Vim を使用しているかに依存する。
  未知のタイプはマッチしないと見なされる。

タイプとパターンを同時に指定することもできる (この場合は両方がマッチしなければ
ならない):

        :au BufRead <&fff>diff*

これは、名前が "diff" で始まるタイプ "&fff" のファイルにマッチする。


                                                        plugin-details
"plugin" ディレクトリは 'runtimepath' オプション内のどのディレクトリにあっても
よい。これらのディレクトリはすべてプラグインが検索され、それらはすべて読み込ま
れる。例えば、このコマンドが:

        set runtimepath

この出力を生成する場合:

        runtimepath=/etc/vim,~/.vim,/usr/local/share/vim/vim82

Vim はこれらのディレクトリおよびその下にあるすべてのプラグインを読み込む:

        /etc/vim/plugin/ 
        ~/.vim/plugin/ 
        /usr/local/share/vim/vim82/plugin/ 

Note 最後のものは展開された $VIMRUNTIME の値であることに注意。

Note プラグインマネージャーまたは packages を使用する場合、多くのディレクト
リが 'runtimepath' に追加されることに注意。これらのプラグインはそれぞれ独自の
ディレクトリを必要とする、それらを直接 ~/.vim/plugin に置かないこと。

プラグインが読み込まれていないように見える場合はどうするか? -V 引数を使用す
ることで、Vim の起動時に何が起こるかを調べることができる:

        vim -V2

多くのメッセージが表示され、その中にプラグインの読み込みに関する記述がある。そ
れは以下で始まる:

        Searching for "plugin/**/*.vim" in

そこで Vim がプラグインスクリプトを探す場所を確認できる。

2. ファイルタイププラグイン                             filetype-plugins

ファイルタイププラグインの読み込みが有効にされているとき
:filetype-plugin-on、オプションが設定され、マッピングが定義される。これらは
すべてバッファローカルであり、他のファイルには使用されない。

ファイルタイプに対するマッピングを定義すると、自分で定義したマッピングの邪魔に
なることがある。これを避けるにはいくつかの方法がある:
1. "maplocalleader" 変数を、マッピングの開始にしたいキーシーケンスに設定する。
   例:
        :let maplocalleader = ","
   そうすると、すべてのマッピングは、デフォルトであるバックスラッシュの代わり
   にコンマで始まるようになる。<LocalLeader> も参照。

2. 自分のマッピングを定義する。例:
        :map ,p <Plug>MailQuote
   提供される機能およびマップする文字列については、以下のプラグインファイルの
   説明を確認する必要がある。
   プラグインが読み込まれる前 (そのタイプのファイルを編集する前) に、自分のマッ
   ピングを定義する必要がある。そうするとプラグインはデフォルトのマッピングの
   インストールをスキップする。
                                        no_mail_maps g:no_mail_maps
3. ファイルタイプの名前を含む変数を設定することで、特定のファイルタイプに対す
   るマッピングの定義を無効にする。"mail" ファイルタイプの場合、これは以下にな
   る:
        :let no_mail_maps = 1
                                        no_plugin_maps g:no_plugin_maps
4. 変数を設定することで、すべてのファイルタイプに対するマッピングの定義を無効
   にする:
        :let no_plugin_maps = 1


                                                        ftplugin-overrule
グローバルファイルタイププラグインが望みどおりのことを正確に行わない場合、これ
を変更する方法は 3 つある:

1. いくつかの設定を追加する。
   'runtimepath' の早い段階にあるディレクトリに、新しいファイルタイププラグイ
   ンを作成しなければならない。例えば Unix では、このファイルを使用できる:
        vim ~/.vim/ftplugin/fortran.vim
    追加したい設定およびマッピングを設定できる。Note グローバルプラグインはこ
   の後に読み込まれることに注意、それはここで行った設定を上書きするかもしれな
   い。この場合は、以下の 2 つの方法のうちの 1 つを使用する必要がある。

2. プラグインのコピーを作成し、それを変更する。
   そのコピーを 'runtimepath' の早い段階にあるディレクトリに置かなければならな
   い。例えば Unix では、このようにできる:
        cp $VIMRUNTIME/ftplugin/fortran.vim ~/.vim/ftplugin/fortran.vim
    それから、コピーしたファイルを好みに合わせて編集できる。b:did_ftplugin 変
   数が設定されるので、グローバルプラグインは読み込まれない。
   この方法の欠点は、配布されているプラグインが改良されたときに、それを再びコ
   ピーして変更しなければならないことである。

3. グローバルプラグインを読み込んだ後に設定を上書きする。
   'runtimepath' の終わりのほうにあるディレクトリに、新しいファイルタイププラ
   グインを作成しなければならない。例えば Unix では、このファイルを使用できる:

        vim ~/.vim/after/ftplugin/fortran.vim
    このファイルでは、変更したい設定だけを変更できる。

CHANGELOG                                               ft-changelog-plugin

Changelog ファイルへの Changelog エントリの簡単な入力を可能にする。探索する価
値のあるいくつかのコマンド、マッピング、および変数がある:

オプション:
'comments'              整形を乱さないように空にされる。
'textwidth'             標準である 78 に設定される。
'formatoptions'         テキストを挿入するときに折り返すために、't' フラグが追
                        加される。

コマンド:
NewChangelogEntry       新しい Changelog エントリを賢い方法で追加する (以下を
                        参照)。

ローカルマッピング:
<Leader>o               同様に賢い方法で新しい Changelog エントリを開始する
                        (以下を参照)。

グローバルマッピング:
                        NOTE: グローバルマッピングは、最初に
                        ftplugin/changelog.vim ファイルを読み込むことでアクセ
                        スされる。例えば以下によって
                                runtime ftplugin/changelog.vim
                        .vimrc 内で。
<Leader>o               現在のディレクトリに対して開かれた ChangeLog バッファ
                        に切り替えるか、または、現在のディレクトリに存在する場
                        合は新しいバッファでそれを開く。それから、上記のローカ
                        ルの <Leader>o と同じことを行う。

変数:
g:changelog_timeformat  非推奨。代わりに g:changelog_dateformat を使用するこ
                        と。
g:changelog_dateformat  ChangeLog エントリで使用される日付 (および時刻) の形
                        式。受け付けられる形式は strftime() 関数に対するもの
                        と同じである。
                        デフォルトは "%Y-%m-%d" であり、これは多くの ChangeLog
                        レイアウトの標準形式である。
g:changelog_username    ユーザーの名前およびメールアドレス。
                        デフォルトは環境変数およびシステムファイルから推測され
                        る。/etc/passwd で現在のユーザーのコメント部分を検索す
                        る。これは、非公式に、最初の区切りのコンマまでユーザー
                        の本名を含む。それから $NAME 環境変数をチェックし、最
                        後に whoami および hostname を実行してメールアドレ
                        スを組み立てる。最終的な形式は以下である
                                Full Name  <user@host>

g:changelog_new_date_format
                        新しい日付エントリを作成するときに使用する形式。
                        以下の表は、文字列内の特殊なトークンを説明する:
                                %%      単一の '%' 文字を挿入する
                                %d      上記の日付を挿入する
                                %u      上記のユーザーを挿入する
                                %p      b:changelog_entry_prefix の結果を
                                        挿入する
                                %c      完了時にカーソルを置く場所
                        デフォルトは "%d  %u\n\n\t* %p%c\n\n" であり、これは以
                        下のようなものを生成する (| はカーソルが置かれる場所で
                        あるが、行頭にある場合は行の始まりを表す)
                                |2003-01-14  Full Name  <user@host>
                                |
                                |        * prefix|

g:changelog_new_entry_format
                        新しいエントリを作成するときに使用される形式。
                        以下の表は、文字列内の特殊なトークンを説明する:
                                %p      b:changelog_entry_prefix の結果を
                                        挿入する
                                %c      完了時にカーソルを置く場所
                        デフォルトは "\t*%c" であり、これは以下に似たものを生
                        成する
                                |        * prefix|

g:changelog_date_entry_search
                        日付エントリを検索するときに使用する検索パターン。
                        g:changelog_new_date_format で使用できるのと同じトーク
                        ンが、ここでも使用できる。
                        デフォルトは '^\s*%d\_s*%u' であり、これは以下の形式
                                |2003-01-14  Full Name  <user@host>
                        およびいくつかの似た形式にマッチする行を見つける。

g:changelog_date_end_entry_search
                        日付エントリの終わりを検索するときに使用する検索パター
                        ン。
                        g:changelog_new_date_format で使用できるのと同じトーク
                        ンが、ここでも使用できる。
                        デフォルトは '^\s*$' であり、これは空白のみを含むか、
                        または完全に空である行を見つける。

b:changelog_name                                        b:changelog_name
                        探す ChangeLog ファイルの名前。
                        デフォルトは 'ChangeLog' である。

b:changelog_path
                        現在のバッファに使用する ChangeLog のパス。デフォルト
                        は空であり、したがって現在のバッファと同じディレクトリ
                        で b:changelog_name という名前のファイルを探す。見つ
                        からない場合、現在のバッファの親ディレクトリが検索され
                        る。これはファイルが見つかるか、または検索する親ディレ
                        クトリが無くなるまで再帰的に続く。

b:changelog_entry_prefix
                        新しいエントリへのプリフィックスを生成するために呼ぶ関
                        数の名前。この関数は引数を取らず、プリフィックスを含む
                        文字列を返すべきである。空のプリフィックスを返しても問
                        題ない。
                        デフォルトは、ChangeLog のパス名と現在のバッファのパス
                        名の間の最短パスを生成する。将来は、この変数に他の変数
                        コンテキスト、例えば g: を使用することも可能になる予定
                        である。

Changelog エントリは、追加されるテキストの量が最も少ない場所に挿入される。現在
の日付およびユーザーを把握した後、現在の日付およびユーザーで始まるエントリが
ファイル内で検索され、見つかった場合はその下に別の項目を追加する。見つからない
場合、新しいエントリおよび項目が Changelog の先頭に追加される。

HTML                                                    ft-html-plugin

タグ折り畳みにはいくつかの困難がある。多くの要素、例えば blockquote は、常に
開始タグおよび終了タグで区切られる。いくつかの要素、例えば p の終了タグは、
特定のコンテキストで省略できる。空要素、例えば hr は終了タグを持たない。省略
可能な終了タグをサポートするためのルールはその場しのぎで複雑であるが [0]、それ
らはスコープ内の要素に適用される。構文的な整形式性を仮定すると、終了タグは、ス
コープ内 [1] かつファイルの先頭に向かって発見できる、最も近いマッチする開始タ
グに関連付けることができ、一方で、すべての釣り合っていないタグおよびインライン
化されたタグは無視できる。構文ハイライトが有効な状態で、fold-expr 方式を使用
したタグ折り畳みは以下で有効にできる:
        let g:html_expr_folding = 1

デフォルトでは、タグ折り畳みは TextChanged または InsertLeave イベントが発
生するたびに、最初からやり直される。そのような頻度は、特に大きなファイルでは望
ましくない場合があり、この再計算は以下で無効にできる:
        let g:html_expr_folding_without_recomputation = 1
        doautocmd FileType

別の再計算を強制するには、以下を実行する:
        unlet! b:foldsmap
        normal zx

[0] https://html.spec.whatwg.org/multipage/syntax.html#optional-tags
[1] https://en.wikipedia.org/wiki/Dangling_else

JAVA                                                    ft-java-plugin

変数 "g:ftplugin_java_source_path" が定義されていて、その値が拡張子が ".jar"
または ".zip" のいずれかであるファイル名であり、例えば:
        let g:ftplugin_java_source_path = '/path/to/src.jar'
        let g:ftplugin_java_source_path = '/path/to/src.zip'

かつ zip プラグインがすでに読み込まれている場合は常に、gf コマンドを使用し
てアーカイブを開くことができ、n コマンドを使用して選択された型を探すことがで
き、<Return> キーを使用して一覧表示されたファイルを読み込むことができる。

Note Zip プラグインで読み込まれたバッファ内で "gf" コマンドを使用した効果は、
Zip プラグインのバージョンに依存することに注意。Jar 形式のアーカイブをサポート
していないバージョンの Zip プラグインでは、関心のある各 Jar アーカイブに対して
".zip" 拡張子のシンボリックリンクを作成し、今後はそのようなファイルを変数に割
り当てることを検討すること。

そうでない場合、定義された変数 "g:ftplugin_java_source_path" に対して、'path'
オプションのローカル値は、変数の値を前に付けることでさらに変更される。例えば:

        let g:ftplugin_java_source_path = $JDK_SRC_PATH
        let &l:path = g:ftplugin_java_source_path .. ',' .. &l:path

そして "gf" コマンドを完全修飾型に対して使用して、"path" 内のファイルを探し、
それを読み込もうとすることができる。

変数に新しい値を割り当てた後は毎回、Java ファイルが読み込まれたバッファから、
手動で FileType イベントを発生させることを忘れないこと:
        doautocmd FileType

Markdown のドキュメントコメントは、美的な理由で、コメント記号 (///) に続く、
縦方向の先頭の空白の共通の連続を含むことがある。しかし、先頭の空白のいくつかの
横方向の連続は、コードブロックなどを表すので、Markdown では意味がある。便宜の
ために、gq オペレータ用の 'formatexpr' 関数が提供されている。
"g:java_ignore_javadoc" も "g:java_ignore_markdown" も定義されていない限り、
Markdown コメントの再整形は、以下で必要に応じて有効にできる:
        setlocal formatexpr=g:javaformat#RemoveCommonMarkdownWhitespace()

または 7.4.265 未満のバージョンの Vim では、以下で:
        setlocal formatexpr=javaformat#RemoveCommonMarkdownWhitespace()

この関数は行の範囲を受け付け、縦方向の先頭の空白の共通の連続を取り除き、範囲の
行を書き直す。作者のレイアウトスタイルおよびコメント内容によって、再整形のため
にどの行を選択するかは、コメント全体からその一部だけまで変わりうる。

"g:java_ignore_markdown" または "g:java_ignore_javadoc" を削除した後に毎回
Markdown コメントの認識を有効にするには、8.2.1397 より大きいバージョンの Vim
では、"javaformat.vim" を手動で再度読み込むことを忘れないこと:
        runtime autoload/javaformat.vim

このプラグインはマニュアルページを見やすく表示する。詳しい情報については、ユー

アップの vimrc ファイルからこのスクリプトを読み込む:

オプション:
'iskeyword'     マニュアルページ名の上で CTRL-] を使用できるようにするため
                に、'.' 文字が追加される。

コマンド:

                {number} セクションの {name} のマニュアルページを表示する。
ManReload       :Man の引数の補完に使用される、使用可能な man ページのキャッ
                シュを再読み込みする。

グローバルマッピング:
<Leader>K       カーソル下の単語のマニュアルページを表示する。
<Plug>ManPreGetPage
                同上、マッピングを使用できるようにする:
                        nmap <F1> <Plug>ManPreGetPage

ローカルマッピング:
<Plug>ManBS
<LocalLeader>h  バッファからバックスペース <BS> 文字を消去する。
CTRL-]          カーソル下の単語のマニュアルページにジャンプする。
CTRL-T          前のマニュアルページに戻る。

        let g:no_man_maps = 1

水平の代わりに垂直分割を使用するには:

新しいタブを使用するには:
        let g:ft_man_open_mode = 'tab'

folding を有効にするには、以下を使う:
        let g:ft_man_folding_enable = 1

        autocmd FileType man setlocal foldmethod=indent foldenable

        let g:ft_man_no_sect_fallback = 1

MANPAGER                                                manpager.vim

:Man コマンドにより、Vim を manpager (man ページを構文ハイライトし、CTRL-]
を押すとリンクされた man ページをたどる) にすることができる。

bash、zsh、ksh または dash の場合は、設定ファイル (.bashrc,.zshrc, ...) に追加
する

        export MANPAGER="vim +MANPAGER --not-a-term -"

(t)csh の場合は、設定ファイルに追加する

        setenv MANPAGER "vim +MANPAGER --not-a-term -"

fish の場合は、設定ファイルに追加する

        set -x MANPAGER "vim +MANPAGER --not-a-term -"

NOTE: いくつかの man 実装は、代わりに一時ファイルのパスを引数としてページャー
に渡す。これには mandoc のフロントエンドが含まれ、それは例えば OpenBSD、Alpine
Linux および Void Linux でのデフォルトである。

その場合は、上記の行を調整して、代わりに MANPAGER 環境変数を
"vim +MANPAGER --not-a-term" に設定し、最後のハイフンの引数を取り除く。

両方の動作をサポートする方法は、以下のラッパースクリプトを作成することである:

        #!/bin/sh
        vim +MANPAGER --not-a-term "${1:--}"

MANPAGER 環境変数をスクリプト名に設定することで、それを有効にできる (PATH 上に
無い場合は絶対パスを使用できる)。実行可能パーミッションビットが設定されている
ことを確認すること。

Python のオムニ補完 compl-omni は、+python/+python3 インタープリタ付きの

*.tex ファイルの最初の行が以下の形式の場合

        let g:tex_flavor = "plain"
        let g:tex_flavor = "context"
        let g:tex_flavor = "latex"
現在、他の形式は認識されない。
