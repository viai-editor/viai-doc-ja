1. Vim の引数                                           vim-arguments

ほとんどの場合、Vim は以下のコマンドで 1 つのファイルを編集するために起動され
る

        vim filename                                    -vim

より一般的には、Vim は以下で起動される:

        vim [option | filename] ..

オプション引数およびファイル名引数は混在させることができ、それらはいくつでも指
定できる。ただし、引数を取るオプションには注意すること。

さまざまな Vi のバージョンとの互換性については cmdline-arguments を参照。

編集の開始方法を選ぶために、以下の 5 つの項目のうちちょうど 1 つを使用できる:

                                                        -file ---
filename        1 つ以上のファイル名。最初のファイルがカレントファイルになり、
                バッファに読み込まれる。カーソルはバッファの最初の行に置かれ
                る。
                '-' で始まるファイル名がオプションとして解釈されるのを避けるに
                は、引数リストの前に "--" を置く。例:
                        vim -- -filename
                "--" の後ろの全ての引数はファイル名として解釈され、他のオプショ
                ンまたは "+command" 引数を続けることはできない。MS-Windows で
                の引用符の振る舞いについては win32-quotes を参照。

                                                        --
-               この引数は、Ex モードが使われるかどうかによって、2 つの意味を
                持つ。

                ノーマルモードでの起動:
                        vim -
                        ex -v -
                stdin から読み込まれたテキストで満たされる、新しいバッファの編
                集を開始する。通常は stdin から読み込まれるはずのコマンドは、
                今度は stderr から読み込まれる。例:
                        find . -name "*.c" -print | vim -

                バッファは変更ありとマークされるので、終了しようとしたときにテ
                キストを保存するよう注意を促される。それが気に入らない場合、こ
                れらの行を vimrc に書くこと:
                        " stdin から読み込むときに 'modified' を設定しない
                        au StdinReadPost * set nomodified

                Ex モードでの起動:
                        ex -
                        vim -e -
                        exim -
                        vim -E
                サイレントモードで編集を開始する。-s-ex を参照。

                                                        -t -tag
-t {tag}        タグ。"tag" がタグファイルから検索され、関連付けられたファイル
                がカレントファイルになり、関連付けられたコマンドが実行される。
                これは主に C プログラムに使われ、その場合 "tag" はたいてい関数
                名である。その結果、その関数を含むファイルがカレントファイルに
                なり、カーソルがその関数の先頭に置かれる (tags を参照)。

                                                        -q -qf
-q [errorfile]  QuickFix モード。[errorfile] という名前のファイルが読み込まれ、
                最初のエラーが表示される。quickfix を参照。
                [errorfile] が指定されない場合、ファイル名として 'errorfile'
                オプションが使われる。デフォルト値については 'errorfile' を参
                照。

(nothing)       上記の 4 つの項目のいずれも無い場合、Vim は新しいバッファの編
                集を開始する。そのバッファは空で、ファイル名を持たない。


起動モードは、"viai" の代わりに別の名前を使うことで変更でき、それはオプション
を指定するのと同じである:
ex       viai -e    Ex モードで起動 (Ex-mode を参照)。          ex
exim     viai -E    改良 Ex モードで起動 (Ex-mode を参照)。     exim
                    (通常はインストールされない)
view     viai -R    読み込み専用モードで起動 (-R を参照)。      view
gviai    viai -g    GUI を起動 (gui を参照)。                   gvim
gex      viai -eg   GUI を Ex モードで起動。                      gex
gview    viai -Rg   GUI を読み込み専用モードで起動。              gview
rviai    viai -Z    "viai" と同様だが、制限モード (-Z を参照)  rvim
rview    viai -RZ   "view" と同様だが、制限モード。               rview
rgviai   viai -gZ   "gviai" と同様だが、制限モード。              rgvim
rgview   viai -RgZ  "gview" と同様だが、制限モード。              rgview
eviai    viai -y    Easy Vim: 'insertmode' を設定 (-y を参照)   evim
eview    viai -yR   読み込み専用モードの "eviai" と同様           eview
viaidiff viai -d    差分モードで起動 diff-mode
gviaidiff viai -gd  差分モードで起動 diff-mode

"viai"、"gviai"、"rviai"、"rgviai"、"eviai"、"viaidiff" および "gviaidiff" だ
けがインストールされる。viai-programs を参照。他の名前および Vim の名前
("vim"、"gvim" など) も同様に動作する。

追加の文字が続いてもよく、それらは無視される。例えば、GUI を起動するために
"gviai-1" とすることもできる。もちろん、その場合はその名前の実行可能ファイルが
必要である。

Unix では、通常 "viai" という名前の実行可能ファイルが 1 つあり、異なる起動名か
らその実行可能ファイルへのリンクがある。システムがリンクをサポートせず、実行可
能ファイルのコピーを複数持ちたくない場合、代わりにエイリアスを使うことができ
る。例えば、C シェルの派生では:
        alias view    viai -R
        alias gviai   viai -g

                                                        startup-options
オプション引数はどの順番で指定してもよい。1 文字のオプションは 1 つのダッシュ
の後ろにまとめることができる。"--" 引数の後ろにオプション引数を置くことはでき
ない。

VMS では、スラッシュが前に付いていない限り、全てのオプション引数は小文字とみな
される。したがって "-R" はリカバリーを意味し、"-/R" は読み込み専用を意味する。

--help                                                  -h --help -?
-?
-h              使用法 (ヘルプ) メッセージを表示して終了する。
                テキストの取り込みについては info-message を参照。

                                                        --version
--version       バージョン情報を表示して終了する。:version コマンドと同じ出
                力である。
                テキストの取り込みについては info-message を参照。

                                                        --noplugin
--noplugin      プラグインの読み込みをスキップする。'loadplugins' オプションを
                オフにする。

                Note -u 引数もプラグインの読み込みを無効にすることがあること
                に注意:
                        引数  読み込み: vimrc ファイル  プラグイン defaults.vim
                        (nothing)            yes        yes       yes
                        -u NONE              no         no        no
                        -u DEFAULTS          no         no        yes
                        -u NORC              no         yes       no
                        --noplugin           yes        no        yes

--startuptime {fname}                                   --startuptime
                起動中に、タイミングメッセージをファイル {fname} に書き込む。
                これは、.vimrc、プラグインの読み込み、および最初のファイルを開
                く間に、どこで時間が費やされているかを調べるために使用できる。
                {fname} が既に存在する場合、新しいメッセージは追記される。
                {+startuptime 機能付きでコンパイルされたときのみ有効}

                                                        --literal
--literal       ファイル名を文字どおりに受け取り、ワイルドカードを展開しない。
                Vim は常にファイル名を文字どおりに受け取る (シェルがワイルド
                カードを展開する) ので、Unix では必要ない。
                全ての名前に適用され、この引数より前に来るものも同様である。

                                                        -+
+[num]          編集される最初のファイルで、カーソルは "num" 行目に置かれる。
                "num" が無い場合、カーソルは最後の行に置かれる。

                                                        -+/
+/{pat}         編集される最初のファイルで、"pat" を含む最初の行にカーソルが置
                かれる (使用可能な検索パターンについては pattern を参照)。検
                索はカーソル位置から開始され、それは最初の行、または viminfo
                から得た最後に使用されたカーソル位置となりうる。最初の行からの
                検索を強制するには "+1 +/pat" を使う。

+{command}                                              -+c -c
-c {command}    {command} は最初のファイルが読み込まれた後 (およびそのファイル
                に対する自動コマンドおよびモードラインが処理された後) に実行さ
                れる。"command" は Ex コマンドとして解釈される。"command" が空
                白を含む場合、それは二重引用符で囲まなければならない (これは使
                用するシェルに依存する)。例:
                        vim  "+set si"  main.c
                        vim  "+find stdio.h"
                        vim  -c "set ff=dos"  -c wq  mine.mak

                Note: Vim コマンドでは "+" または "-c" 引数を 10 個まで使用で
                きる。それらは指定された順番で実行される。"-S" 引数も "-c" 引
                数として数えられる。

--cmd {command}                                         --cmd
                {command} はどの vimrc ファイルを処理するよりも前に実行される。
                それ以外は -c {command} と同様に動作する。"-c" コマンドとは独
                立して、これらのコマンドを 10 個まで使用できる。

                                                        -S
-S {file}       最初のファイルが読み込まれた後に {file} が読み込まれる。これは
                以下と同等のことを行う簡単な方法である:
                        -c "source {file}"
                これは "-c" 引数と混在させることができ、"-c" と同様に繰り返す
                ことができる。10 個という "-c" 引数の制限はここでも適用される。
                {file} は "-" で始めることはできない。

                これを、何らかの作業を行って Vim を終了するスクリプトの実行に
                使用しないこと。エラーメッセージを見ることができない。代わりに
                -u を使うこと。

-S              "-S Session.vim" のように動作する。最後の引数として使われた場
                合、または別の "-" オプションが続く場合のみ。

                                                        -r
-r              リカバリーモード。ファイル名引数が無い場合、既存のスワップファ
                イルの一覧が表示される。ファイル名がある場合、クラッシュした編
                集セッションを復旧するためにスワップファイルが読み込まれる。
                crash-recovery を参照。

                                                        -L
-L              -r と同じ。

                                                        -R
-R              読み込み専用モード。編集される全てのファイルに 'readonly' オプ
                ションが設定される。バッファを編集することはできるが、誤って
                ファイルを上書きすることは防がれる。ビューモードにいることを忘
                れて何らかの変更をした場合、":w!" のように Ex コマンドに感嘆符
                を付けることでファイルを上書きできる。'readonly' オプションは
                ":set noro" でオフにできる (オプションの章 options を参照)。
                その後の編集は読み込み専用モードでは行われない。実行可能ファイ
                ルを "view" として呼び出すと -R 引数と同じ効果がある。
                'updatecount' オプションは 10000 に設定され、スワップファイル
                があまり頻繁には自動更新されないことを意味する。変更を禁止する
                には -M を参照。

                                                        -m
-m              変更を書き込むことが許可されない。'write' オプションがオフにさ
                れるので、ファイルの書き込みは無効になる。ただし、再び書き込み
                を有効にするために 'write' オプションを設定できる。

                                                        -M
-M              変更が許可されない。'modifiable' オプションがオフにされるので、
                変更は許可されない。'write' オプションがオフにされるので、ファ
                イルの書き込みは無効になる。ただし、変更および書き込みを有効に
                するために 'modifiable' および 'write' オプションを設定できる。

                                        -Z restricted-mode E145 E981
-Z              制限モード。外部シェルを利用する全てのコマンドが無効になる。こ
                れには CTRL-Z によるサスペンド、":sh"、フィルタ、system() 関
                数、バッククォート展開および libcall() が含まれる。
                delete()、rename()、mkdir()、job_start()、setenv()
                および環境変数の設定なども禁止される。
                Python、Ruby および Lua などのインターフェイスも、シェルコマン
                ドを実行するために使われうるため、無効になる。Perl は Safe モ
                ジュールを使う。
                Unix では、$SHELL の最後の部分が "nologin" または "false" の場
                合、制限モードが使われる。
                Note それでもユーザーがシェルコマンドを実行する抜け穴を見つけ
                る可能性はあり、難しくされただけであることに注意。

                                                        -g
-g              Vim を GUI モードで起動する。gui を参照。反対については -v
                を参照。

                                                        -v
-v              Ex を Vi モードで起動する。実行可能ファイルが "ex" または
                "gvim" と呼ばれる場合にのみ違いが出る。gvim では、可能な場合、
                GUI は起動されない。

                                                        -e
-e              Vim を Ex モードで起動する。Ex-mode を参照。実行可能ファイル
                が "ex" と呼ばれていない場合にのみ違いが出る。

                                                        -E
-E              Vim を改良 Ex モード gQ で起動する。実行可能ファイルが
                "exim" と呼ばれていない場合にのみ違いが出る。

                                                        -s-ex
-s              サイレントモードまたはバッチモード。Vim が "ex" として起動され
                た場合、または "-e" 引数が前にある場合のみ。それ以外の場合は
                -s を参照。そちらは引数を取るが、この "-s" の使い方では引数
                を取らない。Vim が端末ではなくファイルから Ex コマンドを実行す
                るために使われるときに使用する。ほとんどのプロンプトおよび情報
                メッセージを止める。警告およびエラーメッセージも同様。
                これらのコマンドの出力は (stdout に) 表示される:
                        :print
                        :list
                        :number
                        :set      オプション値を表示するため。
                'verbose' が 0 でない場合、メッセージが表示される (デバッグ用、
                stderr に)。
                'term' および $TERM は使われない。
                Vim が固まったように見える場合、"qa!<Enter>" と入力してみるこ
                と。プロンプトが表示されないので、Vim が何かを入力するのを待っ
                ていることが分からない。
                初期化はスキップされる ("-u" 引数で指定されたものを除く)。
                例:
                        vim -e -s  < thefilter  thefile
                反対に、スクリプトからのエラーを見るには、ファイルを -u フラ
                グで実行する:
                        vim -u thefilter thefile

                                                        -b
-b              バイナリモード。ファイル I/O は行の区切りとして <NL> だけを認
                識する。'expandtab' オプションはオフにされる。'textwidth' オプ
                ションは 0 に設定される。'modeline' はオフにされる。'binary'
                オプションが設定される。これは vimrc/exrc ファイルを読み込んだ
                後、引数リストのファイルを読み込む前に行われる。edit-binary
                も参照。

                                                        -l
-l              Lisp モード。'lisp' および 'showmatch' オプションをオンにする。

                                                        -A
-A              アラビア語モード。'arabic' オプションをオンにする。{+arabic
                機能 (+rightleft を含む) 付きでコンパイルされたときのみ、そ
                うでない場合、Vim はエラーメッセージを出して終了する}

                                                        -F
-F              これはペルシア語モードに使われていたが、それは削除された。
                farsi.txt を参照。

                                                        -H
-H              ヘブライ語モード。'hkmap' および 'rightleft' オプションをオン
                にする。
                {+rightleft 機能付きでコンパイルされたときのみ、そうでない場
                合、Vim はエラーメッセージを出して終了する}

                                                        -V verbose
-V[N]           冗長。'verbose' オプションを [N] に設定する (デフォルト: 10)。
                ":source" された各ファイル、および viminfo ファイルの読み書き
                に対してメッセージが表示される。起動時および終了時に何が起きて
                いるかを調べるために使用できる。
                例:
                        vim -V8 foobar

-V[N]{filename}
                -V と同様で、さらに 'verbosefile' を {filename} に設定する。そ
                の結果、メッセージは表示されず、ファイル {filename} に書き込ま
                れる。{filename} は数字で始まってはならない。
                例:
                        vim -V20vimlog foobar

--log {filename}                                        --log
                ログを開始し、エントリを {filename} に書き込む。
                これは起動中のごく早い段階で ch_logfile({filename}, 'ao') を
                呼ぶのと同様に動作する。
                {+eval および +channel 機能付きのときのみ有効}

                                                        -D
-D              デバッグ。スクリプトから最初のコマンドを実行するときにデバッグ
                モードに入る。debug-mode
                {+eval 機能付きでコンパイルされたときのみ有効}

                                                        -C
-C              互換モード。'compatible' オプションを設定する。.vimrc ファイル
                が存在していても、'compatible' にするためにこれを使用できる。
                何らかのプラグインまたは起動スクリプト中の ":set nocompatible"
                コマンドがこれを上書きし、結局 'nocompatible' になるかもしれな
                いことを覚えておくこと。調べるには、以下を使う:
                        :verbose set compatible?
                いくつかのプラグインは 'compatible' が設定されていると動作しな
                い。このように起動後に設定するとよいかもしれない:
                        vim "+set cp" filename
                compatible-default も参照。

                                                        -N
-N              非互換モード。'compatible' オプションをオフにする。.vimrc ファ
                イルが無いとき、または "-u NONE" を使うときに、'nocompatible'
                にするためにこれを使用できる。
                compatible-default も参照。

                                                        -y easy
-y              イージーモード。evim および eview では暗黙に指定される。
                'insertmode' が設定された状態で起動し、クリック・アンド・タイ
                プのエディタのように振る舞う。これはスクリプト
                $VIMRUNTIME/evim.vim を読み込む。ほとんどのクリック・アンド・
                タイプのエディタのように動作するようにマッピングが設定される。
                evim-keys を参照。使用可能なときは GUI が起動される。

                                                        -n
-n              スワップファイルは使われない。クラッシュ後のリカバリーは不可能
                になる。非常に遅い媒体 (例えばフロッピー) でファイルを閲覧また
                は編集したい場合に便利である。
                ":set updatecount=0" でも同じことができる。'updatecount' オプ
                ションを何らかの値、例えば ":set uc=100" に設定することで、再
                びオンにできる。
                NOTE: -n と -b を組み合わせて -nb にしないこと。それは別の意味
                を持つ: -nb。
                'updatecount' は vimrc ファイルからのコマンドを実行した後、た
                だし GUI 初期化の前に 0 に設定される。したがって、vimrc ファイ
                ル中の 'updatecount' の設定は上書きされるが、gvimrc ファイル中
                の設定は上書きされない。startup を参照。
                ディスクへのアクセスを減らしたいとき (例えばラップトップのため)
                は、"-n" を使わずに、'updatetime' および 'updatecount' を非常
                に大きな数値に設定し、作業を保存したいときに ":preserve" と入
                力すること。こうすることで、クラッシュリカバリーの可能性を保つ
                ことができる。

                                                        -o
-o[N]           N 個のウィンドウを水平分割で開く。[N] が指定されない場合、引数
                として指定された各ファイルに 1 つのウィンドウが開かれる。十分
                な場所が無い場合、最初のいくつかのファイルだけにウィンドウが割
                り当てられる。引数よりウィンドウが多い場合、最後のいくつかの
                ウィンドウは空のファイルを編集することになる。

                                                        -O
-O[N]           N 個のウィンドウを垂直分割で開く。それ以外は -o と同様である。
                -o および -O オプションの両方が指定された場合、コマンドライン
                の最後のものがウィンドウの分割方法を決める。

                                                        -p
-p[N]           N 個のタブページを開く。[N] が指定されない場合、引数として指定
                された各ファイルに 1 つのタブページが開かれる。最大値は
                'tabpagemax' ページで設定される (デフォルト 10)。引数よりタブ
                ページが多い場合、最後のいくつかのタブページは空のファイルを編
                集することになる。tabpage も参照。

                ドに影響する。Vim は使用している端末タイプを判別できるので、こ
                れは通常必要ない。(terminal-info を参照。)

                                                        --not-a-term
--not-a-term    入力および/または出力が端末に接続されていないことをユーザーが

                および 2 秒の遅延が回避される。
                "Reading from stdin..." および "N files to edit" メッセージも
                回避する。

--gui-dialog-file {name}                                --gui-dialog-file

                イルは作成されるか、または追記される。テストのためだけに有用

                る。"-es" を暗黙に指定する: 何も表示されず、Ex コマンドは読み
                込まれず、GUI は起動されない。--servername 引数は無視され、
                サーバーは起動されず、--remote 引数は使用できない。スクリプ
                トは ch_open() およびアドレス "stdio" でチャネルを開く。
                channel-stdio を参照。
                起動コマンドおよびスクリプトが実行された後、Vim はチャネル上の
                メッセージを待ち、チャネルが閉じられると終了する。

-d              vimdiff のように差分モードで起動する。
                {+diff 機能付きでコンパイルされたときのみ有効}

-d {device}     Amiga でのみ、かつ +diff 機能付きでコンパイルされていない場

                                                        -dev
-dev {device}   Amiga でのみ: {device} が編集に使用するために開かれる。
                通常は、ウィンドウの位置およびサイズを設定するためにこれを使う:
                "-d con:x/y/width/height"、例えば "-d con:30/10/600/150"。しか
                し、別のデバイスで編集を開始するためにも使用できる。例えば
                AUX:。

--nofork        GUI: fork しない。-f と同じ。
                                                        -u E282
-u {vimrc}      ファイル {vimrc} が初期化のために読み込まれる。他のほとんどの
                初期化はスキップされる。initialization を参照。

                これは、特別なマッピングおよび設定を使って Vim を特別なモード
                で起動するために使用できる。これを簡単に使えるようにするため
                に、シェルのエイリアスを使用できる。例えば、C シェルの派生では:

                        alias vimc 'vim -u ~/.c_vimrc \!*'
                そして Bash シェルでは:
                        alias vimc='vim -u ~/.c_vimrc'
                自動コマンドを使うことも検討すること。autocommand を参照。

                {vimrc} が "NONE" (全て大文字) と等しいとき、GUI の起動時に
                gvimrc ファイルを読み込むことも含め、ファイルおよび環境変数
                からの全ての初期化がスキップされる。プラグインの読み込みもス
                キップされる。

                {vimrc} が "NORC" (全て大文字) と等しいとき、これは "NONE" と
                同じ効果を持つが、プラグインの読み込みはスキップされない。

                {vimrc} が "DEFAULTS" (全て大文字) と等しいとき、これは "NONE"
                と同じ効果を持つが、defaults.vim スクリプトが読み込まれ、そ
                れによって 'nocompatible' も設定される。--clean も参照。

                DEFAULTS 以外の別の引数で "-u" 引数を使うと、'compatible' オプ
                ションがデフォルトでオンになるという副作用がある。これは予期し
                ない効果をもたらすことがある。'compatible' を参照。

                                                        -U E230
-U {gvimrc}     GUI の起動時に、ファイル {gvimrc} が初期化のために読み込まれ
                る。他の GUI 初期化はスキップされる。{gvimrc} が "NONE" と等し
                いとき、GUI 初期化のためのファイルは一切読み込まれない。
                gui-init

                                                        -i
-i {viminfo}    デフォルトの viminfo ファイルの代わりに、ファイル "viminfo" が
                使われる。名前 "NONE" (全て大文字) が使われた場合、'viminfo'
                が設定されていても、また ":rv" または ":wv" が使われても、
                viminfo ファイルは読み込まれず、書き込まれもしない。
                viminfo-file も参照。

                                                        --clean
--clean         "-u DEFAULTS -U NONE -i NONE" と同様:
                - ファイルおよび環境変数からの初期化はスキップされる
                - 'runtimepath' および 'packpath' は、ホームディレクトリのエン
                  トリを除外するように設定される (-u DEFAULTS では起こらない)。
                - defaults.vim スクリプトが読み込まれ、それは 'nocompatible'
                  を暗に意味する: Vim のデフォルトを使用する
                - gvimrc スクリプトは読み込まれない
                - viminfo ファイルは読み込まれず、書き込まれもしない
                Note 後続の "-u" 引数は "-u DEFAULTS" の効果を上書きすることに
                注意。

                                                        -x
-x              ファイルの読み書きに暗号化を使う。鍵の入力を求められ、それは
                'key' オプションに保存される。その後の全ての書き込みはこの鍵を
                使ってテキストを暗号化する。読み込まれるファイルが暗号化されて
                いるかどうかのチェックがあり、Vim は自動的に鍵を尋ねるので、
                ファイルを読み込むときに '-x' 引数は必要ない。encryption
                {+cryptv 機能付きでコンパイルされたときのみ有効}

                                                        -X
-X              現在のウィンドウタイトルを取得するため、および X クリップボー
                ドを使ってコピー/ペーストするために、X サーバーへの接続を試み
                ない。これにより、端末エミュレータで Vim を実行していて X サー
                バーへの接続が遅いときの長い起動時間が回避される。
                これが影響しているかどうかを調べるには --startuptime を参照。
                Unix または VMS で、+X11 機能付きでコンパイルされているとき
                にのみ違いが出る。それ以外では無視される。
                特定の端末に対してのみ接続を無効にするには、'clipboard' オプ
                ションを参照。
                X11 セッション管理プロトコル (XSMP) ハンドラが組み込まれている
                ときは、-X オプションはその接続も無効にする。それも望ましくな
                い遅延を起こしうるためである。
                それでも後で接続が必要なときは (例えばクライアントサーバーメッ
                セージのため)、serverlist() 関数を呼ぶこと。ただし、これは
                XSMP ハンドラを有効にはしない。

                                                        -Y
-Y              Wayland コンポジタへの接続を試みない。Unix で +wayland 機能
                付きでコンパイルされているときにのみ関係し、それ以外では無視さ
                れる。Note これにより、クリップボードなど、Wayland を使用する
                全ての機能が使用できなくなることに注意。

-s {scriptin}   スクリプトファイル "scriptin" が読み込まれる。ファイル中の文字

                ":source! {scriptin}" でも行える。エディタが終了する前にファイ
                ルの終わりに達した場合、それ以降の文字はキーボードから読み込ま
                れる。Ex モードで起動されていないときにのみ動作する。-s-ex
                を参照。complex-repeat も参照。

                                                        -w_nr
-w {number}
-w{number}      'window' オプションを {number} に設定する。

                                                        -w
-w {scriptout}  入力した全ての文字が、Vim を終了するまでファイル "scriptout"
                に記録される。これは "vim -s" または ":source!" で使用するスク
                リプトファイルを作成したい場合に便利である。"scriptout" ファイ
                ルが既に存在するとき、新しい文字は追記される。complex-repeat
                も参照。{scriptout} は数字で始めることはできない。
                入力したものを人間が読める形式で記録したい場合、ch_logfile()

                --log も参照。

2. Amiga での Vim                                       starting-amiga

Workbench からの Vim の起動                             workbench
---------------------------

Vim はアイコンを 2 回クリックすることで Workbench から起動できる。そのとき、空
のバッファで起動する。

"Project" アイコンを使うことで、1 つ以上のファイルを編集するために Vim を起動
できる。アイコンの "Default Tool" は Vim の実行可能ファイルのフルパス名でなけ
ればならない。".info" ファイルの名前はテキストファイルの名前と同じでなければな
らない。このアイコンを 2 回クリックすることで、Vim はそのファイル名をカレント
ファイル名として起動され、そのファイルは (存在する場合) バッファに読み込まれ
る。アイコンをクリックする間シフトキーを押し、最後のアイコンを 2 回クリックす
ることで、複数のファイルを編集できる。これら全てのアイコンの "Default Tool" は
同じでなければならない。

Workbench から Vim に、ファイル名以外の引数を与えることはできない。

Vim ウィンドウ                                          amiga-window
--------------

Vim は、起動された CLI ウィンドウの中で実行される。Vim が "run" または
"runback" コマンドで起動された場合、または Vim が Workbench から起動された場
合、Vim は自分自身のウィンドウを開く。

技術的な詳細:
        新しいウィンドウを開くために、ちょっとしたトリックが使われる。Vim は通
        常の CLI ウィンドウで実行されていないことを認識するとすぐに、"t:" にス
        クリプトファイルを作成する。このスクリプトファイルには、Vim が起動され
        たときと同じコマンド、および "endcli" コマンドが含まれる。このスクリプ
        トファイルはその後 "newcli" コマンドで実行される (これが動作するには
        "c:run" および "c:newcli" コマンドが必要である)。このスクリプトファイ
        ルは再起動するまで、または削除するまで残る。この方法は ":sh" および
        ":!" コマンドを正しく動作させるために必要である。しかし、Vim が -f オ
        プション (フォアグラウンドモード) で起動されたときは、この方法は使われ
        ない。その理由は、プログラムが -f オプションで Vim を起動するとき、そ
        のプログラムは Vim が終了するのを待つためである。スクリプトのトリック
        では、呼び出したプログラムは Vim がいつ終了するかを知ることができない。
        -f オプションは、同じく編集セッションの終了を待つメールプログラムによっ
        て Vim が起動されるときに使用できる。結果として、-f オプションが使われ
        たときは ":sh" および ":!" コマンドは使用できない。

Vim はウィンドウサイズを自動的に認識し、ウィンドウサイズ変更に反応する。Amiga
DOS 1.3 では、表示の再描画を高速化するために fastfonts プログラム "FF" を使う
ことを勧める。

4. 初期化                                       initialization startup

このセクションは Vim の非 GUI 版についてである。GUI を起動するときの追加の初期
化については gui-fork を参照。

起動時に、Vim は環境変数およびファイルを調べ、それに応じて値を設定する。Vim は
この順番で処理を進める:

1. 'shell' および 'term' オプションを設定する   SHELL COMSPEC TERM
        環境変数 SHELL が存在する場合、それが 'shell' オプションを設定するため
        に使われる。Win32 では、SHELL が設定されていない場合、COMSPEC 変数が使
        われる。
        環境変数 TERM が存在する場合、それが 'term' オプションを設定するために
        使われる。ただし、GUI を起動するとき (以下のステップ 8)、'term' は後で
        変更される。

2. 引数を処理する
        Vim を起動したコマンドのオプションおよびファイル名が調べられる。
        -V 引数は、次に何が起こるかを表示またはログに記録するために使用でき、
        初期化のデバッグに便利である。
        --cmd 引数が実行される。
        全てのファイルに対してバッファが作成される (ただしまだ読み込まれない)。

3. 環境変数および/またはファイルから Ex コマンドを実行する
        環境変数は 1 つの Ex コマンドラインとして読み込まれ、複数のコマンドは
        '|' または "<NL>" で区切らなければならない。
                                                                vimrc exrc
        初期化コマンドを含むファイルは "vimrc" ファイルと呼ばれる。vimrc ファ
        イルの各行は Ex コマンドラインとして実行される。それは "exrc" ファイル
        と呼ばれることもある。それらは同じ種類のファイルであるが、"exrc" は Vi
        が常に使っていたもので、"vimrc" は Vim 特有の名前である。vimrc-intro
        も参照。

        個人用の初期化のための場所:
                Unix            $HOME/.vimrc, $HOME/.vim/vimrc
                                または $XDG_CONFIG_HOME/vim/vimrc
                MS-Windows      $HOME/_vimrc, $HOME/vimfiles/vimrc
                                または $VIM/_vimrc
                Amiga           s:.vimrc, home:.vimrc, home:vimfiles:vimrc
                                または $VIM/.vimrc
                Haiku           $HOME/config/settings/vim/vimrc
        ViAI 独自のユーザー設定が存在するときは (viai-config を参照)、Vim の
        ファイルの代わりにこれらが使われる:
                Unix            $HOME/.viairc, $HOME/.viai/vimrc
                                または $XDG_CONFIG_HOME/viai/vimrc
                MS-Windows      $HOME/_viairc, $HOME/viaifiles/vimrc
                                または $VIM/_vimrc

        ファイルは上記で指定された順番で検索され、最初に見つかったものだけが読
        み込まれる。

        推奨: Vim の全ての設定を $HOME/.vim/ ディレクトリ (MS-Windows では
        $HOME/vimfiles/) に置くこと。そうすれば、別のシステムに簡単にコピーで
        きる。ViAI 独自のユーザー設定では、$HOME/.viai/ (MS-Windows では
        $HOME/viaifiles/) を使うこと。

        Vim が "-u filename" で起動された場合、ファイル "filename" が使われる。
        4. までの以下の全ての初期化はスキップされる。$MYVIMRC および
        $MYVIMDIR は設定されない (ただし、'rtp' が更新された場合、
        $MYVIMDIR は設定される)。
        "vim -u NORC" を使うと、ファイルを読み込まずにこれらの初期化をスキップ
        できる。"vim -u NONE" はプラグインの読み込みもスキップする。-u

        Vim が Ex モードで "-s" 引数付きで起動された場合、4. までの以下の全て
        の初期化はスキップされる。"-u" オプションだけが解釈される。

        このステップが終了した後、v:vim_did_init 変数が 1 に設定される。

                                                        evim.vim
     a. Vim が evim または eview として、または -y 引数付きで起動された
        場合、スクリプト $VIMRUNTIME/evim.vim が読み込まれる。
                                                        system-vimrc
     b. Unix、MS-Windows、VMS、Macintosh および Amiga では、システムの vimrc
        ファイルが初期化のために読み込まれる。このファイルのパスは ":version"
        コマンドで表示される。ほとんどの場合 "$VIM/vimrc" である。Note
        'compatible' の自動的なオフは後でしか行われないため、このファイルは常
        に 'compatible' モードで読み込まれることに注意。望む場合、":set nocp"
        コマンドを追加すること。Macintosh では $VIMRUNTIME/macmap.vim が読み込
        まれる。

                        VIMINIT .vimrc _vimrc EXINIT .exrc _exrc
                        $MYVIMRC $MYVIMDIR
     c. 初期化のために 5 つの場所が検索される。最初に存在したものが使われ、他
        は無視される。$MYVIMRC 環境変数は、VIMINIT を使用したときに
        $MYVIMRC が既に設定されていない限り、最初に見つかったファイルに設定
        される。$MYVIMDIR 環境変数は個人用の 'rtp' ディレクトリに設定される
        が、そのディレクトリが実際に存在するかどうかは検証されない。
        I   環境変数 VIMINIT (compatible-default も参照) (*)
            $VIMINIT の値が Ex コマンドラインとして使われる。
        II  ユーザーの vimrc ファイル:
                    "$HOME/.vimrc"                (Unix 用) (*)
                    "$HOME/.vim/vimrc"            (Unix 用) (*)
                    "$XDG_CONFIG_HOME/vim/vimrc"  (Unix 用) (*)
                    "s:.vimrc"                    (Amiga 用) (*)
                    "home:.vimrc"                 (Amiga 用) (*)
                    "home:vimfiles:vimrc"         (Amiga 用) (*)
                    "$VIM/.vimrc"                 (Amiga 用) (*)
                    "$HOME/_vimrc"                (Win32 用) (*)
                    "$HOME/vimfiles/vimrc"        (Win32 用) (*)
                    "$VIM/_vimrc"                 (Win32 用) (*)
                    "$HOME/config/settings/vim/vimrc"   (Haiku 用) (*)

                Note: Unix および Amiga では、".vimrc" が存在しないとき、
                MS-DOS 互換のファイルシステムが使われている場合に備えて、
                "_vimrc" も試される。MS-Windows では、長いファイル名が使われて
                いる場合に備えて、"_vimrc" の後に ".vimrc" がチェックされる。
                Note: Win32 では、"$HOME" が最初にチェックされる。そこで
                "_vimrc" または ".vimrc" が見つからない場合、"$VIM" が試され
                る。$VIM が設定されていないときについては $VIM を参照。
                Note: ViAI 独自のユーザー設定が存在するときは (viai-config
                を参照)、Vim のファイルの代わりにこれらが使われる:
                            "$HOME/.viairc"               (Unix 用) (*)
                            "$HOME/.viai/vimrc"           (Unix 用) (*)
                            "$XDG_CONFIG_HOME/viai/vimrc" (Unix 用) (*)
                            "$HOME/_viairc"               (Win32 用) (*)
                            "$HOME/viaifiles/vimrc"       (Win32 用) (*)
                            "$VIM/_vimrc"                 (Win32 用) (*)
        III 環境変数 EXINIT。
            $EXINIT の値が Ex コマンドラインとして使われる。
        IV  ユーザーの exrc ファイル。ユーザーの vimrc ファイルと同じだが、
            "vimrc" が "exrc" に置き換えられる。ただし、システムに応じて
            ".exrc" および "_exrc" のうち 1 つだけが使われる。そして (*) は付
            かない!
        V   デフォルトの vimrc ファイル、$VIMRUNTIME/defaults.vim。これはオプ
            ション値を設定し、"syntax on" および "filetype on" コマンドを持つ。
            これはほとんどの新しいユーザーが望むものである。defaults.vim を
            参照。

     d. 'exrc' オプションがオンの場合 (これはデフォルトではない)、カレントディ
        レクトリで 3 つのファイルが検索される。最初に存在したものが使われ、他
        は無視される。
        -  ファイル ".vimrc" (Unix、Amiga 用) (*)
                    "_vimrc" (Win32 用) (*)
        -  ファイル "_vimrc" (Unix、Amiga 用) (*)
                    ".vimrc" (Win32 用) (*)
        -  ファイル ".exrc"  (Unix、Amiga 用)
                    "_exrc"  (Win32 用)

     (*) このファイルまたは環境変数を使うと、'compatible' がデフォルトでオフに
         なる。compatible-default を参照。

     Note: mzscheme インターフェイスを使っているときは、vimrc ファイルを読み
     込んだ後に初期化される。後で 'mzschemedll' を変更しても効果は無い。

4. プラグインスクリプトを読み込む。                             load-plugins
        これは以下のコマンドと同じことを行う:
                :runtime! plugin/**/*.vim
        その結果、'runtimepath' オプションの全てのディレクトリで "plugin" サブ
        ディレクトリが検索され、".vim" で終わる全てのファイルが (ディレクトリ
        ごとにアルファベット順で) 読み込まれる。サブディレクトリ内のものも同様
        である。
        ただし、'runtimepath' の中で "after" で終わるディレクトリはここではス
        キップされ、パッケージの後にのみ読み込まれる。以下を参照。
        以下のときはプラグインの読み込みは行われない:
        - vimrc ファイルで 'loadplugins' オプションがオフにされた。
        - --noplugin コマンドライン引数が使われた。
        - --clean コマンドライン引数が使われた。
        - "-u NONE" コマンドライン引数が使われた -u。
        - Vim が +eval 機能無しでコンパイルされたとき。
        Note "-c 'set noloadplugins'" を使っても動作しないことに注意。コマンド
        ラインからのコマンドはまだ実行されていないためである。
        "--cmd 'set noloadplugins'" または "--cmd 'set loadplugins'" を使うこ
        とができる --cmd。

        パッケージが読み込まれる。これらは上記と同様のプラグインであるが、
        'packpath' の各エントリの "start" ディレクトリで見つかったものである。
        見つかった全てのプラグインディレクトリは 'runtimepath' に追加され、そ
        の後プラグインが読み込まれる。packages を参照。

        プラグインスクリプトが上記と同様に読み込まれるが、今度は "after" で終
        わるディレクトリだけが使われる。Note パッケージが見つかった場合、
        'runtimepath' は変更されているが、それによって "after" で終わるディレ
        クトリが追加されることはないはずであることに注意。

5. 'shellpipe' および 'shellredir' を設定する
        'shellpipe' および 'shellredir' オプションは、前に設定されていない限
        り、'shell' オプション値に応じて設定される。
        これは、自分で設定していない限り、Vim が 'shellpipe' および
        'shellredir' の値を判断することを意味する。

6. "-n" コマンド引数が使われた場合、'updatecount' を 0 に設定する。

7. バイナリオプションを設定する
        "-b" フラグが Vim に指定された場合、ここでバイナリ編集のためのオプショ
        ンが設定される。-b を参照。

8. GUI 初期化を行う
        "gvim" を起動するときのみ、GUI 初期化が行われる。gui-init を参照。

9. viminfo ファイルを読み込む
        'viminfo' オプションが空でない場合、viminfo ファイルが読み込まれる。
        viminfo-file を参照。

10. quickfix ファイルを読み込む
        "-q" フラグが Vim に指定された場合、quickfix ファイルが読み込まれる。
        これに失敗した場合、Vim は終了する。

11. 全てのウィンドウを開く
        -o フラグが指定されたときは、ウィンドウが開かれる (ただしまだ表示さ
        れない)。
        -p フラグが指定されたときは、タブページが作成される (ただしまだ表示
        されない)。
        画面を切り替えるときは、ここで行われる。再描画が始まる。
        "-q" フラグが Vim に指定された場合、最初のエラーにジャンプする。全ての
        ウィンドウのバッファが、BufAdd 自動コマンドを発生させずに読み込まれ
        る。

12. 起動コマンドを実行する
        "-t" フラグが Vim に指定された場合、タグにジャンプする。
        -c および +cmd 引数で指定されたコマンドが実行される。
        'insertmode' オプションが設定されている場合、挿入モードに入る。
        起動中フラグがオフにされ、has("vim_starting") はこれ以降 0 を返す。
        v:vim_did_enter 変数が 1 に設定される。
        VimEnter 自動コマンドが実行される。

$MYVIMRC または $MYGVIMRC 環境変数は、最初に見つかった vimrc および/または
gvimrc ファイルに設定され、一方 $MYVIMDIR はユーザーの個人用ランタイムディレ
クトリ 'rtp' (通常は 'runtimepath' の最初のエントリ) に設定される。'rtp' が変
更された場合、$MYVIMDIR は更新される。
Note: これらの環境変数はシンボリックリンクを解決するが、'rtp' は解決しない。


初期化の使用についてのいくつかのヒント

標準設定:
全ての編集セッションに対するデフォルトの設定およびマッピングを設定するために、
vimrc ファイルを作成する。それを 3b. で見つかるような場所に置くこと:
        ~/.vimrc        (Unix)
        s:.vimrc        (Amiga)
        $VIM\_vimrc     (Win32)
        ~/config/settings/vim/vimrc (Haiku)

Note vimrc ファイルを作成すると、'compatible' オプションがデフォルトでオフにな
ることに注意。compatible-default を参照。

ローカル設定:
特定のディレクトリを編集するためだけに必要な全てのコマンドを vimrc ファイルに
書き、そのディレクトリに ".vimrc" (Win32 では "_vimrc") という名前で置く。NOTE:
Vim がこれらの特別なファイルを探すようにするには、オプション 'exrc' をオンにし
なければならない。trojan-horse も参照。

システム設定:
これは、複数のユーザーがいる Unix システムを管理していて、全てのユーザーに対し
てデフォルトを設定したい場合にのみ当てはまる。デフォルトの設定およびマッピング
のためのコマンドを含む vimrc ファイルを作成し、":version" コマンドで示される場
所に置くこと。


Vim の現在の状態をファイルに保存する

オプション値を変更したとき、またはマッピングを作成したときはいつでも、後で使う
ためにそれらを vimrc ファイルに保存したくなるかもしれない。設定の現在の状態を
ファイルに保存することについては save-settings を参照。


Vi ユーザーのためのセットアップ問題の回避

Vi は変数 EXINIT およびファイル "~/.exrc" を使う。そのため、Vi に干渉したくな
い場合、代わりに変数 VIMINIT およびファイル "vimrc" を使うこと。


Amiga の環境変数

Amiga では、2 種類の環境変数が存在する。DOS 1.3 (またはそれ以降) の setenv コ
マンドで設定されたものは認識される。AmigaDos 1.3 のマニュアルを参照。古い Manx
の Set コマンド (バージョン 5.0 より前) で設定された環境変数は認識されない。


MS-Windows の行区切り

MS-Windows では、Vim は全ての vimrc ファイルが行区切りとして <CR><NL> のペアを
持つとみなす。<NL> だけのファイルがあり、":map xx yy^M" のような行がある場合、
これは問題を起こす。末尾の ^M は無視される。


Vi 互換のデフォルト値
                                                     compatible-default
Vim が起動するとき、'compatible' オプションはオンである。これは Vim が初期化を
開始するときに使われる。しかし、以下のことが起きるとすぐに:
- ユーザーの vimrc ファイルが見つかる、または
- カレントディレクトリに vimrc ファイルが見つかる、または
- "VIMINIT" 環境変数が設定されている、または
- "-N" コマンドライン引数が指定される、または
- "--clean" コマンドライン引数が指定される、または
- defaults.vim スクリプトが読み込まれる、または
- gvimrc ファイルが見つかった、
そのとき、オプションは 'nocompatible' に設定される。

Note システム全体の vimrc ファイルが見つかったときは、これは起こらないことに注
意。

これには、他のオプションを設定またはオフにする副作用がある ('compatible' を参
照)。ただし、設定もオフもされていないオプションだけが変更される。これは、Vim
の起動時に 'compatible' の値がこの値だった場合と同じ効果を持つ。

'compatible' はオフにされず、defaults.vim は読み込まれない:
- Vim が -u コマンドライン引数付きで起動されたとき、特に "-u NONE" の場合、
  または
- -C コマンドライン引数付きで起動されたとき、または
- 実行可能ファイルの名前が "ex" で終わるとき。(これは、"ex" として起動されたと
  きに Vim を "ex" のように振る舞わせるために行われている)

しかし、.vimrc ファイルが見つかった時点で 'compatible' を設定またはオフにする
ことには副作用がある: マッピングは出現した時点で解釈される。これは "<CR>" のよ
うなものを使うときに違いを生む。マッピングが 'compatible' の特定の値に依存する
場合、マッピングを定義する前にそれを設定またはオフにすること。


.vimrc ファイルが無い場合のデフォルト
                                                        defaults.vim E1187
Vim が通常どおり起動され、ユーザーの vimrc ファイルが見つからない場合、
$VIMRUNTIME/defaults.vim スクリプトが読み込まれる。これは 'compatible' をオフ
にし、構文ハイライトおよびその他いくつかのものをオンにする。詳細はスクリプトを
参照。NOTE: これは Vim 8.0 から行われており、Vim 7.4 では行われない。(正確には
パッチ 7.4.2111 で追加された)。

これは新しい Vim ユーザーにとってうまく機能するはずである。自分の .vimrc を作
成する場合、先頭近くのどこかにこれらの行を追加することを推奨する:
        unlet! skip_defaults_vim
        source $VIMRUNTIME/defaults.vim
その後、Vim は .vimrc を持つ前のように動作する。
$VIMRUNTIME/vimrc_example.vim を .vimrc にコピーするのも、これを行う別の方法で
ある。あるいは、defaults.vim を .vimrc にコピーして変更することもできる (ただ
し、その場合は defaults.vim が変更されたときに更新を得られない)。

デフォルトのいくつかが気に入らない場合、それでも defaults.vim を読み込み、個々
の設定を元に戻すことができる。各項目を元に戻す方法のヒントについては
defaults.vim ファイルを参照。
                                                skip_defaults_vim
システム全体の vimrc を使っていて、defaults.vim に設定を変更させたくない場合、
"skip_defaults_vim" 変数を設定すること。これが設定されていて、.vimrc から
defaults.vim を読み込みたい場合、上記の例のように、まず skip_defaults_vim を
unlet すること。


                                        xdg-base-dir $XDG_CONFIG_HOME
XDG Base Directory Specification

XDG Base Directory Specification は、アプリケーションが使用する設定ファイルの
標準的な場所を定義することを目的としている。これは主に、ユーザーのホームディレ
クトリに全てを放り込むという従来の振る舞いを防ぐために行われる。
仕様はオンラインの https://specifications.freedesktop.org/basedir-spec/latest/
で見ることができる

この標準設定ディレクトリの場所は、環境変数を使ってユーザーが設定できるが、それ
らの変数が設定されていない場合に備えてフォールバックも提供すべきである。

これはそれらのディレクトリの網羅的な一覧ではない:
  環境変数              デフォルトの場所        説明
  $XDG_CACHE_HOME     $HOME/.cache            一時的なデータファイル
  $XDG_CONFIG_HOME    $HOME/.config           設定ファイル
  $XDG_DATA_HOME      $HOME/.local/share      永続的なデータファイル
  $XDG_STATE_HOME     $HOME/.local/state      状態データファイル

                                                        xdg.vim
Vim 自体は $XDG_CONFIG_HOME ディレクトリだけを使う。他の XDG ディレクトリのサ
ポートは "$VIMRUNTIME/xdg.vim" スクリプトによって提供される。
Note: xdg.vim は $XDG_CONFIG_HOME/vim ディレクトリ (またはそのデフォルトの
フォールバック) が存在する場合にのみ有効である。デフォルトでは、'viminfofile'
オプションだけを設定する。他のオプションの設定はコメントアウトされている。それ
らを有効にする方法の詳細はスクリプトを参照。

                                                        xdg-vimrc
Unix システムでは、Vim は設定のために $XDG_CONFIG_HOME/vim/vimrc を見る
(vimrc を参照) が、$HOME または $HOME/.vim に他の初期化ファイルが見つか
らない場合にのみそれを読み込む (これにより、この機能は後方互換となる)。ただし、
$XDG_CONFIG_HOME/vim/ ディレクトリを使うように移行したい場合、~/.vimrc お
よび ~/.vim/vimrc ファイルを移動しなければならない。ViAI 独自のユーザー設定
では (viai-config を参照)、同じことが $XDG_CONFIG_HOME/viai/vimrc、
~/.viairc および ~/.viai/vimrc に当てはまる。

                                                        xdg-runtime
xdg-vimrc が使われるとき、'runtimepath' および 'packpath' オプションは
xdg-base-dir に従うように変更される:

  "$XDG_CONFIG_HOME/vim,$VIM/vimfiles,$VIMRUNTIME,$VIM/vimfiles/after,
   $XDG_CONFIG_HOME/vim/after"

ViAI 独自のユーザー設定では、"$XDG_CONFIG_HOME/vim" の代わりに
"$XDG_CONFIG_HOME/viai" が使われる。

トロイの木馬の回避
                                                        trojan-horse
カレントディレクトリの "vimrc" または "exrc" ファイルを読み込んでいる間、
'secure' オプションを設定することで、セキュリティ上の理由からいくつかのコマン
ドを無効にできる。これはタグファイルからコマンドを実行するときは常に行われる。
そうしないと、誰か他の人が作成した、たちの悪いコマンドを含む vimrc またはタグ
ファイルを誤って使ってしまう可能性がある。無効にされるコマンドは、シェルを起動
するもの、ファイルに書き込むもの、および ":autocmd" である。":map" コマンドは
エコーされるので、どのキーがマップされているかを見ることができる。
        ローカルの vimrc ファイル中の全てのコマンドを Vim に実行させたい場合、
EXINIT または VIMINIT 環境変数、またはグローバルな "exrc" または "vimrc" ファ
イルで 'secure' オプションをオフにできる。これは、明らかな理由により、カレント
ディレクトリの "vimrc" または "exrc" では不可能である。
        Unix システムでは、これはあなたが vimrc ファイルの所有者でない場合にの
み起こる。警告: vimrc または exrc ファイルを含むアーカイブを展開した場合、その
ファイルはあなたの所有になる。セキュリティ保護は受けられない。そのディレクトリ
で Vim を起動する前に vimrc ファイルをチェックするか、または 'exrc' オプション
をオフにすること。一部の Unix システムでは、ユーザーがファイルに対して "chown"
を行うことができる。これにより、他のユーザーがたちの悪い vimrc を作成して、あ
なたを所有者にすることが可能になる。注意すること!
        タグ検索コマンドを使うとき、検索コマンド (タグファイルの行の最後の部分)
の実行は常にセキュアモードで行われる。これはカレントディレクトリの vimrc/exrc
からコマンドを実行するのとまったく同様に動作する。


Vim の起動が遅い場合
                                                        slow-start
Vim の起動に長い時間がかかる場合、何が起きているかを調べるために
--startuptime 引数を使うこと。よくある原因がいくつかある:
- Unix 版が GUI および/または X11 付きでコンパイルされている場合 (":version"
  の出力で "+GUI" および "+X11" をチェックすること)、共有ライブラリを読み込み、
  X11 サーバーに接続する必要があるかもしれない。GUI および X11 を無効にしたバー
  ジョンをコンパイルしてみること。これにより実行可能ファイルも小さくなるはずで
  ある。
  端末で実行しているときに X サーバーへの接続を回避するには、-X コマンドライ
  ン引数を使うこと。
- "viminfo" を有効にしている場合、viminfo ファイルの読み込みに時間がかかること
  がある。viminfo を一時的に無効にすることで、これが問題かどうかを調べることが
  できる (Vim の引数 "-i NONE" を使う、-i)。":set viminfo='20,<50,s10" でレ
  ジスタに保存される行数を減らしてみること。viminfo-file。


紹介メッセージ
                                                        :intro
Vim がファイル名無しで起動したとき、(Vim が何であるかを知らない人のために) 紹
介メッセージが表示される。これは何らかの方法で画面が再描画されるとすぐに消え
る。メッセージを再び見るには、":intro" コマンドを使うこと (十分な場所が無い場
合、その一部だけが表示される)。
   起動時の紹介メッセージを避けるには、'shortmess' に 'I' フラグを追加するこ
と。

                                                        info-message
--help および --version 引数は、Vim にメッセージを出力させてから終了させ
る。通常、メッセージは stdout に送られるので、以下でファイルにリダイレクトでき
る:

        vim --help >file

Vim の中からは:

        :read !vim --help

gvim を使っているとき、gvim はデスクトップから起動されたかもしれず、メッセージ
を表示する端末が無いことを検出する。これは stdout および stderr の両方が tty
でないときに検出される。これは上記の例で使われている ":read" コマンドを壊す。
再び動作させるには、'shellredir' をデフォルトの ">&" ではなく ">" に設定するこ
と:

        :set shellredir=>
        :read !gvim --help

ただし、gvim が stdout をまったく使わないシステムでは、これはやはり動作しない。

5. $VIM と $VIMRUNTIME
                                                                $VIM
環境変数 "$VIM" は、ユーザーの起動スクリプト ".vimrc" など、Vim のさまざまな
ユーザーファイルの場所を特定するために使われる。これはシステムに依存する。
startup を参照。

全てのユーザーが $VIM 環境変数を設定する必要が無いように、Vim はこの順番で
$VIM の値を取得しようとする:
1. $VIM 環境変数で定義された値。Vim にサポートファイルを特定のディレクトリで探
   させるために、これを使うことができる。例:
        setenv VIM /home/paul/vim
2. 'helpfile' のパスが使われる。ただし、それも何らかの環境変数を含んでいない限
   り (デフォルトは "$VIMRUNTIME/doc/help.txt": 鶏と卵の問題)。ファイル名
   ("help.txt" またはその他) は取り除かれる。その後、末尾のディレクトリ名がこ
   の順番で取り除かれる: "doc"、"runtime" および "viai{version}" (例えば
   "viai10")。
3. Win32 では、Vim は実行可能ファイルのディレクトリ名を使おうとする。それが
   "/src" で終わる場合、それは取り除かれる。これは、.zip ファイルをどこかのディ
   レクトリに展開し、vim の実行可能ファイルを見つけるように検索パスを調整した
   場合に便利である。末尾のディレクトリ名がこの順番で取り除かれる: "runtime"
   および "viai{version}" (例えば "viai10")。
4. Unix では、コンパイル時に定義されたインストールディレクトリが使われる
   (":version" の出力を参照)。

Vim は一度これを行うと、$VIM 環境変数を設定する。後でそれを変更するには、この
ように ":let" コマンドを使う:
        :let $VIM = "/home/paul/vim/"

                                                                $VIMRUNTIME
環境変数 "$VIMRUNTIME" は、オンラインドキュメントおよび構文ハイライトに使われ
るファイルなど、さまざまなサポートファイルの場所を特定するために使われる。例え
ば、メインのヘルプファイルは通常 "$VIMRUNTIME/doc/help.txt" である。
通常は $VIMRUNTIME を自分で設定せず、Vim に判断させる。これが $VIMRUNTIME の値
を見つけるために使われる順番である:
1. 環境変数 $VIMRUNTIME が設定されている場合、それが使われる。ランタイムファイ
   ルが通常とは異なる場所にあるときに、これを使うことができる。
2. "$VIM/viai{version}" が存在する場合、それが使われる。{version} は ViAI の
   バージョン番号で、'-' または '.' を含まない。例: "$VIM/viai10"。これが
   $VIMRUNTIME の通常の値である。
3. "$VIM/runtime" が存在する場合、それが使われる。
4. $VIM の値が使われる。これは古いバージョンとの後方互換性のためである。
5. 'helpfile' オプションが設定されていて、'$' を含まないとき、その値が末尾から
   "doc/help.txt" を取り除いて使われる。

Unix では、$VIMRUNTIME のコンパイル時に組み込まれたデフォルトがあるとき
(":version" の出力をチェックすること)、ステップ 2、3 および 4 はスキップされ、
コンパイル時に組み込まれたデフォルトがステップ 5 の後に使われる。これは、コン
パイル時に組み込まれたデフォルトが $VIM の値を上書きすることを意味する。これは
$VIM が "/etc" で、ランタイムファイルが "/usr/share/viai/viai10" にある場合に
便利である。

Vim は一度これを行うと、$VIMRUNTIME 環境変数を設定する。後でそれを変更するに
は、このように ":let" コマンドを使う:
        :let $VIMRUNTIME = "/home/piet/viai/viai10"

シェルで $VIMRUNTIME の値が必要な場合 (例えば、ヘルプファイルを grep するスク
リプトのため)、これを使うことができるかもしれない:

        VIMRUNTIME=$(vim -es '+put=$VIMRUNTIME|print|quit!')

$VIMRUNTIME を空の値に設定しないこと。いくつかのものが動作しなくなるかもしれな
い。

6. サスペンド                                           suspend

                                        iconize iconise CTRL-Z v_CTRL-Z
CTRL-Z                  ":stop" のように、Vim をサスペンドする。
                        ノーマルモードおよびビジュアルモードで動作する。挿入
                        モードおよびコマンドラインモードでは、CTRL-Z は通常の
                        文字として挿入される。ビジュアルモードでは、Vim はサス
                        ペンドする前にノーマルモードに戻る。
                        Note: CTRL-Z が変更を undo する場合は mswin.vim を参
                        照。


:sus[pend][!]   または                  :sus :suspend :st :stop
:st[op][!]              Vim をサスペンドする。
                        '!' が指定されず、'autowrite' が設定されている場合、変
                        更があり、ファイル名を持つ全てのバッファが書き出され
                        る。'!' が指定された場合、または 'autowrite' が設定さ
                        れていない場合、変更されたバッファは書き込まれない。後
                        で Vim をフォアグラウンドに戻すことを忘れないこと!

GUI では、サスペンドは gvim をアイコン化することとして実装されている。
MS-Windows では、gvim は最小化される。

多くの Unix システムでは、CTRL-Z で Vim をサスペンドすることができる。これは
ノーマルモードおよびビジュアルモードでのみ可能である (次の章、vim-modes を参
照)。Vim を再びフォアグラウンドジョブにした場合、Vim は再開する。他のシステム
では、CTRL-Z は新しいシェルを起動する。これは ":sh" コマンドと同じである。シェ
ルから抜けた場合、Vim は再開する。

X Window System 環境では、Vim がサスペンドするときにセレクションは放棄される。
これは、それを別のアプリケーションに貼り付けられないことを意味する (Vim はス
リープしようとしているので、セレクションを取得しようとするとプログラムが固まっ
てしまう)。

7. 終了                                                 exiting

Vim を終了するにはいくつかの方法がある:
- :quit で最後のウィンドウを閉じる。変更が無いときのみ。
- :quit! で最後のウィンドウを閉じる。変更があるときも。
- :qall で全てのウィンドウを閉じる。変更が無いときのみ。
- :qall! で全てのウィンドウを閉じる。変更があるときも。
- :cquit を使う。変更があるときも。

:cquit を使ったとき、またはエラーメッセージがあったとき、Vim は終了コード 1
で終了する。エラーは :silent! を使うか、または :catch で回避できる。

8. 設定の保存                                           save-settings

ほとんどの場合、vimrc ファイルは手で編集するだろう。これにより最大の柔軟性が得
られる。vimrc ファイルを自動的に生成するコマンドがいくつかある。これらのファイ
ルをそのまま使うか、または別の vimrc ファイルに含めるために行をコピー/ペースト
することができる。

                                                        :mk :mkexrc
:mk[exrc] [file]        現在のキーマッピングおよび変更されたオプションを [file]
                        (デフォルトはカレントディレクトリの ".exrc") に書き込
                        む。ただし、それが既に存在しない限り。

:mk[exrc]! [file]       常に現在のキーマッピングおよび変更されたオプションを
                        [file] (デフォルトはカレントディレクトリの ".exrc") に
                        書き込む。

                                                :mkv :mkvi :mkvimrc
:mkv[imrc][!] [file]    ":mkexrc" と同様だが、デフォルトはカレントディレクトリ
                        の ".vimrc" である。":version" コマンドもファイルに書
                        き込まれる。

これらのコマンドは、それらのコマンドが実行されたときに現在のキーマッピングおよ
びオプションが同じ値に設定されるように、":map" および ":set" コマンドをファイ
ルに書き込む。オプション 'columns'、'endofline'、'fileformat'、'key'、'lines'、
'modified'、'scroll'、'term'、'textmode'、'ttyfast' および 'ttymouse' は、端末
またはファイルに依存するので含まれない。Note オプション 'binary'、'paste' およ
び 'readonly' は含まれることに注意。これは常に望むものとは限らない。

マッピングで特殊キーが使われているときは、マッピングが誤って解釈されるのを避け
るために、'cpoptions' オプションが一時的に Vim のデフォルトに設定される。これ
によりファイルは Vi と互換性が無くなるが、異なる端末で使えることは保証される。

グローバルなマッピングだけが保存され、バッファにローカルなマッピングは保存され
ない。

一般的な方法は、デフォルトの ".vimrc" ファイルを使い、":map" および ":set" コ
マンドでいくつかの変更を加え、変更されたファイルを書き出すことである。まず
":source ~piet/.vimrc.Cprogs" のようなコマンドでデフォルトの ".vimrc" を読み込
み、設定を変更し、それから ":mkvimrc!" でカレントディレクトリに保存する。この
ファイルをデフォルトの .vimrc にしたい場合、それをホームディレクトリ (Unix)、s:
(Amiga) または $VIM ディレクトリ (MS-Windows) に移動すること。自動コマンド
autocommand および/またはモードライン modeline を使うこともできる。

                                                vimrc-option-example
vimrc に 1 つのオプション設定だけを追加したい場合、これらの手順を使うことがで
きる:
1. Vim で vimrc ファイルを編集する。
2. ちょうどよくなるまでオプションを試す。例えば、'guifont' のさまざまな値を試
   してみる。
3. 値を入力するために式レジスタ '=' を使って、オプション値を設定する行を追加す
   る。例えば、'guifont' オプションの場合:
   o:set guifont=<C-R>=&guifont<CR><Esc>
   [<C-R> は CTRL-R、<CR> はリターン、<Esc> はエスケープキー]
   特殊文字、特に空白はエスケープする必要がある。

Note .vimrc ファイルを作成すると、これが 'compatible' オプションに影響しうるこ
とに注意。それにはいくつかの副作用がある。'compatible' を参照。
":mkvimrc"、":mkexrc" および ":mksession" は、これらの副作用のために、まず
'compatible' オプションを設定またはオフにするコマンドを出力ファイルに書き込む。

9. ビューとセッション                                   views-sessions

これはユーザーマニュアルの 21.4 および 21.5 節で紹介されている。

                                                View view-file
ビューは、1 つのウィンドウに適用される設定の集まりである。ビューを保存してお
き、後でそれを復元するとき、テキストは同じように表示される。このウィンドウのオ
プションおよびマッピングも復元されるので、ビューを保存したときのように編集を続
けることができる。

                                                Session session-file
セッションは、全てのウィンドウのビューに加えて、グローバルな設定を保持する。
セッションを保存しておき、後でそれを復元するとき、ウィンドウレイアウトは同じに
見える。セッションを使って、異なるプロジェクト間を素早く切り替え、そのプロジェ
クトで最後に作業していたファイルを自動的に読み込むことができる。

ビューおよびセッションは viminfo ファイルへの素晴らしい追加機能である。viminfo
ファイルは全てのビューおよびセッションの情報をまとめて記憶するために使われる
viminfo-file。

-S 引数を使って、以前に保存したビューまたはセッションで素早く編集を開始でき
る:
        vim -S Session.vim

これら全ては {+mksession 機能付きでコンパイルされたときのみ有効}。

                                                        :mks :mksession
:mks[ession][!] [file]  現在の編集セッションを復元する Vim script を書き出す。
                        [!] が含まれているとき、既存のファイルは上書きされる。
                        [file] が省略されたとき、"Session.vim" が使われる。

":mksession" の出力は ":mkvimrc" と同様だが、追加のコマンドがファイルに加えら
れる。どれが加えられるかは 'sessionoptions' オプションに依存する。生成された
ファイルは、":source" コマンドで実行されると:
1. 'sessionoptions' に "options" が含まれている場合、グローバルなマッピングお
   よびオプションを復元する。スクリプトローカルなマッピングは書き込まれない。
2. 'sessionoptions' に "globals" が含まれている場合、大文字で始まり、少なくと
   も 1 つの小文字を含むグローバル変数を復元する。
3. カレントタブページの、カレントウィンドウ以外の全てのウィンドウを閉じる。カ
   レントタブページ以外の全てのタブページを閉じる (これにより、現在読み込まれ
   ているバッファはアンロードされ、'hidden' が設定されているか、またはそれ以外
   の方法で指定されている場合、一部は隠れ状態になる)。カレントバッファが空で名
   前が無い場合、それを完全に削除する。
4. 'sessionoptions' に "curdir" が含まれている場合、カレントディレクトリを復元
   する。または、'sessionoptions' に "sesdir" が含まれている場合、カレントディ
   レクトリをセッションファイルがある場所に設定する。
5. 'sessionoptions' に "winpos" が含まれている場合、GUI の Vim のウィンドウ位
   置を復元する。
6. 'sessionoptions' に "resize" が含まれている場合、画面サイズを復元する。
7. 最後のカーソル位置と共にバッファリストを再読み込みする。'sessionoptions' に
   "buffers" が含まれている場合、隠れバッファおよびアンロードされたバッファを
   含む全てのバッファが復元される。それ以外の場合、ウィンドウ内のバッファだけ
   が復元される。
8. 全てのウィンドウを同じレイアウトで復元する。'sessionoptions' に "help" が含
   まれている場合、ヘルプウィンドウが復元される。'sessionoptions' に "blank"
   が含まれている場合、名前の無いバッファを編集しているウィンドウが復元される。
   'sessionoptions' に "winsize" が含まれていて、(ヘルプ/空の) ウィンドウが除
   外されなかった場合、ウィンドウサイズが (画面サイズに対して相対的に) 復元さ
   れる。それ以外の場合、ウィンドウには単に妥当なサイズが与えられる。
9. :mkview と同様に、全てのウィンドウのビューを復元する。ただし、
   'viewoptions' の代わりに 'sessionoptions' が使われる。
10. セッションファイルと同じ名前で、"x.vim" (eXtra の意味) で終わるファイルが
    存在する場合、それも実行する。*x.vim ファイルを使って、GUI 版でメニュー項
    目を作成するなど、あるセッションに関連付けられた追加の設定および動作を指定
    することができる。

セッションを復元した後、現在のセッションのフルファイル名は内部変数
"v:this_session" で使用可能である this_session-variable。
マッピングの例:
  :nmap <F2> :wa<Bar>exe "mksession! " .. v:this_session<CR>:so ~/sessions/
これは現在のセッションを保存し、別のセッションを読み込むコマンドを開始する。

'sessionoptions' から "tabpages" が取り除かれていない限り、セッションは全ての
タブページを含む。tab-page

SessionLoadPre 自動コマンドイベントはセッションファイルが読み込まれる前に発
生し、SessionLoadPost 自動コマンドイベントはその後に発生する。
                                                SessionLoad-variable
セッションファイルの読み込み中、SessionLoad グローバル変数は 1 に設定される。
プラグインはこれを使って、SessionLoadPost イベントが発生するまで何らかの作業を
延期することができる。

                                                        :mkvie :mkview
:mkvie[w][!] [file]     カレントウィンドウの内容を復元する Vim script を書き出
                        す。
                        [!] が含まれているとき、既存のファイルは上書きされる。
                        [file] が省略されたとき、または 1 から 9 までの数値で
                        あるとき、名前が生成され、'viewdir' が前に付けられる。
                        'viewdir' のパスの最後の部分が存在しないとき、このディ
                        レクトリが作成される。例えば、'viewdir' が
                        "$VIM/vimfiles/view" のとき、"$VIM/vimfiles" に "view"
                        が作成される。
                        その場合、既存のファイルは常に上書きされる。このビュー
                        を再び読み込むには :loadview を使う。
                        [file] がファイルの名前であるとき ('viewdir' は使われ
                        ない)、ファイルを編集するコマンドが生成されたファイル
                        に追加される。

":mkview" の出力にはこれらの項目が含まれる:
1. ウィンドウで使われている引数リスト。グローバルな引数リストが使われていると
   き、それはグローバルなリストにリセットされる。
   引数リスト内のインデックスも復元される。
2. ウィンドウで編集されているファイル。ファイルが無い場合、ウィンドウは空にさ
   れる。
3. 'viewoptions' に "options" または "localoptions" が含まれている場合、ウィン
   ドウにローカルなマッピング、短縮入力およびオプションを復元する。カレントバッ
   ファおよびカレントウィンドウにローカルなオプション値だけが復元される。ビュー
   をセッションの一部として保存し、'sessionoptions' に "options" が含まれてい
   るとき、ローカルオプションのグローバルな値も保存される。
4. 手動による折り畳みを使っていて、'viewoptions' に "folds" が含まれていると
   き、折り畳みを復元する。手動で開かれた折り畳みおよび閉じられた折り畳みを復
   元する。
5. ファイル内のスクロール位置およびカーソル位置。閉じられた折り畳みがあるとき
   は、あまりうまく動作しない。
6. グローバルなカレントディレクトリと異なり、'viewoptions' に "curdir" が含ま
   れている場合、ローカルなカレントディレクトリ。

Note ビューおよびセッションは完全ではないことに注意:
- それらは全てを復元するわけではない。例えば、定義された関数、自動コマンドおよ
  び ":syntax on" は含まれない。レジスタの内容およびコマンドライン履歴のような
  ものは viminfo にあり、セッションまたはビューにはない。
- グローバルなオプション値は、デフォルト値と異なるときだけ設定される。現在の値
  がデフォルト値でないとき、セッションを読み込んでもそれはデフォルト値に戻され
  ない。ただし、ローカルオプションはデフォルト値に戻される。
- 既存のマッピングは警告無しで上書きされる。既存のマッピングがあいまいさによる
  エラーを引き起こすかもしれない。
- 手動による折り畳みを保存するとき、および手動で開かれた/閉じられた折り畳みを
  保存するとき、ビューを保存してから読み込むまでの間のファイルの変更はそれを台
  無しにする。
- Vim script はあまり効率的ではない。しかし、それでも自分でコマンドを入力する
  よりは速い!

                                                        :lo :loadview
:lo[adview] [nr]        カレントファイルのビューを読み込む。[nr] が省略された
                        とき、":mkview" で保存されたビューが読み込まれる。[nr]
                        が指定されたとき、":mkview [nr]" で保存されたビューが
                        読み込まれる。

":mkview" および ":loadview" の組み合わせを使って、ファイルの異なるビューを 10
個まで保存できる。これらは 'viewdir' オプションで指定されたディレクトリに記憶
される。ビューはファイル名を使って保存される。ファイルの名前が変更されたか、ま
たは (シンボリック) リンクを通してアクセスされた場合、ビューは見つからない。

'viewdir' ディレクトリを時々掃除するとよいかもしれない。

*.c ファイルのビューを自動的に保存および復元するには:
        au BufWinLeave *.c mkview
        au BufWinEnter *.c silent loadview

10. viminfo ファイル                            viminfo viminfo-file E136
                                                E575 E576 E577
Vim を終了し、後で再び起動した場合、通常は多くの情報を失う。viminfo ファイルを
使ってその情報を記憶することができ、中断したところから続けることが可能になる。

これはユーザーマニュアルの 21.3 節で紹介されている。

viminfo ファイルは以下を保存するために使われる:
- コマンドライン履歴。
- 検索文字列の履歴。
- 入力行履歴。
- 空でないレジスタの内容。
- 複数のファイルのマーク。
- ファイル内の位置を指すファイルマーク。
- 最後の検索/置換パターン ('n' および '&' 用)。
- バッファリスト。
- グローバル変数。

+viminfo 機能がコンパイル時に無効にされているときは、viminfo ファイルはサポー
トされない。

セッションファイルを使うこともできる。違いは、viminfo ファイルは何を作業してい
るかに依存しないことである。通常は viminfo ファイルは 1 つだけである。セッショ
ンファイルは特定の編集セッションの状態を保存するために使われる。作業している各
プロジェクトに 1 つずつ、複数のセッションファイルを持つことができる。viminfo
ファイルおよびセッションファイルを一緒に使うと、効率よく Vim に入り、望みの設
定で直接作業を開始することができる。session-file

                                                        viminfo-security
Vim によって書き込まれた viminfo ファイルはプレーンテキストであり、List、
Dictionary および Tuple の値のための Vim の式を含む。Vim がファイルを
viminfo ファイルとして処理する時点で 'viminfo' に "!" が含まれているとき、それ
らの式は評価される。

'viminfo' のデフォルト値は "!" を含まないので、デフォルトでは式の評価は行われ
ない。

viminfo ファイルをバッファで開くこと (例えば :edit で) は無害である。Vim は
ファイルの内容を表示するだけである。危険なのは、信頼できないファイルを Vim に
viminfo の仕組みを通して処理させることであり、それは以下のときに起こる:
- そのファイルに対して :rviminfo が使われる、または
- 'viminfofile' がそのファイルを指すように設定されている、または
- そのファイルが、Vim が既に viminfo として読み込むパスに置かれている
  viminfo-file-name

それらのいずれの場合も、それを信頼しない場合、'viminfo' に "!" を含めないこと。

                                                        viminfo-read
Vim が起動され、'viminfo' オプションが空でないとき、viminfo ファイルの内容が読
み込まれ、その情報を適切な場所で使用できる。v:oldfiles 変数に値が入れられる。
マークは起動時には読み込まれない (ただしファイルマークは読み込まれる)。起動時
に 'viminfo' オプションを設定する方法については initialization を参照。

                                                        viminfo-write
Vim が終了し、'viminfo' が空でないとき、情報は viminfo ファイルに保存される
(実際には、既存のものがある場合、それとマージされる)。'viminfo' オプションは、
どの情報を保存すべきかについての情報を含む文字列であり、どれだけ保存すべきかの
制限を含む ('viminfo' を参照)。

マージは 2 つの方法で行われる。現在の Vim セッションで変更または設定されたほと
んどの項目が保存され、変更されなかったものは現在 viminfo ファイルにあるもので
埋められる。例えば:
- Vim セッション A は viminfo を読み込み、それには変数 START が含まれている。
- Vim セッション B も同じことをする
- Vim セッション A は変数 AAA および BOTH を設定して終了する
- Vim セッション B は変数 BBB および BOTH を設定して終了する
このとき、viminfo には以下が含まれる:
   START - viminfo にあり、セッション A または B で変更されなかった
   AAA   - セッション A からの値、セッション B はそれを保持した
   BBB   - セッション B からの値
   BOTH  - セッション B からの値、セッション A からの値は失われる

                                                        viminfo-timestamp
いくつかの項目については、最後に変更されたバージョンを保持するためにタイムスタ
ンプが使われる。この場合、Vim セッションがどの順番で終了するかは関係なく、最も
新しい項目が常に保持される。これは以下に使われる:
- コマンドライン履歴。
- 検索文字列の履歴。
- 入力行履歴。
- 空でないレジスタの内容。
- ジャンプリスト。
- ファイルマーク。

タイムスタンプ機能は Vim 8.0 より前に追加された。7.4.1131 以降の古いバージョン
の Vim は、タイムスタンプ付きの項目を保持するが、それらを使わない。したがって、
古いバージョンおよび新しいバージョンの Vim の両方を使っているときは、最新のデー
タが保持される。

Unix についての注意:
- viminfo ファイルのファイル保護は、他のユーザーがそれを読めないように設定され
  る。それは作業したどんなテキストまたはコマンドも含んでいる可能性があるためで
  ある。
- viminfo ファイルを他のユーザーと共有したい場合 (例えば、別のユーザーに "su"
  するとき)、ファイルをグループまたは全員が書き込めるようにすることができる。
  Vim は viminfo ファイルを置き換えるときにこれを保持する。注意すること、誰に
  でも viminfo ファイルの読み書きを許可しないこと!
- Vim は、現在の "real" ユーザーが書き込めない viminfo ファイルを上書きしない。
  これは、root になるために "su" したが、$HOME がまだ通常のユーザーのホームディ
  レクトリに設定されているときに役立つ。そうしないと、Vim は他の誰も読めない
  root 所有の viminfo ファイルを作成してしまう。
- viminfo ファイルはシンボリックリンクにはできない。これはセキュリティ上の問題
  を避けるためである。

マークはファイルごとに別々に保存される。ファイルが読み込まれ、'viminfo' が空で
ないとき、そのファイルのマークが viminfo ファイルから読み込まれる。NOTE: マー
クは Vim を終了するときにのみ書き込まれる。":bdel" が使われない限り、現在の編
集セッションで開いた全てのファイルのマークは記憶されているので、これは問題な
い。":bdel" で破棄しようとしているファイルのマークを保存したい場合、":wv" を使
うこと。'[' および ']' マークは保存されないが、'"' マークは保存される。'"' マー
クは、ファイルを最後に終了したときのカーソル位置にジャンプするのに非常に便利で
ある。'viminfo' の "r" フラグで指定された文字列のいずれかで始まるファイルにつ
いては、マークは保存されない。これは、リムーバブルメディア上のファイルのマーク
を保存しないようにするために使うことができる (MS-Windows では "ra:,rb:"、Amiga
では "rdf0:,rdf1:,rdf2:" を使うだろう)。
v:oldfiles 変数には、viminfo ファイルがマークを持つファイル名が入れられる。

                                                        viminfo-file-marks
大文字のマーク ('A から 'Z) は viminfo ファイルを書き込むときに保存される。番
号付きのマーク ('0 から '9) は少し特別である。viminfo ファイルが書き込まれると
き (終了時または ":wviminfo" コマンドで)、'0 は現在のカーソル位置およびファイ
ルに設定される。古い '0 は '1 に、'1 は '2 に、などと移動される。これは "1 か
ら "9 の削除レジスタで起こることに似ている。現在のカーソル位置が既に '0 から
'9 にある場合、同じ位置が 2 回現れるのを避けるため、それは '0 に移動される。そ
の結果、"'0" で、Vim を終了したファイルおよび行に戻ってジャンプできる。すぐに
そうするには、このコマンドを使ってみること:

        vim -c "normal '0"

C シェルの派生では、そのためのエイリアスを作ることができる:

        alias lvim vim -c '"'normal "'"0'"'

Bash 系のシェルでは:

        alias lvim='vim -c "normal '\''0"'

どのファイルについてマークを記憶しないかを指定するには、'viminfo' の "r" フラ
グを使う。


viminfo ファイル名                                     viminfo-file-name

- viminfo ファイルのデフォルトの名前は、Unix では "$HOME/.viminfo"、Amiga では
  "s:.viminfo"、Win32 では "$HOME\_viminfo" である。Win32 では、$HOME が設定さ
  れていないとき、"$VIM\_viminfo" が使われる。$VIM も設定されていないとき、
  "c:\_viminfo" が使われる。
- ViAI は代わりに、Unix では "$HOME/.viaiinfo"、Win32 では "$HOME\_viaiinfo"
  を使い、$HOME が設定されていないときは "$VIM\_viaiinfo" および
  "c:\_viaiinfo" を使う。viai-viminfo を参照。このファイルがまだ存在しないと
  き、$HOME にある Vim の viminfo ファイルが代わりに読み込まれ、書き込むときに
  それにマージされる。Vim の viminfo ファイルは決して書き込まれない。これはデ
  フォルトのファイル名にのみ当てはまる。
- 'viminfo' オプションの 'n' フラグを使って、別の viminfo ファイル名を指定でき
  る 'viminfo'。
- Vim の引数 "-i" を使って別のファイル名を設定できる、-i。指定されたファイル
  名が "NONE" (全て大文字) のとき、viminfo ファイルは決して読み書きされない。
  以下のコマンドに対してもである!
- 'viminfofile' オプションは "-i" 引数と同様に使うことができる。実際、"-i" 引
  数からの値は 'viminfofile' オプションに保存される。
- 以下のコマンドでは、別のファイル名を指定することができ、デフォルトおよび
  'viminfo' または "-i" で指定された名前を上書きする (それが NONE でない限り)。


文字エンコーディング                                   viminfo-encoding

viminfo ファイル内のテキストは、'encoding' オプションで指定されたようにエンコー
ドされる。通常は常に同じ 'encoding' の値で作業するので、これは問題なく動作す
る。しかし、書き込まれたときとは別の 'encoding' の値で viminfo ファイルを読み
込んだ場合、テキストの一部 (非 ASCII 文字) が不正になることがある。これが受け
入れられない場合、'viminfo' オプションに 'c' フラグを追加する:
        :set viminfo+=c
Vim はその後、viminfo ファイル内のテキストを、書き込まれたときの 'encoding' の
値から現在の 'encoding' の値に変換しようとする。これには、Vim が +iconv 機能
付きでコンパイルされている必要がある。ファイル名は変換されない。


手動での読み込みと書き込み                             viminfo-read-write

viminfo ファイルを手動で読み書きするために 2 つのコマンドを使うことができる。
これは、2 つの実行中の Vim プログラム間でレジスタを交換するために使用できる:
まず一方で ":wv" と入力し、次にもう一方で ":rv" と入力する。Note レジスタに既
に何かが含まれていた場合、":rv!" が必要になることに注意。ただし、これはコマン
ドライン履歴なども含め、全てが最初の Vim からの情報で上書きされることを意味す
ることにも注意。

viminfo ファイル自体も手で編集できるが、形式を正しくするために既存のものから始
めることを勧める。中に入ってしまえば、かなり分かりやすい。これは、Vim を最初に
起動するときに常に欲しい特定の設定を含む 2 番目のファイル、例えば
"~/.my_viminfo" を作成するのに役立つ。例えば、レジスタに特定のデータを事前に読
み込んだり、またはコマンドライン履歴に特定のコマンドを入れたりできる。.vimrc
ファイル中の以下のような行
        :rviminfo! ~/.my_viminfo
を使ってこの情報を読み込むことができる。ファイルの種類ごと (例えば C コード)
に異なる viminfo を持ち、":autocmd" コマンドを使ってファイル名に基づいてそれら
を読み込むことさえできる (:autocmd を参照)。

                                                        viminfo-errors
Vim が viminfo ファイルの読み込み中にエラーを検出したときは、そのファイルを上
書きしない。エラーが 10 個を超える場合、Vim は viminfo ファイルの読み込みを停
止する。これは、viminfo ファイルのファイル名が間違っているときに、誤ってファイ
ルを破壊するのを避けるために行われた。これは "vim -R file" とするつもりで誤っ
て "vim -i file" と入力したときに起こりうる (そう、誰かが実際に誤ってそうし
た!)。エラーのある viminfo ファイルを上書きしたい場合、エラーを修正するか、ま
たはファイルを削除しなければならない (Vim の実行中に。そうすればほとんどの情報
は復元される)。

                                                   :rv :rviminfo E195
:rv[iminfo][!] [file]   viminfo ファイル [file] から読み込む (デフォルト: 上記
                        の viminfo-file-name を参照)。
                        [!] が指定された場合、既に設定されている全ての情報 (レ
                        ジスタ、マーク、v:oldfiles など) が上書きされる。
                        'viminfofile' が "NONE" に設定されているとき、"E195"
                        が出ることがある。

                        :wv :wviminfo E137 E138 E574 E886 E929
:wv[iminfo][!] [file]   viminfo ファイル [file] に書き込む (デフォルト: 上記の
                        viminfo-file-name を参照)。
                        'viminfofile' が "NONE" に設定されているとき、このコマ
                        ンドは何の効果も無い。
                        ファイル内の情報は、古い情報と新しい情報をマージするた
                        めに、まず読み込まれる。[!] が使われたとき、古い情報は
                        まず読み込まれず、内部の情報だけが書き込まれる。
                        'viminfo' が空の場合、最大 100 個のファイルのマークが
                        書き込まれる。
                        エラー "E929: Too many viminfo temp files" が出たとき
                        は、古い一時ファイルが残っていないこと (例えば
                        ~/.viminf*)、および .viminfo ファイルのディレクトリに
                        書き込めることを確認すること。

                                                :ol :oldfiles
:ol[dfiles]             viminfo ファイルにマークが保存されているファイルを一覧
                        表示する。この一覧は起動時に読み込まれ、その後は
                        :rviminfo! でのみ変更される。v:oldfiles も参照。番
                        号は c_#< で使用できる。
                        出力は :filter でフィルタできる。例:
                                filter /\.vim/ oldfiles
                        フィルタリングはファイル名に対して行われる。
