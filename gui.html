1. GUI の起動                                   gui-start E229 E233

まず、GUI のコードが含まれた Vim のバージョンを実際に持っていることを確認しな
ければならない。これは ":version" コマンドで確認できる。それは "with xxx GUI"
と表示する。ここで "xxx" は X11-Motif、Photon、GTK2、GTK3、GTK4 など、または
"MS-Windows 32 bit GUI version" である。

GUI の起動方法は使用するシステムに依存する。たいていは以下で Vim の GUI 版を実
行できる:
    gvim [options] [files...]

Vim の X11 版は GUI モードおよび非 GUI モードの両方で実行できる。
gui-x11-start を参照。

                        gui-init gvimrc .gvimrc _gvimrc $MYGVIMRC
gvimrc ファイルは、GUI 固有の起動時のコマンドを置くべき場所である。それは常に
vimrc ファイルの後に読み込まれる。それがある場合、$MYGVIMRC 環境変数がその名
前を持つ。

GUI が起動する時、初期化がこの順序で実行される:
- 'term' オプションは "builtin_gui" に設定され、端末オプションは GUI 用のデフォ
  ルト値にリセットされる terminal-options。
- システムメニューファイルが存在する場合、それが読み込まれる。このファイルの名
  前は通常 "$VIMRUNTIME/menu.vim" である。これは ":version" で確認できる。
  $VIMRUNTIME も参照。システムメニューの読み込みをスキップするには
  'guioptions' に 'M' を含める。 buffers-menu no_buffers_menu
  システムメニューファイルには "Buffers" メニューが含まれる。これが不要な場合、
  .vimrc (.gvimrc ではない!) で "no_buffers_menu" 変数を設定する:
        :let no_buffers_menu = 1
  NOTE: 構文ハイライトをオンにするとメニューファイルも読み込まれ、したがって
  Buffers メニューの無効化は ":syntax on" より前に行わなければならない。
  パス名は 35 文字に切り詰められる。別の長さ、例えば 50 で、このように切り詰め
  ることができる:
        :let bmenu_max_pathlen = 50
- Vim の起動時に "-U {gvimrc}" コマンドラインオプションが使用された場合、初期
  化のために {gvimrc} ファイルが読み込まれる。以下の初期化はスキップされる。
  {gvimrc} が "NONE" の場合、初期化のためにファイルは読み込まれない。
- Unix および MS-Windows では、システム gvimrc が存在する場合、それが読み込ま
  れる。このファイルの名前は通常 "$VIM/gvimrc" である。これは ":version" で確
  認できる。$VIM も参照。
- 以下が試され、存在する最初のものだけが使用される:
  - GVIMINIT 環境変数が存在し、空でない場合、それが Ex コマンドとして実行され
    る。
  - ユーザーの gvimrc ファイルが存在する場合、それが読み込まれる。このファイル
    の名前は通常 "$HOME/.gvimrc" である。これは ":version" で確認できる。
  - Win32 では、必要な場合、$HOME は Vim によって設定される。$HOME-windows
    を参照。
  - "_gvimrc" ファイルが見つからない時は、".gvimrc" も試される。逆も同様。
  - Unix では、"~/.config/vim/gvimrc" または "$XDG_CONFIG_HOME/vim/gvimrc" が
    存在する場合、それが読み込まれる。これは ":version" で確認できる。
  - ViAI 自身のユーザー設定が存在する時 (viai-config を参照)、Vim のファイル
    の代わりに ViAI のファイルが使用される: Unix では "$HOME/.gviairc"、
    "$HOME/.viai/gvimrc" および "$XDG_CONFIG_HOME/viai/gvimrc"、Win32 では
    "$HOME/_gviairc" および "$HOME/viaifiles/gvimrc"。
  最初に見つかったファイルの名前は、すでに設定されていない限り、$MYGVIMRC に格
  納される。
- 'exrc' オプションが設定されている場合 (これはデフォルトではない)、ファイル
  ./.gvimrc が存在し、システムまたはユーザーの gvimrc ファイルと同じファイルで
  ない場合、それが読み込まれる。このファイルの所有者があなたでない場合、いくつ
  かのセキュリティ制限が適用される。".gvimrc" が見つからない時は、"_gvimrc" も
  試される。Macintosh および DOS/Win32 では "_gvimrc" が最初に試される。

NOTE: Vim が "-u NONE" または "-u DEFAULTS" で起動され、"-U" 引数が指定されな
かった場合、または "-U NONE" で起動された場合、最初のもの以外はすべて実行され
ない。

これはすべて、.vimrc ファイルの読み込みのような、通常の Vim の初期化の後に起こ
る。initialization を参照。
しかし GUI ウィンドウは、すべての初期化が実行された後にだけ開かれる。GUI ウィ
ンドウを開いた直後にいくつかのコマンドを実行したい場合、GUIEnter 自動コマン
ドイベントを使用する。例:
        :autocmd GUIEnter * winpos 100 50

gvimrc ファイルを使用して、独自のカスタマイズしたメニューを設定し (:menu を
参照)、端末版とは異なる設定にしたいその他のことを初期化できる。

個人用の GUI 初期化の推奨される場所:
        Unix                $HOME/.gvimrc or $HOME/.vim/gvimrc
        Win32               $HOME/_gvimrc, $HOME/vimfiles/gvimrc
                            or $VIM/_gvimrc
        Amiga               s:.gvimrc, home:.gvimrc, home:vimfiles:gvimrc
                            or $VIM/.gvimrc
        Haiku               $HOME/config/settings/vim/gvimrc
ViAI 自身のユーザー設定が存在する時は、代わりにこれらが使用される:
        Unix                $HOME/.gviairc or $HOME/.viai/gvimrc
        Win32               $HOME/_gviairc, $HOME/viaifiles/gvimrc
                            or $VIM/_gvimrc

個人用の初期化ファイルは上で指定された順序で検索され、最初に見つかったものだけ
が読み込まれる。

Vim の GUI 版でのみ意味を持つオプションがいくつかある。それらは 'guicursor'、
'guifont'、'guipty' および 'guioptions' である。それらは他のすべてのオプション
と一緒に options.txt で説明されている。

GUI の Motif 版を使用している場合 (ただし GTK+ または Win32 版ではない)、いく
つかの X リソースが使用可能である。gui-resources を参照。

異なる場面で色を設定するもう 1 つの方法は、ハイライトグループを使うことである。
"Normal" グループは背景色および前景色を設定するために使用される。例 (見た目が
よい):

        :highlight Normal guibg=grey90

"guibg" および "guifg" の設定は、通常の背景および前景の設定を上書きする。
Normal ハイライトグループのその他の設定は使用されない。フォントを設定するには
'guifont' オプションを使用する。

さまざまなモードでのカーソルの色を設定するための 'guicursor' オプションも調べ
ること。

Vim は起動時にウィンドウが画面に収まるようにしようとする。これにより、その一部
が見えないことを避ける。X Window System では、これにはちょっとした推測が必要で
ある。'guiheadroom' オプションで、ウィンドウタイトルおよびタスクバーのために使
用される高さを変更できる。

                                                :winp :winpos E188
:winp[os]
                GUI vim ウィンドウの左上隅の現在の位置をピクセル単位で表示す
                る。すべてのバージョンで動作するわけではない。
                getwinpos()、getwinposx() および getwinposy() も参照。

:winp[os] {X} {Y}                                                       E466
                GUI vim ウィンドウを指定された {X} および {Y} 座標に置く。座標
                はウィンドウの左上隅の位置をピクセル単位で指定する必要がある。
                すべてのバージョンで動作するわけではない。(新しい) xterm では
                動作する xterm-color。
                GUI ウィンドウがまだ開かれていない時は、値はウィンドウが開かれ
                るまで記憶される。位置はウィンドウが画面に収まるように調整され
                る (可能な場合)。

                                            :wi :win :winsize E465
:win[size] {width} {height}
                ウィンドウの高さを {width} × {height} 文字に設定する。
                数字の意味がわかりやすいので、代わりに
                :set lines=11 columns=22 を使用することを推奨する。
                期待したより少ない行しか得られない場合、'guiheadroom' オプショ
                ンを確認すること。

X Window System を実行している場合、これらのコマンドで Vim が実行されているウィ
ンドウについての情報を得られる:
        :!xwininfo -id $WINDOWID
        :!xprop -id $WINDOWID
        :execute '!xwininfo -id ' .. v:windowid
        :execute '!xprop -id ' .. v:windowid

                                                        gui-IME iBus
X において XIM フレームワークに依存する国際文字のためのインプットメソッド、特
に iBus は、gvim で望ましくない結果を生じることが知られている。これには、スペー
スを入力できないこと、または文字をタイプしてからそれがアプリケーションによって
認識されるまでの長い遅延が含まれうる。

理由は不明だが成功している回避策の 1 つは、gvim を -f 引数で起動して、バック
グラウンドにフォークしないようにすることである。

2. スクロールバー                                       gui-scrollbars

垂直スクロールバーおよび水平スクロールバーがある。どれを表示するかは
'guioptions' オプションで設定できる。

インターフェイスはこのようになる (":set guioptions=mlrb" の場合):

                       +------------------------------+ 
                       | File  Edit              Help | <- メニューバー (m) 
                       +-+--------------------------+-+ 
                       |^|                          |^| 
                       |#| テキスト領域。           |#| 
                       | |                          | | 
                       |v|__________________________|v| 
 通常のステータス行 -> |-+ File.c              5,2  +-| 
 Vim ウィンドウ間の    |^|""""""""""""""""""""""""""|^| 
                       | |                          | | 
                       | | 別のファイルバッファ。   | | 
                       | |                          | | 
                       |#|                          |#| 
   左スクロールバー -> |#|                          |#| <- 右 
   (l)                 |#|                          |#|    スクロールバー (r) 
                       | |                          | | 
                       |v|                          |v| 
                       +-+--------------------------+-+ 
                       | |< ####                   >| | <- 下 
                       +-+--------------------------+-+    スクロールバー (b) 

'guioptions' 文字列に適切な文字を入れないことで、スクロールバーまたはメニュー
のどの構成要素もオフにできる。下スクロールバーは 'nowrap' が設定されている時に
だけ役に立つ。


垂直スクロールバー                                     gui-vert-scroll

各 Vim ウィンドウの横にはスクロールバーがあり、それを上下にスクロールして、そ
のバッファのテキスト中を移動できる。スクロールバーのつまみの大きさは、ウィンド
ウで見えるバッファの割合を示す。
スクロールバーを一番下までドラッグすると、ファイルの最終行がウィンドウの一番上
に表示される。

ウィンドウが (別のウィンドウが大きくなることにより) 高さ 0 に縮められた場合、
そのスクロールバーは消える。ウィンドウが元に戻ると再び現れる。

ウィンドウが垂直分割されている場合、それがカレントウィンドウである時、およびカ
レントウィンドウの中央を取って垂直線を引いた時にその線がそのウィンドウを通る時
に、そのウィンドウはスクロールバーを得る。
両側にスクロールバーがあり、カレントウィンドウの中央が左半分にある時、右のスク
ロールバーのカラムには最も右のウィンドウのスクロールバーが入る。反対側でも同じ
ことが起こる。


水平スクロールバー                                     gui-horiz-scroll

水平スクロールバー (Vim GUI の下部にある) は、'wrap' オプションがオフの時にテ
キストを横にスクロールするために使用できる。スクロールバーのつまみの大きさは、
表示されている最も長い行のテキストを左右にできるだけスクロールできるようになっ
ている。カーソルは必要な時に移動され、表示されている文字の上になければならない
('virtualedit' が設定されていない限り)。

表示されている最も長い行の長さの計算にはかなりの計算が必要で、何かが変わるたび
に行わなければならない。これに時間がかかりすぎるか、またはカーソルが別の行へ
ジャンプするのが気に入らない場合、'guioptions' に 'h' フラグを含める。そうする
と、スクロールは現在のカーソル行のテキストによって制限される。

                                                        motif-intellimouse
Intellimouse、およびホイールの使用をサポートする X サーバーがある場合、gvim で
ホイールを使ってテキストを上下にスクロールできる。これは XFree86 4.0 以降で動
作し、パッチを当てればいくつかの古いバージョンでも動作する。
scroll-mouse-wheel を参照。

XFree86 の古いバージョンでは、X サーバーにパッチを当てなければならない。以下の
ページには、Linux で Intellimouse を使用することについての情報が少しあり、パッ
チおよび X サーバーのバイナリへのリンクもある (ただし、必要なものはないかもし
れない):
    (リンク切れ) inria.fr/koala/colas/mouse-wheel-scroll/

3. マウス制御                                           gui-mouse

マウスは 'mouse' オプションに適切なフラグが設定されている場合にのみ動作する。
GUI がオンになった時、'mouse' がまだ設定されていなかった場合、'mouse' オプショ
ンは自動的に "a" に設定され、hit-enter プロンプトを除くすべてのモードで有効
になる。これが不要な場合、'mouse' オプションを変更するのによい場所は "gvimrc"
ファイルである。

関連するその他のオプション:
'mousefocus'    ウィンドウフォーカスがマウスポインタに従う gui-mouse-focus
'mousemodel'    どのマウスボタンがどの動作をするか
'mousehide'     テキストをタイプしている間マウスポインタを隠す
'mousemoveevent' <MouseMove> をマップできるようにマウス移動イベントを有効にする
'selectmode'    選択モードまたはビジュアルモードのどちらを開始するか

これらを設定する簡単な方法は ":behave" コマンドである。
                                                        :behave :be
:be[have] {model}       マウスおよび選択の動作を設定する。有効な引数は以下:
                           mswin        MS-Windows の動作
                           xterm        Xterm の動作

                        ":behave" を使用すると、これらのオプションが変わる:
                        オプション      mswin                   xterm
                        'selectmode'    "mouse,key"             ""
                        'mousemodel'    "popup"                 "extend"
                        'keymodel'      "startsel,stopsel"      ""
                        'selection'     "exclusive"             "inclusive"

$VIMRUNTIME ディレクトリには mswin.vim というスクリプトがあり、それはいくつ
かのキーを MS-Windows のカット/コピー/ペーストのコマンドにマップもする。これは
CTRL-V、CTRL-X および CTRL-C キーを使用するので、互換ではない。気にしない場合、
このコマンドを使用する:
        :so $VIMRUNTIME/mswin.vim

マウスのホイールでのスクロールについては、scroll-mouse-wheel を参照。


3.1 マウスでのカーソル移動                              gui-mouse-move

カーソルを移動させたいテキストバッファ内のどこかでマウスの左ボタンをクリックす
ると、そこに移動する!
動作するモード      'mouse' に含まれる文字
ノーマルモード      'n' または 'a'
ビジュアルモード    'v' または 'a'
挿入モード          'i' または 'a'

選択モードはビジュアルモードと同様に扱われる。

これを 'd' のようなオペレータと一緒に使用して、現在のカーソル位置からマウスで
指した位置までのテキストを削除できる。つまり、'd' を打ってから、マウスでどこか
をクリックする。

                                                        gui-mouse-focus
'mousefocus' オプションを設定すると、キーボードフォーカスがマウスポインタに従
うようにできる。これは、マウスポインタがあるウィンドウがアクティブなウィンドウ
になることを意味する。警告: これはメニューを使用する時にはあまりうまく動作しな
い。メニューコマンドは常に一番上のウィンドウに適用されるからである。

':' 行 (または '/' または '?') にいる場合、マウスの左ボタンまたは右ボタンをク
リックすると、':' 行の上にカーソルが置かれる ('mouse' に 'c' または 'a' が含ま
れる場合)。

どんな状況でも、マウスの中ボタンをクリックして現在の選択範囲を貼り付けることが
できる。


3.2 マウスでの選択                                      gui-mouse-select

マウスを使用して選択を開始できる。どのようにするかは 'mousemodel' オプションに
依存する:
'mousemodel' が "extend": マウスの右ボタンを使用する
'mousemodel' が "popup":  Shift キーを押したまま、マウスの左ボタンを使用する。

まだ選択がなかった場合、これは古いカーソル位置からマウスで指した位置までの選択
を開始する。すでに選択がある場合、近い方の端が拡張される。

'selectmode' に "mouse" が含まれる場合、選択は選択モードになる。これは、通常の
テキストをタイプすると選択範囲が置き換えられることを意味する。
Select-mode を参照。そうでない場合、選択はビジュアルモードになる。

ダブルクリックで単語単位の選択にでき、トリプルクリックで行単位、4 回クリックで
矩形ブロック単位になる。

選択がどのように使用されるかについては gui-selections を参照。


3.3 マウスでのその他のテキスト選択              gui-mouse-modeless
                                                modeless-selection
以下の時は、別の種類の選択が使用される:
- コマンドラインモードで
- コマンドラインウィンドウで、別のウィンドウを指している時
- hit-enter プロンプトで
- 現在のモードが 'mouse' オプションに含まれていない時
- GUI で CTRL および SHIFT キーを押している時

Vim は選択がないかのように動作を続け、選択に関連付けられたモードもないので、こ
れはモードレス選択と呼ばれる。Vim ウィンドウ内のどのテキストでも選択できる。開
始位置でマウスの左ボタンを押し、終わりまでドラッグして離すことでテキストを選択
する。選択を拡張するには、'mousemodel' が "extend" の時はマウスの右ボタンを、
または 'mousemodel' が "popup" の時はシフトキーを押しながらマウスの左ボタンを
使用する。
選択されたテキストがスクロールまたは変更されると、選択は解除される。

コマンドラインでは、CTRL-Y を使用して選択範囲をクリップボードにコピーできる。
挿入モードからこれを行うには、CTRL-O : CTRL-Y <CR> を使用する。'guioptions' に
a または A が含まれる場合 (X11 ではデフォルト)、選択範囲は自動的に "* レジスタ
にコピーされる。

そうすると、マウスの中ボタンでそのテキストを貼り付けることができる。X11 以外の
システムでは、CTRL-R + を使用できる。


3.4 ステータス行でのマウスの使用                        gui-mouse-status

Vim ウィンドウの下のステータス行でマウスの左ボタンまたは右ボタンをクリックする
と、そのウィンドウがカレントウィンドウになる。これは実際にはボタンを離した時に
起こる (クリックとドラッグ操作を区別できるようにするため)。

マウスの左ボタンでステータス行を上下にドラッグでき、それによってその上下のウィ
ンドウのサイズが変わる。これはウィンドウフォーカスを変えない。

同じことが垂直区切りでも使用できる: クリックするとその左のウィンドウにフォーカ
スが移り、左右にドラッグするとウィンドウがより広く、およびより狭くなる。


3.5 さまざまなマウスクリック                            gui-mouse-various

    <S-LeftMouse>       マウスでクリックした位置の単語を前方に検索する。
                        'mousemodel' が "popup" の時は、これは選択を開始する
                        か、または拡張する。
    <S-RightMouse>      マウスでクリックした位置の単語を後方に検索する。
    <C-LeftMouse>       マウスでクリックした位置のタグ名へジャンプする。
    <C-RightMouse>      直前のタグジャンプの前の位置へ戻る ("CTRL-T" と同じ)


3.6 マウスのマッピング                                  gui-mouse-mapping

修飾キーを含めたマウスイベントをマップできる。例:
   :map <S-LeftMouse>     <RightMouse>
   :map <S-LeftDrag>      <RightDrag>
   :map <S-LeftRelease>   <RightRelease>
   :map <2-S-LeftMouse>   <2-RightMouse>
   :map <2-S-LeftDrag>    <2-RightDrag>
   :map <2-S-LeftRelease> <2-RightRelease>
   :map <3-S-LeftMouse>   <3-RightMouse>
   :map <3-S-LeftDrag>    <3-RightDrag>
   :map <3-S-LeftRelease> <3-RightRelease>
   :map <4-S-LeftMouse>   <4-RightMouse>
   :map <4-S-LeftDrag>    <4-RightDrag>
   :map <4-S-LeftRelease> <4-RightRelease>
これらのマッピングは、マウスの右ボタンではなくシフト+マウスの左ボタンでビジュ
アル領域を拡張できるようにして、選択を Motif アプリケーションでおそらくそうあ
るべき方法で動作させる。

<MouseMove> はマップできるが、そのマッピングを使用するには 'mousemoveevent' が
有効になっていなければならない。

修飾キー付きのマウスマッピングは、モードレス選択では動作しない。


3.7 ドラッグアンドドロップ                                      drag-n-drop

1 つ以上のファイルを Vim ウィンドウにドラッグアンドドロップすると、:drop コ
マンドが使用されたかのようにそれらが開かれる。これがサポートされているかどうか
は drop_file 機能で確認できる: has('drop_file')。

これを行う時に Shift を押している場合、Vim は最初にドロップされたファイルのディ
レクトリに移動する。Ctrl を押している場合、Vim は常にそのファイルのために新し
いウィンドウを分割する。そうでない場合、それはカレントバッファが変更されている
場合にのみ行われる。

ディレクトリを Vim にドロップすることもできる。これはそのディレクトリに対して
エクスプローラープラグインを開始する (それが有効になっていると仮定する。そうで
ない場合はエラーメッセージが表示される)。代わりにそのディレクトリに移動するに
は、Shift を押したままにする。

Vim がたまたまコマンドラインを編集している場合、ドロップされたファイルおよび
ディレクトリの名前はカーソル位置に挿入される。これにより、それらの名前を任意の
Ex コマンドで使用できる。特殊文字 (スペース、タブ、ダブルクォートおよび '|';
MS-Windows 以外のシステムではバックスラッシュ) はエスケープされる。

4. GUI 選択の作成                                       gui-selections

                                                        quotestar
マウス (gui-mouse-select を参照)、または Vim のビジュアルモード (v を参照)
を使用して選択を作ることができる。'guioptions' に 'a' がある場合、選択が開始さ
れた時 (ビジュアルモードまたは選択モード)、または選択が変更された時は常に、Vim
はウィンドウシステムのプライマリセレクションの所有者になる (MS-Windows では
gui-clipboard が使用される。X11 では x11-selection が使用される - これ
らのうち該当する方を今読むべきである)。

                                                        clipboard
この選択を格納するための特別なレジスタがあり、それは "* レジスタである。どのテ
キストが選択されているかの情報が変わろうとしている時 (例えば、どこかでマウスの
左ボタンをクリックした時)、または別のアプリケーションが選択されたテキストを貼
り付けようとする時以外は、ここには何も入れられない。その時、テキストが "* レジ
スタに入れられる。例えば、行をカットして、それを現在の選択にする/クリップボー
ドに入れるには:

        "*dd

同様に、別のアプリケーションから選択範囲を貼り付けたい時、例えばマウスの中ボタ
ンをクリックすることで、選択範囲はまず "* レジスタに入れられ、それから他のレジ
スタと同じように 'put' される。例えば、選択範囲 (クリップボードの内容) を put
するには:

        "*p

X11 でこのレジスタを使用する時は、x11-selection も参照。これは関連する "+ レ
ジスタについても説明している。

Note ある Vim から別の独立した Vim にテキストを貼り付ける時、選択の種類 (文字、
行、またはブロック) もコピーされることに注意。他のアプリケーションでは、種類は
常に文字である。ただし、テキストが x11-cut-buffer を経由して転送される場合、
選択の種類は常に失われる。

'clipboard' オプションに "unnamed" 文字列が含まれている場合、無名レジスタは "*
レジスタと同じになる。したがって、コマンドの前に "* を付けずに、選択範囲へヤン
クし、選択範囲を貼り付けることができる。

W23 および W24 も参照。

5. メニュー                                             menus

導入については、ユーザーマニュアルの usr_42.txt を参照。


5.1 メニューの使用                                      using-menus

基本的に、メニューはマッピングとまったく同じように使用できる。独自のメニューを
好きなだけ定義できる。
長年の Vim ユーザーはメニューをあまり使わないだろう。しかし、その力は独自のメ
ニューおよびメニュー項目を追加することにある。それらは、キーシーケンスが何だっ
たか思い出せないことに最も役立つ。

別の言語でメニューを作成するには、:menutrans を参照。
メニューをまったく使用したくない場合、'go-M' を参照。

                                                        menu.vim
デフォルトのメニューはファイル "$VIMRUNTIME/menu.vim" から読み込まれる。パスが
どこから来るのかについては $VIMRUNTIME を参照。独自のメニューを設定できる。
デフォルトのセットから始めるのはよい考えである。項目をさらに追加するか、また
は、デフォルトがまったく気に入らない場合、すべてのメニューの削除から始めること
ができる :unmenu-all。.vimrc ファイル (.gvimrc ファイルではない!) にこの行を
追加することで、デフォルトのメニューが読み込まれるのを避けることもできる:
        :let g:did_install_default_menus = 1
Syntax メニューも避けたい場合:
        :let g:did_install_syntax_menu = 1
Syntax メニューの最初の項目を使用して、使用可能なすべてのファイルタイプをメ
ニューに表示できる (読み込みに少し時間がかかることがある)。起動時にすべてのファ
イルタイプがすでに存在するようにしたい場合、以下を追加する:
        :let g:do_syntax_sel_menu = 1
                                    menu-lazyload g:do_no_lazyload_menus
以下のメニュー項目は、使用可能なすべてのカラースキーム、キーマップおよびコンパ
イラ設定を表示する:
        Edit > Color Scheme
        Edit > Keymap
        Tools > Set Compiler
しかし、それらも読み込みに少し時間がかかることがある。'runtimepath' 内のディレ
クトリから関連するすべてのファイルを検索するからである。そのため、それらは
(CursorHold イベントによって) 遅延して読み込まれるか、または手動で読み込むこ
ともできる。起動時にこれらすべての項目がすでに存在するようにしたい場合、以下を
追加する:
        :let g:do_no_lazyload_menus = 1

Note menu.vim は、:syntax on または :filetype on が実行された時、または
.vimrc ファイルが読み込まれた後に読み込まれることに注意。これは、'encoding' オ
プションおよびメッセージの言語 (:language messages) は、それより前に設定しな
ければならないことを意味する (それらを変更したい場合)。

                                                        console-menus
このドキュメントは GUI のセクションにあるが、実際にはコンソールモードでもメ
ニューを使用できる。その場合、menu.vim を明示的に読み込まなければならない。
デフォルトでは行われない。:emenu コマンド、および 'wildmenu' でのコマンドラ
イン補完を使用して、ほとんど本物のメニューシステムのようにメニューエントリにア
クセスできる。これを行うには、.vimrc ファイルにこれらのコマンドを置く:
        :source $VIMRUNTIME/menu.vim
        :set wildmenu
        :set cpo-=<
        :set wcm=<C-Z>
        :map <F4> :emenu <C-Z>
F4> を押すとメニューが開始する。これでカーソルキーを使用してメニューエントリ
を選択できる。実行するには <Enter> を押す。キャンセルしたい場合は <Esc> を押
す。これにはコンパイル時に +menu 機能が有効になっている必要がある。

                                                        tear-off-menus
GTK+ 2 および Motif は切り離しメニューをサポートしている。これらは一種の固定さ
れたメニュー、または常に存在するポップアップメニューである。サイズ変更が正しく
動作しない場合、これはデフォルト設定で "Vim*geometry" のようなものを使用してい
ることが原因かもしれない。代わりに "Vim.geometry" を使用する。

GTK+ 3 については、切り離しメニューは GTK+ 3.4 から非推奨になっている。それに
応じて、gvim が GTK+ 3.4 以降とリンクされている場合、それらは無効になる。

Win32 GUI 版は Motif の切り離しメニューをエミュレートする。実際には、Motif の
ユーザーは違いに簡単に気付くだろうが、同じくらい便利であればと思う。:tearoff
コマンドを hidden-menus と一緒に使用して、メインメニューバーに表示されないフ
ローティングメニューを作成することもできる。


5.2 新しいメニューの作成                                creating-menus

                                :me  :menu   :noreme  :noremenu
                                E330 E327 E331 E336 E333
                                E328 E329 E337 E792
新しいメニュー項目を作成するには、":menu" コマンド群を使用する。それらはほとん
ど ":map" コマンドのセット (map-modes を参照) と同様だが、最初の引数はメ
ニュー項目名で、メニューおよびサブメニューのパスとして、それらの間に '.' を入
れて与えられる。例:

   :menu File.Save  :w<CR>
   :inoremenu File.Save  <C-O>:w<CR>
   :menu Edit.Big\ Changes.Delete\ All\ Spaces  :%s/[ ^I]//g<CR>

この最後のものは、"Edit" というメニューバーの新しい項目を作成する。この上でマ
ウスボタンを押したままにすると、"Big Changes" という項目を含むメニューがポップ
アップする。それは "Delete All Spaces" という項目を含むサブメニューで、それを
選択すると操作が実行される。

端末モード用のメニューを作成するには、キーマッピング (:tmap) とは異なり、
:tmenu の代わりに :tlmenu を使用する。これは、:tmenu がすでにメニューの
ツールチップを定義するために使用されているからである。terminal-typing を参
照。

メニュー名の中の特殊文字:

                                                        menu-shortcut
        &       次の文字がショートカットキーになる。各ショートカットキーが (サ
                ブ) メニュー内で 1 度だけ使用されるようにすること。メニュー名
                にリテラルの "&" を挿入したい場合は "&&" を使用する。
                                                        menu-text
        <Tab>   メニュー名を右寄せのテキストから区切る。これは同等のタイプする
                コマンドを表示するために使用できる。便宜上、ここではテキスト
                "<Tab>" を使用できる。本物のタブを使用する場合、その前にバック
                スラッシュを置くのを忘れないこと!
例:

   :amenu &File.&Open<Tab>:e  :browse e<CR>

[文字どおりにタイプする]
ショートカット "F" で (<Alt> キーを押したまま)、それから "O" で、このメニュー
を使用できる。2 番目の部分は "Open     :e" と表示される。":e" は右寄せされ、
"O" には下線が引かれて、それがショートカットであることを示す。

                                        :am  :amenu  :an      :anoremenu
":amenu" コマンドは、端末モードを除くすべてのモードのメニューエントリを一度に
定義するために使用できる。コマンドを正しく動作させるために、いくつかのモードで
は文字が自動的に挿入される:
        モード          挿入            追加    
        ノーマル        なし            なし
        ビジュアル      <C-C>           <C-\><C-G>
        挿入            <C-\><C-O>
        コマンドライン  <C-C>           <C-\><C-G>
        オペレータ待機  <C-C>           <C-\><C-G>

CTRL-\ CTRL-G を追加するのは、'insertmode' が設定されている時に挿入モードへ戻
るためである。CTRL-\_CTRL-G

例:

   :amenu File.Next     :next^M

これは以下と等しい:

   :nmenu File.Next     :next^M
   :vmenu File.Next     ^C:next^M^\^G
   :imenu File.Next     ^\^O:next^M
   :cmenu File.Next     ^C:next^M^\^G
   :omenu File.Next     ^C:next^M^\^G

注意: 挿入モードでは、CTRL-O のために、これは単一のノーマルモードコマンドに対
してのみ動作する。2 つ以上のコマンドがある場合、":imenu" コマンドを使用する必
要がある。任意のモードでテキストを挿入するには、式レジスタを使用できる:

   :amenu Insert.foobar   "='foobar'<CR>P

特殊テキスト <Cmd> は "コマンドメニュー" を開始する。それはモードを変えずにコ
マンドを直接実行する。":...<CR>" を使用するかもしれない場所では、代わりに
"<Cmd>...<CR>" を使用できる。詳細は <Cmd> を参照。例:
        anoremenu File.Next <Cmd>next<CR>

Note 'cpoptions' の '<' および 'k' フラグはここでも適用される (含まれている時、
それらは <> 形式および生のキーコードを認識されないようにする) ことに注意。

Note コマンドラインモードでの <Esc> は、マッピングの場合と同様に、コマンドを実
行することに注意。これは Vi 互換である。コマンドラインモードを抜けるには
CTRL-C を使用する。

                :nme :nmenu  :nnoreme :nnoremenu :nunme :nunmenu
"n" で始まるメニューコマンドはノーマルモードで動作する。mapmode-n

                :ome :omenu  :onoreme :onoremenu :ounme :ounmenu
"o" で始まるメニューコマンドはオペレータ待機モードで動作する。mapmode-o

                :vme :vmenu  :vnoreme :vnoremenu :vunme :vunmenu
"v" で始まるメニューコマンドはビジュアルモードで動作する。mapmode-v

                :xme :xmenu  :xnoreme :xnoremenu :xunme :xunmenu
"x" で始まるメニューコマンドはビジュアルモードおよび選択モードで動作する。
mapmode-x

                :sme :smenu  :snoreme :snoremenu :sunme :sunmenu
"s" で始まるメニューコマンドは選択モードで動作する。mapmode-s

                :ime :imenu  :inoreme :inoremenu :iunme :iunmenu
"i" で始まるメニューコマンドは挿入モードで動作する。mapmode-i

                :cme :cmenu  :cnoreme :cnoremenu :cunme :cunmenu
"c" で始まるメニューコマンドはコマンドラインモードで動作する。mapmode-c

                :tlm :tlmenu :tln     :tlnoremenu :tlu   :tlunmenu
"tl" で始まるメニューコマンドは端末モードで動作する。mapmode-t

                                                :menu-<silent> :menu-silent
コマンドラインにエコーされないメニューを定義するには、最初の引数として
"<silent>" を追加する。例:
        :menu <silent> Settings.Ignore\ case  :set ic<CR>
このメニューを使用した時、":set ic" はエコーされない。ただし、実行されたコマン
ドからのメッセージは依然として表示される。それらも黙らせるには、実行されるコマ
ンドに ":silent" を追加する:
        :menu <silent> Search.Header :exe ":silent normal /Header\r"<CR>
"<silent>" は "<special>" または "<script>" の直後に置くこともできる。

                                        :menu-<special> :menu-special
'cpoptions' に "<" フラグが含まれることがあっても、特殊キーに <> 表記を使用し
てメニューを定義する。これは、'cpoptions' を設定することの副作用が望ましくない
場合に役立つ。例:
        :menu <special> Search.Header /Header<CR>
"<special>" は、":menu" コマンドのまさに最初の引数として置くか、または
"<silent>" または "<script>" の直後に置かなければならない。

                                                :menu-<script> :menu-script
メニューの "to" の部分はマッピングについて調べられる。これが不要な場合、
":noremenu" コマンド (または特定のモード用の同様のもの) を使用する。スクリプト
ローカルなマッピングを使用したい場合、":menu" コマンドのまさに最初の引数として
"<script>" を追加するか、または "<silent>" または "<special>" の直後に追加す
る。

                                                        menu-priority
メニューに優先順位を与えることができる。優先順位の高いメニューほど右に置かれ
る。優先順位は ":menu" コマンドの前に数値として与える。例:
        :80menu Buffer.next :bn<CR>

デフォルトのメニューはこれらの優先順位を持つ:
        File            10
        Edit            20
        Tools           40
        Syntax          50
        Buffers         60
        Window          70
        Help            9999

優先順位が与えられないか、または 0 の場合、500 が使用される。
PopUp メニューの優先順位は使用されない。

Help メニューは、これをサポートするシステム (Motif および GTK+) では、メニュー
バーの右端に置かれる。GTK+ 2 および 3 では、Help メニューの右寄せは今では推奨
されない UI デザインなので、これはもう行われない。

Help メニューの後に置くために 9999 より大きい優先順位を使用できるが、それは標
準的ではなく、推奨されない。可能な最大の優先順位は約 32000 である。最小は 1 で
ある。

                                                        sub-menu-priority
同じ仕組みを使用してサブメニューの位置を決めることができる。その場合、優先順位
はメニュー名の前に、ドットで区切られた優先順位のリストとして与えられる:
        :menu 80.500 Buffer.next :bn<CR>
サブメニュー優先順位を与えるのは、項目を通常の位置に置かない時だけ必要である。
例えば、サブメニューを他の項目の前に置くには:
        :menu 80.100 Buffer.first :brew<CR>
または、サブメニューを他の項目の後に置き、デフォルトの優先順位を持つそれ以降の
項目はその前に置かれるようにするには:
        :menu 80.900 Buffer.last :blast<CR>
数値がない場合、デフォルト値の 500 が使用される:
        :menu .900 myMenu.test :echo "text"<CR>
メニュー優先順位は新しいメニューを作成する時にのみ使用される。すでに存在してい
た場合、例えば別のモードで、優先順位は変わらない。したがって、優先順位はメ
ニューが最初に使用される時にだけ与える必要がある。
例外は PopUp メニューである。各モード (ノーマル、オペレータ待機、ビジュアル、

異なっていてもよい。これは、すべてのモードで同じ順序を持つメニューバーのメ
ニューとは異なる。

ない。

メニュー項目は、項目の間にいくらかの空白を挿入する特別な項目で区切ることができ
る。システムによって、これは線または点線として表示される。これらの項目は '-'
で始まり '-' で終わらなければならない。その間の部分は、それに一意の名前を与え
るために使用される。通常の項目と同様に優先順位を使用できる。例:
        :menu Example.item1     :do something

Note 区切りにも rhs が必要であることに注意。項目が選択されることはないので、そ

1)  "icon=" 引数が指定された場合、この名前のファイルが使用される。ファイルはフ
    ルパスまたはベース名で指定できる。後者の場合、ポイント 3 と同様に、

    ファイルを開けない場合、次のポイントが試される。

    り、最も一般的な編集操作をカバーしている builtin-tools。
        :amenu ToolBar.BuiltIn22 :call SearchNext("back")<CR>
3)  別の名前の項目は、まず 'runtimepath' 内の "bitmaps" ディレクトリで検索され
    る。見つかった場合、そのビットマップファイルがツールバーボタンの画像として
    使用される。Note 正確なファイル名は OS 固有であることに注意: 例えば、Win32
    ではコマンド

    は 'hello.bmp' というファイルを見つける。GTK+/X11 では 'Hello.xpm' である。
    GTK+ 2 では、ファイル 'Hello.png'、'Hello.xpm' および 'Hello.bmp' の存在が
    調べられ、最初に見つかったものが使用される。
    MS-Windows および GTK+ 2 では、ビットマップはボタンに合わせて拡大縮小され
    る。MS-Windows では、18 × 18 ピクセルのサイズが最適である。
    MS-Windows では、ビットマップは標準パレットの 16 色である必要がある。明る
    い灰色のピクセルはウィンドウの枠の色に、暗い灰色のピクセルはウィンドウの影
    の色に変更される。システムによっては、より多くの色でも動作するかもしれな
    い。
4)  それでもビットマップが見つからない場合、Vim は組み込みの名前のリストとの
    マッチを調べる。各組み込みボタン画像には名前がある。
    したがって、コマンド

    は、open.bmp が存在しない場合、組み込みの "ファイルを開く" ボタン画像を表
    示する。すべての組み込みの名前は menu.vim で使用されているのを見ることがで
    きる。
5)  他のすべてが失敗した場合、空白の、しかし機能するボタンが表示される。

5.3 メニューが何にマップされているかの表示              showing-menus

既存のメニューが何にマップされているかを見るには、メニューコマンドの後に 1 つ
の引数だけを使用する (":map" コマンドで行うのとまったく同じように)。指定された
メニューがサブメニューの場合、その階層の下のすべてのメニューが表示される。
:menu の後に引数がまったく与えられない場合、該当するモードのすべてのメニュー項
目が表示される (例えば、:cmenu ではコマンドラインモード)。

一覧の中の、rhs の直前にある特殊文字:
*       メニューは再マップを禁止するために "nore" で定義された。
&       メニューはスクリプトローカルなマッピングのみの再マップを許可するために
        "<script>" で定義された。
s       メニューは、起動された時にそれが何にマップされているかを表示しないよう
        に "<silent>" で定義された。
-       メニューは無効化された。

Note メニューコマンドの後にメニュー名を入力している時に <Tab> を押すと、メ
ニュー項目の名前を補完できることに注意。

一覧表示している間にメニューを変更することは許されない。 E1310
これは通常は起こらない。例えば、タイマーコールバックでメニューを定義し、ユー
ザーが more-prompt を表示するような方法でメニューを一覧表示した場合にのみ起
こる。

        :amenu disable &Tools.*

6. フォント

このセクションでは、フォント関連のオプションについて説明する。

GUIFONT                                                 gui-font

'guifont' は、Vim にどのフォントを使用するかを伝えるオプションである。最も単純
な形式では、値は 1 つのフォント名だけである。コンマで区切られたフォント名のリ
ストにすることもできる。最初の有効なフォントが使用される。有効なフォントが見つ
からない時は、エラーメッセージが表示される。

'guifontset' がサポートされているシステム (X11) で 'guifontset' が空でない場
合、'guifont' は使用されない。xfontset を参照。

Note: GTK GUI については、無効な名前に対してエラーは表示されず、リストの最初の
要素が常に選ばれて使用される。これは、GTK GUI は与えられた名前をフォントと同一
視する代わりに、それを使用してパターンを構築し、使用可能なフォントの中からその
パターンに最もよくマッチするフォントを探そうとするからであり、このようにして
マッチは決して失敗しない。名前以外のいくつかのフォントプロパティでマッチングが
行われるので、無効な名前は問題にならない。

コンマの後のスペースは無視される。フォント名にコンマを含めるには、その前にバッ
クスラッシュを置く。オプションを設定するには、スペースおよびバックスラッシュの
前に追加のバックスラッシュが必要である。option-backslash も参照。例えば:
    :set guifont=Screen15,\ 7x13,font\\,with\\,commas
これにより、Vim はまずフォント "Screen15" を使用しようとし、それが失敗した場
合、代わりに "7x13"、それから "font,with,commas" を使用しようとする。

どのフォントも読み込めない場合、Vim は現在の設定を維持する。空のフォントリスト
が与えられた場合、Vim は他のリソース設定を使用しようとし (X では、Vim.font リ
ソースを使用する)、最後に常に存在するはずの組み込みのデフォルト (X の場合は
"7x13") を試す。与えるフォント名は "通常の" フォントであるべきである。Vim は関
連する太字およびイタリックのフォントを見つけようとする。

Win32、GTK、Motif、Mac OS および Photon では:
    :set guifont=*
フォント選択ダイアログが表示され、そこで好きなフォントを選択できる。

フォント名は使用する GUI に依存する。さまざまなシステムで 'guifont' を設定する
方法については、setting-guifont を参照。

GTK+ 2 および 3 GUI では、フォント名はこのようになる:
    :set guifont=Andale\ Mono\ 11
それだけである。XLFD は使用されない。中国語では、これがうまく動作すると報告さ
れている:
    if has("gui_gtk2")
      set guifont=Bitstream\ Vera\ Sans\ Mono\ 12,Fixed\ 12
      set guifontwide=Microsoft\ Yahei\ 12,WenQuanYi\ Zen\ Hei\ 12
    endif

(GTK+ 3 GUI では gui_gtk2 を gui_gtk3 に置き換える)

Mac OSX では、このようなものを使用できる:
    :set guifont=Monaco:h10

等幅フォント                                            E236

Note フォントは等幅 (すべての文字が同じ幅を持つ) でなければならないことに注意。
例外は GTK である: すべてのフォントが受け入れられるが、等幅フォントが最もよく
見える。

X11 でフォントをプレビューするには、"xfontsel" プログラムを使用できるかもしれ
ない。"xlsfonts" プログラムは、使用可能なすべてのフォントの一覧を表示する。

Win32 GUI の場合                                        E244 E245
- フォント名の中でこれらのオプションを受け付ける (オプションを区切るには ':'
  を使用する):
        hXX - 高さが XX (ポイント、浮動小数点数も可)
        wXX - 幅が XX (ポイント、浮動小数点数も可)
        WXX - ウェイトが XX (以下のウェイトについての注意を参照)
        b   - 太字。これはウェイトを 700 に設定するのと同等である。
        i   - イタリック
        u   - 下線
        s   - 取り消し線
        cXX - 文字セット XX。有効な文字セットは ANSI、ARABIC、BALTIC、
              CHINESEBIG5、DEFAULT、EASTEUROPE、GB2312、GREEK、HANGEUL、
              HEBREW、JOHAB、MAC、OEM、RUSSIAN、SHIFTJIS、SYMBOL、THAI、
              TURKISH および VIETNAMESE である。通常は "cDEFAULT" を使用する。
        qXX - 品質 XX。有効な品質名は PROOF、DRAFT、ANTIALIASED、
              NONANTIALIASED、CLEARTYPE および DEFAULT である。通常は
              "qDEFAULT" を使用する。
              いくつかの品質値は古い OS ではサポートされていない。
        fXX - OpenType フォント機能。1 つの機能を tag=value として指定する。こ
              こで tag は 4 文字の OpenType 機能タグで、value はパラメーター
              (0 で無効、1 以上で有効化/バリアントの選択) である。":f" オプショ
              ンを繰り返すことで、複数の機能を指定できる。
              これは 'renderoptions' が DirectWrite (type:directx) を使用する
              ように設定されている場合にのみ効果がある。デフォルトの機能
              (calt、liga など) は、明示的に上書きされない限り保持される。
              例: ":fss19=1:fcalt=0" は Stylistic Set 19 を有効にし、
              Contextual Alternates を無効にする。
- スペースの代わりに '_' を使用できるので、スペースをエスケープするためにバッ
  クスラッシュを使用する必要はない。
例:
    :set guifont=courier_new:h12:w5:b:cRUSSIAN
    :set guifont=Andale_Mono:h7.5:w4.5
    :set guifont=Cascadia_Code:h14:fss19=1:fcalt=1:fliga=1

font-sizes、'guiligatures' および 'renderoptions' (MS-Windows のみ) も参照。

ウェイトについての注意: フォントには多くの場合、さまざまなウェイトがある。
Windows での "Normal" ウェイトは 400 の値を持ち、指定されない場合、これがフォ
ントを見つけようとする時に使用される値である。Windows はしばしばフォント名より
も高い優先順位でウェイトに基づいてフォントをマッチさせる。これは、Light または
ExtraLight のバリアントを指定しても、フォントの Book または Medium のバリアン
トが使用されるかもしれないことを意味する。より重いウェイトの置き換えが起こって
いる場合、明示的により低いウェイト値を設定することで、この望ましくない置き換え
を軽減できるかもしれない。


GUIFONTWIDE                                             gui-fontwide

空でない時、'guifontwide' は倍幅文字に使用されるフォントのコンマ区切りのリスト
を指定する。読み込むことができる最初のフォントが使用される。

Note: これらのフォントのサイズは、'guifont' で指定されたフォントのちょうど 2
倍の幅で、同じ高さでなければならない。不一致がある場合、テキストは正しく描画さ
れない。

GTK+ 以外のすべての GUI バージョン:

'guifontwide' は、'encoding' が "utf-8" に設定され、'guifontset' が空または無
効な場合にのみ使用される。
'guifont' が設定され、その中に有効なフォントが見つかり、'guifontwide' が空の
時、Vim はマッチする倍幅フォントを見つけて、それを 'guifontwide' に設定しよう
とする。

GTK+ GUI のみ:                          guifontwide_gtk

設定されていて有効な場合、'encoding' が "utf-8" に設定されていなくても、
'guifontwide' は常に倍幅文字に使用される。
Vim は 'guifontwide' の適切な値を自動的に見つけようとはしない。'guifontwide'
が空の場合、Pango/Xft が 'guifont' で使用可能でない文字のフォントを選択する。
したがって、Pango/Xft による選択を上書きしたい場合を除き、'guifontwide' を設定
する必要はまったくない。

Windows +multi_byte_ime のみ:         guifontwide_win_mbyte

設定されていて有効な場合、'guifontwide' は 'guifont' の代わりに IME に使用され
る。

7. 追加機能                                             gui-extras

このセクションでは、GUI に関連するその他の機能について説明する。

- GUI では、エスケープを押した後に 1 秒待つことはない。キーコードが <Esc> で始
  まらないからである。

- GUI で ^V に続けて特殊キーをタイプすると、"<Key>" が挿入される。使用される内
  部文字列には意味がないからである。修飾キーを押したままにして
  "<Modifiers-Key>" を得ることもできる。

- GUI では、特殊キーおよびマウスイベントのマッピングの中で、修飾キー SHIFT、
  CTRL および ALT (または META) を使用できる。
  例: :map <M-LeftDrag> <LeftDrag>

- GUI では、いくつかの通常のキーはマッピングなどで修飾キーを持つことができる。
  それらは <Space>、<Tab>、<NL>、<CR>、<Esc> である。

- Vim script で GUI が使用されているかどうかを確認するには、このようなものを使
  用できる:

        if has("gui_running")
           echo "yes, we have a GUI"
        else
           echo "Boring old console"
        endif
                                                        setting-guifont
- 同じ vimrc ファイルをさまざまなシステムで使用する時、このようなものを使用し
  て、GUI の種類ごとに固有のオプションを設定できる:

        if has("gui_running")
            if has("gui_gtk")
                :set guifont=Luxi\ Mono\ 12
            elseif has("x11")
                :set guifont=*-lucidatypewriter-medium-r-normal-*-*-180-*-*-m-*-*
            elseif has("gui_win32")
                :set guifont=Luxi_Mono:h12:cANSI
            endif
        endif

推奨される日本語フォントは MS 明朝である。ここで情報を見つけることができる:
https://learn.microsoft.com/en-us/typography/font-list/ms-mincho
それは Windows と一緒に配布されているはずである。


フルスクリーン                                          gui-fullscreen

フルスクリーンモードは現在、Vim の Windows および GTK GUI 版でのみサポートされ
ている。

Vim の GUI 版でフルスクリーンモードを有効にするには、'guioptions' の設定に "s"
フラグを追加する。

便宜上、フルスクリーンモードを切り替えるコマンドまたはマッピングを定義できる:

        command ToggleFullscreen {
          if &guioptions =~# 's'
            set guioptions-=s
          else
            set guioptions+=s
          endif
        }

        map <expr> <F11> &go =~# 's' ? ":se go-=s<CR>" : ":se go+=s<CR>"

フルスクリーンモードは、タイトルバーおよびボーダーなどのウィンドウ装飾を隠しな
がら、画面領域全体を占める。

8. シェルコマンド                                       gui-shell

X11 GUI では、外部コマンドは gvim ウィンドウの中で実行される。gui-pty を参
照。

警告: X11 GUI から外部コマンドを実行することは、常に動作するとは限らない。
"ls"、"grep" および "make" のような "通常の" コマンドはたいていうまく動作する。
"less" および "ispell" のような高機能な端末を必要とするコマンドは動作しない。
ハングして別の端末から kill する必要があるものさえある。だから注意すること!

Win32 GUI では、外部コマンドは別のウィンドウで実行される。gui-shell-win32 を
参照。
