30.1  コンパイルする

Vim には、いわゆる "quickfix" コマンドの一群があります。これらにより、Vim の中
からプログラムをコンパイルし、それから生成されたエラーを順に見ていき、それらを
(うまくいけば) 修正することができます。その後、最終的にあなたのプログラムがエ
ラーなしでコンパイルされるまで、再コンパイルし、見つかった新しいエラーを修正す
ることができます。

以下のコマンドは、プログラム "make" を (あなたが与えた任意の引数を渡して) 実行
し、その結果を取り込みます:

        :make {arguments}

エラーが生成された場合、それらは取り込まれ、エディタは最初のエラーが発生した場
所にあなたを位置付けます。
   ":make" セッションの例を見てください。(典型的な :make セッションでは、はる
かに多くのエラーが生成され、愚かなエラーはより少なくなります。) ":make" をタイ
プした後、画面はこのようになります:

        :!make | &tee /tmp/vim215953.err
        gcc -g -Wall -o prog main.c sub.c
        main.c: In function 'main':
        main.c:6: too many arguments to function 'do_sub'
        main.c: At top level:
        main.c:10: parse error before '}'
        make: *** [prog] Error 1

        2 returned
        "main.c" 11L, 111C
        (3 of 6): too many arguments to function 'do_sub'
        Press ENTER or type command to continue

ここから、ファイル "main.c" にエラーがあることがわかります。<Enter> を押すと、
Vim はファイル "main.c" を表示し、カーソルはエラーのある最初の行である 6 行目
に置かれます。ファイルまたは行番号を指定する必要はありませんでした、Vim はエ
ラーメッセージの中を見ることで、どこへ行けばよいかを知っていました。

                +---------------------------------------------------+
                |int main()                                         |
                |{                                                  |
                |       int i=3;                                    |
      cursor -> |       do_sub("foo");                              |
                |       ++i;                                        |
                |       return (0);                                 |
                |}                                                  |
                |}                                                  |
                | ~                                                 |
                |(3 of 12): too many arguments to function 'do_sub' |
                +---------------------------------------------------+

以下のコマンドは、次のエラーが発生する場所へ移動します:

        :cnext

Vim は、余分な '}' がある、ファイルの最後の行である 10 行目へジャンプします。
   十分な場所がない場合、Vim はエラーメッセージを短くします。メッセージ全体を
見るには、以下を使います:

        :cc

":clist" コマンドで、すべてのエラーメッセージの概要を得ることができます。出力
はこのようになります:

        :clist
        3 main.c: 6:too many arguments to function 'do_sub'
        5 main.c: 10:parse error before '}'

ここには、Vim がファイル名および行番号を認識した行だけが一覧表示されます。それ
は、それらが興味深い行であり、残りは単に退屈なメッセージであると仮定します。し
かし、認識されなかった行に、あなたが見たいものが含まれていることも時々ありま
す。例えば、未定義の関数についてのリンカからの出力。
すべてのメッセージを見るには、コマンドに "!" を追加します:

        :clist!
        1 gcc -g -Wall -o prog main.c sub.c
        2 main.c: In function 'main':
        3 main.c:6: too many arguments to function 'do_sub'
        4 main.c: At top level:
        5 main.c:10: parse error before '}'
        6 make: *** [prog] Error 1

Vim は現在のエラーをハイライトします。前のエラーに戻るには、以下を使います:

        :cprevious

エラーリストの中を移動するための他のコマンド:

        :cfirst         最初のエラーへ
        :clast          最後のエラーへ
        :cc 3           エラー番号 3 へ


別のコンパイラを使う

":make" コマンドが実行されたときに実行するプログラムの名前は、'makeprg' オプ
ションで定義されます。通常、これは "make" に設定されていますが、Visual C++ の
ユーザーは、以下のコマンドを実行することで、これを "nmake" に設定すべきです:

        :set makeprg=nmake

このオプションには引数を含めることもできます。特殊文字はバックスラッシュでエス
ケープする必要があります。例:

        :set makeprg=nmake\ -f\ project.mak

コマンドの指定には、Vim の特別なキーワードを含めることができます。% 文字は、カ
レントファイルの名前に展開されます。したがって、このコマンドを実行した場合:
        :set makeprg=make\ %:S

main.c を編集しているとき、":make" は以下のコマンドを実行します:

        make main.c

これはあまり便利ではないので、コマンドを少し改良して、:r (root) 修飾子を使いま
す:

        :set makeprg=make\ %:r:S.o

これで、実行されるコマンドは以下のとおりです:

        make main.o

これらの修飾子についての詳細はここ: filename-modifiers。


古いエラーリスト

プログラムを ":make" したとします。あるファイルには警告メッセージがあり、別の
ファイルにはエラーメッセージがあります。エラーを修正し、それが本当に修正された
かを確認するために、再び ":make" を使います。ここで、警告メッセージを見たいで
す。警告のあるファイルは再びコンパイルされなかったので、それは最後のエラーリス
トには現れません。以下で、前のエラーリストに戻ることができます:

        :colder

それから、":clist" および ":cc {nr}" を使って、警告のある場所へジャンプします。
   次のエラーリストへ進むには:

        :cnewer

Vim は 10 個のエラーリストを記憶します。


コンパイラを切り替える

あなたのコンパイラが生成するエラーメッセージがどんな形式なのかを、Vim に伝える
必要があります。これは 'errorformat' オプションで行います。このオプションの構
文はかなり複雑で、ほとんどすべてのコンパイラに合うようにすることができます。説
明はここで見つけることができます: errorformat。

あなたはさまざまな異なるコンパイラを使っているかもしれません。'makeprg' オプ
ション、および特に 'errorformat' を毎回設定するのは簡単ではありません。Vim は
このための簡単な方法を提供しています。例えば、Microsoft Visual C++ コンパイラ
の使用に切り替えるには:

        :compiler msvc

これは "msvc" コンパイラ用の Vim script を見つけ、適切なオプションを設定しま
す。
   あなた自身のコンパイラファイルを書くことができます。write-compiler-plugin
を参照してください。


出力リダイレクト

":make" コマンドは、実行されたプログラムの出力をエラーファイルにリダイレクトし
ます。これがどのように動作するかは、'shell' などのさまざまなことに依存します。
あなたの ":make" コマンドが出力を取り込まない場合、'makeef' および 'shellpipe'
オプションを確認してください。'shellquote' および 'shellxquote' オプションも関
係するかもしれません。

":make" にあなたのためにファイルをリダイレクトさせることができない場合、代替案
は、別のウィンドウでプログラムをコンパイルし、出力をファイルにリダイレクトする
ことです。それから、以下で Vim にこのファイルを読み込ませます:

        :cfile {filename}

エラーへのジャンプは、":make" コマンドと同じように動作します。

30.2  C スタイルのテキストをインデントする

行が適切にインデントされていると、プログラムははるかに理解しやすくなります。
Vim は、これの手間を減らすさまざまな方法を提供しています。C、または Java また
は C++ のような C スタイルのプログラムには、'cindent' オプションを設定します。
Vim は C プログラムについて多くのことを知っていて、あなたのためにインデントを
自動的に設定しようと非常に努力します。'shiftwidth' オプションを、より深いレベ
ルに対してあなたが欲しいスペースの量に設定します。4 つのスペースでうまく動作し
ます。1 つの ":set" コマンドでそれができます:

        :set cindent shiftwidth=4

このオプションを有効にすると、"if (x)" のようなものをタイプしたとき、次の行は
自動的に 1 レベル追加でインデントされます。

                                    if (flag)
        自動インデント   --->           do_the_work();
        自動インデント解除 <--      if (other_flag) {
        自動インデント   --->           do_file();
        インデント維持                  do_some_more();
        自動インデント解除 <--      }

波括弧 ({}) の中に何かをタイプすると、テキストは始めでインデントされ、終わりで
インデント解除されます。Vim はあなたが何をタイプしようとしているかを推測できな
いので、インデント解除は '}' をタイプした後に行われます。

自動インデントの副作用の 1 つは、あなたのコードのエラーを早期に見つけるのに役
立つことです。関数を終えるために } をタイプしたのに、自動インデントがそれにあ
なたが予期したより多くのインデントを与えるのがわかったときは、おそらく } が欠
けています。"%" コマンドを使って、どの { がタイプした } にマッチするかを調べて
ください。
   欠けている ) および ; も余分なインデントを引き起こします。したがって、予期
するより多くの空白が得られた場合、前の行を確認してください。

不適切に整形されたコードがあるとき、または行を挿入および削除したときは、行を再
インデントする必要があります。"=" オペレータがこれを行います。最も単純な形式は:


        ==

これは現在の行をインデントします。すべてのオペレータと同様に、それを使う方法は
3 つあります。ビジュアルモードでは、"=" は選択された行をインデントします。便利
なテキストオブジェクトは "a{" です。これは現在の {} ブロックを選択します。した
がって、カーソルがあるコードブロックを再インデントするには:

        =a{

本当にひどくインデントされたコードがある場合、以下でファイル全体を再インデント
できます:

        gg=G

しかし、手動で注意深くインデントされたファイルでは、これを行わないでください。
自動インデントはよい仕事をしますが、状況によってはそれを覆したいかもしれませ
ん。


インデントスタイルを設定する

人によってインデントのスタイルは異なります。既定では、Vim はプログラマの 90%
が行う方法で、かなりうまくインデントします。しかし、異なるスタイルがあります;
したがって、そうしたい場合、'cinoptions' オプションでインデントスタイルをカス
タマイズできます。
   既定では 'cinoptions' は空で、Vim は既定のスタイルを使います。何か違うもの
が欲しいところに、さまざまな項目を追加できます。例えば、波括弧がこのように配置
されるようにするには:

        if (flag)
          {
            i = 8;
            j = 0;
          }

このコマンドを使います:

        :set cinoptions+={2

これらの項目はたくさんあります。cinoptions-values を参照してください。

30.3  自動インデント

C ファイルを編集するたびに、手動で 'cindent' オプションをオンにしたくはありま
せん。これが、それを自動的に動作させる方法です:

        :filetype indent on

実際には、これは C ファイルに対して 'cindent' をオンにするよりもはるかに多くの
ことを行います。まず第一に、ファイルのタイプの検出を有効にします。それは構文ハ
イライトに使われるものと同じです。
   ファイルタイプがわかると、Vim はこのタイプのファイル用のインデントファイル
を検索します。Vim の配布物には、さまざまなプログラミング言語用のこれらがいくつ
か含まれています。それから、このインデントファイルが、特にこのファイル用の自動
インデントを準備します。

自動インデントが気に入らない場合、再びそれをオフに切り替えることができます:

        :filetype indent off

ある特定のタイプのファイルのインデントが気に入らない場合、これがそれを避ける方
法です。この 1 行だけを含むファイルを作成します:

        :let b:did_indent = 1

ここで、これを特定の名前のファイルに書く必要があります:

        {directory}/indent/{filetype}.vim

{filetype} は、"cpp" または "java" のようなファイルタイプの名前です。Vim が検
出した正確な名前は、このコマンドで見ることができます:

        :set filetype

このファイルでは、出力は:

        filetype=help

したがって、{filetype} には "help" を使うことになります。
   {directory} の部分には、あなたのランタイムディレクトリを使う必要があります。
このコマンドの出力を見てください:

        set runtimepath

ここで、最初の項目である、最初のコンマの前の名前を使います。したがって、出力が
このようになっている場合:

        runtimepath=~/.vim,/usr/local/share/vim/vim60/runtime,~/.vim/after

{directory} には "~/.vim" を使います。そうすると、結果のファイル名は:

        ~/.vim/indent/help.vim

インデントをオフに切り替える代わりに、あなた自身のインデントファイルを書くこと
もできます。その方法はここで説明されています: indent-expression。

30.4  その他のインデント

自動インデントの最も単純な形式は、'autoindent' オプションによるものです。
それは前の行のインデントを使います。少し賢いのは 'smartindent' オプションです。
これは、インデントファイルが使用可能でない言語に役立ちます。'smartindent' は
'cindent' ほど賢くはありませんが、'autoindent' よりは賢いです。
   'smartindent' が設定されていると、{ ごとにインデントが 1 レベル追加され、}
ごとに削除されます。'cinwords' オプション内のいずれかの単語に対しても、インデ
ントが 1 レベル追加されます。# で始まる行は特別に扱われます: すべてのインデン
トが削除されます。これは、プリプロセッサ指令がすべて 1 桁目から始まるようにす
るために行われます。インデントは次の行で復元されます。


インデントを修正する

'autoindent' または 'smartindent' を使って前の行のインデントを得ているとき、1
'shiftwidth' 分のインデントを追加または削除する必要があることが何度もあるでしょ
う。これを素早く行う方法は、挿入モードで CTRL-D および CTRL-T コマンドを使うこ
とです。
   例えば、あなたは、このように見えるはずのシェルスクリプトをタイプしています:

        if test -n a; then
           echo a
           echo "-------"
        fi

これらのオプションを設定することから始めます:

        :set autoindent shiftwidth=3

最初の行、<Enter>、および 2 行目の始めをタイプすることから始めます:

        if test -n a; then
        echo

ここで、余分なインデントが必要だとわかります。CTRL-T をタイプします。結果:

        if test -n a; then
           echo

CTRL-T コマンドは、挿入モードで、行のどこにいるかに関係なく、インデントに 1
'shiftwidth' を追加します。
   2 行目、<Enter>、および 3 行目をタイプし続けます。今回はインデントは OK で
す。それから <Enter> および最後の行。これで、このようになっています:

        if test -n a; then
           echo a
           echo "-------"
           fi

最後の行の余分なインデントを削除するには、CTRL-D を押します。これは、行のどこ
にいるかに関係なく、1 'shiftwidth' 分のインデントを削除します。
   ノーマルモードにいるときは、">>" および "<<" コマンドを使って行をシフトでき
ます。">" および "<" はオペレータなので、インデントしたい行を指定する通常の 3
つの方法があります。便利な組み合わせは:

        >i{

これは、{} の内側の、現在の行ブロックに 1 つのインデントを追加します。{ および
} の行自体は変更されないままです。">a{" はそれらを含みます。この例では、カーソ
ルは "printf" の上にあります:

        元のテキスト            ">i{" の後              ">a{" の後

        if (flag)               if (flag)               if (flag)
        {                       {                           {
        printf("yes");              printf("yes");          printf("yes");
        flag = 0;                   flag = 0;               flag = 0; 
        }                       }                           }

30.5  タブとスペース

タブの背後にある設計意図の手短な歴史

vi (Vim の祖先) は Bill Joy によって作られました。当時、彼は限られたメモリお
よび I/O 操作能力を持つ PDP-11 を使っていました。その頃は、以下のトリックでソー
スコードのサイズを最適化するのが一般的でした。
  ASCII 表は、最初はテレプリンターを遠隔制御するために設計されました。制御文字
9 (水平タブ、キャレット記法: ^I) がテレプリンターに送られると、それはキャリッ
ジを次のタブストップへ移動させました。タブストップが 8 桁ごとに区切られている
(典型的な標準) と仮定すると、これは、1 つの制御文字が最大 8 個の空白文字と同じ
見た目の効果を生み出せたことを意味します。例えば、以下の 2 行は同じように表示
されます

        1234^I9
        1234    9

Tab> キーを使うことは、<Space> を何回かタイプするより速くもありました; 同じこ
とが <BS> にも当てはまりました。


タブとインデントの問題

Vim では、2 つの (仮想の) 水平タブストップの間の桁数は 'tabstop' で制御され、
既定では 8 に設定されています。それを変更することはできますが、後ですぐに問題
に遭遇します。他のプログラムは、あなたがどの tabstop 値を使ったかを知りません。
それらはおそらく既定値の 8 を使い、あなたのテキストは突然大きく違って見えます。
また、ほとんどのプリンターは 8 の固定の tabstop 値を使います。したがって、
'tabstop' はそのままにしておくのが最善です; 異なる tabstop 設定で書かれたファ
イルを編集する場合、それを直す方法については 25.3 を参照してください。
   プログラムの行をインデントするのに 8 桁の倍数を使うと、すぐにウィンドウの右
のボーダーにぶつかります。1 つのスペースを使うのでは、見た目に十分な違いが出ま
せん。多くの人は、よい妥協点である 4 つのスペースを使うことを好みます。
   行頭のタブ文字は見た目上 8 つのスペースとして表現され、あなたは 4 つのスペー
スのインデントを使いたいので、あなたのインデントを作るのにタブ文字を使うことは
できません。
  これを解決するために、vi には 'shiftwidth' オプションがありました。4 に設
定されていると、新しい行で、挿入モードで <C-t> を押すと、行は 4 つのスペースで
インデントされ、<Tab> キーおよび 8 に設定された 'tabstop' では得られない結果で
した。
 容量を最適化するために、vi はまた、ひとかたまりのスペースを黙って削除し、そ
れらをタブ文字で置き換えていました。以下は、<C-t> を何回か押すと何が起こるかを
示しています。
  "." はスペース文字を表し、"------->" はタブ文字を表します。

        タイプ                          結果
        <C-t>                           ....
        <C-t><C-t>                      ------->
        <C-t><C-t><C-t>                 ------->....

  同様に、挿入モードで <C-d> を押すとインデントが減りました。したがって、
set tabstop=8 shiftwidth=2 で得られるのは

        タイプ                          結果
        <C-t><Tab><C-t>                 ..----->..
        <C-t><Tab><C-t><C-d>            ------->

  vi で設定できた 3 つ目のオプションは 'autoindent' でした。それは前の行のイ
ンデントレベルをコピーします、

        タイプ                          結果
        <Space><Tab>hello               .------>hello
        <Space><Tab>hello<Enter>        .------>hello
                                        ------->

しかし、新しい行は、使われる文字数を最適化することで生成されます。


スペースだけ

しかし、タブストップを 8 桁で区切ることは普遍的ではありませんでした: IBM には
10 桁の標準があり、今日では一部の Go 開発者は tabstop=4 でコードを書いていま
す。テキストが異なる 'tabstop' 値で表示されるたびに、特にファイルが共有されて
別のマシンで開かれると、テキストの位置がずれる危険があります。
  その間に、コンピュータははるかによくなり、タブを使うことで節約される数オク
テットは、もはや実質的な違いを生まなくなっていました。スペースだけを使い、それ
によってどこでも同じ結果のテキストを保証することが可能になりました。しかし、
vi では、機能を犠牲にせずにスペースだけを使うことは不可能でした。
'autoindent' は、可能なときには体系的にタブ文字を入力しようとしたことを思い出
してください。
  Vim 4.0 は、'expandtab' オプションを導入することで、スペースだけで作業するこ
とを、タブだけ (またはタブおよびスペースの混在) で作業するのと同じくらい便利に
しました。設定されていると、Vim は、通常挿入するはずのすべての水平タブ文字を同
等の数のスペースで置き換え、最終的に同じ見た目の効果になるようにします。<BS>
は引き続き一度に 1 文字だけを削除しました。

        タイプ                          結果
        <Tab>                           ........
        <Tab><BS>                       .......


タブをスペースに変更する (および戻す)

'expandtab' を設定しても、既存のタブ文字にすぐには影響しません。ファイルからす
べての水平タブ文字を一掃するために、Vim 5.3 は :retab コマンドを導入しまし
た。これらのコマンドを使います:

        :set expandtab
        :retab

これは、文字列の中のタブも変更する可能性があるので、少し危険です。これらが存在
するかどうかを確認するには、これを使うことができます:

        /"[^"\t]*\t[^"]*"

文字列の中で実際のタブ文字を使わないことが推奨されます。トラブルを避けるため
に、それらを "\t" で置き換えてください。

  逆方向も同じようにうまく動作します:

        :set noexpandtab
        :retab!


ソフトタブストップ

スペースだけ、またはスペースおよび水平タブの混在を使うと、<Tab> および <BS> の
2 つのキーが、タブ文字だけを使うときのようには鏡のように振る舞わないという、不
快な感じを受けます。
  Vim 5.4 は 'softtabstop' オプションを導入しました。テキスト内の水平タブ文字
を表示するのに使われる (ハード) タブストップに加えて、Vim はカーソル専用の追加
のソフトタブストップを加えます。'softtabstop' が正の値に設定されていると、
<Tab> キーはカーソルを次のソフトタブストップへ押し進めます。Vim は、この効果を
達成するために、タブ文字およびスペースの正しい組み合わせを挿入します。同様に、
<BS> を押すと、カーソルは最も近いソフトタブストップに到達しようとします。以下
の例は :set softtabstop=4 を使います

        タイプ                  結果
        <Tab>                   ....
        <Tab><Tab>a             ------->a
        <Tab><Tab>a<Tab>        ------->a...
        <Tab><Tab>a<Tab><BS>    ------->a

  全体の一貫性を保つために、:set softtabstop=-1 とすることで、2 つのソフトタ
ブストップの間の桁数に 'shiftwidth' の値が使われるようにできます。

  'shiftwidth' および 'softtabstop' に異なる値を持たせるほうが好みの場合、それ
でもそうすることができ、'shiftwidth' でインデントするには <C-t> を使います。ま
たは、'smarttab' オプションを使って、異なる状況で何をすべきかを知っている統一
された <Tab> キーを可能にすることもできます。


可変タブストップ

前に述べたように、ASCII 表はテレプリンターを遠隔制御するために設計されました。
ある特定のテレプリンターは、その物理的なタブストップの間隔を可変にするように構
成できました。結局のところ、^I 制御文字は単に規定していただけでした: 次のタブ
ストップへ、それがどこにあっても行く。
  Vim 7.3 は、同じ機能をエミュレートするために 'vartabstop' を導入しました。例
えば、Vim が +vartabs 付きでコンパイルされていて、:set vartabstop=2,4 とし
た場合、得られるのは

        実際の文字      結果
        ^I                      ->
        ^I^I                    ->--->
        ^I^I^I                  ->--->--->

  同様に、可変間隔のソフトタブストップを持つために、'varsofttabstop' も導入さ
れました。:set varsofttabstop=2,4 で得られるのは

        タイプ                    結果
        <Tab>                     ..
        <Tab><Tab>                ......
        <Tab><Tab><Tab>           ------->....


設定の例

既定では、Vim はタブだけを使うように構成されています:

        :set tabstop=8
        :set shiftwidth=8
        :set noexpandtab
        :set softtabstop=0
        :set nosmarttab

  C のコードを Python であるかのように (スペースだけ、4 つのスペースのインデン
トで) 書きたい場合、使えるのはこれです:

        :set shiftwidth=4
        :set softtabstop=-1
        :set expandtab

  同じ動作だが、位置揃えをよりうまく制御したい (例えば、パラメータまたはコメン
トを 2 つのスペースの倍数で揃える) 場合、以下を使います:

        :set shiftwidth=4
        :set softtabstop=2
        :set expandtab
        :set smarttab

  代わりに、Bram Moolenaar が書いたであろうように (タブおよびスペースの混在を
使って) C のコードを書きたい場合、以下を使うことができます

        :set shiftwidth=4
        :set softtabstop=-1

30.6  コメントを整形する

Vim の素晴らしい点の 1 つは、コメントを理解することです。Vim にコメントを整形
するように頼むことができ、Vim は正しいことを行います。
   例えば、以下のコメントがあるとします:

        /*
         * This is a test
         * of the text formatting.
         */

それから、カーソルをコメントの先頭に置いてタイプすることで、Vim にそれを整形す
るように頼みます:

        gq]/

"gq" はテキストを整形するオペレータです。"]/" はコメントの終わりへ移動するモー
ションです。結果は:

        /*
         * This is a test of the text formatting.
         */

Vim が各行の先頭を正しく扱ったことに注目してください。
  代わりの方法は、整形するテキストをビジュアルモードで選択して "gq" をタイプす
ることです。

コメントに新しい行を追加するには、カーソルを真ん中の行に置いて "o" を押します。
結果はこのようになります:

        /*
         * This is a test of the text formatting.
         *
         */

Vim はあなたのために星印およびスペースを自動的に挿入しました。これで、コメント
テキストをタイプできます。それが 'textwidth' より長くなると、Vim は行を折り返
します。ここでも、星印は自動的に挿入されます:

        /*
         * This is a test of the text formatting.
         * Typing a lot of text here will make Vim
         * break
         */

これが動作するには、'formatoptions' にいくつかのフラグが存在しなければなりませ
ん:

        r       挿入モードで <Enter> をタイプしたときに星印を挿入する
        o       ノーマルモードで "o" または "O" を使ったときに星印を挿入する
        c       'textwidth' に従ってコメントテキストを折り返す

その他のフラグについては fo-table を参照してください。


コメントを定義する

'comments' オプションは、コメントがどのように見えるかを定義します。Vim は、1
行コメントと、異なる始め、終わり、および中間部分を持つコメントを区別します。
   多くの 1 行コメントは特定の文字で始まります。C++ では // が使われ、Makefile
では #、Vim script では " です。例えば、Vim に C++ のコメントを理解させるには:


        :set comments=://

コロンは、項目のフラグを、コメントが認識されるテキストから区切ります。
'comments' の項目の一般的な形式は:

        {flags}:{text}

{flags} の部分は、この場合のように空にできます。
   これらの項目のいくつかを、コンマで区切って連結できます。これにより、異なる
タイプのコメントを同時に認識できます。例えば、電子メールのメッセージを編集しま
しょう。返信するとき、他の人が書いたテキストの前には ">" および "!" 文字が付い
ています。このコマンドが動作するでしょう:

        :set comments=n:>,n:!

2 つの項目があり、1 つは ">" で始まるコメント用、もう 1 つは "!" で始まるコメ
ント用です。両方ともフラグ "n" を使います。これは、これらのコメントが入れ子に
なることを意味します。したがって、">" で始まる行は、">" の後に別のコメントを持
つことができます。これにより、このようなメッセージを整形できます:

        > ! Did you see that site?
        > ! It looks really great.
        > I don't like it.  The
        > colors are terrible.
        What is the URL of that
        site?

'textwidth' を別の値、例えば 80 に設定し、テキストをビジュアル選択して "gq" を
タイプすることで整形してみてください。結果は:

        > ! Did you see that site?  It looks really great.
        > I don't like it.  The colors are terrible.
        What is the URL of that site?

Vim が、あるタイプのコメントから別のタイプへテキストを移動しなかったことに気付
くでしょう。2 行目の "I" は 1 行目の末尾に収まったはずですが、その行は "> !"
で始まり、2 行目は ">" で始まるので、Vim はこれが異なる種類のコメントであるこ
とを知っています。


3 部分からなるコメント

C のコメントは "/*" で始まり、中間に "*" を持ち、終わりに "*/" があります。こ
のための 'comments' の項目はこのようになります:

        :set comments=s1:/*,mb:*,ex:*/

始めは "s1:/*" で定義されます。"s" は 3 部分からなるコメントの始めを示します。
コロンは、フラグを、コメントが認識されるテキストから区切ります: "/*"。フラグは
1 つあります: "1"。これは Vim に、中間部分が 1 スペースのオフセットを持つこと
を伝えます。
   中間部分 "mb:*" は "m" で始まり、これはそれが中間部分であることを示します。
"b" フラグは、テキストの後に空白が続かなければならないことを意味します。そうで
ないと、Vim は "*pointer" のようなテキストもコメントの中間とみなしてしまいま
す。
   終わりの部分 "ex:*/" には、識別のための "e" があります。"x" フラグには特別
な意味があります。それは、Vim が自動的に星印を挿入した後、/ をタイプすると余分
なスペースが削除されることを意味します。

詳細については format-comments を参照してください。
