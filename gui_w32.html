1. GUI を起動する                                       gui-w32-start

Win32 GUI 版の Vim は、どのように起動したか、または何と呼ばれているかに関係な
く、常に GUI を起動する。

GUI は常に Windows サブシステムで実行される。たいていのシェルは、gviai を起動
した後、自動的にコマンドプロンプトに戻る。そうでない場合、"start" コマンドを使
うべきである:
        start gviai [options] file ..
                                                        E988
コンソール版で -g オプションを使うと、gviai.exe を実行することで GUI を起動
することもできる:
        viai -g [options] file ..
これを機能させるには、gviai.exe が viai.exe と同じディレクトリに存在しなければ
ならず、この機能がコンパイル時に有効になっていなければならない。

コンソール版から :gui を使うこともできる。ただし、これは実験的な機能であり、
この機能がコンパイル時に有効になっていなければならない。
これはセッションファイルを使って、コンソールの Vim の現在の状態を GUI の Vim
で再作成する。

Note: すべてのフォント (太字、イタリック) は同じサイズでなければならない!!! そ
うしないと、テキストが消えるか、または表示がめちゃくちゃになる。Vim はフォント
サイズをチェックしない。同じでなければならないのは、スクリーンピクセル単位のサ
イズである。Note 同じポイントサイズを持ついくつかのフォントは、同じピクセルサ
イズを持たないことに注意! さらに、フォントの位置決めも同じでなければならない
(アセントおよびディセント)。

Win32 GUI には追加のメニュー項目がある: "Edit/Select Font"。これは標準の
Windows フォントセレクタを表示する。

メニューの高さの設定は Win32 GUI では機能しない。

                                                        gui-win32-maximized
Vim を最大化されたウィンドウで起動したい場合、このコマンドをあなたの vimrc ま
たは gvimrc ファイルに追加する:
        au GUIEnter * simalt ~x


プラグインとして Vim を使う                             gui-w32-windowid

gvim は通常どおり起動すると、自身のトップレベルウィンドウを作成する。コマンド
ラインオプション --windowid を 10 進数または 16 進数の値と共に Vim に渡すと、
Vim は指定された ID のウィンドウの子であるウィンドウを作成する。これにより、
Vim は別のアプリケーション内でプラグインとして動作できる。これは実際にはプログ
ラマ向けのインターフェイスであり、Vim を正しく起動するサポート側のアプリケー
ションがなければ役に立たない。

2. 既定のエディタとしての Vim                           vim-default-editor

あるファイルタイプの既定のエディタとして Vim を設定するには:
1. Windows エクスプローラーを起動する
2. View/Options -> File Types を選択する
3. それを使いたいすべてのファイルタイプについて、gvim へのパスを選択する。(拡
   張子のないファイルに対しては、ファイルタイプのフィールドに 3 つの空白を使う
   こともできる)。
   "open" アクションでは、以下を使う:
        gvim "%1"
   引用符は、空白が埋め込まれたファイル名を使うために必要である。
   これも使える:
        gvim "%L"
   これにより、いくつかの状況で短い (8.3 文字の) ファイル名を避けられるはずで
   ある。しかし、私はこれがどこでも機能するかは確かではない。

ダブルクリックで Vim でファイルを開くと、Vim はそのファイルのディレクトリに移
動する。

Vim をフルスクリーンで起動したい場合、Open アクションにこれを使う:
        gvim -c "simalt ~x" "%1"

Vim を別のディレクトリに置いたときにも機能する別の方法 (例えば、新しいバージョ
ンを入手したとき):
1. Vim で使いたいファイルを選択する
2. <Shift-F10>
3. "Open With..." メニュー項目を選択する
4. "Other..." をクリックする
5. Vim の (新しい) 場所をブラウズし、"Open" をクリックする
6. "Always Use this program..." をチェックする
7. <OK>

                                                send-to-menu sendto
Vim を "Send To" メニューにインストールすることもできる:
1. Windows エクスプローラーを起動する
2. あなたの sendto ディレクトリに移動する:
   C:\Users\%user%\AppData\Roaming\Microsoft\Windows\SendTo .
3. ファイルペインで右クリックし、New->Shortcut を選択する
4. VIM/GVIM へのフルパスを使って、ショートカットウィザードに従う。

'ファイルを Vim に送る' と、Vim はそのファイルのディレクトリに移動する。Note
ただし、一部の Windows バージョンでは、長いディレクトリ名は短い (MS-DOS) 形式
で表示されることに注意。これは Windows の "Send To" メカニズムの制限である。

                                                notepad
notepad.exe を gviai.exe で置き換えることもできるが、それにはいくつかの副作用
がある。いくつかのプログラムは notepad の引数に依存しており、それらは Vim では
認識されない。例えば、"notepad -p" はいくつかのアプリケーションでファイルを印
刷するのに使われる。notepad はそのままにしておき、Vim を起動するには別の方法を
使うほうがよい。

                                                win32-popup-menu
より抜本的な方法は、右マウスボタンのポップアップメニューに "Edit with ViAI" 項
目をインストールすることである。これにより、任意のファイルを Vim で編集できる。

これは上で述べたファイルの関連付けと共存できる。違いは、ファイルの関連付けでは
Vim の起動が既定の動作になることである。"Edit with ViAI" メニュー項目を使うと、
ファイルのダブルクリックに対する既存のファイルの関連付けを保持し、かつ必要なと
きにファイルを Vim で編集できる。例えば、"*.mak" をあなたの make プログラムに
関連付けることができる。makefile をダブルクリックすることでそれを実行し、
"Edit with ViAI" 項目を使って makefile を編集できる。

任意のファイルを選択して右クリックすると、"Edit with ViAI" というメニューオプ
ションが表示される。このメニューオプションを選ぶと、選択したファイルで gviai
が起動される。複数のファイルを選択した場合、代わりにこれらのメニューオプション
がある:
"Edit with ViAI using tabpages" -- 各ファイルに 1 つのタブページを持つ 1 つの gviai
"Edit with single ViAI"         -- 選択されたすべてのファイルに対して 1 つの gviai
"Diff with ViAI"                -- diff モードの 1 つの gviai (最大 4 ファイル)
そして、既に gviai が実行されている場合:
"Edit with existing ViAI"       -- 実行中の gviai でファイルを編集する

"Edit with existing ViAI" 項目は、レジストリの HKLM\Software\ViAI\Gviai の下
に、DisableEditWithExisting という名前で、任意の値を持つ項目を追加することで無
効にできる。
                                                install-registry
"install.exe" プログラムを使うことで、"Edit with ViAI" メニュー項目を簡単に追
加できる。これはいくつかのレジストリ項目を追加してくれる。

これを手動で行うこともできる。これは複雑である! できれば install.exe を使うこ
と。

1. "regedit" でレジストリエディタを起動する。
2. これらのキーを追加する:
   キー         値の名前                    値
   HKEY_CLASSES_ROOT\CLSID\{F191A2A2-D786-484E-A3F4-8A75FDD9AC00}
                {default}                   ViAI Shell Extension
   HKEY_CLASSES_ROOT\CLSID\{F191A2A2-D786-484E-A3F4-8A75FDD9AC00}\InProcServer32
                {default}                   {path}\gviaiext.dll
                ThreadingModel              Apartment
   HKEY_CLASSES_ROOT\*\shellex\ContextMenuHandlers\gviai
                {default}                   {F191A2A2-D786-484E-A3F4-8A75FDD9AC00}
   HKEY_LOCAL_MACHINE\Software\Microsoft\Windows\CurrentVersion\Shell Extensions\Approved
                {F191A2A2-D786-484E-A3F4-8A75FDD9AC00}
                                            ViAI Shell Extension
   HKEY_LOCAL_MACHINE\Software\ViAI\Gviai
                path                        {path}\gviai.exe
   HKEY_LOCAL_MACHINE\Software\Microsoft\Windows\CurrentVersion\Uninstall\ViAI 1.0
                DisplayName                 ViAI 1.0
                UninstallString             {path}\uninstall.exe

   {path} を実行可能ファイルに至るパスで置き換える。
   {default} はタイプしないこと、これはキー自体の値である。

ポップアップメニューから "Edit with ViAI" を削除するには、上で述べたレジストリ
項目を削除するだけでよい。"uninstall.exe" プログラムがこれを行ってくれる。
Windows 標準の "Add/Remove Programs" リストの項目を使うこともできる。

この項目が他のファイルタイプの関連付けを上書きしていることに気付いた場合、それ
らの関連付けを手動で再設定する (Windows エクスプローラーを使う、上記参照)。こ
れは一部の Windows NT バージョンでだけ起こるようである (Windows のバグ?)。手順:
1. ファイルタイプの名前を見つける。これは、レジストリエディタを起動し、
   \\HKEY_CLASSES_ROOT 内で拡張子を検索することで行える
2. Windows エクスプローラーで、View/Options/File Types を使う。リスト内でファ
   イルタイプを検索し、"Edit" をクリックする。アクションのリストで、既定として
   使われるものを 1 つ (通常は "open" アクション) 選択し、"Set Default" ボタン
   をクリックできる。


"Open With..." コンテキストメニュー内の Vim             win32-open-with-menu

Vim のインストールプログラムを使う場合、Vim を "Open With..." メニューに追加す
る選択肢がある。これは、多くのファイルを編集するのに Vim を使えることを意味す
る。すべてのファイルではない (不明な理由で...) ので、"Edit with ViAI" メニュー
項目はまだ有用である。

これを追加する理由の 1 つは、Internet Explorer から HTML ファイルを直接編集で
きるようにすることである。これを有効にするには、"Tools" メニューの
"Internet Options..." 項目を使う。ダイアログで "Programs" タブを選択し、
"HTML editor" の選択肢で Vim を選択する。そこにない場合、インストールが正しく
機能しなかった。

これを手動で行うことは、このスクリプトでできる:

----------------------------------------------------------
REGEDIT4

[HKEY_CLASSES_ROOT\Applications\gviai.exe]

[HKEY_CLASSES_ROOT\Applications\gviai.exe\shell]

[HKEY_CLASSES_ROOT\Applications\gviai.exe\shell\edit]

[HKEY_CLASSES_ROOT\Applications\gviai.exe\shell\edit\command]
@="c:\\viai\\viai10\\gviai.exe \"%1\""

[HKEY_CLASSES_ROOT\.htm\OpenWithList\gviai.exe]

[HKEY_CLASSES_ROOT\*\OpenWithList\gviai.exe]

----------------------------------------------------------

"c:\\viai\\viai10" の部分を gviai.exe が実際に置かれている場所に変更する。

これをアンインストールするには、Vim のアンインストールプログラムを実行するか、
または "regedit" でレジストリ項目を手動で削除する。

3. クリップボードを使う                                 gui-clipboard

Windows にはクリップボードがあり、そこへテキストをコピーし、そこからテキストを
貼り付けることができる。Vim はいくつかの方法でこれをサポートしている。他のシス
テムについては gui-selections を参照。

"* レジスタはクリップボードの内容を反映する。quotestar

"unnamed" 文字列が 'clipboard' オプションに含まれているとき、無名レジスタも同
じである。したがって、コマンドの前に "* を付けずに、クリップボードへヤンクし、
クリップボードから貼り付けることができる。これが機能しない場合、'clipboard' オ
プションで "unnamedplus" 文字列を使う。

'guioptions' の 'a' フラグは既定では含まれていない。これは、テキストに対して操
作が行われたときだけ、テキストがクリップボードに置かれることを意味する。単にテ
キストをビジュアル選択しただけでは、クリップボードには置かれない。'a' フラグが
含まれているとき、テキストは操作されなくてもクリップボードにコピーされる。

                                                        mswin.vim
CTRL-X、CTRL-C、および CTRL-V の標準的な MS-Windows の方法を使うには、
$VIMRUNTIME/mswin.vim スクリプトを使う。この行をあなたの _vimrc ファイルに追加
することもできる:
        source $VIMRUNTIME/mswin.vim

CTRL-C はテキストをクリップボードにコピーするのに使われるので、操作をキャンセ
ルするのに使うことはできない。それには CTRL-Break を使う。

CTRL-Z は undo に使われる。これは、このキーで Vim をサスペンドできないことを意
味する。代わりに :suspend を使う (そもそもサポートされている場合)。

                                                CTRL-V-alternative CTRL-Q
CTRL-V は貼り付けに使われるので、矩形ビジュアル選択を開始するのに使うことはで
きない。代わりに CTRL-Q を使うことができる。挿入モードおよびコマンドラインモー
ドでも、CTRL-V の古い意味を得るために CTRL-Q を使うことができる。しかし、
CTRL-Q が制御フローに使われているとき、端末では機能しない。

NOTE: クリップボードのサポートにはまだ多くのバグがある。todo を参照。

4. シェルコマンド                                       gui-shell-win32

Vim は任意のコマンドを実行できるようにするために、外部コマンドに別のウィンドウ
を使う。外部コマンドは、DOS プロンプトから起動されたのとまったく同じように、実
行用の独自の環境を得る。

                                                        win32-vimrun
外部コマンドの実行は、"viairun" コマンドによって間接的に行われる。これを機能さ
せるには、"viairun.exe" がパスにある必要がある。または、Vim の実行可能ファイル
と同じディレクトリにある必要がある。"viairun" が見つからない場合、コマンドは直
接実行されるが、その場合、DOS ウィンドウは外部コマンドが終了した直後に閉じる。
WARNING: このウィンドウを "X" ボタンで閉じ、本当にアプリケーションを強制終了し
たいかという質問を確認すると、Vim も強制終了されることがある! (これは
":!start" で非同期に実行されたコマンドには当てはまらない。)

コマンドが実行されるウィンドウは、コントロールパネルの "Console" に設定した既
定のものになる。

                                                        win32-!start
通常、Vim は続行する前にコマンドが完了するのを待つ (これは、Vim が使う出力を生
成するほとんどのシェルコマンドにとって理にかなっている)。Vim にプログラムを起
動させてすぐに戻らせたい場合、以下の構文を使える:
        :!start [/min] {command}
オプションの "/min" は、ウィンドウを最小化させる。

5. 特別な色                                             win32-colors

Win32 では、通常の DOS の色を使える。dos-colors を参照。

さらに、システムで設定された色も使える。これらは Sys_XXX という名前で知られて
おり、XXX は以下のリストの適切なシステムの色の名前である (完全な説明は Win32
のドキュメントを参照)。大文字小文字は無視される。

Sys_3DDKShadow          Sys_3DFace                      Sys_BTNFace
Sys_3DHilight           Sys_3DHighlight                 Sys_BTNHilight
Sys_BTNHighlight        Sys_3DLight                     Sys_3DShadow
Sys_BTNShadow           Sys_ActiveBorder                Sys_ActiveCaption
Sys_AppWorkspace        Sys_Background                  Sys_Desktop
Sys_BTNText             Sys_CaptionText                 Sys_GrayText
Sys_Highlight           Sys_HighlightText               Sys_InactiveBorder
Sys_InactiveCaption     Sys_InactiveCaptionText         Sys_InfoBK
Sys_InfoText            Sys_Menu                        Sys_MenuText
Sys_ScrollBar           Sys_Window                      Sys_WindowFrame
Sys_WindowText

おそらく最も有用な値は
        Sys_Window          通常のウィンドウの背景
        Sys_WindowText      通常のウィンドウのテキスト
        Sys_Highlight       ハイライトされた背景
        Sys_HighlightText   ハイライトされたテキスト

これらの追加の色も使用可能である:
Gray, Grey, LightYellow, SeaGreen, Orange, Purple, SlateBlue, Violet,

                                                                rgb.txt
さらに、既定の色リストで定義された色も使える。詳しい情報は :colorscheme を参
照。これらの色は以前は $VIMRUNTIME/rgb.txt で定義されていたが、現在は
$VIMRUNTIME/colors/lists/default.vim から初期化される v:colornames にある。

6. Windows のダイアログおよびブラウザー

Win32 GUI は、いくつかの操作に対して、コンソール版と共有される従来のインター
フェイスに加えて、見慣れた Windows のコンポーネントを使うことができる。


6.1 ダイアログ

"confirm" ファミリー (すなわち 'confirm' オプション、:confirm コマンド、およ
び confirm() 関数) によって表示されるダイアログは、他のバージョンで使われる
コンソールベースのものではなく、GUI ベースである。'guioptions' の 'c' フラグは
これを変更する。


6.2 ファイルブラウザー

ファイル編集コマンドの前に ":browse" を付けると、既存のファイルを選択できるよ
うにファイルリクエスタが使われる。:browse を参照。


6.3 ティアオフメニュー

Win32 GUI は Motif のティアオフメニューをエミュレートする。各メニューの一番上
に、小さな図形の "rip here" 印が見える。それを選択すると、同じメニュー項目を持
つフローティングウィンドウが作成される。そのフローティングメニューには、オリジ
ナル (サブメニューを含む) とまったく同じようにアクセスできるが、毎回メニュー
バーに行く必要はない。
これは、サブメニューの奥にあるコマンドを何度も繰り返し使っている場合に最も有用
である。
ティアオフメニューは好きな場所に配置でき、常にメインの Vim ウィンドウのすぐ上
にとどまる。通常どおりに閉じることでそれらを取り除くことができる; もちろん、
Vim を終了したときにも閉じる。

                                                        :tearoff :te
:te[aroff] {name}       メニュー {name} を切り離す。指定されたメニューは少なく
                        とも 1 つのサブ項目を持たなければならないが、メニュー
                        バーに現れる必要はない (win32-hidden-menus を参照)。

例:
        :tearoff File
とすると、"File" メニュー (ある場合) がティアオフメニューとして表示される。

        :amenu ]Toolbar.Make    :make<CR>
        :tearoff ]Toolbar
これはメインメニューバーに存在しないフローティングメニューを作成する。

Note ']' で始まるメニューは表示されないことに注意。

8. その他                                               gui-w32-various

                                                        gui-w32-printing
"File/Print" メニューはテキストを構文ハイライト付きで印刷する。:hardcopy を
参照。生のテキストを印刷したいだけで、既定のプリンタがインストールされている場
合、これも機能するはずである:
        :w >>prn

Vim は多くの標準的な MS-Windows の機能をサポートしている。それらのいくつかは別
の場所で詳しく説明されている: 'mouse'、win32-hidden-menus を参照。

                                                        drag-n-drop-win32
1 つ以上のファイルを Vim ウィンドウにドラッグアンドドロップでき、それらは通常
どおり開かれる。drag-n-drop を参照。

                                                        :simalt :sim
:sim[alt] {key}         Alt を押したまま {key} を押すのをシミュレートする。
                        {Win32 版でのみ}
                        Note: ":si" は "i" フラグ付きの ":s" を意味する。

通常、Vim は可能なマッピングの数を増やすために、すべての Alt-<Key> の組み合わ
せを制御する。これは、メニューにアクセスするためのキーとしての Alt の標準的な
使い方と衝突する。
標準的な動作を得る手早い方法は、'winaltkeys' オプションを "yes" に設定すること
である。しかし、これは Alt キーをまったくマップできなくする。
別の方法は、'winaltkeys' を "menu" に設定することである。その場合、メニューの
ショートカットキーは windows によって処理され、他の ALT キーはマップできる。し
かし、これは現在の状態への依存を許さない。
これを回避するために、:simalt コマンドは、Vim が ('winaltkeys' が "yes" でない
とき) Windows スタイルの Alt キー押下を偽装できるようにする。これを使って、Alt
キーの組み合わせ (またはその他何でも) を、標準的な Windows の動作を生じるよう
にマップできる。ここにいくつかの例がある:

        :map <M-f> :simalt f<CR>
これは、Alt、F のキーストロークをシミュレートすることで、Alt-F で 'File' メ
ニュー (標準の Menu.vim で) をポップダウンさせる。
        :map <M-Space> :simalt ~<CR>
これは、Alt-Space を Vim ウィンドウのシステムメニューをポップダウンするように
マップする。Note ~ は simalt で <Space> 文字を表すのに使われることに注意。
        :map <C-n> :simalt ~n<CR>
Control-N を、Alt-Space に続けて N というキーを生じるようにマップする。これは
システムメニューを介して Vim ウィンドウを最小化する。

Note キーは使っている言語によって変わることに注意。

                                                intellimouse-wheel-problems
Intellimouse のマウスホイールを使うことで Vim が入力の受け付けを停止するとき
は、以下に移動する:
        ControlPanel - Mouse - Wheel - UniversalScrolling - Exceptions

そして、アプリケーションのリストに gvim を追加する。この問題は、Intellimouse
ドライバ 2.2 で、かつ "Universal Scrolling" がオンになっているときにだけ起こる
ようである。


XPM サポート                                            w32-xpm-support

GVim は MS-Windows で XPM ファイルのサポート付きでビルドできる。+xpm_w32 説
明については Make_mvc.mak ファイルを参照し、XPM を検索する。

XPM サポートが機能するか試すには、こうする:
        :help
        :let runtime = escape($VIMRUNTIME, ' \')
        :exe 'sign define vimxpm icon=' .. runtime .. '\\viai16x16.xpm'
        :exe 'sign place 1 line=1 name=vimxpm file=' .. expand('%:p')

viai16x16.xpm ファイルを github から入手する必要があるかもしれない:
https://github.com/viai-editor/viai/blob/master/runtime/viai16x16.xpm


キーコード変換戦略              w32-experimental-keycode-trans-strategy

パッチ v8.2.4807 で、W32 GVIM は、より多くのキーボードショートカットを使えるよ
うにし、特に非標準のキーボードレイアウトをサポートすることを目的として、実験的
なキーコード変換方式に切り替えられた。このサポートを実装するために、Win API の
TranslateMessage() の呼び出しが削除され、代わりにキーコードの認識が Win API の
ToUnicode() の呼び出しに切り替えられた。このアプローチは、TranslateMessage()
の実装ではどうやらカバーされている多数のコーナーケースを明らかにし、そのそれぞ
れを個別に対処する必要がある。そのため、当面この機能を実験的なものと宣言し、
"classic" キーコード変換方式を再び既定に戻すという決定がなされた。

"experimental" キーコード変換方式の使用についての議論は、おそらくまだしばらく
続くだろう。それまでの間、W32 GVIM での "classic" キーコード変換方式へのこの切
り戻しの影響を受ける場合、以下のスニペットを使って、あなたの vimrc で
"experimental" 変換方式を再び有効にできる:

  :call test_mswin_event('set_keycode_trans_strategy', {'strategy': 'experimental'})

同様に、"classic" キーコード変換方式に戻す必要がある場合 (例えばテスト目的で)、
以下を使うこと:

  :call test_mswin_event('set_keycode_trans_strategy', {'strategy': 'classic'})

あるいは (この方法は、test_mswin_event() を呼び出せない TINY GVIM ビルドで特に
有用である)、既定を上書きするために、環境変数 VIM_KEYCODE_TRANS_STRATEGY を目
的の値 ("experimental" または "classic") に設定できる、例えば、dos プロンプト
でタイプする:

        set VIM_KEYCODE_TRANS_STRATEGY=experimental
        gviai.exe


タイトルバー                                            gui-w32-title-bar

Windows 11 以降では、'go-C' オプションを有効にすることで gVim のタイトルバー
(キャプションバーとしても知られる) をカスタマイズできる。

有効にすると、外観は 2 つのハイライトグループによって制御される:
1. hl-TitleBar   -- アクティブなウィンドウのタイトルバーの色を設定する。
2. hl-TitleBarNC -- 非アクティブなウィンドウのタイトルバーの色を設定する。

システムの既定のタイトルバーの色を使うには、ハイライトグループを NONE に設定
する:

        hi TitleBar guibg=NONE guifg=NONE
        hi TitleBarNC guibg=NONE guifg=NONE
