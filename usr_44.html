44.1  基本的な構文コマンド

既存の構文ファイルを使って始めると、多くの時間を節約できます。
$VIMRUNTIME/syntax で、似ている言語の構文ファイルを探してみてください。これら
のファイルは、構文ファイルの通常のレイアウトも示してくれます。それを理解するに
は、以下を読む必要があります。

基本的な引数から始めましょう。新しい構文を定義し始める前に、古い定義をすべて消
去する必要があります:

        :syntax clear

これは最終的な構文ファイルでは必要ありませんが、実験するときにはとても便利で
す。

この章には他にも簡略化があります。他の人が使う構文ファイルを書いている場合、最
後まで読み通して詳細を調べてください。


定義されたアイテムを一覧表示する

現在どの構文アイテムが定義されているかを確認するには、このコマンドを使います:


        :syntax

これを使って、実際にどのアイテムが定義されているかを確認できます。新しい構文
ファイルで実験しているときにはとても便利です。これは各アイテムに使われている色
も表示するので、何が何なのかを調べるのに役立ちます。
   特定の構文グループのアイテムを一覧表示するには、こうします:

        :syntax list {group-name}

これはクラスタ (44.8 で説明します) を一覧表示するのにも使えます。名前に @ を
含めるだけです。


大文字小文字を一致させる

Pascal のように、大文字小文字を区別しない言語もあります。C のように、大文字小
文字を区別する言語もあります。以下のコマンドで、どちらの種類なのかを指示する必
要があります:
        :syntax case match
        :syntax case ignore

"match" 引数は、Vim が構文要素の大文字小文字を一致させることを意味します。した
がって、"int" は "Int" および "INT" とは異なります。"ignore" 引数が使われた場
合、以下は同等です: "Procedure"、"PROCEDURE"、および "procedure"。
   ":syntax case" コマンドは構文ファイルのどこにでも置くことができ、それに続く
構文定義に影響します。ほとんどの場合、あなたの構文ファイルには ":syntax case"
コマンドは 1 つしかありません。しかし、大文字小文字を区別する要素および区別し
ない要素の両方を含む変わった言語を扱う場合、":syntax case" コマンドをファイル
全体に散りばめることができます。

44.2  キーワード

最も基本的な構文要素はキーワードです。キーワードを定義するには、以下の形式を使
います:

        :syntax keyword {group} {keyword} ...

{group} は構文グループの名前です。":highlight" コマンドで、{group} に色を割り
当てることができます。{keyword} 引数は実際のキーワードです。以下にいくつかの例
を示します:

        :syntax keyword xType int long char
        :syntax keyword xStatement if then else endif

この例では、グループ名 "xType" および "xStatement" を使っています。慣例により、
各グループ名には定義している言語のファイルタイプがプリフィックスとして付けられ
ます。この例では x 言語 (面白い名前のない eXample 言語) の構文を定義していま
す。"csh" スクリプトの構文ファイルでは、"cshType" という名前が使われるでしょ
う。したがって、プリフィックスは 'filetype' の値と同じです。
   これらのコマンドにより、単語 "int"、"long"、および "char" はある方法でハイ
ライトされ、単語 "if"、"then"、"else"、および "endif" は別の方法でハイライトさ
れます。ここで、x のグループ名を Vim の標準の名前に結び付ける必要があります。
これは以下のコマンドで行います:

        :highlight link xType Type
        :highlight link xStatement Statement

これは、"xType" を "Type" のように、"xStatement" を "Statement" のようにハイラ
イトするように Vim に指示します。標準の名前については group-name を参照して
ください。


普通でないキーワード

キーワードに使われる文字は 'iskeyword' オプションに含まれていなければなりませ
ん。別の文字を使った場合、その単語は決してマッチしません。Vim はこれについて警
告メッセージを出しません。
   x 言語はキーワードに '-' 文字を使います。これはこのように行います:

        :setlocal iskeyword+=-
        :syntax keyword xStatement when-not

":setlocal" コマンドは、カレントバッファに対してだけ 'iskeyword' を変更するた
めに使われます。それでも、"w" および "*" のようなコマンドの動作は変わります。
それが望ましくない場合、キーワードを定義せず、マッチ (次の節で説明します) を
使ってください。

x 言語は省略形を許しています。例えば、"next" は "n"、"ne"、または "nex" に省略
できます。このコマンドを使ってそれらを定義できます:

        :syntax keyword xStatement n[ext]

これは "nextone" にはマッチしません。キーワードは常に単語全体にだけマッチしま
す。

44.3  マッチ

もう少し複雑なものを定義することを考えてみましょう。通常の識別子にマッチさせた
いです。これを行うには、マッチ構文アイテムを定義します。これは小文字だけからな
る任意の単語にマッチします:

        :syntax match xIdentifier /\<\l\+\>/

        Note:
        キーワードは他のすべての構文アイテムより優先されます。したがって、キー
        ワード "if"、"then" などは、xIdentifier のパターンにもマッチしますが、
        上の ":syntax keyword" コマンドで定義したとおりキーワードになります。

末尾の部分はパターンで、検索に使われるようなものです。// はパターンを囲むため
に使われます (":substitute" コマンドで行われるのと同じように)。プラス記号また
は引用符のような他の任意の文字も使えます。

次に、コメントのマッチを定義します。x 言語では、それは # から行末までの任意の
ものです:

        :syntax match xComment /#.*/

任意の検索パターンを使えるので、マッチアイテムでとても複雑なものをハイライトで
きます。検索パターンのヘルプについては pattern を参照してください。

44.4  リージョン

例の x 言語では、文字列はダブルクォート (") で囲まれます。文字列をハイライトす
るには、リージョンを定義します。リージョンの開始 (ダブルクォート) およびリー
ジョンの終了 (ダブルクォート) が必要です。定義は以下のとおりです:

        :syntax region xString start=/"/ end=/"/

"start" および "end" ディレクティブは、リージョンの開始および終了を見つけるた
めに使われるパターンを定義します。しかし、このような文字列はどうでしょうか?

        "A string with a double quote (\") in it"

これは問題を引き起こします: 文字列の途中のダブルクォートがリージョンを終わらせ
てしまいます。文字列中のエスケープされたダブルクォートを飛ばすように Vim に指
示する必要があります。これは skip キーワードで行います:

        :syntax region xString start=/"/ skip=/\\"/ end=/"/

バックスラッシュは検索パターンでは特殊文字なので、二重のバックスラッシュは 1
つのバックスラッシュにマッチします。

マッチの代わりにリージョンを使うのはどういうときでしょうか? 主な違いは、マッチ
アイテムは 1 つのパターンであり、全体としてマッチしなければならないことです。
リージョンは "start" パターンがマッチするとすぐに始まります。"end" パターンが
見つかるかどうかは問題になりません。したがって、アイテムがマッチするのに "end"
パターンに依存する場合、リージョンは使えません。それ以外の場合、リージョンの方
が定義が簡単なことがよくあります。そして、次の節で説明するように、入れ子になっ
たアイテムを使うのがより簡単です。

44.5  入れ子になったアイテム

このコメントを見てください:

        %Get input  TODO: Skip white space

TODO を、青でハイライトされるコメントの中にあっても、大きな黄色の文字でハイラ
イトしたいです。これを Vim に知らせるには、以下の構文グループを定義します:

        :syntax keyword xTodo TODO contained
        :syntax match xComment /%.*/ contains=xTodo

最初の行では、"contained" 引数は、このキーワードが別の構文アイテムの内側にしか
存在できないことを Vim に伝えます。次の行には "contains=xTodo" があります。こ
れは xTodo 構文要素がその内側にあることを示します。結果として、コメント行は全
体として "xComment" にマッチし、青になります。その内側の単語 TODO は xTodo に
マッチし、黄色でハイライトされます (xTodo のハイライトはこのために設定されてい
ました)。


再帰的な入れ子

x 言語は波括弧でコードブロックを定義します。そして、コードブロックは他のコード
ブロックを含むことがあります。これはこのように定義できます:

        :syntax region xBlock start=/{/ end=/}/ contains=xBlock

このテキストがあるとします:

        while i < b {
                if a {
                        b = c;
                }
        }

最初に、xBlock が 1 行目の { で始まります。2 行目で別の { が見つかります。
xBlock アイテムの内側にいて、それは自分自身を含むので、ここで入れ子になった
xBlock アイテムが始まります。したがって、"b = c" の行は 2 段目の xBlock リー
ジョンの内側にあります。それから、次の行で } が見つかり、これはリージョンの終
了パターンにマッチします。これで入れ子になった xBlock が終わります。} は入れ子
になったリージョンに含まれているので、最初の xBlock リージョンからは隠されま
す。それから、最後の } で最初の xBlock リージョンが終わります。


終わりを保つ

以下の 2 つの構文アイテムを考えてみましょう:

        :syntax region xComment start=/%/ end=/$/ contained
        :syntax region xPreProc start=/#/ end=/$/ contains=xComment

コメントを % から行末までの任意のものとして定義しています。プリプロセッサディ
レクティブは # から行末までの任意のものです。プリプロセッサ行にコメントを含め
ることができるので、プリプロセッサの定義は "contains=xComment" 引数を含んでい
ます。では、このテキストで何が起こるかを見てみましょう:

        #define X = Y  % Comment text
        int foo = 1;

2 行目も xPreProc としてハイライトされていることがわかります。プリプロセッサ
ディレクティブは行末で終わるはずです。そのために "end=/$/" を使ったのです。で
は、何がうまくいかないのでしょうか?
   問題は含まれているコメントです。コメントは % で始まり、行末で終わります。コ
メントが終わった後、プリプロセッサの構文が続きます。これは行末が見られた後なの
で、次の行も含まれてしまいます。
   この問題を避け、かつ含まれている構文アイテムが必要な行末を食べてしまうのを
避けるには、"keepend" 引数を使います。これは二重の行末マッチングを処理します:


        :syntax region xComment start=/%/ end=/$/ contained
        :syntax region xPreProc start=/#/ end=/$/ contains=xComment keepend


多くのアイテムを含む

contains 引数を使って、すべてのものを含めることができると指定できます。例えば:


        :syntax region xList start=/\[/ end=/\]/ contains=ALL

すべての構文アイテムがこのアイテムに含まれます。これは自分自身も含みますが、同
じ位置ではありません (それは無限ループを引き起こすでしょう)。
   いくつかのグループを含まないように指定できます。したがって、列挙されたもの
を除くすべてのグループを含めます:

        :syntax region xList start=/\[/ end=/\]/ contains=ALLBUT,xString

"TOP" アイテムを使うと、"contained" 引数を持たないすべてのアイテムを含めること
ができます。"CONTAINED" は、"contained" 引数を持つアイテムだけを含めるために使
われます。詳細は :syn-contains を参照してください。

44.6  後続グループ

x 言語にはこの形式の文があります:

        if (condition) then

3 つのアイテムを異なる方法でハイライトしたいです。しかし、"(condition)" および
"then" は他の場所にも現れることがあり、そこでは異なるハイライトがされます。こ
れはこのようにして行えます:

        :syntax match xIf /if/ nextgroup=xIfCondition skipwhite
        :syntax match xIfCondition /([^)]*)/ contained nextgroup=xThen skipwhite
        :syntax match xThen /then/ contained

"nextgroup" 引数は、次にどのアイテムが来てよいかを指定します。これは必須ではあ
りません。指定されたアイテムがどれも見つからない場合、何も起こりません。例え
ば、このテキストでは:

        if not (condition) then

"if" は xIf にマッチします。"not" は指定された nextgroup xIfCondition にマッチ
しないので、"if" だけがハイライトされます。

"skipwhite" 引数は、アイテムの間にホワイトスペース (スペースおよびタブ) が現れ
てもよいことを Vim に伝えます。同様の引数として、アイテムの間に改行を許す
"skipnl"、および空行を許す "skipempty" があります。"skipnl" は空行を飛ばさない
ことに注意してください。改行の後に何かがマッチしなければなりません。

44.7  その他の引数

MATCHGROUP

リージョンを定義するとき、リージョン全体が指定されたグループ名に従ってハイライ
トされます。例えば、括弧 () で囲まれたテキストをグループ xInside でハイライト
するには、以下のコマンドを使います:

        :syntax region xInside start=/(/ end=/)/

括弧を異なる方法でハイライトしたいとします。多くの込み入った region 文でこれを
行うか、または "matchgroup" 引数を使うことができます。これは、リージョンの開始
および終了を異なるハイライトグループ (この場合、xParen グループ) でハイライト
するように Vim に指示します:

        :syntax region xInside matchgroup=xParen start=/(/ end=/)/

"matchgroup" 引数は、その後に来る開始または終了のマッチに適用されます。前の例
では、開始および終了の両方が xParen でハイライトされます。終了を xParenEnd で
ハイライトするには:

        :syntax region xInside matchgroup=xParen start=/(/
                \ matchgroup=xParenEnd end=/)/

"matchgroup" を使う副作用は、含まれるアイテムがリージョンの開始または終了では
マッチしないことです。"transparent" の例はこれを利用しています。


TRANSPARENT

C 言語のファイルで、"while" の後の () テキストを "for" の後の () テキストとは
異なる方法でハイライトしたいです。これらの両方に、入れ子になった () アイテムが
あり得て、それらは同じ方法でハイライトされるべきです。() のハイライトがマッチ
する ) で止まるようにしなければなりません。これはそれを行う 1 つの方法です:

        :syntax region cWhile matchgroup=cWhile start=/while\s*(/ end=/)/
                \ contains=cCondNest
        :syntax region cFor matchgroup=cFor start=/for\s*(/ end=/)/
                \ contains=cCondNest
        :syntax region cCondNest start=/(/ end=/)/ contained transparent

これで cWhile および cFor に異なるハイライトを与えることができます。cCondNest
アイテムはそのどちらにも現れることができますが、それが含まれているアイテムのハ
イライトを引き継ぎます。"transparent" 引数がこれを引き起こします。
   "matchgroup" 引数がアイテム自身と同じグループを持っていることに注意してくだ
さい。では、なぜそれを定義するのでしょうか? さて、matchgroup を使う副作用は、
そのとき含まれるアイテムが開始アイテムとのマッチの中で見つからないことです。こ
れにより、cCondNest グループが "while" または "for" の直後の ( にマッチするの
を避けられます。これが起こった場合、マッチする ) までのテキスト全体にまたがり、
リージョンはその後も続いてしまいます。これで cCondNest は開始パターンのマッチ
の後、つまり最初の ( の後でだけマッチします。


オフセット

"if" の後の ( と ) の間のテキストに対してリージョンを定義したいとします。しか
し、"if" または ( および ) は含めたくありません。これはパターンにオフセットを
指定することで行えます。例:

        :syntax region xCond start=/if\s*(/ms=e+1 end=/)/me=s-1

開始パターンのオフセットは "ms=e+1" です。"ms" は Match Start を表します。これ
はマッチの開始のオフセットを定義します。通常、マッチはパターンがマッチした場所
から始まります。"e+1" は、マッチが今度はパターンマッチの終わりで始まり、それか
らさらに 1 文字先になることを意味します。
   終了パターンのオフセットは "me=s-1" です。"me" は Match End を表します。
"s-1" はパターンマッチの開始、それから 1 文字戻ったところを意味します。結果と
して、このテキストでは:

        if (foo == bar)

"foo == bar" というテキストだけが xCond としてハイライトされます。

オフセットについてのさらなる情報はこちら: :syn-pattern-offset。


ONELINE

"oneline" 引数は、リージョンが行の境界をまたがないことを示します。例えば:

        :syntax region xIfThen start=/if/ end=/then/ oneline

これは "if" で始まり "then" で終わるリージョンを定義します。しかし、"if" の後
に "then" がない場合、リージョンはマッチしません。

        Note:
        "oneline" を使うとき、終了パターンが同じ行でマッチしない場合、リージョ
        ンは始まりません。"oneline" なしでは、Vim は終了パターンのマッチがある
        かどうかを確認_しません_。リージョンは、終了パターンがファイルの残りの
        部分でマッチしないときでも始まります。


継続行とそれを避ける

ここで事態は少し複雑になります。プリプロセッサ行を定義しましょう。これは 1 カ
ラム目の # で始まり、行末まで続きます。\ で終わる行は次の行を継続行にします。
これを扱う方法は、構文アイテムが継続パターンを含むことができるようにすることで
す:

        :syntax region xPreProc start=/^#/ end=/$/ contains=xLineContinue
        :syntax match xLineContinue "\\$" contained

この場合、xPreProc は通常 1 行にマッチしますが、それに含まれるグループ (つまり
xLineContinue) によって、それが複数行にわたって続くようになります。例えば、こ
れは以下の両方の行にマッチします:

        #define SPAM  spam spam spam \
                        bacon and spam

この場合、これは望みどおりです。それが望むものでない場合、含まれるパターンに
"excludenl" を追加することで、リージョンが 1 行に収まるように要求できます。例
えば、xPreProc の中の "end" を、ただし行末にある場合だけハイライトしたいです。
xLineContinue がするように xPreProc が次の行に続いてしまうのを避けるには、
"excludenl" をこのように使います:

        :syntax region xPreProc start=/^#/ end=/$/
                \ contains=xLineContinue,xPreProcEnd
        :syntax match xPreProcEnd excludenl /end$/ contained
        :syntax match xLineContinue "\\$" contained

"excludenl" はパターンの前に置かなければなりません。"xLineContinue" は
"excludenl" を持っていないので、それとのマッチは以前と同じように xPreProc を次
の行まで延長します。

44.8  クラスタ

構文ファイルを書き始めると気付くことの 1 つは、結局たくさんの構文グループを生
成してしまうことです。Vim では、クラスタと呼ばれる構文グループの集まりを定義で
きます。
   for ループ、if 文、while ループ、および関数を含む言語があるとします。それぞ
れが同じ構文要素を含んでいます: 数値および識別子です。これらを以下のように定義
します:

        :syntax match xFor /^for.*/ contains=xNumber,xIdent
        :syntax match xIf /^if.*/ contains=xNumber,xIdent
        :syntax match xWhile /^while.*/ contains=xNumber,xIdent

毎回同じ "contains=" を繰り返さなければなりません。別の含まれるアイテムを追加
したい場合、それを 3 回追加しなければなりません。構文クラスタは、1 つのクラス
タで複数の構文グループを表せるようにすることで、これらの定義を簡単にします。
   3 つのグループが含む 2 つのアイテムに対してクラスタを定義するには、以下のコ
マンドを使います:

        :syntax cluster xState contains=xNumber,xIdent

クラスタは、他の構文グループとまったく同じように、他の構文アイテムの中で使われ
ます。
その名前は @ で始まります。したがって、3 つのグループをこのように定義できます:


        :syntax match xFor /^for.*/ contains=@xState
        :syntax match xIf /^if.*/ contains=@xState
        :syntax match xWhile /^while.*/ contains=@xState

"add" 引数で、このクラスタに新しいグループ名を追加できます:

        :syntax cluster xState add=xString

このリストから構文グループを削除することもできます:

        :syntax cluster xState remove=xNumber

44.9  別の構文ファイルをインクルードする

C++ 言語の構文は C 言語の上位集合です。2 つの構文ファイルを書きたくはないので、
以下のコマンドを使って C++ の構文ファイルに C 用のものを読み込ませることができ
ます:

        :runtime! syntax/c.vim

":runtime!" コマンドは 'runtimepath' からすべての "syntax/c.vim" ファイルを検
索します。これにより、C++ 構文の C の部分が C ファイルと同じように定義されま
す。c.vim 構文ファイルを置き換えたか、または追加のファイルでアイテムを追加した
場合、それらも読み込まれます。
   C の構文アイテムを読み込んだ後、C++ 固有のアイテムを定義できます。例えば、C
では使われないキーワードを追加します:

        :syntax keyword cppStatement    new delete this friend using

これは他の構文ファイルとまったく同じように機能します。

次に Perl 言語を考えてみましょう。Perl スクリプトは 2 つの異なる部分からなりま
す: POD 形式のドキュメントのセクション、および Perl 自体で書かれたプログラムで
す。POD セクションは "=head" で始まり、"=cut" で終わります。
   POD の構文を 1 つのファイルで定義し、それを Perl の構文ファイルから使いたい
です。":syntax include" コマンドは構文ファイルを読み込み、それが定義した要素を
構文クラスタに格納します。Perl の場合、文は以下のとおりです:

        :syntax include @Pod <sfile>:p:h/pod.vim
        :syntax region perlPOD start=/^=head/ end=/^=cut/ contains=@Pod

Perl ファイルで "=head" が見つかると、perlPOD リージョンが始まります。このリー
ジョンには @Pod クラスタが含まれます。pod.vim 構文ファイルでトップレベルアイテ
ムとして定義されたすべてのアイテムがここでマッチします。"=cut" が見つかると、
リージョンが終わり、Perl ファイルで定義されたアイテムに戻ります。
   ":syntax include" コマンドは、インクルードされたファイル内の
":syntax clear" コマンドを無視するほど賢いです。そして、"contains=ALL" のよう
な引数は、インクルードされたファイルで定義されたアイテムだけを含み、それをイン
クルードしているファイルのアイテムは含みません。
   "<sfile>:p:h/" の部分は、カレントファイルの名前 (<sfile>) を使い、それをフ
ルパスに展開し (:p)、それから頭部を取ります (:h)。これにより、ファイルのディレ
クトリ名になります。これにより、同じディレクトリにある pod.vim ファイルがイン
クルードされます。

44.10 同期

コンパイラは楽です。ファイルの先頭から始めて、まっすぐ解析していきます。Vim は
それほど楽ではありません。編集が行われている途中から始めなければなりません。で
は、どうやって自分がどこにいるかを知るのでしょうか?
   その秘密は ":syntax sync" コマンドです。これは、自分がどこにいるかを判断す
る方法を Vim に指示します。例えば、以下のコマンドは、C スタイルのコメントの始
まりまたは終わりを後方に走査し、そこから構文の色付けを始めるように Vim に指示
します:

        :syntax sync ccomment

この処理はいくつかの引数で調整できます。"minlines" 引数は後方を調べる最小行数
を Vim に指示し、"maxlines" は走査する最大行数をエディタに指示します。
   例えば、以下のコマンドは、画面の最上行より少なくとも 10 行前を調べるように
Vim に指示します:

        :syntax sync ccomment minlines=10 maxlines=500

その範囲で自分がどこにいるかを判断できない場合、何をすべきかがわかるまで、さら
に後方を調べ始めます。しかし、500 行より後方は調べません。(大きな "maxlines"
は処理を遅くします。小さなものは同期の失敗を引き起こすかもしれません。)
   同期をもう少し速くするには、どの構文アイテムを飛ばしてよいかを Vim に指示し
ます。実際にテキストを表示するときにだけ使う必要があるすべてのマッチおよびリー
ジョンには、"display" 引数を与えることができます。
   既定では、見つかるコメントは Comment 構文グループの一部として色付けされま
す。別の方法で色付けしたい場合、別の構文グループを指定できます:

        :syntax sync ccomment xAltComment

あなたのプログラミング言語に C スタイルのコメントがない場合、別の同期の方法を
試すことができます。最も簡単な方法は、何行か後方に戻ってそこから事態を把握しよ
うとするように Vim に指示することです。以下のコマンドは、150 行戻ってそこから
解析を始めるように Vim に指示します:

        :syntax sync minlines=150

大きな "minlines" の値は、特にファイル内を後方にスクロールするときに、Vim を遅
くすることがあります。
   最後に、このコマンドを使って、探す構文グループを指定できます:

        :syntax sync match {sync-group-name}
                \ grouphere {group-name} {pattern}

これは、{pattern} を見つけたときに、{group-name} という名前の構文グループが与
えられたパターンの直後から始まることを Vim に伝えます。{sync-group-name} はこ
の同期の指定に名前を付けるために使われます。例えば、sh スクリプト言語は if 文
を "if" で始め、"fi" で終えます:

        if [ --f file.txt ] ; then
                echo "File exists"
        fi

この構文に対する "grouphere" ディレクティブを定義するには、以下のコマンドを使
います:

        :syntax sync match shIfSync grouphere shIf "\<if\>"

"groupthere" 引数は、パターンがグループを終えることを Vim に伝えます。例えば、
if/fi グループの終わりは以下のとおりです:

        :syntax sync match shIfSync groupthere NONE "\<fi\>"

この例では、NONE は、特別な構文リージョンの中にいないことを Vim に伝えます。特
に、if ブロックの中にはいません。

"grouphere" または "groupthere" 引数のないマッチおよびリージョンを定義すること
もできます。これらのグループは、同期の間に飛ばされる構文グループのためのもので
す。例えば、以下は、通常は別の同期の方法にマッチする場合でも、{} の中にあるも
のをすべて飛ばします:

        :syntax sync match xSpecial /{.*}/

同期についてのさらなる情報はリファレンスマニュアルにあります: :syn-sync。

44.11 構文ファイルをインストールする

あなたの新しい構文ファイルを使う準備ができたときは、それを 'runtimepath' 内の
"syntax" ディレクトリに置きます。Unix の場合、それは "~/.vim/syntax" になるで
しょう。
  構文ファイルの名前は、ファイルタイプに ".vim" を付けたものと等しくなければな
りません。したがって、x 言語の場合、ファイルのフルパスは以下のようになります:

        ~/.vim/syntax/x.vim

ファイルタイプが認識されるようにもしなければなりません。43.2 を参照してくだ
さい。

あなたのファイルがうまく機能する場合、他の Vim ユーザーが使用できるようにした
いと思うかもしれません。まず次の節を読んで、あなたのファイルが他の人にとっても
うまく機能することを確認してください。それから、それを Vim のメンテナーに電子
メールで送ってください: <maintainer@vim.org>。ファイルタイプがどのように検出で
きるかも説明してください。少し運が良ければ、あなたのファイルは次の Vim のバー
ジョンに含まれるでしょう!


既存の構文ファイルに追加する

まったく新しい構文ファイルを追加していると仮定していました。既存の構文ファイル
が機能するが、いくつかのアイテムが欠けている場合、別のファイルでアイテムを追加
できます。これにより、配布されている構文ファイルを変更するのを避けられます。そ
れは新しいバージョンの Vim をインストールするときに失われます。
   あなたのファイルに、場合によっては既存の構文のグループ名を使って、構文コマ
ンドを書きます。例えば、C の構文ファイルに新しい変数の型を追加するには:

        :syntax keyword cType off_t uint

元の構文ファイルと同じ名前でファイルを書き込みます。この場合は "c.vim" です。
それを 'runtimepath' の終わりに近いディレクトリに置きます。これにより、元の構
文ファイルの後に読み込まれるようになります。Unix の場合、これは以下のようにな
ります:

        ~/.vim/after/syntax/c.vim

44.12 移植性のある構文ファイルのレイアウト

すべての Vim ユーザーが構文ファイルを交換する場合、素敵ではないでしょうか? こ
れを可能にするには、構文ファイルはいくつかのガイドラインに従わなければなりませ
ん。

その構文ファイルが何のためのものか、誰がメンテナンスしているか、およびいつ最後
に更新されたかを説明するヘッダーから始めます。変更履歴についての情報をあまり多
く含めないでください。それを読む人は多くありません。例:

        " Vim syntax file
        " Language:     C
        " Maintainer:   Bram Moolenaar <Bram@vim.org>
        " Last Change:  2001 Jun 18
        " Remark:       Included by the C++ syntax.

他の構文ファイルと同じレイアウトを使ってください。既存の構文ファイルを例として
使うと、多くの時間を節約できます。

あなたの構文ファイルには、適切で説明的な名前を選んでください。小文字および数字
を使ってください。あまり長くしないでください。それは多くの場所で使われます: 構
文ファイルの名前 "name.vim"、'filetype'、b:current_syntax、および各構文グルー
プの先頭 (nameType、nameStatement、nameString など) です。

"b:current_syntax" のチェックから始めます。それが定義されている場合、
'runtimepath' のより前にある他の構文ファイルがすでに読み込まれています:

        if exists("b:current_syntax")
          finish
        endif

最後に "b:current_syntax" を構文の名前に設定します。インクルードされたファイル
もこれを行うことを忘れないでください。2 つのファイルをインクルードする場合、
"b:current_syntax" をリセットしなければならないかもしれません。

ユーザーの好みであるものは何も含めないでください。'tabstop'、'expandtab' など
を設定しないでください。それらはファイルタイププラグインに属します。

マッピングまたは短縮入力を含めないでください。'iskeyword' の設定を含めるのは、
キーワードを認識するために本当に必要な場合だけにしてください。

ユーザーが自分の好みの色を選択できるように、ハイライトされるアイテムの種類ごと
に異なるグループ名を作ってください。それから、それぞれを標準のハイライトグルー
プの 1 つにリンクします。これにより、すべてのカラースキームで機能するようにな
ります。特定の色を選択した場合、いくつかのカラースキームでは見た目が悪くなりま
す。そして、異なる背景色を使っている人、または 8 色しか使用できない人もいるこ
とを忘れないでください。

あなたの構文ファイルが読み込まれる前にユーザーが異なるハイライトを選択できるよ
うに、リンクには "hi def link" を使ってください。例:

          hi def link nameString        String
          hi def link nameNumber        Number
          hi def link nameCommand       Statement
          ... etc ...

後方へのスクロールおよび CTRL-L を速くするために、同期の際に使われないアイテム
には "display" 引数を追加してください。
