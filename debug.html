Vim のデバッグ                                          debug-vim

これは、Vim が正しく動作しないときに、Vim 自体をデバッグするためのものである。
Vim script や関数などのデバッグについては debug-scripts を参照

1. gcc および gdb を使ったクラッシュの場所の特定        debug-gcc
2. メモリリークの特定                           debug-leaks
3. Windows のバグ報告                           debug-win32

==============================================================================

1. gcc および gdb を使ったクラッシュの場所の特定        debug-gcc gdb

Vim がテストファイルの 1 つでクラッシュし、コンパイルに gcc を使っている場合
に、Vim がどこでクラッシュするかを正確に突き止めるためにできることをここに示
す。これは MingW ツールを使っている場合にも当てはまる。

1. "-g" オプション付きで Vim をコンパイルする (src/Makefile にこのための行があ
   るので、そのコメントを外せばよい)。また、"strip" が無効になっていることを確
   かめること (それをインストールしないか、または "STRIP = /bin/true" の行を使
   う)。

2. これらのコマンドを実行する ("11" は失敗するテストに置き換える):
        cd testdir
        gdb ../vim
        run -u unix.vim -U NONE -s dotest.in test11.in

3. Vim がどこでクラッシュするかを確認する。gdb がこれについてのメッセージを出
   すはずである。

4. このコマンドで gdb からスタックトレースを取得する:
        where
   スタックトレースの別の場所は、以下で確認できる:
        frame 3
   "3" をスタックトレースの番号の 1 つに置き換える。

==============================================================================

2. メモリリークの特定                           debug-leaks valgrind

Vim がメモリリークしていると疑い、Linux を使っている場合は、valgrind ツールが
メモリリークの場所を正確に突き止めるのにとても役に立つ。

まず、EXITFREE を定義して Vim をビルドする。MAKEFILE でこれを検索し、その行の
コメントを外す。

このコマンドを使って Vim を起動する:

        valgrind --log-file=valgrind.log --leak-check=full ./vim

Note: Vim の動作はかなり遅くなる。.vimrc が大きい場合、またはプラグインがいく
つかある場合は、起動を辛抱強く待つ必要があるか、または "--clean" 引数を付けて
実行する必要がある。

getpwuid() および XtVaAppCreateShell() など、ライブラリからのリークがいくつか
あることが多い。これらは避けられない。そのバイト数は、1 K バイト以下のとても小
さいものであるはずである。

3. Windows のバグ報告                                   debug-win32

Windows 版の Vim が再現可能な形でクラッシュする場合は、役に立つバグ報告をする
ための手順を踏むことができる。


3.1 一般

実行可能ファイルのデバッガシンボル (PDB) ファイルを入手しなければならない:
gviai.exe には gviai.pdb、または viai.exe には viai.pdb。PDB は、実行可能ファ
イルを入手したのと同じ場所から入手できるはずである。EXE と一致する (同じ日付の)
PDB を使うようにすること。

実行可能ファイルを自分で Microsoft Visual C++ コンパイラでビルドした場合は、
PDB は EXE と一緒にビルドされている。

Visual Studio がある場合は、VC Toolkit および WinDbg の代わりにそれを使うこと。

他のコンパイラの場合は、常に対応するデバッガを使うべきである: Cygwin および
MinGW のコンパイラには gdb (上記の debug-gcc を参照)。


                                                                debug-vs2005
3.2 Visual Studio 2005/Visual C++ 2005 Express での Vim のクラッシュのデバッグ

まず viai.exe または gviai.exe を起動し、次に Visual Studio を起動する。
(Visual Studio が無い場合は、get-ms-debuggers の手順に従って、Visual C++
2005 Express Edition の無料のコピーを入手する。)

Tools メニューで、Attach to Process をクリックする。Vim のプロセスを選択する。

Vim で、クラッシュを再現する。Visual Studio にダイアログが現れ、Vim のプロセス
での処理されない例外について知らせる。Break をクリックして、プロセスに割り込
む。

Visual Studio は別のダイアログを表示し、シンボルが読み込まれておらず、ソース
コードを表示できないことを知らせる。OK をクリックする。

いくつかのウィンドウが開く。Call Stack ウィンドウで右クリックする。Load
Symbols を選択する。Find Symbols ダイアログが開き、(g)viai.pdb を探す。PDB ファ
イルがあるディレクトリに移動し、Open をクリックする。

この時点で、vim の関数名および行番号付きの完全なコールスタックが得られるはずで
ある。行の 1 つをダブルクリックすると、Find Source ダイアログが現れる。Vim の
ソースがあるディレクトリに移動する (ソースがある場合。)

これ以上どうデバッグすればよいか分からない場合は、":help bug-reports" の手順に
従うこと。コールスタックをバグ報告に貼り付ける。

Visual Studio の無料でないバージョンがある場合は、Debug メニューからミニダンプ
を保存し、それをバグ報告と一緒に送ることができる。ミニダンプは、プロセスの状態
についての情報を含む小さなファイル (<100KB) である。
Visual C++ 2005 Express Edition はミニダンプを保存できず、ジャストインタイムデ
バッガとしてインストールすることもできない。ミニダンプを保存する必要がある場
合、またはジャストインタイム (ポストモーテム) デバッガが欲しい場合は、WinDbg
(debug-windbg) を使うこと。

                                                                debug-windbg
3.3 WinDbg での Vim のクラッシュのデバッグ

WinDbg のコピーを入手するには get-ms-debuggers を参照。

Visual Studio IDE と同様に、実行中の Vim のプロセスに WinDbg をアタッチできる。
システムが WinDbg をポストモーテムデバッガとして自動的に起動するようにすること
もできる。WinDbg をポストモーテムデバッガとして設定するには、"windbg -I" を実
行する。

実行中の Vim のプロセスに WinDbg をアタッチするには、WinDbg を起動する。File
メニューで、Attach to a Process を選択する。Vim のプロセスを選択し、OK をクリッ
クする。

この時点で、File メニューの Symbol File Path を選択し、Vim の PDB があるフォル
ダを sympath に追加する。Vim のソースがあるなら、File メニューの Source File
Path を使う。これで、WinDbg でソースファイルを開き、必要ならブレークポイントを
設定できる。クラッシュを再現する。WinDbg はクラッシュした場所でソースファイル
を開くはずである。View メニューを使って、コールスタック、ローカル変数、ウォッ
チウィンドウなどを調べられる。

WinDbg がポストモーテムデバッガである場合は、Vim のプロセスに WinDbg をアタッ
チする必要はない。単にクラッシュを再現すれば、WinDbg が自動的に起動する。上と
同様に、Symbol File Path および Source File Path を設定する。

ミニダンプを保存するには、WinDbg のコマンドラインで以下を入力する:
        .dump vim.dmp

                                                        debug-minidump
3.4 ミニダンプを開く

ミニダンプファイルがある場合は、それを Visual Studio または WinDbg で開ける。

Visual Studio 2005 では: File メニューで Open を選択し、次に Project/Solution
を選択する。.dmp ファイルに移動し、それを開く。ここで F5 を押してデバッガを起
動する。Symbol File Path を設定するには、debug-vs2005 の手順に従う。

WinDbg では: File メニューで Open Crash Dump を選択する。Symbol File Path を設
定するには、debug-windbg の手順に従う。

                                                        get-ms-debuggers
3.5 Microsoft のデバッグツールの入手

Debugging Tools for Windows (WinDbg を含む) は以下からダウンロードできる
    https://learn.microsoft.com/en-us/windows-hardware/drivers/debugger/debugger-download-tools
これには WinDbg デバッガが含まれる。

Visual C++ 2005 Express Edition は以下から無料でダウンロードできる:
    https://visualstudio.microsoft.com/
