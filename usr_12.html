12.1  単語を置換する

置換コマンドを使って、ある単語のすべての出現を別の単語で置き換えることができま
す:

        :%s/four/4/g

範囲 "%" は、すべての行で置換することを意味します。末尾の "g" フラグにより、行
内のすべての単語が置換されます。
   ファイルに "thirtyfour" も含まれている場合、これは正しく動作しません。それ
は "thirty4" に置換されてしまいます。これを避けるには、"\<" アイテムを使って単
語の先頭にマッチさせます:

        :%s/\<four/4/g

明らかに、これでもまだ "fourteen" ではうまくいきません。"\>" を使って単語の末
尾にマッチさせます:

        :%s/\<four\>/4/g

プログラミングをしている場合、コメント内の "four" は置換したいが、コード内のも
のは置換したくないかもしれません。これは指定するのが難しいので、"c" フラグを追
加して、置換コマンドが置換ごとに確認を求めるようにします:


        :%s/\<four\>/4/gc


複数のファイルで置換する

単語を複数のファイルで置換したいとします。各ファイルを編集してコマンドを手でタ
イプすることもできます。記録および再生を使う方がずっと速いです。
   すべて ".cpp" で終わる C++ ファイルがあるディレクトリがあるとします。
"GetAnswer" に名前を変更したい "GetResp" という関数があります。

        vim *.cpp               Vim を起動し、引数リストにすべての C++ ファイ
                                ルが含まれるように定義します。これで最初のファ
                                イルにいます。
        qq                      q レジスタへの記録を開始します
        :%s/\<GetResp\>/GetAnswer/g
                                最初のファイルで置換を行います。
        :wnext                  このファイルを書き込み、次のファイルに移動しま
                                す。
        q                       記録を停止します。
        @q                      q レジスタを実行します。これにより、置換および
                                ":wnext" が再生されます。これがエラーメッセー
                                ジを出さないことを確認できます。
        999@q                   残りのファイルで q レジスタを実行します。

最後のファイルでは、":wnext" が次のファイルに移動できないため、エラーメッセー
ジが出ます。これにより実行が止まり、すべてが完了します。

        Note:
        記録したシーケンスを再生しているとき、エラーが起きると実行は止まりま
        す。したがって、記録するときにエラーメッセージが出ないことを確認してく
        ださい。

1 つ落とし穴があります: .cpp ファイルの 1 つが単語 "GetResp" を含んでいない場
合、エラーが出て置換が止まります。これを避けるには、置換コマンドに "e" フラグ
を追加します:

        :%s/\<GetResp\>/GetAnswer/ge

"e" フラグは、マッチが見つからないことはエラーではないと ":substitute" に伝え
ます。

12.2  "Last, First" を "First Last" に変更する

この形式の名前のリストがあります:

        Doe, John
        Smith, Peter

それを次のように変更したいです:

        John Doe
        Peter Smith

これはたった 1 つのコマンドで行えます:

        :%s/\([^,]*\), \(.*\)/\2 \1/

これを部分に分解してみましょう。明らかに、これは置換コマンドで始まっています。
"%" は行範囲で、ファイル全体を表します。したがって、置換はファイルのすべての行
で行われます。
   置換コマンドの引数は "/from/to/" です。スラッシュは "from" パターンおよび
"to" 文字列を区切ります。"from" パターンに含まれるのはこれです:
                                                        \([^,]*\), \(.*\)

        最初の \( \) の間の部分は "Last" にマッチする   \(     \)
            コンマ以外の任意の文字にマッチ                [^,]
            任意の回数                                        *
        ", " にそのままマッチする                                ,
        2 番目の \( \) の間の部分は "First" にマッチする           \(  \)
            任意の文字                                               .
            任意の回数                                                *

"to" の部分には "\2" および "\1" があります。これらは後方参照と呼ばれます。こ
れらは、パターン内の "\( \)" の部分にマッチしたテキストを参照します。"\2" は 2
番目の "\( \)" にマッチしたテキストを参照し、これは "First" の名前です。"\1"
は最初の "\( \)" を参照し、これは "Last" の名前です。
   置換コマンドの "to" の部分では、最大 9 個の後方参照を使えます。"\0" はマッ
チしたパターン全体を表します。置換コマンドには、さらにいくつかの特殊なアイテム
があります。sub-replace-special を参照してください。

12.3  リストをソートする

Makefile には、よくファイルのリストがあります。例えば:

        OBJS = \
                version.o \
                pch.o \
                getopt.o \
                util.o \
                getopt1.o \
                inp.o \
                patch.o \
                backup.o

このリストをソートするには、テキストを外部の sort コマンドに通してフィルタしま
す:

        /^OBJS
        j
        :.,/^$/-1!sort

これは、"OBJS" が行の最初にある最初の行に移動します。次に 1 行下に移動し、次の
空行までの行をフィルタします。ビジュアルモードで行を選択してから "!sort" を使
うこともできます。その方がタイプするのは簡単ですが、行が多いときは手間が増えま
す。
   結果はこうなります:

        OBJS = \
                backup.o
                getopt.o \
                getopt1.o \
                inp.o \
                patch.o \
                pch.o \
                util.o \
                version.o \


各行の末尾のバックスラッシュは、行が続くことを示すために使われていることに注目
してください。ソートした後では、これは正しくありません! 末尾にあった
"backup.o" の行にはバックスラッシュがありませんでした。別の場所にソートされた
今、それにはバックスラッシュが必要です。
   最も簡単な解決法は、"A \<Esc>" でバックスラッシュを追加することです。最後の
行の後に必ず空行が来るようにすれば、最後の行にバックスラッシュを残しておくこと
ができます。そうすれば、この問題が再び起きることはありません。

12.4  行の順序を逆にする

:global コマンドを :move コマンドと組み合わせて、すべての行を最初の行の前
に移動し、結果としてファイルを逆順にすることができます。コマンドはこうです:

        :global/^/move 0

省略形:

        :g/^/m 0

正規表現 "^" は行の先頭にマッチします (行が空であっても)。:move コマンドは、
マッチした行を仮想的な 0 行目の後に移動するので、現在マッチした行がファイルの
最初の行になります。:global コマンドは変化する行番号に惑わされないので、
:global はファイルの残りのすべての行のマッチを続け、それぞれを最初の行に置き
ます。

これは行の範囲にも使えます。まず最初の行の上に移動し、"mt" でマークします。次
に、範囲の最後の行にカーソルを移動して、こうタイプします:

        :'t+1,.g/^/m 't

12.5  単語を数える

最大の単語数が決められた文章を書かなければならないことがあります。Vim はあなた
のために単語を数えることができます。
   ファイル全体の単語を数えたいときは、このコマンドを使います:

        g CTRL-G

g の後に空白をタイプしないでください。これは、ここでコマンドを読みやすくするた
めに使っているだけです。
   出力はこのようになります:

        Col 1 of 0; Line 141 of 157; Word 748 of 774; Byte 4489 of 4976

自分がどの単語にいるか (748)、およびファイル内の単語の総数 (774) がわかります。

文章がファイルの一部だけの場合、文章の先頭に移動して "g CTRL-G" とタイプし、文
章の末尾に移動してもう一度 "g CTRL-G" とタイプし、それから頭を使って単語の位置
の差を計算することもできます。それは良い練習ですが、もっと簡単な方法がありま
す。ビジュアルモードで、単語を数えたいテキストを選択します。それから g CTRL-G
とタイプします。結果:

        Selected 5 of 293 Lines; 70 of 1884 Words; 359 of 10928 Bytes

単語、行、およびその他のアイテムを数える他の方法については、count-items を参
照してください。

12.6  man ページを探す                                find-manpage

シェルスクリプトまたは C プログラムを編集していて、man ページを探したいコマン
ドまたは関数を使っています (これは Unix の場合です)。まず簡単な方法を使ってみ
ましょう: ヘルプを探したい単語にカーソルを移動して、これを押します

        K

Vim はその単語に対して外部の "man" プログラムを実行します。man ページが見つか
れば、それが表示されます。これは、テキストをスクロールするのに通常のページャ
(たいていは "more" プログラム) を使います。最後まで行ったら、<Enter> を押すと
Vim に戻ります。

欠点は、man ページおよび作業中のテキストを同時に見られないことです。man ページ
を Vim のウィンドウに表示させる技があります。まず、man ファイルタイププラグイ
ンを読み込みます:

        :runtime! ftplugin/man.vim

これを頻繁に行うつもりの場合、このコマンドを vimrc ファイルに書いてください。
これで、":Man" コマンドを使って man ページのウィンドウを開くことができます:

        :Man csh

スクロールすることができ、テキストはハイライトされています。これで探していたヘ
ルプを見つけられます。CTRL-W w を使って、作業していたテキストのウィンドウにジャ
ンプします。
   特定のセクションの man ページを探すには、セクション番号を先に置きます。例え
ば、セクション 3 で "echo" を探すには:

        :Man 3 echo

別の man ページにジャンプするには、テキスト内にある典型的な形式 "word(1)" の上
で CTRL-] を押します。以降の ":Man" コマンドは同じウィンドウを使います。

カーソルの下の単語の man ページを表示するには、これを使います:

        \K

(<Leader> を再定義している場合は、バックスラッシュの代わりにそれを使ってくださ
い)。
例えば、この行を編集しているときに "strstr()" の戻り値を知りたいとします:

        if ( strstr (input, "aap") == )

カーソルを "strstr" のどこかに移動して "\K" とタイプします。ウィンドウが開いて
strstr() の man ページが表示されます。

12.7  空白を取り除く

行末の空白およびタブを、役に立たず、無駄で、醜いと考える人もいます。すべての行
の行末の空白文字を取り除くには、以下のコマンドを実行します:

        :%s/\s\+$//

行範囲 "%" が使われているので、これはファイル全体に作用します。":substitute"
コマンドがマッチするパターンは "\s\+$" です。これは行末 ($) の前にある、1 個以
上 (\+) の空白文字 (\s) を見つけます。このようなパターンの書き方は後で説明しま
す。usr_27.txt を参照してください。
   置換コマンドの "to" の部分は空です: "//"。したがって、何もないもので置換し、
実質的にマッチした空白を削除します。

空白のもう 1 つの無駄な使い方は、タブの前に置くことです。多くの場合、空白の量
を変えずにこれらを削除できます。しかし、常にではありません! したがって、これは
手で行うのが一番です。この検索コマンドを使います:

        /       

見えませんが、このコマンドではタブの前に空白があります。したがって、
"/<Space><Tab>" です。では "x" を使って空白を削除し、空白の量が変わらないこと
を確認します。変わる場合は、タブを挿入する必要があるかもしれません。"n" とタイ
プして次のマッチを探します。マッチが見つからなくなるまでこれを繰り返します。

12.8  単語が使われている場所を探す

UNIX ユーザーの場合、Vim および grep コマンドを組み合わせて、ある単語を含むす
べてのファイルを編集できます。これは、プログラムで作業していて、特定の変数を含
むすべてのファイルを表示または編集したい場合に非常に便利です。
   例えば、単語 "frame_counter" を含むすべての C プログラムファイルを編集した
いとします。これを行うには、このコマンドを使います:

        vim `grep -l frame_counter *.c`

このコマンドを詳しく見てみましょう。grep コマンドは、ファイルの集合から指定さ
れた単語を検索します。-l 引数が指定されているので、このコマンドは単語を含むファ
イルを一覧表示するだけで、マッチした行は出力しません。検索している単語は
"frame_counter" です。実際には、これは任意の正規表現にできます。(Note: grep が
正規表現として使うものは、Vim が使うものとまったく同じではありません。)
   コマンド全体はバッククォート (`) で囲まれています。これは UNIX シェルに、こ
のコマンドを実行して、その結果がコマンドラインでタイプされたかのように振る舞う
よう指示します。つまり、grep コマンドが実行されてファイルのリストが作られ、そ
れらのファイルが Vim のコマンドラインに置かれます。これにより、Vim は grep の
出力であるファイルリストを編集することになります。その後、":next" および
":first" のようなコマンドを使ってファイルを見て回ることができます。


各行を探す

上のコマンドは、その単語が見つかったファイルを探すだけです。それらのファイルの
中で単語を探す必要がまだあります。
   Vim には、ファイルの集合から指定された文字列を検索するのに使える組み込みコ
マンドがあります。例えば、すべての C プログラムファイルで "error_string" のす
べての出現を探したい場合は、以下のコマンドを入力します:

        :grep error_string *.c

これにより、Vim は指定されたすべてのファイル (*.c) で文字列 "error_string" を
検索します。エディタは、マッチが見つかった最初のファイルを開き、最初にマッチし
た行にカーソルを置きます。次にマッチした行に行くには (それがどのファイルにあっ
ても)、":cnext" コマンドを使います。前のマッチに行くには、":cprev" コマンドを
使います。":clist" を使うと、すべてのマッチおよびそれらの場所を確認できます。
   ":grep" コマンドは、外部コマンド grep (Unix の場合) または findstr (Windows
の場合) を使います。オプション 'grepprg' を設定することで、これを変更できます。
