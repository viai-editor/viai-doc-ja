1. 検索コマンド                                 search-commands

                                                        /
/{pattern}[/]<CR>       [count] 番目に現れる {pattern} を前方へ検索する
                        exclusive。

/{pattern}/{offset}<CR> [count] 番目に現れる {pattern} を前方へ検索し、
                        {offset} 行だけ上または下へ移動する。linewise。

                                                        /<CR>
/<CR>                   最後に使われたパターン last-pattern が [count] 番目
                        に現れる所を、最後に使われた {offset} で前方へ検索す
                        る。

//{offset}<CR>          最後に使われたパターン last-pattern が [count] 番目
                        に現れる所を、新しい {offset} で前方へ検索する。
                        {offset} が空の場合、オフセットは使われない。

                                                        ?
?{pattern}[?]<CR>       [count] 番目に前に現れる {pattern} を後方へ検索する
                        exclusive。

?{pattern}?{offset}<CR> [count] 番目に前に現れる {pattern} を後方へ検索し、
                        {offset} 行だけ上または下へ移動する linewise。

                                                        ?<CR>
?<CR>                   最後に使われたパターン last-pattern が [count] 番目
                        に現れる所を、最後に使われた {offset} で後方へ検索す
                        る。

??{offset}<CR>          最後に使われたパターン last-pattern が [count] 番目
                        に現れる所を、新しい {offset} で後方へ検索する。
                        {offset} が空の場合、オフセットは使われない。

                                                        n
n                       最後の "/" または "?" を [count] 回繰り返す。
                        カーソルが移動しない場合、検索は count + 1 で繰り返さ
                        れる。
                        last-pattern

                                                        N
N                       最後の "/" または "?" を逆方向に [count] 回繰り返す。
                        last-pattern

                                                        star E348 E349
*                       カーソルに最も近い単語が [count] 番目に現れる所を前方
                        へ検索する。検索に使われる単語は以下のうちの最初のもの:
                                1. カーソル下のキーワード 'iskeyword'
                                2. 現在行の、カーソルの後ろの最初のキーワード
                                3. カーソル下の非空白文字の単語
                                4. 現在行の、カーソルの後ろの最初の非空白文字
                                   の単語
                        コマンド "/\<keyword\>" を使った時のように、キーワード
                        全体のみが検索される。exclusive
                        'ignorecase' は使われるが、'smartcase' は使われない。

                                                        #
#                       "*" と同じだが、後方へ検索する。ポンド記号 (文字 163)
                        も機能する。"#" キーがバックスペースとして機能する場
                        合、Vim を起動する前に "stty erase <BS>" を使ってみる
                        こと (<BS> は CTRL-H または本物のバックスペース)。

                                                        gstar
g*                      "*" と同様だが、単語の周りに "\<" および "\>" を置かな
                        い。これにより、単語全体ではないマッチも検索で見つか
                        る。

                                                        g#
g#                      "#" と同様だが、単語の周りに "\<" および "\>" を置かな
                        い。これにより、単語全体ではないマッチも検索で見つか
                        る。

                                                        gd
gd                      ローカル宣言へ移動する。カーソルがローカル変数の上にあ
                        る時、このコマンドはその宣言へジャンプする。これは C
                        のコード用に作られたもので、他の言語ではうまく機能しな
                        いかもしれない。
                        まず Vim は "[[" と同様に、現在の関数の開始を検索する。
                        それが見つからない場合、検索は 1 行目で止まる。それが
                        見つかった場合、Vim は空行が見つかるまで戻る。この位置
                        から Vim は "*" と同様にカーソル下のキーワードを検索す
                        るが、コメントのように見える行は無視される ('comments'
                        オプションを参照)。
                        Note これが機能する保証は無く、Vim は実際には構文を
                        チェックせず、キーワードに対するマッチを検索するだけで
                        あることに注意。インクルードされたファイルも検索する必
                        要がある場合、include-search に挙げられているコマン
                        ドを使うこと。このコマンドの後、n は次のマッチを前方
                        へ検索する (後方ではない)。

                                                        gD
gD                      グローバル宣言へ移動する。カーソルがファイル内で定義さ
                        れているグローバル変数の上にある時、このコマンドはその
                        宣言へジャンプする。これは "gd" とまったく同じように機
                        能するが、キーワードの検索が常に 1 行目から始まる点が
                        異なる。

                                                        1gd
1gd                     "gd" と同様だが、カーソル位置の前で終わる {} ブロック
                        内のマッチを無視する。

                                                        1gD
1gD                     "gD" と同様だが、カーソル位置の前で終わる {} ブロック
                        内のマッチを無視する。

                                                        CTRL-C
CTRL-C                  現在の (検索) コマンドを中断する。MS-Windows では
                        CTRL-Break を使う dos-CTRL-Break。
                        ノーマルモードでは、保留中のコマンドは全て中止される。
                        Vim が出力をリダイレクトして起動され、変更されたバッ
                        ファが無い場合、CTRL-C は Vim を終了する。これは
                        "vim file | grep word" を使い、抜け出す方法を知らない
                        ユーザーを助けるためである (やみくもに :qa<CR> とタイ
                        プすれば機能するだろう)。
                        popup-filter を持つポップアップが開いている場合、そ
                        のポップアップは閉じられる。

                                                        :noh :nohlsearch
:noh[lsearch]           'hlsearch' オプションによるハイライトを停止する。検索
                        コマンドを使った時、または 'hlsearch' オプションを設定
                        した時に、自動的に再びオンになる。
                        このコマンドは自動コマンド内では機能しない。なぜなら、
                        自動コマンドを実行する時にハイライトの状態が保存され、
                        復元されるからである autocmd-searchpat。
                        ユーザー関数を呼び出す時も同じである。


検索パターンをタイプしている間、'incsearch' オプションがオンの場合、現在のマッ
チが表示される。表示されたマッチに実際にカーソルを置くには、やはり <CR> で検索
コマンドを終える必要があることを覚えておくこと。または <Esc> を使って検索を中
止する。

                                                        nohlsearch-auto
'hlsearch' オプションを設定した場合、最後に使われた検索パターンに対する全ての
マッチがハイライトされる。これは :nohlsearch コマンドで一時停止するか、また
は nohlsearch プラグインで自動的に一時停止できる。nohlsearch-install を参照。


'shortmess' に "S" フラグが含まれていない場合、Vim はカーソルがどこにあるかの
インデックスを自動的に表示する。これはこのように見える:

  [1/5]         カーソルは 5 個のマッチの 1 番目にある。
  [1/>99]       カーソルは 99 個より多いマッチの 1 番目にある。
  [>99/>99]     カーソルは 99 個より多いマッチのうち 99 マッチより後ろにある。
  [?/??]        マッチがいくつ存在するか不明。検索タイムアウトにより、
                統計の生成が中止された。

Note: カウントはオフセットを考慮しない。

マッチが見つからない場合、エラーが出る: E486 Pattern not found
Note :global コマンドでは、旧来のスクリプト内で使われた場合、Vi 互換のため、
通常のメッセージ "Pattern not found" が出ることに注意。
Vim9 script では、"pattern not found" に対して E486 が出るか、または
:vglobal でパターンが全ての行にマッチする場合は E538 が出る。
:s コマンドでは、エラーメッセージを避けるために "e" フラグを使える
:s_flags。

                                        search-options
以下のオプションは Vim で検索がどのように実行されるかに影響する:
    'hlsearch'          マッチをハイライトする
    'ignorecase'        検索時に大文字小文字を無視する
    'imsearch'          検索パターンを入力する時に IME を使う
    'incsearch'         パターンをタイプするにつれてマッチを逐次表示する
    'maxsearchcount'    検索カウントの最大数 shm-S
    'shortmess'         メッセージを抑止する shm-s、検索カウントを表示する shm-S
    'smartcase'         パターンが大文字を含む場合 'ignorecase' を上書きする
    'wrapscan'          ファイルの先頭から検索を続ける

                                        search-offset {offset}
これらのコマンドは指定されたパターンを検索する。"/" および "?" では、追加のオ
フセットを指定できる。オフセットには 2 種類ある: 行オフセットおよび文字オフセッ
ト。

オフセットは、見つかったマッチからの相対的なカーソル位置を与える:
    [num]       [num] 行下へ、1 桁目
    +[num]      [num] 行下へ、1 桁目
    -[num]      [num] 行上へ、1 桁目
    e[+num]     マッチの末尾から [num] 文字右
    e[-num]     マッチの末尾から [num] 文字左
    s[+num]     マッチの先頭から [num] 文字右
    s[-num]     マッチの先頭から [num] 文字左
    b[+num]     [num] 上記の s[+num] と同じ (覚え方: begin)
    b[-num]     [num] 上記の s[-num] と同じ (覚え方: begin)
    ;{pattern}  別の検索を実行する。//; を参照

'-' または '+' が指定されたが [num] が省略された場合、カウント 1 が使われる。
'e' を含むオフセットを指定した場合、検索は inclusive になる (カーソルが着地す
る文字が操作に含まれる)。

例:

パターン                カーソル位置
/test/+1                "test" の 1 行下、1 桁目
/test/e                 "test" の最後の t の上
/test/s+2               "test" の 's' の上
/test/b-3               "test" の 3 文字前

これらのコマンドの 1 つがオペレータの後で使われた場合、検索の前と後のカーソル
位置の間の文字が影響を受ける。ただし、行オフセットが指定された場合、2 つのカー
ソル位置の間の行全体が影響を受ける。

パターンでマッチを検索し、そのマッチを別の単語に変更する方法の例:
        /foo<CR>        "foo" を見つける
        c//e<CR>        マッチの末尾まで変更する
        bar<Esc>        置換文字列をタイプする
        //<CR>          次のマッチの先頭へ移動する
        c//e<CR>        マッチの末尾まで変更する
        beep<Esc>       別の置換文字列をタイプする
                        など

                                                        //; E386
とても特別なオフセットは、';' の後に別の検索コマンドが続くものである。例:

   /test 1/;/test
   /test.*/+1;?ing?

最初のものは、まず次に現れる "test 1" を見つけ、それからその後に最初に現れる
"test" を見つける。

これは 2 つの検索コマンドを続けて実行するのと同様だが、以下を除く:
- オペレータの後で単一のモーションコマンドとして使用できる。
- 後続の "n" または "N" コマンドの方向は、最初の検索コマンドから来る。
- エラーが起きた場合、カーソルはまったく移動しない。

                                                        last-pattern
最後に使われたパターンおよびオフセットは記憶される。これらは検索を繰り返すのに
使用でき、場合によっては別の方向で、または別のカウントで繰り返せる。Note 2 つ
のパターンが記憶されることに注意: 1 つは "通常の" 検索コマンド用、もう 1 つは
置換コマンド ":s" 用である。空のパターンが指定されるたびに、前回使われたパター
ンが使われる。ただし、前回の検索コマンドが無い場合、可能な場合は前回の置換パ
ターンが使われる。

'magic' オプションは最後に使われたパターンに結び付く。'magic' を変更した場合、
これは最後に使われたパターンの解釈のされ方を変えない。
'ignorecase' オプションはこうはならない。'ignorecase' が変更されると、パターン
が別のテキストにマッチする結果になる。

'hlsearch' オプションを設定した場合、最後に使われた検索パターンに対する全ての
マッチがハイライトされる。

最後に使われた検索パターンをクリアするには:
        :let @/ = ""
これはパターンを空文字列に設定するのではない。それは全ての場所にマッチしてしま
うからである。パターンは、Vim を起動した時のように本当にクリアされる。

検索は通常、カーソルを移動しないマッチをスキップする。次のマッチが次の文字で見
つかるか、またはスキップしたマッチの後ろで見つかるかは、'cpoptions' の 'c' フ
ラグに依存する。cpo-c を参照。
        'c' フラグあり:   "/..." は 1 から 3 文字進む
        'c' フラグなし:   "/..." は 1 文字進む
'c' フラグでの予測できなさは、検索を最初の桁から始め、カーソル位置を過ぎたマッ
チが見つかるまでマッチをスキップすることによって起きる。

後方へ検索する時、検索は行の先頭から始まり、上記で説明したように 'cpoptions'
の 'c' フラグを使う。それから、カーソル位置の前の最後のマッチが使われる。

Vi では ":tag" コマンドは、タグを検索する時に最後の検索パターンを設定する。Vim
ではこれは行われず、'cpoptions' に 't' フラグが含まれていない限り、前回の検索
パターンは引き続き記憶されている。検索パターンは常に検索履歴に入れられる。

'wrapscan' オプションがオンの場合 (これがデフォルト)、検索はバッファの末尾で折
り返す。'wrapscan' が設定されていない場合、後方検索は先頭で止まり、前方検索は
バッファの末尾で止まる。'wrapscan' が設定されていて、パターンが見つからなかっ
た場合、エラーメッセージ "pattern not found" が出され、カーソルは移動しない。
'wrapscan' が設定されていない場合、メッセージは、前方へ検索する時は
"search hit BOTTOM without match"、後方へ検索する時は
"search hit TOP without match" になる。wrapscan が設定されていて、検索がファイ
ルの末尾で折り返した場合、後方または前方へ検索する時に、それぞれ
"search hit TOP, continuing at BOTTOM" または
"search hit BOTTOM, continuing at TOP" というメッセージが出される。これは
'shortmess' オプションに 's' フラグを設定することでオフにできる。このメッセー
ジにはハイライト方法 'w' が使われる (デフォルト: standout)。

                                                        search-range
\%>l 項目を含めることで、検索コマンド "/" を特定の範囲の行に限定できる。例え
ば、199 行目より下で、300 行目より上の単語 "limit" にマッチさせるには:
        /\%>199l\%<300llimit
/\%>l も参照。

別の方法は、'c' フラグ付きで ":substitute" コマンドを使うことである。例:
   :.,300s/Pattern//gc
このコマンドはカーソル位置から 300 行目まで "Pattern" を検索する。マッチの所
で、文字をタイプするよう求められる。このマッチで止めるには 'q' をタイプし、次
のマッチを見つけるには 'n' をタイプする。

"*"、"#"、"g*" および "g#" コマンドは、この順序でカーソルの近くの単語を探し、
最初に見つかったものが使われる:
- 現在カーソル下にあるキーワード。
- カーソルの右側にある、同じ行内の最初のキーワード。
- 現在カーソル下にある WORD。
- カーソルの右側にある、同じ行内の最初の WORD。
キーワードには英字および 'iskeyword' 内の文字のみを含めることができる。
WORD には任意の非空白文字 (<Tab> および/または <Space>) を含めることができる。
Note 10 本の指でタイプする場合、文字を覚えやすいことに注意: "#" は左手の中指の
下にあり (左および上へ検索)、"*" は右手の中指の下にある (右および下へ検索)。
(ただし、これはキーボードのレイアウトに依存する)。

                                                                E956
ごくまれに、正規表現が再帰的に使われることがある。これは、パターンの実行に長い
時間がかかり、チャネル上のメッセージをチェックする時に、同じくパターンを使う
コールバックが呼び出されるか、または自動コマンドが発生した場合に起こり得る。ほ
とんどの場合これで問題無いはずだが、パターンが再び使われる時にそれが使用中の場
合、失敗する。通常これはパターンに何か問題があることを意味する。

2. パターンの定義                       search-pattern pattern [pattern]
                                        regular-expression regexp Pattern
                                        E383 E476

手始めに、ユーザーマニュアルの 27 章 usr_27.txt を読むこと。

                                                /bar /\bar /pattern
1. パターンは 1 つ以上のブランチで、"\|" で区切られる。いずれかのブランチにマッ
   チするものにマッチする。例: "foo\|beep" は "foo" にマッチし、"beep" にマッ
   チする。複数のブランチがマッチする場合、最初のものが使われる。

   pattern ::=      branch
                or  branch \| branch
                or  branch \| branch \| branch
                etc.

                                                /branch /\&
2. ブランチは 1 つ以上の concat で、"\&" で区切られる。最後の concat にマッチ
   するが、それは先行する全ての concat も同じ位置でマッチする場合のみである。
   例:
        "foobeep\&..." は "foobeep" 内の "foo" にマッチする。
        ".*Peter\&.*Bob" は "Peter" および "Bob" の両方を含む行でマッチする

   branch ::=       concat
                or  concat \& concat
                or  concat \& concat \& concat
                etc.

                                                /concat
3. concat は 1 つ以上のピースを連結したものである。最初のピースに対するマッチ、
   それに続く 2 番目のピースに対するマッチ、などにマッチする。例: "f[0-9]b"
   は、まず "f" にマッチし、次に数字、そして "b" にマッチする。

   concat  ::=      piece
                or  piece piece
                or  piece piece piece
                etc.

                                                /piece
4. ピースはアトムであり、その後に、アトムが何回マッチできるかの指示であるマル

3. マジック                                                     /magic

パターン中の、英字などのいくつかの文字は、文字どおりに解釈される。それらはテキ
スト中のまったく同じ文字にマッチする。しかし、バックスラッシュが前に付くと、こ
れらの文字は特別な意味を持つことがある。例えば、"a" は文字 "a" にマッチするが、
"\a" は任意の英字にマッチする。

その他の文字はバックスラッシュ無しで特別な意味を持つ。文字どおりにマッチさせる
には、前にバックスラッシュを付ける必要がある。例えば "." は任意の文字にマッチ
するが、"\." はドットにマッチする。

文字が文字どおりに解釈されるかどうかは、'magic' オプションおよび次に述べるパ
ターン中の項目に依存する。'magic' オプションは常に設定しておくべきだが、Vi 互
換のためにオフにすることもできる。完全を期すためにここで 'nomagic' の効果に言
及するが、それを使うことは推奨しない。
                                                        /\m /\M
"\m" を使うと、その後ろのパターンは、実際の 'magic' オプションの値を無視して、
'magic' が設定されているかのように解釈される。
"\M" を使うと、その後ろのパターンは 'nomagic' が使われているかのように解釈され
る。
                                                        /\v /\V
"\v" を使うと、その後ろでは '0'-'9'、'a'-'z'、'A'-'Z' および '_' を除く全ての
ASCII 文字が特別な意味を持つ: "very magic"

"\V" を使うと、その後ろではバックスラッシュおよび終端文字 (通常は / または ?)
のみが特別な意味を持つ: "very nomagic"

例:
後ろ:     \v       \m       \M       \V         マッチするもの
                'magic' 'nomagic'
          a        a        a        a          文字どおりの 'a'

          .        .        \.       \.         任意の文字

          $        $        $        \$         行末

          ()       \(\)     \(\)     \(\)       アトムとしてのグループ
          |        \|       \|       \|         無し: 選択肢を区切る

5. マルチ項目                                           pattern-multi-items

アトムの後ろには、アトムが何回、どのような方法でマッチできるかの指示を続けるこ
とができる。これはマルチと呼ばれる。概要は /multi を参照。

                                                        /star /\star
*       ('magic' が設定されていない時は \* を使う)
        直前のアトムの 0 個以上に、できるだけ多くマッチする。

        a\(bc\)\{1,2}d          "abcd" または "abcbcd"

        a[bc]*[cd]              "abcd" 内の "abcd"

        } の前にはバックスラッシュを付けてもよい: \{n,m\}。

\@=     直前のアトムに幅ゼロでマッチする。
        Perl の "(?=pattern)" と同様。
        例                      マッチするもの
        foo\(bar\)\@=           "foobar" 内の "foo"
        foo\(bar\)\@=foo        無し
                                                        /zero-width
        "\@=" (または "^"、"$"、"\<"、"\>") を使う時、マッチには文字が含まれな
        い。これらの項目は、マッチできるかどうかをチェックするためだけに使われ
        る。後続の項目とのマッチが同じ位置で行われるため、これは扱いにくいこと
        がある。上記の最後の例は "foobarfoo" にマッチしない。なぜなら、"bar"
        がマッチしたのと同じ位置で "foo" のマッチを試みるからである。

        Note "\&" を使うのは "\@=" を使うのと同じように機能することに注意:
        "foo\&.." は "\(foo\)\@=.." と同じである。しかし "\&" を使う方が簡単
        で、括弧が必要ない。


                                                        /\@!
\@!     直前のアトムが現在位置でマッチしない場合、幅ゼロでマッチする。
        /zero-width
        Perl の "(?!pattern)" と同様。
        例                      マッチするもの
        foo\(bar\)\@!           "bar" が後ろに続かない任意の "foo"
        a.\{-}p\@!              直後に "p" が続かない
                                "a"、"ap"、"app"、"appp" など
        if \(\(then\)\@!.\)*$   "then" が後ろに続かない "if "

        "\@!" を使うのは扱いにくい。なぜなら、パターンがマッチしない場所はたく
        さんあるからである。"a.*p\@!" は "a" から行末までにマッチする。なぜな
        ら、".*" は行内の全ての文字にマッチでき、"p" は行末ではマッチしないか
        らである。"a.\{-}p\@!" は "p" が後ろに続かない任意の "a"、"ap"、"app"
        などにマッチする。なぜなら、"." は "p" にマッチでき、その後ろでは
        "p\@!" がマッチしないからである。

        マッチする位置の前でマッチしないものを探すために "\@!" を使うことはで
        きない: "\(foo\)\@!bar" は "foobar" 内の "bar" にマッチする。なぜなら、
        "bar" がマッチする位置では "foo" はマッチしないからである。"foobar" に
        マッチするのを避けるには "\(foo\)\@!...bar" を使うことができるが、それ
        は行頭の bar にはマッチしない。"\(foo\)\@<!bar" を使うこと。

        役に立つ例: "bar" を含まない行で "foo" を見つけるには:
                /^\%(.*bar\)\@!.*\zsfoo
        このパターンはまず、行内に "bar" がマッチする位置が 1 つも無いことを
        チェックする。".*bar" がどこかでマッチする場合、\@! はパターンを拒否す
        る。マッチが無い場合、任意の "foo" が見つかる。"\zs" は "foo" の直前か
        らマッチを開始させるためのものである。

                                                        /\@<=
\@<=    直前のアトムが後に続くものの直前でマッチする場合、幅ゼロでマッチする。
        /zero-width
        Perl の "(?<=pattern)" と同様だが、Vim では固定幅でないパターンも使え
        る。
        例                      マッチするもの
        \(an\_s\+\)\@<=file     "an" および空白または行末の後ろの "file"
        速度のためには、多くの場合このマルチを避ける方がずっとよい。代わりに
        "\zs" を使ってみること /\zs。上記の例と同じものにマッチさせるには:
                an\_s\+\zsfile
        少なくとも後読みに制限を設定すること。以下を参照。

        "\@<=" および "\@<!" は、後に続くものの直前でのマッチをチェックする。
        理論的には、これらのマッチはこの位置より前のどこからでも始まりうる。し
        かし、必要な時間を制限するため、後に続くものがマッチする行、およびその
        1 行前 (存在する場合) だけが検索される。これでほとんどのものにマッチす
        るのに十分で、遅くなりすぎないはずである。

        古い正規表現エンジンでは、"\@<=" および "\@<!" の後ろのパターンの部分
        が最初にマッチをチェックされる。そのため、"\1" のようなものは直前のア
        トム内の \(\) を参照するようには機能しない。逆の場合は機能する:
        悪い例                          マッチするもの
        \%#=1\1\@<=,\([a-z]\+\)         "abc,abc" 内の ",abc"

        しかし、新しい正規表現エンジンは異なる動作をするので、この動作に頼らな
        い方がよく、避けられる場合は \@<= を使わないこと:
        例                              マッチするもの
        \([a-z]\+\)\zs,\1               "abc,abc" 内の ",abc"

\@123<=
        "\@<=" と同様だが、123 バイトだけ遡って見る。これにより、失敗すること
        が分かっている多くのマッチを試し、パターンの実行がとても遅くなるのを避
        けられる。例えば、"span" の直前に "<" があるかどうかをチェックするには:
                /<\@1<=span
        これは "span" の 1 バイト前だけで "<" のマッチを試す。いずれにしてもそ
        こが機能する唯一の場所である。
        行の境界を越えた後、制限は行末からの相対になる。そのため、マッチのある
        行の先頭の文字は数えられない (これは単にシンプルにしておくためである)。
        数値のゼロは制限無しと同じである。

                                                        /\@<!
\@<!    直前のアトムが後に続くものの直前でマッチしない場合、幅ゼロでマッチす
        る。そのため、これは、現在行または前の行に、アトムが後に続くものの直前
        で終わるようにマッチする位置が無い場合にマッチする。/zero-width
        Perl の "(?<!pattern)" と同様だが、Vim では固定幅でないパターンも使え
        る。
        直前のアトムとのマッチは、後に続くものとのマッチの直前で終わるようにさ
        れるので、".*" で終わるアトムも機能する。
        警告: これは遅くなることがある (多くの位置でマッチをチェックする必要が
        あるため)。可能な場合は制限を使うこと。以下を参照。
        例                      マッチするもの
        \(foo\)\@<!bar          "foobar" 内にない任意の "bar"
        \(\/\/.*\)\@<!in        "//" の後ろにない "in"

\@123<!
        "\@<!" と同様だが、123 バイトだけ遡って見る。これにより、失敗すること
        が分かっている多くのマッチを試し、パターンの実行がとても遅くなるのを避
        けられる。

                                                        /\@>
\@>     パターン全体のマッチのように、直前のアトムにマッチする。
        Perl の "(?>pattern)" と同様。
        例              マッチするもの
        \(a*\)\@>a      無し ("a*" が全ての "a" を取るので、後ろに
                        もう 1 つ続くことはありえない)

        これは直前のアトムを、それ自体が 1 つのパターンであるかのようにマッチ
        させる。マッチしない場合、より短いサブマッチなどでの再試行は無い。この
        違いに注目すること: "a*b" および "a*ab" はどちらも "aaab" にマッチする
        が、2 番目の場合、"a*" は最初の 2 つの "a" だけにマッチする。
        "\(a*\)\@>ab" は "aaab" にマッチしない。なぜなら、"a*" が "aaa" (でき
        るだけ多くの "a") にマッチするので、"ab" がマッチできないからである。

6.  通常のアトム                                        pattern-atoms

通常のアトムは以下のものになりうる:

                                                        /^
^       パターンの先頭で、または "\|"、"\("、"\%(" または "\n" の後ろで: 行頭
        にマッチする。それ以外の位置では、文字どおりの '^' にマッチする。
        /zero-width
        例              マッチするもの
        ^beep(          C 関数 "beep" の開始 (おそらく)。

                                                        /\^
\^      文字どおりの '^' にマッチする。パターン中の任意の位置で使えるが、[] の
        中では使えない。

                                                        /\_^
\_^     行頭にマッチする。/zero-width パターン中の任意の位置で使えるが、[]
        の中では使えない。
        例              マッチするもの
        \_s*\_^foo      空白および空行、それから行頭の "foo"

                                                        /$
$       パターンの末尾で、または "\|"、"\)" または "\n" の前で ('magic' オン):
        行末 <EOL> にマッチする。それ以外の位置では、文字どおりの '$' にマッチ
        する。/zero-width

                                                        /\$
\$      文字どおりの '$' にマッチする。パターン中の任意の位置で使えるが、[] の
        中では使えない。

                                                        /\_$
\_$     行末にマッチする。/zero-width パターン中の任意の位置で使えるが、[]
        の中では使えない。Note "b" は行末にマッチできないので、"a\_$b" は決し
        てマッチしないことに注意。代わりに "a\nb" を使うこと /\n。
        例              マッチするもの
        foo\_$\_s*      行末の "foo"、およびそれに続く空白および空行

.       ('nomagic' の場合: \.)                          /. /\.
        任意の 1 文字にマッチするが、行末にはマッチしない。

                                                        /\_.
\_.     任意の 1 文字または行末にマッチする。
        注意: "\_.*" はバッファの末尾までの全てのテキストにマッチする!

                                                        /\<
\<      単語の先頭にマッチする: 次の文字が単語の最初の文字である。'iskeyword'
        オプションで何が単語構成文字かを指定する。/zero-width

                                                        /\>
\>      単語の末尾にマッチする: 前の文字が単語の最後の文字である。'iskeyword'
        オプションで何が単語構成文字かを指定する。/zero-width

                                                        /\zs
\zs     任意の位置で、ただし [] の中は除いてマッチし、そこをマッチの開始に設定
        する: 次の文字がマッチ全体の最初の文字になる。/zero-width
        例:
                /^\s*\zsif
        行頭の "if" に、空白を無視してマッチする。
        複数回使用でき、マッチするブランチ内で最後に出会ったものが使われる。例:

                /\(.\{-}\zsFab\)\{3}
        3 番目に現れる "Fab" を見つける。
        これの後ろにはマルチを続けられない。 E888
        {+syntax 機能付きでコンパイルされたときのみ有効}
                                                        /\ze
\ze     任意の位置で、ただし [] の中は除いてマッチし、そこをマッチの終了に設定
        する: 前の文字がマッチ全体の最後の文字になる。/zero-width
        複数回使用でき、マッチするブランチ内で最後に出会ったものが使われる。
        例: "end\ze\(if\|for\)" は "endif" および "endfor" 内の "end" にマッチ
        する。
        これの後ろにはマルチを続けられない。E888
        {+syntax 機能付きでコンパイルされたときのみ有効}

                                                /\%^ start-of-file
\%^     ファイルの先頭にマッチする。文字列とマッチする場合、文字列の先頭にマッ
        チする。
        例えば、ファイル内の最初の "VIM" を見つけるには:
                /\%^\_.\{-}\zsVIM

                                                /\%$ end-of-file
\%$     ファイルの末尾にマッチする。文字列とマッチする場合、文字列の末尾にマッ
        チする。
        Note これはファイル内の最後の "VIM" を見つけないことに注意:
                /VIM\_.\{-}\%$
        これは次の VIM を見つける。なぜなら、その後ろの部分は常にマッチするか
        らである。これはファイル内の最後の "VIM" を見つける:
                /VIM\ze\(\(VIM\)\@!\_.\)*\%$
        これは、最初の "VIM" の後ろのどの位置でも "VIM" がマッチしないことを確
        かめるために /\@! を使っている。
        ファイルの末尾から後方へ検索する方が簡単である!

                                                /\%V
\%V     ビジュアル範囲内でマッチする。ビジュアルモードがすでに停止している場
        合、gv が再選択する範囲内でマッチする。
        これは /zero-width マッチである。パターン全体が確実にビジュアル範囲
        内にあるようにするには、それをパターンの先頭および末尾の直前に置く。例:

                /\%Vfoo.*ba\%Vr
        これは、"foo bar" だけがビジュアル選択された場合も機能する。これは:
                /\%Vfoo.*bar\%V
        ビジュアル選択が "r" の後ろまで続いている場合、"foo bar" にマッチする
        だろう。
        現在のバッファでのみ機能する。

                                                /\%# cursor-position
\%#     カーソル位置にマッチする。ウィンドウに表示されているバッファ内でマッチ
        する場合のみ機能する。
        警告: パターンが使われた後でカーソルが移動された場合、結果は無効にな
        る。Vim はマッチを自動的に更新しない。これは構文ハイライトおよび
        'hlsearch' に特に関係する。言い換えると: カーソルが移動した時、その変
        更に対して表示は更新されない。更新は、変更された行に対して (行全体が更
        新される)、または CTRL-L コマンドを使った時 (画面全体が更新される)
        に行われる。例えば、カーソル下の単語をハイライトするには:
                /\k*\%#\k*
        'hlsearch' が設定されていて、カーソルをあちこち移動させ、変更を加える
        時、これはマッチが更新されたかどうかをはっきりと示す。

                                                /\%'m /\%<'m /\%>'m
\%'m    マーク m の位置にマッチする。
\%<'m   マーク m の位置の前でマッチする。
\%>'m   マーク m の位置の後ろでマッチする。
        例えば、マーク 's から 'e までのテキストをハイライトするには:
                /.\%>'s.*\%<'e..
        Note マーク 'e をマッチに含めるには 2 つのドットが必要であることに注
        意。なぜなら、"\%<'e" は 'e マークの前の文字でマッチし、それは
        /zero-width マッチなので、その文字を含まないからである。
        警告: パターンが使われた後でマークが移動された場合、結果は無効になる。
        Vim はマッチを自動的に更新しない。"\%#" でのカーソルの移動と同様である
        /\%#。

                                /\%l /\%>l /\%<l E951 E1204 E1273
\%23l   特定の行でマッチする。
\%<23l  特定の行より上でマッチする (より小さい行番号)。
\%>23l  特定の行より下でマッチする (より大きい行番号)。
\%.l    カーソル行でマッチする。
\%<.l   カーソル行より上でマッチする。
\%>.l   カーソル行より下でマッチする。
        これら 6 つは、バッファ内の特定の行にマッチさせるのに使える。"23" は任
        意の行番号でよい。最初の行は 1 である。
        警告: 行を挿入または削除する時、Vim はマッチを自動的に更新しない。これ
        は構文ハイライトがすぐに間違ったものになることを意味する。また、カーソ
        ル位置 (".") を参照していて、カーソルが移動した時、その変更に対して表
        示は更新されない。更新は CTRL-L コマンドを使った時に行われる (画面全
        体が更新される)。例えば、カーソルが現在ある行をハイライトするには:
                :exe '/\%' .. line(".") .. 'l'
        代わりに以下を使う:
                /\%.l
        'hlsearch' が設定されていて、カーソルをあちこち移動させ、変更を加える
        時、これはマッチが更新されたかどうかをはっきりと示す。

                                                /\%c /\%>c /\%<c
\%23c   特定の桁でマッチする。
\%<23c  特定の桁の前でマッチする。
\%>23c  特定の桁の後ろでマッチする。
\%.c    カーソル桁でマッチする。
\%<.c   カーソル桁の前でマッチする。
\%>.c   カーソル桁の後ろでマッチする。
        これら 6 つは、バッファまたは文字列内の特定の桁にマッチさせるのに使え
        る。"23" は任意の桁番号でよい。最初の桁は 1 である。実際には、桁はバイ
        ト番号である (そのため、マルチバイト文字に対しては正確には正しくない)。
        警告: テキストを挿入または削除する時、Vim はマッチを自動的に更新しな
        い。これは構文ハイライトがすぐに間違ったものになることを意味する。ま
        た、カーソル位置 (".") を参照していて、カーソルが移動した時、その変更
        に対して表示は更新されない。更新は CTRL-L コマンドを使った時に行われ
        る (画面全体が更新される)。例えば、カーソルが現在ある桁をハイライトす
        るには:
                :exe '/\%' .. col(".") .. 'c'
        代わりに以下を使う:
                /\%.c
        'hlsearch' が設定されていて、カーソルをあちこち移動させ、変更を加える
        時、これはマッチが更新されたかどうかをはっきりと示す。
        44 桁目の 1 バイトにマッチさせる例:
                /\%>43c.\%<46c
        Note "." が 44 桁目のバイトにマッチする時、"\%<46c" は 45 桁目でマッチ
        することに注意。
                                                /\%v /\%>v /\%<v
\%23v   特定の仮想桁でマッチする。
\%<23v  特定の仮想桁の前でマッチする。
\%>23v  特定の仮想桁の後ろでマッチする。
\%.v    現在の仮想桁でマッチする。
\%<.v   現在の仮想桁の前でマッチする。
\%>.v   現在の仮想桁の後ろでマッチする。
        これら 6 つは、バッファまたは文字列内の特定の仮想桁にマッチさせるのに
        使える。ウィンドウ内のバッファとマッチしていない場合、カレントウィンド
        ウのオプションの値が使われる (例えば 'tabstop')。
        "23" は任意の桁番号でよい。最初の桁は 1 である。
        Note いくつかの仮想桁の位置には決してマッチしないことに注意。なぜなら、
        それらはタブ、または複数の画面文字を占めるその他の文字の途中にあるから
        である。
        警告: テキストを挿入または削除する時、Vim はハイライトされたマッチを自
        動的に更新しない。これは構文ハイライトがすぐに間違ったものになることを
        意味する。また、カーソル位置 (".") を参照していて、カーソルが移動した
        時、その変更に対して表示は更新されない。更新は CTRL-L コマンドを使っ
        た時に行われる (画面全体が更新される)。例えば、仮想桁 72 の後ろの全て
        の文字をハイライトするには:
                /\%>72v.*
        'hlsearch' が設定されていて、カーソルをあちこち移動させ、変更を加える
        時、これはマッチが更新されたかどうかをはっきりと示す。
        17 桁目までのテキストにマッチさせるには:
                /^.*\%17v
        現在の仮想桁 (カーソルがある所) の後ろの全ての文字にマッチさせるには:

                /\%>.v.*
        これは /zero-width マッチなので、17 桁目は含まれない。その桁を含める
        には以下を使う:
                /^.*\%17v.
        このコマンドは同じことをするが、17 桁目に文字が無い場合にもマッチする:

                /^.*\%<18v.
        Note 最初の桁にマッチを固定する "^" が無いと、これは 17 桁目もハイライ
        トすることに注意:
                /.*\%17v
        ".*" がゼロ文字にマッチする別のマッチがあるため、17 桁目は 'hlsearch'
        によってハイライトされる。

7. パターン内での大文字小文字の無視                             /ignorecase

'ignorecase' オプションがオンの場合、通常の英字の大文字小文字は無視される。
'smartcase' を設定すると、パターンが小文字のみを含む場合に大文字小文字を無視す
るようにできる。
                                                        /\c /\C
"\c" がパターン中のどこかに現れた場合、パターン全体が 'ignorecase' がオンであ
るかのように扱われる。'ignorecase' および 'smartcase' の実際の値は無視される。
"\C" はその反対である: パターン全体で大文字小文字を一致させることを強制する。
{Vim のみが \c および \C をサポートする}
Note 'ignorecase'、"\c" および "\C" は文字クラスには使われないことに注意。

例:

        foo       off           -               foo
        foo       on            -               foo Foo FOO
        Foo       on            off             foo Foo FOO
        Foo       on            on                  Foo
        \cfoo     -             -               foo Foo FOO
        foo\C     -             -               foo

技術的な詳細:                                   NL-used-for-Nul
ファイル内の <Nul> 文字は、メモリ内では <NL> として格納される。表示では "^@"
として示される。この変換はファイルを読み込む時および書き込む時に行われる。検索
パターンで <Nul> にマッチさせるには、単に CTRL-@ または "CTRL-V 000" を入力す
ればよい。これはおそらく期待するとおりであろう。内部的には、その文字は検索パ
ターン内で <NL> に置き換えられる。普通でないのは、CTRL-V CTRL-J をタイプしても
<NL> が挿入され、そのためファイル内の <Nul> も検索されることである。

                                                CR-used-for-NL
'fileformat' が "mac" の場合、ファイル内の <NL> 文字は内部的に <CR> 文字として
格納される。テキスト内では、それらは "^J" として示される。それ以外では、これは
<Nul> に対する <NL> の使い方と同様に機能する。

8. 合成文字                                             patterns-composing

                                                        /\Z
"\Z" がパターン中のどこかに現れた場合、全ての合成文字は無視される。そのため、
基底文字のみがマッチする必要があり、合成文字は異なっていてもよく、合成文字の数
が異なっていてもよい。'encoding' が "utf-8" の場合のみ関係がある。
例外: パターンが 1 つ以上の合成文字で始まる場合、それらはマッチしなければなら
ない。
                                                        /\%C
合成文字をスキップするには "\%C" を使う。例えば、パターン "a" は "càt" (a が合
成文字 0x0300 を持つ) にはマッチしないが、"a\%C" はマッチする。Note これは
"cát" (á は文字 0xe1 で、合成文字を持たない) にはマッチしないことに注意。"cat"
(a は単なる a) にはマッチする。

合成文字がパターンの先頭に、または合成文字を含まない項目の後ろに現れた場合、こ
の合成文字を含む任意の文字でマッチが見つかる。

ドットおよび合成文字を使う場合、これは合成文字単独と同じように機能するが、その
前に何が来るかは問題にならない点が異なる。

合成文字の順序は問題にならない。また、テキストがパターンより多くの合成文字を
持っていても、マッチする。しかし、パターン内の全ての合成文字がテキスト内で見つ
からなければならない。

B が基底文字で、x および y が合成文字だとする:
        パターン        テキスト        マッチ
        Bxy             Bxy             はい (完全なマッチ)
        Bxy             Byx             はい (順序は無視)
        Bxy             By              いいえ (x が無い)
        Bxy             Bx              いいえ (y が無い)
        Bx              Bx              はい (完全なマッチ)
        Bx              By              いいえ (x が無い)
        Bx              Bxy             はい (余分な y は無視)
        Bx              Byx             はい (余分な y は無視)

9. Perl パターンとの比較                                perl-patterns

Vim の正規表現は、何ができるかという点で Perl のものに最も似ている。それらの違
いはほとんど単に表記法である。以下は、それらが異なる所の要約である:

機能                            Vim での表記    Perl での表記
----------------------------------------------------------------
大文字小文字の無視を強制        \c              (?i)
大文字小文字の区別を強制        \C              (?-i)
後方参照なしのグループ化        \%(atom\)       (?:atom)
控えめな量指定子                \{-n,m}         *?, +?, ??, {}?
幅 0 のマッチ                   atom\@=         (?=atom)
幅 0 の非マッチ                 atom\@!         (?!atom)
幅 0 の先行マッチ               atom\@<=        (?<=atom)
幅 0 の先行非マッチ             atom\@<!        (?<!atom)
再試行なしのマッチ              atom\@>         (?>atom)

Vim および Perl は、文字列内の改行文字を少し異なって扱う:

Perl では、^ および $ はデフォルトではテキストのまさに先頭および末尾でのみマッ
チするが、'm' フラグを設定でき、それにより埋め込まれた改行でもマッチするように
なる。また、's' フラグを設定することもでき、それにより . が改行にもマッチする
ようになる。(ちなみに、これらのフラグはどちらも、上記の i フラグに使われるのと
同じ構文を使ってパターン内で変更できる。)

一方、Vim の ^ および $ は常に埋め込まれた改行でマッチし、2 つの別々のアトム、
\%^ および \%$ があり、それらはそれぞれテキストのまさに先頭および末尾でのみマッ
チする。Vim は 2 番目の問題を \_ "修飾子" を与えることで解決する: それを . ま
たは文字クラスの前に置くと、それらは改行にもマッチするようになる。

最後に、これらの構文は Perl 特有である:
- 正規表現内での任意のコードの実行:  (?{perl code})
- 条件式:  (?(condition)true-expr|false-expr)

...そして、これらは Vim 特有である:
- パターンの magic 性の変更:  \v \V \m \M
   (バックスラッシュ症候群を避けるのにとても役に立つ)
- 任意にマッチするアトムの並び:  \%[atoms]
- \& (\| に対して、"or" に対する "and" のようなもの。複数のブランチが 1 か所で
  マッチすることを強制する)
- 番号による行/桁のマッチ:  \%5l \%5c \%5v
- マッチの開始および終了の設定:  \zs \ze

10. マッチのハイライト                                  match-highlight

                                                        syntax-vs-match
                Note マッチのハイライトの仕組みは syntax-highlighting から独
                立していることに注意。それは (通常は) バッファローカルのハイラ
                イトであり、一方マッチはウィンドウローカルであり、両方の方法は
                自由に混在できる。マッチのハイライト関数は、いつどのように適用
                するかについて少し多くの柔軟性を与えるが、通常は厳密な規則無し
                に、一時的なハイライトのためにのみ使われる。どちらの方法もテキ
                ストを隠すのに使える。

                そのため、matchadd() のようなマッチ関数は構文規則を考慮せず、
                synconcealed() のような関数についてはその逆である。

                                                        :mat :match
:mat[ch] {group} /{pattern}/
                現在のウィンドウでハイライトするパターンを定義する。それは
                {group} でハイライトされる。例:
                        :highlight MyGroup ctermbg=green guibg=green
                        :match MyGroup /TODO/
                {pattern} の開始および終了を示すために、// の代わりに任意の文
                字を使うことができる。'"' および '|' などの特殊文字を使う時は
                気を付けること。

                {group} はこのコマンドが実行される時点で存在していなければなら
                ない。

                文字が 'hlsearch' でハイライトされる時も、{group} のハイライト
                は適用される。なぜなら、マッチのハイライトは 'hlsearch' のハイ
                ライトより高い優先度を与えられているからである。構文ハイライト
                ('syntax' を参照) もマッチによって上書きされる。

                Note 'hlsearch' による最後に使われた検索パターンのハイライトは
                全てのウィンドウで使われるが、":match" で定義されたパターンは
                カレントウィンドウにのみ存在することに注意。それは別のバッファ
                に切り替えた時も保持される。

                'ignorecase' は適用されない。大文字小文字を無視するにはパター
                ン内で /\c を使うこと。そうしないと大文字小文字は無視されな
                い。

                'redrawtime' は、パターンのマッチを検索する最大時間を定める。

                行末にマッチさせていて、Vim が表示の一部だけを再描画する時、予
                期しない結果になるかもしれない。これは、Vim が再描画を開始する
                行でマッチを探すためである。

                matcharg() および getmatches() も参照。前者は、前回の
                :match コマンドのハイライトグループおよびパターンを返す。後
                者は、matchadd() および :match の両方で定義されたハイライ
                トグループおよびパターンのリストを返す。

                :match を使ったマッチのハイライトは 3 つのマッチに制限される
                (:match とは別に、:2match および :3match が使用可能であ
                る)。matchadd() にはこの制限が無く、さらにマッチに優先順位を
                付けることができる。

                仮想桁 72 以降の全ての文字をハイライトする別の例:
                        :highlight rightMargin term=bold ctermfg=blue guifg=blue
                        :match rightMargin /.\%>72v/
                仮想桁 7 にある全ての文字をハイライトするには:
                        :highlight col8 ctermbg=grey guibg=grey
                        :match col8 /\%<8v.\%>7v/
                Note TAB など、複数の仮想桁を占める文字にもマッチさせるために
                2 つの項目を使っていることに注意。

:mat[ch]
:mat[ch] none
                以前に定義されたマッチパターンをクリアする。


:2mat[ch] {group} /{pattern}/                                   :2match
:2mat[ch]
:2mat[ch] none
:3mat[ch] {group} /{pattern}/                                   :3match
:3mat[ch]
:3mat[ch] none
                上記の :match とまったく同じだが、別のマッチを設定する。その
                ため、同時に 3 つのマッチを有効にできる。同じ位置で複数がマッ
                チする場合、最も小さい番号のマッチが優先される。これはマッチ
                ID 3 を使う。
                ":3match" コマンドは (Vim < 9.0.2054 の) matchparen プラグイ
                ンによって使われる。手動のマッチには ":match" を、別のプラグイ
                ンには ":2match" を使うか、またはさらによいことに、代わりによ
                り柔軟な matchadd() (および類似の) 関数を使用することを勧め
                る。

11. ファジーマッチ                                      fuzzy-matching

ファジーマッチは、パターンの文字が順番どおりに、ただし必ずしも連続せずに現れる
時、文字列がパターンにどれだけよくマッチするかをスコア付けする。

例:
    パターン:   "vim"
    候補:       "vim"        -> 完全
                "vimeo"      -> 良い (v i m)
                "voice mail" -> より弱い (v _ i _ _ _ m)
                "vintage"    -> マッチ無し ("m" が無い)

検索文字列に複数の単語がある場合、各単語は別々にマッチし、候補内で任意の順序で
現れてよい。例えば、"get pat" は "GetPattern"、"PatternGet"、"getPattern"、
"patGetter"、"getSomePattern"、"MatchpatternGet" などにマッチする。

'ignorecase' および 'smartcase' オプションは適用されず、パターンが全て小文字の
場合、大文字小文字は無視される。

Vim の実装は fzy プロジェクトのアルゴリズムに基づいている:
https://github.com/jhawthorn/fzy

これは、与えられたパターンおよび候補に対する最適なスコアを計算するために動的計
画法を使う。

このアルゴリズムは 2 段階で機能する:

1. 前方パス
   候補を左から右へスキャンし、各パターン位置に対する最良のスコアを追跡する。
   マッチは、候補の先頭、単語の先頭 (スペース、アンダースコア、ダッシュ、
   camelCase)、または前のマッチの直後に現れる時、より高いスコアになる。

2. 後方パス
   最良のスコアの終了位置から始め、後方へ戻りながらマッチ位置を見つけ、整列が
   最適であることを保証する。

Vim は元のアルゴリズムを拡張してマルチバイトコードポイントをサポートし、UTF-8
およびその他のエンコーディングに対して正しいマッチを可能にしている。

時間計算量は O(pattern * candidate) である。メモリ使用量は同じものに比例する。

matchfuzzy() および matchfuzzypos() 関数は、文字列のリストの中でファジー検
索を行う。matchfuzzy() はマッチした文字列を返し、一方 matchfuzzypos() は
マッチをその位置およびスコアと共に返す。

:vimgrep の "f" フラグはファジーマッチを有効にする。

ins-completion でファジーマッチを有効にするには、'completeopt' オプションに
"fuzzy" を追加する。cmdline-completion では、'wildoptions' オプションに
"fuzzy" を追加する。
