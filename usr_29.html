                           プログラムの中を移動する


Vim の作者はコンピュータプログラマです。Vim がプログラムを書くのを助ける多くの
機能を含んでいるのは驚くことではありません。識別子が定義および使用されている場
所を見つけるために飛び回ります。別のウィンドウで宣言をプレビューします。次章に
はさらに多くがあります。

29.1  タグを使う

タグとは何でしょうか? それは識別子が定義されている場所です。例としては、C また
は C++ プログラムの関数定義があります。タグのリストはタグファイルに保持されま
す。これは、任意の場所からタグ、つまり識別子が定義されている場所へ直接ジャンプ
するために、Vim が使うことができます。
   カレントディレクトリ内のすべての C ファイルのタグファイルを生成するには、以
下のコマンドを使います:

        ctags *.c

"ctags" は別のプログラムです。ほとんどの Unix システムには既にインストールされ
ています。まだ持っていない場合、Universal/Exuberant ctags を次の場所で見つける
ことができます:
        http://ctags.io
        http://ctags.sf.net

Universal ctags が推奨され、Exuberant ctags はもう開発されていません。

これで、Vim の中にいて関数定義へ行きたいときは、以下のコマンドを使ってそこへ
ジャンプできます:

        :tag startlist

このコマンドは、関数 "startlist" を、それが別のファイルにある場合でも見つけま
す。
   CTRL-] コマンドは、カーソルの下にある単語のタグへジャンプします。これによ
り、もつれた C コードを探索するのが簡単になります。例えば、関数 "write_block"
の中にいるとします。それが "write_line" を呼んでいるのがわかります。しかし、
"write_line" は何をするのでしょうか? "write_line" の呼び出しにカーソルを置いて
CTRL-] を押すと、この関数の定義へジャンプします。
   "write_line" 関数は "write_char" を呼んでいます。それが何をするのかを解明す
る必要があります。そこで、"write_char" の呼び出しの上にカーソルを置いて CTRL-]
を押します。これで "write_char" の定義にいます。

        +-------------------------------------+
        |void write_block(char **s; int cnt)  |
        |{                                    |
        |   int i;                            |
        |   for (i = 0; i < cnt; ++i)         |
        |      write_line(s[i]);              |
        |}          |                         |
        +-----------|-------------------------+
                    |
             CTRL-] |
                    |    +----------------------------+
                    +--> |void write_line(char *s)    |
                         |{                           |
                         |   while (*s != 0)          |
                         |      write_char(*s++);     |
                         |}       |                   |
                         +--------|-------------------+
                                  |
                           CTRL-] |
                                  |    +------------------------------------+
                                  +--> |void write_char(char c)             |
                                       |{                                   |
                                       |    putchar((int)(unsigned char)c); |
                                       |}                                   |
                                       +------------------------------------+

":tags" コマンドは、通ってきたタグのリストを表示します:

        :tags
          # TO tag         FROM line  in file/text
          1  1 write_line          8  write_block.c
          2  1 write_char          7  write_line.c
        >

さて、戻るには。CTRL-T コマンドは前のタグへ行きます。上の例では、"write_line"
関数の、"write_char" の呼び出しのところに戻ります。
   このコマンドは、何個のタグを戻るかを示すカウント引数を取ります。前へ進み、
そして今度は戻りました。もう一度前へ進みましょう。以下のコマンドは、リストの一
番上のタグへ行きます:

        :tag

カウントを前に付けて、その数のタグだけ前へジャンプできます。例えば: ":3tag"。
CTRL-T にもカウントを前に付けることができます。
   したがって、これらのコマンドを使うと、CTRL-] で呼び出しツリーを下っていき、
CTRL-T で再び上へ戻ることができます。自分がどこにいるかを知るには ":tags" を
使ってください。


ウィンドウを分割する

":tag" コマンドは、カレントウィンドウ内のファイルを、新しい関数を含むファイル
で置き換えます。しかし、古い関数だけでなく新しい関数も見たいとしたらどうでしょ
う? ":split" コマンドの後に ":tag" コマンドを使って、ウィンドウを分割できます。
Vim には両方を行う短縮コマンドがあります:
        :stag tagname

カレントウィンドウを分割して、カーソルの下のタグへジャンプするには、このコマン
ドを使います:

        CTRL-W ]

カウントが指定された場合、新しいウィンドウはその行数の高さになります。


さらに多くのタグファイル

多くのディレクトリにファイルがあるときは、それぞれのディレクトリにタグファイル
を作成できます。そうすると Vim は、そのディレクトリ内のタグにしかジャンプでき
なくなります。
   もっと多くのタグファイルを見つけるには、関連するすべてのタグファイルを含む
ように 'tags' オプションを設定します。例:

        :set tags=./tags,./../tags,./*/tags

これは、カレントファイルと同じディレクトリ、1 つ上のディレクトリレベル、および
すべてのサブディレクトリにあるタグファイルを見つけます。
   これはかなりの数のタグファイルですが、それでもまだ十分ではないかもしれませ
ん。例えば、"~/proj/src" 内のファイルを編集しているとき、タグファイル
"~/proj/sub/tags" は見つかりません。この状況のために、Vim はディレクトリツリー
全体でタグファイルを検索することを提供しています。例:

        :set tags=~/proj/**/tags


1 つのタグファイル

Vim がタグファイルを多くの場所で検索しなければならないとき、ディスクがガタガタ
いうのが聞こえます。少し遅くなるかもしれません。その場合は、この時間を 1 つの
大きなタグファイルを生成する間に費やす方がよいです。これは夜通し行うかもしれま
せん。
   これには、上で述べた Universal または Exuberant ctags プログラムが必要です。
それはディレクトリツリー全体を検索する引数を提供しています:

        cd ~/proj
        ctags -R .

これのよいところは、Universal/Exuberant ctags がさまざまなファイルタイプを認識
することです。したがって、これは C および C++ プログラムだけに機能するのではな
く、Eiffel およびさらに Vim script にも機能します。これを調整するには ctags の
ドキュメントを参照してください。
   これで、あなたの大きなタグファイルがどこにあるかを Vim に伝えるだけで済みま
す:

        :set tags=~/proj/tags


複数のマッチ

関数が複数回定義されている (または複数のクラス内のメソッド) とき、":tag" コマ
ンドは最初のものへジャンプします。カレントファイル内にマッチがある場合、それが
最初に使われます。
   これで、同じタグの他のマッチへ以下でジャンプできます:

        :tnext

さらにマッチを見つけるにはこれを繰り返します。たくさんある場合、どれにジャンプ
するかを選択できます:

        :tselect tagname

Vim は選択肢のリストを提示します:

          # pri kind tag               file
          1 F   f    mch_init          os_amiga.c
                       mch_init()
          2 F   f    mch_init          os_mac.c
                       mch_init()
          3 F   f    mch_init          os_msdos.c
                       mch_init(void)
          4 F   f    mch_init          os_riscos.c
                       mch_init()
        Enter nr of choice (<CR> to abort): 

これで、ジャンプしたいマッチの (最初の列にある) 番号を入力できます。他の列の情
報は、マッチがどこで定義されているかについて、よい見当を与えてくれます。

マッチするタグの間を移動するには、これらのコマンドが使えます:

        :tfirst                 最初のマッチへ行く
        :[count]tprevious       [count] 個前のマッチへ行く
        :[count]tnext           [count] 個次のマッチへ行く
        :tlast                  最後のマッチへ行く

[count] が省略された場合、1 が使われます。


タグ名を推測する

コマンドライン補完は、長いタグ名をタイプするのを避けるよい方法です。最初の少し
をタイプして <Tab> を押すだけです:

        :tag write_<Tab>

最初のマッチが得られます。それが望むものでない場合、正しいものが見つかるまで
<Tab> を押してください。
   関数の名前の一部しか知らないこともあります。または、同じ文字列で始まり、異
なる終わり方をするタグがたくさんあることもあります。そのときは、タグを見つける
ためにパターンを使うように Vim に指示できます。
   "block" を含むタグへジャンプしたいとします。まずこれをタイプします:

        :tag /block

ここでコマンドライン補完を使います: <Tab> を押します。Vim は "block" を含むす
べてのタグを見つけ、最初のマッチを使います。
   タグ名の前の "/" は、続くものが文字どおりのタグ名ではなく、パターンであるこ
とを Vim に伝えます。ここでは検索パターンのすべての要素を使えます。例えば、
"write_" で始まるタグを選択したいとします:

        :tselect /^write_

"^" は、タグが "write_" で始まることを指定します。そうしないと、タグ名の途中で
も見つかってしまいます。同様に、末尾の "$" は、パターンがタグの終わりまでマッ
チすることを保証します。


タグブラウザー

CTRL-] はカーソルの下の識別子の定義へ連れていってくれるので、識別子名のリスト
を目次として使うことができます。ここに例があります。
   まず識別子のリストを作成します (これには Universal または Exuberant ctags
が必要です):

        ctags --c-types=f -f functions *.c

次に、ファイルなしで Vim を起動し、Vim の中でこのファイルを、垂直分割したウィ
ンドウで編集します:

        vim
        :vsplit functions

ウィンドウにはすべての関数のリストが含まれています。他にもいくつかのものがあり
ますが、それは無視できます。少し整理するために ":setlocal ts=99" を実行してく
ださい。
   このウィンドウで、マッピングを定義します:

        :nnoremap <buffer> <CR> 0ye<C-W>w:tag <C-R>"<CR>

移動したい関数を含む行にカーソルを移動します。
ここで <Enter> を押します。Vim はもう一方のウィンドウへ行き、選択した関数へジャ
ンプします。


関連項目

タグ名の大文字小文字を無視させるには、'tagcase' を "followic" のままにして
'ignorecase' を設定するか、または 'tagcase' を "ignore" に設定します。

'tagbsearch' オプションは、タグファイルがソートされているかどうかを伝えます。
既定ではソートされたタグファイルを想定し、これはタグの検索をずっと速くします
が、タグファイルがソートされていない場合は機能しません。

'taglength' オプションは、タグの中の有効な文字数を Vim に伝えるために使えます。

Cscope はフリーのプログラムです。それは識別子が宣言されている場所だけでなく、
それが使われている場所も見つけます。cscope を参照してください。

29.2  プレビューウィンドウ

関数呼び出しを含むコードを編集するときは、正しい引数を使う必要があります。どん
な値を渡せばよいかを知るには、その関数がどのように定義されているかを見ることが
できます。タグの仕組みはこれにとてもよく機能します。定義は別のウィンドウに表示
されるのが望ましいです。このためにプレビューウィンドウが使えます。
   関数 "write_char" を表示するプレビューウィンドウを開くには:

        :ptag write_char

Vim はウィンドウを開き、タグ "write_char" へジャンプします。それから元の位置へ
戻してくれます。したがって、CTRL-W コマンドを使う必要なしにタイプを続けること
ができます。
   関数の名前がテキストに現れている場合、以下でプレビューウィンドウにその定義
を得ることができます:

        CTRL-W }

カーソルの下の単語が定義された箇所のテキストを自動的に表示するスクリプトがあり
ます。CursorHold-example を参照してください。

プレビューウィンドウを閉じるには、このコマンドを使います:

        :pclose

プレビューウィンドウで特定のファイルを編集するには、":pedit" を使います。これ
は、例えばヘッダーファイルを編集するのに便利です:

        :pedit defs.h

最後に、":psearch" は、カレントファイルおよびインクルードされたすべてのファイ
ル内で単語を見つけ、そのマッチをプレビューウィンドウに表示するのに使えます。こ
れは、タグファイルを持っていないライブラリ関数を使うときに特に便利です。例:

        :psearch popen

これはプレビューウィンドウに "stdio.h" ファイルを、popen() の関数プロトタイプ
とともに表示します:

        FILE    *popen __P((const char *, const char *));

プレビューウィンドウが開かれるときの高さは、'previewheight' オプションで指定で
きます。

29.3  プログラムの中を移動する

プログラムは構造化されているので、Vim はその中の要素を認識できます。移動するた
めに特定のコマンドを使えます。
   C プログラムにはよくこのような構造が含まれています:

        #ifdef USE_POPEN
            fd = popen("ls", "r")
        #else
            fd = fopen("tmp", "w")
        #endif

しかし、実際にはもっとずっと長く、入れ子になっているかもしれません。カーソルを
"#ifdef" の上に置いて % を押します。Vim は "#else" へジャンプします。もう一度
% を押すと "#endif" へ行きます。もう一度 % で、再び "#ifdef" へ行きます。
   構造が入れ子になっているとき、Vim は対応する要素を見つけます。これは、
"#endif" を忘れていないかを確認するよい方法です。
   "#if" - "#endif" の内側のどこかにいるとき、以下でその開始へジャンプできます:


        [#

"#if" または "#ifdef" の後にいない場合、Vim はビープ音を鳴らします。次の
"#else" または "#endif" へ前方にジャンプするには、以下を使います:

        ]#

これらの 2 つのコマンドは、途中で出会う "#if" - "#endif" ブロックをすべてスキッ
プします。例:

        #if defined(HAS_INC_H)
            a = a + inc();
        # ifdef USE_THEME
            a += 3;
        # endif
            set_width(a);

カーソルが最後の行にあるとき、"[#" は最初の行へ移動します。中間の "#ifdef" -
"#endif" ブロックはスキップされます。


コードブロック内を移動する

C では、コードブロックは {} で囲まれています。これらはかなり長くなることがあり
ます。外側のブロックの開始へ移動するには "[[" コマンドを使います。終わりを見つ
けるには "][" を使います。これは、"{" および "}" が最初の列にあることを前提と
しています。
   "[{" コマンドは、現在のブロックの開始へ移動します。同じレベルにある {} の組
はスキップします。"]}" は終わりへジャンプします。
   概要:

                        function(int a)
           +->          {
           |                if (a)
           |       +->      {
        [[ |       |            for (;;)               --+
           |       |      +->   {                        |
           |    [{ |      |         foo(32);             |     --+
           |       |   [{ |         if (bar(a))  --+     | ]}    |
           +--     |      +--           break;     | ]}  |       |
                   |            }                <-+     |       | ][
                   +--          foobar(a)                |       |
                            }                          <-+       |
                        }                                      <-+

C++ または Java を書いているとき、外側の {} ブロックはクラスのためのものです。
次のレベルの {} はメソッドのためのものです。クラスの内側のどこかにいるとき、前
のメソッドの開始を見つけるには "[m" を使います。"]m" は次のメソッドの開始を見
つけます。

さらに、"[]" は後方へ関数の終わりに移動し、"]]" は前方へ次の関数の開始に移動し
ます。関数の終わりは、最初の列にある "}" によって定義されます。

                                int func1(void)
                                {
                                        return 1;
                  +---------->  }
                  |
              []  |             int func2(void)
                  |        +->  {
                  |    [[  |            if (flag)
        start     +--      +--                  return flag;
                  |    ][  |            return 2;
                  |        +->  }
              ]]  |
                  |             int func3(void)
                  +---------->  {
                                        return 3;
                                }

"%" を使って、対応する ()、{}、および [] の間を移動することもできるのを忘れな
いでください。それらが何行も離れているときでも機能します。


波括弧内を移動する

"[(" および "])" コマンドは、{} の組の代わりに () の組に対して機能することを除
いて、"[{" および "]}" と同じように機能します。

                                  [(
                    <--------------------------------
                              <-------
                if (a == b && (c == d || (e > f)) && x > y)
                                  -------------->
                          -------------------------------->
                                       ])

コメント内を移動する

コメントの開始へ戻るには "[/" を使います。"]/" でコメントの終わりへ前方に移動
します。これは /* - */ コメントにだけ機能します。

          +->     +-> /*
          |    [/ |    * A comment about      --+
       [/ |       +--  * wonderful life.        | ]/
          |            */                     <-+
          |
          +--          foo = bar * 3;         --+
                                                | ]/
                       /* a short comment */  <-+

29.4  グローバル識別子を見つける

C プログラムを編集していて、ある変数が "int" または "unsigned" として宣言され
ているかどうか疑問に思っています。これを素早く見つける方法は "[I" コマンドで
す。
   カーソルが単語 "column" の上にあるとします。こうタイプします:

        [I

Vim は見つけられたマッチする行を一覧表示します。カレントファイル内だけでなく、
インクルードされたすべてのファイル (およびそれらにインクルードされたファイルな
ど) 内でもです。結果はこのようになります:

        structs.h
         1:   29     unsigned     column;    /* column number */

タグまたはプレビューウィンドウを使うことに対する利点は、インクルードされたファ
イルが検索されることです。ほとんどの場合、これにより正しい宣言が見つかります。
タグファイルが古くなっているときもです。インクルードされたファイルのタグを持っ
ていないときもです。
   しかし、"[I" がその仕事をするためには、いくつかのことが正しくなければなりま
せん。まず第一に、'include' オプションが、ファイルがどのようにインクルードされ
るかを指定していなければなりません。既定値は C および C++ で機能します。他の言
語では、それを変更する必要があるでしょう。


インクルードされたファイルの場所を特定する

   Vim は、'path' オプションで指定された場所で、インクルードされたファイルを見
つけます。ディレクトリが欠けている場合、いくつかのインクルードファイルが見つか
りません。これはこのコマンドで発見できます:

        :checkpath

これは、見つけられなかったインクルードファイルを一覧表示します。見つけられた
ファイルによってインクルードされたファイルもです。出力の例:

        --- Included files not found in path ---
        <io.h>
        vim.h -->
          <functions.h>
          <clib/exec_protos.h>

"io.h" ファイルはカレントファイルによってインクルードされていて、見つけること
ができません。"vim.h" は見つけることができるので、":checkpath" はこのファイル
の中に入り、それが何をインクルードしているかをチェックします。"vim.h" によって
インクルードされている "functions.h" および "clib/exec_protos.h" ファイルは見
つかりません。

        Note:
        Vim はコンパイラではありません。"#ifdef" 文を認識しません。これは、す
        べての "#include" 文が、"#if NEVER" の後に来るときも使われることを意味
        します。

見つけられなかったファイルを直すには、'path' オプションにディレクトリを追加し
ます。これについて調べるのによい場所は Makefile です。"-I/usr/local/X11" のよ
うな "-I" 項目を含む行に注目してください。このディレクトリを追加するには、以下
を使います:

        :set path+=/usr/local/X11

サブディレクトリがたくさんあるときは、"*" ワイルドカードを使えます。例:

        :set path+=/usr/*/include

これは "/usr/local/include" および "/usr/X11/include" 内のファイルを見つけるで
しょう。

インクルードされたファイルの入れ子になったツリー全体を持つプロジェクトで作業し
ているとき、"**" 項目が便利です。これはすべてのサブディレクトリの中を下へ検索
します。例:

        :set path+=/projects/invent/**/include

これは、ディレクトリ内のファイルを見つけます:

        /projects/invent/include
        /projects/invent/main/include
        /projects/invent/main/os/include
        など

さらに多くの可能性があります。情報については 'path' オプションを確認してくださ
い。
   実際にどのインクルードされたファイルが見つかったかを見たい場合、このコマン
ドを使います:

        :checkpath!

インクルードされたファイル、それらがインクルードするファイルなどの (とても長い)
リストが得られます。リストを少し短くするために、Vim は以前に見つかったファイル
に対しては "(Already listed)" を表示し、その中のインクルードされたファイルを再
び一覧表示しません。


マッチへジャンプする

"[I" は 1 行のテキストだけを持つリストを生成します。最初の項目をもっと詳しく見
たいときは、このコマンドでその行へジャンプできます:

        [<Tab>

CTRL-I は <Tab> を押すのと同じなので、"[ CTRL-I" も使えます。

"[I" が生成するリストには、各行の先頭に番号があります。最初のもの以外の項目へ
ジャンプしたいときは、まず番号をタイプします:

        3[<Tab>

リストの 3 番目の項目へジャンプします。開始した場所へ戻るのに CTRL-O を使える
ことを覚えておいてください。


関連コマンド

        [i              最初のマッチだけを一覧表示する
        ]I              カーソルより下の項目だけを一覧表示する
        ]i              カーソルより下の最初の項目だけを一覧表示する


定義された識別子を見つける

"[I" コマンドは任意の識別子を見つけます。"#define" で定義されたマクロだけを見
つけるには、以下を使います:

        [D

繰り返しますが、これはインクルードされたファイル内を検索します。'define' オプ
ションは、"[D" のための項目を定義する行がどのように見えるかを指定します。C ま
たは C++ 以外の言語で機能するように、それを変更することもできます。
   "[D" に関連するコマンドは以下です:

        [d              最初のマッチだけを一覧表示する
        ]D              カーソルより下の項目だけを一覧表示する
        ]d              カーソルより下の最初の項目だけを一覧表示する

29.5  ローカル識別子を見つける

"[I" コマンドはインクルードされたファイルを検索します。カレントファイルだけを
検索し、カーソルの下の単語が使われている最初の場所へジャンプするには:

        gD

ヒント: Goto Definition。このコマンドは、ローカルに ("static"、C の用語で) 宣
言された変数または関数を見つけるのにとても便利です。例 (カーソルは "counter"
の上):

           +->   static int counter = 0;
           |
           |     int get_counter(void)
        gD |     {
           |         ++counter;
           +--       return counter;
                 }

検索をさらに制限して、現在の関数内だけを調べるには、このコマンドを使います:

        gd

これは現在の関数の開始へ戻り、カーソルの下の単語の最初の出現を見つけます。実際
には、最初の列にある "{" の上の空行まで後方に検索します。そこから識別子を前方
に検索します。例 (カーソルは "idx" の上):

                int find_entry(char *name)
                {
           +->      int idx;
           |
        gd |        for (idx = 0; idx < table_len; ++idx)
           |            if (strcmp(table[idx].name, name) == 0)
           +--              return idx;
                }
