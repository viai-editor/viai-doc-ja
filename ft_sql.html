Structured Query Language (SQL) は、ユーザーがリレーショナルデータベースとやり
取りできるようにするステートメントを規定する標準である。Vim には、ナビゲーショ
ン、インデント、およびシンタックスハイライトのための機能が含まれている。

1. ナビゲーション                               sql-navigation

SQL ftplugin は、ファイルのナビゲーションを補助するための多数のオプションを提
供する。


1.1 Matchit                                     sql-matchit
-----------
matchit プラグイン (http://www.vim.org/scripts/script.php?script_id=39) は多く
の追加機能を提供し、異なる言語用にカスタマイズできる。matchit プラグインは、
バッファローカル変数 b:match_words を定義することで設定される。様々なキーワー
ド上で % キーを押すと、カーソルがその対応するものへ移動する。例えば、カーソル
が "if" 上にある場合、% を押すと "else"、"elseif"、および "end if" キーワード
の間を巡回する。

以下のキーワードがサポートされている:
    if
    elseif | elsif
    else [if]
    end if

    [while condition] loop
        leave
        break
        continue
        exit
    end loop

    for
        leave
        break
        continue
        exit
    end loop

    do
        statements
    doend

    case
    when
    when
    default
    end case

    merge
    when not matched
    when matched

    create[ or replace] procedure|function|event
    returns


1.2 テキストオブジェクト移動                    sql-object-motions
----------------------------
Vim には、テキストの object-motions を扱うための多数の定義済みキーがある。こ
のファイルタイププラグインは、これらのキーを SQL 言語にとって意味のあるマップ
に変換しようとする。

以下の Normal モードおよび Visual モードのマップが存在する (SQL ファイルを
編集する時):
    ]]              次の 'begin' へ前方に移動する
    [[              前の 'begin' へ後方に移動する
    ][              次の 'end' へ前方に移動する
    []              前の 'end' へ後方に移動する


1.3 定義済みオブジェクト移動                    sql-predefined-objects
----------------------------
ほとんどのリレーショナルデータベースは、様々な標準機能、テーブル、インデック
ス、トリガー、およびストアドプロシージャをサポートしている。各ベンダーはまた、
様々な独自のオブジェクトを持っている。次のマップのセットは、これらのオブジェク
ト間を移動するのを助けるために作られた。使用しているデータベースベンダーに依存
して、オブジェクトのリストは設定可能でなければならない。ファイルタイププラグイ
ンは、多くの標準オブジェクトに加えて、多くの追加のオブジェクトを定義しようとす
る。これをできるだけ柔軟にするために、vimrc の中から以下でオブジェクトのリス
トを上書きできる:
    let g:ftplugin_sql_objects = 'function,procedure,event,table,trigger' ..
                \ ',schema,service,publication,database,datatype,domain' ..
                \ ',index,subscription,synchronization,view,variable'

以下の Normal モードおよび Visual モードのマップが、上記のリストを使うよう
に作られている:
    ]}              次の 'create <object name>' へ前方に移動する
    [{              前の 'create <object name>' へ後方に移動する

]} を繰り返し押すと、これらの各 create ステートメントを巡回する:
    create table t1 (
        ...
    );

    create procedure p1
    begin
        ...
    end;

    create index i1 on t1 (c1);

g:ftplugin_sql_objects のデフォルト設定は以下のとおり:
    let g:ftplugin_sql_objects = 'function,procedure,event,' ..
                \ '\\(existing\\\\|global\\s\\+temporary\\s\\+\\)\\\{,1}' ..
                \ 'table,trigger' ..
                \ ',schema,service,publication,database,datatype,domain' ..
                \ ',index,subscription,synchronization,view,variable'

上記は、これらのケースも扱う:
    create table t1 (
        ...
    );
    create existing table t2 (
        ...
    );
    create global temporary table t3 (
        ...
    );

デフォルトでは、ftplugin は CREATE ステートメントだけを検索する。vimrc で以
下によってこれを上書きすることもできる:
    let g:ftplugin_sql_statements = 'create,alter'

ファイルタイププラグインは 3 種類のコメントを定義する:
    1.  --
    2.  //
    3.  /*
         *
         */

以下の Normal モードおよび Visual モードのマップが、コメントを扱うために作
られている:
    ]"              コメントの先頭へ前方に移動する
    ["              コメントの末尾へ前方に移動する



1.4 マクロ                                         sql-macros
----------
マクロ定義を見つける Vim の機能 'define' は、この正規表現を使ってサポートされ
ている:
    \c\<\(VARIABLE\|DECLARE\|IN\|OUT\|INOUT\)\>

これは以下のコードに対応する:
    CREATE VARIABLE myVar1 INTEGER;

    CREATE PROCEDURE sp_test(
        IN myVar2 INTEGER,
        OUT myVar3 CHAR(30),
        INOUT myVar4 NUMERIC(20,0)
    )
    BEGIN
        DECLARE myVar5 INTEGER;

        SELECT c1, c2, c3
          INTO myVar2, myVar3, myVar4
          FROM T1
         WHERE c4 = myVar1;
    END;

この行の "myVar1" にカーソルを置く:
         WHERE c4 = myVar1;
                     ^

以下のキーのいずれかを押す:
    [d
    [D
    [CTRL-D

2. SQL の方言                                   sql-dialects sql-types
                                                sybase TSQL Transact-SQL
                                                sqlanywhere
                                                oracle plsql sqlj
                                                sqlserver
                                                mysql postgresql psql
                                                informix

全てのリレーショナルデータベースは SQL をサポートしている。SQL にはベンダー間
で移植可能な部分 (例: CREATE TABLE、CREATE INDEX) があるが、SQL に対するベン
ダー固有の拡張が非常に多くある。Oracle は "CREATE OR REPLACE" 構文、CREATE
TABLE ステートメントで指定されるカラムのデフォルト、および手続き型言語 (ストア
ドプロシージャおよびトリガー用) をサポートしている。

デフォルトの Vim 配布物には、Oracle の PL/SQL に基づいたシンタックスハイライト
が同梱されている。デフォルトの SQL インデントスクリプトは Oracle および SQL
Anywhere で動作する。
デフォルトのファイルタイププラグインは全てのベンダーで動作し、ベンダー中立のま
まであるべきだが、拡張可能であるべきだ。

Vim は現在、様々な異なるベンダーをサポートしており、現在これはシンタックススク
リプトによるものである。残念ながら、異なるシンタックスルールを切り替えるには、
次のいずれかを作成しなければならない:
    1.  新しいファイルタイプ
    2.  カスタム自動コマンド
    3.  手動の手順 / コマンド

大多数の人は 1 つのベンダーのデータベース製品だけを扱っており、vimrc でデフォ
ルトを指定できると便利だろう。


2.1 SQLSetType                                  sqlsettype SQLSetType
--------------
多くの異なるデータベースを扱う人にとっては、様々なベンダーのルール (インデン
ト、シンタックス) を、バッファ単位で、いつでも切り替えられると便利である。
ftplugin/sql.vim ファイルはこの関数を定義している:
    SQLSetType

この関数をパラメーターなしで実行すると、インデントおよびシンタックススクリプト
がデフォルトに戻る。sql-type-default を参照。Vi 互換モード 'compatible' をオ
フにしている場合、<Tab> キーを使って省略可能なパラメーターを補完できる。

関数名と空白を入力した後、補完を使ってパラメーターを与えることができる。この関
数は、読み込みたい Vim script の名前を取る。cmdline-completion 機能を使うと、
SQLSetType 関数は 'runtimepath' から、名前に 'sql' を含む全ての Vim script を
検索する。これにより、名前の綴りの当て推量が不要になる。以下は例である:
    :SQLSetType
    :SQLSetType sqloracle
    :SQLSetType sqlanywhere
    :SQLSetType sqlinformix
    :SQLSetType mysql

最も簡単な方法は <Tab> 文字を使うことで、これはまずコマンド名 (SQLSetType) を
補完し、空白ともう 1 つの <Tab> の後、使用可能な Vim script 名のリストを表示す
る:
    :SQL<Tab><space><Tab>


2.2 SQLGetType                                  sqlgettype SQLGetType
--------------
いつでも、SQLGetType コマンドを呼ぶことで、どの SQL の方言を使用しているかを確
認できる。ftplugin/sql.vim ファイルはこの関数を定義している:
    SQLGetType

これは以下を表示する:
    Current SQL dialect in use:sqlanywhere


2.3 SQL の方言のデフォルト                      sql-type-default
--------------------------
前述のとおり、Vim のデフォルトのシンタックスルールは Oracle (PL/SQL) に基づい
ている。vimrc に以下のいずれかを置くことで、このデフォルトを上書きできる:
    let g:sql_type_default = 'sqlanywhere'
    let g:sql_type_default = 'sqlinformix'
    let g:sql_type_default = 'mysql'

vimrc に以下を追加した場合:
    let g:sql_type_default = 'sqlinformix'

次回 SQL ファイルを編集すると、以下のスクリプトが Vim によって自動的に読み込ま
れる:
    ftplugin/sql.vim
    syntax/sqlinformix.vim
    indent/sql.vim

indent/sqlinformix.sql が読み込まれなかったことに注意。Informix 用のインデント
ファイルは無く、指定されたファイルが存在しない場合、Vim はデフォルトのファイル
を読み込む。

3. 新しい SQL の方言の追加                      sql-adding-dialects

デフォルトの Vim 配布物で使用可能なカスタマイズが何も無い SQL の方言を扱い始め
る場合、http://www.vim.org を確認して、何らかのカスタマイズが現在存在するかど
うかを確かめることができる。無い場合、既存のスクリプトを複製することから始める
ことができる。詳細は filetype-plugins を読むこと。

これらのスクリプトを識別しやすくするため、"sql" プリフィックスを付けてファイル
を作成するようにする。SQLite データベース用のカスタマイズを作成したいと決めた
場合、以下のいずれかを作成できる:
    Unix
        ~/.vim/syntax/sqlite.vim
        ~/.vim/indent/sqlite.vim
    Windows
        $VIM/vimfiles/syntax/sqlite.vim
        $VIM/vimfiles/indent/sqlite.vim

SQLSetType 関数に変更は必要ない。SQLSetType コマンドを実行した時に、新しい SQL
ファイルを自動的に認識して読み込む。

4. オムニ SQL 補完                              sql-completion
                                                omni-sql-completion

Vim 7 には、プラグイン開発者が任意の言語のコード補完を組み込めるようにする、
コード補完インターフェイスおよび関数が含まれている。Vim 7 には SQL 言語のコー
ド補完が含まれている。

SQL 補完プラグインには 2 つのモード、静的および動的がある。静的モードは、現在
のシンタックスハイライトルールから生成されたデータでポップアップを埋める。動的
モードは、データベースから直接取得したデータでポップアップを埋める。これには、
テーブルリスト、カラムリスト、プロシージャ名などが含まれる。

4.1 静的モード                                  sql-completion-static
--------------
作成される静的ポップアップには、SQL のファイルタイプでファイルを編集している
間、アクティブなシンタックスルールで定義された項目が含まれる。プラグインは、
ユーザーが表示される項目のリストを絞り込むのを助けるために、(デフォルトで) 様々
なマップを定義する。
デフォルトの静的マップは以下のとおり:
    imap <buffer> <C-C>a <C-\><C-O>:call sqlcomplete#Map('syntax')<CR><C-X><C-O>
    imap <buffer> <C-C>k <C-\><C-O>:call sqlcomplete#Map('sqlKeyword')<CR><C-X><C-O>
    imap <buffer> <C-C>f <C-\><C-O>:call sqlcomplete#Map('sqlFunction')<CR><C-X><C-O>
    imap <buffer> <C-C>o <C-\><C-O>:call sqlcomplete#Map('sqlOption')<CR><C-X><C-O>
    imap <buffer> <C-C>T <C-\><C-O>:call sqlcomplete#Map('sqlType')<CR><C-X><C-O>
    imap <buffer> <C-C>s <C-\><C-O>:call sqlcomplete#Map('sqlStatement')<CR><C-X><C-O>

全てのプラットフォームで正しく動作するとは限らないため、"<C-C>" の使用は、
.vimrc で以下を使用することでユーザーが選択できる:
    let g:ftplugin_sql_omni_key = '<C-C>'

静的マップ (シンタックスハイライトグループに基づく) は以下の形式に従う:
    imap <buffer> <C-C>k <C-\><C-O>:call sqlcomplete#Map('sqlKeyword')<CR><C-X><C-O>
    imap <buffer> <C-C>k <C-\><C-O>:call sqlcomplete#Map('sqlKeyword\w*')<CR><C-X><C-O>

このコマンドは以下のように分解される:
    imap                   - 挿入マップを作成する
    <buffer>               - このバッファのみ
    <C-C>k                 - 選択したキーマップ
    <C-\><C-O>             - 1 つのコマンドを実行し、挿入モードに戻る
    :call sqlcomplete#Map( - SQL 補完プラグインが、他の補完プラグインと組み合
                             わせて使えるようにするための管理用の関数を実行で
                             きるようにする。SQL 補完プラグインにどの項目を補
                             完させたいかを示す。
                             この場合、プラグインにシンタックスハイライトグルー
                             プ 'sqlKeyword' の項目を表示するよう要求している。
                             選択できるハイライトグループ名のリストは、SQL ファ
                             イルの編集中に
                                 :syntax list
                             コマンドを実行することで見ることができる。
    'sqlKeyword'           - sqlKeyword ハイライトグループの項目を表示する
    'sqlKeyword\w*'        - Vim 7.4 で使用可能な 2 つ目のオプションで、正規表
                             現を使ってどのシンタックスグループを使うかを決め
                             る
    )<CR>                  - :let コマンドを実行する
    <C-X><C-O>             - 標準のオムニ補完のキーストロークを発動する。
                             'sqlKeyword' を渡すことで、SQL 補完プラグインに
                             sqlKeyword ハイライトグループの項目でポップアップ
                             を埋めるよう指示する。プラグインはまた、Vim が再
                             起動されるまでこの結果をキャッシュする。シンタッ
                             クスリストは syntaxcomplete プラグインを使って取
                             得される。

'syntax' キーワードを使うのは特別なケースである。これは syntaxcomplete プラグ
インに全てのシンタックス項目を取得するよう指示する。そのため、これは事実上、
Vim の SQL シンタックスファイルのどれに対しても動作する。執筆時点では、これに
は SQL の異なる方言用の 10 個の異なるシンタックスファイルが含まれる (上記のセ
クション 3、sql-dialects を参照)。

以下は、シンタックスファイルから取り出されるエントリの例である:
     全て
         - 全てのシンタックスハイライトグループの内容を含む
     ステートメント
         - Select, Insert, Update, Delete, Create, Alter, ...
     関数
         - Min, Max, Trim, Round, Date, ...
     キーワード
         - Index, Database, Having, Group, With
     オプション
         - Isolation_level, On_error, Qualify_owners, Fire_triggers, ...
     型
         - Integer, Char, Varchar, Date, DateTime, Timestamp, ...


4.2 動的モード                                  sql-completion-dynamic
--------------
動的モードは、データベースから直接のデータでポップアップを埋める。動的機能を有
効にするには、dbext.vim プラグインがインストールされていなければならない、
(https://www.vim.org/scripts/script.php?script_id=356)。

動的モードは SQL 補完プラグインのいくつかの機能で使われる。
dbext プラグインをインストールした後、追加の設定および使い方については
dbext-tutorial を参照。dbext プラグインにより、SQL 補完プラグインはテーブル、
プロシージャ、ビュー、およびカラムのリストを表示できる。
     テーブルリスト
         - 全てのスキーマ所有者の全てのテーブル
     プロシージャリスト
         - 全てのスキーマ所有者の全てのストアドプロシージャ
     ビューリスト
         - 全てのスキーマ所有者の全てのストアドプロシージャ
     カラムリスト
         - 選択されたテーブルについて、そのテーブルの一部であるカラム

ポップアップを有効にするには、挿入モード中に、各グループについて以下のキーの組
み合わせを使う (ここで <C-C> は、CTRL キーを押したままスペースバーを押すことを
意味する):
     テーブルリスト        - <C-C>t
                           - <C-X><C-O> (デフォルトのマップはテーブルを想定する)
     ストアドプロシージャリスト - <C-C>p
     ビューリスト          - <C-C>v
     カラムリスト          - <C-C>c

     ドリルイン / アウト   - テーブルのリストを表示しているポップアップウィン
                             ドウを見ている時、<Right> を押すことができ、これ
                             により、現在ハイライトされているテーブルがそのテー
                             ブルのカラムリストで置き換えられる。
                           - カラムのリストを表示しているポップアップウィンド
                             ウを見ている時、<Left> を押すことができ、これによ
                             り、カラムリストがテーブルのリストで置き換えられ
                             る。
                           - これにより、素早くテーブルにドリルダウンしてその
                             カラムを見て、また戻ることができる。
                           - <Right> および <Left> は、.vimrc で選択すること
                             もできる
                                let g:ftplugin_sql_omni_key_right = '<Right>'
                                let g:ftplugin_sql_omni_key_left  = '<Left>'

SQL 補完プラグインは、ポップアップウィンドウに表示される様々なリストをキャッ
シュする。これにより、これらのリストの再表示が非常に高速になる。新しいテーブル
またはカラムがデータベースに追加された場合、プラグインのキャッシュをクリアする
必要が生じるかもしれない。このためのデフォルトのマップは以下のとおり:
    imap <buffer> <C-C>R <C-\><C-O>:call sqlcomplete#Map('ResetCache')<CR><C-X><C-O>


4.3 SQL チュートリアル                          sql-completion-tutorial
----------------------

このチュートリアルは、以下のようになるように、SQL 補完プラグインの一般的な機能
を案内するよう設計されている:
     a) プラグインに慣れる
     b) より一般的な機能のいくつかを紹介される
     c) 好みに合わせてカスタマイズする方法を示す
     d) プラグインの "Best of Use" (最も簡単な設定方法) を実演する。

まず、新しいバッファを作成する:
     :e tutorial.sql


静的機能
--------
様々なリストを案内するために、単に挿入モードに入り、次を押す:
    <C-C>s   (SQL ステートメントを表示)
この時点で、"select" が見つかるまでリストをページダウンできる。
探している項目をよく知っている場合、例えばステートメントが文字 "s" で始まるこ
とを知っている場合。(引用符なしで) "se" と先行入力してから、次を押す:
    <C-Space>t
ポップアップリストで "select" がハイライトされていると仮定して、<Enter> を押し
てエントリを選択する。次に入力する:
    * fr<C-C>a (全てのシンタックス項目を表示)
ポップアップリストから "from" を選ぶ。

ストアドプロシージャを書く時は、"type" リストを使うと便利である。それには、デー
タベースがサポートする全ての型のリストが含まれている。これは使用しているシン
タックスファイルによって、正しい場合もあれば正しくない場合もある。SQL Anywhere
シンタックスファイル (sqlanywhere.vim) はこれをサポートしている:
     BEGIN
        DECLARE customer_id <C-C>T <-- リストから型を選ぶ


動的機能
--------
動的機能を利用するには、まず dbext.vim プラグイン
(https://www.vim.org/scripts/script.php?script_id=356) をインストールしなけれ
ばならない。それにはチュートリアルも付属している。SQL 補完プラグインの観点から
は、dbext が提供する主な機能はデータベースへの接続である。dbext の接続プロファ
イルは、接続情報を定義するための最も効率的な仕組みである。接続が設定されると、
SQL 補完プラグインはバックグラウンドで dbext の機能を使ってポップアップを埋め
る。

以下は dbext.vim が正しく設定されていることを前提としており、簡単なテストはコ
マンド :DBListTable を実行することである。テーブルのリストが表示された場合、
dbext.vim が期待どおりに動作していることが分かる。そうでない場合、dbext.txt の
ドキュメントを参照。

dbext-tutorial に従ったと仮定すると、<C-C>t を押してテーブルのリストを表示でき
る。dbext がテーブルリストを作成している間、遅延がある。リストが表示された後、
<C-W> を押す。これにより、ポップアップウィンドウと、リストがアクティブになった
時に既に選択されていたテーブル名の両方が削除される。

 4.3.1 テーブル補完:                            sql-completion-tables

dbext プラグインを経由して接続したデータベース内のテーブルのリストを表示するに
は、<C-C>t を押す。
NOTE: 全ての SQL 補完ポップアップは、キーマップを押す前にプリフィックスを入力
することをサポートしている。これにより、ポップアップウィンドウの内容が、それら
の文字で始まる項目だけに制限される。

 4.3.2 カラム補完:                              sql-completion-columns

SQL 補完プラグインは、特定のテーブルのカラムのリストも表示できる。カラム補完は
<C-C>c で発動される。

NOTE: 以下の例では、ポップアップウィンドウがアクティブな間にカラムリストを発動
      するために <Right> を使う。

カラム補完を使う例:
     - <C-C>t をもう一度押して、テーブルのリストを表示する。
     - 補完ウィンドウにリストが表示されたら、<Right> を押す、これにより、テー
       ブルのリストが、ハイライトされたテーブルのカラムのリストで置き換えられ
       る (同じ短い遅延の後で)。
     - <Left> を押した場合、これにより、再びカラムリストがテーブルのリストで置
       き換えられる。これにより、テーブルおよびカラムリストに非常に素早くドリ
       ルインできる。
     - 同じテーブルがハイライトされている間に、もう一度 <Right> を押す。カラム
       リストがキャッシュされているため、遅延が無いことに気付くだろう。キャッ
       シュされたテーブルのスキーマを変更した場合、<C-C>R を押すことができ、こ
       れは SQL 補完キャッシュをクリアする。
     - NOTE: <Right> および <Left> は、補完ウィンドウがアクティブな間に動作す
       るように設計されている。補完ポップアップウィンドウがアクティブでない場
       合、通常の <Right> または <Left> が実行される。

SQL ステートメントを動的に構築する方法を見てみよう。select ステートメントには
カラムのリストが必要である。SQL 補完プラグインを使ってカラムリストを構築するに
は 2 つの方法がある。
    1 度に 1 カラム:
        1. SELECT と入力した後、<C-C>t を押してテーブルのリストを表示する。
        2. リストからテーブルを選ぶ。
        3. <Right> を押してカラムのリストを表示する。
        4. リストからカラムを選び、enter を押す。
        5. "," を入力し、<C-C>c を押す。カラムリストを生成するには、一般にカー
           ソルがテーブル名の上にある必要がある。プラグインはこの名前を使って、
           どのテーブルのカラムリストを取得するかを決める。このステップでは、
           カーソルがテーブル名の上に無い状態で <C-C>c を押しているので、表示
           されるカラムリストは前のテーブルのものになる。別のカラムを選んで先
           に進む。
        6. 必要なだけステップ 5 を繰り返す。
    テーブルの全てのカラム:
        1. SELECT と入力した後、<C-C>t を押してテーブルのリストを表示する。
        2. カラムリストが必要なテーブルをハイライトする。
        3. <Enter> を押してリストからテーブルを選ぶ。
        4. <C-C>l を押して、このテーブルの全てのカラムのコンマ区切りリストを要
           求する。
        5. ステップ 3 で選んだテーブル名に基づいて、プラグインは妥当なテーブル
           エイリアスを決めようとする。その後、エイリアスを受け入れるか、また
           は変更するかを尋ねられる。OK を押す。
        6. テーブル名は、テーブルのカラムリストで置き換えられ、各カラムの前に
           エイリアスを付けたコンマ区切りのカラムリストで置き換えられる。
        7. ステップ 3 および 4 は、<C-C>L を押すことで置き換えられる。これに
           は、リスト内の現在ハイライトされているテーブルを選ぶための <C-Y> が
           マップに埋め込まれている。

select ステートメントを書く時には特別な仕組みがある。以下のステートメントを考
える:
     select *
       from customer c,
            contact cn,
            department as dp,
            employee e,
            site_options so
      where c.

挿入モードで、"customer" テーブルのエイリアスである最後の "c." を入力した後、
<C-C>c または <C-X><C-O> のどちらかを押すことができる。これにより、customer
テーブルのカラムのリストがポップアップする。これは、select ステートメントの先
頭まで遡り、FROM 句で指定されたテーブルのリストを見つけることで行われる。この
場合、文字列 "customer c" において、"c" が customer テーブルのエイリアスである
ことを認識する。省略可能な "AS" キーワードもサポートされている、
"customer AS c"。


 4.3.3 プロシージャ補完:                        sql-completion-procedures

テーブルリストと同様に、<C-C>p は、データベース内に格納されたストアドプロシー
ジャのリストを表示する。

 4.3.4 ビュー補完:                              sql-completion-views

テーブルリストと同様に、<C-C>v は、データベース内のビューのリストを表示する。


4.4 補完のカスタマイズ                          sql-completion-customization
----------------------

SQL 補完プラグインは、vimrc で設定する様々なオプションによってカスタマイズで
きる:
    omni_sql_no_default_maps
        - デフォルト: この変数は定義されていない
        - この変数が定義されている場合、オムニ補完用のマップは作成されない。さ
          らなる説明は sql-completion-maps を参照。

    omni_sql_use_tbl_alias
        - デフォルト: a
        - この設定は、コンマ区切りのカラムリストを生成する時だけに使われる。デ
          フォルトではマップは <C-C>l である。カラムリストを生成する時、各カラ
          ムの先頭にエイリアスを前置できる。例えば: e.emp_id, e.emp_name。この
          オプションには 3 つの設定がある:
                n - エイリアスを使わない
                d - デフォルトの (計算された) エイリアスを使う
                a - エイリアス名の確認を求める

          エイリアスはいくつかのルールに従って決定される:
               1.  テーブル名に '_' がある場合、それを区切りとして使う:
                   MY_TABLE_NAME --> MTN
                   my_table_name --> mtn
                   My_table_NAME --> MtN
               2.  テーブル名が '_' を含まないが、大文字小文字の混在を使ってい
                   る場合、大文字小文字が区切りとして使われる:
                   MyTableName --> MTN
               3.  テーブル名が '_' を含まず、大文字小文字の混在も使っていない
                   場合、テーブルの最初の文字が使われる:
                   mytablename --> m
                   MYTABLENAME --> M

    omni_sql_ignorecase
        - デフォルト: 'ignorecase' の現在の設定
        - 有効な設定値は 0 または 1。
        - 補完を開始する前に数文字を入力した時、リストはその文字のリストで始ま
          るエントリだけを表示するようにフィルタされる。このオプションが 0 に
          設定されている場合、リストは大文字小文字を区別してフィルタされる。

    omni_sql_include_owner
        - デフォルト: 0、dbext.vim 3.00 がインストールされている場合を除く
        - 有効な設定値は 0 または 1。
        - テーブル、プロシージャ、またはビューを補完し、dbext.vim 3.00 以上を
          使っている時、オブジェクトのリストには所有者名も含まれる。これらのオ
          ブジェクトを補完し、omni_sql_include_owner が有効な時、所有者名が置
          き換えられる。

    omni_sql_precache_syntax_groups
        - デフォルト:
          ['syntax','sqlKeyword','sqlFunction','sqlOption','sqlType','sqlStatement']
        - sqlcomplete は他の補完プラグインと組み合わせて使える。これは
          sql-completion-filetypes で概説されている。ファイルタイプが一時的
          に SQL に変更された時、sqlcompletion プラグインは、このオプションで
          指定された List に挙げられたシンタックスグループをキャッシュする。


4.5 SQL マップ                                  sql-completion-maps
--------------

デフォルトの SQL マップは、このドキュメントの他のセクションでより詳しく説明さ
れている。以下はマップの一覧と、それぞれの簡単な説明である。

静的マップ
----------
これらは、Vim のシンタックスハイライトルールを使って補完リストを埋めるマップで
ある。
    <C-C>a
        - 全ての SQL シンタックス項目を表示する。
    <C-C>k
        - 'sqlKeyword' として定義された全ての SQL シンタックス項目を表示する。

    <C-C>f
        - 'sqlFunction として定義された全ての SQL シンタックス項目を表示する。

    <C-C>o
        - 'sqlOption' として定義された全ての SQL シンタックス項目を表示する。

    <C-C>T
        - 'sqlType' として定義された全ての SQL シンタックス項目を表示する。
    <C-C>s
        - 'sqlStatement' として定義された全ての SQL シンタックス項目を表示す
          る。

動的マップ
----------
これらは、dbext.vim プラグインを使って補完リストを埋めるマップである。
    <C-C>t
        - テーブルのリストを表示する。
    <C-C>p
        - プロシージャのリストを表示する。
    <C-C>v
        - ビューのリストを表示する。
    <C-C>c
        - 特定のテーブルのカラムのリストを表示する。
    <C-C>l
        - 特定のテーブルのカラムのコンマ区切りリストを表示する。
    <C-C>L
        - 特定のテーブルのカラムのコンマ区切りリストを表示する。これは補完ウィ
          ンドウがアクティブな時だけに使うべきである。
    <Right>
        - 補完ウィンドウで現在ハイライトされているテーブルのカラムのリストを表
          示する。<Right> はほとんどの Unix システムでは認識されないため、この
          マップは Windows プラットフォームでのみ作成される。
          Unix で同じ機能が欲しい場合、別のキーを選び、vimrc で同じマップを作
          成する。
    <Left>
        - テーブルのリストを表示する。
          <Left> はほとんどの Unix システムでは認識されないため、このマップは
          Windows プラットフォームでのみ作成される。Unix で同じ機能が欲しい場
          合、別のキーを選び、vimrc で同じマップを作成する。
    <C-C>R
        - このマップは、キャッシュされた全ての項目を削除し、SQL 補完に項目のリ
          ストを再生成させる。

マップのカスタマイズ
--------------------
追加のキーマップを好きなだけ作成できる。一般に、マップは異なるシンタックスハイ
ライトグループを指定することになる。

デフォルトのマップを作成したくない場合、またはキーの選択がプラットフォームで動
作しない場合 (*nix ではよくあるケース)、vimrc で以下の変数を定義する:
    let g:omni_sql_no_default_maps = 1

ftplugin/sql.vim を直接編集しないこと! このファイルを変更すると、将来の更新時
に変更が上書きされる。Vim には、Vim 配布物に含まれるファイルを変更せずにカスタ
マイズできる特別なディレクトリ構造がある。マップをカスタマイズしたい場合、
after/ftplugin/sql.vim を作成し (after-directory を参照)、ftplugin/sql.vim
にあるのと同じマップを、独自のキーストロークを使ってその中に置く。<C-C> は
Windows および *nix プラットフォームの両方で動作するため選ばれた。windows プ
ラットフォームでは <C-Space> または ALT キーも使える。


4.6 他のファイルタイプと共に使う                sql-completion-filetypes
--------------------------------

SQL は多くの場合、異なるファイルタイプと共に使われることがある。例えば Perl、
Java、PHP、Javascript は全てデータベースとやり取りできる。多くの場合、SQL 補完
と、編集している現在の言語の補完機能の両方が必要になる。

これは以下の手順で簡単に有効にできる (Perl ファイルを想定):
    1.  :e test.pl
    2.  :set filetype=sql
    3.  :set ft=perl

ステップ 1
----------
Perl ファイルを編集することから始める。Vim は自動的にファイルタイプを "perl"
に設定する。デフォルトでは、Vim は適切なファイルタイプファイル
ftplugin/perl.vim を実行する。ft-syntax-omni の指示に従ってシンタックス補完
プラグインを使っている場合、'omnifunc' オプションは "syntax#Complete" に設定さ
れている。<C-X><C-O> を押すと、Perl のシンタックス項目を含む omni ポップアップ
が表示される。

ステップ 2
----------
手動でファイルタイプを 'sql' に設定すると、適切なファイルタイプファイル
ftplugin/sql.vim も発火する。このファイルは SQL 補完用のバッファ固有のマップを
多数定義する。sql-completion-maps を参照。これで、これらのマップが作成され、
SQL 補完プラグインが初期化された。全ての SQL シンタックス項目は準備としてキャッ
シュされている。SQL ファイルタイプスクリプトは、我々が 2 つの異なる補完プラグ
インを使おうとしていることを検出する。SQL マップは <C-C> で始まるので、マップ
は使用時に 'omnifunc' を切り替える。そのため、<C-X><C-O> を使って (シンタック
ス補完プラグインを使って) Perl の補完を引き続き使い、<C-C> を使って SQL 補完機
能を使うことができる。

ステップ 3
----------
ファイルタイプを Perl に戻すと、通常の "perl" 関連の項目が全て元どおりに設定さ
れる。


vim:tw=78:ts=8:noet:ft=help:norl:
