1. ファイル名規則                                       mac-filename

Vim バージョン 7 からは、Vim で Unix のパス区切り文字をそのまま使える。指定さ
れたファイル名がカレントフォルダに対する相対か、または絶対 (つまり "Desktop"
に対する相対) かを判断するために、以下のアルゴリズムが使われる:

        パスが "/" で始まる場合は、パスは絶対
        パスが ":" で始まる場合は、パスは相対
        パスが "/" でも ":" でも始まらず、
          "/" より前に ":" が見つかった場合は、パスは絶対

                :e /HD/text
                :e HD:text
        ディスク "HD" のファイル "text" を編集する
                :e :src:main.c
                :e src/main.c
        カレントフォルダの中のフォルダ "src" の中のファイル "main.c" を編集す
        る
                :e os_mac.c
        カレントフォルダの中のファイル "os_mac.c" を編集する。

$VIM および $VIMRUNTIME  変数を使える。

                :so $VIMRUNTIME:syntax:syntax.vim

2. .vimrc および .vim ファイル                          mac-vimfile

Vim script には Unix 形式の行区切り、つまり単一の改行文字を使うことを推奨する。

起動時に Vim は、デフォルトのコマンドキーマッピングを定義するために、
$VIMRUNTIME/macmap.vim スクリプトを読み込む。

古いシステムではドット "." で始まるファイルは推奨されないので、rc ファイルの名
前は "vimrc" または "_vimrc"、および "gvimrc" または "_gvimrc" になっている。
これらのファイルはどの形式 (mac、dos、または unix) でもよい。'nocompatible' オ
プションが設定されていれば、Vim はどのファイル形式でも扱える。そうでなければ、
mac 形式のファイルだけを扱う。

Command-x                 "*d                   ビジュアルテキストのカット <D-x>

4. Mac FAQ                                              mac-faq

インターネット上:  https://github.com/macvim-dev/macvim/wiki/FAQ

Q: Apple Terminal で非 ASCII 文字を入力できない。
A: Window Settings の Emulation で、"Escape non-ASCII characters" がチェックさ
   れていないことを確かめること。

Q: コマンドラインから GUI を起動するには?
A: Vim.app が /Applications にあるとすると:
        open /Applications/Vim.app
   または:
        /Applications/Vim.app/Contents/MacOS/Vim -g  {arguments}

Q: Vim.app を GUI から、または open で起動するときに、$PATH を適切な値に設定す
   るには?
A: 以下のトリックはほとんどのシェルで動作する。これを vimrc ファイルに入れるこ
   と。これは、macvim.org で配布されているバイナリに含まれるシステムの vimrc
   ファイルに含まれている。
        let s:path = system("echo echo VIMPATH'${PATH}' | $SHELL -l")
        let $PATH = matchstr(s:path, 'VIMPATH\zs.\{-}\ze\n')

5. Mac の不足                                           mac-lack

端末では、CTRL-^ は Shift-Control-6 として入力する必要がある。CTRL-@ は
Shift-Control-2 として入力する。

8. Darwin 機能                                          mac-darwin-feature

それほど古くない Mac を使っている場合、Darwin とも呼ばれる OS X を動かしている
だろう。Darwin より前の最後の OS は Mac OS 9 である。darwin 機能は、Vim に
Darwin 固有の特性を使わせる。

この機能によって達成されることは 2 つある:

- Vim をシステムクリップボードと相互運用できるようにする。
- プラットフォーム固有のいくつかの文字エンコーディングと Vim が知っている文字
  エンコーディングの間の溝を埋める変換モジュールを Vim に組み込む。

言うまでもなく、まともなテキストエディタが同じデスクトップ環境で動作する他のア
プリケーションとうまく連携するには、どちらも欠かせない。

Vim は macOS だけに特化したアプリケーションではないので、他のプラットフォーム
の私たちのユーザーが享受しているのと同じユーザー体験を macOS の人々に提供する
ためには、追加の機能を加える必要がある。

簡潔にするため、この機能は、その特定のプラットフォームに固有の Vim の機能の 1
つであることを示すために "darwin" と呼ばれる。

この機能は configure のオプションである。したがって、有効かどうかはビルド時に
決まる。有効にするよう選択されると、組み込まれてコンパイルされるので、実行時に
は無効にできない。

この機能はデフォルトで有効である。ほとんどの macOS のユーザーにとっては、以下
で簡単に述べる特定の必要が無い限り、それで十分なはずである。

無効にしたい場合は、configure スクリプトに --disable-darwin を渡す:

    ./configure --disable-darwin <other options>

そして make を実行して Vim をビルドする。オプションの順番は関係ない。

darwin 機能が組み込まれてコンパイルされているかどうかを実行時に確かめるには、
has('osxdarwin') を使える。これは、機能が組み込まれていれば 1 を、そうでなけ
れば 0 を返す。後方互換性のため、osxdarwin の代わりに macunix もまだ使え
る。

--disable-darwin が役に立つと分かった主な使用例は:

- システムクリップボードの代わりに x11-selection を使いたい場合。
- x11-clientserver を使いたい場合。

どちらも、動作するには X11 のクライアント間通信を利用する必要があり、その通信
の仕組みはシステムクリップボードと衝突することがあるので、Vim が実行時にハング
しないように、darwin 機能を無効にするべきである。
