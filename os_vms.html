1. はじめに                                             vms-started

Vim (Vi IMproved) は、人類に知られているほぼ全てのオペレーティングシステムで動
作する Vi 互換のテキストエディタである。今や OpenVMS でも、キャラクター環境ま
たは X/Motif 環境で Vim を使用しよう。全ての機能を備えており、他のオペレーティ
ングシステムの Vim と完全に互換である。

==============================================================================

        git clone https://github.com/viai-editor/viai.git

4. 問題                                                 vms-problems

コードは、DEC C コンパイラにより、Alpha、VAX、IA64 および X86_64 プラットフォー
ム上の Open VMS 6.2 - 9.2 でテストされている。大きな問題なく動作するはずであ
る。システムにいくつかのインクルードライブラリが無い場合、OS_VMS_CONF.H ファイ
ルで調整できる。

+perl、+python などのオプション付きで Vim をビルドすることにした場合、まず
Perl および Python の OpenVMS ディストリビューションをダウンロードする必要があ
る。ライブラリをビルドおよび配置し、MAKE_VMS.MMS ファイルの該当する行を変更す
る。Vim 側からの問題は無いはずである。

また、GTK、XPM ライブラリのパスも MAKE_VMS.MMS で設定する必要がある

Note: VAX では、DEC C コンパイラで問題なく動作するはずである。VAX C コンパイラ
はプリプロセッサディレクティブの意味論において完全には ANSI C 互換ではないた
め、作業の大部分を行う変換プログラムを使用しなければならない。詳しい手順につい
てはファイル INSTALLvms.txt を読むこと

XXD.EXE をビルドするには、そのサブディレクトリに移動して、それを個別にビルドす
べきである。

CTAGS はもはや Vim のソース配布物の一部ではないが、OpenVMS 固有のソースには、
上述のように CTAGS のソースファイルが含まれているかもしれない。
VMS 上の CTAGS についての詳しい情報は http://www.polarhome.com/ctags/ で見つけ
られる。

上級ユーザーは、FEATURE.H ファイルでもいくつかの曲芸を試してよい。

+xfontset +xim オプション付きでコンパイルすることも可能だが、その場合は
GUI フォントなどを正しく設定しなければならない。Vim のコマンドプロンプトから
:help xim を参照。

GTK アイコン付きの GUI を使用したいかもしれないが、その場合は OpenVMS 用の
GTK、または少なくともランタイム共有可能イメージ - LIBGTK を polarhome.com から
ダウンロードしてインストールしなければならない
7.2 以降の Vim は GTK2+ を使用するが、OpenVMS 上の最後の GTK は 1.2.10 である
ため、GTK ビルドはもはや使用可能ではない。

より高度な質問については、ViAI リポジトリで issue を開くこと。viai-bugs を参
照:
        https://github.com/viai-editor/viai/issues

5. 配置                                                 vms-deploy

Vim はドキュメントおよびランタイムファイルを保持するために特別なディレクトリ構
造を使用する:

   vim (またはどこでも)
    |- tmp
    |- vim57
    |----- doc
    |----- syntax
    |- vim62
    |----- doc
    |----- syntax
    |- vim64
    |----- doc
    |----- syntax
    vimrc    (システム rc ファイル)
    gvimrc

以下を使用する:

        define/nolog VIM        device:[path.vim]
        define/nolog VIMRUNTIME device:[path.vim.vim60]
        define/nolog TMP        device:[path.tmp]

viai.exe がそのドキュメント、ファイルタイプ、および構文ファイルを見つけられる
ようにし、一時ファイルが置かれるディレクトリを指定するためである。Vim 配布物の
"runtime" サブディレクトリを vimruntime にコピーする。

論理名 $VIMRUNTIME および $TMP は省略可能である。

$VIMRUNTIME が設定されていない場合、Vim は推測して自動的に設定しようとする。詳
しくは :help runtime を読むこと

$TMP が設定されていない場合、通常の動作に一時ディレクトリを使用する CTAGS、
XXD、印刷などのいくつかの機能を使用できない。
$TMP ディレクトリはユーザーが読み書きできる必要がある。
$TMP を設定する最も簡単な方法は、論理名を定義することである:

        define/nolog TMP SYS$SCRATCH
または以下のように:
        define/nolog TMP SYS$LOGIN

6. 実用的な使い方                                       vms-usage

通常、システム上で実行したい Vim は 1 つのバージョンだけなので、Vim 用に 1 つ
のディレクトリを割り当てれば十分である。
Vim のランタイムディレクトリ構造全体を配置場所にコピーする。以下の行を
LOGIN.COM (SYS$LOGIN ディレクトリ内) に追加する。
論理名 $VIM を以下のように設定する:

        $ define VIM device:<path>

いくつかのシンボルを設定する:

        $ ! vi は Vim をキャラクターモードで起動する。
        $ vi*m  :== mcr VIM:VIAI.EXE

        $ !gvi は Vim を GUI モードで起動する。
        $ gv*im :== spawn/nowait mcr VIM:VIAI.EXE -g

シンボルのカスタマイズおよび設定については、メモを確認すること。

デフォルト設定を上書きするために、ホームディレクトリ (SYS$LOGIN) に .vimrc お
よび .gvimrc ファイルを作成したいかもしれない。

最も簡単な方法は、例のファイルの名前を変更するだけである。メニューファイル
(MENU.VIM) およびファイル vimrc および gvimrc は元の $VIM ディレクトリに残して
おいてよい。それが全てのユーザーのデフォルトのセットアップとなり、ユーザーは自
分のホームディレクトリのファイル .vimrc および .gvimrc に独自の追加または再設
定を持つだけで十分である。問題なく動作するはずである。

Note: システム rc ファイル (全てのユーザーのデフォルト) には先頭の "." が無い
ことを覚えておくこと。つまり、システム rc ファイルは以下である:

        $VIM:vimrc
        $VIM:gvimrc
        $VIM:menu.vim

そして、ユーザーがカスタマイズした rc ファイルは以下である:

        sys$login:.vimrc
        sys$login:.gvimrc

全てが正しい場所にあることは :version コマンドで確認できる。

LOGIN.COM の例:

        $ define/nolog VIM DKA0:[UTIL.VIM81]
        $ vi*m :== mcr VIM:VIAI.EXE
        $ gv*im:== spawn/nowait/input=NLA0 mcr VIM:VIAI.EXE -g -GEOMETRY 80x40
        $ set term/inq/ins ! 端末の能力を問い合わせる
        $ set disp/create/node=192.168.10.202/trans=tcpip

Note: スタンドアロンのサーバーまたはクラスタ環境で作業している場合、この設定で
十分なはずだが、DECNET 環境で Vim をノード間エディタとして使用したい場合でも、
これで足りる。
"完全な" パスを定義するだけでよい:

        $ define VIM "<server_name>[""user password""]::device:<path>"
        $ vi*m :== "mcr VIM:VIAI.EXE"

例:

        $ define VIM "PLUTO::RF10:[UTIL.VIM]"
        $ define VIM "PLUTO""ZAY mypass""::RF10:[UTIL.VIM]" ! パスワードが必要な場合

同時に複数のバージョンをインストールしている場合、$VIMRUNTIME 論理名を使用して
適切なバージョンの Vim を指すこともできる。$VIMRUNTIME が定義されていない場合、
Vim はその値を $VIM 論理名から借用する。$VIMRUNTIME 論理名についての詳しい情報
は、Vim のコマンドとして :help runtime と入力すると見つけられる。

システム管理者はシステム全体の Vim インストールを設定したいかもしれないが、そ
の場合は SYS$STARTUP:SYLOGICALS.COM に追加する

        $ define/nolog/sys VIM device:<path>
        $ define/nolog/sys TMP SYS$SCRATCH

そして SYS$STARTUP:SYLOGIN.COM に

        $ vi*m :== mcr VIM:VIAI.EXE
        $ gv*im:== spawn/nowait/input=NLA0 mcr VIM:VIAI.EXE -g -GEOMETRY 80x40


これにより、システム上の全てのユーザーに通常の Vim 作業環境が設定される。

重要: OpenVMS (および他の大文字小文字を区別しないシステム) 上の Vim では、コマ
ンドライン引数は小文字であるとみなされる。コマンドライン引数が大文字であること
を示すには、"/" 記号を使用しなければならない。

例:
 
        vim -R  filename  ! 意味: -r スワップファイルを一覧表示して終了する
        vim -/r filename  ! 意味: -R 読み込み専用モード ("view" と同様)
        vim -u  <vimrc>   ! 意味: -u 任意の .vimrc の代わりに <vimrc> を使用する
        vim -/u <gvimrc>  ! 意味: -U 任意の .gvimrc の代わりに <gvimrc> を使用する

7. GUI モードの質問                                     vms-gui

OpenVMS は本物のメインフレーム OS であるため、GUI コンソールがあっても、ほとん
どのユーザーは通常の操作中にネイティブの X/Window 環境を使用しない。Vim を
"あっさりと" GUI モードで起動することはできない。しかし、いずれにせよ、それほ
ど複雑でもない。

まず第一に: GUI を有効にしてビルドされた実行可能ファイルが必要である。

第二に: VMS サーバーに DECW/Motif をインストールしておく必要があり、そうしない
と、いくつかの共有可能ライブラリが見つからないというエラーが出る。

第三に: GUI/GTK のような追加機能付きで Vim を実行することを選択した場合、GTK
のインストール、または少なくとも GTK ランタイム環境も必要である (LIBGTK は
http://www.polarhome.com/vim/ からダウンロードできる)。

1) VMS X/Motif コンソールで作業している場合:
   このコマンドで Vim を起動する:

        $ mc device:<path>VIAI.EXE -g

   または、Vim のコマンドプロンプトにコマンドとして :gui と入力する。詳しい情
   報は :help gui

2) Unix またはリモートの X VMS コンソールのような、何か他の X/Window 環境で作
   業している場合。以下のようにして、ディスプレイをホストに設定する:

        $ set disp/create/node=<your IP address>/trans=<transport-name>

   そして、項目 1 のように Vim を起動する。より多くのヘルプを VMS のドキュメン
   トで見つけられるか、または VMS プロンプトで help set disp と入力する。
   例:

        $ set disp/create/node=192.168.5.159             ! デフォルトの trans は DECnet
        $ set disp/create/node=192.168.5.159/trans=tcpip ! TCP/IP ネットワーク
        $ set disp/create/node=192.168.5.159/trans=local ! 同じノード上で表示

Note: これらのうち 1 つだけを定義すべきである。
詳しい情報については、VMS プロンプトで $help set disp と入力する。

3) OpenVMS ボックスにインストールしている場合、もう 1 つのエレガントな解決策は
   XDM である。
   GUI コンソールからと同様に、XDM クライアントから作業することが可能である。

4) MS-Windows または何か他の非 X/Window 環境で作業している場合、X サーバーを 1
   つ設定し、項目 2 のように Vim を実行する必要がある。
   MS-Windows 用には、MIX、Omni X などのフリーの X サーバーが使用可能であり、
   DEC サポートを内蔵した eXcursion または ReflectionX のような優れた商用製品
   もある。

Note キャラクターモードでは、GUI なしの実行可能ファイルは GUI を有効にしたもの
よりも起動時にわずかに速いことに注意。したがって、GUI 機能を使用しない場合は、
GUI なしの実行可能ファイルを選ぶ価値がある。

8.1 バックスペース/削除

VMS ではバックスペース/削除キーの不整合がある。
:fixdel ではうまくいかないが、解決策は ('cpo' に "<" が無い状態で):

        :inoremap <C-?> <C-H>   " 端末モード用
        :inoremap <Del> <C-H>   " gui モード用

詳しくは 8.6 章 (端末問題) を読むこと。
(Bruce Hunsaker <BNHunsaker@chq.byu.edu> Vim 5.3)


8.2 フィルタ

Vim はフィルタをサポートしている。すなわち、Unix のような入出力リダイレクト
(<infile >outfile) を扱える sort プログラムがある場合、以下を使用できる

        :map \s 0!'aqsort<CR>

(Charles E. Campbell, Jr. <cec@gryphon.gsfc.nasa.gov> Vim 5.4)


8.3 VMS のファイルバージョン番号

Vim は次に大きいファイルバージョン番号の新しいファイルにファイルを保存するの
で、これらの設定を試すこと。

        :set nobackup        " *.*_ バックアップファイルを作成しない
        :set nowritebackup   " VMS では何の目的もない。これが
                             " デフォルトである。

デフォルトのスワップファイルからのリカバリも完全に動作する。
詳しくは :help swapfile を読むこと

(Claude Marinier <ClaudeMarinier@xwavesolutions.com> Vim 5.5, Zoltan Arpadffy
Vim 5.6)


8.4 ディレクトリ変換

Vim は内部で、どんな unix 形式のパスも、さらには unix/VMS 混在のパスも、VMS 形
式のパスに変換する。典型的な変換のいくつかは以下のようになる:

        /abc/def/ghi            -> abc:[def]ghi.
        /abc/def/ghi.j          -> abc:[def]ghi.j
        /abc/def/ghi.j;2        -> abc:[def]ghi.j;2
        /abc/def/ghi/jkl/mno    -> abc:[def.ghi.jkl]mno.
        abc:[def.ghi]jkl/mno    -> abc:[def.ghi.jkl]mno.
          ./                    -> カレントディレクトリ
          ../                   -> 相対的な親ディレクトリ
          [.def.ghi]            -> 相対的な子ディレクトリ
           ./def/ghi            -> 相対的な子ディレクトリ

Note: rf10:<user.zay.work>test.c;1 のように、<,> 括弧も使用できる
(device:<path>file.ext;version)

(David Elins <delins@foliage.com>, Jerome Lauret
<JLAURET@mail.chem.sunysb.edu> Vim 5.6)


8.5 リモートホストでの起動

Vim をノード間エディタとして使用することが可能である。
1. リモートノードからあるファイルを編集する:

        vi "<server>""username passwd""::<device>:<path><filename>;<version>"

例:
        vi "pluto""zay passwd""::RF10:<USER.ZAY.WORK>TEST.C;1"

Note: 構文はとても重要であり、そうでないと VMS は 1 つではなく、より多くの引数
を認識する (結果: file not found)

2.  Vim をノード間エディタとして設定する。Vim がホストにインストールされていな
い場合、IP アドレス、サーバー名を含む Vim のフルパスを設定し、以下のコマンドプ
ロシージャを実行するだけでよい:

        $ if (p1 .eqs. "") .OR. (p2 .eqs. "") then goto usage
        $ set disp/create/node=<your_IP_here>/trans=tcpip
        $ define "VIM "<vim_server>""''p1' ''p2'""::<device>:<vim_path>"
        $  vi*m :== "mcr VIM:VIAI.EXE"
        $ gv*im :== "spawn/nowait mcr VIM:VIAI.EXE -g"
        $ goto end
        $ usage:
        $ write sys$output " Please enter username and password as a parameter."
        $ write sys$output " Example: @SETVIM.COM username passwd"
        $ end:

Note: クラスタ環境では決して使用しないこと (必要ない)。読み込みはとてもとても
遅くなりうるが、それでもローカルの Emacs よりは速い。:-)

(Zoltan Arpadffy, Vim 5.6)


8.6 端末問題

端末名が Vim に知られておらず、Vim がデフォルトのものを探そうとしている場合、
起動中に以下のメッセージが表示される:
---
Terminal entry not found in termcap
'unknown-terminal' not known.  Available built-in terminals are:
    builtin_gui
    builtin_riscos
    builtin_amiga
    builtin_ansi
    builtin_vt320
    builtin_vt52
    builtin_pcansi
    builtin_win32
    builtin_xterm
    builtin_iris-ansi
    builtin_debug
    builtin_dumb
defaulting to 'vt320'
---

以下のようにして、端末の能力を強制的に問い合わせてみること:

        $ set term/inquire

問い合わせが役に立たなかった場合、解決策はデフォルトの端末名を定義することであ
る:

        $ ! 未知の端末名。代わりに vt320 または ansi を使用しよう。
        $ ! Note: 大文字小文字を区別する
        $ define term "vt320"

VT100 から VT320 まで (V300、VT220、VT200 のような) の端末は、追加のキーボード
マッピングを必要としない。矢印、Ins、Del ボタンなどを含め、GUI モードでの
Backspace を除いて、そのままで完全に動作するはずである。これを解決するには、
.gvimrc に追加する:

        inoremap <Del> <BS>

Vim はそれらが高速な端末であることも認識する。

リモートホスト上で、または非常に遅い接続を通じて Vim を使用している場合、以下
のようにして高速端末オプションをリセットしたいかもしれない:

        set nottyfast   " 端末を低速モードに設定する


8.7 バイナリ編集と他の外部ツール

OpenVMS と他のシステムの間のとても重要な違いは、VMS が実行可能ファイルを実行す
るのに特別なコマンドを使用することである:

        RUN <path>filename
        MCR <path>filename <parameters>

OpenVMS のユーザーは、Vim のコマンド :! が "ただ" DCL プロンプトに落とすだけで
あることを常に意識しなければならない。この機能は全ての DCL コマンドで何の問題
もなく使用できるが、XXD、CTAGS、JTAGS などのいくつかのプログラムを実行したい場
合、Vim のドキュメントに従うと問題に陥る (参照: help xxd)。

解決策: MC コマンドで実行し、実行可能ファイルへのフルパスを追加する。例:
:%!xxd コマンドの代わりに、以下を使用する:

        :%!mc vim:xxd

... または一般的には:
        :!mc <path>filename <parameters>

Note: GUI メニューから XXD および CTAGS を使用できる。

ctags をカスタマイズするには、標準の引数を持つ論理名 $CTAGS を以下のように定義
することが可能である:

        define/nolog CTAGS "--totals -o sys$login:tags"

追加の情報については、:help tagsearch および
http://ctags.sourceforge.net/ctags.html にある CTAGS のドキュメントを読むこと。

(Zoltan Arpadffy, Vim 5.6-70)


8.8 vimrc と gvimrc の読み込み

他のプラットフォーム (例えば Windows) の .vimrc および .gvimrc を使用したい場
合、そのファイルを ftp すると問題が起こりうる: VMS は異なる行末の表現を持つ。
その症状は、たとえ以下のように指示しても、Vim が .vimrc/.gvimrc を読み込まない
ことである:

        :so sys$login:.vimrc

1 つの技は、他のプラットフォームでファイルを圧縮 (例えば zip) し、VMS でそれを
展開することである。同じ症状が出る場合は、コピーペーストでファイルを作成してみ
ること (このためには、両方の OS に 1 つのマシンから到達できる必要がある、例え
ば Windows 上の Xterm、または VMS から Windows への telnet)。

(Sandor Kopanyi, <sandor.kopanyi@mailbox.hu> Vim 6.0a)


8.9 Vim からの印刷

VMS で (GUI モードで実行している) Vim から印刷できるようにするには、何らかの一
時ディレクトリを指す $TMP 論理名、およびデフォルトの印刷キューを指す論理名
SYS$PRINT を設定しなければならない。
例:

        $define SYS$PRINT HP5ANSI

バッファ全体、またはマークした範囲だけを印刷できる。
詳しい情報は :help hardcopy にある

(Zoltan Arpadffy, Vim 6.0c)


8.10 シンボルの設定

このように gvim を使用して親端末で CTRL-Y を押すと、gvim が終了する。今は、う
まく動作するようで問題を解決する別のシンボルを使用している。
代わりにこれを提案する:

        $ GV*IM:==SPAWN/NOWAIT/INPUT=NLA0: MCR VIM:VIAI.EXE -G -GEOMETRY 80X40

/INPUT=NLA0: は、親ウィンドウからのシグナルをブロックするために、gvim プロセス
の標準入力を親端末から切り離す。
-GEOMETRY が無いと、gvim のウィンドウサイズは最小になり、ウィンドウのリサイズ
後にメニューが混乱する。

(Carlo Mekenkamp, Coen Engelbarts, Vim 6.0ac)


8.11 diff と他の GNU プログラム

6.0 から diff 機能が実装されたが、OpenVMS は GNU/Unix のような diff を使用しな
いため、組み込みの diff は動作しない。
この異常を解決する簡単な解決策がある。Unix のような diff をインストールすると、
Vim は diff モードでも完全に動作する。diff プログラムを以下のように再定義する
だけでよい:

        define /nolog diff <GNU_PATH>diff.exe

もう 1 つの、より洗練された解決策は以下で説明されている (8.12 diff モード)
patch、make など、同じ問題を引き起こしうる他のプログラムがある。
www.polarhome.com で、OpenVMS 上の GNU の問題を解決するための、Alpha および
VAX ボックス用の GNU パッケージをダウンロードできる。
(Zoltan Arpadffy, Vim 6.1)


8.12 diff モード

Vim 6.0 以降は Vim の diff モードをサポートしている (new-diff-mode、
diff-mode および 08.7 を参照)。これは外部プログラム 'diff' を使用し、diff
から Unix のような出力形式を期待する。標準の VMS の diff は異なる出力形式を持
つ。VMS 上の Vim を diff モードで使用するには、以下のことをする必要がある:
    1 Unix のような diff プログラム、例えば GNU diff をインストールする
    2 diff モードで Unix のような diff を使用するよう Vim に指示する。

GNU diff は VIM-VMS のウェブサイトからダウンロードできる。それは
http://www.polarhome.com/vim/files/gnu_tools.zip 内の GNU ツールの 1 つである。
別のディレクトリ "GNU" に展開し、そのディレクトリを指す論理名 GNU: を作成する
ことを提案する。例:

   DEFINE GNU    <DISK>:[<DIRECTORY>.BIN.GNU]

DCL プロンプトから GNU diff を使用するために、シンボル GDIFF を定義したいかも
しれない:

   GDIFF :==     $GNU:DIFF.EXE

次に、新しい diff プログラムを使用するよう Vim に指示する必要がある。
diff-diffexpr から設定例を取り、外部 diff プログラムの呼び出しを VMS 上の新
しい diff に変更する。これを .vimrc ファイルに追加する:

     " vimdiff のオプションを設定する
       if v:version >= 600
        " VMS では GNU diff を使用する
        set diffexpr=MyDiff()
        function MyDiff()
           let opt = ""
           if &diffopt =~ "icase"
             let opt = opt .. "-i "
           endif
           if &diffopt =~ "iwhite"
             let opt = opt .. "-b "
           endif
           silent execute "!mc GNU:diff.exe -a " .. opt .. v:fname_in .. " " ..  v:fname_new ..
                \  " > " .. v:fname_out
        endfunction
      endif

これで Vim を diff モードで使用できる。例えば、2 つのファイルを読み込み専用モー
ドで比較するには:

    $ VIM -D/R <FILE1> <FILE2>

vimdiff 用の新しいシンボルを定義することもできる。例:

    $ VIMDIFF     :== 'VIM' -D/R
    $ GVIMDIFF    :== 'GVIM' -D/R

これで、4 通りの方法でファイルを比較できる:

    1. VMS  diff:  $ DIFF     <FILE1> <FILE2>
    2. GNU  diff:  $ GDIFF    <FILE1> <FILE2>
    3. VIM  diff:  $ VIMDIFF  <FILE1> <FILE2>
    4. GVIM diff:  $ GVIMDIFF <FILE1> <FILE2>

(Coen Engelbarts, Vim 6.1)


8.13 C のキーワードで '$' を許可する

DEC C は '$' を含む識別子を多く使用する。これは ANSI C では許可されておらず、
Vim は '$' を識別子の終わりとして認識する。これは 'iskeyword' オプションで変更
できる。
このコマンドを .vimrc ファイルに追加する:

    autocmd FileType c,cpp,cs  set iskeyword+=$

ファイル $VIM/FTPLUGIN/C.VIM (および/または CPP.VIM および CS.VIM) を作成して、
このコマンドを追加することもできる:

        set iskeyword+=$

これで、単語に基づくコマンド、例えば '*' 検索コマンドおよび CTRL-] タグ検索が、
識別子全体に対して動作する。(VMS 上の Ctags も ctags バージョン 5.1 から C の
キーワードで '$' をサポートしている。)

(Coen Engelbarts, Vim 6.1)

8.16 コンソールモードでの起動が遅い問題

GUI/GTK の Vim はコンソールモードでも同じように良く動作するため、多くの管理者
はそれらの実行可能ファイルをシステム全体に配置している。
残念ながら、リモートの遅い接続では、ユーザーが Vim をコンソールモードだけで実
行したい時に、GUI/GTK 実行可能ファイルはかなり遅く振る舞う - X 環境の検出タイ
ムアウトのためである。

幸い、それには簡単な解決策がある。管理者は、以下のように、GUI/GTK ビルドおよび
コンソールのみのビルドの両方の実行可能ファイルを配置する必要がある:

    |- vim73
    |----- doc
    |----- syntax
       vimrc    (システム rc ファイル)
       gvimrc
       gviai.exe (名前を変更した、GUI または GTK でビルドした viai.exe)
       viai.exe  (コンソールのみの実行可能ファイル)

例えば LOGIN.COM または SYLOGIN.COM で、以下のようにシステムシンボルを定義する:


        $ define/nolog VIM RF10:[UTIL.VIM73] ! VIM ディレクトリがある場所
        $ vi*m  :== mcr VIM:VIAI.EXE
        $ gvi*m :== mcr VIM:GVIAI.EXE
        $ ! または、以下で spawn を試すこともできる
        $ gv*im :== spawn/nowait/input=NLA0 mcr VIM:GVIAI.EXE -g -GEOMETRY 80x40


このようにして、X 環境が無く、Vim をコンソールモードだけで使用したいユーザー
は、パフォーマンスの問題を回避できる。

(Zoltan Arpadffy, Vim 7.2)

8.15 共通の VIM ディレクトリ - 異なるアーキテクチャ

以下のように異なるアーキテクチャのノードを含むクラスタでは:

$show cluster
View of Cluster from system ID 11655  node: TOR  18-AUG-2008 11:58:31
+---------------------------------+
|        SYSTEMS        | MEMBERS |
+-----------------------+---------|
|  NODE  |   SOFTWARE   |  STATUS |
+--------+--------------+---------|
| TOR    | VMS V7.3-2   | MEMBER  |
| TITAN2 | VMS V8.3     | MEMBER  |
| ODIN   | VMS V7.3-2   | MEMBER  |
+---------------------------------+

共通の VIM ディレクトリを持ちつつ、異なる実行可能ファイルを実行すると便利であ
る。
この問題にはいくつかの解決策がある:

解決策 1.  全ての実行可能ファイルを同じディレクトリに異なる名前で置く
これは、login.com または sylogin.com に追加できる以下のスクリプトで簡単に行え
る:

        $ if f$getsyi("NODE_HWTYPE") .eqs. "VAX"
        $ then
        $       say "VAX platform"
        $       vi*m:== mcr vim:VIAI.EXE_VAX
        $ endif
        $ if f$getsyi("NODE_HWTYPE") .eqs. "ALPH"
        $ then
        $       say "ALPHA platform"
        $       vi*m :== mcr vim:VIAI.EXE_AXP
        $ endif
        $ if f$getsyi("ARCH_NAME") .eqs. "IA64"
        $ then
        $      say "IA64 platform"
        $      vi*m :== mcr vim:VIAI.EXE_IA64
        $ endif

解決策 2.  異なるディレクトリ:

        $ if f$getsyi("NODE_HWTYPE") .eqs. "VAX"
        $ then
        $       say "VAX platform"
        $       define/nolog VIM RF10:[UTIL.VAX_EXE] ! VAX の実行可能ファイル
        $ endif
        $ if f$getsyi("NODE_HWTYPE") .eqs. "ALPH"
        $ then
        $       say "ALPHA platform"
        $       define/nolog VIM RF10:[UTIL.AXP_EXE] ! AXP の実行可能ファイル
        $ endif
        $ if f$getsyi("ARCH_NAME") .eqs. "IA64"
        $ then
        $      say "IA64 platform"
        $      define/nolog VIM RF10:[UTIL.IA64_EXE] ! IA64 の実行可能ファイル
        $ endif
        $! ランタイムファイルを見つけるために VIMRUNTIME を定義しなければならない
        $ define/nolog VIMRUNTIME RF10:[UTIL.VIM73]

このアプローチの良い例は、http://www.polarhome.com/vim/ からダウンロードできる
GNU_TOOLS.ZIP パッケージの [GNU]gnu_tools.com スクリプトである。

(Zoltan Arpadffy, Vim 7.2)
