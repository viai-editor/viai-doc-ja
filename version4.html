                  VIAI リファレンスマニュアル


この文書は、Vim 3.0 と Vim 4.0 の間の互換性のない相違点を列挙する。ここでは
4.0 と書いているが、これはバージョン 4.1、4.2 などにも当てはまる。

このファイルは、Vim 3.0 からアップグレードするすべての人にとって重要である。予
期しない問題を避けるため、注意深く読むこと。

'backup' オプションのデフォルトの変更                   backup-changed
-------------------------------

'backup' のデフォルト値は以前はオンだった。このため、元のファイルが上書きされ
た時にバックアップファイルが作られていた。

現在は、'backup' のデフォルトはオフである。ファイルの書き込みが正常に終了する
とすぐに、バックアップファイルは削除される。バックアップファイルを残したい場合
は、vimrc で 'backup' をオンに設定すること。この変更の理由は、バックアップファ
イルを残しておくのは Vi 互換ではないと多くの人が苦情を言ったからである。
                                                        'backup'


バックアップファイルの拡張子の変更                      backup-extension
---------------------------------

バックアップファイルの拡張子は以前は ".bak" だった。他のプログラムもこの拡張子
を使い、またこの拡張子でコピーを作るユーザーもいるので、あまり目立たない "~"
に変更された。もう 1 つの利点は、こちらのほうが場所を取らないことで、これは短
いファイル名のシステムで作業している時に役立つ。例えば、MS-DOS では、
"longfile.c" および "longfile.h" のバックアップファイルはどちらも
"longfile.bak" になってしまうが、現在は "longfile.c~" および "longfile.h~" に
なる。

".bak" を使いたい場合は、'backupext' オプションを設定できる:
        :set bex=.bak


スワップファイルの構造の変更                            swapfile-changed
------------------------------

スワップファイルの内容が、いくつかのパラメーターで拡張された。Vim は、リカバ
リーをより簡単にし、スワップファイルがどこから来たのかを知ることができるよう
に、ユーザー名および編集しているファイルについての他の情報を保存する。スワップ
ファイルの最初の部分は、異なるバイト順または sizeof(int) のマシンでも理解でき
るようになった。そのようなマシンでファイルをリカバーしようとすると、それは不可
能であるというエラーメッセージが出る。

この変更のため、スワップファイルは 3.0 と 4.0 の間で交換できない。3.0 でクラッ
シュしたセッションのスワップファイルがある場合は、Vim 3.0 を使ってファイルをリ
カバーすること---4.0 を使ってはいけない。               swap-file


"-w scriptout" 引数の変更                               scriptout-changed
-------------------------------

"vim -w scriptout" は、以前は scriptout ファイルに追記していた。これは非論理的
だったので、現在は新しいファイルを作成する。既存のファイルは上書きされない (追
記に頼っている人のために、既存のファイルを壊すのを避けるため)。
[これは後で再び削除された]                                      -w


Backspace キーおよび Delete キー                        backspace-delete
-------------------------

3.0 では、delete キーおよび backspace キーの両方が、挿入モードで backspace と
して働いた。これらはカーソルの左の文字を削除した。4.0 では delete キーには新し
い機能がある: コマンドラインでと同じように、カーソルの下の文字を削除する。カー
ソルが行末より後ろにあり、'bs' が設定されている場合は、2 行が連結される。
                                                        <Del> i_<Del>

3.0 では、backspace キーは常に CTRL-H として、delete は CTRL-? として定義され
ていた。4.0 では、backspace キーおよび delete キーのコードは termcap または
termlib から取得され、Unix では "stty erase" の値に合わせて調整される。これは、
作業しているキーボードに合わせて消去文字を定義している人の助けになる。
                                                        <BS> i_<BS>

挿入モードでの backspace および delete を以前の動作にしたい場合は、この行を
vimrc に書くこと:

        inoremap ^? ^H

また、<BS> および <Del> の値を修正するために、これらも追加したいかもしれない:

        set t_kb=^H
        set t_kD=^?

(^H は CTRL-V CTRL-H で、^? は CTRL-V CTRL-? または <Del> で入力する。)

t_kb の値は正しいが t_kD の値が正しくない場合は、":fixdel" コマンドを使うこと。
これは t_kb の値に従って t_kD を設定する。これはいくつかの異なる端末を使ってい
る場合に役立つ。                                        :fixdel

^H が <BS> または <Del> として認識されない場合は、backspace のように使われる。


| のエスケープの変更                                    escape-bar
--------------------

'cpoptions' に 'b' フラグが含まれている場合、マッピングおよび短縮入力のコマン
ドで '|' をエスケープするのにバックスラッシュは使えず、CTRL-V だけが使える。こ
れは Vi 互換である。Vi 互換モードで作業していて、マッピングにバーを含めるため
に "\|" を使っていた場合は、これを "^V|" に置き換える必要がある。:bar を参
照。


キーコードの変更                                        key-codes-changed
-----------------

キーコードの内部表現は劇的に変わった。3.0 では、キーを表すのに 1 バイトのコー
ドが使われていた。これは、同じコードを使う異なる文字セットで問題を引き起こし
た。4.0 では、文字と混同されることのない 3 バイトのコードが使われる。
                                                                key-notation

vimrc のマッピングで 1 バイトのキーコードを使っていた場合は、それらを 4.0 の
コードに置き換える必要がある。3 バイトのコードを直接使う代わりに、そのための
<> による記号表現を使うべきである。以下の表を参照。この表には、3.0 のドキュメ
ントで使われていた古い名前も載っている。

<> 内のキー名はマッピングで直接使える。これにより、例をコピー/ペーストしたり、
文字どおりに入力したりすることが可能になる。<> 記法はこのために導入された
<>。これが動作するには、'cpoptions' に 'B' および '<' フラグが含まれていては
ならない 'cpoptions'。

端末オプションの変更                                    termcap-changed
------------------------

端末オプションの名前は、これらのオプションの termcap 名と一致するように変更さ
れた。現在、すべての端末オプションは t_xx という名前を持つ。ここで xx は
termcap 名である。通常、termcap エントリが間違っているか、または不完全である場
合、またはハイライトオプションを異なる値に設定した場合でない限り、これらのオプ
ションは使われない。                                    terminal-options

Note いくつかのキーには termcap 名がないことに注意。代わりに <> 形式の名前を使
うこと。いずれにしても、それはよい考えである。

Note "t_ti" は "t_mr" (反転/リバース出力) になり、"t_ts" は "t_ti" (端末モード
の初期化) になったことに注意。"t_ti" を使う時は注意すること!

'errorformat' オプションの変更                          errorformat-changed
----------------------------

'errorformat' には、コンマで区切って、いくつかのフォーマットを含められるように
なった。最初にマッチしたフォーマットが使われる。デフォルト値は、最も一般的な
フォーマットを捉えるように調整された。                  errorformat

コンマを含むフォーマットがある場合は、その前にバックスラッシュを置く必要があ
る。":set" コマンドが 1 つ食べてしまうので、バックスラッシュを 2 つ入力するこ
と。


'graphic' オプションの廃止                              graphic-option-gone
---------------------

'graphic' オプションは、<~> と 0xa0 の間の文字を画面上に直接表示させるために使
われていた。現在は、'isprint' オプションがはるかに多くの可能性とともにこれを扱
う。デフォルト設定は同じである。以前に vimrc で 'graphic' オプションを設定して
いた場合だけ、これを調べる必要がある。
                                                        'isprint'


'yankendofline' オプションの廃止                        ye-option-gone
---------------------------

'yankendofline' オプションは削除された。代わりに、単にこれを使える
        :map Y y$


'icon' および 'title' のデフォルト値の変更              icon-changed
----------------------------------------

'title' オプションは、現在は元のタイトルを復元できる場合にだけデフォルトで設定
される。"Thanks for flying Vim" というタイトルを避ける。それでもタイトルが欲し
い場合は、vimrc に ":set title" を書くこと。            'title'

'icon' のデフォルトは、現在は 'title' と同じように、元の値を復元できるかどうか
に依存する。アイコンタイトルが変更されるのが嫌な場合は、vimrc にこの行を追加す
ること:                                                 'icon'
        :set noicon


'highlight' オプションの変更                            highlight-changed
--------------------------

'i' フラグは、現在は反転ではなくイタリックのハイライトを意味する。'r' フラグは
リバースハイライトに使われ、これは以前の 'i' の意味である。ほとんどの端末では
イタリックモードはサポートされておらず、代替としてリバースモードが使われるの
で、通常は違いが分からないだろう。                      'highlight'

'highlight' にある場面が含まれていない場合は、リバースモードではなく、
'highlight' のデフォルト値のモードを使う。


'tildeop' および 'weirdinvert' の短縮名の変更           short-name-changed
-----------------------------------------------

'to' ('tildeop' の短縮形) を 'top' に名前変更した。     'tildeop'
'wi' ('weirdinvert' の短縮形) を 'wiv' に名前変更した。 'weirdinvert'

これは、Vi が 'wi' を 'window' の短縮名として、'to' を 'timeout' の短縮名とし
て使っているために行われた。これは、これらのオプションを設定しようとしてもエ
ラーメッセージは出ないが、効果が異なることを意味する。


ビジュアルモードでの "v"、"V"、および "CTRL-V" の使用   use-visual-cmds
-------------------------------------------

ビジュアルモードでは、以前は "v"、"V"、および "CTRL-V" はビジュアルモードを終
了させた。現在は、ビジュアルモードが対応する種類だった場合にだけそうなる。そう
でない場合は、ビジュアルモードの種類が変更される。現在、何もせずにビジュアル
モードを終了するのに、どんな状況でも使えるのは ESC だけである。 v_V


挿入モードの CTRL-B の削除                              toggle-revins
-----------------------------

挿入モードの CTRL-B は、以前は 'revins' オプションを切り替えていた。これを知ら
ずにうっかり CTRL-B を押すと、どうやって元に戻すかを見つけるのがとても難しい。
この機能を使う人はほとんどいないので、デフォルトでは無効になっている。使いたい
場合は、コンパイルする前に feature.h で RIGHTLEFT を定義すること。'revins'

 vim:tw=78:ts=8:noet:ft=help:norl:
