ヘルプファイルについてのヘルプ                          helphelp

1. ヘルプコマンド               online-help
2. 翻訳されたヘルプファイル     help-translated
3. ヘルプファイルを書く         help-writing

==============================================================================
1. ヘルプコマンド                                       online-help

                        help <Help> :h :help <F1> i_<F1> i_<Help>
<Help>          または
:h[elp]                 ウィンドウを開き、ヘルプファイルを読み込み専用モードで
                        表示する。すでにヘルプウィンドウが開いている場合は、そ
                        れを使う。そうでなく、カレントウィンドウがスクリーンの
                        全幅を使っているか、少なくとも 80 文字の幅がある場合
                        は、ヘルプウィンドウはカレントウィンドウのすぐ上に現れ
                        る。そうでない場合、新しいウィンドウは一番上に置かれ
                        る。
                        メインのヘルプファイルが複数の言語で利用できる場合、言
                        語を選択するのに 'helplang' オプションが使われる。

                                                {subject} E149 E661
:h[elp] {subject}       ":help" と同様だが、さらにタグ {subject} へジャンプす
                        る。例えば:
                                :help options

                        {subject} には "*"、"?"、"[a-z]" のようなワイルドカー
                        ドを含めることができる:
                           :help z?     任意の "z" コマンドのヘルプへジャンプする
                           :help z.     "z." のヘルプへジャンプする
                        しかし、タグが存在する場合は、文字どおりに解釈される:
                           :help :?     ":?" のヘルプへジャンプする

                        パターンに完全にマッチするものがない場合、または複数の
                        マッチがある場合は、"最善の" マッチが使われる。
                        どのマッチが他のマッチより良いかを決めるのに、洗練され
                        たアルゴリズムが使われる。計算ではこれらの項目が考慮さ
                        れる:
                        - 大文字小文字が同じマッチは、大文字小文字が異なるマッ
                          チよりもずっと良い。
                        - 英数字でない文字の後から始まるマッチは、単語の途中の
                          マッチよりも良い。
                        - タグの先頭またはその近くでのマッチは、より後ろでの
                          マッチよりも良い。
                        - マッチする英数字が多いほど良い。
                        - マッチの長さが短いほど良い。

                        {subject} が複数の言語で利用できる場合、言語を選択する
                        のに 'helplang' オプションが使われる。
                        特定の言語のタグを見つけるには、"@ab" を付け加える。
                        "ab" は 2 文字の言語コードである。help-translated を
                        参照。

                        与える {subject} が長いほど、見つかるマッチは少なくな
                        ることに注意。コマンドライン補完を使うと
                        (":help subject" の後で CTRL-D をタイプする
                        c_CTRL-D)、これがすべてどのように動作するかが分かる。
                        複数のマッチがある場合は、CTRL-D を押すとそれらを一覧
                        表示できる。例:
                                :help cont<Ctrl-D>

                        CTRL-V のヘルプを検索するのに ":help CTRL-V" とタイプ
                        する代わりに、こうタイプできる:
                                :help ^V
                        これは他の文字と組み合わせても動作する。例えば、挿入
                        モードでの CTRL-V のヘルプを見つけるには:
                                :help i^V

                        まず ":help" を実行し、その後ヘルプウィンドウで
                        ":tag {pattern}" を使うこともできる。その後、他のマッ
                        チへジャンプするのに ":tnext" コマンドが、マッチを一覧
                        表示して 1 つを選ぶのに "tselect" が使える。
                                :help index
                                :tselect /.*mode

                        引数がない場合は、すべての可能なマッチを一覧表示するの
                        を避けるため (それは非常に遅くなる)、"help" のマッチが
                        表示される。
                        表示されるマッチの数は 300 に制限されている。

                        :help コマンドの後には '|' と別のコマンドを続けるこ
                        とができるが、help コマンドの中の '|' をエスケープする
                        必要はない。そのため、これらはどちらも動作する:
                                :help |
                                :help k| only
                        '|' の前の空白は ":help" の引数の一部とみなされること
                        に注意。
                        help コマンドとそれに続くコマンドを区切るのに、<NL> や
                        <CR> を使うこともできる。<NL> や <CR> を挿入するには、
                        まず CTRL-V をタイプする必要がある。例:
                                :help so<C-V><CR>only

:h[elp]! [subject]      ":help" と同様だが、英語でないヘルプファイルでは、カレ
                        ントファイルと同じ言語のファイルにあるタグを見つけるの
                        を優先する。help-translated を参照。

                                                        :helpc :helpclose
:helpc[lose]            ヘルプウィンドウがあれば、それを 1 つ閉じる。
                        Vim は、ウィンドウレイアウト (カーソル位置を含む) を、
                        最初にヘルプウィンドウを開く前と同じレイアウトに復元し
                        ようとする。これにより、いくつかの自動コマンドがトリ
                        ガーされるかもしれない。

                                                        :helpg :helpgrep
:helpg[rep] {pattern}[@xx]
                        すべてのヘルプテキストファイルを検索し、{pattern} が
                        マッチする行のリストを作る。最初のマッチへジャンプす
                        る。省略可能な [@xx] は、"xx" 言語のマッチだけを見つけ
                        ることを指定する。
                        quickfix コマンドでマッチを移動できる。例えば、
                        :cnext で次のマッチへジャンプする。または、
                        :cwindow を使って quickfix ウィンドウにマッチのリス
                        トを表示する。
                        {pattern} は Vim の正規表現 pattern として使われる。
                        'ignorecase' は使われない。大文字小文字を無視するには
                        "\c" を追加する。大文字小文字を区別する検索の例:
                                :helpgrep Uganda
                        大文字小文字を無視する検索の例:
                                :helpgrep uganda\c
                        フランス語のヘルプで検索する例:
                                :helpgrep backspace@fr
                        パターンは改行をサポートしていない。1 行の中でマッチし
                        なければならない。代わりに :grep を使うこともできる
                        が、その場合はヘルプファイルのリストを複雑な方法で取得
                        する必要がある。
                        後に別のコマンドを続けることはできない。すべてがパター
                        ンの一部として使われる。しかし、必要なときは
                        :execute を使える。
                        圧縮されたヘルプファイルは検索されない (Fedora はヘル
                        プファイルを圧縮している)。

                                                        :lh :lhelpgrep
:lh[elpgrep] {pattern}[@xx]
                        ":helpgrep" と同じだが、quickfix リストの代わりに
                        location リストが使われる。ヘルプウィンドウがすでに開
                        いている場合は、そのウィンドウの location リストが使わ
                        れる。そうでない場合は、新しいヘルプウィンドウが開か
                        れ、そのウィンドウの location リストが設定される。その
                        とき、カレントウィンドウの location リストは変更されな
                        い。

                                                        :exu :exusage
:exu[sage]              Ex コマンドのヘルプを表示する。Nvi のコマンドを模倣す
                        るために追加された。

                                                        :viu :viusage
:viu[sage]              ノーマルモードコマンドのヘルプを表示する。Nvi のコマン
                        ドを模倣するために追加された。

:help に引数が与えられない場合は、'helpfile' オプションで指定されたファイル
が開かれる。そうでない場合は、指定されたタグが 'runtimepath' オプションで指定
されたディレクトリにあるすべての "doc/tags" ファイルから検索される。

ヘルプウィンドウの初期の高さは 'helpheight' オプションで設定できる (デフォルト
は 20)。

カレントウィンドウで {subject} のヘルプを開きたい場合は、オプションの
helpcurwin パッケージが使える。package-helpcurwin を参照。

                                                help-buffer-options
ヘルプバッファが作られるとき、ヘルプテキストが意図どおりに表示されるように、い
くつかのローカルオプションが設定される:
    'iskeyword'         ' '、'*'、'"'、'|' を除くほぼすべての ASCII 文字
    'foldmethod'        "manual"
    'tabstop'           8
    'arabic'            off
    'binary'            off
    'buflisted'         off
    'cursorbind'        off
    'diff'              off
    'foldenable'        off
    'list'              off
    'modifiable'        off
    'number'            off
    'relativenumber'    off
    'rightleft'         off
    'scrollbind'        off
    'spell'             off

タグを使って特定の項目へジャンプする。これは 2 つの方法でできる:
- コマンドやオプションの名前の上にいるときに "CTRL-]" コマンドを使う。これはタ
  グがキーワードのときにだけ動作する。"<C-Leftmouse>" と "g<LeftMouse>" は
  "CTRL-]" とまったく同じように動作する。
- ":ta {subject}" コマンドを使う。これはキーワードでない文字でも動作する。

戻るには CTRL-T か CTRL-O を使う。
ヘルプウィンドウを閉じるには ":q" を使う。

探している項目に複数のマッチがある場合は、このようにしてそれぞれにジャンプでき
る:
1. ヘルプウィンドウを開く
2. タグの前にスラッシュを付けて ":tag" コマンドを使う。例:
        :tag /min
3. ":tnext" を使って次のマッチするタグへジャンプする。

プラグインや他の項目のためのヘルプファイルを追加することができる。そのために配
布されたヘルプファイルを変更する必要はない。add-local-help を参照。

ローカルヘルプファイルを書くには、write-local-help を参照。

ローカルヘルプファイルのタイトル行は、"help.txt" ヘルプファイルの
"LOCAL ADDITIONS" セクションに自動的に追加されることに注意 local-additions。
これは Vim でファイルを表示するときに行われ、ファイル自体は変更されない。これ
は、すべてのヘルプファイルを調べて、各ファイルの最初の行を取得することで行われ
る。$VIMRUNTIME/doc 内のファイルはスキップされる。

                                                        help-xterm-window
ヘルプを別の xterm ウィンドウに表示したい場合は、このコマンドを使うことができ
る:
        :!xterm -e vim +help &


                        :helpfind :helpf
:helpf[ind]             :help と同様だが、引数を入力するのにダイアログを使
                        う。後方互換性のためだけにある。現在は、組み込みのダイ
                        アログを使う代わりに、ToolBar.FindHelp メニュー項目を
                        実行する。{+GUI_GTK 付きでコンパイルされたときのみ}

                                        :helpt :helptags
                                E150 E151 E152 E153 E154 E670
:helpt[ags] [++t] {dir}
                        ディレクトリ {dir} のヘルプタグファイルを生成する。
                        {dir} が ALL の場合は、'runtimepath' 内のすべての
                        "doc" ディレクトリが使われる。

                        ディレクトリとサブディレクトリ内のすべての "*.txt" と
                        "*.??x" ファイルが、スターで挟まれたヘルプタグの定義を
                        求めてスキャンされる。"*.??x" ファイルは翻訳されたド
                        キュメント用で、"tags-??" ファイルを生成する。
                        help-translated を参照。生成されたタグファイルはソー
                        トされる。
                        重複がある場合は、エラーメッセージが表示される。既存の
                        タグファイルは黙って上書きされる。

                        省略可能な "++t" 引数は、"help-tags" タグの追加を強制
                        する。これは {dir} が $VIMRUNTIME/doc と等しい場合にも
                        行われる。

                        ランタイムディレクトリのヘルプタグを再構築するには (そ
                        こへの書き込み権限が必要):
                                :helptags $VIMRUNTIME/doc

                :HelpToc help-TOC help-toc-install package-helptoc

ファイル内のどの位置からでも対話的な目次にアクセスしたい場合は、helptoc プラグ
インを使うことができる。このようにしてプラグインを読み込む:

    packadd helptoc

                                        HelpToc-mappings
その後、:HelpToc コマンドを使ってポップアップメニューを開くことができる。
後者は以下のノーマルコマンドをサポートしている:

        キー| 効果
        ----+---------------------------------------------------------
        c   | メインバッファのカーソル位置から最も近いエントリを選択する
        g   | 最初のエントリを選択する
        G   | 最後のエントリを選択する
        H   | 1 レベル折り畳む
        j   | 次のエントリを選択する
        J   | j と同じで、さらにメインバッファの対応する行へジャンプする
        k   | 前のエントリを選択する
        K   | k と同じで、さらにメインバッファの対応する行へジャンプする
        L   | 1 レベル展開する
        p   | 現在のエントリをコマンドラインに表示する

        P   | p と同じだが、選択が変わるたびに自動的に行う
            | 何度か押すと機能のオン/オフが切り替わる

        q   | メニューを終了する
        s   | ウィンドウを分割し、選択されたエントリへジャンプする
        z   | 現在のエントリを中央にしてメニューを再描画する
        +   | ポップアップメニューの幅を広げる
        -   | ポップアップメニューの幅を狭める
        ?   | ヘルプウィンドウを表示/非表示にする
        /   | パターンを検索する

        <C-D>      | 半ページ下へスクロールする
        <C-U>      | 半ページ上へスクロールする
        <PageUp>   | 1 ページ全体を下へスクロールする
        <PageDown> | 1 ページ全体を上へスクロールする
        <Home>     | 最初のエントリを選択する
        <End>      | 最後のエントリを選択する

このプラグインは、以下のファイルタイプのバッファでも目次を提供できる:
asciidoc、html、man、markdown、tex、vim、xhtml。さらに、端末バッファの目次も提
供し、過去に実行されたシェルコマンドをエントリとして生成する。それらを見つける
ために、デフォルトでは以下のパターンが使われる:

        ^\w\+@\w\+:\f\+\$\s

これはデフォルトの bash プロンプトにマッチすることを意図している。プロンプトに
マッチしない場合は、g:helptoc 辞書変数の shell_prompt キーで正規表現を変更
できる:

        let g:helptoc = {'shell_prompt': 'regexp matching your shell prompt'}

Tip: / コマンドで探すパターンを入力した後、<CR> の代わりに <Esc> を押すと、
J や K を押して残りの各エントリのより多くの文脈を得ることができる。

helptoc についての詳細、特にヘルプ以外のファイルタイプでの使い方と、オプション
の設定については、helptoc.txt を参照。
Note: helptoc.txt へジャンプできるようにするには、先に packadd helptoc す
る必要がある。

2. 翻訳されたヘルプファイル                             help-translated

元の英語のヘルプファイルの隣に、翻訳されたヘルプファイルを追加することができ
る。Vim は 'runtimepath' 内の "doc" ディレクトリにあるすべてのヘルプを検索す
る。これは +multi_lang 機能付きでコンパイルされたときのみ利用できる。

現時点では、以下の翻訳が利用できる:
        Chinese  - 複数の作者
        French   - David Blanchet による翻訳
        Italian  - Antonio Colombo による翻訳
        Japanese - 複数の作者
        Polish   - Mikolaj Machowski による翻訳
        Russian  - Vassily Ragosin による翻訳
        Swedish  - Daniel Nylander による翻訳
Vim のウェブサイトでそれらを見つけられる: http://www.vim.org/translations.php

翻訳されたヘルプファイルのセットは、これらのファイルからなる:

        help.abx
        howto.abx
        ...
        tags-ab

"ab" は 2 文字の言語コードである。したがって、イタリア語の場合の名前は:

        help.itx
        howto.itx
        ...
        tags-it

'helplang' オプションには、優先する言語 (複数可) を設定できる。デフォルトは環
境に従って設定される。Vim はまず、優先する言語でマッチするタグを見つけようとす
る。見つからない場合は英語が使われる。

特定の言語のタグを見つけるには、タグに "@ab" を付け加える。"ab" は 2 文字の言
語コードである。例:
        :he user-manual@it
        :he user-manual@en
1 つ目は、'helplang' が空の場合でも、イタリア語のユーザーマニュアルを見つける。
2 つ目は、'helplang' が "it" に設定されている場合でも、英語のユーザーマニュア
ルを見つける。

":help" コマンドでコマンドライン補完を使う場合、"@en" 拡張子は、タグが複数の言
語に存在するときにだけ表示される。タグが英語にだけ存在する場合は "@en" は省略
される。最初の候補が "@ab" 拡張子を持ち、それが 'helplang' の最初の言語にマッ
チする場合も "@ab" は省略される。

英語でないヘルプファイルで CTRL-] や ":help!" を使うと、Vim は同じ言語でタグ
を見つけようとする。見つからない場合は、言語を選択するのに 'helplang' が使われ
る。

ヘルプファイルは latin1 か utf-8 エンコーディングを使わなければならない。Vim
は、最初の行に非 ASCII 文字を見つけると、エンコーディングが utf-8 であるとみな
す。したがって、"For Vim version" があるヘッダーを翻訳しなければならない。

1 つのディレクトリにある 1 つの言語のヘルプファイルには、同じエンコーディング
を使わなければならない。異なる言語には異なるエンコーディングを使うことができ、
同じ言語でも異なるディレクトリにあるヘルプファイルには異なるエンコーディングを
使うことができる。

翻訳者向けのヒント:
- タグは翻訳しないこと。これにより、'helplang' を使って優先する言語を指定でき
  るようになる。自分の言語で新しいタグを追加してもよい。
- ファイルの一部を翻訳しない場合は、"tag@en" 表記を使って、英語版へのタグを追
  加すること。
- すべてのファイルとタグファイルを含むパッケージを作り、ダウンロードできるよう
  にすること。ユーザーはそれを "doc" ディレクトリの 1 つに置いて使い始めること
  ができる。
  開発チームに報告すること。そうすれば、www.vim.org にリンクを追加できる。
- :helptags コマンドを使ってタグファイルを生成すること。これは指定されたディ
  レクトリ内のすべての言語を見つける。

3. ヘルプファイルを書く                                 help-writing

使いやすさのために、プラグインの Vim ヘルプファイルは、最初の行を除いて、標準
の Vim ヘルプファイルの書式に従うべきである。新しいヘルプファイルを書く場合は、
既存のファイルの 1 つをコピーしてテンプレートとして使うのが最善である。

Vim のヘルプファイルは、一般に文の後に 2 つの空白を使う (固定幅フォントを使っ
て書かれており、それが 70 年代/80 年代に好まれたスタイルだったため)。ここで説
明されているように: https://english.stackexchange.com/a/2602

ヘルプファイルの最初の行は、以下の書式であるべきである:

plugin_name.txt       {プラグインの短い説明}

最初のフィールドは、":help plugin_name" でジャンプする先のヘルプタグである。行
の残りの部分は、タブの後に、プラグインの目的を短く記述する。これはメインのヘル
プファイルの "LOCAL ADDITIONS" セクションに表示される。それがそこで正しく表示
されることを確認すること: local-additions。

バージョン番号や最終更新日を追加したい場合は、2 行目に右寄せで置くこと。

ヘルプファイルの最後に、'textwidth' と 'tabstop' オプション、そして 'filetype'
を "help" に設定する Vim のモードラインを置くこと。そのようなモードラインでグ
ローバルオプションを設定してはならない。望ましくない結果を招くことがある。


スタイル

Vim で 'modeline' が有効になっている場合、組み込みのヘルプファイルを編集すると
き、Vim は自動的に推奨スタイルに従うはずである。

Vim のヘルプファイルは、典型的な 80 x 24 の端末ウィンドウで見栄えが良いように、
'textwidth' が 78 文字になるように整形されるべきである。視覚的なガイドとして
:set colorcolumn=+0 を使うこと。

文の最後のピリオドと、次の文の最初の文字の間には、2 つの空白を使う。このよう
に。

内容をそろえるにはタブ文字を使い、'tabstop' の設定は 8 にする。
これはファイルサイズを減らすのにも役立つ。

編集を終えたら、必ず :retab を使うこと。:retab! をむやみに使わず、望まない
変更を避けるため、何が変更されるかを常に確認すること。


タグ

ヘルプタグを定義するには、名前をアスタリスクで挟む ("*tag-name*")。tag-name
は、すべての Vim ヘルプタグ名と異なっているべきで、理想的には Vim プラグインの
名前で始まるべきである。タグ名は通常、行の右に寄せる。

既存のヘルプタグを参照し、ホットリンクを作るには、名前を 2 つのバー (|) で挟
む。例: help-writing。

Vim のコマンドを参照し、ホットリンクを作るには、名前を 2 つのバッククォートで
挟む。例: :filetype のように内側に置く。これがコードブロックのようにコマンド
としてハイライトされるのが分かるだろう (下を参照)。

ヘルプファイル内で Vim のオプションを参照するときは、オプション名を 2 つのシン
グルクォートで挟む。例: 'statusline'


ハイライト

列見出しを定義するには、行末にチルダ文字を使う。
これにより列見出しが別の色でハイライトされる。例:

列見出し

ヘルプファイル内のセクションを区切るには、1 列目から始まる行に一連の '=' 文字
を置く。セクション区切りの行は別の方法でハイライトされる。

Ex コマンドのブロックをそのまま引用するには、ブロックの前の行の末尾に大なり (>)
文字を置き、ブロックの後に続く行の最初の非空白文字として小なり (<) 文字を置く。
1 列目から始まる行も、その前の Ex コマンドのブロックを暗黙的に終了させる。例:


        function Example_Func()
          echo "Example"
        endfunction

コードのブロックで構文ハイライトを有効にするには、大なり (>) 文字の後に言語名
の注釈 (例: "vim") を置く。例:

        function Example_Func()
          echo "Example"
        endfunction

                                                g:help_example_languages
デフォルトでは、ヘルプファイルは Vim script のハイライトだけをサポートしてい
る。他の言語の構文ハイライトが必要な場合は、vimrc に追加する:
        :let g:help_example_languages = #{
              \ vim: "vim", vim9: "vim", vim9mix: "vim9", bash: "sh" }
キーは注釈マーカーの名前を表し、値は 'syntax' の名前である。

Note: "g:help_example_languages" に "vim" を含めない場合、その構文ハイライトは
有効にならない。"g:help_example_languages" を空の値に設定すると、埋め込まれた
言語の構文ハイライトは無効になる。

さらに注意: 含まれる 'syntax' スクリプトがそのような取り込みを考慮していない場
合、ヘルプファイルに任意の構文言語を含めることは、常に完璧に動作するとは限らな
い。
                                                help-notation
Vim のヘルプファイルでは、以下のものが異なる方法でハイライトされる:
  - <PageDown> のような <> 表記か、CTRL-X のような Ctrl 文字のどちらかで表され
    た特殊キー名
  - {braces} の間にあるすべてのもの。例: {lhs} と {rhs}

"Note"、"Notes" などの語は、自動的に独特のハイライトを受ける。これらも同様であ
る:
        *Todo   something to do
        *Error  something wrong

詳細は $VIMRUNTIME/syntax/help.vim で見つけられる


ファイルタイプ補完                                     ft-help-omni

タグ参照を書くときにヘルプタグの補完を得るには、i_CTRL-X_CTRL-O コマンドを使
うことができる。


性別中立な言語
                                                gender-neutral inclusion
Vim は、人種、性別、その他何であれ、すべての人のためのものである。新規または更
新されたヘルプテキストには、性別中立な言語が推奨される。ヘルプテキストの一部は
何年も前のもので、それを変更する必要はない。テキストがどのように表現されていて
も、我々はユーザーの性別について何も仮定しない。目標は読者が Vim がどのように
動作するかを理解することであり、正確な言い回しは二の次である。

多くのオンラインの技術スタイルガイドには、性別中立な言語についてのセクションが
ある。ここにいくつかを挙げる:

        https://developers.google.com/style/pronouns
        https://techwhirl.com/gender-neutral-technical-writing/
        https://www.skillsyouneed.com/write/gender-neutral-language.html
        https://ualr.edu/writingcenter/avoid-sexist-language/

Note: 性別中立な言語は、単数の "they" を使うことを必要としない。
