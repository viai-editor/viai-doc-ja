クラッシュ後のリカバリー                                crash-recovery

翌朝までに仕上げなければならないそのテキストのタイプに数時間を費やしてきたとこ
ろで、災難が襲う: コンピュータがクラッシュする。

                        慌てるな!

Vim がファイルの内容を保存するために使うファイルから、変更のほとんどを回復でき
る。たいていは 1 つのコマンドで作業を回復できる:
        vim -r filename

1. スワップファイル     swap-file
2. リカバリー           recovery

==============================================================================
1. スワップファイル                                     swap-file

Vim は変更したものをスワップファイルに保存する。開始時の元のファイルに加えてス
ワップファイルを使うことで、たいていは作業を回復できる。

使われている現在のスワップファイルの名前は、このコマンドで確認できる:

        :sw[apname]                                     :sw :swapname

または swapname() 関数を使うこともでき、これは他のバッファのスワップファイル
名を確認することもできる。

スワップファイルの名前は通常、編集しているファイルと同じで、拡張子が ".swp" に
なる。
- Unix では、編集されたファイルと同じディレクトリにあるスワップファイルの名前
  の前に '.' が付けられる。これにより、スワップファイルがディレクトリ一覧に表
  示されることが避けられる。
- MS-Windows マシンの場合、および 'shortname' オプションがオンの場合、元のファ
  イル名の中の '.' はすべて '_' に置き換えられる。
- このファイルが既に存在する場合 (例えば、クラッシュから回復しているとき)、警
  告が出され、別の拡張子 ".swo"、".swn" などが使われる。
- 既存のファイルが上書きされることは決してない。
- スワップファイルは、Vim がそのファイルの編集をやめるとすぐに削除される。

技術情報:  '.' から '_' への置き換えは、MS-DOS 互換のファイルシステム (例えば、
           crossdos、multidos) での問題を避けるために行われる。ファイルが
           MS-DOS 風のファイルシステム上にあることを Vim が検出できた場合、
           'shortname' オプションと同じ効果を持つフラグが設定される。このフラ
           グは別のファイルの編集を始めるとリセットされる。
                                                        E326
           ".swp" のファイル名が既に存在する場合、その名前のファイルが無くなる
           か、または ".saa" に達するまで、最後の文字が減らされる。最後の場合、
           スワップファイルは作成されない。

'directory' オプションを設定することで、スワップファイルを、編集されたファイル
がある場所とは別の場所に置くことができる。
利点:
- ディレクトリを ".swp" ファイルで汚さない。
- 'directory' が別のパーティションにある場合、(クラッシュ時に) ファイルがある
  ファイルシステムを損傷させる危険を減らす。
欠点:
- 同じ名前だが異なるディレクトリにあるファイルから、名前衝突が起こることがある
  (Vim はパス名を比較することでそれを避けようとするが)。これにより偽の
  ATTENTION 警告メッセージが出る。
- ホームディレクトリを使っていて、他の誰かが同じファイルを編集しようとした場
  合、そのユーザーにはあなたのスワップファイルが見えず、ATTENTION 警告メッセー
  ジも出ない。
Amiga では回復可能な ram ディスクも使えるが、これが動作する 100% の保証はない。
通常の ram ディスク (Amiga の RAM: など) または再起動時に消去される場所 (Unix
の /tmp など) にスワップファイルを置くことは意味がなく、クラッシュ時にスワップ
ファイルを失う。

スワップファイルを固定の場所に置きたい場合は、以下のようなコマンドを .vimrc に
書く:
        :set dir=dh2:tmp        (Amiga 用)
        :set dir=~/tmp          (Unix 用)
        :set dir=c:\\tmp        (Win32 用)
これはフロッピー上のファイルを編集するときにもとても便利である。もちろん、これ
が動作するには、その "tmp" ディレクトリを作成する必要がある!

読み込み専用ファイルでは、スワップファイルは使われない。ファイルが大きく、使わ
れるメモリの量が 'maxmem' または 'maxmemtot' で指定された量より多くなる場合を
除く。そして、読み込み専用ファイルに変更を加えるときは、いずれにしてもスワップ
ファイルが作成される。

スワップファイルの作成を避けるために、'swapfile' オプションをリセットできる。
そして、新しいバッファにスワップファイルを作成しないために、:noswapfile 修飾
子を使える。

:nos[wapfile]   {command}                       :nos :noswapfile
                {command} を実行する。それが新しいバッファを読み込むコマンドを
                含む場合、そのバッファはスワップファイルを作成せずに読み込ま
                れ、'swapfile' オプションはリセットされる。バッファが既にスワッ
                プファイルを持っていた場合、それは削除されず、'swapfile' はリ
                セットされない。

スワップファイルの更新

スワップファイルは、200 文字タイプした後、または 4 秒間何もタイプしなかったと
きに更新される。これはバッファが変更された場合にだけ起こり、移動しただけのとき
は起こらない。常に最新の状態に保たない理由は、そうすると通常の作業が遅くなりす
ぎるからである。200 文字の数は 'updatecount' オプションで変更できる。時間は
'updatetime' オプションで設定できる。時間はミリ秒で指定する。スワップファイル
に書き込んだ後、Vim はファイルをディスクに同期させる。これには、特に忙しい
Unix システムでは、いくらか時間がかかる。これを望まない場合は、'swapsync' オプ
ションに空文字列を設定できる。ただし、作業を失う危険は大きくなる。一部の Unix
以外のシステム (MS-Windows、Amiga) では、スワップファイルはまったく書き込まれ
ない。

スワップファイルへの書き込みが望まれない場合は、'updatecount' オプションを 0
に設定することでオフにできる。"-n" オプションを付けて Vim を起動したときも同じ
ことが行われる。書き込みは 'updatecount' オプションを 0 以外に設定することで再
びオンにできる。こうすると、すべてのバッファに対してスワップファイルが作成され
る。しかし、'updatecount' を 0 に設定したとき、既存のスワップファイルは削除さ
れず、この後に開かれるファイルにだけ影響する。

変更がスワップファイルに入っていることを確かめたい場合は、このコマンドを使う:

                                        :pre :preserve E313 E314
:pre[serve]             カレントバッファのすべてのテキストをそのスワップファイ
                        ルに書き込む。元のファイルは回復にはもう必要ない。これ
                        はカレントバッファにフラグを設定する。'cpoptions' に
                        '&' フラグが含まれている場合、Vim が終了するときにバッ
                        ファがまだ読み込まれていると、このバッファのスワップ
                        ファイルは削除されない cpo-&。

Vim のスワップファイルは最初の 6 文字で識別できる: "b0VIM "。その後にバージョ
ン番号、例えば、"3.0" が来る。


リンクとシンボリックリンク

Unix では、同じファイルに 2 つの名前を持たせることができる。これはハードリンク
およびシンボリックリンク (symlink) で行える。

ハードリンクの場合、Vim はそのファイルの別の名前を知らない。そのため、スワップ
ファイルの名前は、ファイルを編集するのに使った名前に基づく。別の名前でも同じ
ファイルを編集していないかのチェックは行われない。Vim は別のスワップファイルを
見つけられないからである (ハードディスク全体を検索する場合を除く。それはとても
遅いだろう)。

シンボリックリンクの場合、Vim はリンクを解決して実際のファイルの名前を見つけ
る。スワップファイル名はその名前に基づく。したがって、どの名前でファイルを編集
しても、スワップファイル名は通常同じになる。ただし、例外がある:
- 実際のファイルのディレクトリが書き込み可能でない場合、スワップファイルは別の
  場所に置かれる。
- シンボリックリンクが何らかの形でループを作っている場合は E773 エラーメッ
  セージが出て、変更されていないファイル名が使われる。ファイルを通常どおり保存
  することはできない。

2. リカバリー                                   recovery E308 E311

基本的なファイルリカバリーはユーザーマニュアルで説明されている: usr_11.txt。

リカバリーを行う別の方法は、Vim を起動して ":recover" コマンドを使うことであ
る。これは、ファイルを編集するために Vim を起動して
"ATTENTION: Found a swap file ..." メッセージが出たときに簡単である。この場合、
":recover" という 1 つのコマンドで済む。recover コマンドには、ファイルの名前ま
たはスワップファイルの名前を与えることもできる:
                                        :rec :recover E305 E306 E307
:rec[over] [file]       スワップファイルから [file] の回復を試みる。[file] が
                        与えられていない場合は、カレントバッファのファイル名を
                        使う。バッファの現在の内容は失われる。バッファが変更さ
                        れていた場合、このコマンドは失敗する。

:rec[over]! [file]      ":recover" と同様だが、カレントバッファの変更はすべて
                        失われる。

                                                E312 E309 E310 E1364
Vim は、スワップファイルが何らかの形で壊れている場合にどうするかについて、ある
程度の知能を持っている。見つけたものに Vim が疑いを持った場合、エラーメッセー
ジを出し、テキストに "???" を含む行を挿入する。回復中にエラーメッセージが出た
ら、ファイル内で "???" を検索して、何がおかしいのかを確認する。必要なテキスト
を得るために、カットアンドペーストしたくなるかもしれない。

最もよくある注記は "???LINES MISSING" である。これは、Vim が元のファイルからテ
キストを読み込めないことを意味する。これは、システムがクラッシュして、元のファ
イルの一部がディスクに書き込まれなかった場合に起こりうる。

元のファイルを上書きするか、またはスワップファイルを削除する前に、リカバリーが
成功したことを確かめること。回復したファイルを別の場所に書き込み、'diff' を実
行して、望む変更が回復したファイルに入っているかを調べるのがよい習慣である。ま
たは :DiffOrig を使う。

リカバリーが問題ないと確信したら、スワップファイルを削除する。そうしないと、
".swp" ファイルが既に存在するという警告メッセージが出続ける。

Note: スワップファイルの回復はベストエフォートである。Vim はフィールドを検証
し、壊れた部分を飛ばそうとするが、スワップファイルの形式は信頼できるファイルの
ためのものである。細工されたスワップファイルはパーサーのバグを引き起こすことが
ある。そのような報告は、セキュリティ脆弱性ではなく、堅牢性問題として扱われる。


暗号化とスワップファイル                               :recover-crypt

テキストファイルが暗号化されている場合、スワップファイルも暗号化される。これに
よりリカバリーは少し複雑になる。スワップファイルから回復するときに暗号化が使わ
れていた場合、1 つまたは 2 つの暗号キーを入力するように求められる。

テキストファイルが存在しない場合は、スワップファイルの暗号キーの入力だけを求め
られる。

テキストファイルが存在する場合、それはスワップファイルとは異なる方法で暗号化さ
れているかもしれない。暗号キーを 2 回尋ねられる:

        Need encryption key for "/tmp/tt"
        Enter encryption key: ******
        "/tmp/tt" [crypted] 23200L, 522129C
        Using swap file "/tmp/.tt.swp"
        Original file "/tmp/tt"
        Swap file is encrypted: "/tmp/.tt.swp"
        If you entered a new crypt key but did not write the text file,
        enter the new crypt key.
        If you wrote the text file after changing the crypt key press enter
        to use the same key for text file and swap file
        Enter encryption key: 

これら 2 つの状況のどちらかにありうる:

1. 暗号化キーが変更されなかったか、またはキーを変更した後にテキストファイルが
   書き込まれた。暗号キーの入力を 2 回促される。2 回目は単に Enter を押せばよ
   い。これは、テキストファイルおよびスワップファイルに同じキーが使われること
   を意味する。
2. 新しい暗号化キーを入力したが、テキストファイルを保存しなかった。そのとき
   Vim はスワップファイルに新しいキーを使い、テキストファイルは古いキーで暗号
   化されたままになる。2 回目のプロンプトで新しいキーを入力する。

Note リカバリーの後、スワップファイルのキーがテキストファイルに使われることに
注意。したがって、テキストファイルを書き込む場合は、その新しいキーを使う必要が
ある。
