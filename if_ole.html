1. 起動                                                 ole-activation

Vim は OLE オートメーションサーバーとして動作し、どのオートメーションクライア
ント、例えば Visual Basic、Python、または Perl からでもアクセスできる。Vim の
アプリケーションの "名前" (OLE の用語では "ProgID") は "ViAI.Application" であ
る。

したがって、Vim のインスタンスを起動する (または、すでに起動しているインスタン
スに接続する) には、以下のようなコードを使えばよい:

[Visual Basic]
        Dim Vim As Object
        Set Vim = CreateObject("ViAI.Application")

[Python]
        from win32com.client.dynamic import Dispatch
        vim = Dispatch('ViAI.Application')

[Perl]
        use Win32::OLE;
        $vim = new Win32::OLE 'ViAI.Application';

[C#]
        // プロジェクトに Vim への参照を追加する。
        // COM タブを選ぶ。
        // "ViAI OLE Interface 1.1 Type Library" を選択する
        ViAI.ViAI vimobj = new ViAI.ViAI();

Vim は、他の一部の OLE オートメーションサーバーのような "hidden" の OLE サー
バーとしての動作をサポートしていない。クライアントが Vim のインスタンスを起動
すると、そのインスタンスはすぐに見える状態になる。Vim のインスタンスへの OLE
接続を閉じるだけでは、Vim のインスタンスを終了させるには足りない - 明示的に終
了のコマンド (例えば :qa!、:wqa) を実行する必要がある。

2. メソッド                                             ole-methods

Vim はクライアントが使うための 4 つのメソッドを公開している。

                                                        ole-sendkeys
SendKeys(keys)          キーの並びを実行する。

このメソッドは 1 つの引数を取り、それはキーストロークの文字列である。これらの
キーストロークは、キーボードから打ち込まれたのとまったく同じように実行される。
特殊キーは、マッピングの右辺と同様に、<..> の名前で指定できる。Note: Ex の
"normal" コマンドの実行はサポートされていない - 以下の ole-normal を参照。

例 (Visual Basic の構文)
        Vim.SendKeys "ihello<Esc>"
        Vim.SendKeys "ma1GV4jy`a"

これらの例は、Vim がノーマルモードで始まることを前提にしている。ノーマルモード
にするには、以下のようにキーシーケンスを CTRL-\ CTRL-N で始める

        Vim.SendKeys "<C-\><C-N>ihello<Esc>"

CTRL-\ CTRL-N は、挿入モードまたはコマンドラインモードのときに、Vim をノーマル
モードに戻す。Note これは Vim のコマンドの途中では動作しないことに注意

                                                        ole-eval
Eval(expr)              式を評価する。

このメソッドは 1 つの引数を取り、それは Vim の通常の形式の式である
(expression を参照)。戻り値は文字列で、式を評価した結果である。List は、要
素を連結し改行を挿入して、文字列に変換される。

例 (Visual Basic の構文)
        Line20 = Vim.Eval("getline(20)")
        Twelve = Vim.Eval("6 + 6")              ' Note これは STRING であることに注意
        Font = Vim.Eval("&guifont")

                                                        ole-setforeground
SetForeground()         Vim のウィンドウを前面に出す

このメソッドは引数を取らない。値は返さない。

例 (Visual Basic の構文)
        Vim.SetForeground


                                                        ole-gethwnd
GetHwnd()               Vim のウィンドウのハンドルを返す。

このメソッドは引数を取らない。Vim のメインウィンドウの hwnd を返す。Vim のウィ
ンドウを操作するか、または z オーダーでそれを追跡する必要があるものなどを書い
ているときに、これを使える。

例 (Visual Basic の構文)
        Vim_Hwnd = Vim.GetHwnd

3. "normal" コマンド                                    ole-normal

Vim が OLE オートメーションのコマンドを処理する方法と、Ex コマンド :normal の
実装方法の組み合わせにより、OLE オートメーションから :normal コマンドを実行す
ることはできない。実行しようとすると失敗する。おそらく害はないが、予測できない
形で失敗するかもしれない。

現在、この状況を捕捉する実用的な方法は無く、ユーザーはこの制限を知っておくしか
ない。

4. 登録                                         ole-registration E243

Vim が OLE サーバーとして動作するには、その前にシステムレジストリに登録されて
いなければならない。これを行うには、Vim を "-register" という 1 つの引数で実行
すればよい。
                                                        -register 
        gviai -register

OLE サポート付きの gviai を実行し、ViAI の OLE サーバーが登録されていないこと
を検出すると、ダイアログを表示し、"Yes" をクリックして登録するかを選べるように
する。

登録できない状況もある。これはレジストリが書き込み可能でない場合に起こる。この
問題に遭遇したら、gviai を "Administrator" として実行する必要がある。

いったん vim が登録されると、アプリケーションパスはレジストリに保存される。Vim
を移動、削除、またはアップグレードする前に、"-unregister" スイッチを使ってレジ
ストリ項目を削除するべきである。
                                                        -unregister 
        gviai -unregister

OLE の仕組みは、最初に見つけた登録済みの Vim を使う。Vim がすでに実行中の場合
は、それが使われる。OLE コマンドに反応してはいけない Vim のセッションを (いく
つか) 開いておきたい場合は、非 OLE 版を使い、それを別のディレクトリに置くこと。
そして OLE 版は通常のパスに入っていないディレクトリに置き、"gviai" とタイプす
ると非 OLE 版が起動するようにすること。

                                                        -silent
結果を報告するためにポップアップするメッセージボックスを避けるには、"-silent"
を前に付ける:

        gviai -silent -register
        gviai -silent -unregister

5. MS Visual Studio との統合                            MSVisualStudio

古い "VisVim" との統合は、パッチ 9.0.0698 で Vim から削除された。


Vim を Visual Studio .Net で使う

.Net studio は外部エディタをサポートしている。これらの指示に従うこと:

.Net Studio で、メニューから Tools->External Tools... を選ぶ
追加する
     Title     - Vim
     Command   - c:\viai\viai10\gviai.exe
     Arguments - --servername VS_NET --remote-silent "+call cursor($(CurLine), $(CurCol))" $(ItemPath)
     Init Dir  - Empty

これで、.Net でファイルを開くときに、.Net のメニューから選べる:
Tools->Vim

これで、そのファイルが Vim で開かれる。
その後、この外部コマンドをアイコンとして追加し、好きな場所に置ける。これをデ
フォルトエディタに設定することもできるかもしれない。

これをさらに改良したら、記録が残るように、Vim のメーリングリストに投稿していた
だきたい。

--servername VS_NET
これは VS_NET という名前の vim の新しいインスタンスを作る。そのため、VS から複
数のファイルを開いても、それらは同じ Vim のインスタンスを使う。これにより、複
数の Vim のコピーを実行できるが、どれが VS のファイルを持つかは制御できる。

--remote-silent "+call cursor(10, 27)"
              - カーソルを 10 行目の 27 桁目に置く
Vim の中で
   :h --remote-silent で詳細を参照

[.Net の記述は Dave Fishburn および Brian Sturk によって提供された]
