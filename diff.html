1. 差分モードを開始する                                 start-vimdiff

差分モードで編集を開始する最も簡単な方法は "vimdiff" コマンドを使うことである。
これは通常どおり Vim を起動し、さらに引数の間の差分を表示するための設定を行う。


        vimdiff file1 file2 [file3 [file4]]

これは以下と同等である:

        vim -d file1 file2 [file3 [file4]]

"gvimdiff" または "vim -d -g" を使うこともできる。そのときは GUI が起動される。
"viewdiff" または "gviewdiff" を使うこともできる。そのときは Vim は読み取り専
用モードで起動する。制限モードのために "r" を前に付けてもよい (-Z を参照)。

2 番目および以下の引数はディレクトリ名でもよい。そのときは Vim は、ファイルを
見つけるために、最初の引数のファイル名をディレクトリ名に付け足す。

既定では内部 diff ライブラリが使われる。'diffopt' または 'diffexpr' が設定され
ているときは、外部の "diff" コマンドが使われる。これはそのような diff プログラ
ムが使用可能なときにだけ機能する。

差分はカレントタブページ tab-page にローカルである。別のタブページにあるウィ
ンドウとの差分を見ることはできない。これにより、それぞれが独自のタブページにあ
る、複数の差分を同時に持つことが可能になる。

何が起こるかというと、Vim はファイルごとにウィンドウを開く。これは -O 引数を
使うのと同様である。これは垂直分割を使う。水平分割の方が好みの場合、-o 引数
を追加する:

        vimdiff -o file1 file2 [file3 [file4]]

常に水平分割の方が好みの場合、'diffopt' に "horizontal" を含める。

編集される各ファイルでは、これらのオプションが設定される:

        'diff'          on
        'scrollbind'    on
        'cursorbind'    on
        'scrollopt'     "hor" を含む
        'wrap'          off、または 'diffopt' が "followwrap" を含む場合、そのままにする
        'foldmethod'    "diff"
        'foldcolumn'    'diffopt' からの値、既定は 2

これらのオプションはウィンドウにローカルに設定される。別のファイルを編集すると
きは、それらはグローバル値にリセットされる。
ファイルを再編集するとき、オプションは依然としてモードラインから上書きできる。
しかし、'diff' が設定されているときは、'foldmethod' および 'wrap' はモードライ
ンから設定されない。
オプションを元に戻す簡単な方法については :diffoff を参照。

表示される差分は、実際にはバッファ内の差分である。したがって、ファイルを読み込
んだ後で変更を加えた場合、それらは表示される差分に含まれる。時々 ":diffupdate"
を行う必要があるかもしれない、すべての変更がすぐに考慮されるわけではない、特に
外部の diff コマンドを使っているときは。

あなたの .vimrc ファイルで、Vim が差分モードで起動されたときに何か特別なことを
行うことができる。このような構文を使うことができる:

        if &diff
           差分モード用の設定
        else
           非差分モード用の設定
        endif

すでに Vim の中にいるときは、3 つの方法で差分モードを開始できる。

                                                        E98
:diffs[plit] {filename}                                 :diffs :diffsplit
                ファイル {filename} に対して新しいウィンドウを開く。カレント
                ウィンドウおよび新しく開かれたウィンドウに対して、"vimdiff" と
                同様にオプションが設定される。'diffexpr' も参照。

                                                        :difft :diffthis
:difft[his]     カレントウィンドウを差分ウィンドウの一部にする。これは
                "vimdiff" と同様にオプションを設定する。

:diffp[atch] {patchfile}                         E816 :diffp :diffpatch
                カレントバッファを使い、{patchfile} 内で見つかった diff でそれ
                にパッチを当て、その結果に対してバッファを開く。オプションは
                "vimdiff" と同様に設定される。
                {patchfile} は、"patch" プログラムが理解するか、または
                'patchexpr' が扱える任意の形式でよい。
                Note {patchfile} は 1 つのファイル、カレントファイルに対する
                diff だけを含むべきであることに注意。{patchfile} が他のファイ
                ルに対する diff も含んでいる場合、結果は予測できない。Vim は、
                カレントディレクトリ内のファイルに誤ってパッチが当てられるのを
                避けるために、ディレクトリを /tmp に変更する。しかし、それでも
                さまざまな ".rej" ファイルが作成される結果になるかもしれない。
                そして、絶対パス名が存在するときは、これらのファイルはいずれに
                せよパッチを当てられるかもしれない。
                restricted-mode では "patch" コマンドを使うことは許可されて
                いない。

これらのコマンドで垂直分割を使うようにするには、:vertical を前に付ける。例:


        :vert diffsplit main.c~
        :vert diffpatch /tmp/diff

常に垂直分割の方が好みの場合、'diffopt' に "vertical" を含める。

                                                        E96
'diff' が設定されたバッファは 8 個まで存在できる。

オプションの値はバッファと共に記憶されるので、別のファイルを少しの間編集し、同
じファイルに戻ってきて、再び差分モードになることができる。

                                                        :diffo :diffoff
:diffo[ff]      カレントウィンドウの差分モードをオフにする。'diff' が設定され
                ていなかったときも、関連するオプションをリセットする。

:diffo[ff]!     カレントウィンドウ、およびカレントタブページ内の 'diff' が設定
                されているすべてのウィンドウで、差分モードをオフにする。関連す
                るオプションのリセットは 'diff' が設定されているウィンドウでだ
                け行われ、カレントウィンドウに 'diff' が設定されていない場合、
                その中のオプションは何も変更されない。
                隠しバッファも、diff されたバッファのリストから削除される。

:diffoff コマンドは、関連するオプションを、:diffsplit、:diffpatch、
:diffthis を使ったとき、または Vim を差分モードで起動したときに持っていた値
にリセットする。:diffoff を 2 回使うときは、最後に保存された値が復元される。
それ以外の場合、それらは既定値に設定される:

        'diff'          off
        'scrollbind'    off
        'cursorbind'    off
        'scrollopt'     "hor" なし
        'wrap'          on、または 'diffopt' が "followwrap" を含む場合、そのままにする
        'foldmethod'    "manual"
        'foldcolumn'    0

'foldenable' はおそらくオフにリセットされる。それは 'foldmethod' が "manual"
に復元されるときである。折り畳み自体はクリアされないが、それらは表示されるべき
ではない、'foldenable' をリセットするのがそれを行う最善の方法である。

2. 差分を表示する                                               view-diffs

その効果は、差分ウィンドウが同じテキストを、差分をハイライトして表示することで
ある。テキストをスクロールするとき、'scrollbind' オプションにより他のウィンド
ウのテキストも同様にスクロールされる。垂直分割では、テキストは正しく揃えられる
はずである。

テキストの位置揃えは、以下のときに狂う:
- 'wrap' がオンで、いくつかの行が折り返されて 2 行以上の画面行を占める
- 折り畳みが一方のウィンドウでは開いているが、別のウィンドウでは開いていない
- 'scrollbind' がオフである
- テキストに変更が加えられた
- 'diffopt' に "filler" が含まれておらず、削除/挿入された行が位置揃えを狂わせ
  る

'diff' オプションが設定されたウィンドウで編集されたすべてのバッファが、差分に
参加する。これは隠しバッファでも可能である。これが可能になるためには、それらが
最初にウィンドウで編集されていなければならない。隠しバッファを取り除くには
:diffoff! を使う。

                                        :DiffOrig diff-original-file
'diff' はウィンドウローカルなオプションなので、同じバッファを、あるウィンドウ
では差分モードで、別のウィンドウでは "normal" で表示することが可能である。ファ
イルが読み込まれてからバッファに加えた変更を表示することも可能である。Vim は同
じファイルに対して 2 つのバッファを持つことを許さないので、別のバッファが必要
である。このコマンドが便利である:
         command DiffOrig vert new | set bt=nofile | r ++edit # | 0d_
                \ | diffthis | wincmd p | diffthis
(これは defaults.vim にある)。カレントバッファと、それが読み込まれたファイル
の間の差分を見るには、":DiffOrig" を使う。

アンロードされたバッファは差分に使えない。しかし、隠しバッファでは機能する。
":hide" を使うと、バッファをアンロードせずにウィンドウを閉じることができる。
バッファを差分に使われたままにしたくない場合、それを隠す前に ":set nodiff" を
行う。

                                                :dif :diff :diffupdate
:dif[fupdate][!]                差分のハイライトおよび折り畳みを更新する。

テキストに変更を加えたとき、Vim は差分を更新された状態に保とうとする。これは主
に、挿入および削除された行を処理する。行内の変更およびより複雑な変更では、差分
は更新されない。差分を強制的に更新するには、以下を使う:

        :diffupdate

! が含まれている場合、Vim はファイルが外部で変更されていて、再読み込みが必要か
どうかをチェックする。:checktime が使われたときのように、変更されたファイル
ごとに確認を求める。

Vim は、一方のウィンドウには存在しないが別のウィンドウには存在する行に対して、
フィラー行を表示する。これらの行は、別のファイルで挿入されたか、またはこのファ
イルで削除された。'diffopt' オプションから "filler" を取り除くと、Vim はこれら
のフィラー行を表示しなくなる。


折り畳みは、変更されていないテキストを隠すために使われる。折り畳みで使えるすべ
てのコマンドについては folding を参照。

折り畳みに含まれない、差分の上にある行のコンテキストは、'diffopt' オプションで
設定できる。例えば、コンテキストを 3 行に設定するには:

        :set diffopt=filler,context:3


差分はこれらのグループでハイライトされる:

hl-DiffAdd    DiffAdd         追加 (挿入) された行。これらの行はこのバッファ
                                には存在するが、別のバッファには存在しない。
hl-DiffChange DiffChange      変更された行。
hl-DiffText   DiffText        変更された行の中の、変更されたテキスト。正確な
                                動作は 'diffopt' の inline: 設定に依存する。
                                inline: が "simple" に設定されているとき、
                                Vim は異なる最初の文字、および異なる最後の文字
                                を見つける (行末から検索する)。その間のテキス
                                トがハイライトされる。これは、中間にあるまだ同
                                じ部分も、いずれにせよハイライトされることを意
                                味する。ここでは 'diffopt' のフラグ "iwhite"
                                および "icase" が使われる。
                                inline: が "char" または "word" に設定されて
                                いるとき、Vim は内部 diff ライブラリを使って、
                                変更されたブロックの間の詳細な diff を実行し、
                                2 つの間の正確な差分をハイライトする。内部
                                diff に影響するすべての 'diffopt' フラグを尊重
                                する。
                                inline: が "none" に設定されているときは使わ
                                れない。
hl-DiffTextAdd  DiffTextAdd   変更された行の中の、追加されたテキスト。
                                DiffText と同様だが、他のバッファに対応するテ
                                キストがないときに使われる。inline: が
                                "simple" または "none" に設定されているときは
                                使われない。
hl-DiffDelete DiffDelete      削除された行。それらはこのバッファには実際には
                                存在しないので、フィラー行とも呼ばれる。

3. 差分へジャンプする                                   jumpto-diffs

差分へジャンプするために、2 つのコマンドが使える:
                                                                [c
        [c              前の変更の開始位置へ後方にジャンプする。カウントが使わ
                        れたときは、その回数だけ行う。
                                                                ]c
        ]c              次の変更の開始位置へ前方にジャンプする。
                        カウントが使われたときは、その回数だけ行う。

カーソルの移動先となる変更がない場合、それはエラーである。

4. 差分コピー                   copy-diffs E99 E100 E101 E102 E103
                                                                merge
あるバッファから別のバッファへテキストをコピーするコマンドが 2 つある。その結
果、指定された範囲内でバッファが等しくなる。

                                                        :diffg :diffget
:[range]diffg[et] [bufspec]
                別のバッファとの差分を undo するように、カレントバッファを変更
                する。[bufspec] が指定された場合、そのバッファが使われる。
                [bufspec] がカレントバッファを指す場合、何も起こらない。そうで
                ない場合、これは差分モードの他のバッファが 1 つある場合にだけ
                機能する。
                [range] については以下を参照。

                                                :diffpu :diffput E793
:[range]diffpu[t] [bufspec]
                カレントバッファとの差分を undo するように、別のバッファを変更
                する。":diffget" と同様だが、カレントバッファの代わりに別のバッ
                ファが変更される。
                [bufspec] が省略され、'modifiable' が設定された差分モードの他
                のバッファが 2 つ以上あるときは、これは失敗する。
                [range] については以下を参照。

                                                        do
[count]do       範囲なしの ":diffget" と同じ。"o" は "obtain" を表す ("dg" は
                使えない、それは "dgg" の開始かもしれない!)。Note: これはビジュ
                アルモードでは機能しない。
                [count] を指定した場合、それは ":diffget" の [bufspec] 引数と
                して使われる。

                                                        dp
[count]dp       範囲なしの ":diffput" と同じ。Note: これはビジュアルモードでは
                機能しない。
                [count] を指定した場合、それは ":diffput" の [bufspec] 引数と
                して使われる。


[range] が指定されていないときは、カーソル位置またはそのすぐ上の差分が影響を受
ける。バッファの最終行の下に、削除された行があることがある。カーソルがバッファ
の最終行にあり、この行の上に差分がなく、[range] が指定されていないときは、代わ
りにカーソル位置の下の差分が使われる。

[range] が使われたときは、Vim は指定された行だけを put または get しようとす
る。削除された行があるときは、それらが [range] で指定された行の間にある場合、
それらが使われる。

[range] でそれらの行を別のバッファへ/から put または get できるように、0 およ
び最終行番号に 1 を足したものを使うことが許されている。このコマンドは、他のバッ
ファからすべての差分を get する:

        :0,$+1diffget

Note 削除された行は表示されるが、テキスト行としては数えられないことに注意。そ
れらの中にカーソルを移動することはできない。削除された行を別のバッファの行で埋
めるには、それらの下の行で ":diffget" を使う。
                                                                E787
変更されようとしているバッファが読み取り専用で、FileChangedRO によって発生す
る自動コマンドがバッファを変更するときは、コマンドは失敗する。自動コマンドは
バッファを変更してはならない。

上記の [bufspec] 引数には、バッファ番号、バッファ名に対するパターン、またはバッ
ファ名の一部を指定できる。例:

        :diffget                差分モードにある他のバッファを使う
        :diffget 3              バッファ 3 を使う
        :diffget v2             "v2" にマッチし、差分モードにあるバッファを使う
                                (例: "file.c.v2")

5. 差分アンカー                                         diff-anchors

差分アンカーを使うと、diff アルゴリズムがどこで位置を揃え、ファイル間でテキス
トを同期させるかを制御できる。各アンカーは各ファイルで互いにマッチし、diff の
出力を制御できるようにする。

これは、変更に複雑な編集が含まれるときに便利である。例えば、関数が別の場所に移
動され、さらに編集された場合。既定では、アルゴリズムは最小の diff を作成するこ
とを目指し、その結果、その関数全体が削除されて反対側で追加されたとみなされ、そ
れに対する実際の編集が何だったかを見るのが難しくなる。差分アンカーを使ってその
関数を固定し、diff アルゴリズムがそれに基づいて位置を揃えるようにできる。

これを使うには、各ファイル内の {address} のコンマ区切りリストである
'diffanchors' を使ってアンカーを設定し、それから 'diffopt' に "anchor" を追加
する。内部的には、Vim は各ファイルを、アンカーで分割されたセクションに分割す
る。結果をマージして戻す前に、セクションの各ペアに対して個別に diff を実行す
る。

'diffanchors' を設定すると、すぐに diff が更新される。アンカーがマークに結びつ
いていて、そのマークが指すものを変更した場合、更新された diff の結果を得るに
は、その後で手動で :diffupdate を呼び出す必要がある。

例:

以下のファイルが左右に並んでいるとする。我々は関数 foo() に起きた変更に関心
があり、それは編集もされ、移動もされた。

ファイル A:
        int foo() {
            int n = 1;
            return n;
        }

        int g = 1;

        int bar(int a) {
            a *= 2;
            a += 3;
            return a;
        }
ファイル B:
        int bar(int a) {
            a *= 2;
            a += 3;
            return a;
        }

        int foo() {
            int n = 999;
            return n;
        }

        int g = 1;

通常の diff は、たいてい diff の結果をこのように揃える:

        int foo() {     |----------------
            int n = 1;  |----------------
            return n;   |----------------
        }               |----------------
                        |----------------
        int g = 1;      |----------------
                        |----------------
        int bar(int a) {|int bar(int a) {
            a *= 2;     |    a *= 2;
            a += 3;     |    a += 3;
            return a;   |    return a;
        }               |}
        ----------------|
        ----------------|int foo() {
        ----------------|    int n = 999;
        ----------------|    return n;
        ----------------|}
        ----------------|
        ----------------|int g = 1;

我々が望むのは、代わりに foo() で揃えるように diff に求めることである:

        ----------------|int bar(int a) {
        ----------------|    a *= 2;
        ----------------|    a += 3;
        ----------------|    return a;
        ----------------|}
        ----------------|
        int foo() {     |int foo() {
            int n = 1;  |    int n = 999;
            return n;   |    return n;
        }               |}
                        |
        int g = 1;      |int g = 1;
                        |----------------
        int bar(int a) {|----------------
            a *= 2;     |----------------
            a += 3;     |----------------
            return a;   |----------------
        }               |----------------


以下は、上の結果を得るために差分アンカーを設定するいくつかの方法である。各例で
は、これが効果を持つためには 'diffopt' に anchor が設定されている必要がある。

マーク: アンカーを設定する前に、まず各ファイルの int foo() の行に 'a マー
クを設定する:
        set diffanchors='a

パターン: pattern を使ってアンカーを指定する (:/ を参照)。ここでは、一貫性
のために、常に 1 行目から検索を開始するようにしている:
        set diffanchors=1/int\ foo(/

選択: ビジュアルモードを使って、各ファイルで foo() 関数の本体全体を選択する。
ここでは 2 つのアンカーを使う。これは、関数本体だけが互いにアンカーされ、その
後の行はアンカーされないようにすることについて、よりよい仕事をする。Note 以下
の '>+1 に注意。分割を関数の最後の行の上ではなく、下で起こしたいので、"+1"
が必要である:
        set diffanchors='<,'>+1

バッファローカルなオプションを介して、行番号を使って手動で 2 つのアンカーを設
定する:
        setlocal diffanchors=1,5
        wincmd w
        setlocal diffanchors=7,11

差分を見つける                                 diff-diffexpr

'diffexpr' オプションを設定すると、2 つのファイルを比較して差分を見つけるため
に、内部 diff サポートまたは標準の "diff" プログラム以外のものを使うことができ
る。 E959

'diffexpr' が空のときは、Vim は file1 と file2 の間の差分を見つけるために、こ
のコマンドを使う:

        diff file1 file2 > outfile

">" は 'shellredir' の値で置き換えられる。

"diff" の出力は、通常の "ed" 形式の diff、または unified diff でなければならな
い。context diff は機能しない。unified diff では、コンテキスト行は使えない。
"diff -u" を使うと機能しない、"diff -U0" を使う。

この例は、Vim が "ed" 形式の diff に期待する形式を説明する:

        1a2
        > bbb
        4d4
        < 111
        7c7
        < GGG
        ---
        > ggg

"1a2" 項目は行 "bbb" を追加する。
"4d4" 項目は行 "111" を削除する。
"7c7" 項目は行 "GGG" を "ggg" で置き換える。

'diffexpr' が空でないときは、Vim はそれを評価して、前述の形式の diff ファイル
を得る。これらの変数には、使われるファイル名が設定される:

        v:fname_in              元のファイル
        v:fname_new             同じファイルの新しいバージョン
        v:fname_out             結果の diff ファイルを書き込む場所

さらに、'diffexpr' は 'diffopt' オプションの "icase" および "iwhite" を処理す
べきである。'diffexpr' は 'lines' および 'columns' の値を変更できない。

引数なしの関数呼び出しを使う利点は、それがより高速であることである、
expr-option-function を参照。

例 (これは 'diffexpr' が空であるのとほぼ同じことを行う):

        set diffexpr=MyDiff()
        function MyDiff()
           let opt = ""
           if &diffopt =~ "icase"
             let opt = opt .. "-i "
           endif
           if &diffopt =~ "iwhite"
             let opt = opt .. "-b "
           endif
           silent execute "!diff -a --binary " .. opt .. v:fname_in .. " " .. v:fname_new ..
                \  " > " .. v:fname_out
           redraw!
        endfunction

"-a" 引数は、ファイルをテキストとして比較することを強制するために使われる、バ
イナリとして比較するのは役に立たない。"--binary" 引数はファイルをバイナリモー
ドで読み込ませるので、DOS で CTRL-Z がテキストを終わらせることはない。

redraw! コマンドは、シェルコマンドの実行が画面に何かを表示するかどうかによっ
ては、必要ないかもしれない。

'diffexpr' の式が s: または <SID> で始まる場合、それはスクリプト ID
(local-function) で置き換えられる。例:
                set diffexpr=s:MyDiffExpr()
                set diffexpr=<SID>SomeDiffExpr()
そうでない場合、式はオプションが設定されたスクリプトのコンテキストで評価される
ので、スクリプトローカルな項目が使用可能である。

                                                E810 E97
Vim は diff の出力が問題ないかどうかをテストする。問題がある場合、エラーメッ
セージが表示される。考えられる原因:
-  "diff" プログラムを実行できない。
-  "diff" プログラムが通常の "ed" 形式の diff を生成しない (上記を参照)。
-  'shell' および関連するオプションが正しく設定されていない。":!sort" のような
   コマンドでフィルタリングが機能するかどうか試す。
-  'diffexpr' を使っていて、それが機能しない。
問題が何か明らかでない場合、より多くのメッセージを見るために、'verbose' オプ
ションを 1 以上に設定する。

MS-Windows 用の自己インストール版 Vim には diff プログラムが含まれている。それ
がない場合、diff.exe をダウンロードしたいかもしれない。例えば
http://gnuwin32.sourceforge.net/packages/diffutils.htm から。


パッチを使う                                   diff-patchexpr

'patchexpr' オプションを設定すると、標準の "patch" プログラム以外のものを使う
ことができる。

'patchexpr' が空のときは、Vim は "patch" プログラムをこのように呼び出す:

        patch -o outfile origfile < patchfile

これは "patch" プログラムのほとんどのバージョンでうまく機能するはずである。
Note 行の途中の CR は問題を引き起こすかもしれない、それは改行とみなされること
に注意。

既定のものがあなたにとって機能しない場合、同じ効果を持つ式を 'patchexpr' に設
定する。これらの変数には、使われるファイル名が設定される:

        v:fname_in              元のファイル
        v:fname_diff            パッチファイル
        v:fname_out             パッチが当てられた結果のファイル

引数なしの関数呼び出しを使う利点は、それがより高速であることである、
expr-option-function を参照。

例 (これは 'patchexpr' が空であるのと同じことを行う):

        set patchexpr=MyPatch()
        function MyPatch()
           :call system("patch -o " .. v:fname_out .. " " .. v:fname_in ..
           \  " < " .. v:fname_diff)
        endfunction

"patch" プログラムを使うことが望ましくない副作用を持たないことを確認する。例え
ば、削除されるべき、追加で生成されたファイルに気をつける。それはファイルにパッ
チを当てるだけで、他には何もすべきではない。
   Vim は 'patchexpr' を評価する前に、ディレクトリを "/tmp" または別の一時ディ
レクトリに変更する。これにより、願わくはカレントディレクトリ内のファイルに誤っ
てパッチが当てられることが避けられる。Vim は v:fname_in で始まり、".rej" およ
び ".orig" で終わるファイルも削除する。

'patchexpr' の式が s: または <SID> で始まる場合、それはスクリプト ID
(local-function) で置き換えられる。例:
                set patchexpr=s:MyPatchExpr()
                set patchexpr=<SID>SomePatchExpr()
そうでない場合、式はオプションが設定されたスクリプトのコンテキストで評価される
ので、スクリプトローカルな項目が使用可能である。


diff 関数の例                                  diff-func-examples

文字列の 2 つのリストの間の diff インデックスを計算するために diff() 関数を
使う、いくつかの例は以下にある。

  " いくつかの行が変更されている
  :echo diff(['abc', 'def', 'ghi'], ['abx', 'rrr', 'xhi'], {'output': 'indices'})
   [{'from_idx': 0, 'from_count': 3, 'to_idx': 0, 'to_count': 3}]

  " 少数の行が先頭に追加された
  :echo diff(['ghi'], ['abc', 'def', 'ghi'], {'output': 'indices'})
   [{'from_idx': 0, 'from_count': 0, 'to_idx': 0, 'to_count': 2}]

  " 少数の行が先頭から削除された
  :echo diff(['abc', 'def', 'ghi'], ['ghi'], {'output': 'indices'})
   [{'from_idx': 0, 'from_count': 2, 'to_idx': 0, 'to_count': 0}]

  " 少数の行が中間に追加された
  :echo diff(['abc', 'jkl'], ['abc', 'def', 'ghi', 'jkl'], {'output': 'indices'})
   [{'from_idx': 1, 'from_count': 0, 'to_idx': 1, 'to_count': 2}]

  " 少数の行が中間で削除された
  :echo diff(['abc', 'def', 'ghi', 'jkl'], ['abc', 'jkl'], {'output': 'indices'})
   [{'from_idx': 1, 'from_count': 2, 'to_idx': 1, 'to_count': 0}]

  " 少数の行が末尾に追加された
  :echo diff(['abc'], ['abc', 'def', 'ghi'], {'output': 'indices'})
   [{'from_idx': 1, 'from_count': 0, 'to_idx': 1, 'to_count': 2}]

  " 少数の行が末尾から削除された
  :echo diff(['abc', 'def', 'ghi'], ['abc'], {'output': 'indices'})
   [{'from_idx': 1, 'from_count': 2, 'to_idx': 1, 'to_count': 0}]

  " ばらばらの変更
  :echo diff(['ab', 'def', 'ghi', 'jkl'], ['abc', 'def', 'ghi', 'jk'], {'output': 'indices', 'context': 0})
   [{'from_idx': 0, 'from_count': 1, 'to_idx': 0, 'to_count': 1},
    {'from_idx': 3, 'from_count': 1, 'to_idx': 3, 'to_count': 1}]

  " コンテキスト長 1 のばらばらの変更
  :echo diff(['ab', 'def', 'ghi', 'jkl'], ['abc', 'def', 'ghi', 'jk'], {'output': 'indices', 'context': 1})
   [{'from_idx': 0, 'from_count': 4, 'to_idx': 0, 'to_count': 4}]
