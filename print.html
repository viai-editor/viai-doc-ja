1. はじめに                                             print-intro

MS-Windows では、Vim はインストールされている任意のプリンタでテキストを印刷で
きる。他のシステムでは PostScript ファイルが生成される。これは PostScript プリ
ンタに直接送ることができる。その他のプリンタでは ghostscript のようなプログラ
ムを使う必要がある。

Note: :hardcopy での印刷に問題がある場合、代わりの方法は :TOhtml を使い、
その結果の html ファイルをブラウザーから印刷することである。

                                        :ha :hardcopy E237 E238 E324
:[range]ha[rdcopy][!] [arguments]
                        [range] の行 (デフォルトはファイル全体) をプリンタに送
                        る。

                        MS-Windows または GTK4 GUI では、プリンタ、用紙サイズ
                        などを選択できるようにダイアログが表示される。ダイアロ
                        グを省略するには [!] を使う。この場合、'printdevice'
                        で定義されたプリンタ、または 'printdevice' が空の場合
                        はシステムのデフォルトプリンタが使われる。Note GTK4
                        GUI の印刷ダイアログには GTK 4.14 以上が必要であること
                        に注意。

                        MS-Windows または Pango 以外のシステムでは、PostScript
                        は一時ファイルに書き込まれ、実際に印刷するために
                        'printexpr' が使われる。そして [arguments] は
                        v:cmdarg を通して 'printexpr' で使うことができる。そ
                        れ以外の場合、[arguments] は無視される。'printoptions'
                        を使って、用紙サイズ、両面印刷などを指定できる。
                        Note: PDF が必要な場合、PostScript を PDF に変換できる
                        "ps2pdf" などのツールがある。+pango 機能が有効な場
                        合、'printoptions' で "format" を "pdf" に設定して PDF
                        を出力する。

:[range]ha[rdcopy][!] >{filename}
                        上記と同様だが、結果の PostScript をファイル {filename}
                        に書き込む。
                        "%" のようなものは展開される cmdline-special
                        注意: 既存のファイルは何も通知されずに上書きされる。
                        {+postscript または +pango 機能付きでコンパイルさ
                        れたときのみ使用可能}
                        MS-Windows ではプリンタドライバの "print to file" 機能
                        を使う。

印刷中は、進捗がページ番号およびパーセンテージで表示される。印刷を中止するには
割り込みキー (CTRL-C、または MS のシステムでは CTRL-Break) を使う。

プリンタの出力は 'printfont' および 'printoptions' オプションで制御される。
'printheader' はページヘッダーの書式を指定する。

印刷されるファイルは、カレントウィンドウの 'wrap' または 'linebreak' の設定に
関係なく、常に選択されたマージン内に制限される。'printoptions' の "wrap" 項目
を使って折り返しをオフにできる。
現在のハイライトの色が、以下の点を考慮して印刷物に使われる:
1) 通常の背景は常に白 (つまり白紙) として描画される。
2) 白のテキストまたはデフォルトの前景色は、見えるように黒で描画される!
3) 'background' が "dark" の場合、そうしないと明るすぎて白い紙の上ではっきり見
   えないという事実を補うために、色が暗くされる。

2. 印刷オプション                                       print-options

ここでは、印刷の方法を変更するオプションの詳細を示す。オプションの設定について
の一般的な情報は options.txt を参照。

                                                        pdev-option
'printdevice' 'pdev'    文字列  (既定では空)
                        グローバル
これは、プリンタ選択ダイアログを省略するために :hardcopy コマンドが感嘆符 (!)
付きで実行されたときに使われるプリンタの名前を定義する。Win32 では、標準のプリ
ンタダイアログに表示されるとおりのプリンタ名でなければならない。
このオプションが空の場合、vim は ":hardcopy!" に対してシステムのデフォルトプリ
ンタを使う

                                                        penc-option E620
'printencoding' 'penc'  文字列  (既定では空、以下を除く:
                                        MS-Windows: cp1252,
                                        Macintosh: mac-roman,
                                        VMS: dec-mcs,
                                        HPUX: hp-roman8,
                                        EBCDIC: ebcdic-uk)
                        グローバル
印刷時に使われる文字エンコーディングを設定する。このオプションは、
'runtimepath' の "print" ディレクトリにあるどの印刷文字エンコーディングファイ
ルを使うかを Vim に伝える。

このオプションは encoding-names のどの値でも受け付ける。認識された名前はすべ
て Vim の標準の名前に変換される - 詳細は 'encoding' を参照。Vim が認識しない名
前は、単に小文字に変換され、アンダースコアは '-' 記号に置き換えられる。

'printencoding' が空であるか、または Vim がファイルを見つけられない場合、
'encoding' (8 ビットエンコーディングが設定されている場合) を使って印刷文字エン
コーディングファイルを探す。Vim が文字エンコーディングファイルを見つけられない
場合、"latin1" 印刷文字エンコーディングファイルを使う。

'encoding' がマルチバイトエンコーディングに設定されている場合、Vim は印刷のた
めに文字を印刷エンコーディングに変換しようとする ('printencoding' が空の場合、
変換先は latin1 になる)。latin1 以外の印刷エンコーディングへの変換には、Vim が
+iconv 機能付きでコンパイルされている必要がある。変換ができない場合、印刷は
失敗する。変換できない文字はすべて、上下逆さまの疑問符に置き換えられる。

デフォルトの Mac、VMS、HPUX、および EBCDIC 文字エンコーディングをサポートする
4 つの印刷文字エンコーディングファイルが提供されており、これらのプラットフォー
ムではデフォルトで使われる。MS-Windows プラットフォームでは、コードページ 1252
の印刷文字エンコーディングがデフォルトで使われる。

                                                        pexpr-option
'printexpr' 'pexpr'     文字列  (既定値は、以下を参照)
                        グローバル
:hardcopy で生成された PostScript または PDF を印刷するために評価される式。
印刷するファイルの名前は v:fname_in にある。
":hardcopy" コマンドの引数は v:cmdarg にある。
式は、印刷した後にファイルを削除しなければならない。
エラーがあるときは、式は 0 以外の数値を返さなければならない。
エラーが無い場合は、0 または空文字列を返す。
MS-Windows または VMS 以外のシステムでのデフォルトは、単に "lpr" を使ってファ
イルを印刷することである:

    system('lpr' .. (&printdevice == '' ? '' : ' -P' .. &printdevice)
        .. ' ' .. v:fname_in) .. delete(v:fname_in) + v:shell_error

MS-Windows マシンでのデフォルトは、ファイルを現在指定されている printdevice に
コピーすることである:

    system('copy' .. ' ' .. v:fname_in .. (&printdevice == ''
                ? ' LPT1:' : (' \"' .. &printdevice .. '\"')))
                .. delete(v:fname_in)

VMS マシンでのデフォルトは、ファイルをデフォルトまたは現在指定されている
printdevice のどちらかに送ることである:

    system('print' .. (&printdevice == '' ? '' : ' /queue=' ..
                &printdevice) .. ' ' .. v:fname_in) .. delete(v:fname_in)

このオプションを変更する場合、関数を使うのが、すべての空白をエスケープする必要
を避ける簡単な方法である。例:

        :set printexpr=PrintFile()
        :function PrintFile()
        :  call system("ghostview " .. v:fname_in)
        :  call delete(v:fname_in)
        :  return v:shell_error
        :endfunc

オプションが関数呼び出しだけに設定されている場合、より効率的である。
expr-option-function を参照。

印刷プログラムによっては、ファイルを読み込む前に制御を戻すものがあることに注意
すること。ファイルを早く削除しすぎると、印刷されない。これらのプログラムには通
常、印刷が終わったときにファイルを削除させるオプションがある。
                                                        E365
式の評価が失敗するか、またはその結果が 0 以外の数値になった場合、エラーメッセー
ジが表示される。その場合、Vim はファイルを削除する。MS-Windows 以外のデフォル
ト値では、トリックが使われている: "v:shell_error" を加えることで、system() の
呼び出しが失敗したときに 0 以外の数値になる。

式が s: または <SID> で始まる場合、それはスクリプト ID (local-function) に
置き換えられる。例:
                set printexpr=s:MyPrintFile()
                set printexpr=<SID>SomePrintFile()
それ以外の場合、式はオプションが設定されたスクリプトのコンテキストで評価される
ので、スクリプトローカルな項目が使用可能である。

セキュリティ上の理由から、このオプションは modeline から、または sandbox
内で設定することはできない。

                                                        pfn-option E613
'printfont' 'pfn'       文字列  (既定では "courier")
                        グローバル
これは :hardcopy コマンドの出力に使われるフォントの名前である。'guifont' オ
プションと同じ書式を持つが、フォントは 1 つしか指定できず、特別な "guifont=*"
構文は使用できない。

Win32 GUI 版では、これは 'guifont' オプションと同様に、追加の属性を伴うフォン
ト名を指定する。+pango が有効な場合、書式は GTK GUI の 'guifont' と同じであ
る (例: "Courier 10")。

その他のシステムでは、":h11" だけが認識される。ここで "11" はフォントのポイン
トサイズである。省略した場合、ポイントサイズは 10 である。

                                                        pheader-option
'printheader' 'pheader'  文字列  (既定では "%<%f%h%m%=Page %N")
                         グローバル
これは :hardcopy の出力で生成されるヘッダーの書式を定義する。このオプション
は 'statusline' オプションと同じ方法で定義される。Vim が +statusline 機能付
きでコンパイルされていない場合、このオプションは効果を持たず、ページ番号を表示
する単純なデフォルトのヘッダーが使われる。このオプションが空の場合も、同じ単純
なヘッダーが使われる。

日本語のテキストを印刷するための正しいエンコーディングおよび文字セットを設定す
るには、以下のようにする;
        :set printencoding=euc-jp
        :set printmbcharset=JIS_X_1983

'printmbcharset' が上記の値のいずれでもない場合、それはカスタムのマルチバイト
文字セットを指定しているとみなされ、それが 'printencoding' の値と互換性がある
かどうかのチェックは行われない。Vim は 'runtimepath' の "print" ディレクトリか
ら、その文字セットを定義するファイルを探す。

                                                        pmbfn-option
'printmbfont' 'pmbfn'   文字列 (既定では "")
                        グローバル
これは、:hardcopy から CJK 出力を生成するときに使われるフォント名のフィール
ドのコンマ区切りのリストである。各フォント名の前には、以下のように、そのフォン
トを使うスタイルを示す文字を付けなければならない:

  r:{font-name}         通常の文字に使うフォント
  b:{font-name}         太字の文字に使うフォント
  i:{font-name}         イタリックの文字に使うフォント
  o:{font-name}         太字イタリックの文字に使うフォント

CJK 印刷を行うときは、r: プリフィックスのフィールドを指定しなければならない。
その他のフォント名指定子は省略可能である。指定子が無い場合、以下のように別の
フォントが使われる:

  b: が無い場合、r: を使う
  i: が無い場合、r: を使う
  o: が無い場合、b: を使う

一部の CJK フォントは、ASCII コード範囲のコードの文字を含んでいない。また、CJK
の ASCII コード範囲の一部の文字は、いくつかのコードポイントで従来の ASCII 文字
と異なる。ASCII コード範囲の文字の印刷を制御する 2 つの追加のフィールドがある。

  c:yes                 ASCII コード範囲の文字に Courier フォントを
  c:no (default)        使う。

  a:yes                 ASCII コード範囲のコードに ASCII 文字セットを
  a:no (default)        使う。

以下は、通常およびイタリックの印刷用に 1 つ、太字および太字イタリックの印刷用
に 1 つの、2 つのマルチバイトフォントを指定し、ASCII コード範囲のコードの印刷
に Courier を使うが国の文字セットを使う例である:
        :set printmbfont=r:WadaMin-Regular,b:WadaMin-Bold,c:yes

                                                        popt-option
'printoptions' 'popt'   文字列 (既定では "")
                        グローバル
これは、:hardcopy の出力の書式を制御する項目のコンマ区切りのリストである:

  left:{spec}           左マージン (デフォルト: 10pc)
  right:{spec}          右マージン (デフォルト: 5pc)
  top:{spec}            上マージン (デフォルト: 5pc)
  bottom:{spec}         下マージン (デフォルト: 5pc)
                        {spec} は数値の後に、インチの場合は "in"、ポイント (1
                        ポイントは 1/72 インチ) の場合は "pt"、ミリメートルの
                        場合は "mm"、または用紙サイズに対するパーセンテージの
                        場合は "pc" が続くものである。
                        変な例:
                            left:2in,top:30pt,right:16mm,bottom:3pc
                        単位が認識されない場合、エラーにはならず、デフォルト値
                        が使われる。

  header:{nr}           ヘッダー用に確保する行数。
                        実際に埋められるのは最初の行だけなので、{nr} が 2 の場
                        合は 1 行の空行がある。ヘッダーは 'printheader' に従っ
                        て整形される。
  header:0              ヘッダーを印刷しない。
  header:2  (default)   ヘッダーに 2 行を使う

  syntax:n              構文ハイライトを使わない。これはより速いので、大きな
                        ファイルを印刷するときに便利である。
  syntax:y              構文ハイライトを行う。
  syntax:a  (default)   プリンタがカラーまたはグレーを印刷できるように見える場
                        合、構文ハイライトを使う。

  number:y              印刷出力に行番号を含める。
  number:n  (default)   行番号なし。

  wrap:y    (default)   長い行を折り返す。
  wrap:n                長い行を切り詰める。

  duplex:off            片面に印刷する。
  duplex:long (default) 両面に印刷し (可能な場合)、長辺で綴じる。
  duplex:short          両面に印刷し (可能な場合)、短辺で綴じる。

  collate:y  (default)  丁合いあり: 1 2 3, 1 2 3, 1 2 3
  collate:n             丁合いなし: 1 1 1, 2 2 2, 3 3 3

  jobsplit:n (default)  すべての部数を 1 つの印刷ジョブで行う
  jobsplit:y            各部を別々の印刷ジョブで行う。N-up の後処理を行うとき
                        に便利である。

  portrait:y (default)  向きは縦。
  portrait:n            向きは横。

3. PostScript 印刷                                      postscript-printing
                                                E455 E456 E457 E624
十分なディスク容量がある場合、PostScript ファイルの生成に問題は無いはずである。
ランタイムファイルが正しくインストールされている必要がある (ヘルプファイルを見
つけられる場合、おそらくインストールされている)。

現在、PostScript 印刷にはいくつかの制限がある:

- 'printfont' - フォント名は無視される (常に Courier ファミリーが使われる - こ
  れはすべての PostScript プリンタで使用可能なはずである) が、フォントサイズは
  使われる。

- 'printoptions' - 両面印刷の設定は PostScript 出力の生成時に使われるが、その
  設定に従うかどうかはプリンタ次第である。プリンタが両面印刷をサポートしていな
  い場合、その設定は黙って無視されるはずである。しかし、一部のプリンタはまった
  く印刷しない。

- 8 ビットサポート - いくつかの 8 ビット印刷文字エンコーディングがサポートされ
  ているが、一部の文字が印刷されない可能性がある。文字が印刷されるかどうかは、
  プリンタ内のフォントがその文字を知っているかどうかに依存する。欠けている文字
  は上下逆さまの疑問符に置き換えられるか、またはその文字もフォントが知らない場
  合は空白に置き換えられる。Courier フォントファミリーの新しいバージョンをイン
  ストールすることで、エンコーディング内のすべての文字を印刷できるようになる可
  能性がある。

- マルチバイトサポート - 現在、Vim はマルチバイト文字を 'printencoding' で指定
  された 8 ビットエンコーディング (それが空の場合は latin1) に変換しようとす
  る。正常に変換されなかった文字はすべて、不明な文字として表示される。Vim がマ
  ルチバイトを 8 ビットエンコーディングに変換できない場合、印刷は失敗する。

印刷に Pango バックエンドを使う場合、これらの制限は解決される。詳細は
pango-printing を参照。

4. カスタム 8 ビット印刷文字エンコーディング    postscript-print-encoding
                                                                E618 E619
8 ビットの文字データを印刷するときに独自の印刷文字エンコーディングを使うには、
独自の PostScript フォントエンコーディングベクターを定義する必要がある。フォン
トエンコーディングベクターの定義方法の詳細はこのヘルプファイルの範囲を超える
が、詳細は、Addison-Wesley 発行で https://www.adobe.com/ から PDF 形式で入手可
能な PostScript Language Reference Manual, 3rd Edition で見つけることができる。
以下では、Vim が独自の印刷文字エンコーディングを見つけて使うために必要なことを
説明する。

i.   エンコーディングベクターの一意な名前を決める。それは Vim が使う認識済みま
     たは標準のエンコーディング名 (一覧は encoding-names を参照) のどれとも
     衝突せず、他の誰も使いそうにないものにする。
ii.  $VIMRUNTIME/print/latin1.ps を 'runtimepath' 内の print サブディレクトリ
     にコピーし、一意な名前に名前を変更する。
iii. 名前を変更した latin1.ps のコピーを編集し、latin1 をすべて一意な名前に置
     き換え (%%Title: で始まる行を忘れないこと)、グリフ名の配列を変更して新し
     いエンコーディングベクターを定義する。配列はちょうど 256 個のエントリを持
     たなければならず、そうでないと印刷できない!
iv.  Vim 内で 'printencoding' を一意なエンコーディング名に設定し、ファイルを印
     刷する。これで Vim は独自の印刷文字エンコーディングを使う。

最初の 3 行の順序または内容を、%%Title: で始まる行のエンコーディングの名前、ま
たは %%Version: で始まる行のバージョン番号以外で変更した場合、Vim はリソース
ファイルのエラーを報告する。

[PostScript を知っている人向けの技術的な説明 - Vim は、印刷時に使うエンコーディ
ングと同じ名前のファイルを探す。そのファイルは /VIM-name という新しい
PostScript Encoding リソースを定義する。ここで name は Vim が使う印刷文字エン
コーディングである。]

5. PostScript CJK 印刷                          postscript-cjk-printing
                                                        E673 E674 E675

Vim は中国語、日本語、および韓国語のファイルの印刷をサポートしている。CJK ファ
イルを正しく印刷するように Vim を設定するには、さらにいくつかのオプションを設
定する必要がある。

これらの国には、それぞれ多くの標準の文字セットおよびエンコーディングがあり、印
刷時には両方を指定する必要がある。加えて、CJK フォントは通常イタリックのグリフ
の概念を持たず、印刷時の強調には異なるウェイトまたはストロークスタイルを使う。
そのため、印刷時に使うフォントの指定には異なるアプローチが必要になる。

エンコーディングおよび文字セットは、'printencoding' および 'printmbcharset' オ
プションで指定する。'printencoding' が指定されていない場合、通常どおり
'encoding' が使われる。'printencoding' が指定されている場合、文字は印刷のため
にこのエンコーディングに変換される。エンコーディングがファイルの内容に必要な文
字セットと互換性があることを確認すること。そうしないと、一部の文字が印刷時に現
れない可能性がある。

CJK 印刷に使うフォントは 'printmbfont' で指定する。このオプションでは、フォン
トスタイルの通常、イタリック、太字、および太字イタリックで構文ハイライトされる
文字を印刷するときに使う、異なるフォントを指定できる。

Vim には CJK フォントは付属していない。いくつかの無料の韓国語、日本語、および
繁体字中国語のフォントが以下で入手可能である:

  http://examples.oreilly.com/cjkvinfo/adobe/samples/
  https://resources.oreilly.com/examples/9781565922242/

さまざまなフォントの説明は、以下にある read me ファイルで見つけることができる

  https://resources.oreilly.com/examples/9781565922242/-/blob/master/00README

新しいフォントのインストール方法については、プリンタのドキュメントを読むこと。

CJK フォントは数千のグリフを含む大きなものになることがあり、国の標準規格のサブ
セットしか含んでいないことも珍しくない。フォントが ASCII コード範囲のコードの
文字を含んでいないことも珍しくない。印刷物に半角のローマ字が現れない場合、
'printmbfont' で半角 ASCII 文字に Courier フォントを使うように Vim を設定する
必要がある。フォントがその他の文字を含んでいない場合、それを含む別のフォントを
探す必要がある。

ASCII 文字に関するもう 1 つの問題は、さまざまな国の文字セットが ASCII コード範
囲にいくつかの異なるグリフを指定していることである。国の文字セットを使って
ASCII テキストを印刷する場合、予期しない文字が表示されることがある。真の ASCII
コードの印刷が必要な場合、'printmbfont' で ASCII コード範囲に ASCII 文字を出力
するように Vim を設定する必要がある。

独自のマルチバイト文字セットを定義することは可能だが、軽い気持ちで試みるべきで
はない。その手順の議論はこれらのヘルプファイルの範囲を超える。CMap (文字マップ)
ファイルの詳細は、https://www.adobe.com から PDF ファイルとして入手可能なドキュ
メント 'Adobe CMap and CIDFont Files Specification, Version 1.0' で見つけるこ
とができる。

6. PostScript 印刷のトラブルシューティング      postscript-print-trouble
                                                                        E621
通常、PostScript での印刷で問題が起きたことを示す唯一の兆候は、印刷物が出てこ
ないことである。運が良い場合、印刷ジョブの完了を妨げたエラーを生成した
PostScript オペレータを示すページが印刷されるかもしれない。

印刷が失敗した原因として考えられるものがいくつかある:

- 間違ったバージョンの prolog リソースファイル。prolog リソースファイルには、
  Vim が印刷できるために必要な PostScript が含まれている。Vim の各バージョンは
  特定の 1 つのバージョンを必要とする。ランタイムファイルが正しくインストール
  されていること、および 'runtimepath' ディレクトリ内の print ディレクトリに
  prolog という名前のファイルの古いバージョンが無いことを確認すること。

- 用紙サイズ。一部の PostScript プリンタは、要求された用紙サイズをサポートして
  いない場合、ファイルの印刷を中止する。デフォルトでは、Vim は A4 用紙を使う。
  プリンタが通常使う用紙のサイズを調べ、'printoptions' で適切な用紙サイズを設
  定すること。使われている用紙の名前が見つからない場合、用紙を 1 枚測って
  'printoptions' 用に列挙されているサポートされた用紙サイズの表と比較し、幅お
  よび高さの両方が最も近い用紙を使うこと。
  Note: 実際の用紙の寸法は、列挙されているものとわずかに異なる場合がある。十分
  に近い用紙が列挙されていない場合、以下で説明する PSUtils の psresize を試す
  とよいかもしれない。

- 両面印刷 (duplex)。通常、両面印刷をサポートしていない PostScript プリンタは、
  両面印刷の要求をすべて無視する。しかし、一部のプリンタはジョブを完全に中止す
  るかもしれない。両面印刷をオフにして印刷してみること。Note: 両面印刷は PS
  utils を使って手動で実現できる - 以下を参照。

- 丁合い印刷。両面印刷と同様に、印刷物の丁合いをサポートしていないほとんどの
  PostScript プリンタは、その要求を無視する。無視しないものもあるかもしれない。
  丁合いをオフにして印刷してみること。

- 構文ハイライト。一部の印刷管理コードは、構文ハイライトがオンの場合、たとえ使
  われている色が黒一色だけであっても、生成された PostScript ファイルが白黒プリ
  ンタで印刷されるのを妨げることがある。構文ハイライトをオフにして印刷してみる
  こと。

試すのに安全な printoptions の設定:

        :set printoptions=paper:A4,duplex:off,collate:n,syntax:n

"A4" を、プリンタの用紙に最もよく一致する用紙サイズに置き換えること。

Ghostscript は非常にさまざまなプラットフォームで動作する。

3 つのバージョンが入手可能である:

- 非商用利用では無料の AFPL Ghostscript (旧 Aladdin Ghostscript)。以下から入手

7.3 PSUtils

PSUtils は PostScript ドキュメントを操作するためのユーティリティプログラム集で
ある。完全なソースと同様に、多くのプラットフォーム向けのバイナリ配布物が入手可
能である。PSUtils は以下で見つけることができる:

  http://knackered.org/angus/psutils

関心のあるユーティリティには以下がある:

- psnup.     N-up 印刷用に PS ファイルを変換する。
- psselect.  ページ範囲および印刷の順序を選択する。
- psresize.  ページサイズを変更する。
- psbook.    本を作るためにページを並べ替えてレイアウトする。

あるプログラムの出力を次のプログラムの入力として使うことができ、複雑な印刷ド
キュメントの作成が可能になる。


N-UP 印刷

psnup ユーティリティは、Vim から生成された既存の PostScript ファイルを受け取
り、それを n-up バージョンに変換する。2-up の印刷物を作成する最も簡単な方法は、
まず以下で PostScript ファイルを作成することである:

        :hardcopy > test.ps

次に、コマンドラインで以下を実行する:

        psnup -n 2 test.ps final.ps

Note: 一部の Ghostscript プレビューアでは、psnup で生成されたファイルに対して
警告が出ることがある - これらは無視しても問題ない。

最後に、プラットフォームの印刷コマンドで、ファイル final.ps を PostScript プリ
ンタに印刷する。(後で 2 つの PostScript ファイルを自分で削除する必要がある。)
'printexpr' を変更して、印刷の前にこの追加のステップを実行するようにすることも
できる。


代替の両面印刷

PS ユーティリティ psselect を使って、簡易版の両面印刷を実現することができる。
このユーティリティには、PS ファイルの偶数ページまたは奇数ページだけをそれぞれ
印刷するためのオプション -e および -o がある。

まず、'hardcopy' コマンドで PS ファイルを生成し、次に以下で、奇数番号および偶
数番号のページをすべて含む新しいファイルを生成する:

        psselect -o test.ps odd.ps
        psselect -e test.ps even.ps

次に、プラットフォームの通常の印刷コマンドで odd.ps を印刷する。そして印刷出力
を取り、裏返して給紙トレイに戻す。ここで、プラットフォームの印刷コマンドで
even.ps を印刷する。これで、すべての偶数ページが奇数ページの裏に現れるはずであ
る。

いくつか心に留めておくべき点がある:

1. 最初のページの位置。奇数ページを印刷するときに最初のページが印刷物の一番上
   にある場合、奇数ページが印刷される順序を逆にする必要がある。これは psselect
   の -r オプションで行うことができる。これにより、ページ 2 がページ 1 の裏に
   印刷されることが保証される。
   Note: 元の PS ファイルのページ数が奇数の場合に備えて、偶数番号のページより
   も奇数番号のページを逆にするほうが良い。

2. 用紙の裏返し。奇数ページが印刷された用紙を裏返すときに、用紙を水平方向 (長
   辺に沿って) または垂直方向 (短辺に沿って) のどちらかに裏返し、さらに場合に
   よっては 180 度回転させる必要があるかもしれない。これはすべてプリンタに依存
   する - 用紙経路が見えないようになっている小型のオフィス用レーザープリンタよ
   りも、デスクトップ用インクジェットのほうがより明白になる。

9. フォームフィード文字                                 printing-formfeed

デフォルトでは、Vim はフォームフィード制御文字に対して特別な処理を何も行わな
い。'printoptions' の formfeed 項目を設定すると、Vim はフォームフィード文字を
認識し、現在の行の印刷を新しいページの最初の行の先頭から続ける。フォームフィー
ド文字を使うと初歩的な印刷制御ができるが、注意すべき点がいくつかある。

フォームフィード文字が行の最初の文字であっても、Vim はその文字を含む行の印刷
(有効な場合は行番号を含む) を常に開始する。これは、フォームフィード文字で始ま
る行がページの最初の行である場合、Vim が空白のページを印刷することを意味する。

行番号はフォームフィード文字を含む行の印刷の開始時に印刷されるので、新しいペー
ジに印刷される行の残りの部分には行番号が印刷されない ('printoptions' の wrap
が有効なときの、長い行の折り返された行と同じように)。

フォームフィード文字が行の最後の文字である場合、印刷は新しいページの最初の行で
はなく、2 行目から続けられる。これは、Vim がフォームフィード文字の後に行末を処
理し、印刷を続けるために 1 行下に移動するためである。

上記の点により、フォームフィード文字の処理を有効にするときは、行番号の印刷を無
効にし、フォームフィード文字を行の最後の文字にしないことが推奨される。それで
も、偶発的な空白ページを防ぐために、フォームフィード文字の前の行数を調整する必
要があるかもしれない。
