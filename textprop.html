==============================================================================
1. はじめに                                             text-prop-intro

テキストプロパティはバッファ内のテキストに付加できる。それらはテキストと一緒に
移動する: 行が削除または挿入された場合、プロパティは付加されているテキストと一
緒に移動する。また、行内でテキストプロパティより前のテキストを挿入/削除すると
きも。そして、テキストプロパティの内側でテキストを挿入/削除するとき、そのサイ
ズは増加/減少する。

テキストプロパティの主な用途は、テキストをハイライトすることである。これは構文
ハイライトの代替と見なすことができる。テキストにマッチするパターンを定義する代
わりに、ハイライトはスクリプトによって、場合によっては外部パーサーの出力を使っ
て設定される。これは画面を再描画するたびにではなく、1 回だけ行えばよいので、テ
キストプロパティを付加する初期コストの後は、はるかに高速になりうる。

テキストプロパティは、テキストを識別するための他の目的にも使える。例えば、関数
名にテキストプロパティを追加して、次/前の関数にジャンプする検索を定義できるよ
うにする。

テキストプロパティは特定の行および列に付加され、指定された長さを持つ。プロパ
ティは複数行にわたることができる。

テキストプロパティにはこれらのフィールドがある:
        "id"            望みどおりに使える数値
        "type"          プロパティタイプの名前


プロパティタイプ
                                                        E971
テキストプロパティは通常、プロパティタイプの名前を持ち、それがテキストをどのよ
うにハイライトするかを定義する。プロパティタイプはこれらのエントリを持つことが
できる:
        "highlight"     使用するハイライトグループの名前
        "combine"       省略されたとき、または TRUE のとき、テキストプロパティ
                        のハイライトはあらゆる構文ハイライトと組み合わされる;
                        FALSE のとき、テキストプロパティのハイライトが構文ハイ
                        ライトを置き換える
        "priority"      プロパティが重なるとき、最も高い優先度を持つものが使わ
                        れる。
        "start_incl"    TRUE のとき、開始位置での挿入がテキストプロパティに含
                        まれる
        "end_incl"      TRUE のとき、終了位置での挿入がテキストプロパティに含
                        まれる


例

バッファの 11 行目にこのテキストがあるとする (インデントを除く):

        The number 123 is smaller than 4567.

このテキスト内の数値をハイライトするには:
        call prop_type_add('number', {'highlight': 'Constant'})
        call prop_add(11, 12, {'length': 3, 'type': 'number'})
        call prop_add(11, 32, {'length': 4, 'type': 'number'})

テキストの上の行を挿入または削除してみると、テキストプロパティがテキストにくっ
ついていて、したがって行番号が必要に応じて調整されることがわかるだろう。

"start_incl" および "end_incl" を設定するのは、例えば関数名の場合のように、空
白がテキストを囲んでいるときに便利である。false を使うのは、文字列を囲む引用符
のような特定の文字でテキストが始まる、および/または終わるときに便利である。

        func FuncName(arg)
             ^^^^^^^^        start_incl および end_incl が設定されたプロパティ

        var = "text";
              ^^^^^^         start_incl および end_incl が設定されていないプロパティ

それでもなお、テキストが挿入または削除されたときは、テキストを解析し、テキスト
プロパティを更新する必要があるかもしれない。しかし、これは非同期に行うことがで
きる。


内部エラー E967

E967 を見た場合、バグを報告してほしい。これは Github で行える:
https://github.com/viai-editor/viai/issues/new

                                                text-prop-functions-details

                                                prop_add() E965
prop_add({lnum}, {col}, {props})
                位置 {lnum}, {col} にテキストプロパティを付加する。{col} はバ
                イト単位で数え、最初の列には 1 を使う。
                {lnum} が無効な場合、エラーが発生する。 E966
                {col} が無効な場合、エラーが発生する。 E964

                {props} はこれらのフィールドを持つ辞書である:
                   type         テキストプロパティタイプの名前
                   length       テキストのバイト単位の長さ、別の行に続かないプ
                                ロパティに対してのみ使用できる; 0 でもよい
                   end_lnum     テキストの終わりの行番号 (含む)
                   end_col      テキストの直後の列; "length" が存在するときは
                                使われない; {col} と "end_col" が等しく、かつ
                                "end_lnum" が省略されているか、または {lnum}
                                と等しいとき、これは幅 0 のテキストプロパティ
                                である
                   bufnr        プロパティを追加するバッファ; 省略されたときは
                                カレントバッファが使われる
                   id           プロパティのユーザー定義の ID; 数値でなければ
                                ならず、正であるべきである E1510; "text" を
                                使うときは、"id" の値はすべて無視され、負の数
                                値が自動的に割り当てられる; それ以外の場合は 0
                                が使われる
                                                        E1305
                   text         {col} の前、または {col} が 0 の場合は行の上/
                                下に表示されるテキスト; ハイライト付きのパディ
                                ングのために、前および/または後に空白を付ける;
                                "length"、"end_lnum"、および "end_col" と一緒
                                には使えない
                                詳しい情報は virtual-text を参照。
                                                        E1294
                   text_align   "text" が存在し、かつ {col} が 0 のとき; テキ
                                ストをどこに表示するかを指定する:
                                   after   行末の後
                                   right   ウィンドウ内で右寄せ (テキストが次
                                           の画面行に折り返さない限り)
                                   below   次の画面行に
                                   above   行のすぐ上に
                                省略されたときは "after" が使われる。各行には
                                "right" プロパティは 1 つしか収まらず、2 つ以
                                上ある場合、それらは別の行に置かれる (それでも
                                右寄せされる)。
                   text_padding_left                            E1296
                                "text" が存在し、かつ {col} が 0 のときに使わ
                                れる; テキスト行の終わり ("above" および
                                "below" では最も左の列) と仮想テキストの間のパ
                                ディング、ハイライトされない
                   text_wrap    "text" が存在し、かつ {col} が 0 のとき、テキ
                                ストが収まらない場合に何が起こるかを指定する:
                                   wrap      テキストを次の行に折り返す
                                   truncate  収まるようにテキストを切り詰める
                                省略されたときは "truncate" が使われる。
                                Note これは個々のテキストプロパティに適用され、
                                'wrap' オプションは全体の動作を設定することに
                                注意。"wrap" は 'wrap' オプションが設定されて
                                いるときにのみ効果がある; 'nowrap' では、テキ
                                ストはウィンドウの右端で切り詰められる。
                "type" 以外のすべてのフィールドは省略可能である。

                "length"、および "end_lnum" または "end_col" の両方が指定され
                たときはエラーである。1 行内のプロパティには "length" または
                "end_col" のどちらかを使うか、または複数行にわたるプロパティに
                は "end_lnum" および "end_col" を使う。
                "length" も "end_col" も指定されないとき、プロパティは幅 0 に
                なる。これは、一種のマークとして、テキストと一緒に移動すること
                を意味する。タイプがハイライトを指定している場合、1 文字がハイ
                ライトされる。
                プロパティは、テキストのちょうど最後の文字で終わるか、またはそ
                の直後で終わることができる。後者の場合、行にテキストが追加され
                た場合、プロパティタイプに "end_incl" が設定されていないときで
                も、テキストプロパティのサイズは増加する。

                "type" はまず、プロパティが追加されるバッファ内で検索される。
                見つからないときは、グローバルなプロパティタイプが使われる。見
                つからない場合、エラーが発生する。
                                                        virtual-text
                "text" が使われ、かつ列が 0 でないとき、このテキストはテキスト
                プロパティの指定された開始位置に表示される。バッファ行のテキス
                トは、場所を空けるためにずらされる。これは "仮想テキスト" と呼
                ばれる。
                列が 0 のとき、仮想テキストはバッファテキストの上、後、または
                下に表示される。"text_align" および "text_wrap" 引数が、それが
                どのように表示されるかを決める。
                仮想テキストをバッファテキストから分離するには、"text" フィー
                ルドの前および/または後に空白を付けるか、または
                "text_padding_left" の値を使う。

                これが仮想テキストであることをユーザーに明確にするハイライトを
                必ず使うこと、そうしないと、テキストが編集できないことがとても
                紛らわしくなる。"above" を使うときは、このテキストがその下のテ
                キスト行に属することを明確にする必要があり、"below" を使うとき
                は、それがその上のテキスト行に属することを確実にする必要があ
                る。

                テキストは表示されるが、実際のバッファ行の一部ではなく、カーソ
                ルをその上に置くことはできない。テキスト内でマウスをクリックす
                ると、カーソルはテキストの後の最初の文字、または行の最後の文字
                に移動する。
                テキスト内のタブおよびその他の制御文字はすべて空白に変更される
                (根拠: そうしないとテキストのサイズを計算するのが難しい)。
                負の "id" が選ばれ、返される。

                負の "id" は "text" を持つテキストプロパティ用に予約されてお
                り、それ以外には使えない。負の "id" を使うと E1293 になる。

                method としても使用できる:
                        GetLnum()->prop_add(col, props)

                戻り値の型: Number


prop_add_list({props}, [{item}, ...])                   prop_add_list()
                prop_add() と似ているが、バッファ内の複数の位置にテキストプロ
                パティを付加する。

                {props} はこれらのフィールドを持つ辞書である:
                   bufnr        プロパティを追加するバッファ; 省略されたときは
                                カレントバッファが使われる
                   id           プロパティのユーザー定義の ID; 数値でなければ
                                ならない; 省略されたときは 0 が使われる
                   type         テキストプロパティタイプの名前
                "type" 以外のすべてのフィールドは省略可能である。

                2 番目の引数は項目の List で、各 {item} はテキストの開始位置お
                よび終了位置を指定するリストである:
                [{lnum}, {col}, {end-lnum}, {end-col}]
                または:   [{lnum}, {col}, {end-lnum}, {end-col}, {id}]

                最初の 2 つの項目 {lnum} および {col} は、プロパティが付加され
                るテキストの開始位置を指定する。
                次の 2 つの項目 {end-lnum} および {end-col} は、テキストの直後
                の位置を指定する。
                省略可能な 5 番目の項目 {id} を使って、プロパティに異なる ID
                を与えることができる。省略されたときは {props} の ID が使われ、
                何も存在しない場合は 0 にフォールバックする。

                ここで "text" フィールドを持つテキストプロパティを追加すること
                はできない。

                例:
                        call prop_add_list(#{type: 'MyProp', id: 2},
                                        \ [[1, 4, 1, 7],
                                        \  [1, 15, 1, 20],
                                        \  [2, 30, 3, 30]])

                method としても使用できる:
                        GetProp()->prop_add_list([[1, 1, 1, 2], [1, 4, 1, 8]])

                戻り値の型: void


prop_clear({lnum} [, {lnum-end} [, {props}]])           prop_clear()
                行 {lnum} からすべてのテキストプロパティを削除する。
                {lnum-end} が指定されたときは、行 {lnum} から {lnum-end} まで
                (含む) のすべてのテキストプロパティを削除する。

                {props} に "bufnr" 項目が含まれているときはこのバッファを使い、
                そうでないときはカレントバッファを使う。

                method としても使用できる:
                        GetLnum()->prop_clear()

                戻り値の型: void


prop_find({props} [, {direction}])                      prop_find()
                {props} で指定されたテキストプロパティを検索する:
                   id           この ID を持つプロパティ
                   type         このタイプ名を持つプロパティ
                   both         "id" および "type" の両方がマッチしなければな
                                らない
                   bufnr        検索するバッファ; 存在するときは、"lnum" およ
                                び "col" による開始位置を指定しなければならな
                                い; 省略されたときはカレントバッファが使われる
                   lnum         この行で開始する (省略されたときはカーソル位置
                                で開始する)
                   col          この列で開始する (省略されて、かつ "lnum" が指
                                定されているとき: 列 1 を使い、そうでないとき
                                はカーソル位置で開始する)
                   skipstart    開始位置ではマッチを探さない

                "id" または "type" のどちらかがマッチするとき、プロパティはマッ
                チする。{direction} には、前方には "f"、後方には "b" を指定で
                きる。省略されたときは前方検索が行われる。

                マッチが見つかった場合、prop_list() と同様のエントリ、さらに
                "lnum" エントリを持つ Dict が返される。
                マッチが見つからない場合、空の Dict が返される。

                戻り値の型: dict<any>


prop_list({lnum} [, {props}])                           prop_list()
                行 {lnum} 内のすべてのテキストプロパティを含む List を返す。

                {props} では以下の省略可能な項目がサポートされている:
                   bufnr        カレントバッファの代わりにこのバッファを使う
                   end_lnum     {lnum} と {end_lnum} の間 (含む) のすべての行
                                のテキストプロパティを返す。
                                負の値は、バッファの最終行からのオフセットとし
                                て使われる; -1 はバッファの最終行を指す。
                   types        プロパティタイプ名の List。タイプ名のいずれか
                                にマッチするテキストプロパティのみを返す。
                   ids          プロパティ識別子の List。これらの識別子のいず
                                れかを持つテキストプロパティのみを返す。

                プロパティは開始列および優先度の順に並べられる。各プロパティ
                は、これらのエントリを持つ Dict である:
                   lnum         開始行番号。{lnum} と {end_lnum} の間のテキス
                                トプロパティを返すときにのみ存在する。
                   col          開始列
                   length       バイト単位の長さ、改行が含まれる場合は 1 多い
                   id           プロパティ ID
                   text         {col} の前に表示されるテキスト。virtual-text
                                プロパティにのみ存在する。
                   text_align   virtual-text の配置プロパティ。
                   text_padding_left
                                仮想テキストに使われる左パディング。
                   text_wrap    virtual-text が折り返されるかどうかを指定す
                                る。
                   type         プロパティタイプの名前、タイプが削除された場合
                                は省略される
                   type_bufnr   このタイプが定義されたバッファ番号; タイプがグ
                                ローバルの場合は 0
                   start        TRUE のとき、プロパティはこの行で始まる
                   end          TRUE のとき、プロパティはこの行で終わる

                "start" が 0 のとき、プロパティは前の行で始まっており、現在の
                行は続きである。
                "end" が 0 のとき、プロパティは次の行に続く。この行の後の改行
                は含まれる。

                エラーのときは空のリストを返す。

                例:
                   " 5 行目に置かれたテキストプロパティを取得する
                   echo prop_list(5)
                   " バッファ 4 の 20 行目に置かれたテキストプロパティを取得する
                   echo prop_list(20, {'bufnr': 4})
                   " 1 行目と 20 行目の間のすべてのテキストプロパティを取得する
                   echo prop_list(1, {'end_lnum': 20})
                   " タイプ 'myprop' のすべてのテキストプロパティを取得する
                   echo prop_list(1, {'types': ['myprop'],
                                                \ 'end_lnum': -1})
                   " タイプ 'prop1' または 'prop2' のすべてのテキストプロパティを取得する
                   echo prop_list(1, {'types': ['prop1', 'prop2'],
                                                \ 'end_lnum': -1})
                   " ID 8 を持つすべてのテキストプロパティを取得する
                   echo prop_list(1, {'ids': [8], 'end_lnum': line('$')})
                   " ID 10 および 20 を持つすべてのテキストプロパティを取得する
                   echo prop_list(1, {'ids': [10, 20], 'end_lnum': -1})
                   " バッファ 4 内の、タイプ 'myprop' および ID 100 を持つ
                   " テキストプロパティを取得する。
                   echo prop_list(1, {'bufnr': 4, 'types': ['myprop'],
                                        \ 'ids': [100], 'end_lnum': -1})

                method としても使用できる:
                        GetLnum()->prop_list()

                戻り値の型: list<dict<any>> または list<any>

                                                prop_remove() E968 E860
prop_remove({props} [, {lnum} [, {lnum-end}]])
                行 {lnum} からマッチするテキストプロパティを削除する。
                {lnum-end} が指定されたときは、行 {lnum} から {lnum-end} まで
                (含む) のマッチするテキストプロパティを削除する。
                {lnum} が省略されたときは、すべての行からマッチするテキストプ
                ロパティを削除する (これはすべての行を調べる必要があるので、行
                数の多いバッファでは少し遅くなる)。

                {props} はこれらのフィールドを持つ辞書である:
                   id           この ID を持つテキストプロパティを削除する
                   type         このタイプ名を持つテキストプロパティを削除する
                   types        この List 内のタイプ名を持つテキストプロパティ
                                を削除する
                   both         "id" および "type"/"types" の両方がマッチしな
                                ければならない
                   bufnr        カレントバッファの代わりにこのバッファを使う
                   all          TRUE のとき、最初のものだけでなく、マッチする
                                すべてのテキストプロパティを削除する
                "type" および "types" のうち 1 つだけを指定できる。 E1295

                "id"、または指定されたタイプのいずれかがマッチするとき、プロパ
                ティはマッチする。
                バッファ "bufnr" が存在しない場合、エラーメッセージが表示され
                る。
                バッファ "bufnr" が読み込まれていない場合、何も起こらない。

                削除されたプロパティの数を返す。

                method としても使用できる:
                        GetProps()->prop_remove()

                戻り値の型: Number

3. テキストが変更されたとき                     text-prop-changes

Vim は、テキストプロパティを付加されたテキスト上に保つよう最善を尽くす。テキス
トを挿入または削除するとき、変更の後のプロパティはそれに応じて移動する。

テキストが削除され、テキストプロパティがもはやテキストを含まなくなったとき、そ
れは削除される。ただし、幅 0 として定義されたテキストプロパティは、行全体が削
除されない限り残る。複数行の置換コマンドによって行が連結されるとき、削除された
行上の仮想テキストプロパティは、連結された結果の行に移動される。
                                                                E275
バッファがアンロードされると、すべてのテキストプロパティは失われる。プロパティ
をファイルに保存する方法はない。再作成することしかできない。バッファが隠されて
いるときは、テキストは保持され、テキストプロパティも保持される。アンロードされ
たバッファにテキストプロパティを追加することはできない。

置換モードを使うとき、文字自体が変わっても、テキストプロパティは同じ文字位置に
留まる。

テキストが変更された後にテキストプロパティを更新するには、listener_add() で
コールバックをインストールする。例えば、あなたのプラグインがスペルチェックを行
う場合、コールバックに、変更されたテキスト内のスペルミスを更新させることができ
る。Vim は変更されたテキストの下のプロパティを、それらが依然として同じテキスト
をハイライトするように移動するので、これらを更新する必要はない。

                                                        text-prop-cleared
テキストプロパティの列は更新またはコピーされない:

- setline() で、または Lua、Tcl、または Python のようなインターフェイスを通
  して行を設定するとき。Vim はどのテキストが挿入または削除されたかを知らない。
- :move のような、テキストの行を文脈から取り出すコマンドを使うとき。
