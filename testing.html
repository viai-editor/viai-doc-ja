Vim および Vim script のテスト                  testing-support

式の評価については eval.txt で説明されている。このファイルでは、Vim script
でテストを書くことについて詳しく扱う。これは Vim 自体のテストおよびプラグイン
のテストに使用できる。

1. Vim のテスト                         testing
2. テスト関数                           test-functions-details
3. アサート関数                         assert-functions-details

==============================================================================
1. Vim のテスト                                         testing

Vim はビルドした後に、通常は "make test" でテストできる。
テストはディレクトリ "src/testdir" にある。

時間とともに追加されてきた 2 種類のテストがある:
        test20.in               最も古い、tiny ビルド専用
        test_something.vim      新しいスタイルのテスト

                                                new-style-testing
新しいテストは新しいスタイルのテストとして追加すべきである。テストスクリプトは
test_<feature>.vim という名前になる (<feature> はテスト対象の機能に置き換え
る)。これらは assert_equal() などの関数を使い、テストコマンドおよび期待され
る結果を 1 か所にまとめておく。
                                                old-style-testing
これらのテストは、+eval 機能なしの Vim をテストするためだけに使われる。

さらなる情報はファイル src/testdir/README.txt にある。

2. テスト関数                                   test-functions-details

test_alloc_fail({id}, {countdown}, {repeat})            test_alloc_fail()
                これはテスト用である: {id} のメモリ割り当てが呼ばれた場合、
                {countdown} を減らし、それがゼロに達したとき、メモリ割り当てを
                {repeat} 回失敗させる。{repeat} が 1 より小さい場合、1 回失敗
                する。

                method としても使用できる:
                        GetAllocId()->test_alloc_fail()

                戻り値の型: void


test_autochdir()                                        test_autochdir()
                Vim の起動が完了する前に 'autochdir' の効果を有効にするフラグ
                を設定する。

                戻り値の型: void


test_feedinput({string})                                test_feedinput()
                {string} 内の文字は、ユーザーによってタイプされたかのように、
                処理のためにキューに入れられる。これは低レベルの入力バッファを
                使用する。この関数は +unix があるか、または GUI が実行中のと
                きのみ動作する。

                method としても使用できる:
                        GetText()->test_feedinput()

                戻り値の型: void


test_garbagecollect_now()                        test_garbagecollect_now()
                garbagecollect() と同様だが、すぐに実行される。内部に何らか
                の構造体が存在するのを避けるため、これは直接呼び出されなければ
                ならず、また、関数を呼び出す前に v:testing が設定されていな
                ければならない。   E1142
                これは :def 関数から呼び出されたときは動作しない。スタック上の
                変数が解放されるからである。

                戻り値の型: void

test_garbagecollect_soon()                       test_garbagecollect_soon()
                メインループ内にいるかのようにガベージコレクタを呼び出すフラグ
                を設定する。テストでのみ使用される。

                戻り値の型: void

test_getvalue({name})                                   test_getvalue()
                内部変数の値を取得する。{name} にはこれらの値がサポートされて
                いる:
                        need_fileinfo

                method としても使用できる:
                        GetName()->test_getvalue()

                戻り値の型: Number

                                                test_gui_event()
test_gui_event({event}, {args})
                Vim の機能をテストするために、引数 {args} を伴う GUI {event}
                を生成する。この関数は GUI が実行中のときのみ動作する。

                {event} は文字列であり、サポートされている値は:
                    "dropfiles" ウィンドウに 1 つ以上のファイルをドロップする。
                    "findrepl"  テキストを検索および置換する。
                    "mouse"     マウスボタンのクリックイベント。
                    "scrollbar" スクロールバーを移動するか、またはドラッグする。
                    "key"       低レベルのキーボードイベントを送る。
                    "tabline"   マウスクリックでタブページを選択する。
                    "tabmenu"   タブラインのメニュー項目を選択する。

                {args} は辞書であり、イベントの引数を含む。

                "dropfiles":
                  指定されたウィンドウに 1 つ以上のファイルをドロップする。
                  {args} でサポートされている項目は:
                    files:      ファイル名のリスト
                    row:        ウィンドウの行番号
                    col:        ウィンドウの列番号
                    modifiers:  キー修飾子。サポートされている値は:
                                    0x4 Shift
                                    0x8 Alt
                                   0x10 Ctrl
                  ファイルは argument-list に追加され、{files} の最初のファ
                  イルがウィンドウで編集される。さらなる情報は drag-n-drop
                  を参照。このイベントは drop_file 機能が存在するときのみ動
                  作する。

                "findrepl":
                  {Vim の GUI に検索/置換ダイアログがあるときのみ使用可能}
                  テキストの検索および置換を実行する。{args} でサポートされて
                  いる項目は:
                    find_text:  検索する文字列。
                    repl_text:  置換文字列。
                    flags:      検索/置換を制御するフラグ。サポートされている
                                値は:
                                    1   次の文字列を検索する (検索ダイアログ)
                                    2   次の文字列を検索する (置換ダイアログ)
                                    3   文字列を 1 回置換する
                                    4   すべてのマッチを置換する
                                    8   単語全体にのみマッチする
                                   16   大文字小文字を区別する
                    forward:    前方検索には 1 に設定する。

                "mouse":
                  マウスボタンのクリック、またはマウスの移動のどちらかのイベン
                  トを注入する。{args} でサポートされている項目は:
                    button:     マウスボタン。サポートされている値は:
                                    0   マウスの左ボタン
                                    1   マウスの中ボタン
                                    2   マウスの右ボタン
                                    3   マウスボタンのリリース
                                    4   スクロールホイールを下
                                    5   スクロールホイールを上
                                    6   スクロールホイールを左
                                    7   スクロールホイールを右
                    row:        マウスクリックの行番号。Vim ウィンドウの最初の
                                行は 1 で、最後の行は 'lines' である。
                    col:        マウスクリックの列番号。{col} の最大値は
                                'columns' である。
                    multiclick: マルチクリックのマウスイベントを注入するには 1
                                に設定する。
                    modifiers:  キー修飾子。サポートされている値は:
                                    4   shift が押されている
                                    8   alt が押されている
                                   16   ctrl が押されている
                    move:       省略可能; 使用されていて TRUE の場合、マウス移
                                動イベントを生成できる。
                                {args} の row: および col: のみが使用され、必
                                須である; それらは "cell" に応じて、ピクセルま
                                たはスクリーンセルとして解釈される。
                                'mousemoveevent' が設定されているか、またはポッ
                                プアップがマウス移動イベントを使用しているとき
                                のみ、イベントになる。
                    cell:       省略可能: 存在して TRUE のとき、"move" はピク
                                セル位置の代わりにスクリーンセルを使用する

                "scrollbar":
                  左、右、または水平のスクロールバーを設定するか、またはドラッ
                  グする。スクロールバーが実際に存在するときのみ動作する。
                  {args} でサポートされている項目は:
                    which:      スクロールバーを選択する。サポートされている値
                                は:
                                    left  カレントウィンドウの左スクロールバー
                                    right カレントウィンドウの右スクロールバー
                                    hor   水平スクロールバー
                    value:      スクロールする量。垂直スクロールバーでは、値は
                                0 からバッファの行数マイナス 1 までの間にでき
                                る。水平スクロールバーでは、'wrap' が設定され
                                ていないと仮定して、値は 1 と最大の行の長さの
                                間にできる。
                    dragging:   スクロールバーをドラッグするには 1、およびスク
                                ロールバー内をクリックするには 0。

                "key":
                  低レベルのキーボードイベントを送る (例: key-up または down)。
                  現在は MS-Windows でのみサポートされている。
                  {args} でサポートされている項目は:
                    event:      サポートされている文字列の値は:
                                    keyup   keyup イベントを生成する
                                    keydown keydown イベントを生成する
                    keycode:    keyup または keydown イベントに使用するキーコー
                                ド。
                                                                E1291

                "tabline":
                  タブページを選択するために、タブライン上でマウスクリックイベ
                  ントを注入する。{args} でサポートされている項目は:
                    tabnr:      タブページ番号

                "tabmenu":
                  タブラインのメニュー項目を選択するイベントを注入する。{args}
                  でサポートされている項目は:
                    tabnr:      タブページ番号
                    item:       タブページのメニュー項目番号。最初のメニュー項
                                目は 1、2 番目の項目は 2、以下同様。

                GUI イベントを注入した後、それらを処理させるために、おそらく
                feedkeys() を呼び出すべきである。例:
                        call feedkeys("y", 'Lx!')

                イベントの追加に成功した場合は TRUE を返し、失敗した場合は
                FALSE を返す。

                method としても使用できる:
                        GetEvent()->test_gui_event({args})

                戻り値の型: vim9-boolean

test_ignore_error({expr})                        test_ignore_error()
                {expr} を含むエラーをすべて無視する。代わりに通常のメッセージ
                が表示される。
                これは、try/catch でエラーを捕捉することが使えない (後続のコー
                ドを飛ばしてしまうため) テストでのみ使われることを意図してい
                る。
                {expr} はパターンとしてではなく、文字どおりに使われる。
                {expr} が文字列 "RESET" の場合、無視されるエラーのリストは空に
                される。

                method としても使用できる:
                        GetErrorText()->test_ignore_error()

                戻り値の型: void

test_mswin_event({event}, {args})               test_mswin_event()
                Vim の機能をテストするために、引数 {args} を伴う低レベルの
                MS-Windows {event} を生成する。MS-Windows の GUI およびコンソー
                ルで動作する。

                {event} は文字列であり、サポートされている値は:
                    "mouse"     マウスイベント。
                    "key"       キーボードイベント。
                    "set_keycode_trans_strategy"
                                キー変換方式を変更する。

                "mouse":
                  マウスボタンのクリック、またはマウスの移動のどちらかのイベン
                  トを注入する。{args} でサポートされている項目は:
                    button:     マウスボタン。サポートされている値は:
                                    0   マウスの右ボタン
                                    1   マウスの中ボタン
                                    2   マウスの左ボタン
                                    3   マウスボタンのリリース
                                    4   スクロールホイールを下
                                    5   スクロールホイールを上
                                    6   スクロールホイールを左
                                    7   スクロールホイールを右
                    row:        マウスクリックの行番号。Vim ウィンドウの最初の
                                行は 1 で、最後の行は 'lines' である。
                    col:        マウスクリックの列番号。{col} の最大値は
                                'columns' である。
                                Note: row および col は、コンソールアプリケー
                                ションでは常にスクリーンセルとして解釈される。
                                しかし、GUI では "cell" に応じてピクセルとして
                                解釈されることがある。
                    multiclick: ダブルクリックのマウスイベントを注入するには 1
                                に設定する。
                    modifiers:  キー修飾子。サポートされている値は:
                                    4   shift が押されている
                                    8   alt が押されている
                                   16   ctrl が押されている
                    move:       省略可能; 使用されていて TRUE の場合、マウス移
                                動イベントを生成できる。
                                {args} の row: および col: のみが使用され、必
                                須である。
                                'mousemoveevent' が設定されているか、またはポッ
                                プアップがマウス移動イベントを使用しているとき
                                のみ、イベントになる。
                    cell:       GUI では省略可能: 存在して TRUE のとき、"move"
                                はピクセル位置の代わりにスクリーンセルを使用す
                                る。コンソールでは使用されない。

                "key":
                  低レベルのキーボードイベントを送る (例: keyup または
                  keydown)。{args} でサポートされている項目は:
                    event:      サポートされている文字列の値は:
                                    keyup   keyup イベントを生成する
                                    keydown keydown イベントを生成する
                    keycode:    keyup または keydown イベントに使用するキーコー
                                ド。
                    modifiers:  省略可能; キー修飾子。
                                サポートされている値は:
                                    2   shift が押されている
                                    4   ctrl が押されている
                                    8   alt が押されている
                                Note: これらの値はマウスの修飾子とは異なる。
                    execute:    省略可能。feedkeys() のモード x と同様。これ
                                が含まれていて true (非ゼロ) に設定されている
                                場合、Vim はバッファリングされた未処理のキーイ
                                ベントをすべて処理する。これが設定されていて
                                true のとき、他の {args} の項目はすべて省略可
                                能である。

                "set_keycode_trans_strategy":
                  w32-experimental-keycode-trans-strategy
                  キーコード変換方式を切り替える。サポートされている方式は:
                    experimental:   ToUnicode() Win API 呼び出しを使用
                                            する、Patch v8.2.4807 以降に使われ
                                            る方式。
                    classic:        TranslateMessage() Win API 呼び出
                                            しを使用する、Patch v8.2.4807 より
                                            前に使われていた方式。

                イベントの追加または実行に成功した場合は TRUE を返し、失敗した
                場合は FALSE を返す。

                method としても使用できる:
                        GetEvent()->test_mswin_event({args})

                戻り値の型: vim9-boolean

test_option_not_set({name})                             test_option_not_set()
                オプション {name} が設定されたことを示すフラグをリセットする。
                したがって、それはまだ既定値を持っているように見える。このよう
                に使用する:
                        set ambiwidth=double
                        call test_option_not_set('ambiwidth')
                これで、値が "double" であるにもかかわらず、'ambiwidth' オプ
                ションは一度も変更されなかったかのように振る舞う。
                テストでのみ使用すること!

                method としても使用できる:
                        GetOptionName()->test_option_not_set()

                戻り値の型: void

test_override({name}, {val})                            test_override()
                テストを実行できるように、Vim の内部処理の特定の部分を上書きす
                る。Vim のテストでのみ使用すること!
                {val} が非ゼロのときに上書きが有効になり、{val} がゼロのときに
                解除される。
                {name} に現在サポートされている値は:

                {name}       {val} が非ゼロのときの効果
                alloc_lines  valgrind でメモリアクセスエラーを見つけられるよう
                             に、すべてのバッファ行のコピーを割り当てられたメ
                             モリに作成する。
                autoload     import autoload が、項目が使われるまで延期せず
                             に、すぐにスクリプトを読み込む。
                char_avail   char_avail() 関数を無効にする。
                defcompile   読み込まれたスクリプト内のすべての :def 関数が、
                             定義されたときにコンパイルされる。これはスクリプ
                             ト内で :defcompile コマンドを使うのと同様であ
                             る。
                nfa_fail     古いエンジンへのフォールバックを強制するために、
                             NFA 正規表現エンジンを失敗させる。
                no_query_mouse  "dec" 端末に対してマウス位置を問い合わせない。
                no_wait_return  "no_wait_return" フラグを設定する。"ALL" では
                                元に戻されない。
                redraw       redrawing() 関数を無効にする。
                redraw_flag  RedrawingDisabled フラグを無視する。
                starting     "starting" 変数をリセットする。以下を参照。
                syn_idlist_cache        構文の "contains"/cluster リストを解決
                                        するためのキャッシュを無効にする。
                term_props   バージョン文字列が検出されたときに、すべての端末
                             プロパティをリセットする。
                ui_delay     ui_delay() で使用するミリ秒単位の時間; メッセージ
                             に対する最大 3 秒の待ち時間に優先する。
                unreachable  :throw および :return の後のコードに対してエ
                             ラーを出さない。
                uptime       sysinfo.uptime に優先する。
                vterm_title  端末ウィンドウで実行中のジョブによるウィンドウタ
                             イトルの設定。
                ALL          alloc_lines を除くすべての上書きをクリアする
                             ({val} は使用されない)。

                "starting" は、テストが起動が完了したかのように振る舞うべきと
                きに使用する。テストはスクリプトを読み込むことで実行されるの
                で、"starting" 変数は非ゼロである。これは通常は良いこと (テス
                トがより速く実行される) だが、時にはこれが、テストが正しく動作
                しないような形で振る舞いを変える。
                以下を使用すると:
                        call test_override('starting', 1)
                "starting" の値が保存される。それは以下で復元される:
                        call test_override('starting', 0)

                後でフラグが確実にリセットされるようにするには、:defer を使
                うと便利なことがある:
                        call test_override('unreachable', 1)
                        defer call test_override('unreachable', 0)

                method としても使用できる:
                        GetOverrideVal()-> test_override('starting')

                戻り値の型: void

test_refcount({expr})                                   test_refcount()
                {expr} の参照カウントを返す。{expr} が参照カウントを持たない型
                の場合、-1 を返す。テストでのみ使用すること。

                method としても使用できる:
                        GetVarname()->test_refcount()

                戻り値の型: Number

test_setmouse({row}, {col})                             test_setmouse()
                次のマウス操作に使用されるマウス位置を設定する。{row} および
                {col} は 1 から始まる。
                例:
                        call test_setmouse(4, 20)
                        call feedkeys("\<LeftMouse>", "xt")

                戻り値の型: void


test_settime({expr})                                    test_settime()
                Vim が内部で使用する時刻を設定する。現在は、viminfo で使用され
                るとおりの履歴内のタイムスタンプ、および undo にのみ使用され
                る。
                値 1 を使用すると、Vim は警告またはエラーメッセージの後にスリー
                プしなくなる。
                {expr} は数値に評価されなければならない。値がゼロの場合、通常
                の振る舞いが復元される。

                method としても使用できる:
                        GetTime()->test_settime()

                戻り値の型: void

test_srand_seed([{seed}])                               test_srand_seed()
                {seed} が指定された場合、これは srand() で使用されるシード値
                を設定する。省略された場合、テスト用のシードは削除される。

                戻り値の型: void

test_unknown()                                          test_unknown()
                unknown 型の値を返す。テストでのみ有用。

                戻り値の型: unknown

test_void()                                             test_void()
                void 型の値を返す。テストでのみ有用。

                戻り値の型: void

3. アサート関数                                 assert-functions-details


assert_beeps({cmd})                                     assert_beeps()
                {cmd} を実行し、それがビープまたはビジュアルベルを発生させない
                場合、v:errors にエラーメッセージを追加する。
                assert_fails()、assert_nobeep()、および assert-return も
                参照。

                method としても使用できる:
                        GetCmd()->assert_beeps()

                戻り値の型: Number

                                                        assert_equal()
assert_equal({expected}, {actual} [, {msg}])
                {expected} および {actual} が等しくない場合、v:errors にエ
                ラーメッセージが追加され、1 が返される。そうでない場合はゼロが
                返される。assert-return エラーは
                "Expected {expected} but got {actual}" という形式である。{msg}
                が存在する場合、スクリプトから実行されたときはアサートの位置と
                ともに、それがその前に付けられる。

                自動的な変換はなく、文字列 "4" は数値 4 とは異なる。そして、数
                値 4 は浮動小数点数 4.0 とは異なる。ここでは 'ignorecase' の値
                は使われず、大文字小文字は常に区別される。
                例:
                        call assert_equal('foo', 'bar', 'baz')
                以下を v:errors に追加する:
                        test.vim line 12: baz: Expected 'foo' but got 'bar'

                method としても使用でき、ベースは 2 番目の引数として渡される:

                        mylist->assert_equal([1, 2, 3])

                戻り値の型: Number

                                                        assert_equalfile()
assert_equalfile({fname-one}, {fname-two} [, {msg}])
                ファイル {fname-one} および {fname-two} が完全に同じテキストを
                含まない場合、v:errors にエラーメッセージが追加される。
                assert-return も参照。
                {fname-one} または {fname-two} が存在しない場合、エラーはその
                ことに言及する。
                主に terminal-diff とともに有用。

                method としても使用できる:
                        GetLog()->assert_equalfile('expected.log')

                戻り値の型: Number

assert_exception({error} [, {msg}])                     assert_exception()
                v:exception が文字列 {error} を含まない場合、v:errors にエ
                ラーメッセージが追加される。assert-return も参照。これは、コ
                マンドが例外を投げることをアサートするのに使用できる。エラー番
                号の後にコロンを付けて使うと、翻訳の問題を避けられる:
                        try
                          commandthatfails
                          call assert_false(1, 'command should have failed')
                        catch
                          call assert_exception('E492:')
                        endtry

                戻り値の型: Number

                                                        assert_fails()
assert_fails({cmd} [, {error} [, {msg} [, {lnum} [, {context}]]]])
                {cmd} を実行し、それがエラーを発生させない場合、またはエラー
                メッセージ内に {error} が見つからない場合、v:errors にエラー
                メッセージを追加する。assert-return も参照。
                                                        E856
                {error} が文字列の場合、それは最初に報告されたエラー内で文字ど
                おりに見つからなければならない。ほとんどの場合、これはコロンを
                含むエラーコード、例えば "E123:" になる。
                        call assert_fails('bad cmd', 'E987:')

                {error} が 1 つまたは 2 つの文字列を持つ List の場合、それら
                はパターンとして使われる。最初のパターンは最初に報告されたエ
                ラーに対してマッチされる:
                        call assert_fails('cmd', ['E987:.*expected bool'])
                2 番目のパターンは、存在する場合、最後に報告されたエラーに対し
                てマッチされる。
                エラーが 1 つだけの場合、両方のパターンがマッチしなければなら
                ない。
                これは、エラーが 1 つだけであることを確認するのに使用できる。
                最後のエラーだけにマッチさせるには、最初のエラーに空文字列を使
                う:
                        call assert_fails('cmd', ['', 'E987:'])

                {msg} が空の場合、それは使われない。{lnum} 引数を渡すときに既
                定のメッセージを得るには、こうする。
                                                        E1115
                {lnum} が存在して負でなく、かつ {error} 引数が存在してマッチす
                る場合、これはエラーが報告された行番号と比較される。それは関数
                内またはスクリプト内の行番号である可能性がある。
                                                        E1116
                {context} が存在する場合、それはパターンとして使われ、{lnum}
                がある場所のコンテキスト (スクリプト名または関数名) に対して
                マッチされる。

                Note ビープはエラーとはみなされず、一部の失敗するコマンドはビー
                プを鳴らすだけであることに注意。それらには assert_beeps() を
                使用すること。

                method としても使用できる:
                        GetCmd()->assert_fails('E99:')

                戻り値の型: Number

assert_false({actual} [, {msg}])                        assert_false()
                {actual} が false でない場合、assert_equal() と同様に、
                v:errors にエラーメッセージが追加される。
                エラーは "Expected False but got {actual}" という形式である。
                {msg} が存在する場合、スクリプトから実行されたときはアサートの
                位置とともに、それがその前に付けられる。
                assert-return も参照。

                値はゼロのときに false である。{actual} が数値でない場合、ア
                サートは失敗する。

                method としても使用できる:
                        GetResult()->assert_false()

                戻り値の型: Number

assert_inrange({lower}, {upper}, {actual} [, {msg}])     assert_inrange()
                これは数値および Float の値をアサートする。{actual} が
                {lower} より小さいか、または {upper} より大きい場合、
                v:errors にエラーメッセージが追加される。assert-return も
                参照。
                エラーは "Expected range {lower} - {upper}, but got {actual}"
                という形式である。{msg} が存在する場合、それがその前に付けられ
                る。

                戻り値の型: Number

                                                                assert_match()
assert_match({pattern}, {actual} [, {msg}])
                {pattern} が {actual} にマッチしない場合、v:errors にエラー
                メッセージが追加される。assert-return も参照。
                エラーは "Pattern {pattern} does not match {actual}" という形
                式である。{msg} が存在する場合、スクリプトから実行されたときは
                アサートの位置とともに、それがその前に付けられる。

                {pattern} は =~ と同様に使われる: マッチングは、'magic' また
                は 'cpoptions' の実際の値が何であるかに関係なく、常に 'magic'
                が設定され、'cpoptions' が空であるかのように行われる。

                {actual} は文字列として使われ、自動的な変換が適用される。テキ
                ストの先頭および末尾にマッチさせるには "^" および "$" を使う。
                テキスト全体にマッチさせるには両方を使う。

                例:
                        call assert_match('^f.*o$', 'foobar')
                結果として、文字列が v:errors に追加される:
                        test.vim line 12: Pattern '^f.*o$' does not match 'foobar'

                method としても使用できる:
                        getFile()->assert_match('foo.*')

                戻り値の型: Number

assert_nobeep({cmd})                                    assert_nobeep()
                {cmd} を実行し、それがビープまたはビジュアルベルを発生させた場
                合、v:errors にエラーメッセージを追加する。
                assert_beeps() も参照。

                method としても使用できる:
                        GetCmd()->assert_nobeep()

                戻り値の型: Number

                                                        assert_notequal()
assert_notequal({expected}, {actual} [, {msg}])
                assert_equal() の反対: {expected} および {actual} が等しいと
                き、v:errors にエラーメッセージを追加する。
                assert-return も参照。

                method としても使用できる:
                        mylist->assert_notequal([1, 2, 3])

                戻り値の型: Number

                                                        assert_notmatch()
assert_notmatch({pattern}, {actual} [, {msg}])
                assert_match() の反対: {pattern} が {actual} にマッチすると
                き、v:errors にエラーメッセージを追加する。
                assert-return も参照。

                method としても使用できる:
                        getFile()->assert_notmatch('bar.*')

                戻り値の型: Number

assert_report({msg})                                    assert_report()
                文字列 {msg} を使って、テストの失敗を直接報告する。
                常に 1 を返す。

                method としても使用できる:
                        GetMessage()->assert_report()

                戻り値の型: Number


assert_true({actual} [, {msg}])                         assert_true()
                {actual} が true でない場合、assert_equal() と同様に、
                v:errors にエラーメッセージが追加される。
                assert-return も参照。
                値は非ゼロの数値のときに TRUE である。{actual} が数値でない場
                合、アサートは失敗する。
                {msg} が指定された場合、スクリプトから実行されたときはアサート
                の位置とともに、それが既定のメッセージの前に付けられる。

                method としても使用できる:
                        GetResult()->assert_true()

                戻り値の型: Number
