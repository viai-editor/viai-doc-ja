Vim と Vi の違い                                        vi-differences

このファイルは Vim と Vi/Ex の違いを一覧にし、Vi にはなくて Vim にあるものの概
要を示す。

Vim はほぼ POSIX 1003.2-1 に準拠している。欠けていることが分かっている唯一のコ
マンドは ":open" である。おそらく小さな違いはたくさんある (Vim に何かが欠けて
いるためか、または Posix が的外れであるため)。

2. 存在しないオプション                 missing-options
3. 制限                                 limits
4. 最も興味深い追加                     vim-additions
5. その他の vim の機能                  other-features
6. サポートされている Vi の機能         vi-features

9. サポートされているオペレーティングシステム   os-support

==============================================================================
1. シミュレートされたコマンド                           simulated-command

このコマンドは Vi にあるが、Vim はそれをシミュレートするだけである:

                                                        :o :op :open
:[range]o[pen]                  :visual のように動作する: Ex モードを終了す
                                る。
                                {Vi: オープンモードで編集を開始する}

:[range]o[pen] /pattern/        上記と同様で、加えて、カーソル行で "pattern"
                                がマッチするカラムへカーソルを移動する。

Vim はオープンモードをサポートしていない。実際にはあまり役に立たないからであ
る。":open" がオープンモードを開始するであろう状況では、Vim は Ex モードを終了
し、それにより同じコマンドを実行できるが、1 行だけではなく画面全体を更新する。

==============================================================================
2. 存在しないオプション                                 missing-options

これらのオプションは Unix の Vi にはあるが、Vim にはない。これらのいずれかを設
定しようとした場合、エラーメッセージは出ないが、値は使用されず、表示することも
できない。

beautify (bf)           切替    (デフォルトはオフ)      'beautify' 'bf'
flash (fl)              切替    (デフォルトはオン)      'flash' 'fl'
graphic (gr)            切替    (デフォルトはオフ)      'graphic' 'gr'
hardtabs (ht)           数値    (デフォルトは 8)        'hardtabs' 'ht'
        <Tab> が画面上で移動するスペースの数
mesg                    切替    (デフォルトはオン)      'mesg'
novice                  切替    (デフォルトはオフ)      'novice'
open                    切替    (デフォルトはオン)      'open'
optimize (op)           切替    (デフォルトはオフ)      'optimize' 'op'
redraw                  切替    (デフォルトはオフ)      'redraw'
slowopen (slow)         切替    (デフォルトはオフ)      'slowopen' 'slow'
sourceany               切替    (デフォルトはオフ)      'sourceany'
w300                    数値    (デフォルトは 23)       'w300'
w1200                   数値    (デフォルトは 23)       'w1200'

再試行する必要があった。Vim には terminal-options がある。

3. 制限                                                 limits

Vim には編集できるファイルについての制限がわずかしかない {Vi: <Nul> 文字および
128 より上の文字を扱えず、行の長さが制限され、他にも多くの制限がある}。

行の最大長                 2147483647 文字。それより長い行は分割される。
最大行数                   2147483647 行。
最大ファイルサイズ         long 整数が 32 ビットの場合、2147483647 バイト (2
                           Gbyte)。64 ビットの long ではずっと大きい。
                           swap-file のための使用可能なディスク容量によって
                           も制限される。
                                                        E75
ファイルパスの長さ         Unix および Win32: 1024 文字、それ以外は 256 文字
                           (またはシステムがサポートするだけ)。
展開された文字列オプションの長さ
                           Unix および Win32: 1024 文字、それ以外は 256 文字
最大表示幅                 Unix および Win32: 1024 文字、それ以外は 255 文字
マッピングの lhs の最大長  50 文字。
異なるハイライトの種類の数: 30000 以上
Number 変数の範囲:         -2147483648 から 2147483647 (64 ビットシステムでは
                           もっと大きいかもしれない)  以下も参照:
                           v:numbermax、v:numbermin および v:numbersize
タグファイルの行の最大長: 512 バイト。
                                                        E1541
/\U および /\%U の最大値: 2147483647 (32bit 整数の場合)。

undo の情報およびレジスタ内のテキストはメモリに保持されるので、(大きな) 変更を
行う場合、使用可能な (仮想) メモリの量が、undo レベルの数およびレジスタに保持
できるテキストを制限する。他のものもメモリに保持される:  コマンドライン履歴、
Quickfix モードのエラーメッセージなど。

メモリ使用量の制限
------------------

オプション 'maxmem' ('mm') は 1 つのバッファに使用される最大メモリ (キロバイト
単位) を設定するために使用される。'maxmemtot' はすべてのバッファに使用される最
大メモリ (キロバイト単位) を設定するために使用される。デフォルト値は使用される
システムに依存する。Amiga では、'maxmemtot' は使用可能なメモリの量に応じて設定
される。
これらは厳密な制限ではなく、いつテキストをスワップファイルに移すかを Vim に伝
えるものである。Vim がファイルへスワップするのを好まない場合、'maxmem' および
'maxmemtot' をとても大きな値に設定する。そうするとスワップファイルは回復のため
だけに使用される。スワップファイルがまったく必要ない場合、'updatecount' を 0
に設定するか、または Vim の起動時に "-n" 引数を使用する。

4. 最も興味深い追加                                     vim-additions

Vi 互換。                                               'compatible'
        Vim は 99% Vi 互換だが、Vi のいくつかのことはバグであると見なされうる
        か、または少なくとも改善が必要である。それでも、Vim は可能な限り
        "本物の" Vi のように振る舞うモードで起動する。Vim をもう少し良く振る舞
        わせるには、'compatible' オプションをリセットしてみること:
                :set nocompatible
        または "-N" 引数を付けて Vim を起動する:
                vim -N
        .vimrc ファイルがある場合、Vim は自動的に 'nocompatible' で起動する。
        startup を参照。
        'cpoptions' オプションを使用して、いくつかの特定の項目について Vi 互換
        をオン/オフに設定できる。

異なるシステムのサポート。
        Vim は以下で使用できる:
        - すべての Unix システム (テストされたすべてのシステムで動作するが、
          GUI および Perl インターフェイスはどこでも動作するとは限らない)。
        - Amiga (500, 1000, 1200, 2000, 3000, 4000, ...).
        - MS-Windows
        - VMS
        - Macintosh
        - IBM OS/390
        Note 一部のシステムではリソース使用量を減らすために機能を無効にする必
        要があることに注意。一部の時代遅れのシステムでは、より古いバージョンの
        Vim を使用する必要がある。

多段階の永続的な undo。                                         undo
        'u' は時間を遡り、'CTRL-R' は再び進む。オプション 'undolevels' に記憶
        される変更の数を設定する (デフォルトは 1000)。Vi 互換の 1 段階の undo
        にするには 'undolevels' を 0 に設定する。まったく undo しないようにす
        るには -1 に設定する。
        バッファ内のすべての変更が undo されると、そのバッファは変更されたとは
        見なされなくなる。:q で、<!> なしでそこから抜けられる。いくつかの変更
        を undo してから新しい変更を行うと、Vim は undo ツリーにブランチを作成
        する。これは、テキストの任意の状態に戻ることができ、変更によってテキス
        トが永久に失われる危険がないことを意味する。undo-tree
        'undofile' オプションが設定されている場合、undo 情報はファイルに保存さ
        れる。これは、Vim を終了し、以前に編集したファイルで Vim を起動して、
        Vim の終了前に行われた変更を undo できることを意味する。

グラフィカルユーザーインターフェイス (GUI)。            gui
        GUI のサポートを含む: メニュー、マウス、スクロールバーなど。独自のメ
        ニューを定義できる。特殊キーおよびマウスと組み合わせた CTRL/SHIFT/ALT
        キーのサポートが改善された。Motif 付きの X11、GTK、Win32 (Windows XP
        以降)、Amiga および Macintosh など、さまざまなプラットフォームでサポー
        トされている。

複数のウィンドウとバッファ。                            windows.txt
        Vim は画面を複数のウィンドウに分割でき、それぞれ異なるバッファ、または
        同じバッファの異なる位置を編集できる。バッファは、ウィンドウに表示され
        ないまま、読み込まれた (および変更された) 状態にできる。これは隠しバッ
        ファと呼ばれる。この機能のために多くのコマンドおよびオプションが追加さ
        れた。
        Vim は複数のタブページも使用でき、それぞれに 1 つ以上のウィンドウがあ
        る。タブラベルのある行を使用して、これらのページを素早く切り替えること
        ができる。
        tab-page

端末ウィンドウ。                                        :terminal
        Vim は端末エミュレーターが動作するウィンドウを作成できる。これは任意の
        コマンド、シェル、またはデバッガーを実行するために使用できる。

構文ハイライト。                                        :syntax
        Vim はキーワード、パターン、およびその他のものをハイライトできる。これ
        は多数の :syntax コマンドによって定義され、ほとんどの言語およびファ
        イルタイプをハイライトするようにできる。C、C++、Java、Pascal、
        Makefile、シェルスクリプトなど、最も一般的な言語をハイライトするための
        多数のファイルが含まれている。ハイライトに使用される色は、:highlight
        コマンドで、通常の端末、カラー端末、および GUI について定義できる。こ
        れを行う便利な方法は :colorscheme コマンドを使用することである。
        ハイライトされたテキストは HTML としてエクスポートできる。
        convert-to-HTML
        ハイライトできる他の項目は、検索文字列とのマッチ 'hlsearch'、対応する
        括弧 matchparen、およびカーソルの行および列 'cursorline'
        'cursorcolumn' である。

テキストプロパティ                                      textprop.txt
        Vim はプラグインによるテキストのハイライトをサポートする。プロパティタ
        イプは prop_type_add() で指定でき、プロパティは prop_add() で配置
        できる。

スペルチェック。                                        spell
        'spell' オプションが設定されている場合、Vim はスペルミスをハイライトす
        る。現在、約 50 の言語がサポートされており、'spelllang' オプションで選
        択する。ソースコードでは、コメントおよび文字列だけがスペルチェックされ
        る。

折り畳み。                                              folding
        行の範囲を 1 つの "折り畳まれた" 行として表示できる。これにより、ファ
        イルの概観およびテキストのブロックの素早い移動が可能になる。
        折り畳みは、手動で、ファイルの構文から、インデントによって、などで作成
        できる。

差分モード。                                            diff
        Vim はファイルの 2 つのバージョンを、違いをハイライトして表示できる。
        テキストの等しい部分は折り畳まれる。コマンドを使用して、一方のバージョ
        ンから他方へテキストを移動できる。

プラグイン。                                            add-plugin
        プラグインファイルを適切なディレクトリに置くことで機能を拡張できる。こ
        れは他の人が書いた Vim script を使い始める簡単な方法である。プラグイン
        は、すべての種類のファイル用、または特定のファイルタイプ専用にできる。
        パッケージはこれをさらに簡単にする。packages

非同期通信とタイマー。                          channel job timer
        Vim はバックグラウンドで他のプロセスとメッセージを交換できる。これによ
        り、サーバーに処理をさせて結果を Vim に送り返させることが可能になる。
        channel
        Vim はジョブを開始し、それと通信し、それを停止できる。job
        タイマーは 1 回または繰り返し発火し、任意の処理を行う関数を呼び出せる。
        timer

一連のコマンドの繰り返し。                              q
        "q{c}" は、タイプした文字の名前付きレジスタ {c} への記録を開始する。
        続く "q" で記録が停止する。その後、レジスタは "@{c}" コマンドで実行で
        きる。これは複雑な動作を繰り返すのにとても便利である。

柔軟な挿入モード。                                      ins-special-special
        挿入モードで矢印キーを使用してファイル内を移動できる。これにより、undo
        および redo に関する限り、挿入は 2 つの部分に分割される。

        CTRL-O を使用して、単一のノーマルモードコマンドを実行できる。これは
        <Esc> を押し、コマンドをタイプし、a を行うのとほぼ同じである。

ビジュアルモード。                                      Visual-mode
        ビジュアルモードを使用して、まずテキストの一部をハイライトし、それから
        それに対して何かを行うコマンドを与えることができる。これは、まずオペ
        レータを与え、それから操作対象のテキストの終わりまで移動することの (使
        いやすい) 代替である。
        v および V はビジュアルモードを開始するために使用される。v は文
        字単位で、V は行単位で動作する。カーソルを移動してビジュアル領域を拡
        張する。それは画面上でハイライトされて表示される。"o" をタイプすると、
        ビジュアル領域の他方の端を移動できる。ビジュアル領域はオペレータの作用
        を受けることができる:
                d               削除
                c               変更
                y               ヤンク
                > または <      インデントを挿入または削除
                !               外部プログラムを通してフィルタ
                =               indent を通してフィルタ
                :               ビジュアル行に対する : コマンドを開始する。
                gq              テキストを 'textwidth' 桁に整形
                J               行を連結
                ~               大文字/小文字を入れ替え
                u               小文字にする
                U               大文字にする
        {Vi にはビジュアルモードはなく、Ex モードと区別するために、ノーマルモー
        ドに "visual" という名前が使われている}

矩形オペレータ。                                        visual-block
        ビジュアルモードでは、テキストの矩形ブロックを選択できる。CTRL-V でビ
        ジュアルモードを開始する。ブロックは削除 ("d")、ヤンク ("y")、またはそ
        の大文字/小文字の変更 ("~"、"u" および "U") ができる。削除またはヤンク
        したブロックは、"p" および "P" コマンドでテキストに貼り付けられる。

ヘルプシステム。                                        :help
        ヘルプはウィンドウに表示される。通常のコマンドを使用して、移動、文字列
        の検索などができる。タグを使用して、ハイパーテキストリンクとまったく同
        じように、ヘルプファイル内をジャンプできる。:help コマンドは引数を取
        り、ある主題についての情報へ素早くジャンプする。<F1> はヘルプシステム
        への素早いアクセスである。ヘルプのインデックスファイルの名前は
        'helpfile' オプションで設定できる。

コマンドライン編集と履歴。                              cmdline-editing
        カーソルキーを使用して、コマンドラインの任意の場所で挿入または削除がで
        きる。右/左カーソルキーを使用して 1 文字前方/後方へ移動できる。シフト
        した右/左カーソルキーを使用して 1 単語前方/後方へ移動できる。
        CTRL-B/CTRL-E を使用してコマンドラインの先頭/末尾へ移動できる。
        {Vi: 行の最後の文字だけを変更できる}
        {Vi: <Esc> を押すとコマンドラインが実行される。これはほとんどの人にとっ
        て予想外である。そのため Vim では変更された。しかし <Esc> がマッピング
        の一部である場合は、コマンドラインが実行される。<Esc> をタイプした時に
        も Vi の振る舞いが欲しい場合、":cmap ^V<Esc> ^V^M" を使用する}
                                                        cmdline-history
        コマンドラインは記憶される。上/下カーソルキーを使用して以前のコマンド
        ラインを呼び出せる。'history' オプションで記憶される行数を設定できる。
        コマンドおよび検索パターンには別々の履歴がある。

コマンドライン補完。                                    cmdline-completion
        コマンドライン (画面の最下行) の入力中に、<Tab> をタイプして補完できる
           対象                 例
        - コマンド              :e<Tab>
        - タグ                  :ta scr<Tab>
        - オプション            :set sc<Tab>
        - オプション値          :set hf=<Tab>
        - ファイル名            :e ve<Tab>
        - など

        複数のマッチがある場合、CTRL-N (次) および CTRL-P (前) でマッチを順に
        移動する。<Tab> は CTRL-N のように動作するが、最初のマッチへ折り返す。

        'wildchar' オプションでコマンドライン補完のための文字を設定でき、<Tab>
        がデフォルトである。(不完全な) ワイルドカードの後に CTRL-D をタイプで
        き、すべてのマッチが一覧表示される。CTRL-A はすべてのマッチを挿入する。
        CTRL-L はマッチの最長共通部分を挿入する。

挿入モード補完。                                        ins-completion
        挿入モードでは、CTRL-N および CTRL-P キーを使用して、他の場所に現れる
        単語を補完できる。 i_CTRL-N
        CTRL-X で別のモードに入り、それを通して以下の補完ができる:
        i_CTRL-X_CTRL-F       ファイル名
        i_CTRL-X_CTRL-K       'dictionary' ファイルの単語
        i_CTRL-X_CTRL-T       'thesaurus' ファイルの単語
        i_CTRL-X_CTRL-I       インクルードされたファイルの単語
        i_CTRL-X_CTRL-L       行全体
        i_CTRL-X_CTRL-]       タグファイルの単語
        i_CTRL-X_CTRL-D       定義またはマクロ
        i_CTRL-X_CTRL-O       オムニ補完: ファイルタイプに特化した賢い補完
        i_CTRL-X_CTRL-R       レジスタの内容
        など

長い行のサポート。                                      'wrap' 'linebreak'
        'wrap' オプションがオフの場合、長い行は折り返されず、その一部だけが表
        示される。カーソルが表示されていない部分に移動されると、画面は水平にス
        クロールする。スクロールする最小のカラム数は 'sidescroll' オプションで
        設定できる。zh および zl コマンドを使用して横にスクロールできる。
        あるいは、'linebreak' オプションが設定されている場合、長い行は単語の間
        で折り返される。これにより、1 行の段落を便利に編集できる (例: テキスト
        を後で DTP プログラムに読み込む場合)。gk および gj コマンドでカー
        ソルを上/下に移動する。

テキスト整形。                                          formatting

        :center、:left および :right。

拡張された検索パターン。                                pattern

ディレクトリ、リモートとアーカイブのブラウズ。          netrw

        常のコマンドで一覧内を移動し、<Enter> を押してカーソルの下のディレクト
        リまたはファイルへ移動する。
        これは ftp、http、ssh などを介したリモートファイルでも動作する。
        Zip および tar アーカイブもブラウズできる。tar zip

編集-コンパイル-編集の高速化。                          quickfix

        できる。コンパイラのエラーメッセージを含むファイルが解釈される。Vim は
        最初のエラーへジャンプする。

        して走査される。'errorformat' オプションに scanf 風の文字列のリストを
        設定して、多くのコンパイラからの出力を扱うことができる。

        'makeprg' オプションには :make コマンドで実行されるプログラムの名前
        が入る。
        'shellpipe' オプションには、コンパイラの出力をエラーファイルに入れるた
        めに使用される文字列が入る。

ファイル内のマッチの検索。                              :vimgrep

改善されたプログラムのインデント。                      'cindent'

インクルードされたファイル内の単語の検索。              include-search

5. その他の vim の機能                                  other-features

いろいろな素晴らしい追加機能を無作為に集めたもの。


Vim が "-s scriptfile" で起動された場合、"scriptfile" から読み込まれた文字は、
あなたがタイプしたかのように扱われる。エディタが終了する前にファイルの終わりに
達した場合、それ以降の文字はコンソールから読み込まれる。

"-w" オプションを使用して、タイプしたすべての文字をスクリプトファイルに記録で
きる。その後、このファイルを使用して、場合によっては別のファイルに対して、また
はスクリプトファイル内のいくつかのコマンドを変更した後に、編集を redo できる。

"-o" オプションは各引数に対してウィンドウを開く。"-o4" は 4 つのウィンドウを開
く。

Vi はフルスクリーンで動作するためにいくつかの termcap エントリを必要とする。
Vim は "cm" エントリ (カーソル移動) だけを必要とする。


コマンドモードで:

'showcmd' オプションが設定されている場合、コマンドの文字が画面の最終行に表示さ
れる。それらはコマンドが終了すると消去される。

'ruler' オプションが設定されている場合、現在のカーソル位置が画面の最終行に表示
される。

"U" は最後に変更した行から移動した後および "u" の後でも動作する。

8 番目のビットがセットされた文字は表示される。'~' と 0xa0 の間の文字は、
'isprint' オプションに含まれていない限り、"~?"、"~@"、"~A" などとして表示され
る。

"][" は次の C 関数の終わり (1 カラム目の '}') へ移動する。
"[]" は前の C 関数の終わり (1 カラム目の '}') へ移動する。

"]f"、"[f" および "gf" は、カーソルの下にある名前のファイルの編集を開始する。
CTRL-W f はウィンドウを分割し、カーソルの下にある名前のファイルの編集を開始す
る。

"*" はカーソルの下の識別子を前方に検索し、"#" は後方に検索する。
"K" は 'keywordprg' オプションで定義されたプログラムを、カーソルの下の識別子を
引数として実行する。

"%" の前にカウントを付けることができる。カーソルはファイル内のそのパーセンテー
ジの位置の行へジャンプする。対応する括弧へジャンプする通常の "%" の機能は、引
用符内の括弧をスキップする。

CTRL-] コマンドでは、カーソルは識別子の途中にあってもよい。

使用したタグは記憶される。タグスタックで使用できるコマンドは CTRL-T、":pop" お
よび ":tag" である。":tags" はタグスタックを一覧表示する。

Vi はタグを検索する時に 'wrapscan' を使用する。タグへジャンプする時、Vi は別の
ファイルの 2 行目から検索を開始する。'wrapscan' が設定されていない場合、別の
ファイルの 1 行目にあるタグを見つけられない。

'tags' オプションにはタグファイル名のリストを設定できる。そのため、複数のタグ
ファイルを使用できる。"./" で始まるファイル名については、"./" はカレントファイ
ルのパスで置き換えられる。これにより、編集中のファイルと同じディレクトリにある
タグファイルを使用できる。
{Vi: いくつかのバージョンでは常に二分探索を使用する}
{Vi にはタグファイル内のコマンドに対するセキュリティ防御がない}

以前に使用したファイル名は代替ファイル名リストに記憶される。CTRL-^ はカウント
を受け付け、それはこのリスト内のインデックスである。
":files" コマンドは代替ファイル名のリストを表示する。
"#<N>" はリスト内の <N> 番目の代替ファイル名で置き換えられる。
"#<" は拡張子を除いたカレントファイル名で置き換えられる。

検索パターンにはより多くの機能がある。<NL> 文字は検索パターンおよび ":s" の置
換文字列の一部と見なされる。Vi はそれをコマンドの終わりと見なす。

検索ではカーソルをマッチの終わりに置くことができ、文字オフセットを含めることも
できる。

"~"、":next"、":Next"、"n" および "N" にカウントが追加された。

'autowrite' が設定されている時、コマンド ":next!" はファイルを書き込まない。vi
ではファイルは書き込まれたが、これはバグであると見なされる。なぜなら誰もそれを
予期しないし、":rewind!" ではファイルは書き込まれないからである。

Vi では、置換モードで <CR> を入力すると、'ai' が設定されている場合にのみ文字が
削除される (しかし <Esc> を押すまでそれは表示されない)。Vim は常に文字を削除す
る (そして即座にそれを表示する)。

:wnext コマンドが追加された。":write" の後に ":next" を行うのと同じ。

":w!" コマンドは、ファイルが書き込み禁止の場合でも、常に書き込む。Vi では
":!chmod +w %:S" および ":set noro" を行う必要があるだろう。

'tildeop' が設定されている場合、"~" はオペレータになる (移動コマンドが後に続か
なければならない)。

"J" (連結) コマンドでは、'joinspaces' オプションをリセットして、ピリオドの後の
スペースを 1 つだけにすることができる (Vi は 2 つのスペースを挿入する)。

"cw" を使用して、複数の文字からなる空白を変更できる (Vi は紛らわしい: "cw" は
1 つのスペースしか変更しないが、"dw" はすべての空白を削除する)。{Vi: 他の空白
が続く空白上での "cw" は最初の空白だけを変更する。"dw" はすべての空白を削除す
るので、これはおそらくバグである}

"o" および "O" は挿入を繰り返すためのカウントを受け付ける (Vi は表示の一部をク
リアする)。

Ex コマンドの後のフラグはサポートされていない (含める予定はない)。

UNIX 以外のシステムでは、":cd" コマンドはホームディレクトリへ移動する代わりに
カレントディレクトリを表示する (ホームディレクトリは存在しない)。":pwd" はすべ
てのシステムでカレントディレクトリを表示する。

":cd" コマンドの後も、(引数リスト内の、開いている) ファイル名は同じファイルを
指したままである。Vi では、変更されたファイルでは ":cd" は許可されない。そうし
ないとファイル名の意味が変わってしまう。

":source!" コマンドはファイルから Vi のコマンドを読み込む。

":mkexrc" コマンドは現在の変更されたオプションおよびマッピングを ".exrc" ファ
イルに書き込む。":mkvimrc" は ".vimrc" ファイルに書き込む。

マッピングで "末尾再帰" のチェックをしない。これにより ":map! foo ^]foo" のよ
うなことが可能になる。

マッピングが数字で始まる場合、vi はその前にタイプされたカウントを失う (例えば、
マッピング ":map g 4G" を使用している時、コマンド "7g" は 4 行目へ移動する)。
これは vi のバグと見なされる。Vim は、ほとんどの人が予期するように、カウントを
連結する (この例では "74G" になる)。

:put! コマンドはレジスタの内容をカレント行の上に挿入する。

vi の "p" および "P" コマンドは、貼り付けたテキストが 1 行未満の場合、"." で繰
り返すことができない。Vim では常に繰り返すことができる。

":noremap" コマンドを使用して、再マップされないマッピングを入力できる。これは
2 つのキーの意味を交換するのに役立つ。":cmap"、":cunmap" および ":cnoremap" は
コマンドライン編集のみのマッピングに使用できる。":imap"、":iunmap" および
":inoremap" は挿入モードのみのマッピングに使用できる。短縮入力にも同様のコマン
ドが存在する: ":noreabbrev"、":iabbrev" ":cabbrev"、":iunabbrev"、
":cunabbrev"、":inoreabbrev"、":cnoreabbrev"。

Vi では、コマンド ":map foo bar" は以前のマッピング ":map bug foo" を削除して
しまう。これはバグと見なされるので、Vim には含まれていない。":unmap! foo" は
":map! bug foo" を削除する。そうしないとアンマップがとても難しくなるからである
(これは vi 互換である)。

':' レジスタには最後のコマンドラインが入っている。
'%' レジスタにはカレントファイル名が入っている。
'.' レジスタには最後に挿入されたテキストが入っている。

":dis" コマンドはヤンクレジスタの内容を表示する。

CTRL-O/CTRL-I を使用して、より古い/より新しい位置へジャンプできる。これらは ''
コマンドで使用されるのと同じ位置だが、別のファイル内にあってもよい。":jumps"
コマンドはより古い位置を一覧表示する。

'shiftround' オプションが設定されている場合、">" および "<" コマンドで、インデ
ントは 'shiftwidth' の倍数に丸められる。

'scrolljump' オプションには、カーソルが画面から外れた時にスクロールする最小の
行数を設定できる。スクロールが遅い時にこれを使用する。

'scrolloff' オプションには、カーソルの上および下に保つ最小の行数を設定できる。
これにより、編集している場所の周りの文脈が見える。大きな数に設定すると、カーソ
ル行は常にウィンドウの中央になる。

大文字のマークを使用して、ファイル間をジャンプできる。":marks" コマンドは現在
設定されているすべてのマークを一覧表示する。コマンド "']" および "`]" は、直前
のオペレータの終わり、または put コマンドで挿入されたテキストの終わりへジャン
プする。"'[" および "`[" は開始位置へジャンプする。{Vi: 大文字のマークはない}

'shelltype' オプションは、Amiga で使用するシェルの種類を反映するように設定でき
る。

'highlight' オプションには、いくつかのコマンドで使用されるハイライトモードを設
定できる。

CTRL-A (加算) および CTRL-X (減算) コマンドは新しい。コマンドへのカウント (デ
フォルトは 1) が、カーソル位置またはカーソルの後にある数値に加算/から減算され
る。その数値は 10 進数、8 進数 ('0' で始まる)、または 16 進数 ('0x' で始まる)
でよい。マクロでとても便利である。

:set コマンドでは、プリフィックス "inv" を使用してブール値オプションを反転でき
る。

Vi および Vim の両方で、":substitute" コマンドで CTRL-M を使用して改行を作成で
きる。Vi では、これはテキストに本物の CTRL-M を挿入できないことを意味する。Vim
では、CTRL-V を前に付けることで、本物の CTRL-M をテキストに入れられる。


挿入モードで:

'revins' オプションが設定されている場合、挿入は逆向きに行われる。これはヘブラ
イ語をタイプするためのものである。通常の文字を挿入する時、カーソルは移動せず、
テキストが右へ移動する。Backspace、CTRL-W および CTRL-U も逆方向に動作する。
CTRL-B は 'revins' オプションを切り替える。置換モードでは 'revins' は効果がな
い。コンパイル時に有効にされた場合のみ。

バックスペースキーを使用して、CTRL-D と同じように自動インデントを削除できる。

'backspace' (bs) オプションに "eol" が含まれている場合、改行を越えてバックス
ペース、CTRL-U および CTRL-W ができる。'backspace' オプションに "start" が含ま
れている場合、挿入の開始位置を越えてバックスペースできる。

'paste' オプションが設定されている場合、いくつかのオプションがリセットされ、挿
入モードでのマッピングおよび短縮入力が無効になる。これにより、ウィンドウシステ
ムで予期しない結果なしにテキストを貼り付けることができる。'paste' オプションが
リセットされると、古いオプションの値が復元される。

CTRL-T/CTRL-D は、カーソルがどのカラムにあっても、常にカレント行のインデントを
挿入/削除する。

CTRL-@ (以前に挿入したテキストを挿入する) は常に動作する (Vi: 最初の文字として
タイプした場合のみ)。

CTRL-A は CTRL-@ のように動作するが、挿入モードを抜けない。

CTRL-R {register} を使用してレジスタの内容を挿入できる。

'smartindent' オプションが設定されている場合、C プログラムはより良く自動インデ
ントされる。'cindent' ではさらに良い。

CTRL-Y および CTRL-E を使用して、現在のカーソル位置の上/下から文字をコピーでき
る。

CTRL-V の後に、3 桁の 10 進数を入力できる。このバイト値は 1 つの文字としてテキ
ストに挿入される。キーボードにない国際的な文字に便利である。

'expandtab' (et) オプションが設定されている場合、<Tab> は適切な数のスペースに
展開される。

ウィンドウは常にバッファの内容を反映する (Vi はテキストを変更する時、およびそ
の他のいくつかの場合にはこれを行わない)。

Vim が DIGRAPHS を定義してコンパイルされている場合、ダイグラフがサポートされ
る。通常のダイグラフのセットが含まれている。それらは ":digraph" コマンドで表示
される。":digraph {char1}{char2} {number}" でさらに追加できる。ダイグラフは
"CTRL-K {char1} {char2}" または "{char1} BS {char2}" (オプション 'digraph' が
設定されている場合のみ) で入力する。

挿入を繰り返す時、例えば "10atest <Esc>" で、vi は最初の挿入に対してのみ
wrapmargin を処理する。Vim はすべてに対して処理する。

"i" または "a" コマンドへのカウントはすべてのテキストに対して使用される。Vi は
カウントを 1 行に対してのみ使用する。"3iabc<NL>def<Esc>" は、Vi では
"abcabcabc<NL>def" を挿入するが、Vim では "abc<NL>defabc<NL>defabc<NL>def" を
挿入する。


コマンドラインモードで:

<Esc> はコマンドラインを実行せずに終了させる。vi ではコマンドラインが実行され
るが、それはほとんどの人が予期するものではない (<Esc> を押すと常にコマンドモー
ドに戻るべきである)。いくつかの分かりにくいマクロでの問題を避けるために、マク
ロ内の <Esc> はコマンドを実行する。タイプした <Esc> で vi のようにコマンドを実
行したい場合、これを以下で修正できる
        ":cmap ^V<Esc> ^V<CR>"

全般:

'ttimeout' オプションは 'timeout' と同様だが、カーソルキーおよびファンクション
キーに対してのみ動作し、通常のマップされた文字には動作しない。'timeoutlen' オ
プションは待つミリ秒数を与える。'esckeys' オプションが設定されていない場合、
<Esc> で始まるカーソルキーおよびファンクションキーは挿入モードで認識されない。

各端末文字列に対してオプションがある。termcap がサポートされていない場合、また
は個々の文字列を変更するために使用できる。

'fileformat' オプションで <EOL> を選択できる: "dos" <CR><NL>、"unix" <NL> また
は "mac" <CR>。
'fileformats' オプションが空でない場合、Vim は <EOL> の種類を自動的に検出しよ
うとする。それに応じて 'fileformat' オプションが設定される。

ジョブ制御のないシステム (古い Unix システムおよび Unix 以外のシステム) では、
CTRL-Z、":stop" または ":suspend" コマンドは新しいシェルを開始する。

Vim が Amiga で出力用の対話的なウィンドウなしで起動された場合、ウィンドウが開
かれる (そして :sh はまだ動作する)。-d 引数で編集に使用するデバイスを与える
ことができる。例: "-d con:20/20/600/150"。

'columns' および 'lines' オプションは、画面の幅および高さを設定または取得する
ために使用される。

オプション設定はファイルの最初および最後の数行から読み込まれる。オプション
'modelines' は何行を試すかを決める (デフォルトは 5)。Note これは、モードライン
内で任意の Ex コマンドを実行できる Vi のバージョン (重大なセキュリティ問題) と
は異なることに注意。trojan-horse

'insertmode' オプションが設定されている場合 (例えば .exrc 内で)、Vim は挿入モー
ドで起動する。そして <Esc> を押すと、そこへ戻ってくる。

undo の情報はメモリに保持される。使用可能なメモリが、undo できる変更の数および
サイズを制限する。これは Amiga ではほとんど問題にならず、Unix および Win32 で
はほぼ決して問題にならない。

'backup' または 'writebackup' オプションが設定されている場合: ファイルが上書き
される前に、バックアップファイル (.bak) が作成される。"backup" オプションが設
定されている場合、それは残される。

Vim は、変更されたファイルの部分、またはメモリに収まらない部分を保存するため
に、".swp" で終わるファイルを作成する。このファイルを使用して、"vim -r file"
で中断された編集セッションから回復できる。スワップファイルの使用は、
'updatecount' オプションを 0 に設定するか、または Vim を "-n" オプションで起動
することでオフにできる。.swp ファイルを別の場所に置くには 'directory' オプショ
ンを使用する。

Vim は 8.3 ファイル名のファイルシステム上で正しく動作でき、Amiga で messydos
または crossdos ファイルシステム、または Unix で任意の 8.3 でマウントされたファ
イルシステムを使用している場合も同様である。'shortname' を参照。

エラーメッセージは少なくとも 1 秒間表示される (Vi はエラーメッセージを上書きす
る)。

Vim が hit-enter プロンプトを出した場合、任意のキーを押すことができる。<CR>、
<NL> および <Space> 以外の文字は、コマンド (の開始) として解釈される。
{Vi: ":" コマンドだけが解釈される}

番号付きレジスタおよび無名レジスタの内容は、ファイルを切り替える時に記憶され
る。

"No lines in buffer" メッセージは、エラーメッセージではなく通常のメッセージで
ある。エラーメッセージだとマッピングが中断される可能性があるからである。
{Vi: エラーメッセージは、読む機会を得る前に他のメッセージで上書きされることが
ある}

Amiga の AUX: デバイスがサポートされている。

8. POSIX 準拠                                   posix posix-compliance

2005年に、Vim の互換性をチェックするために POSIX テストスイートが実行された。
テストのほとんどは正しく実行された。Vi 互換モードで実行した場合でも、Vim が
POSIX に準拠していないいくつかのことがある。
                                                        $VIM_POSIX
Vim の起動時に 'cpoptions' に POSIX フラグが含まれるようにするには、$VIM_POSIX
環境変数を設定する。これにより Vim は可能な限り POSIX として動作する。それは
Vi 互換であることとは少し異なる。

Vi の Posix 仕様は以下で見つけられる:
https://pubs.opengroup.org/onlinepubs/9699919799/utilities/vi.html
そして関連する Ex の仕様:
https://pubs.opengroup.org/onlinepubs/9699919799/utilities/ex.html

以下は、Vim が POSIX の仕様どおりに動作しない点およびその理由である:

                                                        posix-screen-size
        より信頼できる方法で端末からサイズを取得できる場合、$COLUMNS および
        $LINES 環境変数は Vim によって無視される。$COLUMNS および $LINES が他
        の方法で取得したサイズより優先されるようにするには、'cpoptions' に '|'
        フラグを追加する。

        "{" および "}" コマンドはオリジナルの Vi では "{" で止まらないが、
        POSIX ではそうすると規定されている。POSIX の方法にしたい場合は、
        'cpoptions' に '{' フラグを追加する。

        "D"、"o" および "O" コマンドはカウントを受け付ける。繰り返した場合も同
        様。カウントを無視したい場合は、'cpoptions' に '#' フラグを追加する。

        'cpoptions' に '.' フラグが含まれている時、カレントバッファが変更され
        ている場合、":cd" コマンドは失敗する。

        ATTENTION メッセージはなく、'shortmess' に "A" フラグが追加される。
