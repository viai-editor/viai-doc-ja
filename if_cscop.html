                                                        cscope Cscope
このドキュメントは、Vim の cscope インターフェイスの使い方を説明する。

Cscope は ctags のようなツールだが、ctags が提供するものよりもはるかに多くのこ
とを行うので、ステロイドを使った ctags と考えること。Vim では、cscope の問い合
わせの結果へのジャンプは、任意のタグへのジャンプとまったく同じである; それはタ
グスタックに保存されるので、適切なキーボードマッピングを使うと、tags で通常
行うように関数の間を行ったり来たりジャンプできる。

1. Cscope の紹介                cscope-intro
2. Cscope 関連コマンド          cscope-commands
3. Cscope オプション            cscope-options
4. Vim で cscope を使う方法     cscope-howtouse
5. 制限事項                     cscope-limitations
6. 推奨される使い方             cscope-suggestions
7. 入手可能性および情報         cscope-info

現在、これは Unix および Win32 専用である。

1. Cscope の紹介                                        cscope-intro

以下のテキストは、あるバージョンの cscope の man ページから取ったものである:

                                    -----

  Cscope は、以下のことを助ける、対話的な画面指向のツールである:

       分厚いリストを延々とめくることなく、C プログラムがどのように動作するか
       を学ぶ。

       プログラム全体を学ぶ必要なく、バグを修正するために変更するコードのセク
       ションを特定する。

       enum 変数に値を追加するなど、提案された変更の影響を調べる。

       既存の関数に引数を追加するなど、変更がすべてのソースファイルで行われた
       ことを確認する。

       すべてのソースファイルでグローバル変数の名前を変更する。

       ファイルの選択された行で、定数をプリプロセッサシンボルに変更する。

  これは以下のような質問に答えるように設計されている:
       このシンボルはどこで使われているか?
       それはどこで定義されているか?
       この変数はどこで値を得たか?
       このグローバルシンボルの定義は何か?
       この関数はソースファイルのどこにあるか?
       どの関数がこの関数を呼んでいるか?
       この関数によってどの関数が呼ばれているか?
       "out of space" というメッセージはどこから来ているか?
       このソースファイルはディレクトリ構造のどこにあるか?
       どのファイルがこのヘッダーファイルをインクルードしているか?

  Cscope は、ソースファイルに対して最初に使われたときに構築するシンボルデータ
  ベースから、これらの質問に答える。その後の呼び出しでは、cscope は、ソースファ
  イルが変更されたか、またはソースファイルのリストが異なる場合にだけ、データ
  ベースを再構築する。データベースが再構築されるとき、変更されていないファイル
  のデータは古いデータベースからコピーされるので、再構築は最初の構築よりもはる
  かに速い。

                                    -----

cscope が普通に起動されると、上記の質問の 1 つについて問い合わせを行うことので
きる全画面の選択画面が表示される。
しかし、あなたの問い合わせに対するマッチが見つかり、マッチを含むソースファイル
を編集するためにあなたのテキストエディタに入ると、vi の Ctrl-] または :tag コ
マンドで通常行うように、単純にタグからタグへジャンプすることはできない。

Vim の cscope インターフェイスは、cscope をその行指向インターフェイスで起動し、
それから問い合わせから返された出力を解析することで実現されている。最終的な結果
として、cscope の問い合わせ結果は通常のタグとまったく同じになるので、通常のタ
グ (Ctrl-] または :tag) と同様にそれらにジャンプし、それから Ctrl-T でタグス
タックをポップして戻ることができる。(ただし、これらのコマンドを再マップするか、
またはオプションを設定することなしに、単に Ctrl-] または :tag を行うだけでは、
実際には cscope タグにジャンプしないことに注意。
cscope インターフェイスがどのように動作するか、および推奨される使い方について
は、残りのセクションを参照。)

2. Cscope 関連コマンド                                  cscope-commands

                :cscope :cs :scs :scscope E259 E262 E560 E561
すべての cscope コマンドは、cscope コマンドのサブオプションを通じてアクセスさ
れる。
        :cscope または :cs がメインのコマンドである
        :scscope または :scs は同じことを行い、ウィンドウを分割する
        :lcscope または :lcs は location リストを使う、:lcscope を参照

使用可能なサブコマンドは以下のとおり:

                        E563 E564 E566 E568 E622 E623 E625
                        E626 E609
    add   : 新しい cscope データベース/接続を追加する。

        使用法  :cs add {file|dir} [pre-path] [flags]

            [pre-path] は、cscope への -P コマンドで使われるパス名である。

            [flags] は、cscope に渡したい任意の追加のフラグである。

        例
            :cscope add /usr/local/cdb/cscope.out
            :cscope add /projects/vim/cscope.out /usr/local/vim
            :cscope add cscope.out /usr/local/vim -C

                                      cscope-find cs-find E567
    find  : cscope に問い合わせる。オプション #5 ("Change this grep pattern")
            を除き、すべての cscope の問い合わせオプションが使用可能である。

        使用法  :cs find {querytype} {name}

            {querytype} は、実際の cscope の行インターフェイスの番号、および既
            定の nvi コマンドに対応する:

                0 または s: この C シンボルを検索する
                1 または g: この定義を検索する
                2 または d: この関数によって呼ばれる関数を検索する
                3 または c: この関数を呼んでいる関数を検索する
                4 または t: このテキスト文字列を検索する
                6 または e: この egrep パターンを検索する
                7 または f: このファイルを検索する
                8 または i: このファイルを #include しているファイルを検索する
                9 または a: このシンボルに値が代入されている場所を検索する

        4 および 6 を除くすべての種類で、{name} の先頭の空白は削除される。4 お
        よび 6 では、{querytype} と {name} の間にちょうど 1 つの空白がある。そ
        れ以降の空白は {name} に含まれる。

        例
            :cscope find c vim_free
            :cscope find 3  vim_free

            これら 2 つの例は同じ問い合わせを行う: "vim_free" を呼んでいる関
            数。

            :cscope find t initOnce
            :cscope find t  initOnce

            1 つ目はテキスト "initOnce" を検索し、2 つ目は " initOnce" を検索
            する。

            :cscope find 0 DEFAULT_TERM

            この例を Vim 5.1 のソースコードに対して実行すると、以下の出力が生
            成される:

                                                        :lcscope :lcs
このコマンドは、'cscopequickfix' オプションが設定されているときに、cscope の結
果を表示するのに quickfix リストの代わりにカレントウィンドウの location リスト
が使われることを除き、":cscope" コマンドと同じである。

                                                        :cstag E257 E562
ctags に加えて cscope も使う場合、:cstag を使うと、ジャンプする前に一方また
は他方を検索することができる。例えば、まずあなたの cscope データベースでマッチ
を検索し、見つからない場合は、あなたのタグファイルが検索されるように選択でき
る。これが行われる順序は csto の値によって決まる。詳細は cscope-options を
参照。

:cstag は、cscope データベースを検索するとき、識別子に対して ":cs find g" と
同等のことを行う。

:cstag は、あなたのタグファイルを検索するとき、識別子に対して :tjump と同
等のことを行う。

3. Cscope オプション                                    cscope-options

すべての cscope オプションを設定するには :set コマンドを使う。理想的には、こ
れをあなたのスタートアップファイルの 1 つ (例えば .vimrc) で行う。いくつかの
cscope 関連の変数は .vimrc 内でだけ有効である。vim が起動した後にそれらを設
定しても効果はない!

                                                        cscopeprg csprg
'cscopeprg' は cscope を実行するコマンドを指定する。既定値は "cscope" である。
例えば:
        :set csprg=/usr/local/bin/cscope

                                            cscopequickfix csqf E469
{+quickfix 機能なしでコンパイルされたときは使用できない}
'cscopequickfix' は、cscope の結果を表示するのに quickfix ウィンドウを使うかど
うかを指定する。これはコンマ区切りの値のリストである。各項目は、cscope-find
のコマンド (s、g、d、c、t、e、f、i、または a) およびフラグ (+、-、または 0) か
ら成る。
'+' は、結果が quickfix ウィンドウに追加されなければならないことを示し、'-' は
以前の結果の消去を意味し、'0' またはコマンドの不在 - quickfix を使わない。検索
は最初から最初のコマンドの出現まで行われる。
既定値は "" である (いずれにせよ quickfix を使わない)。以下の値が有用なようで
ある:
        :set cscopequickfix=s-,c-,d-,i-,t-,e-,a-

                                                        cscopetag cst
'cscopetag' が設定されている場合、コマンド ":tag"、CTRL-]、および "vim -t" は、
既定の :tag の動作の代わりに常に :cstag を使う。事実上、'cst' を設定すること
で、常にあなたのタグファイルに加えてあなたの cscope データベースも検索すること
になる。既定ではオフである。例:
        :set cst
        :set nocst

                                                        cscoperelative csre
'cscoperelative' が設定されている場合、cscope に与えられるプリフィックス (プリ
フィックスは cscope の -P オプションの引数) がないときは、cscope.out の場所
(通常はプロジェクトのルートディレクトリ) の basename が、絶対パスを構築するた
めのプリフィックスとして使われる。既定ではオフである。Note: このオプションは、
cscope (cscopeprg) がプリフィックスパス (-P) なしで初期化されたときにだけ有効
である。例:
        :set csre
        :set nocsre

                                                        cscopetagorder csto
'csto' の値は、:cstag が検索を行う順序を決める。'csto' がゼロに設定されてい
る場合、まず cscope データベースが検索され、cscope がマッチを返さなかった場合
はその後にタグファイルが検索される。'csto' が 1 に設定されている場合、タグファ
イルが cscope データベースより前に検索される。既定値はゼロである。例:
        :set csto=0
        :set csto=1

                                                cscopeverbose csverb
'cscopeverbose' が設定されていない (既定) 場合、cscope データベースを追加する
ときに成功または失敗を示すメッセージは表示されない。理想的には、cscope データ
ベースを追加する前にあなたの .vimrc でこのオプションをリセットし、追加した後
でそれを設定すべきである。それ以降、Vim 内でさらにデータベースを追加するとき、
データベースの追加に失敗した場合は (できれば) 有用なメッセージが表示される。例:

        :set csverb
        :set nocsverb

                                                      cscopepathcomp cspc
'cspc' の値は、ファイルのパスの構成要素をいくつ表示するかを決める。既定値のゼ
ロでは、パス全体が表示される。値 1 では、パスなしでファイル名だけが表示される。
他の値では、その数の構成要素が表示される。例えば:
        :set cspc=3
とすると、ファイル名自体を含めて、ファイルのパスの最後の 3 つの構成要素が表示
される。

4. Vim で cscope を使う方法                             cscope-howtouse

最初に行う必要があるのは、あなたのソースファイルの cscope データベースを構築す
ることである。最も基本的な場合、単に "cscope -b" を行う。詳細は cscope の man
ページを参照。

cscope データベースがあるとすると、そのデータベースを Vim に "add" する必要が
ある。これは cscope の "接続" を確立し、Vim がそれを使用できるようにする。これ
はあなたの .vimrc ファイルで行うか、または vim を起動した後に手動で行うことが
できる。例えば、cscope データベース "cscope.out" を追加するには、こうする:

        :cs add cscope.out

":cs show" を実行することで、この結果を再確認できる。これはこのような出力を生
成する:

 # pid    database name                       prepend path
 0 28806  cscope.out                          <none>

Note:
Microsoft RTL の制限のため、Win32 版は実際の pid の代わりに 0 を表示する。

cscope 接続が確立されると、cscope に問い合わせを行うことができ、結果が表示され
る。問い合わせはコマンド ":cs find" を使って行われる。例えば:

        :cs find g ALIGN_SIZE

これは、かなりの量をタイプすることになるので、少し面倒になることがある。幸い、
ショートカットキーをマップすることでこれを回避する方法がある。推奨される使い方
については cscope-suggestions を参照。

結果が 1 つのマッチだけを返す場合、自動的にそこに移動する。複数のマッチがある
場合、移動したいマッチを選ぶための選択画面が表示される。新しい場所にジャンプし
た後、前の場所に戻るには単に Ctrl-T を押す。


==============================================================================
5. 制限事項                                             cscope-limitations

Vim の cscope サポートは、これらの 4 つのシステムコールをサポートするシステム
でだけ使用可能である: fork()、pipe()、execl()、waitpid()。これは、ほとんど
Unix システムに限られることを意味する。

さらに、Cscope サポートは Win32 でも機能する。詳しい情報および Win32 用の
cscope のバージョンについては、以下を参照 (リンクは切れているようだ):

        iamphet.nm.ru/cscope/index.html

http://cscope.sourceforge.net の DJGPP でビルドされたバージョンは、Vim では動
作しないことが知られている。

ハードコードされた制限: :cstag がタグファイルを検索するときに :tjump を行
うことは、設定できない (例えば、代わりに tselect を行うことはできない)。

6. 推奨される使い方                                     cscope-suggestions

これらの項目をあなたの .vimrc に入れる (パス名はあなたのセットアップに合わせて
調整する):

        if has("cscope")
                set csprg=/usr/local/bin/cscope
                set csto=0
                set cst
                set nocsverb
                " カレントディレクトリにある任意のデータベースを追加する
                if filereadable("cscope.out")
                    cs add cscope.out
                " そうでない場合、環境が指すデータベースを追加する
                elseif $CSCOPE_DB != ""
                    cs add $CSCOPE_DB
                endif
                set csverb
        endif

'cscopetag' を設定することで、:tag コマンドのすべての使用箇所を事実上 :cstag
で置き換えたことになる。これには、:tag、Ctrl-]、および "vim -t" が含まれる。こ
うすることで、通常のタグコマンドは、あなたの ctags が生成したタグファイルだけ
でなく、あなたの cscope データベースも検索する。

ユーザーによっては、通常のタグの動作を保ち、:cstag にアクセスするための別の
ショートカットを持ちたいかもしれない。例えば、以下のコマンドで Ctrl-_  (アン
ダースコア) を :cstag にマップできる:

        map <C-_> :cstag <C-R>=expand("<cword>")<CR><CR>

非常によく使われる cscope の問い合わせ (":cs find" を使う) のいくつかは、ある
関数を呼んでいるすべての関数を見つけること、および特定の C シンボルのすべての
出現を見つけることである。これを行うには、例としてこれらのマッピングを使える:


        map g<C-]> :cs find 3 <C-R>=expand("<cword>")<CR><CR>
        map g<C-\> :cs find 0 <C-R>=expand("<cword>")<CR><CR>

Ctrl-] (右角括弧) および Ctrl-\ (バックスラッシュ) に対するこれらのマッピング
により、あなたのカーソルを関数名または C シンボルの上に置いて、すばやく cscope
にマッチを問い合わせることができる。

または、Cscope ホームページ (http://cscope.sourceforge.net/) の Vim/Cscope
チュートリアルに触発された、以下の方式を使うこともできる:

        nmap <C-_>s :cs find s <C-R>=expand("<cword>")<CR><CR>

7. Cscope の入手可能性および情報                        cscope-info

cscope をまだ持っていない (あなたのコンパイラのライセンスまたは OS のディスト
リビューションに付属していなかった) 場合、以下から無料でダウンロードできる:
        http://cscope.sourceforge.net/
これは SCO によって BSD ライセンスの下でリリースされている。

Solaris 2.x では、C コンパイラのライセンスを持っている場合、cscope も持ってい
ることになる。どちらも通常は /opt/SUNWspro/bin の下にある

cscope のクローン ("cs" と呼ばれる) の古いバージョンのソースがネット上で入手可
能である。さまざまな理由により、これは Vim ではサポートされていない。

Vim の cscope インターフェイス/サポートは、もともと Andy Kahn
<ackahn@netapp.com> によって書かれた。元の構造 (およびごく一部のコード) は、
nvi の cscope インターフェイスから採り入れられた。
                                                        cscope-win32
Win32 用の cscope のバージョンについては、以下を参照 (放棄されたようだ):
        https://code.google.com/archive/p/cscope-win32/

Win32 サポートは Sergey Khorev <sergey.khorev@gmail.com> によって追加された。
Win32 固有の問題がある場合は彼に連絡すること。
