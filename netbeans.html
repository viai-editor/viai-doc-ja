1. はじめに                                             netbeans-intro

NetBeans インターフェイスは当初、外部エディタプラグインを使用して、Vim を
NetBeans Java IDE に統合するために開発された。この NetBeans プラグインは最近の
バージョンの NetBeans にはもう存在しないが、プロトコルはどの IDE でも Vim を統
合するために使用できるように開発された。

Vim の NetBeans プロトコルは、古典的な TCP ソケット上のテキストベースの通信プ
ロトコルである。Java または NetBeans への依存はない。ソケットインターフェイス
を提供するどの言語または環境でも、このプロトコルを使用して Vim を制御できる。
C、C++、Python および Java による既存の実装がある。NetBeans という名前は今日で
は歴史的な理由で残されている。

Vim の NetBeans プロトコルを使用している活発なプロジェクト:
- Eclim、(リンク切れ) eclim.org/

VimIntegration、Vim 統合を行っているさまざまなプロジェクトの説明:
        (リンク切れ) www.freehackers.org/VimIntegration

Vim の NetBeans プロトコルを使用している、または使用していたプロジェクト:
- Agide、Python で書かれた AAP プロジェクト用の IDE (現在は :Termdebug に置
  き換えられた): http://www.a-a-p.org (リンクは現在切れている)
- Clewn、C で書かれた、Vim への gdb の統合:
        http://clewn.sourceforge.net/
- Pyclewn、Python で書かれた、Vim への gdb の統合:
        http://pyclewn.sourceforge.net/
- VimWrapper、IDE への Vim の統合を容易にするライブラリ:
        (リンク切れ) freehackers.org/VimWrapper
古いプロジェクト (リンクは機能しない):
- VimPlugin、Eclipse 内への Vim の統合:
        http://vimplugin.sourceforge.net/wiki/pmwiki.php
- PIDA、Vim を統合する、Python で書かれた IDE:
        http://pida.co.uk/

これらのプロジェクトで Vim を使用する方法を知るには、各プロジェクトのページを
確認すること。

代替手段はチャネルを使用することである。channel を参照。

このヘルプページの残りでは、NetBeans ソケットインターフェイスを通じて Vim を制
御するプログラムを表すために "Vim Controller" という用語を使用する。


NetBeans IDE について

NetBeans は、Sun Microsystems, Inc. および netbeans.org 開発者コミュニティに
よって共同で開発されたオープンソースの統合開発環境である。当初は Java IDE にす
ぎなかったが、NetBeans には最近のリリースで C、C++、および Fortran のサポート
が追加された。

詳しい情報については NetBeans のメインウェブサイト http://www.netbeans.org を
訪れること。External Editor は現在、残念ながら廃止されたと宣言されている。(リ
ンクは切れているようだ): externaleditor.netbeans.org を参照。

Sun Microsystems, Inc. は NetBeans を Sun ONE Studio という名前でも出荷してい
る。Sun ONE Studio 製品ラインに関する詳しい情報は http://www.sun.com を訪れる
こと。

現在のリリースの NetBeans は Java を完全にサポートし、C、C++、および Fortran
を限定的にサポートしている。現在のリリースの Sun ONE Studio は Java、C、C++、
および Fortran を完全にサポートしている。

2. 統合機能                                             netbeans-integration

Vim の NetBeans ソケットインターフェイスは、Vim から情報を取得するか、または
Vim に特定の動作を実行するよう依頼することを可能にする:
- バッファに関する情報を取得する: バッファ名、カーソル位置、バッファの内容な
  ど。
- バッファが開かれたか、または閉じられたときに通知を受ける
- バッファの内容がどのように変更されたかの通知を受ける
- ファイルを読み込み、保存する
- バッファの内容を変更する
- 特殊なキーバインドをインストールする
- ウィンドウを前面に出す、ウィンドウのジオメトリを制御する

Vim にキーストロークを送るか、または Vim で関数を評価するには、clientserver
インターフェイスを使用しなければならない。

3. NetBeans 用の Vim の設定                     netbeans-configure

Vim のインストールについての詳しいヘルプは、Vim ユーザーマニュアルの
usr_90.txt を読むこと。


Unix の場合:
------------

引数なしで configure を実行すると、NetBeans インターフェイスが含まれるはずであ
る。つまり、システムが必要な機能をサポートしているかを調べる configure のチェッ
クが成功した場合である。

NetBeans インターフェイスが不要な場合、Makefile の "--disable-netbeans" のある
行のコメントを外すことで無効にできる。

現在、NetBeans インターフェイスは、端末で実行されている Vim、および以下の GUI
のいずれかで実行されている場合の gvim によってサポートされている: GTK、GNOME、
Windows および Motif。

                                                        netbeans-xpm
Motif サポートが必要な場合、ユーザーは XPM ライブラリを用意しなければならない。
XPM ライブラリは Motif で Vim 内に画像を表示するために必要である。
それがないと、ツールバーおよび目印は無効になる。

XPM ライブラリは French National Institute for Research in Computer Science
and Control の Arnaud Le Hors によって提供されている。それは
https://ftp.nluug.nl/ftp/windowing/X/contrib/libraries/ からダウンロードでき
る。これを書いている時点での現在のリリースは xpm-3.4k-solaris.tgz で、gzip さ
れた tar ファイルである。ディレクトリ /usr/local/xpm を作成し、そこでファイル
を untar した場合、Makefile のコメントアウトされていない行を変更せずに使用でき
る。別の xpm ディレクトリを使用する場合、src/Makefile の XPM_DIR を変更する必
要がある。


MS-Windows の場合:
------------------

Win32 サポートは現在ベータ段階である。

Win32 で XPM 目印を使用するには (例: NetBeans と一緒に使用する場合)、XPM を自
分でコンパイルするか、または (リンクは切れているようだ): iamphet.nm.ru/misc/
(MS Visual C++ 用) または http://gnuwin32.sourceforge.net (MinGW 用) からコン
パイル済みのライブラリを使用できる。

デバッグを有効にする:
---------------------

Vim および NetBeans プロトコルのデバッグを有効にするには、"NBDEBUG" マクロを定
義する必要がある。使用しているプラットフォームの Makefile で "NBDEBUG" を検索
し、どの行のコメントを外す必要があるかを確認すること。これにより実質的にコンパ
イルコマンドに "-DNBDEBUG" が追加される。netbeans-debugging も参照

4. エラーメッセージ                                     netbeans-messages

これらのエラーメッセージは NetBeans ソケットプロトコルに固有のものである:

                                                        E463
Region is guarded, cannot modify
                Vim Controller がテキスト内に、変更できない保護された領域を定
                義している。必要な場合、カレントバッファも設定する。

                                                        E532
The defineAnnoType highlighting color name is too long
                defineAnnoType コマンドの "fg" または "bg" の色引数の最大長は
                32 文字である。
                バージョン 2.5 で追加。

                                                        E656
Writes of unmodified buffers forbidden
                Vim Controller から開かれた未変更のバッファの書き込みはできな
                い。

                                                        E657
Partial writes disallowed
                Vim Controller から開かれたバッファの部分的な書き込みは許可さ
                れていない。

                                                        E658
Connection lost for this buffer
                Vim Controller がこのファイルの状態について混乱した。データ破
                損の危険を冒すよりも、このファイルの接続を切断した。Vim がこの
                ファイルへの変更を保存する責任を引き継ぎ、Vim Controller はこ
                れらの変更をもう知ることはない。

                                                        E744
Read-only file
                Vim は通常、読み込み専用ファイルへの変更を許可し、ファイルを書
                き込もうとした場合にのみ読み込み専用の規則を強制する。しかし、
                NetBeans は読み込み専用のファイルへの変更を許さず、Vim がこれ
                を行うと混乱する。
                そのため、NetBeans モードで実行されている場合、Vim はファイル
                への変更を許可しない。

5. NetBeans モードで Vim を実行する                     netbeans-run

NetBeans モードで Vim を実行するには 2 つの異なる方法がある:

        + IDE は -nb コマンドライン引数で Vim を起動できる
        + NetBeans は :nbstart コマンドで Vim 内から起動できる

Vim は接続を試みる際に 3 秒のタイムアウトを使用する。

                                                        netbeans-parameters
NetBeans の接続パラメータを設定するには 3 つの形式を使用できる。
コマンドラインから起動された場合、-nb コマンドライン引数は以下にできる:

        -nb={fname}                             ファイルから
        -nb:{hostname}:{addr}:{password}        直接
        -nb                                     ファイルまたは環境から

Vim 内から起動された場合、:nbstart のオプション引数は以下にできる:

        ={fname}                                ファイルから
        :{hostname}:{addr}:{password}           直接
        <MISSING ARGUMENT>                      ファイルまたは環境から

                                                        E660 E668
NetBeans がコマンドラインから起動される場合、セキュリティ上の理由から、最良の
方法はユーザーのみが読み込み可能なファイルに情報を書き込むことである。ファイル
名は "-nb={fname}" 引数で渡すか、または "-nb" がパラメータなしで使用された場合
は環境変数 "__NETBEANS_CONINFO" で渡すことができる。ファイルはこれら 3 行を任
意の順序で含んでいなければならない:

        host={hostname}
        port={addr}
        auth={password}

その他の行は無視される。Vim Controller は後でファイルを削除する責任がある。

{hostname} は Vim Controller が実行されているマシンの名前である。省略された場
合、環境変数 "__NETBEANS_HOST" が使用されるか、またはデフォルトの "localhost"
が使用される。

{addr} は NetBeans インターフェイスのポート番号である。省略された場合、環境変
数 "__NETBEANS_SOCKET" が使用されるか、またはデフォルトの 3219 が使用される。

{password} は NetBeans に接続するためのパスワードである。省略された場合、環境
変数 "__NETBEANS_VIM_PASSWORD" が使用されるか、または "changeme" が使用される。

Vim は起動時に、指定されたホストおよびポートへのソケット接続 (クライアント側)
を開始する。接続が確立されると、パスワードが AUTH イベントで送られる。

6. NetBeans プロトコル                                  netbeans-protocol

Vim Controller と Vim の間の通信はプレーンテキストのメッセージを使用する。この
プロトコルは最初、NetBeans の外部エディタモジュールと動作するように設計された。
後に Agide (A-A-P GUI IDE、以前は http://www.a-a-p.org、リンクは現在切れている)
と動作するように拡張され、その後他の IDE と動作するように拡張された。
拡張には "version 2.1" という印が付けられている。

プロトコルのバージョン 2.2 にはいくつかの小さな変更があり、それは NetBeans ユー
ザー (つまり、Agide ユーザーではない) にのみ影響するはずである。しかし、混乱を
引き起こす可能性のあるバグが修正された。netbeans_saved() 関数は "save" プロト
コルコマンドを送っていた。プロトコルバージョン 2.1 以前では、これは書き込みが
行われたという通知として誤って解釈されていた。実際には、それは NetBeans にファ
イルを保存するよう指示していたので、複数回の書き込みが行われていた。これはさま
ざまな問題を引き起こし、2.2 で修正された。この混乱が再び起こる可能性を減らすた
め、netbeans_saved() は netbeans_save_buffer() に名前が変更された。

現在はバージョン 2.5 である。2.4 と 2.5 の間の違いについては、以下で "2.5" を
検索すること。

メッセージは現在ソケット上で送られる。メッセージはプレーンな UTF-8 テキストな
ので、このプロトコルは他のどんな通信機構でも使用できる。

Netbeans のメッセージは、Vim がアイドル状態でユーザー入力を待っているときに処
理される。Vim が非対話モードで実行されている場合、例えば Vim script を読み込む
自動テストケースを実行している場合、アイドルループが十分な頻度で呼ばれないこと
がある。その場合、Vim script に :sleep コマンドを挿入すること。:sleep コマ
ンドは Netbeans メッセージの処理を呼び出す。

6.1 メッセージの種類                                    nb-messages

メッセージには 4 種類ある:

種類            方向            備考
Command         IDE -> editor   応答不要
Function        IDE -> editor   editor は応答を返さなければならない
Reply           editor -> IDE   Function への応答としてのみ
Event           editor -> IDE   応答不要

メッセージは終端の改行文字が付いた単一の行として送られる。引数は単一の空白で区
切られる。メッセージの最初の項目はメッセージの種類によって異なる:

種類            最初の項目              例
Command         bufID:name!seqno        11:showBalloon!123 "text"
Function        bufID:name/seqno        11:getLength/123
Reply           seqno                   123 5000
Event           bufID:name=seqno        11:keyCommand=123 "S-F2"



6.2 用語                                                nb-terms

bufID           バッファ番号。メッセージは特定のバッファに対するものか、または
                汎用的なものである。汎用メッセージは bufID に 0 を使用する。
                NOTE: このバッファ ID は IDE によって割り当てられ、Vim のバッ
                ファ番号ではない。bufID は 1 から始まる、順番に増加する番号で
                なければならない。'switchbuf' オプションが "usetab" に設定され
                ていて "bufID" バッファがカレントタブページに見つからない場合、
                このバッファをカレントバッファとして設定する netbeans のコマン
                ドおよび関数は、カレントウィンドウのバッファを置き換える代わり
                に、他のタブページでこのバッファを含む最初の開いているウィンド
                ウにジャンプする。

seqno           IDE は Command および Function にシーケンス番号を使用する。
                Reply は、それが関連付けられている Function のシーケンス番号を
                使用しなければならない。Event には 0 のシーケンス番号を使用で
                きる (最後に受信した Command または Function の seqno も使用で
                きる)。

string          二重引用符で囲まれた引数。テキストは UTF-8 エンコーディングで
                ある。これは ASCII がそのまま渡されることを意味する。特殊文字
                はバックスラッシュで表される:
                        \"      二重引用符
                        \n      改行
                        \r      キャリッジリターン
                        \t      タブ (省略可能、そのままでも機能する)
                        \\      バックスラッシュ
                NUL バイトは許可されていない!

boolean         2 つの値を取りうる引数:
                        T       真
                        F       偽

number          10 進数の数値の引数。

color           10 進数の数値、"none" (引用符なし)、または highlight-ctermfg
                の色リストおよび gui-colors の色リストの両方で定義されている
                色の名前 (引用符なし) のいずれかを持つ引数。
                バージョン 2.5 で追加。

offset          バッファ内のバイト位置を示す数値引数。最初のバイトのオフセット
                は 0 である。改行はファイル内での現れ方に従って数えられる
                (CR/LF は 2 バイトとして数えられる)。Note マルチバイト文字はそ
                れが占めるバイト数として数えられることに注意。

lnum/col        行番号および桁番号の位置を持つ引数。行番号は 1 から始まり、桁
                はバイト位置で、0 から始まる。Note マルチバイト文字は複数の桁
                として数えられることに注意。

pathname        文字列引数: フルパス付きのファイル名。


6.3 コマンド                                            nb-commands

actionMenuItem  未実装。

actionSensitivity
                未実装。

addAnno serNum typeNum off len
                このバッファにアノテーションを配置する。
                引数:
                   serNum       number  この配置されたアノテーションのシリアル
                                        番号、それを削除できるようにするために
                                        使用される
                   typeNum      number  このバッファに対して defineAnnoType で
                                        定義されたアノテーションのシーケンス番
                                        号
                   off          number  アノテーションが配置されるオフセット
                   len          number  使用されない
                バージョン 2.1 では "off" の代わりに "lnum/col" を使用できる。

balloonResult text
                未実装。

close           バッファを閉じる。これによりカレントバッファがない状態になり、
                使用するのは非常に危険である!

create          名前のないバッファを作成する。カレントバッファを置き換える (変
                更されていた場合は隠される)。
                Vim Controller は、開かれようとしているファイルに対する最初の
                コマンドとしてこれを使用するべきである。コマンドの順序は以下の
                ようになりうる:
                        create
                        setCaretListener        (無視される)
                        setModified             (効果なし)
                        setContentType          (無視される)
                        startDocumentListen
                        setTitle
                        setFullName

defineAnnoType typeNum typeName tooltip glyphFile fg bg
                このバッファに対するアノテーションの種類を定義する。
                引数:
                   typeNum      number  シーケンス番号 (実際には使われていない)
                   typeName     string  このアノテーションを識別する名前
                   tooltip      string  使用されない
                   glyphFile    string  アイコンファイルの名前
                   fg           color   行ハイライトの前景色
                   bg           color   行ハイライトの背景色
                Vim はアノテーションに対して目印を定義する。
                color が数値の場合、これは色の "#rrggbb" の赤、緑および青の値
                であり (gui-colors を参照)、ハイライトは gVim に対してのみ定
                義される。
                color が名前の場合、この色はカラー端末で実行されている Vim お
                よび gVim の両方に対して定義される。
                "fg" および "bg" の両方が "none" の場合、行ハイライトは使用さ
                れない (バージョン 2.1 で追加)。
                "glyphFile" が空の場合、テキスト目印は使用されない (バージョン

getCursor       カレントバッファおよびカーソル位置を返す。

                seqno = 関数のシーケンス番号
                bufID = カレントバッファのバッファ ID (これが不明な場合は -1

                lnum  = カーソルの行番号 (最初の行は 1)
                col   = カーソルの桁番号 (バイト単位、0 始まり)
                off   = バッファ内でのカーソルのオフセット (バイト単位)
                バージョン 2.1 で追加。

getLength       バッファの長さをバイト単位で返す。
                5000 バイトのバッファに対する応答の例:
                        123 5000
                TODO: 部分的な行の使用について説明する。

getMark         未実装。

getAnno serNum
                バッファ内のアノテーションの行番号を返す。
                引数:
                        serNum          この配置されたアノテーションのシリアル
                                        番号
                応答は以下のとおり:
                        123 lnum        アノテーションの行番号
                        123 0           無効なアノテーションシリアル番号
                バージョン 2.4 で追加。

getModified     バッファが指定された場合: バッファに変更がない場合は 0 を返し、
                変更がある場合は 1 を返す。
                バッファが指定されない場合 (バッファ番号 0): 変更のあるバッファ
                の数を返す。結果が 0 の場合、Vim に終了を指示しても安全である。
                バージョン 2.1 で追加。

getText         バッファの内容を文字列として返す。
                2 行のバッファに対する応答の例
                        123 "first line\nsecond line\n"
                NOTE: ドキュメントにはオフセットおよび長さの引数が示されている
                が、これは実装されていない。

insert off text
                位置 "off" の前に "text" を挿入する。"text" は文字列引数で、
                "off" は数値である。
                "text" は各行の末尾に "\n" (改行) を持つべきである。または
                'fileformat' が "dos" の場合は "\r\n"。空のバッファで "insert"
                を使用する場合、Vim はそれに応じて 'fileformat' を設定する。
                "off" が行の先頭を指している場合、テキストはこの行の上に挿入さ
                れる。したがって "off" が 0 の場合、行は最初の行の前に挿入され
                る。
                "off" が行の先頭より後、場合によっては行末の NUL 上を指してい
                る場合、テキストの最初の行はこの行に追加される。それ以降の行は
                その下に来る。
                可能な応答:
                        123             問題なし
                        123 !message    失敗
                Note 応答内のメッセージは引用符で囲まれないことに注意。
                必要な場合、カレントバッファも設定する。
                変更されたテキストにカーソルを移動しない。
                undo 情報をリセットする。

remove off length
                位置 "off" から "length" バイトのテキストを削除する。両方の引
                数は数値である。
                可能な応答:
                        123             問題なし
                        123 !message    失敗
                Note 応答内のメッセージは引用符で囲まれないことに注意。
                必要な場合、カレントバッファも設定する。

saveAndExit     Vim を閉じるのと同等の操作を実行する: ":confirm qall"。
                変更されたファイルがないか、またはユーザーが操作をキャンセルし
                ない場合、Vim は終了し、結果は返されない。IDE は接続が閉じられ
                たことを成功の結果とみなせる。
                ユーザーが操作をキャンセルした場合、残っている変更されたバッ
                ファの数が返され、Vim は終了しない。
                バージョン 2.1 で追加。

7. NetBeans コマンド                                    netbeans-commands

                                                        :nbstart E511 E838
:nbs[tart] {connection} {connection} をソケット接続パラメータとして、新しい
                        Netbeans セッションを開始する。{connection} の形式は
                        netbeans-parameters で説明されている。いつでも、以下
                        のコマンドを実行することで netbeans ソケットが接続され
                        ているかを確認できる:
                        ':echo has("netbeans_enabled")'

                                                        :nbclose
:nbc[lose]              現在の NetBeans セッションを閉じる。配置されている全て
                        の目印を削除する。

                                                        :nbkey
:nb[key] {key}          {key} を処理のために Vim Controller に渡す。
                        specialKeys コマンドでホットキーがインストールされてい
                        る場合、このコマンドを使用して Vim Controller へのホッ
                        トキーメッセージを生成できる。
                        このコマンドは任意のテキストを Vim Controller に渡すた
                        めにも使用できる。例えば Pyclewn は、gdb コマンドの完
                        全なセットを Vim のユーザーコマンドとして構築するため
                        にこれを使用している。
                        イベント newDotAndMark、keyCommand および keyAtPos が
                        (この順序で) 生成される。

8. 既知の問題                                           netbeans-problems

NUL バイトは扱えない。editor -> IDE では NL 文字として現れる。IDE -> editor で
は挿入できない。

NetBeans セッションは、端末で実行されている Vim で開始され、後で :gui コマン
ドを実行した後に GUI 環境で継続されることがある。この場合、":gui" コマンドが
.gvimrc を読み込み、このファイルが ":highlight clear" コマンドを実行するカラー
スキームを読み込むと、NetBeans アノテーションに対して定義されたハイライトがク
リアされることがある。
バージョン 2.5 で追加。

9. NetBeans プロトコルのデバッグ                        netbeans-debugging

10. NetBeans External Editor

NOTE: この情報は古くなっている! 古いバージョンの NetBeans を使用している場合に
のみ関係する。


10.1. NetBeans のダウンロード                   netbeans-download

NetBeans IDE は netbeans.org からダウンロード可能である。リリース版をダウンロー
ドするか、ソースをダウンロードするか、または CVS を使用して現在のソースツリー
をダウンロードできる。ソースをダウンロードすることを選択した場合、NetBeans の
ビルドについては netbeans.org の指示に従うこと。

ダウンロードする NetBeans のバージョンによっては、必要な External Editor モ
ジュールを入手するためにさらに作業が必要になることがある。これは NetBeans が
gvim (または xemacs :-) と動作できるようにするモジュールである。NetBeans リリー
スにこのモジュールがない場合、このモジュールのダウンロードの詳細については (リ
ンク切れ) externaleditor.netbeans.org を参照。

C、C++、および Fortran のサポートには cpp モジュールも必要になる。このモジュー
ルに関する情報は cpp.netbeans.org (リンクは切れているようだ) を参照。

Sun ONE Studio を Sun Microsystems, Inc から 30 日間の無料試用版としてダウン
ロードすることもできる。詳細は http://www.sun.com を参照。


10.2. NetBeans キーバインド                     netbeans-keybindings

Vim は NetBeans コマンドを実行するいくつかのキーバインドを理解する。これらは通
常、全てのファンクションキーの組み合わせである。NetBeans コマンドを実行するに
は、ユーザーは Pause キーを押し、続いて NetBeans のキーバインドを押さなければ
ならない。例えば、Java ファイルをコンパイルするための NetBeans のキーバインド
は "F9" である。そのため、vim で java ファイルをコンパイルするには "Pause F9"
を押す。カレント行のブレークポイントを切り替えるには、"Pause Shift F8" を押す。

Pause キーはファンクションキー 21 である。動作する Pause キーがなく、代わりに
F8 を使用したい場合、以下を使用する:

        :map <F8> <F21>

External Editor モジュールは NetBeans のキーバインドを動的に読み込むので、
NetBeans がキーバインドを変更した場合でも、vim は常に最新のキーバインドを持つ
はずである。


10.3. Vim 用の NetBeans の準備                  netbeans-preparation

NetBeans が vim と動作するためには、NetBeans External Editor モジュールが読み
込まれ、有効になっていなければならない。Sun ONE Studio Enterprise Edition を
持っている場合、このモジュールは読み込まれ、有効になっているはずである。
NetBeans リリースを持っている場合、このオープンソースのモジュールを入手する別
の方法を見つける必要があるかもしれない。

Tools->Options ダイアログを開き、"Modules" リスト (IDE
Configuration->System->Modules) まで掘り下げることで、このモジュールがあるかを
確認できる。Modules リストに "External Editor" のエントリがある場合、それが有
効になっていることを確認しなければならない ("Enabled" プロパティの値が "True"
であるべきである)。Modules リストに External Editor がない場合、次の節
obtaining-exted を参照。


10.4. External Editor モジュールの入手          obtaining-exted

External Editor モジュールを入手するには 2 つの方法がある。最も簡単な方法は、
NetBeans Update Center を使用してモジュールをダウンロードし、インストールする
ことである。残念ながら、一部のバージョンでは update center にこのモジュールが
ない。update center 経由でダウンロードできない場合、ソースをダウンロードしてモ
ジュールをビルドする必要がある。ビルドが不要になるように、NetBeans Update
Center からモジュールを入手できるよう努めるつもりである。他の入手方法について
は (リンク切れ) externaleditor.netbeans.org も確認すること。

CVS 経由で External Editor のソースをダウンロードして独自のモジュールをビルド
するには、(リンク切れ) externaleditor.netbeans.org および
http://www.netbeans.org を参照。残念ながら、これは簡単な手順ではない。


10.5. Vim と動作するように NetBeans を設定する  netbeans-setup

netbeans-preparation で説明されているように NetBeans External Editor モジュー
ルを読み込んで有効にしていると仮定すると、必要なことは gvim のコマンドラインが
環境に対して適切に設定されていることを確認することだけである。

Tools->Options ダイアログを開き、Editing カテゴリを開く。External Editor を選
択する。右側のペインには Properties タブおよび Expert タブがあるはずである。
Properties タブで "Editor Type" が "Vim" に設定されていることを確認する。
Expert タブで "Vim Command" が正しいことを確認する。

"Vim Command" を変更する場合は注意するべきである。そこには、接続が適切に設定さ
れるためになければならないコマンドラインオプションがある。コマンド名は変更でき
るが、それだけである。gvim が $PATH で見つかる場合、Vim Command は "gvim" で始
めることができる。gvim を $PATH から検索させたくない場合、完全な Unix パス名を
ハードコードする。この時点で、NetBeans で開くあらゆるソースファイルに対して
gvim が得られるはずである。

一部のファイルは gvim で開かれ、他のファイル (異なるファイル拡張子を持つ) はデ
フォルトの NetBeans エディタで開かれる場合、Expert タブの MIME Type プロパティ
の MIME タイプを確認するべきである。NetBeans は MIME 指向であり、External
Editor はこのプロパティで指定された MIME タイプのみを開く。
