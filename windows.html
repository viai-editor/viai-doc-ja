複数のウィンドウとバッファでの編集。                    windows buffers

複数のウィンドウおよびバッファを使用するために追加されたコマンドをここで説明す
る。さらに、2 つ以上のウィンドウと組み合わせて使用した時に異なる動作をするコマ

明されている。

1. はじめに                                     windows-intro window

要約:
   バッファはファイルのメモリ上のテキストである。
   ウィンドウはバッファのビューポートである。
   タブページはウィンドウの集まりである。

ウィンドウはバッファへのビューポートである。1 つのバッファに対して複数のウィン
ドウを、または異なるバッファに対していくつかのウィンドウを使用できる。

バッファは編集のためにメモリに読み込まれたファイルである。元のファイルは、バッ
ファをファイルに書き込むまで変更されないままである。

バッファは 3 つの状態のうちの 1 つになりうる:

                                                        active-buffer
active:   バッファはウィンドウに表示されている。このバッファに対するファイルが
          ある場合、それはバッファに読み込まれている。それ以降にバッファが変更
          されて、その結果ファイルと異なっているかもしれない。
                                                        hidden-buffer
hidden:   バッファは表示されていない。このバッファに対するファイルがある場合、
          それはバッファに読み込まれている。それ以外はアクティブバッファと同じ
          で、ただそれを見ることができないだけである。
                                                        inactive-buffer
inactive: バッファは表示されておらず、何も含んでいない。ファイルが一度読み込ま
          れていた場合、バッファのオプションは記憶されている。viminfo ファイ
          ルからのマークを含むことができる。しかし、バッファはテキストを含んで
          いない。

表にすると:

状態            ウィンドウに    読み込み        ":buffers" 
                表示                            の表示     
active            はい           はい             'a'
hidden            いいえ         はい             'h'
inactive          いいえ         いいえ           ' '

                                                        buffer-reuse
各バッファは一意な番号を持ち、その番号は Vim のセッション内で変わらない。
bufnr() および bufname() 関数を使って、バッファ名とバッファ番号の間で変換
できる。1 つ例外がある: 新しい空のバッファが作成され、それが変更されていない場
合、そのバッファに別のファイルを読み込む時に、そのバッファは再使用される。これ
は、バッファ番号も変わらないことを意味する。

メインの Vim ウィンドウは、いくつかの分割されたウィンドウを保持できる。タブペー
ジ tab-page もあり、それぞれが複数のウィンドウを保持できる。

                                        window-ID winid windowid
各ウィンドウは、ウィンドウ ID と呼ばれる一意な識別子を持つ。この識別子は Vim
のセッション内で変わらない。win_getid() および win_id2tabwin() 関数を使っ
て、ウィンドウ/タブ番号と識別子の間で変換できる。ウィンドウ番号もあり、これは
ウィンドウが開かれるか、または閉じられるたびに変わる可能性がある。winnr() を
参照。
ウィンドウ番号は 1 つの特定のタブでのみ有効である。ウィンドウ ID はタブをまた
いで有効である。ウィンドウ ID またはウィンドウ番号を受け取るほとんどの関数で
は、ウィンドウ番号はカレントタブにのみ適用されるが、ウィンドウ ID はどのタブの
ウィンドウも参照できる。

2. Vim の起動                                           windows-starting

デフォルトでは、Vim は Vi と同じように 1 つのウィンドウで起動する。

Vim の "-o" および "-O" 引数を使って、引数リストの各ファイルに対してウィンドウ
を開くことができる。"-o" 引数はウィンドウを水平に分割し、"-O" 引数はウィンドウ
を垂直に分割する。"-o" および "-O" の両方が与えられた場合、分割方向を決めるの
に最後に現れたものが使用される。例えば、これは水平に分割された 3 つのウィンド
ウを開く:
        vim -o file1 file2 file3

N が 10 進数である "-oN" は、水平に分割された N 個のウィンドウを開く。ウィンド
ウよりファイル名が多い場合、N 個のウィンドウだけが開かれ、いくつかのファイルは
ウィンドウを得ない。ファイル名よりウィンドウが多い場合、最後のいくつかのウィン
ドウは空のバッファを編集することになる。同様に、"-ON" は同じ制限で、垂直に分割
された N 個のウィンドウを開く。

ファイル名が多い場合、ウィンドウは非常に小さくなる。作業できる状況を作るため
に、'winheight' および/または 'winwidth' オプションを設定したいかもしれない。

Buf/Win Enter/Leave autocommand は、新しいウィンドウを開いてファイルを読み込
む時には実行されない。それはそれらに実際に入った時にだけ行われる。

                                                        status-line
ウィンドウを区切るためにステータスラインが使用される。'laststatus' オプション
は、最後のウィンドウもステータスラインを持つ時を指示する:
        'laststatus' = 0        ステータスラインなし
        'laststatus' = 1        ウィンドウが 2 つ以上ある場合はステータスラインあり
        'laststatus' = 2        常にステータスラインあり

'statusline' および 'statuslineopt' オプションで、ステータスラインの内容および
高さを変更できる。どちらもウィンドウにローカルにでき、各ウィンドウが固有のス
テータスラインの外観および高さを持つことを可能にする。

通常、ステータスラインの表示には反転が使用される。これは 'highlight' オプショ
ンの 's' 文字で変更できる。例えば、"sb" はそれを太字に設定する。ステータスライ
ンにハイライトが使用されない場合 ("sn")、カレントウィンドウには '^' 文字が、他
のウィンドウには '=' が使用される。マウスがサポートされ、'mouse' オプションで
有効にされている場合、ステータスラインをドラッグしてウィンドウのサイズを変更で
きる。

Note: ステータスラインが反転表示になることを期待していて、そうならない場合、
'highlight' オプションが "si" を含んでいるか確認すること。バージョン 3.0 では、
これはステータスラインを反転することを意味していた。現在は、ステータスラインを
反転する "sr" であるべきである。"si" は現在はイタリックを表すからである! 端末
でイタリックが使用可能でない場合、いずれにしてもステータスラインは反転される。
この問題は、イタリックの termcap コードを持つ端末でのみ見られる。

                                                        filler-lines
ウィンドウ内のバッファの最終行より後の行は、フィラー行と呼ばれる。デフォルトで
は、これらの行はチルダ (~) 文字で始まる。'fillchars' オプションの "eob" 項目を
使って、この文字を変更できる。デフォルトでは、これらの文字は NonText
(hl-NonText) としてハイライトされる。EndOfBuffer ハイライトグループ
(hl-EndOfBuffer) を使って、フィラー文字のハイライトを変更できる。

3. ウィンドウを開くことと閉じること                     opening-window

CTRL-W s                                                CTRL-W_s
CTRL-W S                                                CTRL-W_S
CTRL-W CTRL-S                                           CTRL-W_CTRL-S
:[N]sp[lit] [++opt] [+cmd]                              :sp :split
                カレントウィンドウを 2 つに分割する。結果は同じファイルに対す
                る 2 つのビューポートになる。

                新しいウィンドウの高さを N にする (デフォルトはカレントウィン
                ドウの高さの半分を使う)。場所を作るためにカレントウィンドウの
                高さを減らす ('equalalways' オプションが設定され、
                'eadirection' が "hor" でなく、それらの 1 つがカレントまたは新
                しいウィンドウより高い場合、他のウィンドウも)。

                Note: CTRL-S は全ての端末で動作するわけではなく、それ以降の入
                力をブロックするかもしれない。再開するには CTRL-Q を使うこと。
                ++opt および +cmd も参照。
                                                        E242 E1159
                自動コマンドの中でウィンドウを分割する時は注意すること。他の
                ウィンドウレイアウトの変更を行っている間にこれが起こると、ウィ
                ンドウレイアウトがめちゃくちゃになるかもしれない。

:[N]sp[lit] [++opt] [+cmd] {file}                       :split_f
                :split と同様だが、新しいウィンドウを作成して、そこでファイ
                ル {file} の編集を開始する。
                これは、まず ":split" をして、次に ":edit" コマンドをするのと
                ほぼ同じように動作するが、元のウィンドウのオルタネートファイル
                名は {file} に設定される。
                [+cmd] が与えられた場合、ファイルが読み込まれた時にそのコマン
                ドを実行する +cmd。
                ++opt も参照。
                新しいウィンドウの高さを N にする (デフォルトは既存の高さの半
                分を使う)。場所を作るためにカレントウィンドウの高さを減らす
                ('equalalways' オプションが設定されている場合、他のウィンドウ
                も)。

CTRL-W CTRL-V                                           CTRL-W_CTRL-V
CTRL-W v                                                CTRL-W_v
:[N]vs[plit] [++opt] [+cmd] [file]                      :vs :vsplit
                :split と同様だが、垂直に分割する。ウィンドウは、以下の場合
                に水平に広げられる
                1. 幅が指定されなかった、
                2. 'equalalways' が設定されている、
                3. 'eadirection' が "ver" でない、および
                4. 他のウィンドウの 1 つがカレントまたは新しいウィンドウより広
                   い。
                N が与えられた場合、可能な場合は新しいウィンドウを N 桁の幅に
                する。
                Note: 他の場所では CTRL-Q は CTRL-V と同じことをするが、ここで
                はそうではない!

CTRL-W n                                                CTRL-W_n
CTRL-W CTRL-N                                           CTRL-W_CTRL-N
:[N]new [++opt] [+cmd]                                  :new
                新しいウィンドウを作成し、そこで空のファイルの編集を開始する。
                新しいウィンドウの高さを N にする (デフォルトは既存の高さの半
                分を使う)。場所を作るためにカレントウィンドウの高さを減らす
                ('equalalways' オプションが設定され、'eadirection' が "hor" で
                ない場合、他のウィンドウも)。
                ++opt および +cmd も参照。
                'fileformats' が空でない場合、与えられた最初の書式が新しいバッ
                ファに使用される。'fileformats' が空の場合、カレントバッファの
                'fileformat' が使用される。これは ++opt 引数で上書きできる。
                自動コマンドは以下の順序で実行される:
                1. カレントウィンドウに対する WinLeave
                2. 新しいウィンドウに対する WinEnter
                3. カレントバッファに対する BufLeave
                4. 新しいバッファに対する BufEnter
                これは、まず ":split" をして、次に ":enew" コマンドをするよう
                に動作する。

:[N]new [++opt] [+cmd] {file}
                :split_f と同様で、新しいウィンドウを作成し、{file} の編集を
                開始する。

:[N]vne[w] [++opt] [+cmd] [file]                        :vne :vnew
                :new と同様だが、垂直に分割する。'equalalways' が設定され、
                'eadirection' が "ver" でない場合、幅が指定されない限り、ウィ
                ンドウは水平に広げられる。

:[N]sv[iew] [++opt] [+cmd] [file]               :sv :sview splitview
                ":split" と同じだが、このバッファに 'readonly' オプションを設
                定する。

:[N]sf[ind] [++opt] [+cmd] {file}            :sf :sfi :sfind splitfind
                ":split" と同じだが、:find と同様に 'path' から {file} を探
                す。{file} が見つからない場合は分割しない。

CTRL-W CTRL-^                                   CTRL-W_CTRL-^ CTRL-W_^
CTRL-W ^        カレントウィンドウを 2 つに分割し、オルタネートファイルを編集
                する。カウント N が与えられた時は、カレントウィンドウを分割し、
                バッファ N を編集する。":sp #" および ":sp #N" に似ているが、
                もう一方のバッファが無名であってもよい。このコマンドは、最初に
                ウィンドウを分割することを除いて、CTRL-^ の動作と一致する。

                                                CTRL-W_:
CTRL-W :        : をタイプするのと同じことをする - コマンドラインを入力する。
                全ての Vim コマンドの前に CTRL-W または 'termwinkey' を付けな
                ければならない端末ウィンドウで便利である。

Note 'splitbelow' および 'splitright' オプションが、新しいウィンドウが現れる場
所に影響することに注意。
                                                                E36
十分な場所がない場合、ウィンドウの作成は失敗する。全てのウィンドウは少なくとも
1 画面行および 1 桁を必要とし、時にはもっと必要とする。オプション
'winminheight' および 'winminwidth' が関係する。

                                                :vert :vertical
:vert[ical] {cmd}
                {cmd} を実行する。それがウィンドウを分割するコマンドを含む場
                合、それは垂直に分割される。vertical wincmd = では、ウィンド
                ウは垂直方向にだけ均等にされる。
                :execute および :normal には効かない。

                                                :hor :horizontal
:hor[izontal] {cmd}
                {cmd} を実行する。現在は horizontal wincmd = に対してだけ違
                いが生じ、それはウィンドウを水平方向にだけ均等にする。

:lefta[bove] {cmd}                              :lefta :leftabove
:abo[veleft] {cmd}                              :abo :aboveleft
                {cmd} を実行する。それがウィンドウを分割するコマンドを含む場
                合、それはカレントウィンドウの左 (垂直分割) または上 (水平分割)
                に開かれる。'splitbelow' および 'splitright' より優先される。
                :execute および :normal には効かない。

:rightb[elow] {cmd}                             :rightb :rightbelow
:bel[owright] {cmd}                             :bel :belowright
                {cmd} を実行する。それがウィンドウを分割するコマンドを含む場
                合、それはカレントウィンドウの右 (垂直分割) または下 (水平分割)
                に開かれる。'splitbelow' および 'splitright' より優先される。
                :execute および :normal には効かない。

                                                :topleft E442
:to[pleft] {cmd}
                {cmd} を実行する。それがウィンドウを分割するコマンドを含む場
                合、それは最上部に現れ、Vim ウィンドウの全幅を占める。分割が垂
                直の時は、ウィンドウは最も左に現れ、Vim ウィンドウの全高を占め
                る。:execute および :normal には効かない。

                                                :bo :botright
:bo[tright] {cmd}
                {cmd} を実行する。それがウィンドウを分割するコマンドを含む場
                合、それは最下部に現れ、Vim ウィンドウの全幅を占める。分割が垂
                直の時は、ウィンドウは最も右に現れ、Vim ウィンドウの全高を占め
                る。:execute および :normal には効かない。

これらのコマンド修飾子を組み合わせて、垂直に分割されたウィンドウが全高を占める
ようにできる。例:
        :vertical topleft split tags
垂直に分割された全高のウィンドウを、Vim ウィンドウの最も左に "tags" ファイルに
対して開く。


ウィンドウを閉じる
------------------

:q[uit]
:{count}q[uit]                                          :count_quit
CTRL-W q                                                CTRL-W_q
CTRL-W CTRL-Q                                           CTRL-W_CTRL-Q
                {count} なし: カレントウィンドウを終了する。{count} が与えられ
                た場合、{count} のウィンドウを終了する。
                                                        edit-window
                最後の編集ウィンドウ (ヘルプまたはプレビューウィンドウを数えな
                い) を終了する時は、Vim を終了する。

                'hidden' が設定されていて、カレントバッファに対するウィンドウ
                が 1 つだけの時は、そのバッファは隠れ状態になる。'hidden' が設
                定されておらず、カレントバッファに対するウィンドウが 1 つだけ
                で、バッファが変更されていた時は、コマンドは失敗する。

                (Note: CTRL-Q は全ての端末で動作するわけではない)。

                [count] が最後のウィンドウ番号より大きい場合、最後のウィンドウ
                が閉じられる:
                    :1quit  " 最初のウィンドウを終了する
                    :$quit  " 最後のウィンドウを終了する
                    :9quit  " 最後のウィンドウを終了する
                            " 開いているウィンドウが 9 個より少ない場合
                    :-quit  " 前のウィンドウを終了する
                    :+quit  " 次のウィンドウを終了する
                    :+2quit " 2 つ先のウィンドウを終了する

                ヘルプウィンドウを閉じる時、それが唯一のウィンドウでない場合、
                Vim は前のウィンドウレイアウトを復元しようとする。:helpclose
                を参照。

:q[uit]!
:{count}q[uit]!
                {count} なし: カレントウィンドウを終了する。{count} が与えられ
                た場合、{count} のウィンドウを終了する。

                これがバッファに対する最後のウィンドウだった場合、そのバッファ
                への変更は全て失われる。最後のウィンドウ (ヘルプウィンドウを数
                えない) を終了する時は、Vim を終了する。'hidden' が設定されて
                いても、バッファの内容は失われる。

:clo[se][!]
:{count}clo[se][!]
CTRL-W c                                        CTRL-W_c :clo :close
                {count} なし: カレントウィンドウを閉じる。{count} が与えられた
                場合、{count} のウィンドウを閉じる。

                'hidden' オプションが設定されている時、またはバッファが変更さ
                れていて [!] が使用された時、そのバッファは隠れ状態になる (そ
                れを編集している別のウィンドウがない限り)。

                カレントタブページに edit-window が 1 つだけあり、別のタブ
                ページがある時、これはカレントタブページを閉じる。tab-page。

                - 画面上にウィンドウが 1 つだけある。

マウスでステータスラインを上下にドラッグして、ウィンドウのサイズを変更すること
もできる。または、垂直の区切り線を左右にドラッグすることによって。これは、使用
している Vim のバージョンがマウスをサポートしていて、'mouse' オプションがそれ
を有効にするように設定されている場合にだけ動作する。

オプション 'winheight' ('wh') は、カレントウィンドウの最小の高さを設定するのに
使用される。このオプションは、別のウィンドウがカレントウィンドウになるたびに使
用される。オプションが '0' の場合、それは無効である。カレントウィンドウが常に
使用可能な全ての空間を埋めるようにするには、'winheight' を非常に大きな値、例え
ば '9999' に設定する。カレントウィンドウでの編集を快適にするには、それを適当な
値、例えば '10' に設定する。

同等の 'winwidth' ('wiw') オプションは、カレントウィンドウの最小の幅を設定する
のに使用される。

オプション 'equalalways' ('ea') が設定されている時、ウィンドウを分割するか、ま
たは閉じた後に、全てのウィンドウが自動的に同じサイズにされる。このオプションを
設定しない場合、ウィンドウを分割するとカレントウィンドウのサイズが減り、他の
ウィンドウはそのままになる。ウィンドウを閉じる時、余った行はその上のウィンドウ
に与えられる。

'eadirection' オプションは、'equalalways' オプションが適用される方向を制限す
る。デフォルトの "both" は両方の方向でサイズを変更する。値が "ver" の時は、ウィ
ンドウの高さだけが均等にされる。垂直に分割されたウィンドウのサイズを手動で変更
し、この幅を保ちたい時にこれを使う。同様に、"hor" はウィンドウの幅だけを均等に
させる。

オプション 'cmdheight' ('ch') は、コマンドラインの高さを設定するのに使用され
る。長いメッセージに対する hit-enter プロンプトが煩わしい場合、このオプショ
ンを 2 または 3 に設定する。

ウィンドウが 1 つだけの場合、そのウィンドウのサイズを変更するとコマンドライン
の高さも変わる。いくつかのウィンドウがある場合、カレントウィンドウのサイズを変
更すると、その下のウィンドウ (および時にはその上のウィンドウ) の高さも変わる。

ウィンドウの最小の高さおよび幅は、'winminheight' および 'winminwidth' で設定さ
れる。これらは厳格な値で、ウィンドウがこれより小さくなることは決してない。


WinScrolled と WinResized 自動コマンド
                                                win-scrolled-resized
ウィンドウサイズの変更を通知してほしい場合、WinResized 自動コマンドイベント
を使用できる。
ウィンドウ内のテキストが垂直または水平にスクロールすることを通知してほしい場
合、WinScrolled 自動コマンドイベントを使用できる。これはウィンドウサイズの変
更でも発生する。
例外: 'incsearch' のためにテキストがスクロールする時は、イベントは発生しない。
                                                        WinResized-event
WinResized イベントは画面表示を更新した後に発生し、その時には複数のウィンド
ウのサイズが変わっている可能性がある。前回から変わったウィンドウの ID のリスト
が v:event.windows 変数で提供される。例えば:
        [1003, 1006]
                                                        WinScrolled-event
WinScrolled イベントは WinResized の後、およびウィンドウがスクロールされた
場合にも発生する。それは垂直 (ウィンドウの最上部のテキストが変わった) または水
平 ('wrap' がオフの時、または最初の行の最初に表示される部分が変わった時) であ
りうる。Note WinScrolled は WinResized よりもずっと多く発生し、編集を少し
遅くするかもしれないことに注意。

WinScrolled によって提供される情報は、変更がある各ウィンドウに対する辞書で、
ウィンドウ ID をキーとして使用し、変更の合計数をキー "all" に持つ。v:event
(Vim9 構文) の値の例:
        {
           all:  {width: 0, height:  2, leftcol: 0, skipcol: 0, topline: 1, topfill: 0},
           1003: {width: 0, height: -1, leftcol: 0, skipcol: 0, topline: 0, topfill: 0},
           1006: {width: 0, height:  1, leftcol: 0, skipcol: 0, topline: 1, topfill: 0},
        }

Note "all" エントリは、個々のウィンドウの絶対値を累積したものを持つことに注意。

何が変わったのかについてもっと情報が必要な場合、またはイベントを "debounce" し
たい (やりすぎる作業を避けるために全てのイベントを処理しない) 場合、
winlayout() および getwininfo() 関数を使用したいかもしれない。

WinScrolled および WinResized は、最初の自動コマンドが追加された時には発生
せず、最初のスクロールまたはサイズ変更の後でのみ発生する。それらは別のタブペー
ジへ切り替える時に発生するかもしれない。

実行されるコマンドは、ウィンドウサイズまたはスクロールの変更を起こさないことが
期待されている。それでもこれが起きた場合、イベントはすぐに再び発生する。言い換
えると: イベントを発生させる直前に、現在のサイズおよびスクロール位置が保存さ
れ、変更があったかどうかを決めるのに使用される。
                                                                E1312
ここでウィンドウレイアウトを変更すること (ウィンドウを分割する、閉じる、または
移動する) は許可されていない。

 [N] は 11 および 31 ではバッファ番号で、デフォルトはカレントバッファ
 [N] は 19 および 39 ではカウント

Note: ":next" は例外である。Vi との互換性のために、ファイル名のリストを受け付
けなければならないからである。


引数リストと複数のウィンドウ
----------------------------

引数リスト内の現在の位置は、ウィンドウごとに異なっていてもよい。":e file" を実
行した時、引数リスト内の位置は同じままだが、その位置のファイルを編集しているわ
けではないことを覚えておくこと。これを示すために、ファイルメッセージ (およびタ
イトルがある場合はタイトル) は "(file (N) of M)" を表示する。ここで "(N)" は
ファイルリスト内の現在の位置で、"M" はファイルリスト内のファイルの数である。

引数リスト内の全てのエントリはバッファリストに追加される。そのため、":bnext"
のようなバッファリストのコマンドでもそれらへ移動できる。

:[N]al[l][!] [N]                                :al :all :sal :sall
:[N]sal[l][!] [N]
                画面を再配置して、各引数に対して 1 つのウィンドウを開く。他の
                全てのウィンドウは閉じられる。カウントが与えられた時は、これが
                開くウィンドウの最大数になる。
                :tab 修飾子付きでは、各引数に対してタブページを開く。
                'tabpagemax' より多くの引数がある時は、それ以降のものは最後の
                タブページ内の分割ウィンドウになる。
                'hidden' オプションが設定されている時、閉じられたウィンドウ内
                の全てのバッファは隠れ状態になる。
                'hidden' が設定されておらず、'autowrite' オプションが設定され
                ている時、変更されたバッファは書き込まれる。そうでない場合、変
                更されたバッファを持つウィンドウは、[!] が与えられない限り取り
                除かれず、[!] が与えられた場合、それらは隠れ状態になる。しか
                し、変更されたバッファが放棄されることは決してないので、変更が
                失われることはない。
                [N] は開くウィンドウの最大数である。'winheight' も開かれるウィ
                ンドウの数を制限する (:vertical が前置された場合は
                'winwidth')。
                Buf/Win Enter/Leave 自動コマンドは、ここでは新しいウィンドウに
                対して実行されない。それはそれらに実際に入った時にだけ行われ
                る。このコマンドの実行中に自動コマンドがウィンドウレイアウトを
                変更した場合、エラーが与えられる。 E249

:[N]sa[rgument][!] [++opt] [+cmd] [N]                   :sa :sargument
                ":split | argument [N]" の短縮形: ウィンドウを分割し、N 番目の
                引数へ移動する。しかし、そのような引数がない時は、ウィンドウは
                分割されない。++opt および +cmd も参照。

:[N]sn[ext][!] [++opt] [+cmd] [file ..]                 :sn :snext
                ":split | [N]next" の短縮形: ウィンドウを分割し、N 個次の引数
                へ移動する。しかし、次のファイルがない時は、ウィンドウは分割さ
                れない。++opt および +cmd も参照。

:[N]spr[evious][!] [++opt] [+cmd] [N]                   :spr :sprevious
:[N]sN[ext][!] [++opt] [+cmd] [N]                       :sN :sNext
                ":split | [N]Next" の短縮形: ウィンドウを分割し、N 個前の引数
                へ移動する。しかし、前のファイルがない時は、ウィンドウは分割さ
                れない。++opt および +cmd も参照。

                                                :sre :srewind
:sre[wind][!] [++opt] [+cmd]
                ":split | rewind" の短縮形: ウィンドウを分割し、最初の引数へ移
                動する。しかし、引数リストがない時は、ウィンドウは分割されな
                い。++opt および +cmd も参照。

                                                :sfir :sfirst
:sfir[st] [++opt] [+cmd]
                ":srewind" と同じ。

                                                :sla :slast
:sla[st][!] [++opt] [+cmd]
                ":split | last" の短縮形: ウィンドウを分割し、最後の引数へ移動
                する。しかし、引数リストがない時は、ウィンドウは分割されない。
                ++opt および +cmd も参照。

                                                :dr :drop
:dr[op] [++opt] [+cmd] {file} ..
                最初の {file} をウィンドウで編集する。
                - ファイルが既にウィンドウで開かれている場合、そのウィンドウへ
                  切り替える。
                - ファイルがウィンドウで開かれていない場合、カレントウィンドウ
                  でファイルを編集する。カレントバッファを abandon できない
                  場合、まずウィンドウが分割される。
                - 引数リストにないウィンドウ、または全幅でないウィンドウは、可
                  能な場合は閉じられる。
                :next コマンドと同様に、argument-list が設定される。このコ
                マンドの目的は、Vim に別のファイルを編集させたいプログラム、例
                えばデバッガから使用できることである。:tab 修飾子を使用する
                時は、各引数がタブページで開かれる。最後のウィンドウは、それが
                空の場合に使用される。
                ++opt および +cmd も参照。

8. 全てのバッファまたはウィンドウでコマンドを実行する           list-repeat

                                                        :windo
:[range]windo {cmd}     各ウィンドウで、または [range] が与えられた場合はウィ
                        ンドウ番号が [range] 内にあるウィンドウでのみ、{cmd}
                        を実行する。これは以下を行うのと同様に動作する:
                                CTRL-W t
                                :{cmd}
                                CTRL-W w
                                :{cmd}
                                etc.
                        これはカレントタブページ内でのみ動作する。
                        1 つのウィンドウでエラーが検出された時、それ以降のウィ
                        ンドウは訪問されない。
                        最後のウィンドウ (またはエラーが発生したところ) がカレ
                        ントウィンドウになる。
                        {cmd} には、複数のコマンドを連結するための '|' を含め
                        ることができる。{cmd} は、ウィンドウを開くか、閉じる
                        か、または並べ替えてはならない。

                        :tabdo、:argdo、:bufdo、:cdo、:ldo、:cfdo、
                        および :lfdo も参照

                                                        :bufdo
:[range]bufdo[!] {cmd}  バッファリスト内の各バッファで、または [range] が与え
                        られた場合はバッファ番号が [range] 内にあるバッファで
                        のみ、{cmd} を実行する。これは以下を行うのと同様に動作
                        する:
                                :bfirst
                                :{cmd}
                                :bnext
                                :{cmd}
                                etc.
                        カレントファイルを abandon できず、[!] がない時は、
                        コマンドは失敗する。
                        1 つのバッファでエラーが検出された時、それ以降のバッ
                        ファは訪問されない。
                        非リストバッファはスキップされる。
                        最後のバッファ (またはエラーが発生したところ) がカレン
                        トバッファになる。
                        {cmd} には、複数のコマンドを連結するための '|' を含め
                        ることができる。{cmd} は、バッファを削除するか、または
                        バッファリストにバッファを追加してはならない。
                        Note: このコマンドの実行中は、Syntax 自動コマンドイベ
                        ントは 'eventignore' に追加されることで無効にされる。
                        これにより各バッファの編集がかなり速くなる。

                        :tabdo、:argdo、:windo、:cdo、:ldo、:cfdo、
                        および :lfdo も参照

例:

        :windo set nolist foldcolumn=0 | normal! zn

これは全てのウィンドウで 'list' オプションをリセットし、折り畳みを無効にする。


        :bufdo set fileencoding= | update

これは各バッファで 'fileencoding' をリセットし、それによってバッファが変更され
た場合はそれを書き込む。結果として、全てのバッファが 'encoding' エンコーディン
グを使用することになる (変換が成功した場合)。

10. プレビューウィンドウ                        preview-window

プレビューウィンドウは、別のファイルを表示 (プレビュー) するための特殊なウィン
ドウである。それは通常、インクルードファイルまたは関数の定義を表示するのに使用
される小さなウィンドウである。
{Vim が +quickfix 機能なしでコンパイルされた時は使用できない}

プレビューウィンドウは (タブページごとに) 1 つだけ存在できる。それは以下のコマ
ンドのどれかで作成される。'previewheight' オプションを設定して、プレビューウィ
ンドウが開かれた時の高さを指定できる。プレビューウィンドウでは、それを識別でき
るように 'previewwindow' オプションが設定される。他のウィンドウを開く/閉じる時
に同じ高さを保つように、'winfixheight' オプションが設定される。
                                                preview-popup
代わりに、'previewpopup' オプションを設定することで、ポップアップウィンドウを
使用できる。設定された時、それは 'previewwindow' および 'previewheight' の設定
より優先される。オプションは値のコンマ区切りのリストである:
        border          ボーダースタイル ('pumborder' を参照)
        borderhighlight ポップアップのボーダー文字に対するハイライトグループ
        close           閉じるボタンを表示する: "on" (デフォルト) または "off"
                        で、値が "on" の場合、それは border の後に設定しなけれ
                        ばならない。
        height          ポップアップの最大の高さ
        highlight       ポップアップのハイライトグループ (デフォルトは Pmenu)
        opacity         不透明度のパーセンテージ 0-100 (デフォルトは 100、完全
                        に不透明)。100 未満の時は、ポップアップの下の内容が透
                        けて見える。
        resize          サイズ変更ハンドルを表示する: "on" (デフォルト) または
                        "off"
        shadow          "off" (デフォルト) または hl-PmenuShadow を使用する
                        "on"
        width           ポップアップの最大の幅

例:
        :set previewpopup=height:10,width:60
        :set previewpopup=border:single,borderhighlight:PmenuBorder
        :set previewpopup=border:custom:─;│;─;│;┌;┐;┘;└
        :set previewpopup=border:round,opacity:80

いくつかの特異な点:
- ファイルが既にバッファにある場合、それは再使用される。これにより、ファイルが
  ポップアップウィンドウに表示されている間に、それを編集できる。
- ポップアップウィンドウではファイルを編集できないので、ATTENTION ダイアログは
  使用されない。しかし、後で同じバッファを通常のウィンドウで開いた場合、それが
  他の場所で編集されていることに気付かないかもしれない。そしてその時に ":edit"
  を使って ATTENTION を発生させ、Abort の "A" で応答すると、プレビューウィンド
  ウは空になる。

                                                :pt :ptag
:pt[ag][!] [tagname]
                ":tag[!] [tagname]" を実行し、カレントバッファまたはカーソル位
                置を変更せずに、見つかったタグを "Preview" ウィンドウに表示す
                る。"Preview" ウィンドウが既に存在する場合、それは (ヘルプウィ
                ンドウと同様に) 再使用される。新しいウィンドウが開かれる場合、
                ウィンドウの高さには 'previewheight' が使用される。:tag も参
                照。
                例については以下を参照。CursorHold-example
                :tag との小さな違い: [tagname] が既に表示されているタグと等
                しい時、マッチするタグリスト内の位置はリセットされない。これに
                より、:ptnext の後で CursorHold の例が動作する。

CTRL-W z                                        CTRL-W_z
CTRL-W CTRL-Z                                   CTRL-W_CTRL-Z :pc :pclose
:pc[lose][!]    現在開いている "Preview" ウィンドウを全て閉じる。'hidden' オプ
                ションが設定されている時、またはバッファが変更されていて [!]
                が使用された時、そのバッファは隠れ状態になる (それを編集してい
                る別のウィンドウがない限り)。"Preview" バッファのどれかを閉じ
                ることができない場合、コマンドは失敗する。:close も参照。

                                                        :pp :ppop
:[count]pp[op][!]
                プレビューウィンドウで ":[count]pop[!]" を実行する。:pop お
                よび :ptag を参照。

CTRL-W }                                                CTRL-W_}
                カーソルの下の識別子をタグとして使用し、それに対して :ptag を
                実行する。新しい Preview ウィンドウ (必要な場合) の高さを N に
                する。N が与えられない場合、'previewheight' が使用される。

CTRL-W g }                                              CTRL-W_g}
                カーソルの下の識別子をタグとして使用し、それに対して :ptjump
                を実行する。新しい Preview ウィンドウ (必要な場合) の高さを N
                にする。N が与えられない場合、'previewheight' が使用される。

                                                        :pb :pbuffer
:[N]pb[uffer][!] [+cmd] [N]
                プレビューウィンドウで、バッファリストからバッファ [N] を編集
                する。[N] が与えられない場合、カレントバッファが編集されたまま
                になる。[!] については :buffer-! を参照。これは、'buflisted'
                フラグを設定せずに、バッファリストにないバッファも編集する。こ
                こでは単一引用符の表記は動作しない。:pbuffer 12'345' は
                12'345' をバッファ名として使用する。
                +cmd も参照。

                                                        :ped :pedit
:ped[it][!] [++opt] [+cmd] {file}
                プレビューウィンドウで {file} を編集する。プレビューウィンドウ
                は :ptag と同様に開かれる。カレントウィンドウおよびカーソル
                位置は変更されない。便利な例:
                        :pedit +/fputc /usr/include/stdio.h

                ++opt および +cmd も参照。

                                                        :ps :psearch
:[range]ps[earch][!] [count] [/]pattern[/]
                :ijump と同様に動作するが、見つかったマッチをプレビューウィ
                ンドウに表示する。プレビューウィンドウは :ptag と同様に開か
                れる。カレントウィンドウおよびカーソル位置は変更されない。便利
                な例:
                        :psearch popen
                :ptag コマンドと同様に、これを使ってカーソルの下の単語につい
                ての情報を自動的に表示できる。これは :ptag を使用するよりも
                賢くないが、タグファイルを必要とせず、システムのインクルード
                ファイル内のマッチも見つける。例:
  :au! CursorHold *.[ch] ++nested exe "silent! psearch " .. expand("<cword>")
                警告: これは遅いかもしれない。

例                                              CursorHold-example 

  :au! CursorHold *.[ch] ++nested exe "silent! ptag " .. expand("<cword>")

これにより、カーソルが 'updatetime' で設定された時間動かなかった時、カーソルの
下のキーワードに対して ":ptag" が実行される。"nested" は他の自動コマンドが実行
されるようにし、プレビューウィンドウで構文ハイライトが動作するようにする。
"silent!" は、タグが見つからなかった時のエラーメッセージを回避する。
CursorHold も参照。これを再び無効にするには:

  :au! CursorHold

良い追加は、見つかったタグをハイライトし、カーソルの下に単語がない時は ":ptag"
を回避し、その他いくつかのことをすることである:

11. 隠れバッファの使用                                  buffer-hidden

隠れバッファはウィンドウに表示されていないが、まだメモリに読み込まれている。こ
れにより、ウィンドウで別のバッファを得るたびにファイルを読み込むか、または書き
込む必要なしに、ファイルからファイルへジャンプすることが可能になる。

                                                        :buffer-!
オプション 'hidden' ('hid') が設定されている場合、別のファイルの編集を開始する
全てのコマンドに対して、放棄されたバッファが保持される: ":edit"、":next"、
":tag" など。バッファリストを移動するコマンドは、'hidden' オプションが設定され
ていなくても、時々カレントバッファを隠れ状態にする。これは、バッファが変更され
ているが、('!' で) 強制的にウィンドウから取り除かれ、'autowrite' がオフである
か、またはバッファが書き込めない時に起こる。

隠れバッファは、何らかのコマンドでそれの編集を開始するか、または ":bdelete" コ
マンドでそれを削除することで、隠れでなくすることができる。

'hidden' はグローバルで、全てのバッファに対して使用される。'bufhidden' オプショ
ンを使って、特定のバッファに対して例外を作ることができる。それは以下の値を取る
ことができる:
        <empty>         'hidden' の値を使用する。
        hide            このバッファを隠す。'hidden' が設定されていない時も。
        unload          隠さずにこのバッファをアンロードする。'hidden' が設定
                        されている時も。
        delete          バッファを削除する。

                                                        hidden-quit
隠れていて変更されたバッファがある間に Vim を終了しようとすると、エラーメッセー
ジが出て、Vim はそのバッファをカレントバッファにする。その後、このバッファを書
き込む (":wq") か、または書き込まずに終了する (":q!") かを決めることができる。
注意すること: 隠れていて変更されたバッファがもっとあるかもしれない!

バッファは非リストでもありうる。これは、それが存在するが、バッファのリストには
ないことを意味する。unlisted-buffer

ファイルのテキストを含む代わりに、バッファを他の目的に使用することもできる。い
くつかのオプションを設定して、バッファの動作を変更できる:
        'bufhidden'     バッファがもうウィンドウに表示されなくなった時に何が起
                        こるか。
        'buftype'       これがどんな種類のバッファか
        'swapfile'      バッファがスワップファイルを持つかどうか
        'buflisted'     バッファがバッファリストに現れる

いくつかの便利な種類のバッファ:

quickfix        エラーリストまたは location リストを含むのに使用される。
                :cwindow および :lwindow を参照。このコマンドは 'buftype'
                オプションを "quickfix" に設定する。これを変更することは想定さ
                れていない! 'swapfile' はオフ。

help            ヘルプファイルを含む。:help コマンドでのみ作成される。ヘルプ
                バッファを示すフラグは内部的なもので、変更できない。ヘルプバッ
                ファでは 'buflisted' オプションはリセットされる。

terminal        端末ウィンドウのバッファ。terminal を参照。ジョブが終了する
                まで、内容を読むことも変更することもできない。

directory       ディレクトリ内容を表示する。ファイルエクスプローラープラグイン
                で使用できる。バッファは以下の設定で作成される:
                        :setlocal buftype=nowrite
                        :setlocal bufhidden=delete
                        :setlocal noswapfile
                バッファ名はディレクトリの名前で、:cd コマンドを使用した時に
                調整される。

                                                scratch-buffer
scratch         いつでも破棄できるテキストを含む。それはウィンドウを閉じる時も
                保持され、明示的に削除しなければならない。設定:
                        :setlocal buftype=nofile
                        :setlocal bufhidden=hide
                        :setlocal noswapfile
                意味のある名前を与えた場合、バッファ名を使ってバッファを識別で
                きる。

                                                unlisted-buffer
unlisted        バッファはバッファリストにない。それは通常の編集には使用され
                ず、ヘルプファイルの表示、ファイル名またはマークの記憶に使用さ
                れる。":bdelete" コマンドもこのオプションを設定するので、それ
                はバッファを完全には削除しない。設定:
                        :setlocal nobuflisted
