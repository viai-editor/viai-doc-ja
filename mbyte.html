マルチバイトサポート                            multibyte multi-byte
                                                Chinese Japanese Korean
これは、1 バイト (1 オクテット) を使用して表現できない多数の文字を持つ言語でテ
キストを編集することについてである。例としては中国語、日本語および韓国語があ

最も一般的な機能の紹介については、ユーザーマニュアルの usr_45.txt を参照。
メッセージおよびメニューの言語を変更するには mlang.txt を参照。

1. はじめに                                             mbyte-first

これは Vim のマルチバイト機能の要約である。運が良い場合、記述どおりに動作し、
あまり苦労せずに Vim を使い始めることができる。何かが動作しない場合、残りを読
まなければならないだろう。Vim に全てのマルチバイト機能を使わせるのに、かなりの
作業および試行錯誤が必要だとしても驚かないこと。残念ながら、どのシステムもマル
チバイト言語を扱う独自の方法を持っており、それはかなり複雑である。


ロケール

まず第一に、現在のロケールが正しく設定されていることを確認しなければならない。
システムがその言語を使用するようにインストールされている場合、おそらくすぐに動
作する。そうでない場合、シェルで環境変数 $LANG を設定することで、しばしば動作
させることができる:

        setenv LANG ja_JP.EUC

残念ながら、ロケールの名前はシステムに依存する。日本語は "ja_JP.EUCjp" または
単に "ja" と呼ばれることもある。現在使用されているものを見るには:

        :language

Vim の中でロケールを変更するには、以下を使用する:

        :language ja_JP.EUC

これが動作しない場合、Vim はエラーメッセージを出す。これは、試してみて、使用し
たいロケール名を見つけるのに良い方法である。しかし、最初から使用されるように、
シェルでロケールを設定するほうが常に良い。

詳細は mbyte-locale を参照。


エンコーディング

ロケールが正しく動作する場合、Vim はそれに応じて 'encoding' オプションを設定し
ようとする。これが動作しない場合、その値を上書きできる:

        :set encoding=utf-8

受け付けられる値の一覧は encoding-values を参照。

その結果、Vim の中で使用される全てのテキストがこのエンコーディングになる。バッ
ファ内のテキストだけでなく、レジスタ、変数などの中のテキストも。これは、
'encoding' の値を変更すると既存のテキストが無効になることも意味する! テキスト
は変わらないが、間違って表示される。

'encoding' に設定されているものとは別のエンコーディングのファイルを編集できる。
Vim はファイルを読み込む時に変換し、書き込む時に元に戻す。'fileencoding'、
'fileencodings' および ++enc を参照。


表示とフォント

端末 (エミュレータ) で作業している場合、それが Vim が動作しているのと同じエン
コーディングを受け付けることを確認しなければならない。そうでない場合、
'termencoding' オプションを使用して、Vim にテキストを自動的に変換させることが
できる。

GUI では、現在の 'encoding' で動作するフォントを選択しなければならない。これが
難しい部分である。使用しているシステム、ロケールおよびいくつかの他のことに依存
する。フォントについての章を参照: X-Windows については mbyte-fonts-X11、およ
び MS-Windows については mbyte-fonts-MSwin。

GTK+ 2 では、この節のほとんどを飛ばしてよい。'guifontset' オプションはもう存在
しない。'guifont' を設定するだけでよく、全てが "ただ動作する" はずである。シス
テムに Xft2 および fontconfig が付属していて、現在のフォントがある字形を含まな
い場合、使用可能な場合は別のフォントが自動的に使用される。'guifontwide' オプ
ションはまだサポートされているが、通常は設定する必要はない。自動のフォント選択
が要求に合わない場合にだけ必要である。

X11 では、'guifontset' オプションに、使用される文字を合わせてカバーするフォン
トのリストを設定できる。韓国語の例:

        :set guifontset=k12,r12

別の方法として、'guifont' および 'guifontwide' を設定できる。'guifont' は単一
幅の文字に使用され、'guifontwide' は 2 倍幅の文字に使用される。したがって、
'guifontwide' のフォントは 'guifont' のちょうど 2 倍の幅でなければならない。
UTF-8 の例:

        :set guifont=-misc-fixed-medium-r-normal-*-18-120-100-100-c-90-iso10646-1
        :set guifontwide=-misc-fixed-medium-r-normal-*-18-120-100-100-c-180-iso10646-1

'guifont' だけを設定することもでき、Vim があなたのためにマッチする
'guifontwide' を探そうとする。


入力

マルチバイト文字を入力するにはいくつかの方法がある:
- X11 では XIM を使用できる。XIM を参照。
- MS-Windows では IME を使用できる。IME を参照。
- 全てのシステムでキーマップを使用できる。mbyte-keymap を参照。

オプション 'iminsert'、'imsearch' および 'imcmdline' は、異なるインプットメソッ
ドを選択するか、または一時的にそれらを無効にするのに使用できる。

2.  ロケール                                            mbyte-locale

最も簡単な設定は、システム全体が、作業したいロケールを使用している時である。し
かし、作業している 1 つのシェルにロケールを設定するか、または Vim の中だけで特
定のロケールを使用することもできる。


ロケールとは何か?                                      locale

世界には多くの言語がある。そして、少なくとも言語の数と同じだけの異なる文化およ
び環境がある。ある地域に対応する言語的な環境は "ロケール" と呼ばれる。これは、
使用される言語、文字セット、ソートの照合順序、日付の書式、通貨の書式などについ
ての情報を含む。Vim にとっては、言語および文字セットだけが本当に重要である。

ロケールは、システムがそれをサポートしている場合にだけ使用できる。いくつかのシ
ステムは、特に USA では、少数のロケールしか持たない。使用したい言語がシステム
に無いかもしれない。その場合、追加のパッケージとしてそれをインストールできるか
もしれない。その方法についてはシステムのドキュメントを確認すること。

ロケールがインストールされる場所はシステムごとに異なる。例えば、
"/usr/share/locale" または "/usr/lib/locale"。システムの setlocale() の man
ページを参照。

これらのディレクトリを見ると、各ロケールの正確な名前が分かる。たいてい大文字/
小文字が重要なので、"ja_JP.EUC" と "ja_jp.euc" は異なる。いくつかのシステムに
は locale.alias ファイルがあり、"nl" のような短い名前から完全な名前
"nl_NL.ISO_8859-1" への変換ができる。

Note X-windows には独自のロケールの仕組みがあることに注意。そして残念ながら、
他の場所で使用されているものとは異なるロケール名を使用する。これは紛らわしい!
Vim にとって重要なのは setlocale() 関数が使用するものであり、それは一般に
X-windows のものではない。何が本当に動作するかを見つけるには、いくつか実験をし
なければならないかもしれない。

                                                        locale-name
locale 名の (簡略化した) 書式は以下である:

        language
または  language_territory
または  language_territory.codeset

Territory は国 (またはその一部) を意味し、codeset は charset を意味する。例
えば、ロケール名 "ja_JP.eucJP" は以下を意味する:
        ja      言語は日本語
        JP      国は日本
        eucJP   codeset は EUC-JP
しかし、"ja"、"ja_JP.EUC"、"ja_JP.ujis" などでもあり得る。そして残念ながら、特
定の言語、地域およびコードセットに対するロケール名は統一されておらず、システム
に依存する。

ロケール名の例:
    文字セット      言語                  ロケール名
    GB2312          中国語 (簡体字)       zh_CN.EUC, zh_CN.GB2312
    Big5            中国語 (繁体字)       zh_TW.BIG5, zh_TW.Big5
    CNS-11643       中国語 (繁体字)       zh_TW
    EUC-JP          日本語                ja, ja_JP.EUC, ja_JP.ujis, ja_JP.eucJP
    Shift_JIS       日本語                ja_JP.SJIS, ja_JP.Shift_JIS
    EUC-KR          韓国語                ko, ko_KR.EUC


ロケールを使用する

システム全体でロケールを使用し始めるには、システムのドキュメントを参照。たいて
いは "/etc" にある設定ファイルで設定する必要がある。

シェルでロケールを使用するには、$LANG 環境値を設定する。韓国語を使用したく、
locale 名が "ko" である時は、以下のようにする:

    sh:    export LANG=ko
    csh:   setenv LANG ko

常に使用するには、これを ~/.profile または ~/.cshrc ファイルに入れることができ
る。

Vim の中だけでロケールを使用するには、:language コマンドを使用する:

        :language ko

常に使用するには、これを ~/.vimrc ファイルに入れる。

または、Vim を起動する時に $LANG を指定する:

   sh:    LANG=ko vim {vim-arguments}
   csh:   env LANG=ko vim {vim-arguments}

このための小さなシェルスクリプトを作ってもよい。

3.  エンコーディング                    mbyte-encoding

Vim は 'encoding' オプションを使用して、Vim の中で使用される時に文字がどのよう
に識別され、エンコードされるかを指定する。これは、バッファ (メモリに読み込まれ
たファイル)、レジスタおよび変数を含む、テキストが使用される全ての場所に適用さ
れる。

                                                        charset codeset
Charset はエンコーディングの別名である。微妙な違いがあるが、Vim を使用する時は
問題にならない。"codeset" も別の似た名前である。

各文字は 1 バイト以上としてエンコードされる。全ての文字が 1 バイトでエンコード
される時、これをシングルバイトエンコーディングと呼ぶ。最もよく使用されるものは
"latin1" と呼ばれる。これは文字の数を 256 に制限する。これらのいくつかは制御文
字であるので、テキストに使用できるのはさらに少ない。

いくつかの文字が 2 バイト以上を使用する時、これをマルチバイトエンコーディング
と呼ぶ。これにより 256 よりずっと多くの文字を使用でき、これはほとんどの東アジ
アの言語に必要である。

ほとんどのマルチバイトエンコーディングは、最初の 127 文字に 1 バイトを使用す
る。これらは ASCII と同じであり、どの言語が使用されていても、プレーン ASCII の
テキストを交換するのが容易になる。したがって、エンコーディングが間違って設定さ
れていても、正しいテキストが見えるかもしれない。

                                                        encoding-names
Vim は多くの異なる文字エンコーディングを使用できる。3 つの主要なグループがある:

1   8bit        シングルバイトエンコーディング、256 の異なる文字。主に USA お
                よびヨーロッパで使用される。例: ISO-8859-1 (Latin1)。全ての文
                字は 1 つの画面セルだけを占める。

2   2byte       ダブルバイトエンコーディング、10000 を超える異なる文字。主にア
                ジアの国々で使用される。例: euc-kr (韓国語)
                画面セルの数はバイト数と等しい (euc-jp で最初のバイトが 0x8e
                の時を除く)。

u   Unicode     ユニバーサルエンコーディング、他の全てを置き換えることができ
                る。ISO 10646。数百万の異なる文字。例: UTF-8。バイトと画面セル
                の間の関係は複雑である。

他のエンコーディングは Vim の内部では使用できない。しかし、他のエンコーディン
グのファイルは変換を使用して編集できる。'fileencoding' を参照。
Note 全てのエンコーディングは、128 までの文字に ASCII を使用しなければならない
(EBCDIC 用にコンパイルされた時を除く) ことに注意。

サポートされている 'encoding' の値は以下である:         encoding-values

1   iso-8859-n  ISO_8859 の変種 (n = 2 から 15)

1   cp737       iso-8859-7 に類似

は、ファイルのエンコーディングと現在のロケールの間で変換するために iconv() に
渡される。MS-Windows では、"cp{number}" はコードページ {number} を使用すること
を意味する。
例:
                :set encoding=8bit-cp1252

同じエンコーディングが使用され、latin1 と呼ばれる。'isprint' は、文字 0x80 -
0xA0 を表示するかどうかに使用できる。

覧:

1   ansi        latin1 と同じ (廃止、後方互換性のため)
2   japan       日本語: Unix では "euc-jp"、MS-Windows では cp932
2   korea       韓国語: Unix では "euc-kr"、MS-Windows では cp949
2   prc         簡体字中国語: Unix では "euc-cn"、MS-Windows では cp936
2   chinese     "prc" と同じ
2   taiwan      繁体字中国語: Unix では "euc-tw"、MS-Windows では cp950
u   utf8        utf-8 と同じ
u   unicode     ucs-2 と同じ
u   ucs2be      ucs-2 と同じ (ビッグエンディアン)
u   ucs-2be     ucs-2 と同じ (ビッグエンディアン)
u   ucs-4be     ucs-4 と同じ (ビッグエンディアン)
u   utf-32      ucs-4 と同じ
u   utf-32le    ucs-4le と同じ
    default     'encoding' のデフォルト値を表し、環境に依存する

UCS コードではバイト順序が重要である。これは厄介なので、可能な限り UTF-8 を使
用すること。デフォルトではビッグエンディアン (最上位バイトが最初に来る) を使用
する:
            名前        バイト          文字
            ucs-2             11 22         1122
            ucs-2le           22 11         1122
            ucs-4       11 22 33 44     11223344
            ucs-4le     44 33 22 11     11223344

MS-Windows のシステムでは、それがリトルエンディアンの UCS-2 を使用するので、し
ばしば "ucs-2le" を使用したくなる。

似ているが、完全には同じではないエンコーディングがいくつかある。Vim はそれらを
異なるエンコーディングであるかのように扱うので、必要な時に変換が行われる。変換
を避けるため、または変換ができない時に、似た名前を使用したいかもしれない:

        cp932, shift-jis, sjis
        cp936, euc-cn

                                                        encoding-table
通常、'encoding' は現在のロケールと等しく、'termencoding' は空である。これは、
キーボードおよびディスプレイが現在のロケールでエンコードされた文字で動作し、
Vim が内部で同じ文字を使用することを意味する。

'encoding' オプションを異なる値に設定することで、Vim に異なるエンコーディング
の文字を使用させることができる。キーボードおよびディスプレイは引き続き現在のロ
ケールを使用するので、変換を行う必要がある。その場合、'termencoding' が現在の
ロケールの値を引き継ぐので、Vim は 'encoding' と 'termencoding' の間で変換す
る。例:
        :let &termencoding = &encoding
        :set encoding=utf-8

しかし、値の全ての組み合わせが可能なわけではない。以下の表は、9 つの組み合わせ
のそれぞれがどのように動作するかを示している。これは、全ての変換が可能なわけで
はないこと、iconv() が存在することなどによって、さらに制限される。これは使用さ
れるシステムに依存するので、詳細な一覧を示すことはできない。

('tenc' は 'termencoding' の短縮名、'enc' は 'encoding' の短縮名)

'tenc'      'enc'       備考

 8bit       8bit        動作する。'termencoding' が 'encoding' と異なる時は、
                        いくつかの文字のタイプおよび表示が間違うかもしれず、
                        Vim は変換を行わない (これを得るには 'encoding' を
                        "utf-8" に設定する)。
 8bit      2byte        MS-Windows: システムにインストールされている全てのコー
                        ドページで動作する。8bit 文字だけをタイプできる。
                        その他のシステム: 動作しない。
 8bit      Unicode      動作するが、直接タイプできるのは 8bit 文字だけである
                        (他はダイグラフ、キーマップなどを通して)。端末では
                        8bit 文字だけが見え、GUI は 'guifont' がサポートする全
                        ての文字を表示できる。

 2byte      8bit        動作するが、非 ASCII 文字のタイプが問題になるかもしれ
                        ない。
 2byte     2byte        MS-Windows: システムにインストールされている全てのコー
                        ドページで動作する。ロケールが 'encoding' と異なる時
                        は、文字のタイプが問題になるかもしれない。
                        その他のシステム: 'termencoding' が 'encoding' と等し
                        い時だけ動作する。空のままにしておいてもよい。
 2byte     Unicode      動作し、Vim はタイプされた文字を変換する。

 Unicode    8bit        動作する (普通ではない)
 Unicode    2byte       動作しない
 Unicode   Unicode      非常によく動作する (全ての Unicode は内部で UTF-8 とし
                        て扱われるので、'termencoding' を空のままにしても同じ
                        ように動作する)

変換                                                   charset-conversion

Vim はいくつかの場所で、あるエンコーディングから別のエンコーディングへ自動的に
変換する:
- ファイルを読み込み、'fileencoding' が 'encoding' と異なる時
- ファイルを書き込み、'fileencoding' が 'encoding' と異なる時
- 文字を表示し、'termencoding' が 'encoding' と異なる時
- 入力を読み取り、'termencoding' が 'encoding' と異なる時
- メッセージを表示し、LC_MESSAGES に使用されるエンコーディングが 'encoding' と
  異なる時 (これをサポートする gettext のバージョンが必要)。
- :scriptencoding が 'encoding' と異なる Vim script を読み込む時。
- viminfo ファイルを読み込むか、または書き込む時。
これらのほとんどは +iconv 機能を必要とする。ファイルの読み込みおよび書き込み
のための変換は、'charconvert' オプションで指定することもできる。

文字セットを変換するための便利なユーティリティ:
    全て:           iconv
        GNU iconv はほとんどのエンコーディングを変換できる。Unicode が中間エン
        コーディングとして使用され、これにより他の全てのエンコーディングとの間
        の変換ができる。http://www.gnu.org/directory/libiconv.html を参照。

    日本語:         nkf
        Nkf は "Network Kanji code conversion Filter" である。nkf の最もユニー
        クな機能の 1 つは、入力の漢字コードの推測である。そのため、入力ファイ
        ルの charset が何であるかを知る必要はない。ISO-2022-JP または
        Shift_JIS から EUC-JP へ変換する時は、Vim で以下のコマンドを実行するだ
        けでよい:
            :%!nkf -e
        Nkf は以下で見つけられる:
        http://www.sfc.wide.ad.jp/~max/FreeBSD/ports/distfiles/nkf-1.62.tar.gz

    中国語:         hc
        Hc は "Hanzi Converter" である。Hc は GB ファイルを Big5 ファイルに、
        または Big5 ファイルを GB ファイルに変換する。Hc は以下で見つけられる:
        https://www.freshports.org/chinese/hc
        ftp://ftp.cuhk.hk/pub/chinese/ifcss/software/unix/convert/hc-30.tar.gz

    韓国語:         hmconv
        Hmconv は、特に E-mail 用の韓国語コード変換ユーティリティである。
        EUC-KR と ISO-2022-KR の間で変換できる。Hmconv は以下で見つけられる:
        https://www.freshports.org/korean/hmconv/

    多言語:         lv
        Lv は強力な多言語ファイルビューアである。そして charset 変換器として
        動作させることができる。サポートされる charset: ISO-2022-CN、
        ISO-2022-JP、ISO-2022-KR、EUC-CN、EUC-JP、EUC-KR、EUC-TW、UTF-7、
        UTF-8、ISO-8859 シリーズ、Shift_JIS、Big5 および HZ。Lv は以下で見つけ
        られる (リンクは切れているようだ):
        ff.iij4u.or.jp/~nrt/lv/index.html


                                                        mbyte-conversion
'encoding' と異なるエンコーディングのファイルを読み込む時および書き込む時は、
変換を行う必要がある。以下の変換がサポートされている:
- Latin-1 (ISO-8859-1)、UTF-8、UCS-2 および UCS-4 の間の全ての変換は内部で処理
  される。
- MS-Windows では、'encoding' が Unicode エンコーディングの時は、任意のコード
  ページとの間の変換が動作するはずである。
- 'charconvert' で指定された変換
- iconv ライブラリが使用可能な場合は、それによる変換。
        古いバージョンの GNU iconv() は変換を失敗させることがある (非常に大き
        なバッファ、Vim が提供しようとする以上のものを要求する)。別の iconv()
        の実装を入手してみること。

                                                        iconv-dynamic
MS-Windows では、Vim を +iconv/dyn 機能付きでコンパイルできる。これは、Vim
が "iconv.dll" および "libiconv.dll" ライブラリを探すことを意味する。そのどち
らも見つからない時は、Vim はそれでも動作するが、いくつかの変換はできない。

4. 端末を使用する                                       mbyte-terminal

GUI はマルチバイト文字を完全にサポートしている。端末でも、端末が Vim が使用す
るのと同じエンコーディングをサポートしている場合は可能である。したがって、これ
は柔軟性が低い。

例えば、マルチバイトサポートおよび/または XIM が追加された xterm で Vim を実
行できる。例としては kterm (Kanji term) および hanterm (韓国語用)、Eterm
(Enlightened terminal) および rxvt がある。

端末が正しいエンコーディングをサポートしていない場合、'termencoding' オプショ
ンを設定できる。そうすると、Vim はタイプされた文字を 'termencoding' から
'encoding' に変換する。そして、表示されるテキストは 'encoding' から
'termencoding' に変換される。端末がサポートするエンコーディングが Vim が使用す
る全ての文字を含んでいない場合、これは文字の喪失につながる。これにより表示が乱
れるかもしれない。以下で述べる xterm のような、Unicode をサポートする端末を使
用している場合、ほとんど全ての文字セットは情報を失うことなく Unicode に変換で
きるので、問題なく動作するはずである。


XFREE86 XTERM での UTF-8                               UTF8-xterm

これは、XFree86 に付属する Thomas Dickey による xterm で UTF-8 文字エンコーディ
ングを使用する方法の短い説明である (Markus Kuhn による文章)。

UTF-8 をサポートするようになった最新の xterm のバージョンを入手する:

        http://invisible-island.net/xterm/xterm.html

"./configure --enable-wide-chars ; make" でコンパイルする

また、様々なフォントの ISO 10646-1 版を入手する。これは以下で入手できる

        http://www.cl.cam.ac.uk/~mgk25/download/ucs-fonts.tar.gz

そして、README ファイルに記載されているとおりにフォントをインストールする。

次に、以下で xterm を起動する

  xterm -u8 -fn -misc-fixed-medium-r-semicondensed--13-120-75-75-c-60-iso10646-1
または、より大きな文字の場合:
  xterm -u8 -fn -misc-fixed-medium-r-normal--15-140-75-75-c-90-iso10646-1

そうすると、動作する UTF-8 端末エミュレータができる。以下の両方を試すこと

   cat utf-8-demo.txt
   vim utf-8-demo.txt

xterm で UTF-8 に何か問題があるかどうかを確認するために、ucs-fonts.tar.gz に付
属するデモテキストで。

Vim では、'encoding' を "utf-8" に設定する必要があるかもしれない。

5.  X11 のフォント                                      mbyte-fonts-X11

残念ながら、X11 でフォントを使用するのは複雑である。シングルバイトフォントの名
前は長い文字列である。マルチバイトフォントでは、これがいくつか必要である...

Note: このほとんどは GTK+ 2 ではもはや関係ない。XLFD によるフォントの選択はサ
ポートされていない。フォントを設定する方法の例については 'guifont' を参照。自
分のためにも、以下の XLFD および xfontset の節は無視すること。

まず第一に、Vim はテキストの表示に固定幅フォントだけを受け付ける。プロポーショ
ナルフォントは使用できない。これにより、使用可能な (そしてより見栄えの良い)
フォントの多くが除外される。ただし、メニューおよびツールチップには任意のフォン
トを使用できる。

Note 表示と入力は独立していることに注意。その言語のインプットメソッドが無くて
も、その言語を見ることはできる。

動作するメニューおよびツールチップ用のデフォルトのフォントが得られるはずだが、
見栄えが悪いかもしれない。より良いフォントを選択する方法を知るには、以下を読む
こと。


X 論理フォント記述 (XLFD)
                                                        XLFD
XLFD は X のフォント名であり、フォントサイズ、文字セットなどについての情報を含
んでいる。名前は以下の書式である:

FOUNDRY-FAMILY-WEIGHT-SLANT-WIDTH-STYLE-PIXEL-POINT-X-Y-SPACE-AVE-CR-CE

各フィールドは以下を意味する:

- FOUNDRY:  FOUNDRY フィールド。フォントを作成した会社。
- FAMILY:   FAMILY_NAME フィールド。基本のフォントファミリー名。(helvetica、
            gothic、times など)
- WEIGHT:   WEIGHT_NAME フィールド。文字の太さ。(light、medium、bold など)
- SLANT:    SLANT フィールド。
                r:  ローマン (傾きなし)
                i:  イタリック
                o:  オブリーク
                ri: 逆イタリック
                ro: 逆オブリーク
                ot: その他
                数値:   スケーリングされたフォント
- WIDTH:    SETWIDTH_NAME フィールド。文字の幅。(normal、condensed、narrow、
            double wide)
- STYLE:    ADD_STYLE_NAME フィールド。フォントを記述する追加情報。(Serif、
            Sans Serif、Informal、Decorated など)
- PIXEL:    PIXEL_SIZE フィールド。ピクセル単位での文字の高さ。
- POINT:    POINT_SIZE フィールド。ポイント単位での文字の高さの 10 倍。
- X:        RESOLUTION_X フィールド。X 解像度 (1 インチあたりのドット数)。
- Y:        RESOLUTION_Y フィールド。Y 解像度 (1 インチあたりのドット数)。
- SPACE:    SPACING フィールド。
                p:  プロポーショナル
                m:  等幅
                c:  文字セル
- AVE:      AVERAGE_WIDTH フィールド。ピクセル単位での平均幅の 10 倍。
- CR:       CHARSET_REGISTRY フィールド。文字セットグループの名前。
- CE:       CHARSET_ENCODING フィールド。文字セット名の残りの部分。JIS X 0208
            のようないくつかの文字セットでは、このフィールドが 0 の場合、コー
            ドポイントは GL と同じ値を持ち、1 の場合は GR と同じ値を持つ。

例えば、JIS X 0208 に対応する 16 ドットフォントの場合、以下のように書かれる:
    -misc-fixed-medium-r-normal--16-110-100-100-c-160-jisx0208.1990-0


X フォントセット
                                                fontset xfontset
シングルバイトの文字セットは、通常 1 つのフォントに関連付けられている。マルチ
バイトの文字セットでは、フォントの組み合わせがしばしば使用される。これは、文字
のあるグループがあるフォントから使用され、別のグループが別のフォント (2 倍幅か
もしれない) から使用されることを意味する。このフォントの集まりはフォントセット
と呼ばれる。

フォントセットでどのフォントが必要かは、現在のロケールに依存する。X windows
は、あるロケールにどの文字のグループが必要かの表を保持している。ロケールが必要
とする全てのフォントを 'guifontset' オプションに指定しなければならない。

'guifontset' オプションを設定すると、全てのフォント名がフォントセット名として
扱われることにもなる。:highlight コマンドの "font" 引数に使用されるものも。

Note 'guifont' と 'guifontset' の間の違いに注意: 'guifont' では、コンマ区切り
の名前は代替の名前であり、そのうちの 1 つが使用される。'guifontset' では、文字
列全体が、コンマを含めて 1 つのフォントセット名である。代替のフォントセット名
を指定することはできない。
この例は多くの X11 システムで動作する:
        :set guifontset=-*-*-medium-r-normal--16-*-*-*-c-*-*-*

フォントは現在のロケールにマッチしなければならない。現在のロケールが使用する文
字セットのフォントが含まれていない場合、'guifontset' の設定は失敗する。

NOTE: フォントセットは、'encoding' が異なる文字セットを使用するように設定され
ていても、常に現在のロケールを使用する。その状況では、'guifontset' の代わりに
'guifont' および 'guifontwide' を使用したいかもしれない。

例:
    |charset| 言語                  "文字のグループ"
    GB2312    中国語 (簡体字)       ISO-8859-1 および GB 2312
    Big5      中国語 (繁体字)       ISO-8859-1 および Big5
    CNS-11643 中国語 (繁体字)       ISO-8859-1、CNS 11643-1 および CNS 11643-2
    EUC-JP    日本語                JIS X 0201 および JIS X 0208
    EUC-KR    韓国語                ISO-8859-1 および KS C 5601 (KS X 1001)

xlsfonts コマンドを使用してフォントを検索できる。例えば、KS C 5601 用のフォン
トを検索している時:
    xlsfonts | grep ksc5601

これは複雑で紛らわしい。何か分からないことがある場合は、X-Windows のドキュメン
トを参照するとよいかもしれない。

                                                base_font_name_list
使用したいフォントの名前が見つかったら、'guifontset' オプションを設定する必要
がある。フォント名を連結し、それらの間にコンマを置くことで、リストを指定する。

例えば、ja_JP.eucJP ロケールを使用する時は、JIS X 0201 および JIS X 0208 が必
要である。文字セットを明示的に指定するフォントのリストを与えることができる。以
下のように:

 :set guifontset=-misc-fixed-medium-r-normal--14-130-75-75-c-140-jisx0208.1983-0,
        \-misc-fixed-medium-r-normal--14-130-75-75-c-70-jisx0201.1976-0

別の方法として、文字セット名を省略した基本フォント名リストを与え、X-Windows に
ロケールに必要なフォント文字を選択させることもできる。例えば:

 :set guifontset=-misc-fixed-medium-r-normal--14-130-75-75-c-140,
        \-misc-fixed-medium-r-normal--14-130-75-75-c-70

別の方法として、X-Windows が全ての使用可能なフォントから選択できるような単一の
基本フォント名を与えることもできる。例えば:

 :set guifontset=-misc-fixed-medium-r-normal--14-*

別の方法として、別名を指定することもできる。フォントディレクトリ (例:
/usr/X11R6/lib/X11/fonts/) にある fonts.alias ファイルを参照。例えば:

 :set guifontset=k14,r14

                                                        E253
Note 東アジアのフォントでは、標準の文字セルは正方形であることに注意。ラテンフォ
ントと東アジアのフォントを混在させる時は、東アジアのフォントの幅はラテンフォン
トの幅の 2 倍であるべきである。

'guifontset' が空でない場合、:highlight コマンドの "font" 引数もフォントセッ
トとして解釈される。例えば、ハイライトには以下を使用すべきである:
        :hi Comment font=english_font,your_font
間違った "font" 引数を使用した場合、エラーメッセージが表示される。
また、ハイライトグループのフォントを設定する前に、'guifontset' を設定するよう
にすること。


リソースファイルを使用する

'guifontset' を指定する代わりに、X11 リソースを設定して Vim にそれらを取り込ま
せることができる。これは X のリソースファイルがどのように動作するかを知ってい
る人だけのためのものである。

Motif では、$HOME/.Xdefaults ファイルに以下の 3 行を挿入する:

        Vim.font: base_font_name_list
        Vim*fontSet: base_font_name_list
        Vim*fontList: your_language_font

Note: Vim.font はテキスト領域用である。
      Vim*fontSet はメニュー用である。
      Vim*fontList はメニュー用である (Motif GUI の場合)

例えば、日本語および 14 ドットのフォントを使用している時は、

        Vim.font: -misc-fixed-medium-r-normal--14-*
        Vim*fontSet: -misc-fixed-medium-r-normal--14-*
        Vim*fontList: -misc-fixed-medium-r-normal--14-*

または:

        Vim*font: k14,r14
        Vim*fontSet: k14,r14
        Vim*fontList: k14,r14

すぐに有効にするには、以下を実行しなければならない

        xrdb -merge ~/.Xdefaults

そうしないと、変更が有効になる前に X サーバーを停止して再起動しなければならな
い。


GUI Vim の GTK+ 版は .Xdefaults を使用しない。代わりに ~/.gtkrc を使用するこ
と。デフォルトでたいていはうまく動作する。しかし、メニューについては変更する必
要があるかもしれない。例:

        style "default"
        {
                fontset="-*-*-medium-r-normal--14-*-*-*-c-*-*-*"
        }
        widget_class "*" style "default"

7.  X11 での入力                                mbyte-XIM

X インプットメソッド (XIM) の背景              XIM xim x-input-method

XIM は X のための国際的な入力モジュールである。2 種類の構造、Xlib unit タイプ
および IM-server (Input-Method server) タイプがある。IM-server タイプは
CJK のような複雑な入力に適している。

- IM-server
                                                        IM-server
  IM-server タイプの入力構造では、入力イベントは 2 つの方法のどちらかで処理
  される: FrontEnd システムおよび BackEnd システム。FrontEnd システムでは、入
  力イベントはまず IM-server に横取りされ、それから IM-server がアプリケー
  ションに入力の結果を渡す。一方、BackEnd システムは逆の順序で動作する。
  MS-Windows は BackEnd システムを採用している。X では、ほとんどの IM-server
  は FrontEnd システムを採用している。BackEnd システムの欠点は通信のオーバー
  ヘッドが大きいことであるが、アプリケーションに制限なく安全な同期を提供する。

  例えば、日本語の IM-server には xwnmo および kinput2 があり、どちらも
  FrontEnd システムである。Xwnmo は Wnn (以下を参照) と一緒に配布されており、
  kinput2 は以下で見つけられる (リンクは切れているようだ):
  ftp://ftp.sra.co.jp/pub/x11/kinput2/

  中国語には、"xcin" という素晴らしい XIM サーバーがあり、繁体字および簡体字の
  中国語の文字の両方を入力できる。そして、正しい入力テーブルを作った場合、他の
  ロケールも受け付けることができる。Xcin は以下で見つけられる (リンクは切れて
  いるようだ): http://cle.linux.org.tw/xcin/
  他には scim: https://www.freedesktop.org/wiki/Software/scim/ および fcitx:
  http://www.fcitx.org/ がある。

- 変換サーバー
                                                        conversion-server
  いくつかのシステムは追加のサーバーを必要とする: 変換サーバーである。日本語の
  IM-server のほとんどは、それ、かな漢字変換サーバーを必要とする。中国語の入
  力では、入力の方法に依存し、いくつかの方法では、PinYin または ZhuYin から
  HanZi への変換サーバーが必要である。韓国語の入力では、Hanja を入力したい場
  合、Hangul-Hanja 変換サーバーが必要である。

  例えば、日本語の入力処理は 2 つの段階に分けられる。まず、ひらがなを事前入力
  し、次に、かな漢字変換を行う。漢字の文字は非常に多く (JIS X 0208 では 6349
  の漢字が定義されている)、ひらがなの文字の数は 76 である。そこで、まず、ひら
  がなで発音どおりにテキストを事前入力し、次に、必要な場合は、ひらがなを漢字ま
  たはカタカナに変換する。かな漢字変換サーバーはいくつかある: jserver (Wnn と
  一緒に配布されている、以下を参照) および canna。Canna は以下で見つけられる:
  (リンク切れ) osdn.net/projects/canna/

良い入力システムがある: Wnn4.2。Wnn 4.2 は以下を含む、
    xwnmo (IM-server)
    jserver (日本語かな漢字変換サーバー)
    cserver (中国語 PinYin または ZhuYin から簡体字 HanZi への変換サーバー)
    tserver (中国語 PinYin または ZhuYin から繁体字 HanZi への変換サーバー)
    kserver (Hangul-Hanja 変換サーバー)
いくつかのシステム用の Wnn 4.2 は、インターネット上の様々な場所で見つけられる。
システム用の RPM または port を使用すること。


- 入力スタイル
                                                        xim-input-style
  CJK を入力する時は、4 つの領域がある:
      1. 組み立てられている間の入力を表示する領域
      2. 現在有効な入力モードを表示する領域。
      3. 選択のための次の候補を表示する領域。
      4. 他のツールを表示する領域。

  3 番目の領域は変換する時に必要である。例えば、日本語の入力では、複数の漢字が
  同じ発音を持つことがあるので、ひらがなの並びが別個の漢字の並びにマップされる
  ことがある。

  1 番目および 2 番目の領域は、X の国際入力で、それぞれ "Preedit Area"、
  "Status Area" という名前で定義されている。3 番目および 4 番目の領域は定義さ
  れておらず、IM-server によって管理されるように任されている。国際入力では、
  Preedit Area および Status Area の組み合わせを使用して、4 つの入力スタイルが
  定義されている: OnTheSpot、OffTheSpot、OverTheSpot および Root。

  現在、GUI Vim は 3 つのスタイル、OverTheSpot、OffTheSpot および Root
  をサポートしている。
  +GUI_GTK 機能付きでコンパイルされた時は、GUI Vim は 2 つのスタイル、
  OnTheSpot および OverTheSpot をサポートする。'imstyle' オプションでスタ
  イルを選択できる。

*.  on-the-spot                                         OnTheSpot
    Preedit Area および Status Area は、クライアントアプリケーションによってア
    プリケーションの領域内で実行される。クライアントアプリケーションは
    IM-server によって、全てのプリエディットデータをテキストの挿入位置に表示
    するように指示される。クライアントは、プリエディットの間にインプットメソッ
    ドによって呼び出されるコールバックを登録する。
*.  over-the-spot                                       OverTheSpot
    Status Area は、アプリケーションの領域内の固定の位置に作成され、Vim の場
    合、その位置は追加のステータス行である。Preedit Area は、アプリケーション
    の現在の入力位置に作られる。インプットメソッドは、テキストの挿入位置の真上
    に出現させるウィンドウ内にプリエディットデータを表示する。
*.  off-the-spot                                        OffTheSpot
    Preedit Area および Status Area はアプリケーションの領域内で実行され、Vim
    の場合、その領域は追加のステータス行である。クライアントアプリケーション
    は、プリエディットデータのための表示ウィンドウをインプットメソッドに提供
    し、インプットメソッドはそれらに直接表示する。
*.  root-window                                         Root
    Preedit Area および Status Area はアプリケーションの外側にある。インプット
    メソッドは、全てのプリエディットデータを、画面の別の領域の、インプットメ
    ソッド固有のウィンドウ内に表示する。


XIM を使用する         multibyte-input E284 E285 E286 E287
                                        E288 E289

Note 表示と入力は独立していることに注意。その言語のインプットメソッドが無くて
も、その言語を見ることはできる。しかし、表示方法が入力方法にマッチしない時は、
テキストは間違って表示される。

        Note: 'guifontset' を指定しない限り、IM を使用することはできない。
              したがって、ラテン系のユーザーは、IM を使用する場合、
              'guifontset' も使用しなければならない。

自分の言語を入力するには、その言語をサポートする IM-server および、必要な場
合は conversion-server を実行すべきである。

以下の 3 行を ~/.Xdefaults ファイルに入れるべきである。これらは XIM を使用す
る全ての X アプリケーションに共通である。既に XIM を使用している場合は、これ
は飛ばしてよい。

        *international: True
        *.inputMethod: your_input_server_name
        *.preeditType: your_input_style

input_server_name       は、IM-server の名前である (IM-server のマニュアル
                        を確認すること)。
your_input_style        は、OverTheSpot、OffTheSpot、Root のいずれかであ
                        る。xim-input-style も参照。

*international は、X11R6 を使用している場合は必要ないかもしれない。
*.inputMethod および *.preeditType は、X11R6 を使用している場合はオプションで
ある。

例えば、IM-server として kinput2 を使用している時は、

        *international: True
        *.inputMethod: kinput2
        *.preeditType: OverTheSpot

OverTheSpot を使用する時は、GUI Vim はノーマルモードでも常に IM Server に接
続するので、"f" および "r" のようなコマンドで自分の言語を入力できる。しかし、
他の 2 つの方法のいずれかを使用する時は、GUI Vim はノーマルモードでない場合に
だけ IM Server に接続する。

IM Server が OverTheSpot をサポートしておらず、"f" または "r" のようないくつ
かのノーマルモードのコマンドで自分の言語を使用したい場合は、ローカライズされた
xterm または XIM をサポートする xterm を使用すべきである

必要な場合、XMODIFIERS 環境変数を設定できる:

        sh:  export XMODIFIERS="@im=input_server_name"
        csh: setenv XMODIFIERS "@im=input_server_name"

例えば、IM-server として kinput2 を使用し、sh を使用している時は、

        export XMODIFIERS="@im=kinput2"


完全に制御された XIM

MS-Windows の IME のように、XIM を完全に制御できる (multibyte-ime を参照)。
これは現在、GTK GUI でのみ使用可能である。

完全に制御された XIM を使用する前に、1 つの設定が必要である。'imactivatekey'
オプションに、インプットメソッドの有効化に使用されるキーを設定する。例えば、IM
Server として kinput2 + canna を使用している時は、有効化キーはおそらく
Shift+Space である:

        :set imactivatekey=S-space

書式については 'imactivatekey' を参照。

8.  MS-Windows での入力                                 mbyte-IME

(Windows IME サポート)                          multibyte-ime IME

{Vim の Windows GUI で、かつ +multi_byte_ime 機能付きでコンパイルされた場合
にのみ動作する}

Windows でマルチバイト文字を入力するには、Input Method Editor (IME) を使用でき
る。テキストを編集する過程で、IME の状態 (on/off) を何度も何度も何度も切り替え
なければならない。状態が on の IME は全てのキー入力をフックしているので、'j'、
'k'、またはほとんど全てのキーを Vim に直接入力することはできない。

+multi_byte_ime 機能はこれを助ける。IME の状態を手動で切り替えなければならな
い回数を減らす。ノーマルモードでは、マルチバイトのテキストを編集している時で
も、IME を使用する必要はほとんどない。そのため、挿入モードを抜ける時に、Vim は
IME の最後の状態を記憶し、IME をオフにする。挿入モードに再び入る時に、Vim は
IME の状態をその記憶した状態に自動的に設定する。

これは挿入-ノーマルモードだけでなく、検索コマンドの入力および置換モードでも動
作する。
オプション 'iminsert'、'imsearch' および 'imcmdline' は、異なるインプットメソッ
ドを選択するか、または一時的にそれらを無効にするのに使用できる。

Windows 9x および Windows NT 4.0 では global-ime があったが、これはもうサポー
トされていない。Active Input Method Manager (Global IME) のドキュメントは、ま
だここで見つけられる:
        http://msdn.microsoft.com/en-us/library/aa741221(v=VS.85).aspx

NOTE: IME が動作するためには、システムに自分の言語の入力ロケールが追加されてい
ることを確認しなければならない。この正確な場所は、使用している Windows のバー
ジョンに依存する。例えば、私の Windows 2000 マシンでは:
1. コントロールパネル
2. 地域のオプション
3. 入力ロケールタブ
4. インストールされている入力ロケールの追加 -> Chinese(PRC)
   デフォルトは依然として English (United Stated) である


MS-Windows IME 互換性                           multibyte-ime-compatibility

Vim は Windows システムでのインプットメソッドを imm32.dll (Input Method
Manager) を介して管理している。この実装は Windows 2000 の時代にさかのぼるもの
で、最新のインプットメソッドとは完全には互換でないかもしれない。最新のインプッ
トメソッドの処理は Text Services Framework (TSF) に移行しており、その動作は従
来の IME のインターフェイスと完全には一致しないかもしれない。IME および TSF に
ついての詳細は、Microsoft のドキュメントのウェブサイトを参照 (MS のドキュメン
トの URL はしばしば変わるため、リンクは省略している)。

場合によっては、Windows の表示言語が CJK の言語に設定されている時に、Vim が起
動時にノーマルモードでインプットメソッド (IM) を誤って有効にすることがある。こ
の問題を回避するには、gvimrc ファイルに以下の設定を追加してみること:

        autocmd VimEnter * set imdisable | set noimdisable

これらの問題の診断または解決に何か進展があった場合は、フィードバックを歓迎す
る。

Note: IME の動作は、異なるベンダーによる実装の違いによって異なることがある。特
定のインプットメソッドで問題に遭遇した場合は、別のもので試すことを推奨する。

Vim の +multi_byte_ime システムと適切に統合するためには、インプットメソッド
の状態の変化が Vim のソースコード内の ImmGetOpenStatus() 関数で検出可能でな
ければならない。現在、多言語入力をサポートするいくつかのインプットメソッドは、
gVim が捕捉できない内部の状態変化を持つかもしれない。


IME または XIM が on の時のカーソルの色                         CursorIM
    IME のためのちょっとかわいい機能がある。カーソルは色を変えることで IME の
    状態を示すことができる。通常、IME の状態はデスクトップ (またはタスクバー)
    の隅にある小さなアイコンで示されていた。IME の状態を確認するのは容易ではな
    い。しかし、この機能はこれを助ける。
    XIM を使用する時も同じように動作する。

    ハイライトグループ CursorIM を使用して、状態が on の時のカーソルの色を選択
    できる。例えば、gvimrc に以下の行を追加する:

        if has('multi_byte_ime')
            highlight Cursor guifg=NONE guibg=Green
            highlight CursorIM guifg=NONE guibg=Purple
        endif

    IME が off の時のカーソルの色は緑である。そして、紫のカーソルは状態が on
    であることを示す。

9. キーマップによる入力                                 mbyte-keymap

キーボードが、テキストに入力したい文字を生成しない時は、'keymap' オプションを
使用できる。これは、1 つ以上の (英語の) 文字を別の (非英語の) 文字に変換する。
これはテキストをタイプする時だけ起こり、Vim のコマンドをタイプする時は起こらな
い。これにより、2 つのキーボード設定を切り替える必要がなくなる。
{Vim が +keymap 機能付きでコンパイルされた場合にのみ使用可能}

'keymap' オプションの値は、使用するキーマップファイルを指定する。このファイル
の名前は以下の 2 つのうちの 1 つである:

        keymap/{keymap}_{encoding}.vim
        keymap/{keymap}.vim

ここで、{keymap} は 'keymap' オプションの値であり、{encoding} は 'encoding' オ
プションの値である。{encoding} を含むファイル名が最初に試される。

これらのファイルを見つけるために 'runtimepath' が使用される。全ての使用可能な
キーマップファイルの概要を見るには、以下を使用する:
        :echo globpath(&rtp, "keymap/*.vim")

挿入モードおよびコマンドラインモードでは、CTRL-^ を使用して、キーボードマップ
を使用するかどうかを切り替えることができる。i_CTRL-^ c_CTRL-^
このフラグは、挿入モードについては 'iminsert' オプションで記憶される。挿入モー
ドを抜けて入る時は、前の値が使用される。f および r のような、1 文字の引数
を取るコマンドにも同じ値が使用される。
コマンドラインモードでは、このフラグは記憶されない。最初に Ex コマンドをタイプ
することが期待されており、それは ASCII である。
検索パターンをタイプする時は、'imsearch' オプションが使用される。これは
'iminsert' と同じ値を使用するように設定できる。
                                                                lCursor
言語マッピングが使用されている時は、GUI のカーソルに別の色を付けることができ
る。これは、標準でない背景色を使用している時にカーソルが見えなくなるのを避ける
ため、デフォルトでは無効になっている。ここに明るい色のカーソルを使用する例があ
る:
        :highlight Cursor guifg=NONE guibg=Green
        :highlight lCursor guifg=NONE guibg=Cyan

                keymap-file-format :loadk :loadkeymap E105 E791
キーマップファイルはおおよそこのようになる:

        " Maintainer:   name <email@address>
        " Last Changed: 2001 Jan 1

        let b:keymap_name = "short"

        loadkeymap
        a       A
        b       B       コメント

" で始まる行はコメントであり、無視される。空行も無視される。マッピングのある行
は、有用なテキストの後にコメントがあってもよい。

"b:keymap_name" には短い名前を設定でき、それはステータス行に表示される。これ
は、'keymap' の値よりも少ない場所を取るという考えである。'keymap' の値は、異な
る言語、キーボードおよびエンコーディングを区別するために長くなるかもしれない。

実際のマッピングは "loadkeymap" 以下の行にある。例では、"a" は "A" に、"b" は
"B" にマップされる。したがって、最初の項目が 2 番目の項目にマップされる。これ
はファイルの終わりまで、各行に対して行われる。
これらの項目は、"<buffer>" を使用してマッピングをバッファローカルにした
:lnoremap コマンドで使用できるものと完全に同じである。
このコマンドで結果を確認できる:
        :lmap
2 つの項目は空白で区切られていなければならない。項目の中に空白を含めることはで
きない。代わりに特別な名前 "<Tab>" および "<Space>" を使用すること。2 つの項目
を合わせた長さは 200 バイトを超えてはならない。

最初のカラムに 2 つ以上の文字を置くことができる。これはデッドキーのように動作
する。例:
        'a      á
Vim は引用符の後の次の文字が本当に "a" であるかどうかを知らないので、次の文字
を待つ。単一引用符を挿入できるようにするには、この行も追加する:
        ''      '
マッピングは :lnoremap で定義されているので、結果の引用符は別の文字の開始に
は使用されない。
"accents" キーマップはこれを使用している。              keymap-accents

最初のカラムは <> 形式にすることもできる:
        <C-c>           Ctrl-C
        <A-c>           Alt-c
        <A-C>           Alt-C
Note キーボードおよび端末によっては、Alt のマッピングは動作しないかもしれない
ことに注意。

2 番目のカラムに 2 つ以上の文字を置くこともできるが、これは普通ではない。しか
し、様々な方法で文字を指定できる:
        A       a               リテラル文字
        A       <char-97>       10 進数の値
        A       <char-0x61>     16 進数の値
        A       <char-0141>     8 進数の値
        x       <Space>         特別なキーの名前

文字は、'encoding' の現在の値でエンコードされていると見なされる。全ての文字が
リテラルで与えられている時は、":scriptencoding" を使用できる。変換は結果の文字
ではなく、キーマップファイルに対して行われるので、<char-> の構文を使用する時
は、それは動作しない。

"loadkeymap" の後の行は、'cpoptions' を "C" に設定して解釈される。これは、継続
行が使用されず、バックスラッシュがマッピングの中で特別な意味を持つことを意味す
る。例:

        " コメント行
        \"      x       " を x にマップする
        \\      y       \ を y にマップする

他の人にも役に立つキーマップファイルを書いた場合は、配布物に含めるために Vim
のメンテナーに提出することを検討すること:
<maintainer@vim.org>

10.  imactivatefunc() による入力                                mbyte-func

Vim には 'imactivatefunc' および 'imstatusfunc' オプションがある。これらは、外
部コマンドも含め、任意の方法で Vim からインプットメソッドを有効化/無効化するの
に便利である。例えば、fcitx は fcitx-remote コマンドを提供している:

        set iminsert=2
        set imsearch=2
        set imcmdline

        set imactivatefunc=ImActivate
        function! ImActivate(active)
          if a:active
            call system('fcitx-remote -o')
          else
            call system('fcitx-remote -c')
          endif
        endfunction

        set imstatusfunc=ImStatus
        function! ImStatus()
          return system('fcitx-remote')[0] is# '2'
        endfunction

このスクリプトを使用すると、Vim が +xim 付きでコンパイルされていない時でも、
Vim を介して XIM を有効化/無効化できる。

11. UTF-8 を使用する                    mbyte-utf8 UTF-8 utf-8 utf8
                                                        Unicode unicode
Unicode 文字セットは、他の文字セットの全ての文字を含むように設計された。した
がって、Unicode を使用して任意の言語でテキストを書くことができる (いくつかのま
れにしか使用されない言語は除く)。そして、たいていはこれらの言語を 1 つのファイ
ルに混在させることができ、これは他のエンコーディングでは不可能である。

Unicode はいくつかの方法でエンコードできる。最もよく使われているものは UTF-8
であり、各文字に 1 バイト以上を使用し、ASCII と後方互換性がある。MS-Windows で
は UTF-16 (以前は UCS-2) も使用されており、16 ビットのワードを使用する。Vim は
これらの全てのエンコーディングをサポートできるが、内部では常に UTF-8 を使用す
る。

Vim には包括的な UTF-8 サポートがある。以下でうまく動作する:
- UTF-8 サポートが有効な xterm
- Motif および GTK GUI
- MS-Windows GUI
- いくつかの他のプラットフォーム

2 倍幅の文字がサポートされている。これは 'guifontwide' または 'guifontset' で
最もよく動作する。'guifont' だけを使用している時は、幅の広い文字は通常の幅で描
画され、隙間を埋めるためにスペースが置かれる。Note 'guifontset' オプションは
GTK+ 2 GUI ではもはや関係ないことに注意。

                                                        bom-bytes
ファイルを読み込む時、Unicode のエンコーディングを認識するために BOM (Byte
Order Mark) を使用できる:
        EF BB BF     UTF-8
        FE FF        UTF-16 ビッグエンディアン
        FF FE        UTF-16 リトルエンディアン
        00 00 FE FF  UTF-32 ビッグエンディアン
        FF FE 00 00  UTF-32 リトルエンディアン

UTF-8 が推奨されるエンコーディングである。Note utf-16 と utf-32 を区別するのは
難しいことに注意。Utf-16 は MS-Windows でしばしば使用され、utf-32 はファイル形
式としては普及していない。


                                        mbyte-combining mbyte-composing
合成文字または結合文字は、その前の文字の意味を変えるために使用される。結合文字
は前の文字の上に描画される。
デフォルトでは、最大 2 つの結合文字を使用できる。これは 'maxcombine' オプショ
ンで変更できる。
テキストを編集する時は、合成文字はたいてい前の文字の一部と見なされる。例えば、
"x" はデフォルトで 1 文字とそれに続く合成文字を削除する。
'delcombine' オプションがオンの場合、'x' を押すと結合文字が 1 つずつ削除され、
それから基底文字が削除される。しかし、挿入する時は、最初の文字とそれに続く合成
文字を別々にタイプし、その後それらは結合される。"r" コマンドは、結合文字が来る
ことを知らないので、結合文字をタイプすることを許さない。代わりに "R" を使用す
ること。

有効な UTF-8 のバイトシーケンスの一部でないバイトは、1 つの文字のように扱われ、
<xx> として表示される。ここで "xx" はそのバイトの 16 進数の値である。

冗長なシーケンスは特別に扱われず、有効な文字のように表示される。しかし、検索パ
ターンは冗長なシーケンスにマッチしないかもしれない。(冗長なシーケンスとは、そ
の文字に必要なよりも多くのバイトが使用されているものである。) 例外は NUL (ゼロ)
で、"<00>" として表示される。

ファイルおよびバッファでは、Unicode の文字の全範囲 (31 ビット) を使用できる。
しかし、表示は選択されたフォントに存在する文字に対してのみ動作する。

便利なコマンド:
- "ga" はカーソルの下の文字の 10 進数、16 進数および 8 進数の値を表示する。合
  成文字がある場合は、これらも表示される。(メッセージが切り詰められた場合は、
  ":messages" を使用すること)。
- "g8" は UTF-8 の文字に使用されているバイトを、合成文字も含めて、16 進数とし
  て表示する。
- ":set encoding=utf-8 fileencodings=" は全てのファイルに UTF-8 を使用すること
  を強制する。デフォルトでは、'encoding' に現在のロケールを使用し、ファイルの
  エンコーディングを自動的に検出するように 'fileencodings' を設定する。


Vim を起動する

現在のロケールが UTF-8 エンコーディングの場合、Vim は自動的に UTF-8 モードで起
動する。

別のロケールを使用している場合:

        set encoding=utf-8

メニューに使用されるフォントも選択したいかもしれない。残念ながら、これは常に動
作するわけではない。以下のシステム固有の注意および 'langmenu' を参照。


X-WINDOWS で UTF-8 を使用する                          utf-8-in-xwindows

Note: この節は GTK+ 2 GUI には適用されない。

使用するフォントを指定する必要がある。2 倍幅の文字には、ちょうど 2 倍の幅の別
のフォントが必要である。これを行うには 3 つの方法がある:

1. 'guifont' を設定し、Vim にマッチする 'guifontwide' を探させる
2. 'guifont' および 'guifontwide' を設定する
3. 'guifontset' を設定する

詳細は各オプションのドキュメントを参照。例:

   :set guifont=-misc-fixed-medium-r-normal--15-140-75-75-c-90-iso10646-1

メニューに使用されるフォントも設定したいかもしれない。これは Motif でのみ動作
する。これには ":hi Menu font={fontname}" コマンドを使用する。:highlight


UTF-8 をタイプする                                     utf-8-typing

X-Windows を使用している場合、UTF-8 エンコーディングをサポートするインプットメ
ソッドを見つけるべきである。

システムが UTF-8 のタイプのサポートを提供していない場合、'keymap' 機能を使用で
きる。これにより、UTF-8 の文字を ASCII 文字の並びとして定義するキーマップファ
イルを書くことができる。mbyte-keymap を参照。

別の方法は、現在のロケールを、使用したい言語であり、かつ XIM が使用可能な言語
に設定することである。それから、'termencoding' をその言語に設定すると、Vim は
タイプされた文字を 'encoding' に変換してくれる。

他の全てが失敗した場合は、任意の文字を 4 つの 16 進数のバイトとしてタイプでき
る:

        CTRL-V u 1234

"1234" は 16 進数として解釈される。4 文字をタイプしなければならず、必要な場合
は 0 を前に付ける。


コマンド引数                                           utf-8-char-arg

f、F、t および r のようなコマンドは 1 文字の引数を取る。UTF-8 では、こ
の引数は 1 つまたは 2 つの合成文字を含んでもよい。これらは基底文字と一緒に入力
される必要があり、Vim は次の文字がタイプされるのを待って、それが合成文字かどう
かを調べることはしない。'keymap' または :lmap を使用するのは、これらの文字を
タイプする良い方法である。

行内の文字を検索するコマンドは、合成文字を以下のように扱う。合成文字なしの文字
を検索する時は、合成文字ありまたはなしのテキスト内のマッチが見つかる。合成文字
ありの文字を検索する時は、その合成文字を持つマッチだけが見つかる。誰もが合成文
字をタイプできるわけではないので、このように実装された。

12. オプションの概要                                    mbyte-options

これらのオプションはマルチバイトのファイルの編集に関係する。詳細な情報は
options.txt のヘルプを確認すること。

'encoding'      キーボードおよびディスプレイに使用されるエンコーディング。これ
                はファイルのデフォルトのエンコーディングでもある。

'fileencoding'  ファイルのエンコーディング。それが 'encoding' と異なる時は、
                ファイルを読み込むか、または書き込む時に変換が行われる。

'fileencodings' ファイルの可能なエンコーディングのリスト。ファイルを開く時、こ
                れらが試され、エラーを起こさない最初のものが 'fileencoding' に
                使用される。

'charconvert'   ファイルをあるエンコーディングから別のエンコーディングに変換す
                るのに使用される式。

'formatoptions' 'm' フラグを含めると、256 以上のマルチバイト文字で整形が行を分
                割するようになる。これは、文字の並びをどこでも分割できる言語に
                便利である。

'guifontset'    マルチバイトエンコーディングに使用されるフォント名のリスト。こ
                のオプションが空でない時は、'guifont' を置き換える。

'keymap'        キーボードマッピングの名前を指定する。
