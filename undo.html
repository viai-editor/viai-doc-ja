1. undo と redo コマンド                                undo-commands

<Undo>          または                                  undo <Undo> u
u                       [count] 個の変更を undo する。

                                                        :u :un :undo
:u[ndo]                 1 つの変更を undo する。
                                                                E830
:u[ndo] {N}             変更番号 {N} の後へジャンプする。{N} の意味については
                        undo-branches を参照。

                                                        CTRL-R
CTRL-R                  undo された [count] 個の変更を redo する。

                                                        :red :redo redo
:red[o]                 undo された 1 つの変更を redo する。

                                                        U
U                       1 つの行、つまり最新の変更が行われた行に対する、最新の
                        変更をすべて undo する。U 自体も変更とみなされるの
                        で、U は前の U を undo する。

最近の変更は記憶されている。上記の undo および redo コマンドを使って、テキスト
を各変更の前の状態に戻すことができる。また、変更を再び適用して、undo の前のテ
キストに戻すこともできる。

"U" コマンドは、undo/redo によって他のコマンドとまったく同様に扱われる。した
がって、"u" コマンドは "U" コマンドを undo し、'CTRL-R' コマンドはそれを再び
redo する。"U"、"u"、および 'CTRL-R' を混ぜて使うと、"U" コマンドが行の状態を
前の "U" コマンドの前に復元することに気付くだろう。これは混乱するかもしれない。
慣れるために試してみること。
"U" コマンドは常にバッファを変更ありとしてマークする。"U" がバッファを変更のな
い状態に戻したときも、それは変更されているとみなされる。バッファが変更なしにな
るまで変更を undo するには "u" を使う。

2. undo の 2 つの方法                                   undo-two-ways

undo および redo コマンドがどのように機能するかは、'cpoptions' の 'u' フラグに
依存する。
Vim の方法 ('u' を除外) および Vi 互換の方法 ('u' を含む) がある。Vim の方法で
は、"uu" は 2 つの変更を undo する。Vi 互換の方法では、"uu" は何もしない (undo
を undo する)。

'u' を除外、Vim の方法:
undo コマンドで時間をさかのぼることができる。その後、redo コマンドで再び進むこ
とができる。undo コマンドの後に新しい変更を行うと、redo はもうできなくなる。

'u' を含む、Vi 互換の方法:
undo コマンドは直前の変更を undo し、直前の undo コマンドも undo する。redo コ
マンドは直前の undo コマンドを繰り返す。これは変更コマンドを繰り返さない。それ
には "." を使う。

例              Vim の方法              Vi 互換の方法   
"uu"            2 回 undo               何もしない
"u CTRL-R"      何もしない              2 回 undo

根拠:  Nvi は CTRL-R の代わりに "." コマンドを使う。残念ながら、これは Vi
            互換ではない。例えば、Vi で "dwdwu." は 2 つの単語を削除するが、
            Nvi では何もしない。

3. undo ブロック                                        undo-blocks

1 つの undo コマンドは通常、タイプされたコマンドを、そのコマンドがいくつの変更
を行ったかに関係なく undo する。この undo 可能な変更の連続が undo ブロックを形
成する。したがって、タイプされたキーが関数を呼び出す場合、関数内のすべてのコマ
ンドが一緒に undo される。

新しい undo 可能な変更を作成せず、直前の変更に結合する関数またはスクリプトを書
きたい場合、このコマンドを使う:

                                                :undoj :undojoin E790
:undoj[oin]             以降の変更を直前の undo ブロックに結合する。警告: 注意
                        して使うこと。ユーザーが変更を適切に undo できなくなる
                        かもしれない。undo または redo の後にこれを使わないこ
                        と。

これは、変更の途中でユーザーに入力を求める必要があるときに最も便利である。例え
ば getchar() を呼び出す関数内で。これより前に、結合しなければならない関連す
る変更があったことを確認すること。

次のキー押下が再び新しい変更を開始するので、これ単独では機能しない。しかし、次
のようなことができる:

        :undojoin | delete

この後、"u" コマンドは delete コマンドおよび直前の変更を undo する。
                                        undo-break undo-close-block
その逆を行う、つまり次の変更に新しい undo ブロックを使うには、挿入モードで
CTRL-G u を使う。これは、挿入コマンドを部分ごとに undo 可能にしたい場合に便利
である。例えば、文ごとに。i_CTRL-G_u

'undolevels' の値を設定することでも undo ブロックは閉じられる。新しい値が古い
値と等しい場合でも。'undolevels' のグローバル値だけを明示的に読み書きするには
g:undolevels を使う。Vim9 script では:
        &g:undolevels = &g:undolevels
旧来の script では:
        let &g:undolevels = &g:undolevels

Note 似たように見える代入 let &undolevels=&undolevels は、ローカルオプション
が異なる値に設定されていた場合、'undolevels' のグローバルオプションの値を保持
しないことに注意。例えば:
        " 'undolevels' のグローバル値およびローカル値を異なる値で開始する。
        let &g:undolevels = 1000
        let &l:undolevels = 2000
        " この代入はグローバルオプションを 2000 に変更する:
        let &undolevels = &undolevels

4. undo ブランチ                                undo-branches undo-tree

上では、undo/redo の 1 本の線についてだけ議論した。しかし、枝分かれすることも
可能である。これは、いくつかの変更を undo してから新しい変更を行ったときに起こ
る。undo された変更はブランチになる。以下のコマンドでそのブランチへ移動できる。

これはユーザーマニュアルで説明されている: usr_32.txt。

                                                        :undol :undolist
:undol[ist]             変更のツリーの葉を一覧表示する。例:
                           number changes  when               saved
                               88      88  2010/01/04 14:25:53
                              108     107  08/07 12:47:51
                              136      46  13:33:01             7
                              166     164  3 seconds ago

                        "number" 列は変更番号である。この番号は継続的に増加し、
                        特定の undo 可能な変更を識別するのに使える。:undo を
                        参照。
                        "changes" 列は、ツリーの根からこの葉までの変更の数であ
                        る。
                        "when" 列は、この変更が行われた日付および時刻である。4
                        つの可能な形式は:
                            N seconds ago
                            HH:MM:SS             時、分、秒
                            MM/DD HH:MM:SS       同上、月および日付き
                            YYYY/MM/DD HH:MM:SS  同上、年付き
                        "saved" 列は、この変更がディスクに書き込まれたかどう
                        か、およびそれが何回目のファイル書き込みだったかを示
                        す。これは :later および :earlier コマンドで使え
                        る。詳細については undotree() 関数を使う。

                                                        g-
g-                      より古いテキストの状態へ移動する。カウントを付けると、
                        その回数だけ繰り返す。
                                                        :ea :earlier
:ea[rlier] {count}      より古いテキストの状態へ {count} 回移動する。
:ea[rlier] {N}s         約 {N} 秒前の、より古いテキストの状態へ移動する。
:ea[rlier] {N}m         約 {N} 分前の、より古いテキストの状態へ移動する。
:ea[rlier] {N}h         約 {N} 時間前の、より古いテキストの状態へ移動する。
:ea[rlier] {N}d         約 {N} 日前の、より古いテキストの状態へ移動する。

:ea[rlier] {N}f         {N} 回前のファイル書き込みの、より古いテキストの状態へ
                        移動する。
                        最後の書き込み以降に変更が行われていた場合、
                        ":earlier 1f" はテキストを書き込まれたときの状態に戻
                        す。そうでない場合は、その前の書き込みへ移動する。
                        最初のファイル書き込みの状態にいるとき、またはファイル
                        が書き込まれていないとき、":earlier 1f" は最初の変更の
                        前へ移動する。

                                                        g+
g+                      より新しいテキストの状態へ移動する。カウントを付ける
                        と、その回数だけ繰り返す。
                                                        :lat :later
:lat[er] {count}        より新しいテキストの状態へ {count} 回移動する。
:lat[er] {N}s           約 {N} 秒後の、より新しいテキストの状態へ移動する。
:lat[er] {N}m           約 {N} 分後の、より新しいテキストの状態へ移動する。
:lat[er] {N}h           約 {N} 時間後の、より新しいテキストの状態へ移動する。
:lat[er] {N}d           約 {N} 日後の、より新しいテキストの状態へ移動する。

:lat[er] {N}f           {N} 回後のファイル書き込みの、より新しいテキストの状態
                        へ移動する。
                        最後のファイル書き込みの状態にいるとき、":later 1f" は
                        最も新しいテキストの状態へ移動する。


Note 'undolevels' のために undo 情報がクリアされると、テキストの状態に到達でき
なくなることに注意。

時間を移動したときに、複数の変更が一度に起こるように見えても驚かないこと。これ
は、undo ツリー内を移動してから新しい変更を行ったときに起こる。

例

このテキストで開始する:
        one two three

"x" を 3 回押して最初の単語を削除する:
        ne two three
        e two three
         two three

ここで "u" を 3 回押してそれを undo する:
        e two three
        ne two three
        one two three

"x" を 3 回押して 2 番目の単語を削除する:
        one wo three
        one o three
        one  three

ここで "g-" を 3 回使ってそれを undo する:
        one o three
        one wo three
         two three

これで、"one" を削除した後の、最初の undo ブランチに戻った。ここで "g-" を繰り
返すと、元のテキストに戻る:
        e two three
        ne two three
        one two three

":later 1h" で最後の変更へジャンプする:
        one  three

そして ":earlier 1h" で再び開始に戻る:
        one two three


Note "u" および CTRL-R を使っても、可能なすべてのテキストの状態に到達できるわ
けではないが、"g-" および "g+" を繰り返すと到達できることに注意。

5. undo の永続化                undo-persistence persistent-undo

バッファをアンロードするとき、Vim は通常、そのバッファに対して作成された undo
のツリーを破棄する。'undofile' オプションを設定することで、Vim はファイルを書
き込むときにあなたの undo 履歴を自動的に保存し、ファイルを再び編集するときに
undo 履歴を復元する。

'undofile' オプションは、ファイルを書き込んだ後、BufWritePost 自動コマンドの前
にチェックされる。どのファイルについて undo 情報を書き込むかを制御したい場合、
BufWritePre 自動コマンドを使える:
        au BufWritePre /tmp/* setlocal noundofile

Vim は、ファイルシステムのパスを undo ファイルに直接マッピングする単純な方式を
使って、編集したファイルごとに 1 つの、別々の undo ファイルに undo ツリーを保
存する。Vim は、undo ファイルが、それが書き込まれたファイルともう同期していな
いかどうかを (ファイル内容のハッシュによって) 検出し、破損を防ぐために、undo
ファイルが書き込まれた後にファイルが変更された場合はそれを無視する。undo ファ
イルは、その所有者が編集されたファイルの所有者と異なる場合も無視される。ただ
し、undo ファイルの所有者が現在のユーザーである場合を除く。ファイルを開くとき
にそれについてのメッセージを得るには 'verbose' を設定する。

undo ファイルは通常、ファイルと同じディレクトリに保存される。これは 'undodir'
オプションで変更できる。

ファイルが暗号化されているときは、undo ファイル内のテキストも暗号化される。同
じキーおよび方式が使われる。encryption

Note テキストプロパティは undo ファイルに保存されないことに注意。バッファが読
み込まれている限りテキストプロパティを復元できるが、undo ファイルから復元する
ことはできない。根拠: 関連するテキストプロパティの型が以前とまったく同じ方法で
定義されている必要があり、それは保証できない。

":wundo" および ":rundo" を使って、それぞれ undo 履歴を保存および復元すること
もできる:
                                                        :wu :wundo
:wu[ndo][!] {file}
                undo 履歴を {file} に書き込む。
                {file} が存在し、それが undo ファイルのように見えない場合 (ファ
                イルの先頭のマジックナンバーが間違っている)、! が追加されてい
                ない限り、これは失敗する。
                それが存在し、undo ファイルのように見える場合、それは上書きさ
                れる。undo 履歴がない場合、何も書き込まれない。
                実装の詳細: 上書きは、まず既存のファイルを削除し、それから同じ
                名前で新しいファイルを作成することで行われる。そのため、書き込
                み禁止のディレクトリ内の既存の undo ファイルを上書きすることは
                できない。

                                                        :rund :rundo
:rund[o] {file} {file} から undo 履歴を読み込む。

これらを自動コマンドで使って、履歴ファイルの名前を明示的に指定できる。例:

        au BufReadPost * call ReadUndo()
        au BufWritePost * call WriteUndo()
        func ReadUndo()
          if filereadable(expand('%:h') .. '/UNDO/' .. expand('%:t'))
            rundo %:h/UNDO/%:t
          endif
        endfunc
        func WriteUndo()
          let dirname = expand('%:h') .. '/UNDO'
          if !isdirectory(dirname)
            call mkdir(dirname)
          endif
          wundo %:h/UNDO/%:t
        endfunc

'undofile' はオフにしておくべきである。そうしないと、書き込みごとに 2 つの
undo ファイルができてしまう。

undofile() 関数を使って、Vim が使うファイル名を調べることができる。

Note ファイルの読み書き中に 'undofile' が設定されている場合、'verbose' が設定
されていない限り、ほとんどのエラーは表示されないことに注意。:wundo および
:rundo では、例えばファイルを読み書きできないときに、より多くのエラーメッセー
ジが表示される。

NOTE: undo ファイルは Vim によって削除されることはない。自分で削除する必要があ
る。

既存の undo ファイルの読み込みは、いくつかの理由で失敗することがある:
E822  ファイルのパーミッションが許可しないため、それを開くことができない。
E823  ファイルの先頭のマジックナンバーが一致しない。これは通常、それが undo
        ファイルではないことを意味する。
E824  undo ファイルのバージョン番号が、それが Vim のより新しいバージョンに
        よって書き込まれたことを示している。それを開くにはその新しいバージョン
        が必要である。ファイル内の undo 情報を保持したい場合、バッファを書き込
        まないこと。
"File contents changed, cannot use undo info"
        ファイルのテキストが、undo ファイルが書き込まれたときと異なる。これは、
        undo ファイルを使えないことを意味する。それはテキストを破損させるだろ
        う。これは、'encoding' が undo ファイルが書き込まれたときと異なる場合
        にも起こる。
E825  undo ファイルは有効な内容を含んでおらず、使えない。
E826  undo ファイルは暗号化されているが、復号に失敗した。
E827  undo ファイルは暗号化されているが、このバージョンの Vim は暗号化をサ
        ポートしていない。別の Vim でファイルを開くこと。
E832  undo ファイルは暗号化されているが 'key' が設定されておらず、テキスト
        ファイルは暗号化されていない。これは、テキストファイルが最初は Vim に
        よって暗号化されて書き込まれ、後で暗号化されていないテキストで上書きさ
        れた場合に起こる。
        おそらく、この undo ファイルを削除したいだろう。
"Not reading undo file, owner differs"
        undo ファイルが、テキストファイルの所有者以外の誰かによって所有されて
        いる。安全のため、undo ファイルは使われない。

undo ファイルの書き込みは、以下の理由で失敗することがある:
E828  書き込むファイルを作成できない。おそらく、そのディレクトリに書き込みの
        パーミッションがない。
"Cannot write undo file in any directory in 'undodir'"
        'undodir' 内のどのディレクトリも使えない。
"Will not overwrite with undo file, cannot read"
        書き込む undo ファイルの名前のファイルが存在するが、それを読み込むこと
        ができない。このファイルを削除するか、または名前を変更したいかもしれな
        い。
"Will not overwrite, this is not an undo file"
        書き込む undo ファイルの名前のファイルが存在するが、それは正しいマジッ
        クナンバーで始まっていない。このファイルを削除するか、または名前を変更
        したいかもしれない。
"Skipping undo file write, nothing to undo"
        書き込む undo 情報がない。何も変更されていないか、または 'undolevels'
        が負である。
E829  undo ファイルの書き込み中にエラーが発生した。もう一度試したいかもしれ
        ない。

6. undo についての備考                                  undo-remarks

記憶される変更の数は 'undolevels' オプションで設定される。0 の場合、常に Vi 互
換の方法が使われる。負の場合、undo はできない。メモリが不足している場合にこれ
を使う。

                                                        clear-undo
'undolevels' を -1 に設定したとき、undo 情報はすぐにはクリアされず、次の変更の
ときにクリアされる。undo 情報を強制的にクリアするには、以下のコマンドを使える:

        :let old_undolevels = &l:undolevels
        :setlocal undolevels=-1
        :exe "normal a \<BS>\<Esc>"
        :let &l:undolevels = old_undolevels
        :unlet old_undolevels

Note 'undolevels' のローカル値を明示的に読むための &l:undolevels の使用、お
よびローカルオプション (対応するグローバルオプションの値より優先される) だけを
変更するための :setlocal の使用に注意。&undolevels を使ってオプションの値
を保存することは予測できない; それはローカル値 (設定されている場合) またはグ
ローバル値 (それ以外の場合) のどちらかを読む。また、ローカル値が設定されている
場合、:set undolevels でオプションを変更するとグローバル値およびローカル値の
両方が変更され、両方の値を保存および復元するための余分な作業が必要になる。

バッファのマーク ('a から 'z) も、テキストと一緒に保存および復元される。

すべての変更が undo されたとき、バッファは変更されているとはみなされない。その
とき、":q!" の代わりに ":q" で Vim を終了できる。Note これはファイルの最後の書
き込みに対して相対的であることに注意。":w" の後に "u" をタイプすると、書き込ま
れたものと比べて実際にバッファが変更されるので、そのときバッファは変更されてい
るとみなされる。

手動の folding が使われているとき、折り畳みは保存および復元されない。折り畳
みの最初および最後の行が変わらないので、完全に折り畳みの中での変更だけが折り畳
みを元のまま保つ。

番号付きレジスタも、削除を undo するのに使える。テキストを削除するたびに、それ
はレジスタ "1 に入れられる。レジスタ "1 の内容は "2 にシフトされ、以下同様であ
る。レジスタ "9 の内容は失われる。これで、貼り付けコマンドで最も最近削除された
テキストを取り戻せる: '"1P'。(また、削除されたテキストが最後の削除またはコピー
操作の結果だった場合、これは無名レジスタの内容を貼り付けるので、'P' または 'p'
も機能する)。'"3P' で 3 回前の削除のテキストを取り戻せる。

                                                redo-register
削除されたテキストの複数の部分を取り戻したい場合、繰り返しコマンド "." の特別
な機能を使える。これは使われるレジスタの番号を増やす。そのため、最初に '"1P'
を実行した場合、続く "." は '"2P' になる。これを繰り返すと、番号付きレジスタが
すべて挿入される。

例:             'dd....' でテキストを削除した場合、'"1P....' で復元できる。

削除されたテキストがどのレジスタにあるかわからない場合、:display コマンドを使
える。別の方法は、最初のレジスタを '"1P' で試し、それが望むものでない場合は
'u.' を実行することである。これは最初の貼り付けの内容を削除し、2 番目のレジス
タに対して貼り付けコマンドを繰り返す。望むものが得られるまで 'u.' を繰り返す。
