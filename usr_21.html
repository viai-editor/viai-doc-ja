この章では、他のプログラムの使用を Vim と混ぜることについて扱います。Vim の中
からプログラムを実行するか、または Vim を離れて後で戻ってくるかのどちらかによっ
てです。さらに、これは Vim の状態を記憶して後で復元する方法についてです。

21.1  サスペンドとレジューム

ほとんどの Unix プログラムと同様に、Vim は CTRL-Z を押すことでサスペンドできま
す。これは Vim を停止し、Vim が起動されたシェルに戻ります。それから、飽きるま
で他の任意のコマンドを実行できます。その後、"fg" コマンドで Vim を呼び戻しま
す。

        CTRL-Z
        {任意の一連のシェルコマンド}
        fg

Vim を離れたところにそのまま戻り、何も変わっていません。
   CTRL-Z を押しても動作しない場合、":suspend" も使えます。
Vim をフォアグラウンドに戻すのを忘れないでください。行った変更をすべて失ってし
まいます!

これをサポートしているのは Unix だけです。他のシステムでは、Vim はシェルを起動
します。これにもシェルコマンドを実行できるという機能があります。しかし、それは
新しいシェルであり、Vim を起動したシェルではありません。
   GUI を実行しているときは、Vim が起動されたシェルに戻ることはできません。代
わりに、CTRL-Z は Vim ウィンドウを最小化します。

21.2  シェルコマンドの実行

Vim から 1 つのシェルコマンドを実行するには、":!{command}" を使います。例えば、
ディレクトリの一覧を見るには:

        :!ls
        :!dir

1 つ目は Unix 用、2 つ目は MS-Windows 用です。
   Vim はプログラムを実行します。それが終了すると、<Enter> を押すように促すプ
ロンプトが表示されます。これにより、編集していたテキストに戻る前に、コマンドか
らの出力を見ることができます。
   "!" は、プログラムが実行される他の場所でも使われます。概要を見てみましょう:

        :!{program}             {program} を実行する
        :r !{program}           {program} を実行し、その出力を読み込む
        :w !{program}           {program} を実行し、テキストをその入力に送る
        :[range]!{program}      {program} を通してテキストをフィルタする

"!{program}" の前に範囲があることが大きな違いを生むことに注意してください。範
囲がないとプログラムを通常どおり実行し、範囲があるといくつかのテキスト行がプロ
グラムを通してフィルタされます。

この方法で一連のプログラムを実行することは可能です。しかし、シェルの方がはるか
に得意です。この方法で新しいシェルを起動できます:

        :shell

これは、CTRL-Z を使って Vim をサスペンドするのと似ています。違いは、新しいシェ
ルが起動されることです。

GUI を使っているときは、シェルは入力および出力に Vim ウィンドウを使います。Vim
は端末エミュレータではないので、これは完全には動作しません。問題がある場合、
'guipty' オプションを切り替えてみてください。それでもまだ十分にうまく動作しな
い場合、シェルを実行する新しい端末を起動してください。例えば以下で:

        :!xterm&

21.3  viminfo に情報を記憶する

しばらく編集した後には、レジスタ内のテキスト、さまざまなファイル内のマーク、注
意深く作り上げたコマンドで埋まったコマンドライン履歴があるでしょう。Vim を終了
すると、これらはすべて失われます。しかし、取り戻すことができます!

viminfo ファイルは、状態の情報を保存するために設計されています:

        コマンドラインおよび検索パターンの履歴
        レジスタ内のテキスト
        さまざまなファイルのマーク
        バッファリスト
        グローバル変数

Vim を終了するたびに、Vim はこの情報をファイル、つまり viminfo ファイルに保存
します。Vim が再び起動すると、viminfo ファイルが読み込まれ、情報が復元されま
す。

'viminfo' オプションは、既定では限られた数の項目を復元するように設定されていま
す。もっと多くの情報を記憶するように設定したいかもしれません。これは以下のコマ
ンドで行います:

        :set viminfo=string

string は保存するものを指定します。この文字列の構文は、オプション文字の後に引
数が続くものです。オプション/引数の組はコンマで区切られます。
   自分の viminfo 文字列をどのように組み立てられるかを見てください。まず、' オ
プションは、マーク (a-z) を保存するファイルの数を指定するために使われます。こ
のオプションには、きりのよい偶数 (例えば 1000) を選んでください。これでコマン
ドはこのようになります:

        :set viminfo='1000

f オプションは、グローバルマーク (A-Z および 0-9) を保存するかどうかを制御しま
す。このオプションが 0 の場合、何も保存されません。1 であるか、または f オプ
ションを指定しない場合、マークは保存されます。この機能が欲しいので、これでこう
なります:

        :set viminfo='1000,f1

オプション < は、各レジスタについて何行保存するかを制御します。既定では、すべ
ての行が保存されます。0 の場合、何も保存されません。viminfo ファイルに何千行も
追加するのを避けるために (それは決して使われないかもしれず、Vim の起動を遅くし
ます)、最大 500 行を使います:

        :set viminfo='1000,f1,<500

使いたいかもしれない他のオプション:
        :       コマンドライン履歴から保存する行数
        @       入力行履歴から保存する行数
        /       検索履歴から保存する行数
        r       リムーバブルメディア。これに対してはマークが保存されない (複数
                回使用できる)
        !       大文字で始まり、小文字を含まないグローバル変数
        h       起動時に 'hlsearch' のハイライトを無効にする
        %       バッファリスト (ファイル引数なしで Vim を起動したときだけ復元
                される)
        c       'encoding' を使ってテキストを変換する
        n       viminfo ファイルに使われる名前 (最後のオプションでなければなら
                ない)

さらなる情報については、'viminfo' オプションおよび viminfo-file を参照してく
ださい。

Vim を複数回実行するとき、最後に終了したものがその情報を保存します。これによ
り、以前に終了した Vim が保存した情報が失われることがあります。各項目は 1 回だ
け記憶できます。


Vim を停止した場所に戻る

ファイルの編集の途中で、休暇に出かける時間になりました。Vim を終了し、仕事のこ
とはすっかり忘れて楽しみに出かけます。2 週間ほど後に Vim を起動し、こうタイプ
します:

        '0

そして、Vim を離れたところにそのまま戻ります。したがって、作業を続けることがで
きます。
   Vim は、Vim を終了するたびにマークを作成します。最後のものは '0 です。'0 が
指していた位置は '1 になります。そして '1 は '2 になり、以下同様です。マーク
'9 は失われます。
   :marks コマンドは、'0 から '9 がどこに連れていくかを調べるのに便利です。


あるファイルに戻る

最近編集したが、Vim を終了したときに編集していたのではないファイルに戻りたい場
合、少しだけ複雑な方法があります。コマンドをタイプすることで、ファイルのリスト
を見ることができます:

        :oldfiles
        1: ~/.viminfo
        2: ~/text/resume.txt
        3: /tmp/draft

ここで、2 番目のファイルを編集したいとします。それはリストで "2:" が前に付いて
いるものです。こうタイプします:

        :e #<2

":e" の代わりに、ファイル名を引数に取る任意のコマンドを使えます。"#<2" という
項目は、"%" (カレントファイル名) および "#" (代替ファイル名) と同じ場所で機能
します。したがって、ウィンドウを分割して 3 番目のファイルを編集することもでき
ます:

        :split #<3

ただファイルを編集したいだけのときには、#<123 というものは少し複雑です。幸い、
もっと簡単な方法があります:

        :browse oldfiles
        1: ~/.viminfo
        2: ~/text/resume.txt
        3: /tmp/draft
        -- More --

:oldfiles と同じファイルのリストが得られます。"resume.txt" を編集したい場合、
まず "q" を押して一覧表示を止めます。プロンプトが表示されます:

        Type number and <Enter> (empty cancels):

2 番目のファイルを編集するには、"2" をタイプして <Enter> を押します。

ファイル名にあるパターンが含まれていることがわかっている場合、ファイルのリスト
を :filter することもできます:

        :filter /resume/ :browse oldfiles

マッチするファイル名は 1 つだけなので、Vim はプロンプトを出さずにそのファイル
を直接編集します。フィルタが複数のファイルにマッチする場合、代わりにマッチする
ファイルのリストについてプロンプトが出ます:

        :filter! /resume/ browse oldfiles
        1: ~/.viminfo
        3: /tmp/draft
        Type number and <Enter> (q or empty cancels):

Note: 今回は、resume にマッチしないすべてのファイルを除外しました。


詳しい情報は :oldfiles、v:oldfiles、および c_#< にあります。


ある Vim から別の Vim へ情報を移す

":wviminfo" および ":rviminfo" コマンドを使うと、Vim を実行したまま情報を保存
および復元できます。これは、例えば 2 つの Vim のインスタンスの間でレジスタの内
容をやり取りするのに便利です。1 つ目の Vim でこうします:

        :wviminfo! ~/tmp/viminfo

そして 2 つ目の Vim でこうします:

        :rviminfo! ~/tmp/viminfo

言うまでもなく、"w" は "write" を表し、"r" は "read" を表します。
   ! 文字は、":wviminfo" で既存のファイルを強制的に上書きするために使われます。
それが省略されていて、かつファイルが存在するときは、情報はファイルにマージされ
ます。
   ":rviminfo" に使われる ! 文字は、すべての情報が使われることを意味し、これは
既存の情報を上書きすることがあります。! がない場合、設定されていなかった情報だ
けが使われます。
   これらのコマンドは、情報を保存して後で再び使うためにも使えます。viminfo ファ
イルでいっぱいのディレクトリを作り、それぞれに異なる目的のための情報を入れてお
くこともできます。

21.4  セッション

編集を続けていて、1 日の終わりになったとします。作業をやめて、次の日に中断した
ところから再開したいです。これは、編集セッションを保存して、次の日にそれを復元
することで行えます。
   Vim セッションには、編集しているものについてのすべての情報が含まれます。こ
れには、ファイルリスト、ウィンドウレイアウト、グローバル変数、オプション、およ
びその他の情報のようなものが含まれます。(正確に何が記憶されるかは、以下で説明
する 'sessionoptions' オプションで制御されます。)
   以下のコマンドはセッションファイルを作成します:

        :mksession vimbook.vim

後でこのセッションを復元したい場合、このコマンドを使えます:

        :source vimbook.vim

Vim を起動して特定のセッションを復元したい場合、以下のコマンドを使えます:

        vim -S vimbook.vim

これは、起動時に特定のファイルを読み込むように Vim に指示します。'S' は
session を表します (実際には、-S で任意の Vim script を読み込めるので、
"source" を表すと考えてもよいでしょう)。

開いていたウィンドウは、以前と同じ位置およびサイズで復元されます。マッピングお
よびオプションの値は以前と同じです。
   正確に何が復元されるかは、'sessionoptions' オプションによります。既定値は以
下です:
"blank,buffers,curdir,folds,help,options,tabpages,winsize,terminal".

        blank           空のウィンドウを保持する
        buffers         ウィンドウ内のものだけでなく、すべてのバッファ
        curdir          カレントディレクトリ
        folds           折り畳み、手動で作成したものも
        help            ヘルプウィンドウ
        options         すべてのオプションおよびマッピング
        tabpages        すべてのタブページ
        winsize         ウィンドウサイズ
        terminal        端末ウィンドウを含める

好みに合わせてこれを変更してください。例えば、Vim ウィンドウのサイズも復元する
には、こうします:

        :set sessionoptions+=resize


ここでセッション、あそこでセッション

セッションを使う明らかな方法は、異なるプロジェクトで作業するときです。セッショ
ンファイルをディレクトリ "~/.vim" に保存しているとします。現在 "secret" プロ
ジェクトで作業していて、"boring" プロジェクトに切り替えなければなりません:

        :wall
        :mksession! ~/.vim/secret.vim
        :source ~/.vim/boring.vim

これはまず ":wall" を使って、変更されたすべてのファイルを書き込みます。次に、
":mksession!" を使って、現在のセッションが保存されます。これは以前のセッション
を上書きします。次に secret セッションを読み込むときは、この時点でいたところか
ら続けることができます。そして最後に、新しい "boring" セッションを読み込みま
す。

ヘルプウィンドウを開き、さまざまなウィンドウを分割して閉じ、全体的にウィンドウ
レイアウトを散らかした場合、最後に保存したセッションに戻ることができます:

        :source ~/.vim/boring.vim

したがって、現在の設定をセッションに保存することで次回は今いるところから続けた
いのか、またはセッションファイルを開始点として保持したいのかを、完全に制御でき
ます。
   セッションを使う別の方法は、使いたいウィンドウレイアウトを作成し、これをセッ
ションに保存することです。そうすれば、いつでも好きなときにこのレイアウトに戻る
ことができます。
   例えば、これは使うのによいレイアウトです:

        +----------------------------------------+
        |                  VIM - main help file  |
        |                                        |
        |Move around:  Use the cursor keys, or "h|
        |help.txt================================|
        |explorer   |                            |
        |dir        |~                           |
        |dir        |~                           |
        |file       |~                           |
        |file       |~                           |
        |file       |~                           |
        |file       |~                           |
        |~/=========|[No File]===================|
        |                                        |
        +----------------------------------------+

これは、このテキストを読めるように、上部にヘルプウィンドウがあります。左側の幅
の狭い縦のウィンドウには、ファイルエクスプローラーが含まれています。これは、
ディレクトリの内容を一覧表示する Vim プラグインです。そこで編集するファイルを
選択できます。詳しくは次章で。
   起動したばかりの Vim から、これを以下で作成します:

        :help
        CTRL-W w
        :vertical split ~/

好みに合わせてウィンドウのサイズを少し変更できます。それから、以下でセッション
を保存します:

        :mksession ~/.vim/mine.vim

これで、このレイアウトで Vim を起動できます:

        vim -S ~/.vim/mine.vim

ヒント: エクスプローラーウィンドウに一覧表示されているファイルを空のウィンドウ
で開くには、カーソルをファイル名に移動して "O" を押します。マウスでダブルクリッ
クしても同じことができます。


Unix と MS-Windows

ある日は MS-Windows システムで、別の日は Unix で作業しなければならない人もいま
す。あなたがその 1 人の場合、'sessionoptions' に "slash" および "unix" を追加
することを検討してください。そうすると、セッションファイルは両方のシステムで使
える形式で書き込まれます。これが vimrc ファイルに入れるコマンドです:

        :set sessionoptions+=unix,slash

MS-Windows の Vim は Unix ファイルを読み書きできますが、Unix の Vim は
MS-Windows 形式のセッションファイルを読めないので、そのとき Vim は Unix 形式を
使います。同様に、MS-Windows の Vim は名前を区切るのに / を使ったファイル名を
理解しますが、Unix の Vim は \ を理解しません。


セッションと viminfo

セッションは多くのものを保存しますが、マークの位置、レジスタの内容、およびコマ
ンドライン履歴は保存しません。これらのものには viminfo 機能を使う必要がありま
す。
   ほとんどの状況では、セッションを viminfo とは別に使いたいでしょう。これは、
別のセッションに切り替えるが、コマンドライン履歴は保持する、ということに使えま
す。そして、あるセッションでテキストをレジスタにヤンクし、別のセッションでそれ
を貼り付けます。
   情報をセッションと一緒に保持したいかもしれません。その場合は、これを自分で
行う必要があります。例:

        :mksession! ~/.vim/secret.vim
        :wviminfo! ~/.vim/secret.viminfo

そして、これを再び復元するには:

        :source ~/.vim/secret.vim
        :rviminfo! ~/.vim/secret.viminfo

21.5  ビュー

セッションは Vim 全体の見た目を保存します。1 つのウィンドウだけの属性を保存し
たいときは、ビューを使います。
   ビューの用途は、ファイルを特定の方法で編集したいときのためです。例えば、
'number' オプションで行番号を有効にし、いくつかの折り畳みを定義しています。セッ
ションと同じように、ファイルに対するこのビューを記憶し、後で復元することができ
ます。実際、セッションを保存すると、各ウィンドウのビューが保存されます。
   ビューを使う基本的な方法は 2 つあります。1 つ目は、ビューファイルの名前を
Vim に選ばせることです。後で同じファイルを編集するときに、ビューを復元できま
す。カレントウィンドウのビューを保存するには:

        :mkview

Vim がビューをどこに保存するかを決めます。後で同じファイルを編集するとき、この
コマンドでビューを取り戻せます:

        :loadview

簡単でしょう?
   ここで、'number' オプションをオフにして、またはすべての折り畳みを開いた状態
でファイルを見たいとすると、ウィンドウがそのように見えるようにオプションを設定
できます。それから、このビューを以下で保存します:

        :mkview 1

言うまでもなく、これは以下で取り戻せます:

        :loadview 1

これで、":loadview" を "1" 引数ありで、およびなしで使うことで、ファイルの 2 つ
のビューを切り替えることができます。
   この方法で、同じファイルに対して最大 10 個のビューを保存できます。番号なし
のものが 1 つ、および 1 から 9 の番号付きのものが 9 つです。


名前付きのビュー

ビューを使う 2 つ目の基本的な方法は、自分で選んだ名前のファイルにビューを保存
することです。このビューは、別のファイルを編集している間に読み込むことができま
す。そうすると Vim は、ビューで指定されたファイルの編集に切り替えます。したがっ
て、これを使うと、すべてのオプションを保存したとおりに設定した状態で、別のファ
イルの編集に素早く切り替えることができます。
   例えば、カレントファイルのビューを保存するには:

        :mkview ~/.vim/main.vim

これは以下で復元できます:

        :source ~/.vim/main.vim

21.6  モードライン

特定のファイルを編集するとき、そのファイル専用にオプションを設定することがある
でしょう。これらのコマンドを毎回タイプするのは退屈です。ファイルを編集するため
にセッションまたはビューを使うことは、ファイルを複数の人で共有しているときには
機能しません。
   この状況の解決策は、ファイルにモードラインを追加することです。これは、この
ファイルだけで使われるオプションの値を Vim に伝えるテキスト行です。
   典型的な例は、4 個の空白の倍数でインデントを付ける C プログラムです。これに
は 'shiftwidth' オプションを 4 に設定する必要があります。このモードラインがそ
れを行います:

        /* vim:set shiftwidth=4: */

この行を、ファイルの最初または最後の 5 行のうちの 1 行として置きます。このファ
イルを編集するとき、'shiftwidth' が 4 に設定されていることに気付くでしょう。別
のファイルを編集するときは、既定値の 8 に戻されます。
   ファイルによっては、モードラインがヘッダーにうまく収まるので、ファイルの先
頭に置くことができます。テキストファイル、およびモードラインが通常の内容の邪魔
になるその他のファイルでは、ファイルの末尾に置いてください。

'modelines' オプションは、ファイルの先頭および末尾の何行を、モードラインを含ん
でいるか調べるかを指定します。10 行を調べるには:

        :set modelines=10

'modeline' オプションを使うと、これをオフに切り替えることができます。Unix の
root、または MS-Windows の Administrator として作業しているとき、または編集し
ているファイルを信用していないときは、これを行ってください:

        :set nomodeline

モードラインにはこの形式を使います:

        any-text vim:set {option}={value} ... : any-text

"any-text" は、Vim が使う部分の前および後に任意のテキストを置けることを示しま
す。これにより、上で /* および */ で行ったように、それをコメントのように見せる
ことができます。
   " vim:" の部分が、Vim にこの行を認識させるものです。"vim" の前に空白がある
か、または "vim" が行頭になければなりません。したがって、"gvim:" のようなもの
を使っても機能しません。
   コロンの間の部分は ":set" コマンドです。コロンの前にバックスラッシュを挿入
する必要がある (そうしないとモードラインの終わりとみなされる) ことを除けば、
":set" コマンドをタイプするのと同じように機能します。

別の例:

        // vim:set textwidth=72 dir=c\:\tmp:  use c:\tmp here

最初のコロンの前に余分なバックスラッシュがあるので、それは ":set" コマンドに含
まれます。2 つ目のコロンの後のテキストは無視されるので、そこに注釈を置くことが
できます。

詳細は modeline を参照してください。
