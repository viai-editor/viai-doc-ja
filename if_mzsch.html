Brent Fulgham の成果に基づく。
動的ロードは Sergey Khorev によって追加された。

MzScheme および PLT Scheme という名前は Racket にブランド変更された。詳しくは
http://racket-lang.org を確認すること。

5.3.1 およびそれ以前の Racket バージョン 5.x の futures および places は、Vim
によって作成されたプロセスでは正しく動作しない。
最も簡単な解決策は、これらの機能を無効にして Racket を自分でビルドすることであ
る:
  ./configure --disable-futures --disable-places --prefix=your-install-prefix

処理を速くするために、--disable-gracket および --disable-docs も使用したいかも
しれない。

1. コマンド                                             mzscheme-commands

                                                        :mzscheme :mz
:[range]mz[scheme] {stmt}
                        MzScheme の文 {stmt} を実行する。

:[range]mz[scheme] << [trim] [{endmarker}]
{script}
{endmarker}
                        インライン化された MzScheme スクリプト {script} を実行
                        する。
                        Note: このコマンドは MzScheme 機能が組み込まれていない
                        場合は動作しない。エラーを避けるには、script-here を
                        参照。

                        "<<" の後の [endmarker] が省略された場合、:append お
                        よび :insert コマンドと同様に、{script} の後にドット
                        '.' を使用しなければならない。詳細は :let-heredoc を
                        参照。


                                                        :mzfile :mzf
:[range]mzf[ile] {file} {file} 内の MzScheme スクリプトを実行する。

これらのコマンドはどれも本質的に同じことを行う - 指定された行範囲を
"現在の範囲" に設定して、MzScheme コードの断片を実行する。

:mzscheme の場合、実行するコードはコマンドラインにある。
:mzfile の場合、実行するコードは指定されたファイルの内容である。

MzScheme インターフェイスは、exn から派生した例外 exn:vim を定義する。
これはさまざまな Vim のエラーで発生する。

コンパイル時に、MzScheme インターフェイスは現在の MzScheme コレクションパスを
記憶する。追加のパスを指定したい場合は "current-library-collection-paths" パラ
メーターを使用する。例えば、ユーザーローカルの MzScheme コレクションパスを
cons するには:
    :mz << EOF
    (current-library-collection-paths
        (cons
            (build-path (find-system-path 'addon-dir) (version) "collects")
            (current-library-collection-paths)))
    EOF


すべての機能はモジュール vimext を通して提供される。

exn:vim は明示的な import 無しで使用可能である。

MzScheme との衝突を避けるため、モジュールを require する時にプリフィックスを使
用することを検討すること。例:
        :mzscheme (require (prefix vim- vimext))

以下のすべての例はこの命名方式を前提としている。

                                                        mzscheme-sandbox
sandbox 内で実行された場合、一部のファイルシステムおよび Vim インターフェイ
スの手続きへのアクセスは制限される。

2. 例                                                   mzscheme-examples

        :mzscheme (display "Hello")
        :mz (display (string-append "Using MzScheme version " (version)))
        :mzscheme (require (prefix vim- vimext)) ; MzScheme < 4.x 用
        :mzscheme (require (prefix-in vim- 'vimext)) ; MzScheme 4.x
        :mzscheme (vim-set-buff-line 10 "This is line #10")

手元の MzScheme のバージョンを確認するには:
        :mzscheme (display (version))

インラインスクリプトの使用法:
        function! <SID>SetFirstLine()
            :mz << EOF
            (display "!!!")
            (require (prefix vim- vimext))
            ; 新しいバージョンでは (require (prefix-in vim- 'vimext))
            (vim-set-buff-line 1 "This is line #1")
            (vim-beep)
        EOF
        endfunction

        nmap <F9> :call <SID>SetFirstLine() <CR>

ファイルの実行:
        :mzfile supascript.scm

Vim の例外処理:
        :mz << EOF
        (require (prefix vim- vimext))
        ; 新しいバージョンでは (require (prefix-in vim- 'vimext))
        (with-handlers
          ([exn:vim? (lambda (e) (display (exn-message e)))])
          (vim-eval "nonsense-string"))
        EOF

vimext モジュールの自動インスタンス化 (vimrc に置くことができる):
    function! MzRequire()
        :redir => l:mzversion
        :mz (version)
        :redir END
        if strpart(l:mzversion, 1, 1) < "4"
            " MzScheme バージョン < 4.x:
            :mz (require (prefix vim- vimext))
        else
            " 新しいバージョン:
            :mz (require (prefix-in vim- 'vimext))
        endif
    endfunction

    if has("mzscheme")
        silent call MzRequire()
    endif

3. スレッド                                             mzscheme-threads

MzScheme インターフェイスはスレッドをサポートする。それらは OS のスレッドから
独立しており、したがってスケジューリングが必要である。オプション 'mzquantum'
は、Vim が使用可能な MzScheme スレッドをどのくらいの頻度でポーリングするべきか
を決める。
NOTE
Vim のコンソール版でのスレッドスケジューリングは、GUI 版よりも信頼性が低い。

==============================================================================
4. MzScheme からの Vim へのアクセス                     mzscheme-vim

                                                        mzscheme-vimext
'vimext' モジュールは、MzScheme インターフェイスで定義された手続きへのアクセス
を提供する。

共通
----
    (command {command-string})      vim の ":Ex" 形式のコマンドを実行する。
    (eval {expr-string})            vim の式を評価し、対応する MzScheme オブ
                                    ジェクトにする: Lists は Scheme のリスト
                                    として、Dictionaries はハッシュテーブル
                                    として、Funcref は関数として表現される
                                    (mzscheme-funcref も参照)
                                    NOTE 名前が MzScheme の eval と衝突する。
                                    これを克服するにはモジュール修飾子を使用す
                                    ること。
    (range-start)                   Scheme コマンドで渡された範囲の
    (range-end)                     開始/終了。
    (beep)                          ビープ
    (get-option {option-name} [buffer-or-window])
                                    Vim のオプションの値を取得する (ローカルま
                                    たはグローバルのどちらか、set-option を参
                                    照)。
    (set-option {string} [buffer-or-window])
                                    Vim のオプションを設定する。文字列はオプ
                                    ション設定の形式 (optname=optval、または
                                    optname+=optval など) でなければならない。
                                    {buffer} または {window} を指定して呼ばれ
                                    た場合、ローカルオプションが設定される。シ
                                    ンボル 'global を {buffer-or-window} とし
                                    て渡すことができる。その場合 :setglobal
                                    が使用される。

バッファ                                                 mzscheme-buffer
--------
    (buff? {object})                object はバッファか?
    (buff-valid? {object})          object は有効なバッファか? (つまり、実際の
                                    Vim バッファに対応している)
    (get-buff-line {linenr} [buffer])
                                    バッファから行を取得する。
    (set-buff-line {linenr} {string} [buffer])
                                    バッファの行を設定する。{string} が #f の
                                    場合、その行は削除される。[buffer] 引数は
                                    省略可能である。省略された場合、カレント
                                    バッファが使用される。
    (get-buff-line-list {start} {end} [buffer])
                                    バッファ内の行のリストを取得する。{start}
                                    および {end} は 1 から始まり、両端を含む。
    (set-buff-line-list {start} {end} {string-list} [buffer])
                                    バッファ内の行のリストを設定する。
                                    string-list が #f または null の場合、それ
                                    らの行は削除される。リストが {end}-{start}
                                    より短い場合、残りの行は削除される。
    (get-buff-name [buffer])        バッファのテキスト名を取得する。
    (get-buff-num [buffer])         バッファの番号を取得する。
    (get-buff-size [buffer])        バッファの行数を取得する。
    (insert-buff-line-list {linenr} {string/string-list} [buffer])
                                    行のリストをバッファの {linenr} の後に挿入
                                    する。{linenr} が 0 の場合、行は先頭に挿入
                                    される。
    (curr-buff)                     カレントバッファを取得する。それを変更する
                                    には他の MzScheme インターフェイスの手続き
                                    を使用する。
    (buff-count)                    エディタ内のバッファの総数を取得する。
    (get-next-buff [buffer])        次のバッファを取得する。
    (get-prev-buff [buffer])        前のバッファを取得する。それ以上バッファが
                                    無い場合は #f を返す。
    (open-buff {filename})          新しいバッファを開く (ファイル {filename}
                                    用)
    (get-buff-by-name {buffername}) ファイル名でバッファを、またはそのような
                                    バッファが無い場合は #f を取得する。
    (get-buff-by-num {buffernum})   番号でバッファを取得する (この番号のバッ
                                    ファが無い場合は #f を返す)。

ウィンドウ                                                  mzscheme-window
------
    (win? {object})                 object はウィンドウか?
    (win-valid? {object})           object は有効なウィンドウ (つまり、実際の
                                    Vim ウィンドウに対応している) か?
    (curr-win)                      カレントウィンドウを取得する。
    (win-count)                     ウィンドウの数を取得する。
    (get-win-num [window])          ウィンドウ番号を取得する。
    (get-win-by-num {windownum})    番号でウィンドウを取得する。
    (get-win-buffer [window])       指定されたウィンドウのバッファを取得する。
    (get-win-height [window])
    (set-win-height {height} [window])  ウィンドウの高さを取得/設定する。
    (get-win-width [window])
    (set-win-width {width} [window])  ウィンドウの幅を取得/設定する。
    (get-win-list [buffer])         バッファのウィンドウのリストを取得する。
    (get-cursor [window])           ウィンドウ内のカーソル位置をペア (linenr .
                                    column) として取得する。
    (set-cursor (line . col) [window])  カーソル位置を設定する。

6. 関数参照の使用                                           mzscheme-funcref

MzScheme インターフェイスでは Funcref を使用できるので、Scheme から Vim の関
数を直接呼ぶことができる。例えば:
    function! MyAdd2(arg)
        return a:arg + 2
    endfunction
    mz (define f2 (vim-eval "function(\"MyAdd2\")"))
    mz (f2 7)
  または:
    :mz (define indent (vim-eval "function('indent')"))
    " 12 行目の Vim のインデントを返す
    :mz (indent 12)

7. 動的ロード                                   mzscheme-dynamic E815

MS-Windows では、MzScheme ライブラリを動的にロードできる。その場合、:version
の出力に +mzscheme/dyn が含まれる。

これは、Vim が MzScheme の DLL ファイルを必要な時にのみ検索することを意味する。
MzScheme インターフェイスを使用しない場合はそれらは不要であり、したがってこれ
らの DLL ファイル無しで Vim を使用できる。
NOTE: 新しいバージョンの MzScheme (Racket) は、scheme_main_setup による早い段
階の (trampolined) 初期化を必要とする。そのため、Vim は可能な場合、常に起動時
に MzScheme の DLL をロードする。これにより Vim の起動が遅くなることがある。

MzScheme インターフェイスを使用するには、MzScheme の DLL が検索パス内に無けれ
ばならない。コンソールウィンドウで "path" と入力して、どのディレクトリが使用さ
れているかを確認する。

MS-Windows では、ロードするライブラリの名前に 'mzschemedll' および
'mzschemegcdll' オプションが使用される。初期値はビルド時に指定される。

DLL のバージョンは、Vim がコンパイルされた MzScheme のバージョンと一致しなけれ
ばならない。MzScheme バージョン 209 の場合、それらは "libmzsch209_000.dll" お
よび "libmzgc209_000.dll" になる。確実に知るには、":version" コマンドの出力を
見て、"Compilation" 情報内の -DDYNAMIC_MZSCH_DLL="something" および
-DDYNAMIC_MZGC_DLL="something" を探す。

例えば、MzScheme (Racket) が C:\Racket63 にインストールされている場合、以下の
ように環境変数を設定する必要があるかもしれない:

  PATH=%PATH%;C:\Racket63\lib
  PLTCOLLECTS=C:\Racket63\collects
  PLTCONFIGDIR=C:\Racket63\etc

8. MzScheme セットアップ                            mzscheme-setup E895

Vim は、if_mzsch コアのために "racket/base" モジュール (それが存在しない場合は
"scheme/base" にフォールバックする)、テストのために "r5rs" モジュール、および
Vim のビルドのために "raco ctool" コマンドを必要とする。MzScheme にそれらが無
かった場合は、MzScheme の raco コマンドでそれらをインストールできる:

  raco pkg install scheme-lib       # scheme/base モジュール
  raco pkg install r5rs-lib         # r5rs モジュール
  raco pkg install cext-lib         # raco ctool コマンド
