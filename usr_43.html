                             ファイルタイプを使う


特定のタイプのファイル、例えば C プログラムまたはシェルスクリプトを編集してい
ると、同じオプション設定およびマップをよく使います。これらを毎回手で設定するの
はすぐに面倒になります。この章では、それを自動的に行う方法を説明します。

43.1  ファイルタイプのためのプラグイン                filetype-plugin

ファイルタイププラグインを使い始める方法は、すでにここで説明しました:
add-filetype-plugin。しかし、デフォルトの設定は最小限にしてあるので、おそら
く満足できないでしょう。C ファイルで 'softtabstop' オプションを 4 に設定し、3
行のコメントを挿入するマップを定義したいとします。これは 2 つの手順だけででき
ます:

                                                        your-runtime-dir
1. 自分用のランタイムディレクトリを作ります。Unix では、これは通常 "~/.vim" で
   す。このディレクトリの中に "ftplugin" ディレクトリを作ります:

        mkdir ~/.vim
        mkdir ~/.vim/ftplugin

   Unix でない場合は、'runtimepath' オプションの値を調べて、Vim がどこで
   "ftplugin" ディレクトリを探すかを確かめてください:

        set runtimepath

   通常は最初のディレクトリ名 (最初のコンマより前) を使います。デフォルト値が
   気に入らない場合は、vimrc ファイルで 'runtimepath' オプションの先頭にディ
   レクトリ名を追加するとよいでしょう。

2. ファイル "~/.vim/ftplugin/c.vim" を作ります。内容は:

        setlocal softtabstop=4
        noremap <buffer> <LocalLeader>c o/**************<CR><CR>/<Esc>
        let b:undo_ftplugin = "setl softtabstop< | unmap <buffer> <LocalLeader>c"

C ファイルを編集してみてください。'softtabstop' オプションが 4 に設定されてい
るのが分かるはずです。しかし、別のファイルを編集すると、デフォルトの 0 に戻り
ます。これは ":setlocal" コマンドを使ったからです。これは 'softtabstop' オプ
ションをバッファにローカルにだけ設定します。別のバッファを編集するとすぐに、そ
のバッファに設定された値になります。新しいバッファでは、デフォルト値、または最
後の ":set" コマンドの値になります。

同様に、"\c" のマップも、別のバッファを編集すると無くなります。":map <buffer>"
コマンドは、カレントバッファにローカルなマップを作ります。これはどのマップコマ
ンドでも使えます: ":map!"、":vmap" など。マップの中の <LocalLeader> は
"maplocalleader" 変数の値に置き換えられます。

b:undo_ftplugin を設定する行は、ファイルタイプが別の値に設定されたときのための
ものです。その場合は、自分の設定を元に戻したいでしょう。b:undo_ftplugin 変数は
コマンドとして実行されます。文字列の中で特別な意味を持つ文字、例えばバックス
ラッシュに注意してください。

ファイルタイププラグインの例は、このディレクトリにあります:

        $VIMRUNTIME/ftplugin/

ファイルタイププラグインの書き方の詳細は、ここにあります: write-plugin。

43.2  ファイルタイプを追加する

Vim が認識しないタイプのファイルを使っている場合は、これが認識させる方法です。
自分用のランタイムディレクトリが必要です。上の your-runtime-dir を参照してく
ださい。

自分のファイルタイプのための自動コマンドを含むファイル "filetype.vim" を作りま
す。(自動コマンドはセクション 40.3 で説明しました。) 例:

        augroup filetypedetect
        au BufNewFile,BufRead *.xyz     setf xyz
        augroup END

これは、".xyz" で終わるすべてのファイルを "xyz" ファイルタイプと認識します。
":augroup" コマンドは、この自動コマンドを "filetypedetect" グループに入れます。
こうすると、":filetype off" を実行したときに、ファイルタイプ検出の自動コマンド
をすべて削除できます。"setf" コマンドは、'filetype' オプションがまだ設定されて
いなければ、引数の値に設定します。これで 'filetype' が 2 回設定されないように
なります。

ファイルの名前にマッチさせるために、さまざまなパターンを使えます。ディレクトリ
名も含められます。autocmd-patterns を参照してください。例えば、
"/usr/share/scripts/" の下のファイルはすべて "ruby" ファイルですが、期待される
拡張子を持っていません。上の例にこれを追加します:

        augroup filetypedetect
        au BufNewFile,BufRead *.xyz                     setf xyz
        au BufNewFile,BufRead /usr/share/scripts/*      setf ruby
        augroup END

しかし、ここでファイル /usr/share/scripts/README.txt を編集すると、これは ruby
のファイルではありません。"*" で終わるパターンの危険は、すぐにあまりにも多くの
ファイルにマッチしてしまうことです。これによる問題を避けるには、filetype.vim
ファイルを別のディレクトリ、'runtimepath' の最後にあるディレクトリに置きます。
例えば Unix では、"~/.vim/after/filetype.vim" を使えます。
   ここで、テキストファイルの検出を ~/.vim/filetype.vim に書きます:

        augroup filetypedetect
        au BufNewFile,BufRead *.txt                     setf text
        augroup END

このファイルは 'runtimepath' の中で最初に見つかります。そして、最後に見つかる
~/.vim/after/filetype.vim でこれを使います:

        augroup filetypedetect
        au BufNewFile,BufRead /usr/share/scripts/*      setf ruby
        augroup END

これで、Vim は 'runtimepath' の各ディレクトリで "filetype.vim" ファイルを探す
ようになります。最初に ~/.vim/filetype.vim が見つかります。*.txt ファイルを捕
まえる自動コマンドは、そこで定義されます。次に Vim は、'runtimepath' の途中に
ある $VIMRUNTIME の filetype.vim ファイルを見つけます。最後に
~/.vim/after/filetype.vim が見つかり、/usr/share/scripts の ruby ファイルを検
出する自動コマンドが追加されます。
   ここで /usr/share/scripts/README.txt を編集すると、自動コマンドは定義された
順にチェックされます。*.txt パターンがマッチするので、"setf text" が実行され、
ファイルタイプが "text" に設定されます。ruby のパターンもマッチし、"setf ruby"
が実行されます。しかし、'filetype' はすでに "text" に設定されているので、ここ
では何も起こりません。
   ファイル /usr/share/scripts/foobar を編集すると、同じ自動コマンドがチェック
されます。ruby のものだけがマッチし、"setf ruby" が 'filetype' を ruby に設定
します。


内容による認識

ファイル名からファイルを認識できない場合でも、内容から認識できるかもしれませ
ん。例えば、多くのスクリプトファイルは以下のような行で始まります:

        #!/bin/xyz

このスクリプトを認識するには、ランタイムディレクトリ (filetype.vim を置くのと
同じ場所) にファイル "scripts.vim" を作ります。このようになるかもしれません:

        if did_filetype()
          finish
        endif
        if getline(1) =~ '^#!.*[/\\]xyz\>'
          setf xyz
        endif

最初の did_filetype() によるチェックは、ファイル名によってすでにファイルタイプ
が検出されているファイルの内容をチェックしないようにするためのものです。これに
より、"setf" コマンドが何もしないときに、ファイルのチェックに時間を無駄に使わ
ずに済みます。
   scripts.vim ファイルは、デフォルトの filetype.vim ファイルの中の自動コマン
ドによって読み込まれます。したがって、チェックの順番は:

        1. 'runtimepath' の中の $VIMRUNTIME より前にある filetype.vim ファイル
        2. $VIMRUNTIME/filetype.vim の最初の部分
        3. 'runtimepath' の中のすべての scripts.vim ファイル
        4. $VIMRUNTIME/filetype.vim の残りの部分
        5. 'runtimepath' の中の $VIMRUNTIME より後にある filetype.vim ファイル

これで足りない場合は、すべてのファイルにマッチし、スクリプトを読み込むか、また
は関数を実行してファイルの内容をチェックする自動コマンドを追加してください。
