2. Vimball 入門                                                 vimball-intro

        Vimball はプラグインユーザーの生活をより簡単にすることを意図している。
        ユーザーが vimball に対して行う必要があるのは、これだけである:
                vim someplugin.vba
                :so %
                :q
        すると、プラグインおよびそのすべての構成要素が、それぞれの適切なディレ
        クトリにインストールされる。Note これを行うときに、特定のディレクトリ
        にいる必要はないことに注意。さらに、プラグインのヘルプも自動的にインス
        トールされる。

        ユーザーが AsNeeded プラグインを使うことにしている場合、vimball は賢い
        ので、名目上 .vim/plugin/ 向けのスクリプトを、代わりに .vim/AsNeeded/
        に置く。

        vimball でインストールされたプラグインを削除するのは本当に簡単である:

                vim
                :RmVimball someplugin
        例えば、zip および tarball では、この操作はまったく簡単ではない。

        Vimball はユーザーの 'runtimepath' を調べて、スクリプトをどこに置くか
        を決める。可能なら、通常は runtimepath で最初に挙げられたディレクトリ
        が使われる。そのディレクトリを見るには
                :echo &rtp
        を使う。

3. Vimball マニュアル                                   vimball-manual

Vimball の作成                                         :MkVimball
                :[range]MkVimball[!] filename [path]

        範囲は、新しい vimball に含めるファイルへのパスを保持する行で構成され、
        パスのうち、通常 runtimepath ('rtp') で指定される部分は省く。例として:

                plugin/something.vim
                doc/something.txt
        この範囲の行に対して
                :[range]MkVimball filename

        を使うと、"filename.vba" というファイルが作成され、それは Vimball.vim
        がこれらのファイルを再作成するのに使える。"filename.vba" ファイルが既
        に存在する場合は、MkVimball は警告を出し、ファイルを作成しない。Note
        これらのパスは .vim (vimfiles) ディレクトリからの相対パスであり、ファ
        イルはそのディレクトリにあるべきであることに注意。vimball プラグインは
        通常、存在する最初の 'runtimepath' ディレクトリをプリフィックスとして
        使う。ユーザーがそのようなパスを指定していない限り、絶対パスを使っては
        ならない。

        感嘆符 (!) を使うと、MkVimball は "filename.vba" ファイルを作成し、そ
        れが既に存在する場合は上書きする。この動作は :w のそれに似ている。

        ファイル名にスラッシュを強制的に入れたい場合も、感嘆符を使うことででき
        る (すなわち :MkVimball! path/filename)。

        http://vim.wikia.com/wiki/Using_VimBall_with_%27Make%27 の tip には、
        make を使って vimball の生成を自動化する方法についての良いアイデアがあ
        る。


Vimball 展開ディレクトリの制御                 g:vimball_home

        変数 g:vimball_home を指定することで、'runtimepath' の使用を上書きでき
        る。

                                                        vimball-extract
                vim filename.vba

        Vimball を単に編集すると、Vimball.vim はユーザーに、内容を展開するため
        にそのファイルを読み込むよう伝える。

        展開は、vimball と思われるファイルの 1 行目に
        "Vimball Archiver by Charles E. Campbell" という行がある場合にのみ進
        む。

Vimball 内のファイルの一覧表示                         :VimballList

                :VimballList

        このコマンドは Vimball に、アーカイブ内のファイルを、行数で表したその
        長さとともに一覧表示させる。

Vimball 展開の手動呼び出し                                     :UseVimball

                :UseVimball [path]

        このコマンドは vimball 自体の中に含まれている。これは vimball の展開を
        担う vimball#Vimball() ルーチンを呼び出す。vimball を読み込む代わりに、
        手でそれを実行することを選んでもよい。また、インストールのためのパスを
        指定することを選んでもよく、それにより、'runtimepath' 上で最初に存在す
        るディレクトリという自動的な選択を上書きする。

Vimball の削除                                         :RmVimball

                :RmVimball vimballfile [path]

        このコマンドは、指定された vimball によって生成されたすべてのファイル
        を削除する (ただし、それが作成したかもしれないディレクトリは削除しな
        い)。アンインストールのためのパスを選ぶこともできる ('runtimepath' を
        参照)。そうでなければ、デフォルトは 'runtimepath' 上で最初に存在する
        ディレクトリである。
        これを実装するため、そのディレクトリにファイル (.VimballRecord) が作成
        され、これまでに使われたすべての vimball について、どのファイルを削除
        する必要があるかの記録を保持する。

読み込みの防止

        何らかの理由で、vimball を使ってプラグインを展開できないようにしたい場
        合は、以下の 2 つの変数を <.vimrc> に入れることで、vimball.vim の読み
        込みを防止できる:

                let g:loaded_vimballPlugin= 1
                let g:loaded_vimball      = 1

Windows                                                vimball-windows

        多くの vimball ファイルは gzip で圧縮されている。残念ながら、Windows
        には gzip されたファイルを展開するツールが付属していない。幸い、
        Windows ユーザーが利用できる、ファイルを un-gzip するためのツールがい
        くつかある:

            Item     Tool/Suite   Free   Website
            ----     ----------   ----   -------
            7zip        tool       y     http://www.7-zip.org/
            Winzip      tool       n     http://www.winzip.com/downwz.htm
            unxutils    suite      y     http://unxutils.sourceforge.net/
            cygwin      suite      y     http://www.cygwin.com/
            GnuWin32    suite      y     http://gnuwin32.sourceforge.net/
            MinGW       suite      y     http://www.mingw.org/
