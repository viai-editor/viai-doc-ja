1. 概要                                         Vim9-class-overview

しゃれた用語で言えば「オブジェクト指向プログラミング」である。この主題について
は学習資料がたくさん見つかる。ここでは、あなたがすでに基本を知っていることを前
提として、Vim9 script が提供するものを説明する。この機能を効果的に使う方法に
ついての役に立つヒントも加えている。Vim9 のクラスとオブジェクトは、旧来の Vim
script と旧来の関数では使えない。

基本となる要素はオブジェクトである:
- オブジェクトは状態を保持する。オブジェクトには 1 つ以上の変数が含まれ、それ
  ぞれが値を持つことができる。
- オブジェクトは、その状態を使ったり操作したりする関数を提供する。これらの関数
  は「オブジェクトに対して」呼び出される。これが、データとデータを操作するコー
  ドを分ける従来の方法との違いである。
- オブジェクトは、型付きのメンバー変数とメソッドを備えた、明確に定義されたイン
  ターフェイスを持つ。
- オブジェクトはクラスから作られ、すべてのオブジェクトは同じインターフェイスを
  持つ。これは実行時に変わることはなく、動的ではない。

オブジェクトはクラスによってのみ作ることができる。クラスは以下を提供する:
- new() メソッド。これはコンストラクタで、そのクラスのオブジェクトを返す。
  このメソッドはクラス名に対して呼び出される: MyClass.new()。
- クラスのすべてのオブジェクトで共有される状態: クラス変数 (クラスメンバー)。
- スーパークラスとサブクラス、継承による、クラスの階層。

インターフェイスは、オブジェクトの性質を指定するために使われる:
- オブジェクトは、自身が実装する複数のインターフェイスを宣言できる。
- 同じインターフェイスを実装した異なるオブジェクトは、同じように使うことができ
  る。

クラスの階層では単一継承ができる。それ以外の場合は、必要に応じてインターフェイ
スを使うこと。

クラスのモデリング

クラスは好きなようにモデル化できる。何を作っているのかを念頭に置き、現実世界を
モデル化しようとしないこと。これは混乱を招くことがある。特に、教師は現実世界の
物を使ってクラスの関係を説明するので、自分のモデルもそのため現実世界を反映すべ
きだと思うかもしれない。そんなことはない! モデルは目的に合っているべきである。

コンポジション (オブジェクトが他のオブジェクトを含む) は、継承 (オブジェクトが
他のオブジェクトを拡張する) よりも良いことが多いことを念頭に置くこと。最適なク
ラスモデルを見つけようとして時間を無駄にしないこと。また、正方形は長方形なの
か、長方形は正方形なのかを議論して時間を無駄にしないこと。それは重要ではない。

2.  単純なクラス                                Vim9-simple-class

単純な例から始めよう: テキストの位置を保持するクラスである (これをより効率的に
行う方法は以下を参照):

        class TextPosition
           var lnum: number
           var col: number

           def new(lnum: number, col: number)
              this.lnum = lnum
              this.col = col
           enddef

           def SetLnum(lnum: number)
              this.lnum = lnum
           enddef

           def SetCol(col: number)
              this.col = col
           enddef

           def SetPosition(lnum: number, col: number)
              this.lnum = lnum
              this.col = col
           enddef
         endclass
                                                        object Object
このクラスから、new() メソッドでオブジェクトを作ることができる:

        var pos = TextPosition.new(1, 1)

オブジェクト変数 "lnum" と "col" には直接アクセスできる:

        echo $'The text position is ({pos.lnum}, {pos.col})'
                                                    E1317 E1327 :this
他のオブジェクト指向言語を使ったことがある場合、Vim では、クラス定義の中で、宣
言されたオブジェクトメンバーが一貫して "this." プリフィックスを付けて参照され
ることに気付くだろう。これは Java や TypeScript のような言語とは異なる。この命
名規則により、オブジェクトメンバーを見つけやすくなる。また、変数に "this." プ
リフィックスが付いていなければ、それがオブジェクト変数でないことが分かる。
                                                        E1411
クラス定義の外からは、オブジェクト名に続けてドット、その後にメンバーを書いて、
オブジェクトのメソッドと変数にアクセスする:

        pos.lnum
        pos.SetCol(10)

                                                        E1405
クラス名は式として使えない。クラス名は代入の左辺で使えない。

オブジェクト変数の書き込みアクセス
                                                    read-only-variable
オブジェクト変数を直接変更してみよう:

        pos.lnum = 9
                                                        E1335
これはエラーになる! デフォルトでは、オブジェクト変数は読み取れるが設定できない
からである。そのため、TextPosition クラスはそのためのメソッドを提供している:

        pos.SetLnum(9)

オブジェクト変数を読み取れるが設定できないようにすることは、最も一般的で最も安
全な方法である。たいていの場合、値を使うことには問題がないが、値を設定すること
には、対処が必要な副作用があるかもしれない。この場合、SetLnum() メソッドで行番
号が有効かどうかを確かめ、エラーを出すか、最も近い有効な値を使うことができる。
                                        :public public-variable E1331
副作用を気にせず、オブジェクト変数をいつでも変更できるようにしたい場合は、
public にすることができる:

        public var lnum: number
        public var col: number

これで SetLnum()、SetCol()、SetPosition() メソッドは不要になり、上で
"pos.lnum" を直接設定してもエラーにならなくなる。
                                                        E1326
存在しないオブジェクト変数を設定しようとすると、エラーになる:
        pos.other = 9
        E1326: Member not found on object "TextPosition": other

                                                        E1376
オブジェクト変数には、クラス名を使ってアクセスすることはできない。

Protected 変数
                                        protected-variable E1332 E1333
一方、オブジェクト変数をクラスやそのサブクラスの外から直接読み取られたくない場
合は、それを protected にすることができる。これは、名前の前にアンダースコアを
付けることで行う:

        var _lnum: number
        var _col: number

これで、protected 変数の値を得るためのメソッドを提供する必要がある。これは一般
にゲッターと呼ばれる。"Get" で始まる名前を使うことを勧める:

        def GetLnum(): number
           return this._lnum
        enddef

        def GetCol(): number
           return this._col
        enddef

この例はあまり役に立たない。変数を public にしても同じだったであろう。値を確か
めるようにすると役に立つ。例えば、行番号を総行数までに制限する:

        def GetLnum(): number
           if this._lnum > this._lineCount
              return this._lineCount
           endif
           return this._lnum
        enddef

Protected メソッド
                                                protected-method E1366
オブジェクトメソッドを、同じクラスの他のメソッドからだけアクセスできるように
し、クラスの外からは使えないようにしたい場合は、それを protected にすることが
できる。これは、メソッド名の前にアンダースコアを付けることで行う:

    class SomeClass
        def _Foo(): number
          return 10
        enddef
        def Bar(): number
          return this._Foo()
        enddef
    endclass

protected メソッドにクラスの外からアクセスすると、エラーになる (上のクラスを
使った場合):

    var a = SomeClass.new()
    a._Foo()

new() メソッドを単純にする
                                                new() constructor
default-constructor と multiple-constructors も参照。

多くのコンストラクタは、オブジェクト変数の値を受け取る。そのため、このパターン
をよく見かける:

         class SomeClass
           var lnum: number
           var col: number

           def new(lnum: number, col: number)
              this.lnum = lnum
              this.col = col
           enddef
         endclass

                                                        E1390
これは書く必要のあるテキストであるだけでなく、各変数の型が 2 回出てくる。これ
はとてもよくあることなので、new() をより短く書く方法が提供されている:

           def new(this.lnum, this.col)
           enddef

この意味は分かりやすい: "this." を含めたオブジェクト変数名を new() の引数とし
て指定すると、new() の呼び出しで渡された値がそのオブジェクト変数に代入される。
この仕組みは Dart 言語から来ている。

new() のこの使い方と、変数を public にすることを組み合わせると、最初のものより
ずっと短いクラス定義になる:

        class TextPosition
           public var lnum: number
           public var col: number

           def new(this.lnum, this.col)
           enddef

           def SetPosition(lnum: number, col: number)
              this.lnum = lnum
              this.col = col
           enddef
         endclass

新しいオブジェクトを構築する順序は次のとおりである:
1. メモリが確保され、クリアされる。すべての値はゼロ/false/空である。
2. 初期化子を持つ宣言された各オブジェクト変数について、その式が評価され、変数
   に代入される。これは、クラス内で変数が宣言された順に行われる。
3. new() メソッドの "this.name" 形式の引数が代入される。
4. new() メソッドの本体が実行される。

クラスが親クラスを拡張している場合も、同じことが起こる。2 番目のステップでは、
親クラスのオブジェクト変数が最初に初期化される。親に対して "super()" や
"new()" を呼ぶ必要はない。

                                                        E1365
new() メソッドを定義するとき、戻り値の型を指定すべきではない。new() は常にその
クラスのオブジェクトを返す。

new() メソッドは、"_new()" とすることで protected メソッドにすることができる。
これは、シングルトンデザインパターンをサポートするのに使える。

                                                        E1386
オブジェクトメソッドを呼び出すときは、メソッド名の前にオブジェクト変数名を付け
るべきである。オブジェクトメソッドは、クラス名を使って呼び出すことはできない。

3.  クラス変数とメソッド                        Vim9-class-member

                                    :static E1329 E1337 E1338 E1368
クラスメンバーは "static" で宣言する。クラスメンバーは、それが定義されているク
ラスの中では、プリフィックスなしの名前で使われる:

        class OtherThing
           var size: number
           static var totalSize: number

           def new(this.size)
              totalSize += this.size
           enddef
        endclass
                                                        E1340 E1341
名前はそのまま使われるので、メソッドの引数名やローカル変数名で名前を隠すことは
許されない。

                                            E1374 E1375 E1384 E1385
クラスメンバーが定義されているクラスの外からクラスメンバーにアクセスするには、
クラス名のプリフィックスを使わなければならない。クラスメンバーには、オブジェク
トを使ってアクセスすることはできない。

オブジェクトメンバーと同様に、名前の最初の文字にアンダースコアを使うことでアク
セスを protected にすることができ、"public" を前に付けることで public にするこ
とができる:

    class OtherThing
        static var total: number          # 誰でも読めるが書けるのはクラスだけ
        static var _sum: number           # クラスだけが読み書きできる
        public static var result: number  # 誰でも読み書きできる
    endclass

                                                        class-method
クラスメソッドも "static" で宣言する。クラスメソッドはクラス変数を使うことがで
きるが、オブジェクト変数にはアクセスできず、"this" キーワードを使うことはでき
ない:

        class OtherThing
           var size: number
           static var totalSize: number

           # 合計サイズをクリアし、それまでの値を返す。
           static def ClearTotalSize(): number
              var prev = totalSize
              totalSize = 0
              return prev
           enddef
        endclass

クラスの中では、クラスメソッドを名前で直接呼び出すことができる。クラスの外で
は、クラス名を前に付けなければならない: OtherThing.ClearTotalSize()。また、
クラス変数の初期化子、ラムダ式、ネストした関数という特別なコンテキストでは、
public なクラスメソッドに名前のプリフィックスを使わなければならない:

    class OtherThing
        static var name: string = OtherThing.GiveName()

        static def GiveName(): string
            def DoGiveName(): string
                return OtherThing.NameAny()
            enddef

            return DoGiveName()
        enddef

        static def NameAny(): string
            return "any"
        enddef
    endclass


オブジェクトメソッドと同様に、メソッド名の最初の文字にアンダースコアを使うこと
でアクセスを protected にすることができる:

    class OtherThing
        static def _Foo()
            echo "Foo"
        enddef
        def Bar()
            _Foo()
        enddef
    endclass

                                                        E1370
Note コンストラクタは "static" として宣言できないことに注意。コンストラクタは
static のように呼ばれるが、オブジェクトメソッドとして実行される。コンストラク
タは "this" にアクセスできる。

拡張したクラスの中でスーパークラスのクラスメソッドとクラス変数にアクセスするに
は、定義しているクラスの外のどこからでもそうするのと同じように、クラス名のプリ
フィックスを使うべきである:

    vim9script
    class Vehicle
        static var nextID: number = 1000
        static def GetID(): number
            nextID += 1
            return nextID
        enddef
    endclass
    class Car extends Vehicle
        var myID: number
        def new()
            this.myID = Vehicle.GetID()
        enddef
    endclass

クラス変数とクラスメソッドは、子クラスに継承されない。子クラスは、スーパークラ
スにあるものと同じ名前の static 変数やメソッドを宣言できる。メンバーが使われる
クラスによって、対応するクラスメンバーが使われる。子クラスのクラスメンバーの型
は、スーパークラスのものと異なっていてもよい。

クラスメソッドやオブジェクトメソッドの名前の、2 つのアンダースコア (__) のプリ
フィックスは、将来の使用のために予約されている。

                                        object-final-variable E1409
:final キーワードを使って、クラス変数やオブジェクト変数を定数にすることがで
きる。例:

    class A
        final v1 = [1, 2]               # final オブジェクト変数
        public final v2 = {x: 1}        # final オブジェクト変数
        static final v3 = 'abc'         # final クラス変数
        public static final v4 = 0z10   # final クラス変数
    endclass

final 変数は、コンストラクタ関数からのみ変更できる。例:

    class A
        final v1: list<number>
        def new()
            this.v1 = [1, 2]
        enddef
    endclass
    var a = A.new()
    echo a.v1

Note final 変数の値は変更できることに注意。例:

    class A
        public final v1 = [1, 2]
    endclass
    var a = A.new()
    a.v1[0] = 6                 # OK
    a.v1->add(3)                # OK
    a.v1 = [3, 4]               # エラー

                                                        E1408
final 変数はインターフェイスではサポートされていない。クラスメソッドやオブジェ
クトメソッドを final にすることはできない。

                                        object-const-variable
:const キーワードを使って、クラス変数やオブジェクト変数とその値を定数にする
ことができる。例:

    class A
        const v1 = [1, 2]               # const オブジェクト変数
        public const v2 = {x: 1}        # const オブジェクト変数
        static const v3 = 'abc'         # const クラス変数
        public static const v4 = 0z10   # const クラス変数
    endclass

const 変数は、コンストラクタ関数からのみ変更できる。例:

    class A
        const v1: list<number>
        def new()
            this.v1 = [1, 2]
        enddef
    endclass
    var a = A.new()
    echo a.v1

const 変数とその値は変更できない。例:

    class A
        public const v1 = [1, 2]
    endclass
    var a = A.new()
    a.v1[0] = 6                 # エラー
    a.v1->add(3)                # エラー
    a.v1 = [3, 4]               # エラー

                                                         E1410
const 変数はインターフェイスではサポートされていない。クラスメソッドやオブジェ
クトメソッドを const にすることはできない。

4.  抽象クラスを使う                            Vim9-abstract-class

抽象クラスは、少なくとも 1 つのサブクラスの基になる。クラスモデルでは、いくつ
かのクラスが共有できる同じ性質を持つことがよくあるが、それらの性質を持つクラス
には、オブジェクトを作るのに十分な状態がない。サブクラスは、オブジェクトを作る
のに使えるようになる前に、抽象クラスを拡張して、足りない状態やメソッドを追加し
なければならない。

例えば、Shape クラスは色と太さを保持することができる。Shape オブジェクトを作る
ことはできない。それがどのような種類の形なのかという情報が欠けているからであ
る。Shape クラスは Square クラスと Triangle クラスの基として機能し、それらにつ
いてはオブジェクトを作ることができる。例:

        abstract class Shape
           var color = Color.Black
           var thickness = 10
        endclass

        class Square extends Shape
           var size: number

           def new(this.size)
           enddef
        endclass

        class Triangle extends Shape
           var base: number
           var height: number

           def new(this.base, this.height)
           enddef
        endclass

抽象クラスは、new() メソッドを持たないことを除けば、通常のクラスと同じ方法で定
義される。 E1359

                                            abstract-method E1371 E1372
抽象クラスの中では、メソッドを定義するときに "abstract" プリフィックスを使うこ
とで、抽象メソッドを定義できる:

        abstract class Shape
           abstract def Draw()
        endclass

抽象クラスの static メソッドは、抽象メソッドにすることはできない。

                                                E1404
インターフェイスのメソッドは、抽象メソッドにすることはできない。

                                                E1373
抽象クラスを拡張する抽象クラスでないクラスは、すべての抽象メソッドを実装しなけ
ればならない。シグネチャ (引数、引数の型、戻り値の型) はまったく同じでなければ
ならない。メソッドの戻り値の型がクラスの場合、拡張したメソッドでは、そのクラス
かそのサブクラスの 1 つを使うことができる。

                                                E1431
抽象スーパークラスの抽象メソッドは、呼び出すことができない。

5.  インターフェイスを使う                      Vim9-using-interface

上の Shape、Square、Triangle の例は、オブジェクトの面積を計算するメソッドを追
加すると、もっと役に立つものにできる。そのために、数値を返す 1 つのメソッド
Surface() を指定する、HasSurface というインターフェイスを作る。この例は上のも
のを拡張している:

        abstract class Shape
           var color = Color.Black
           var thickness = 10
        endclass

        interface HasSurface
           def Surface(): number
        endinterface

        class Square extends Shape implements HasSurface
           var size: number

           def new(this.size)
           enddef

           def Surface(): number
              return this.size * this.size
           enddef
        endclass

        class Triangle extends Shape implements HasSurface
           var base: number
           var height: number

           def new(this.base, this.height)
           enddef

           def Surface(): number
              return this.base * this.height / 2
           enddef
        endclass

                                        E1348 E1349 E1367 E1382 E1383
クラスがインターフェイスを実装すると宣言した場合、インターフェイスで指定された
すべての項目が、同じ型で、クラスに現れなければならない。

インターフェイス名は型として使うことができる:

        var shapes: list<HasSurface> = [
                                Square.new(12),
                                Triangle.new(8, 15),
                                ]
        for shape in shapes
           echo $'the surface is {shape.Surface()}'
        endfor

                                        E1378 E1379 E1380 E1387
インターフェイスには、オブジェクトメソッドと読み取り専用のオブジェクト変数だけ
を含めることができる。インターフェイスには、読み書き可能なオブジェクト変数や
protected オブジェクト変数、protected オブジェクトメソッド、クラス変数、クラス
メソッドを含めることはできない。

インターフェイスは "extends" を使って、別のインターフェイスを拡張できる。サブ
インターフェイスは、スーパーインターフェイスからすべてのインスタンス変数とメ
ソッドを継承する。

インターフェイスは関数の中では定義できない。            E1436

6.  クラスの詳細                                Vim9-class Class class

クラスを定義する
                                        :class :endclass :abstract
クラスは :class と :endclass の間で定義される。クラス全体は 1 つのスクリプ
トファイルの中で定義される。後からクラスに追加することはできない。

クラスは Vim9 script ファイルの中でのみ定義できる。 E1316
クラスは関数の中では定義できない。 E1429

1 つのスクリプトファイルで、複数のクラスを定義することができる。ただし、通常は
1 つのメインクラスだけをエクスポートするほうが良い。とはいえ、型、列挙型、ヘル
パークラスを定義することは役に立つ場合がある。

:abstract キーワードを前に付けることができ、:export を使うことができる。そ
れにより、これらのバリエーションができる:

        class ClassName
        endclass

        export class ClassName
        endclass

        abstract class ClassName
        endclass

        export abstract class ClassName
        endclass

                                                        E1314
クラス名はキャメルケースにすべきである。クラス名は大文字で始まらなければならな
い。これにより、組み込みの型との衝突を避けられる。
                                                        E1315
クラス名の後には、これらの省略可能な項目を使うことができる。それぞれ 1 回だけ
現れることができる。どの順序でも現れることができるが、この順序を勧める:
        extends ClassName
        implements InterfaceName, OtherInterface
        specifies SomeInterface

"specifies" の機能は、現在は実装されていない。

                                                E1355 E1369 E1406
各変数名とメソッド名は 1 回だけ使うことができる。同じ名前で引数の型が異なるメ
ソッドを定義することはできない。同じ名前の public なメンバー変数と protected
なメンバー変数を使うことはできない。スーパークラスで使われたオブジェクト変数名
を、子クラスで再び使うことはできない。

オブジェクト変数の初期化

                                                        E1430
クラスの中で変数の型が明示的に指定されていない場合、クラス定義の間は "any" に
設定される。そのクラスからオブジェクトがインスタンス化されるときに、変数の型が
設定される。

以下の予約済みのキーワードの名前は、オブジェクト変数やクラス変数の名前として使
えない: "super"、"this"、"true"、"false"、"null"、"null_blob"、"null_channel"、
"null_class"、"null_dict"、"null_function"、"null_job"、"null_list"、
"null_object"、"null_partial"、"null_string"。

クラスを拡張する
                                                        extends
クラスは 1 つの他のクラスを拡張できる。 E1352 E1353 E1354
基本的な考え方は、既存のクラスの上に構築し、それに性質を追加することである。

拡張されたクラスは「基底クラス」または「スーパークラス」と呼ばれる。新しいクラ
スは「子クラス」と呼ばれる。

基底クラスのオブジェクト変数は、すべて子クラスに引き継がれる。
それらをオーバーライドすることはできない (他のいくつかの言語とは異なる)。

                                                E1356 E1357 E1358
基底クラスのオブジェクトメソッドは、上書きすることができる。シグネチャ (引数、
引数の型、戻り値の型) はまったく同じでなければならない。メソッドの戻り値の型が
クラスの場合、拡張したメソッドでは、そのクラスかそのサブクラスの 1 つを使うこ
とができる。基底クラスのメソッドは、"super." を前に付けることで呼び出すことが
できる。

                                                E1377
子クラスのメソッドのアクセスレベル (public か protected か) は、スーパークラス
と同じであるべきである。

基底クラスのその他のオブジェクトメソッドは、子クラスに引き継がれる。

"new" で始まるメソッドを含め、クラスメソッドは、オブジェクトメソッドと同様に上
書きすることができる。基底クラスのメソッドは、クラスの名前 (クラスメソッドの場
合) か "super." を前に付けることで呼び出すことができる。

他の言語とは異なり、基底クラスのコンストラクタを呼び出す必要はない。実際のとこ
ろ、呼び出すことはできない。基底クラスの初期化の一部を子クラスでも行う必要があ
る場合は、それをオブジェクトメソッドに入れ、すべての constructor() からそのメ
ソッドを呼び出すこと。

基底クラスで new() メソッドが指定されていなかった場合は、自動的に作られている。
このメソッドは子クラスには引き継がれない。子クラスは独自の new() メソッドを定
義でき、定義しなかった場合は、new() メソッドが自動的に追加される。


インターフェイスを実装するクラス
                                        implements E1346 E1347 E1389
クラスは 1 つ以上のインターフェイスを実装できる。"implements" キーワードは 1
回だけ現れることができる E1350 。複数のインターフェイスを、コンマで区切って
指定できる。各インターフェイス名は 1 回だけ現れることができる。 E1351

インターフェイスを定義するクラス
                                                        specifies
クラスは、名前付きのインターフェイスで、自身のインターフェイス、つまりオブジェ
クト変数とメソッドを宣言できる。これにより、インターフェイスを別に指定する必要
がなくなる。多くの言語、特に Java では、別に指定することがよく行われている。

クラス内の項目
                                                E1318 E1325 E1388
クラスの中の、:class と :endclass の間には、これらの項目が現れることができ
る:
- オブジェクト変数の宣言:
        var _protectedVariableName: memberType
        var readonlyVariableName: memberType
        public var readwriteVariableName: memberType
- クラス変数の宣言:
        static var _protectedClassVariableName: memberType
        static var readonlyClassVariableName: memberType
        public static var readwriteClassVariableName: memberType
- コンストラクタメソッド:
        def new(arguments)
        def newName(arguments)
- クラスメソッド:
        static def SomeMethod(arguments)
        static def _ProtectedMethod(arguments)
- オブジェクトメソッド:
        def SomeMethod(arguments)
        def _ProtectedMethod(arguments)

オブジェクト変数には、型を指定しなければならない。最も良い方法は、": {type}"
で明示的に指定することである。単純な型の場合は、"= 123" のような初期化子を使う
こともでき、Vim は型が数値であると分かる。より複雑な型の場合や、型が不完全にな
る場合は、これを避けること。例えば:
        var nameList = []
これはリストを指定するが、要素の型は分からない。こちらを使うほうが良い:
        var nameList: list<string>
初期化は必要ない。リストはデフォルトで空である。
                                                        E1330
"void"、"null"、"v:none" など、使えない型もある。

組み込みのオブジェクトメソッド
                                                       builtin-object-methods
empty()、len()、string() など、組み込み関数のいくつかはオブジェクトに対
して使うことができる。オブジェクトは、これらの組み込み関数と同じ名前のメソッド
を実装して、オブジェクト固有の値を返すことができる。

                                                        E1412
以下の組み込みメソッドがサポートされている:
                                                        object-empty()
    empty()  empty() 関数から、オブジェクトが空かどうかを確かめるために呼び
             出される。このメソッドがない場合は、true が返される。このメソッド
             は引数を受け取るべきではなく、ブール値を返さなければならない。
                                                        object-len()
    len()    len() 関数から、オブジェクトの長さを返すために呼び出される。ク
             ラスにこのメソッドがない場合は、エラーが出て、ゼロが返される。こ
             のメソッドは引数を受け取るべきではなく、数値を返さなければならな
             い。
                                                        object-string()
    string() string() 関数から、オブジェクトのテキスト表現を得るために呼び出
             される。オブジェクトに対する :echo コマンドでも使われる。クラス
             にこのメソッドがない場合は、組み込みのデフォルトのテキスト表現が
             使われる。このメソッドは引数を受け取るべきではなく、文字列を返さ
             なければならない。

                                                        E1413
クラスメソッドは、組み込みメソッドとして使うことはできない。

インターフェイスを定義する
                        interface Interface :interface :endinterface
インターフェイスは :interface と :endinterface の間で定義される。前に
:export を付けることができる:

        interface InterfaceName
        endinterface

        export interface InterfaceName
        endinterface
                                                        E1344
インターフェイスは、クラスと同じようにオブジェクト変数を宣言できるが、初期化子
は付けられない。
                                                        E1345
インターフェイスは :def でメソッドを宣言でき、引数と戻り値の型も含められる
が、本体と :enddef は付けられない。例:

        interface HasSurface
           var size: number
           def Surface(): number
        endinterface

インターフェイス名は大文字で始まらなければならない。 E1343
"Has" プリフィックスを使うと、これがインターフェイス名であると推測しやすくな
り、それが何を提供するのかのヒントにもなる。
インターフェイスは Vim9 script ファイルの中でのみ定義できる。 E1342
インターフェイスは、別のインターフェイスを "implement" することはできないが、
別のインターフェイスを "extend" することはできる。 E1381

null オブジェクト

変数がオブジェクトの型を持つと宣言されているが、初期化されていない場合、その値
は null である。この null オブジェクトを使おうとしたとき、Vim はどのクラスが使
われるはずだったのかを分からないことが多い。そのため Vim は変数名が正しいかど
うかを確かめることができず、変数名が無効な場合でも "Using a null object" エラー
になる。 E1360 E1362

デフォルトのコンストラクタ
                                                        default-constructor
new() メソッドを持たないクラスを定義した場合は、自動的に定義される。このデフォ
ルトのコンストラクタは、すべてのオブジェクト変数の引数を、それらが指定された順
に持つ。そのため、クラスが次のようになっている場合:

        class AutoNew
           var name: string
           var age: number
           var gender: Gender
        endclass

デフォルトのコンストラクタはこうなる:

        def new(this.name = v:none, this.age = v:none, this.gender = v:none)
        enddef

"= v:none" というデフォルト値により、引数は省略可能になる。そのため、引数なし
で new() を呼ぶこともできる。代入は行われず、オブジェクト変数のデフォルト値
が使われる。これは、デフォルト値を使った、より役に立つ例である:

        class TextPosition
           var lnum: number = 1
           var col: number = 1
        endclass

コンストラクタに必須の引数を持たせたい場合は、自分で書く必要がある。例えば、上
の AutoNew クラスで名前の取得を必須にしたい場合は、コンストラクタをこのように
定義できる:

        def new(this.name, this.age = v:none, this.gender = v:none)
        enddef

デフォルトの new() メソッドを使っている場合、後でクラス内のオブジェクト変数の
順序が変わると、デフォルトの new() メソッドの呼び出し元をすべて変更する必要が
ある。これを避けるために、new() メソッドを引数なしで明示的に定義することができ
る。

                                                        E1328
Note ここでは "v:none" 以外のデフォルト値を使えないことに注意。オブジェクト変
数を初期化したい場合は、それらが宣言されている場所で行うこと。こうすれば、デ
フォルト値を見るのは 1 か所だけで済む。

protected アクセスのものを含め、すべてのオブジェクト変数がデフォルトのコンスト
ラクタで使われる。

クラスが別のクラスを拡張している場合は、そのクラスのオブジェクト変数が最初に来
る。


複数のコンストラクタ
                                                multiple-constructors
通常、クラスにはただ 1 つの new() コンストラクタがある。コンストラクタがしばし
ば同じ引数で呼ばれることが分かった場合は、それらの引数を 2 つ目のコンストラク
タメソッドにまとめて、コードを単純にしたいと思うかもしれない。例えば、黒色をよ
く使う場合:

        def new(this.garment, this.color, this.size)
        enddef
        ...
        var pants = new(Garment.pants, Color.black, "XL")
        var shirt = new(Garment.shirt, Color.black, "XL")
        var shoes = new(Garment.shoes, Color.black, "45")

毎回色を繰り返す代わりに、それを含んだコンストラクタを追加できる:

        def newBlack(this.garment, this.size)
           this.color = Color.black
        enddef
        ...
        var pants = newBlack(Garment.pants, "XL")
        var shirt = newBlack(Garment.shirt, "XL")
        var shoes = newBlack(Garment.shoes, "9.5")

Note メソッド名は "new" で始まらなければならないことに注意。"new()" という名前
のメソッドがない場合は、他のコンストラクタメソッドがあっても、デフォルトのコン
ストラクタが追加される。

オブジェクトに変数の型 "any" を使う
                                                        obj-var-type-any
型 "any" で宣言された変数を使って、オブジェクトを保持することができる。例:

    vim9script
    class A
        var n = 10
        def Get(): number
            return this.n
        enddef
    endclass

    def Fn(o: any)
        echo o.n
        echo o.Get()
    enddef

    var a = A.new()
    Fn(a)

この例では、Vim はコンパイル時に関数 Fn() の引数 "o" の型を決定できない。それ
は Dict か Object の値のどちらかでありうる。そのため、実行時に型が分かった
ときに、オブジェクトのメンバー変数とメソッドが検索される。この処理は効率的では
ないので、より良い効率のために、可能な場合はいつでもより具体的な型を使うことを
勧める。

クラス内のメソッドをコンパイルする
                                                        class-compile
:defcompile コマンドを使って、クラスで定義されたすべてのクラスメソッドとオブ
ジェクトメソッドをコンパイルできる:

        defcompile MyClass      # クラス "MyClass" をコンパイルする
        defcompile              # 現在のスクリプト内のクラスをコンパイルする

7.  型定義                                      typealias Vim9-type :type

                                                E1393 E1396 E1397 E1398
型定義とは、型の指定に名前を付けることである。これは「型エイリアス」としても知
られている。型エイリアスは、組み込みの型を使えるところではどこでも使うことがで
きる。例:

    type ListOfStrings = list<string>
    var s: ListOfStrings = ['a', 'b']

    def ProcessStr(str: ListOfStrings): ListOfStrings
        return str
    enddef
    echo ProcessStr(s)

                                                        E1394
型エイリアスの名前は大文字で始まらなければならない。既存の型だけに別名を付ける
ことができる。

                                                        E1399
型エイリアスはスクリプトレベルでのみ作ることができ、関数の中では作れない。型エ
イリアスはエクスポートして、スクリプト間で使うことができる。

                                                        E1403 E1407
型エイリアスは式として使えない。型エイリアスは代入の左辺で使えない。

型エイリアスの名前に対しては、typename() 関数は別名が付けられた型を返す:

    type ListOfStudents = list<dict<any>>

8.  列挙型                                      Vim9-enum :enum :endenum

                                                enum E1418 E1419 E1420
列挙型は、値のリストのうち 1 つを持つことができる型である。例:

    enum Color
        White,
        Red,
        Green, Blue, Black
    endenum

                                                enumvalue E1422 E1428
列挙値はコンマで区切られる。1 行に複数の列挙値を並べることができる。最後の列挙
値の後にはコンマを付けるべきではない。重複した列挙値は許されない。

列挙値には、列挙型の名前に続けて値の名前を書いてアクセスする:

    var a: Color = Color.Blue

列挙型はクラスとして扱われ、各列挙値は本質的にそのクラスのインスタンスである。
new() メソッドによる通常のオブジェクトのインスタンス化とは異なり、列挙型のイ
ンスタンスをこの方法で作ることはできない。

列挙型は Vim9 script ファイルの中でのみ定義できる。   E1414
列挙型は関数の中では定義できない。                      E1435

                                                        E1415
列挙型の名前は大文字で始まらなければならない。列挙型の中の列挙値の名前は、大文
字でも小文字でも始めることができる。

                                                        E1416
列挙型はインターフェイスを実装できるが、クラスを拡張することはできない:

    enum MyEnum implements MyIntf
        Value1,
        Value2

        def SomeMethod()
        enddef
    endenum

                                                        enum-constructor
列挙型の中の列挙値のオブジェクトは、他のオブジェクトと同様に new() メソッド
を使って構築される。関数を呼ぶのと同じように、列挙値の名前の後に引数を指定する
ことで、列挙型のコンストラクタに引数を渡すことができる。デフォルトのコンストラ
クタは引数を持たない。

                                                        E1417
列挙型には、クラス変数、クラスメソッド、オブジェクト変数、オブジェクトメソッド
を含めることができる。列挙型の中のメソッドは :abstract メソッドにすることは
できない。

以下の例は、オブジェクト変数とメソッドを持つ列挙型を示している:

    vim9script
    enum Planet
        Earth(1, false),
        Jupiter(95, true),
        Saturn(146, true)

        var moons: number
        var has_rings: bool
        def GetMoons(): number
            return this.moons
        enddef
    endenum
    echo Planet.Jupiter.GetMoons()
    echo Planet.Earth.has_rings

                                                E1421 E1423 E1424 E1425
列挙型とその値は変更できない。それらを数値型や文字列型として使用することはでき
ない。列挙値は変更可能なインスタンス変数を宣言できる。

                                                enum-name E1427
各列挙値のオブジェクトは、列挙値の名前を含む "name" インスタンス変数を持つ。こ
れは読み取り専用の変数である。

                                                enum-ordinal E1426
各列挙値には、0 から始まる序数が関連付けられている。列挙値の序数には、
"ordinal" インスタンス変数を使ってアクセスできる。これは読み取り専用の変数であ
る。Note 列挙型の中の列挙値の順序を変えると、それらの序数も変わることに注意。

                                                enum-values
列挙型のすべての値には、列挙型のオブジェクトのリストである "values" クラス変数
を使ってアクセスできる。これは読み取り専用の変数である。

例:
    enum Planet
        Mercury,
        Venus,
        Earth
    endenum

    echo Planet.Mercury
    echo Planet.Venus.name
    echo Planet.Venus.ordinal
    for p in Planet.values
        # ...
    endfor

列挙型は、列挙値のオブジェクトのためのクラス変数と、列挙値の名前と列挙値の序数
のためのオブジェクト変数を持つクラスである:

    enum Planet
        Mercury,
        Venus
    endenum

上の列挙型の定義は、以下のクラス定義と同等である:

    class Planet
      public static final Mercury: Planet = Planet.new('Mercury', 0)
      public static final Venus: Planet = Planet.new('Venus', 1)

      public static const values: list<Planet> = [Planet.Mercury, Planet.Venus]

      public const name: string
      public const ordinal: number
    endclass

列挙型は、通常のクラスと同じように、オブジェクト変数とメソッドを含むことができ
る:

    enum Color
        Cyan([0, 255, 255]),
        Magenta([255, 0, 255]),
        Gray([128, 128, 128])

        var rgb_values: list<number>

        def Get_RGB(): list<number>
            return this.rgb_values
        enddef
    endenum
    echo Color.Magenta.Get_RGB()

9.  設計意図

Vim9 のクラスについての選択のほとんどは、Java、TypeScript、Dart のような、人
気があり最近開発された言語から来ている。構文は、クラス全体を波括弧で囲む代わり
に endclass を使うなど、Vim script の動作に合うように作られている。

オブジェクト指向言語の一般的な構文要素のいくつかは、この種のプログラミングがま
だ新しかったずっと昔に選ばれ、後で最適ではないことが分かった。その時までには、
それらの構文要素は広く使われており、変更することは選択肢になかった。Vim では、
クラスは完全に新しいので、異なる選択をする自由がある。「古い」言語が使っている
ものより、構文を単純で一貫したものにすることができる。あまり逸脱することなく、
既存の言語で知っているものとほぼ同じように見えるべきである。

最近開発された言語の中には、Vim には必要ない、あらゆる種類のしゃれた機能を追加
しているものがある。しかし、ぜひ使いたい良いアイデアを持つものもある。
そのため、人気のある言語で一般的なものを基にし、悪いアイデアに見えるものを取り
除き、分かりやすいいくつかの良い機能を追加することになる。

判断を下すのに使う主なルール:
- 単純に保つ。
- 驚きをなくし、ほとんどは他の言語がしていることをする。
- 過去の誤りを避ける。
- スクリプトを書く人が、動作を理解するためにヘルプを調べる必要がないようにす
  る。ほとんどのことは明白であるべきである。
- 一貫性を保つ。
- 巨大なプロジェクトではなく、平均的なサイズのプラグインを目指す。


コンストラクタに new() を使う

多くの言語は、コンストラクタメソッドにクラス名を使う。欠点は、これがかなり長い
名前になることがよくあることである。また、クラス名を変更するときは、すべてのコ
ンストラクタメソッドの名前を変更する必要がある。大したことではないが、それでも
欠点である。

TypeScript のような他の言語は、"constructor()" のような特定の名前を使う。その
ほうが良いように思える。しかし、新しいオブジェクトを作るのに "new" や "new()"
を使うことは、"constructor()" と明白な関係がない。

Vim9 script では、すべてのコンストラクタに同じメソッド名を使うことが正しい選
択に思えた。また、それを new() と呼ぶことで、呼び出し側と呼び出されるメソッド
の関係が明白になる。

コンストラクタのオーバーロードはない

Vim script では、旧来のものも Vim9 script も、メソッドのオーバーロードはな
い。つまり、同じメソッド名を異なる型の引数で使うことはできない。そのため、new()
コンストラクタも 1 つしかない。

Vim9 script では、引数に型があるので、オーバーロードをサポートすることも可能
だろう。しかし、これはすぐにとても複雑になる。new() の呼び出しを見たとき、複数
の new() メソッドのうちどれが実際に呼ばれているかを知るには、引数の型を調べな
ければならない。そして、それにはかなりの量のコードを調べる必要があるかもしれな
い。例えば、引数の 1 つがメソッドの戻り値である場合、そのメソッドがどんな型を
返すのかを見るために、そのメソッドを見つける必要がある。

代わりに、すべてのコンストラクタは、"new" で始まる異なる名前を持たなければなら
ない。こうすれば、異なる引数を持つ複数のコンストラクタが可能になり、どのコンス
トラクタが使われているかもとても分かりやすい。そして、引数の型を適切にチェック
できる。

メソッドのオーバーロードはない

コンストラクタと同じ理由である: 引数がどんな型を持つのかが明白でないことがよく
あり、そのため実際にどのメソッドが呼ばれているかを理解するのが難しくなる。メ
ソッドに異なる名前を付けるほうが良い。そうすれば、型チェックによって意図したと
おりに動作することが確かめられる。これによりポリモーフィズムは除外されるが、ど
のみちそれは実際には必要ない。

単一継承とインターフェイス

多重継承をサポートする言語もある。それが役に立つ場合もあるが、クラスの動作の
ルールがかなり複雑になる。代わりに、インターフェイスを使って何がサポートされて
いるかを宣言するほうが、ずっと単純である。とても人気のある Java 言語はこの方法
を取っており、Vim にとっては十分なはずである。ここでは「単純に保つ」ルールが当
てはまる。

クラスがインターフェイスをサポートすることを明示的に宣言すると、クラスが何を意
図しているのかが分かりやすくなる。また、適切な型チェックをすることも可能にな
る。インターフェイスが変更されると、それを実装すると宣言しているクラスはすべ
て、その変更も変更されたかどうかがチェックされる。メソッドがたまたま一致してい
るというだけで、クラスがインターフェイスを実装しているとみなす仕組みは脆く、分
かりにくい問題を引き起こすので、そうしないことにしよう。

どこでも "this.variable" を使う

さまざまなプログラミング言語のオブジェクト変数には、場所によって異なる方法でア
クセスできることがよくある。あいまいさを避けるために "this." を前に付けなけれ
ばならないこともある。それらは通常 "this." なしで宣言される。
これはかなり一貫性がなく、時に混乱を招く。

とてもよくある問題は、コンストラクタで引数がオブジェクト変数と同じ名前を使うこ
とである。そうすると、本体ではこれらの変数には "this." を前に付ける必要がある
が、他の変数にはこれは必要なく、しばしば省略される。これにより、"this." がある
ものとないものとの変数が混在することになり、一貫性がない。

Vim9 のクラスでは、宣言されたメソッドと変数には常に "this." プリフィックスが
使われる。単純で一貫している。クラスの中のコードを見たときに、どの変数参照がオ
ブジェクト変数で、どれがそうでないかもすぐに分かる。

クラス変数を使う

クラス変数を宣言するのに "static variable" を使うのはとても一般的であり、ここ
に新しいものは何もない。Vim9 script では、これらには名前で直接アクセスでき
る。
これは、スクリプトローカル変数をメソッドの中で使うことができるのとよく似てい
る。オブジェクト変数には常に "this." を前に付けてアクセスするので、それがどん
な種類の変数なのかもすぐに分かる。

TypeScript は、クラスの中でも、クラス変数名の前にクラス名を付ける。これには 2
つの問題がある: クラス名がかなり長くなり、かなりの場所を取ることがある。また、
クラス名を変更すると、これらの場所もすべて変更する必要がある。

オブジェクト変数とクラス変数を宣言する

主な選択は、変数宣言と同じように "var" を使うかどうかである。TypeScript はそれ
を使わない:
        class Point {
          x: number;
          y = 0;
        }

それに従うと、Vim のオブジェクト変数はこのように宣言できる:
        class Point
          this.x: number
          this.y = 0
        endclass

これは宣言というより代入のように見えると指摘したユーザーもいる。"var" を追加
し、"this." を省略すると、それが変わる:
        class Point
          var x: number
          var y = 0
        endclass

"static" キーワードを使ってクラス変数を宣言できる必要もある。そこでも "var" を
省略することを選べる:
        class Point
          var x: number
          static count = 0
        endclass

または、"static" の前に、それを使う:
        class Point
          var x: number
          var static count = 0
        endclass

または、"static" の後に:
        class Point
          var x: number
          static var count = 0
        endclass

これは "static def Func()" とより合っている。

"var" を使うかどうかについて、明確な好みはない。それを省く主な理由は 2 つある:
1. TypeScript や他の人気のある言語はそれを使わない。
2. ごちゃごちゃしない。

しかし、言語では、一般的な変数宣言と関数宣言の構文を、クラス変数/オブジェクト
変数とメソッドに再利用するほうが一般的である。Vim9 も、メソッドに一般的な関数
宣言の構文を再利用している。そのため、一貫性のために、これらの宣言では "var"
を必須にする。

オブジェクトを構築するのに "ClassName.new()" を使う

多くの言語は、オブジェクトを作るのに "new" 演算子を使うが、これは実はちょっと
奇妙である。コンストラクタは、コマンドではなく、引数を持つメソッドとして定義さ
れるからである。TypeScript にも "new" キーワードがあるが、メソッドは
"constructor()" と呼ばれ、この 2 つの関係が分かりにくい。

Vim9 script では、コンストラクタメソッドは new() と呼ばれ、new() として呼び
出される。単純で分かりやすい。他の言語は "new ClassName()" を使うが、
ClassName() というメソッドはなく、ClassName というクラスの中にある別の名前のメ
ソッドである。かなり紛らわしい。


Vim9class のアクセスモード
                                                    vim9-access-modes
Vim9class がサポートする変数のアクセスモードとその意味は以下である
        public-variable       どこからでも読み書きできる
        read-only-variable    どこからでも読み取れ、クラスとサブクラスの中か
                                ら書き込める
        protected-variable    クラスとサブクラスの中から読み書きできる

メソッドのアクセスモードも同様だが、読み取り専用モードはない。


オブジェクト変数へのデフォルトの読み取りアクセス

オブジェクト変数のアクセスルールは非対称だと言うユーザーもいるだろう。それは意
図的なものである。値を変更することは、値を読み取ることとはとても異なる操作であ
る。読み取り操作には副作用がなく、オブジェクトに影響を与えることなく何度でも行
うことができる。値を変更することには多くの副作用がありうるし、波及効果を持ち、
他のオブジェクトに影響を与えることさえある。

オブジェクト変数を追加するとき、普通はこのことをあまり考えず、ただ型を正しくす
るだけである。そして通常、値は new() メソッドで設定される。そのため、デフォル
トを読み取りアクセスのみにすることは、ほとんどの場合「そのまま動く」。そして、
直接書き込むとエラーになり、本当にそれを許したいのかを考えさせられる。これは、
誤りの少ないコードを書く助けになる。


アンダースコアでオブジェクト変数を protected にする

オブジェクト変数が protected の場合、それはクラスの中 (とサブクラスの中) での
み読み取りと変更ができ、クラスの外では使えない。アンダースコアを前に付けること
は、それを見えるようにする単純な方法である。さまざまなプログラミング言語がこれ
を推奨している。

考えを変えて、オブジェクト変数をクラスの外からアクセスできるようにしたい場合
は、すべての場所でアンダースコアを取り除かなければならない。
名前はクラス (とサブクラス) の中にしか現れないので、見つけて変更するのは簡単だ
ろう。

逆はずっと難しい: クラスの中でオブジェクト変数の前にアンダースコアを付けて
protected にすることは簡単にできるが、他の場所での使用はすべて突き止めて変更し
なければならない。それを "set" メソッドの呼び出しにしなければならないかもしれ
ない。これは、アクセスを取り上げるには、そのアクセスが存在するすべての場所につ
いて作業が必要になるという、現実世界の問題を反映している。

"public" が逆方向にアクセスを変えるのと同じように、"protected" キーワードを使
うという選択肢もあっただろう。まあ、それは単にキーワードの数を減らすためであ
る。

private なオブジェクト変数はない

オブジェクト変数へのアクセスを制御する方法をいくつか提供する言語もある。
最もよく知られているのは "protected" で、その意味は言語によって異なる。他には
"shared"、"private"、"package"、さらには "friend" がある。

これらのルールは生活をより難しくする。多くの人が、誤りを犯しやすい同じ複雑な
コードに取り組むプロジェクトでは、それは正当化されうる。特に、リファクタリング
やクラスモデルの他の変更をするときにそうである。

Vim script は、1 人か小さなチームが取り組むプラグインの中で使われることが想定
されている。そうすると、複雑なルールはより複雑にするだけで、ルールが提供する追
加の安全性は実際には必要ない。単純に保ち、アクセスの詳細は指定しないことにしよ
う。
