52.1  エクスポートとインポート

Vim9 script は、大きな Vim script を書くのをより簡単にするために設計されまし
た。それは他のスクリプト言語、特に Typescript により似ています。また、関数は、
素早く実行できる命令にコンパイルされます。これにより、Vim9 script はずっと速く
なり、最大で 100 倍になります。

基本的な考え方は、スクリプトファイルには、private な、スクリプトファイルの中で
だけ使われる項目、およびエクスポートされた、それらをインポートするスクリプトが
使用できる項目がある、ということです。これにより、何がどこで定義されているかが
とても明確になります。

例から始めましょう。1 つの関数をエクスポートし、1 つの private 関数を持つスク
リプトです:

        vim9script

        export def GetMessage(count: string): string
           var nr = str2nr(count)
           var result = $'To {nr} we say '
           result ..= GetReply(nr)
           return result
        enddef

        def GetReply(nr: number): string
          if nr == 42
             return 'yes'
          elseif nr == 22
             return 'maybe'
          else
             return 'no'
          endif
        enddef

vim9script コマンドは必須で、export は Vim9 script の中でだけ動作します。

export def GetMessage(... の行は export で始まっており、これはこの関数が他
のスクリプトから呼び出せることを意味します。def GetReply(... の行は export
で始まっておらず、これはスクリプトローカル関数で、このスクリプトファイルの中で
だけ使えます。

次に、これがインポートされるスクリプトについてです。この例では、"pack" ディレ
クトリの下のプラグインでうまく動作する、このレイアウトを使います:
        .../plugin/theplugin.vim
        .../lib/getmessage.vim

"..." ディレクトリが 'runtimepath' に追加されていると仮定すると、Vim は
"plugin" ディレクトリでプラグインを探し、"theplugin.vim" を読み込みます。Vim
は "lib" ディレクトリを認識せず、そこには任意のスクリプトを置くことができます。

GetMessage() をエクスポートする上記のスクリプトは lib/getmessage.vim に入りま
す。GetMessage() 関数は plugin/theplugin.vim で使われます:

        vim9script

        import "../lib/getmessage.vim"
        command -nargs=1 ShowMessage echomsg getmessage.GetMessage(<f-args>)

import コマンドは相対パスを使っており、それは "../" で始まっています。これは
1 つ上のディレクトリに行くことを意味します。他の種類のパスについては :import
コマンドを参照してください。

プラグインが提供するコマンドをどのように試せるか:
        ShowMessage 1
        To 1 we say no

        ShowMessage 22
        To 22 we say maybe

関数 GetMessage() に、インポートされたスクリプト名 "getmessage" が前に付いてい
ることに注目してください。こうすることで、使われるインポートされた関数のすべて
について、それがどのスクリプトからインポートされたかがわかります。いくつかのス
クリプトをインポートする場合、それぞれが GetMessage() 関数を定義することができ
ます:

        vim9script

        import "../lib/getmessage.vim"
        import "../lib/getother.vim"
        command -nargs=1 ShowMessage echomsg getmessage.GetMessage(<f-args>)
        command -nargs=1 ShowOther echomsg getother.GetMessage(<f-args>)

インポートされたスクリプト名が長いか、または多くの場所でそれを使う場合、"as"
引数を追加することでそれを短くできます:
        import "../lib/getmessage.vim" as msg
        command -nargs=1 ShowMessage echomsg msg.GetMessage(<f-args>)


再読み込み

覚えておくべきことが 1 つあります: インポートされた "lib/getmessage.vim" スク
リプトは 1 回だけ読み込まれます。2 回目にインポートされたときは、その中の項目
はすでに作成されているので、読み込みはスキップされます。このインポートコマンド
が別のスクリプトにあるか、または再び読み込まれる同じスクリプトにあるかは関係あ
りません。

これはプラグインを使うときには効率的ですが、まだプラグインを開発しているとき
は、インポートされた後に "lib/getmessage.vim" を変更しても効果がないことを意味
します。Vim を終了して、再び起動する必要があります。(根拠: スクリプトで定義さ
れた項目はコンパイルされた関数で使われている可能性があり、スクリプトを再び読み
込むとそれらの関数が壊れることがあります)。


グローバルを使う

どこでも使えるように、グローバル変数または関数を使いたいことがあるでしょう。よ
い例は、プラグインに設定を渡すグローバル変数です。他のスクリプトが同じ名前を使
うのを避けるために、他の場所ではまず使われそうにないプリフィックスを使ってくだ
さい。例えば、"mytags" プラグインがある場合、次のように使えます:

        g:mytags_location = '$HOME/project'
        g:mytags_style = 'fast'

52.2  オートロード

大きなスクリプトを分割した後、インポートされたスクリプトは、インポートするスク
リプトが読み込まれた時点で読み込まれ、実行されます。すべての :import は、そ
こで定義された項目を見つけるためにインポートされたスクリプトを読み込みます。し
かし、インポートされたスクリプトが大きい場合、起動時間が目に見えて遅くなること
がありますが、その一方で、エラーがある場合、それらはインポート時に検出されま
す。

長い起動時間を避けるために、インポートされたスクリプトの読み込みを、実際に必要
になるまで遅らせることができます。これは autoload キーワードで行います。上の
例を使うと、plugin/theplugin.vim で必要な変更は 1 つだけです:

        import autoload "../lib/getmessage.vim"

スクリプトの残りの部分は何も変更する必要はありません。しかし、型はチェックされ
ず、"../lib/getmessage.vim" はインポート時に読み込まれません。Vim は、ファイル
が存在して読み込み可能であることだけを検証します。GetMessage() 関数の存在さえ
も、それが使われるまではチェックされません。結果として、"getmessage.vim" スク
リプトのエラーは実行時にだけ検出されます。

あなたのスクリプトにとって何がより重要かを決める必要があります: 速い起動か、ま
たはエラーを早く得ることか。

実用的な戦略は、開発およびデバッグの間は autoload キーワードを省いてエラーが
すぐに報告されるようにし、それからあなたのプラグインを配布する前に、起動性能を
改善するためにそれを戻すことです。


autoload ディレクトリ

スクリプトを遅延して読み込む別の方法は、以下の例のように、相対パスまたは絶対パ
スを指定せずにスクリプトを import autoload することです:

        import autoload "monthlib.vim"

Vim は 'runtimepath' の下の "autoload" ディレクトリでスクリプトを探します。こ
れは、スクリプトが "autoload" フォルダーに置かれていなければならないことを意味
します。Unix システムでは、そのようなディレクトリの 1 つは、多くの場合
~/.vim/autoload です。'packpath' の下の "start" の下も探します。

スクリプトがこの方法でインポートされた場合、そのエクスポートされたシンボルは、
インポートするスクリプトにローカルなままになるのではなく、グローバルなオート
ロード名前空間を通して参照されます。

Vim は 'runtimepath' 内のすべての "autoload" ディレクトリを探すので、一意なス
クリプト名を選んでください。プラグインマネージャーはしばしば複数のディレクトリ
を 'runtimepath' に追加し、そのそれぞれが "autoload" ディレクトリを含んでいる
かもしれません。

import autoload の 2 つの形式は、以下のようにまとめられます:

- import autoload "foo.vim"
  Vim はスクリプトを 'runtimepath' で探す。そのようなスクリプトは "autoload"
  ディレクトリの下に置かれなければならないので、エクスポートされたシンボルはグ
  ローバルなオートロード名前空間を通して使用可能である。

- import autoload "/some/path/foo.vim"
  解決されたパスが "autoload" ディレクトリの下にある場合、エクスポートされたシ
  ンボルは同様にグローバルなオートロード名前空間にあり、そうでない場合、イン
  ポートするスクリプトにローカルなままである。

グローバルなオートロード名前空間を通してシンボルにアクセスすることの主な利点
は、スクリプトを他のスクリプトから簡単にインポートでき、シンボルをすぐに使える
ことです。しかし、これにはスクリプトを再読み込みするときにいくつかの欠点があり
ます。詳しくは vim9-reload を参照してください。

シンボルがスクリプトローカルなスコープにあるときは、スクリプト間でそれらを共有
することはより複雑で、一般的な規則はありません: 正しいアプローチはプラグインの
レイアウトによります。

最後に、以下の例のように、スクリプトが autoload なしで、およびパスなしでイン
ポートされたとき:
        import "monthlib.vim"

Vim は 'runtimepath' の import ディレクトリでスクリプト "monthlib.vim" を探し
ます。

この場合、autoload キーワードを追加または削除すると、Vim がスクリプトを探す
場所が変わります。相対パスまたは絶対パスが使われている場合、場所は変わりませ
ん。

52.3  インポート/エクスポートなしでのオートロード

                                                write-library-script
インポート/エクスポート以前からの仕組みはまだ便利で、一部のユーザーはそれのほ
うが少しシンプルだと感じるかもしれません。考え方は、特別な名前の関数を呼び出
す、ということです。その関数は、オートロードスクリプトの中にあります。その 1
つのスクリプトをライブラリスクリプトと呼ぶことにします。

オートロードの仕組みは、"#" 文字を含む関数名に基づいています:

        mylib#myfunction(arg)

Vim は埋め込まれた "#" 文字によってその関数名を認識し、それがまだ定義されてい
ないときは、'runtimepath' でスクリプト "autoload/mylib.vim" を探します。そのス
クリプトは "mylib#myfunction()" 関数を定義しなければなりません。明らかに、名前
"mylib" は "#" の前の部分であり、".vim" を付け加えてスクリプトの名前として使わ
れます。

mylib.vim スクリプトには他の多くの関数を入れることができ、ライブラリスクリプト
の中であなたの関数を自由に整理できます。しかし、'#' の前の部分がスクリプト名と
一致する関数名を使わなければなりません。そうしないと、Vim はどのスクリプトを読
み込むかがわからないでしょう。ここがインポート/エクスポートの仕組みと異なる点
です。

本当に熱中してたくさんのライブラリスクリプトを書く場合、サブディレクトリを使い
たくなるかもしれません。例:

        netlib#ftp#read('somefile')

ここでは、スクリプト名は関数名の最後の "#" までから取られます。途中の "#" はス
ラッシュに、最後のものは ".vim" に置き換えられます。したがって、
"netlib/ftp.vim" が得られます。Unix では、このために使われるライブラリスクリプ
トは次のようになります:

        ~/.vim/autoload/netlib/ftp.vim

そこで、関数は次のように定義されます:

        def netlib#ftp#read(fname: string)
                #  ファイル fname を ftp で読み込む
        enddef

関数が定義されるときの名前は、関数を呼び出すために使われる名前とまったく同じで
あることに注目してください。そして、最後の '#' の前の部分は、サブディレクトリ
およびスクリプト名とちょうど一致します。

同じ仕組みを変数にも使えます:

        var weekdays = dutch#weekdays

これはスクリプト "autoload/dutch.vim" を読み込みます。それには次のようなものが
含まれているはずです:

        var dutch#weekdays = ['zondag', 'maandag', 'dinsdag', 'woensdag',
                \ 'donderdag', 'vrijdag', 'zaterdag']

さらなる情報: autoload。

52.4  使用する他の仕組み

複数のファイルを使うのを面倒に思い、すべてを 1 つのスクリプトにまとめておくこ
とを好む人もいるでしょう。これにより起動が遅くなるのを避けるために、小さな部分
だけを定義し、残りを実際に使われるときまで延期する仕組みがあります。
write-plugin-quickload

基本的な考え方は、プラグインが 2 回読み込まれるということです。1 回目は、機能
を提供するユーザーコマンドおよびマッピングが定義されます。2 回目は、機能を実装
する関数が定義されます。

クイックロードがスクリプトを 2 回読み込むことを意味するというのは、驚くように
聞こえるかもしれません。私たちが意味しているのは、1 回目は素早く読み込み、スク
リプトの大部分を 2 回目に延期するということで、2 回目は実際にそれを使うときに
だけ起こります。常にその機能を使う場合、実際には遅くなります!

これは FuncUndefined 自動コマンドを使います。これは上で説明した autoload の
機能とは異なる動作をします。

以下の例は、それがどのように行われるかを示します:

        " クイックロードを実演するための Vim グローバルプラグイン
        " Last Change:  2005 Feb 25
        " Maintainer:   Bram Moolenaar <Bram@vim.org>
        " License:      このファイルはパブリックドメインに置かれている。

        if !exists("s:did_load")
                command -nargs=* BNRead  call BufNetRead(<f-args>)
                map <F19> :call BufNetWrite('something')<CR>

                let s:did_load = 1
                exe 'au FuncUndefined BufNet* source ' .. expand('<sfile>')
                finish
        endif

        function BufNetRead(...)
                echo 'BufNetRead(' .. string(a:000) .. ')'
                " 読み込み機能をここに
        endfunction

        function BufNetWrite(...)
                echo 'BufNetWrite(' .. string(a:000) .. ')'
                " 書き込み機能をここに
        endfunction

スクリプトが最初に読み込まれるとき、"s:did_load" は設定されていません。"if" と
"endif" の間のコマンドが実行されます。これは :finish コマンドで終わるので、
スクリプトの残りは実行されません。

2 回目にスクリプトが読み込まれるとき、"s:did_load" が存在し、"endif" の後のコ
マンドが実行されます。これにより、(長いかもしれない) BufNetRead() および
BufNetWrite() 関数が定義されます。

このスクリプトをあなたのプラグインディレクトリに置いた場合、Vim は起動時にそれ
を実行します。これが起こるイベントの順序です:

1. スクリプトが起動時に読み込まれるとき、"BNRead" コマンドが定義され、<F19>
   キーがマップされる。FuncUndefined 自動コマンドが定義される。":finish" コ
   マンドにより、スクリプトは早く終了する。

2. ユーザーが BNRead コマンドをタイプするか、または <F19> キーを押す。
   BufNetRead() または BufNetWrite() 関数が呼ばれる。

3. Vim はその関数を見つけられず、FuncUndefined 自動コマンドイベントを発生さ
   せる。パターン "BufNet*" は呼び出された関数にマッチするので、コマンド
   "source fname" が実行される。"fname" は、それがどこにあるかに関係なく、スク
   リプトの名前と同じになる。それは "<sfile>" を展開したもの (expand() を参
   照) だからである。

4. スクリプトが再び読み込まれ、"s:did_load" 変数が存在し、関数が定義される。

後で読み込まれる関数は FuncUndefined 自動コマンドのパターンにマッチすること
に注目してください。他のプラグインがこのパターンにマッチする関数を定義しないこ
とを確認する必要があります。

52.5  旧来のスクリプトから Vim9 script を使う         source-vim9-script

場合によっては、Vim9 script の項目を使いたい旧来の Vim script があります。例え
ば、あなたの .vimrc でプラグインを初期化したいとします。これを行う最もよい方法
は、:import を使うことです。例えば:

        import 'myNicePlugin.vim'
        call myNicePlugin.NiceInit('today')

これは Vim9 script ファイル内のエクスポートされた関数 "NiceInit" を見つけ、そ
れをスクリプトローカルな項目 "myNicePlugin.NiceInit" として使用可能にします。
:import は、"s:" が指定されていないときでも、常にスクリプト名前空間を使いま
す。"myNicePlugin.vim" がすでに読み込まれている場合、再び読み込まれることはあ
りません。

グローバル名前空間に項目を置くことを避ける (そこでは名前の衝突が予期しないエ
ラーを引き起こすことがある) ことに加えて、これは、そこから項目が何回インポート
されても、スクリプトが 1 回だけ読み込まれることも意味します。

場合によっては、例えばテストのために、単に Vim9 script を読み込みたいこともあ
るでしょう。それは OK ですが、その場合はグローバルな項目だけが使用可能になりま
す。Vim9 script は、これらのグローバルな項目に一意な名前を使うようにする必要が
あります。例:
        source ~/.vim/extra/myNicePlugin.vim
        call g:NicePluginTest()

52.6  Vim9 の例: コメントとハイライトヤンクプラグイン

コメントパッケージ

Vim には、Vim9 script で書かれたコメントプラグインが付属しています。
comment-install
$VIMRUNTIME/pack/dist/opt/comment/ にあるパッケージを見てください

ハイライトヤンクプラグイン

Vim には、Vim9 script で書かれた highlight-yank プラグインが付属しています
hlyank-install、ここに簡略化された実装があります:

        vim9script

        def HighlightedYank(hlgroup = 'IncSearch', duration = 300, in_visual = true)
          if v:event.operator ==? 'y'
            if !in_visual && visualmode() != null_string
              visualmode(1)
              return
            endif
            var [beg, end] = [getpos("'["), getpos("']")]
            var type = v:event.regtype ?? 'v'
            var pos = getregionpos(beg, end, {type: type, exclusive: false})
            var m = matchaddpos(hlgroup, pos->mapnew((_, v) => {
              var col_beg = v[0][2] + v[0][3]
              var col_end = v[1][2] + v[1][3] + 1
              return [v[0][1], col_beg, col_end - col_beg]
            }))
            var winid = win_getid()
            timer_start(duration, (_) => m->matchdelete(winid))
          endif
        enddef

        autocmd TextYankPost * HighlightedYank()

完全な例については、$VIMRUNTIME/pack/dist/opt/hlyank/ にあるパッケージを見て
ください
