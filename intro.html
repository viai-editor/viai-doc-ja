1. はじめに                                             intro

ViAI は Vim の改変版である。viai を参照。このマニュアルの残りの部分は、Vim
に言及している箇所でも、ViAI に適用される。

Vim は Vi IMproved を表す。以前は Vi IMitation だったが、非常に多くの改良があっ
たため、名前の変更が適切だった。Vim は、Unix のプログラム "Vi" のほとんど全て
のコマンドおよび多数の新しいコマンドを含むテキストエディタである。プログラムお
よび他のプレーンテキストを編集するのにとても便利である。
   全てのコマンドはキーボードで与えられる。これには、指をキーボードに、目を画
面に置いたままにできるという利点がある。それを望む人のために、マウスサポートお
よびスクロールバーおよびメニュー付きの GUI 版がある (gui.txt を参照)。

このマニュアルの概要は、ファイル "help.txt"、help.txt にある。Vim の中から
<Help> キーまたは <F1> キーで、および :help コマンドで参照できる (縦棒または
引用符を付けずに、単に ":help" とタイプする)。
   'helpfile' オプションは、ヘルプファイルがデフォルトの場所に置かれていない場
合に備えて、ヘルプファイルの名前に設定できる。タグと同じように主題にジャンプで
きる: カーソル下の主題にジャンプするには CTRL-] を使用し、戻るには CTRL-T を使
用する。

Vi と Vim の間の違いは vi_diff.txt に記載されている。

このマニュアルは様々なマシン上の Vim について述べている。異なるコンピュータと
端末の間で小さな違いがあるかもしれない。このドキュメントで述べられている注意に
加え、サポートされている各システムに対して個別のドキュメントがある。
sys-file-list を参照。

                                                        pronounce
ViAI は "vee-eye" と発音する。viai を参照。ViAI の GUI 版は "GViAI" と書く。
Vim は Jim と同様に 1 つの単語として発音し、vi-ai-em とは発音しない。名前であ
るため、これも Jim と同様に、大文字で書き始める。Vim の GUI 版は "gVim" と書く
(または文の先頭では "GVim")。

このマニュアルは Vim の全てのコマンドおよびオプションのリファレンスである。こ
れは Vi または Vim の使い方の入門ではなく、ところどころ少し複雑になっている。
初心者のためには、実践的な tutor がある。Vim の使い方を学ぶには、ユーザーマ
ニュアル usr_toc.txt を読むこと。

                                                        book books
Vi および Vim に関するほとんどの本には、初心者向けの節がある。他の本は、特定の
機能により多くの言葉を費やしている。Vim の本の概要はここで見つけられる:
        http://iccf-holland.org/vim_books.html

バグ報告:                               bugs bug-reports bugreport.vim

                                                        viai-bugs
ViAI のバグがどのように扱われるかは、それがどこで起きるかによる:
- ViAI でのみ起きるバグ: 報告するには、ViAI のリポジトリで issue を開くこと:
        https://github.com/viai-editor/viai/issues
  メンテナーがプルリクエストによって ViAI で修正する。
- Vim でも起きるバグ: 報告するには、ViAI のリポジトリで issue を開くこと。メン
  テナーが ViAI で修正し、Vim に報告する。後で Vim が修正した時、ViAI は Vim
  の修正を取り込む。
- Vim でのみ起きるバグ: 以下で説明するように Vim に報告すること。

Vim にバグを報告するには 3 つの方法がある:
1. ランタイムファイルの問題については、メールアドレスまたはメンテナーに報告す
   る他の何らかの方法をヘッダーで探すこと。
2. GitHub で issue を開く: https://github.com/vim/vim/issues
   テキストは vim-dev メーリングリストに転送される。
3. バグ報告の送り先: Vim Developers <vim-dev@vim.org>
   これはメーリングリストであり、まずメンバーになる必要があり、多くの人がメッ
   セージを見ることになる。例えばセキュリティの問題であるためにそれを望まない
   場合は、現在の Vim のメンテナーにメールアドレス
   <vim-security@googlegroups.com> で連絡するか、または Github でセキュリティ
   アドバイザリを作成すること:
   https://github.com/vim/vim/security/advisories

手短にすること。メールへの返答に費やされる全ての時間は、Vim の改良に費やされる
時間から差し引かれるのだ! 常に再現可能な例を示し、どの設定または他の物事がバグ
を引き起こすのかを見つけるようにすること。

できれば、以下のように Vim を起動すること:
        vim --clean -u reproduce.vim
ここで reproduce.vim は問題を再現するスクリプトである。関係がある場合は、異な
るマシンで試すこと (これはもしかすると MS-Windows 固有のバグか?)。

できる場合はパッチを送ること! https://github.com/vim/vim でプルリクエストを作
成した場合、自動チェックが実行され、何らかの明らかな問題が報告される。しかし、
パッチをメールで送ることもできる (空白の変更を避けるため、添付ファイルを使用す
ること)。

使用している Vim のバージョンおよびあなたのセットアップについての情報を含める
と役立つ。その情報はこのコマンドで取得できる:
   :so $VIMRUNTIME/bugreport.vim
これにより、カレントディレクトリに、あなたの環境についての多くの情報を含むファ
イル "bugreport.txt" が作成される。これを送る前に、機密情報が含まれていないか
確認すること!

Vim がクラッシュする場合は、どこでクラッシュするのかを見つけるようにすること。
これについてのヘルプはここにある: debug.txt。

疑わしい場合、または問題がすでに修正されているかどうか知りたいがその修正が見つ
からない場合は、vim-dev メーリングリストのメンバーになり、そこで質問すること。
maillist

                                                        year-2000 Y2K
Vim は内部で編集に日付を使用しないので、心配すべき 2000 年問題はない。Vim は
1970年1月1日からの秒数の形式で時刻を使用する。これは編集中のファイルおよびス
ワップファイルのタイムスタンプのチェックに使用されるが、これは致命的なものでは
なく、警告メッセージが出るだけのはずである。

秒数が 32 ビットの int に収まらなくなった時、2038 年問題があるかもしれない。こ
れはコンパイラ、ライブラリ、およびオペレーティングシステムに依存する。具体的に
は、time_t および ctime() 関数が使用されている。そして、time_t はスワップファ
イルに 4 バイトで格納される。しかし、それはリカバリのためにファイルの日付/時刻
を表示するのにだけ使用され、通常の編集に影響することは決してない。

Vim の strftime() 関数は、システム関数 strftime() を直接使用する。localtime()
はシステム関数 time() を使用する。getftime() はシステム関数 stat() が返す時刻
を使用する。システムのライブラリが 2000 年対応である場合、Vim も対応している。

ユーザーは、外部コマンドを使用する Vim のスクリプトを作成するかもしれない。そ
れらは Y2K 問題を持ち込むかもしれないが、それは実際には Vim 自体の一部ではな
い。

4. 表記法                                               notation

構文ハイライトを使用してこれを読む時、文字どおりにタイプされないテキストは、し
ばしば Special グループでハイライトされる。これらは []、{} および <> の中の項
目、および CTRL-X である。

Note Vim はコマンドで全ての可能な文字を使用することに注意。[]、{} および <> が
タイプするものの一部であることもあるが、それは文脈から明らかになるはずである。


[]              角括弧内の文字は省略可能である。

                                                    count [count]
[count]         コマンドを倍にするか、または繰り返すためにコマンドの前に置くこ
                とができる、省略可能な数値。数値が与えられない場合、特に断りが
                ない限り、1 のカウントが使用される。Note このマニュアルでは、
                [count] はコマンドの記述では言及されず、説明でのみ言及されるこ
                とに注意。これはコマンドを探しやすくするためである。'showcmd'
                オプションがオンの場合、(部分的に) 入力されたカウントがウィン
                ドウの下端に表示される。最後の桁を消すには <Del> を使用できる
                (N<Del>)。

                                                        [quotex]
["x]            テキストを格納できる、省略可能なレジスタ指定。registers を参
                照。x は 'a' と 'z' の間、または 'A' と 'Z' の間の 1 文字、ま
                たは '"' であり、場合によっては (put コマンドで) '0' と '9' の
                間、'%'、'#'、またはその他である。大文字および小文字は同じレジ
                スタを指定するが、小文字は以前のレジスタの内容を上書きするのに
                使用され、一方、大文字は以前のレジスタの内容に追加するのに使用
                される。""x" なしの場合、または """" を付けた場合、格納される
                テキストは無名レジスタに入れられる。

                                                        {}
{}              中括弧は、必ず現れるが、いくつかの異なる値をとり得るコマンドの
                部分を示す。Vim と Vi の間の違いも中括弧で示される (これは文脈
                から明らかになる)。

                                                        {char1-char2}
{char1-char2}   char1 から char2 までの範囲の 1 文字。例えば: {a-z} は小文字で
                ある。複数の範囲を連結できる。例えば、{a-zA-Z0-9} は任意の英数
                字である。

                                                {motion} movement
{motion}        カーソルを移動するコマンド。これらは motion.txt で説明されて
                いる。例:
                        w               次の単語の先頭へ
                        b               現在の単語の先頭へ
                        4j              4 行下へ
                        /The<CR>        次の "The" の出現位置へ
                これは operator コマンドの後で、操作されるテキストを越えて移
                動するのに使用される。
                - モーションがカウントを含み、オペレータもカウントを持つ場合、
                  2 つのカウントは掛け合わされる。例えば: "2d3w" は 6 つの単語
                  を削除する。
                - モーションは後方でもよい。例えば、単語の先頭まで削除する
                  "db"。
                - モーションはマウスクリックでもよい。ただし、マウスは全ての端
                  末でサポートされているわけではない。
                - オペレータが保留中の間に文字をマップするのに、":omap" コマン
                  ドを使用できる。
                - カーソルを移動するのに Ex コマンドを使用できる。これは、何ら
                  かの複雑なモーションを行う関数を呼び出すのに使用できる。モー
                  ションは、どの ":" コマンドが使用されても、常に文字単位の排
                  他的である。これは、改行なしで行の最後の文字を含めることは不
                  可能であることを意味する ('virtualedit' が設定されていない限
                  り)。
                  Ex コマンドがオペレータの開始位置より前のテキストを変更する
                  か、または別のバッファにジャンプする場合、結果は予測できな
                  い。さらに下のテキストを変更することは可能である。カレント
                  バッファがアンロードされない場合、別のバッファへジャンプする
                  ことは可能である。

                                                        {Visual}
{Visual}        選択されたテキスト領域。"v"、"V"、または CTRL-V コマンドで開始
                され、その後、任意のカーソル移動コマンドを使用して、選択された
                テキストの終わりを変更できる。
                これは operator コマンドの前に、操作されるテキストをハイライ
                トするのに使用される。
                Visual-mode を参照。

                                                        <character>
<character>     修飾キーを付けてもよい、以下の表の特殊文字、または修飾キー付き
                の 1 つの ASCII 文字。

                                                        'character'
'c'             1 つの ASCII 文字。

                                                        CTRL-{char}
CTRL-{char}     コントロール文字としてタイプされた {char}。つまり、CTRL キーを
                押したまま {char} をタイプする。{char} の大文字小文字は関係な
                い。したがって CTRL-A と CTRL-a は等価である。しかし、一部の端
                末では SHIFT キーを使用すると別のコードが生成されるので、その
                場合は使用しないこと。

                                                        'option'
'option'        値を設定できるオプション、またはパラメータは、単一引用符で囲ま
                れる。options を参照。

                                                        quotecommandquote
"command"       タイプできるコマンドへの参照は、二重引用符で囲まれる。
command       新しいスタイルのコマンド。これにより、他の引用されたテキストお
                よび文字列と区別される。

                                        key-notation key-codes keycodes
これらのキーの名前はドキュメントで使用される。これらは ":map" コマンドでも使用
できる (CTRL-K を押してから名前を知りたいキーを押すことで、キー名を挿入する)。

きる。規則は:
 1.  バックスラッシュおよび '<' を除き、全ての印字可能文字は直接タイプされる
 2.  バックスラッシュは "\\"、二重バックスラッシュ、または "<Bslash>" で表され
     る。
 3.  実際の '<' は "\<" または "<lt>" で表される。混乱の可能性がない場合は、
     '<' を直接使用できる。
 4.  "<key>" はタイプされた特殊キーを意味する。これは上の表で説明されている表
     記である。いくつかの例:
           <Esc>                エスケープキー
           <C-G>                CTRL-G
           <Up>                 カーソル上キー
           <C-LeftMouse>        Control- 左マウスクリック
           <S-F11>              シフトされたファンクションキー 11
           <M-a>                Meta- a  (ビット 8 がセットされた 'a')
           <M-A>                Meta- A  (ビット 8 がセットされた 'A')
           <t_kd>               "kd" termcap エントリ (カーソル下キー)
    {char} がマルチバイト文字である <M-{char}> を指定することはできるが、Vim
    はそれがどのバイトシーケンスであるかを知ることができない場合があり、その場
    合は機能しない。

<> 表記を Vim で完全に使用したい場合は、'cpoptions' から '<' フラグが除外され
ていることを確認しなければならない ('compatible' が設定されていない時は、デフォ
ルトですでに除外されている)。
        :set cpo-=<
> 表記は、キー名の特別な意味をエスケープするのに <lt> を使用する。バックスラッ
シュを使用することもできるが、'cpoptions' が 'B' フラグを含まない場合に限られ
る。

CTRL-H を 6 文字 "<Home>" にマッピングする例:
        :imap <C-H> \<Home>
        :imap <C-H> <lt>Home>
1 つ目は、'B' フラグが 'cpoptions' に含まれていない場合にのみ機能する。2 つ目
は常に機能する。

マッピング、短縮入力、およびメニューのコマンドでは、その場合、例をコピー&ペー
ストしてそのまま使用できる。または、'<' および '>' の文字を含めて文字どおりに
タイプする。これは ":set" および ":autocmd" のような他のコマンドでは機能しない!

この表記は、開始に "\<" を使用することで、二重引用符の文字列の中で使用できる。
例: "\<C-Space>"。これは特殊なキーコードになる。これを読める形のテキストに戻す
には keytrans() を使用する。

5. モード、はじめに                             vim-modes-intro vim-modes

Vim には 7 つの基本モードがある:

                                        Normal Normal-mode command-mode
ノーマルモード          ノーマルモードでは、通常のエディタコマンドを全て入力で
                        きる。エディタを起動した場合、このモードになる
                        ('insertmode' オプションを設定していない限り。以下を参
                        照)。これはコマンドモードとしても知られている。

ビジュアルモード        これはノーマルモードに似ているが、移動コマンドはハイラ
                        イトされた領域を拡張する。移動以外のコマンドが使用され
                        ると、それはハイライトされた領域に対して実行される。
                        Visual-mode を参照。
                        'showmode' オプションがオンの場合、ウィンドウの下端に
                        "-- VISUAL --" が表示される。

選択モード              これは MS-Windows の選択モードに最も似ている。印字可能
                        文字をタイプすると、選択範囲が削除され、挿入モードが開
                        始される。Select-mode を参照。
                        'showmode' オプションがオンの場合、ウィンドウの下端に
                        "-- SELECT --" が表示される。

挿入モード              挿入モードでは、タイプしたテキストがバッファに挿入され
                        る。Insert-mode を参照。
                        'showmode' オプションがオンの場合、ウィンドウの下端に
                        "-- INSERT --" が表示される。

コマンドラインモード    コマンドラインモード (Cmdline モードとも呼ばれる) で
Cmdline モード          は、ウィンドウの下端に 1 行のテキストを入力できる。こ
                        れは Ex コマンド ":"、パターン検索コマンド "?" および
                        "/"、およびフィルタコマンド "!" のためのものである。
                        Cmdline-mode

Ex モード               コマンドラインモードに似ているが、コマンドを入力した後
                        も Ex モードにとどまる。コマンドラインの非常に限られた
                        編集。Ex-mode

端末ジョブモード        端末ウィンドウ内のジョブとの対話。タイプしたキーはジョ
                        ブに送られ、ジョブの出力は端末ウィンドウに表示される。
                        他のモードへの切り替え方については terminal を参照。

7 つの追加モードがある。これらは基本モードの変種である:

                                Operator-pending Operator-pending-mode
オペレータ待機モード    これはノーマルモードに似ているが、オペレータコマンドが
                        開始された後で、Vim はオペレータが作用するテキストを指
                        定する {motion} を待っている。

置換モード              置換モードは挿入モードの特殊な場合である。挿入モードと
                        同じことができるが、入力した 1 文字ごとに、既存のテキ
                        ストの 1 文字が削除される。Replace-mode を参照。
                        'showmode' オプションがオンの場合、ウィンドウの下端に
                        "-- REPLACE --" が表示される。

仮想置換モード          仮想置換モードは置換モードに似ているが、ファイルの文字
                        の代わりに、画面の領域を置き換える。
                        Virtual-Replace-mode を参照。
                        'showmode' オプションがオンの場合、ウィンドウの下端に
                        "-- VREPLACE --" が表示される。

挿入ノーマルモード      挿入モードで CTRL-O をタイプした時に入る (i_CTRL-O
                        を参照)。これはノーマルモードに似ているが、1 つのコマ
                        ンドを実行した後、Vim は挿入モードに戻る。
                        'showmode' オプションがオンの場合、ウィンドウの下端に
                        "-- (insert) --" が表示される。

端末ノーマルモード      端末ウィンドウでのノーマルモードの使用。変更を加えるこ
                        とは不可能である。端末ジョブモードに戻るには、"a" また
                        は "i" のような挿入コマンドを使用する。

挿入ビジュアルモード    例えば CTRL-O を使用し、それから "v"、"V" または
                        CTRL-V を使用することによって、挿入モードからビジュア
                        ル選択を開始した時に入る。ビジュアル選択が終わると、
                        Vim は挿入モードに戻る。
                        'showmode' オプションがオンの場合、ウィンドウの下端に
                        "-- (insert) VISUAL --" が表示される。

挿入選択モード          挿入モードから選択モードを開始した時に入る。例えば、マ
                        ウスのドラッグまたは <S-Right> によって。
                        選択モードが終わると、Vim は挿入モードに戻る。
                        'showmode' オプションがオンの場合、ウィンドウの下端に
                        "-- (insert) SELECT --" が表示される。

6. モードからモードへの切り替え                         mode-switching

何らかの理由でどのモードにいるのか分からない場合、<Esc> を 2 回タイプすること
で、いつでもノーマルモードに戻ることができる。ただし、これは Ex モードでは機能
しないので、":visual" を使用すること。
<Esc> をタイプした後に、画面がフラッシュするのを見るか、またはベルが鳴るのを聞
いた時、ノーマルモードに戻ったことが分かる。ただし、挿入モードで CTRL-O を使用
した後に <Esc> を押すと、ビープ音が鳴るが、まだ挿入モードにいるので、もう一度
<Esc> をタイプすること。

                移行先モード

移行元モード

*1 "i"、"I"、"a"、"A"、"o"、"O"、"c"、"C"、"s" または S" コマンドを与えること
   で、ノーマルモードから挿入モードに移る。
*2 そのコマンドを実行させる、移動以外のコマンドを与えるか、または副作用なしに
   単にビジュアルモードを停止する <Esc> "v"、"V" または "CTRL-V" (v_v を参照)
   を押すことで、ビジュアルモードからノーマルモードに移る。
*3 以下によって、コマンドラインモードからノーマルモードに移る:
   - <CR> または <NL> を押す。これにより、入力したコマンドが実行される。
   - 行全体を削除し (例えば CTRL-U で)、最後に <BS> を与える。
   - CTRL-C または <Esc> を押す。これは、コマンドを実行せずにコマンドラインを
     終了する。
   最後の場合、<Esc> が 'wildchar' オプションで定義された文字であることがあり、
   その場合はコマンドライン補完が開始される。それを無視して、もう一度 <Esc> を
   タイプできる。
*4 以下によって、ノーマルモードから選択モードに移る:
   - 'selectmode' が "mouse" を含む時に、マウスを使用してテキストを選択する
   - Shift キーを押したまま、カーソルを移動する印字不可能なコマンドを使用し、
     かつ 'selectmode' オプションが "key" を含む
   - 'selectmode' が "cmd" を含む時に、"v"、"V" または "CTRL-V" を使用する
   - "gh"、"gH" または "g CTRL-H" を使用する  g_CTRL-H
*5 Shift キーを押さずに、カーソルを移動する印字不可能なコマンドを使用すること
   で、選択モードからノーマルモードに移る。
*6 印字可能文字をタイプすることで、選択モードから挿入モードに移る。選択範囲が
   削除され、その文字が挿入される。

'insertmode' オプションがオンの場合、ファイルの編集は挿入モードで開始する。

        CTRL-\_CTRL-N i_CTRL-\_CTRL-N c_CTRL-\_CTRL-N v_CTRL-\_CTRL-N
さらに、コマンド CTRL-\ CTRL-N または <C-\><C-N> を使用して、他のどのモードか
らでもノーマルモードに移ることができる。これは、<Esc> のようにビープ音を鳴らす
ことなく、Vim がノーマルモードにあることを確実にするのに使用できる。ただし、こ
れは Ex モードでは機能しない。f または m のような引数を取るコマンドの後で
使用された時、'ttimeoutlen' で設定されたタイムアウトが適用される。
端末ウィンドウにフォーカスがある時、CTRL-\ CTRL-N は、編集コマンドが入力される
までノーマルモードに移る。t_CTRL-\_CTRL-N を参照。

        CTRL-\_CTRL-G i_CTRL-\_CTRL-G c_CTRL-\_CTRL-G v_CTRL-\_CTRL-G
コマンド CTRL-\ CTRL-G または <C-\><C-G> は、'insertmode' が設定されている時に
挿入モードに移るのに使用できる。それ以外の場合はノーマルモードに移る。これは、
Vim が現在どのモードにあるかを知らなくても、Vim が 'insertmode' で示されるモー
ドにあることを確実にするのに使用できる。

                                    Q mode-Ex Ex-mode Ex EX E501
Q                       "Ex" モードに切り替える。これは、":" コマンドを次々に
                        タイプするのに少し似ているが、以下を除く:
                        - ":" を繰り返し押す必要はない。
                        - 各コマンドの後で画面は更新されない。
                        - 通常のコマンドライン編集はない。
                        - マッピングおよび短縮入力は使用されない。
                        実際には、"標準の" 行入力編集コマンド (消去には <Del>
                        または <BS>、行全体を削除するには CTRL-U) で行を編集し
                        ている。
                        Vim がコマンドラインで "ex" として起動されたか、または
                        -e コマンドライン引数が使用された場合、Vim はデフォ
                        ルトでこのモードに入る。
                        "Ex" モードを終了するには ":vi" コマンド :visual を
                        使用する。
                        Note: 古いバージョンの Vim では "Q" はテキストを整形し
                        たが、それは現在は gq で行われる。しかし、
                        vimrc_example.vim スクリプトまたは defaults.vim を
                        使用している場合、"Q" は "gq" のように動作する。選択
                        モードを除く。

                                        gQ
gQ                      "Q" と同様に "Ex" モードに切り替えるが、本当に ":" コ
                        マンドを次々にタイプするように動作する。全てのコマンド
                        ライン編集、補完などが使用可能である。
                        "Ex" モードを終了するには :vi コマンド (:visual)
                        を使用する。

7. ウィンドウの内容                                     window-contents

ノーマルモードおよび挿入/置換モードでは、画面のウィンドウはバッファの現在の内
容を表示する: What You See Is What You Get。2 つの例外がある:
- 'cpoptions' オプションが '$' を含み、変更が 1 行内である時、テキストは直接削
  除されず、削除された最後の文字に '$' が置かれる。
- あるウィンドウでテキストを挿入している時、同じテキストの他のウィンドウは、挿
  入が終わるまで更新されない。

ウィンドウの幅より長い行は、'wrap' オプションがオフでない限り、折り返される
(以下を参照)。'linebreak' オプションを設定すると、空白文字で折り返すことができ
る。

ウィンドウにバッファの最後の行の後の余地がある場合、Vim はウィンドウの最後の行
の 1 桁目に '~' を表示する。このように:

        +-----------------------+
        |some line              |
        |last line              |
        |~                      |
        |~                      |
        +-----------------------+

したがって、'~' の行は、バッファの終わりに達したことを示す。

ウィンドウ内の最後の行が収まらない場合、Vim はウィンドウの最後の行の 1 桁目に
'@' を付けてこれを示す。このように:

        +-----------------------+
        |first line             |
        |second line            |
        |@                      |
        |@                      |
        +-----------------------+

したがって、'@' の行は、ウィンドウに収まらない行があることを示す。

'display' オプションに "lastline" フラグが含まれている時、ウィンドウの左側に
'@' 文字は表示されない。最後の行が完全には収まらない場合、収まる部分だけが表示
され、最後の行の最後の 3 文字が "@@@" で置き換えられる。このように:

        +-----------------------+
        |first line             |
        |second line            |
        |a very long line that d|
        |oesn't fit in the wi@@@|
        +-----------------------+

ウィンドウに収まらないほど長い 1 行がある場合、これは特別な状況である。Vim は、
カーソルがある位置の周辺の、行の一部だけを表示する。特殊文字は表示されないの
で、この行の全ての部分を編集できる。

'highlight' オプションの '@' の項目を使用して、'@' および '~' 文字に特別なハイ
ライトを設定できる。これにより、それらをバッファ内の実際の文字と区別できるよう
になる。

'showbreak' オプションは、折り返された行の前に置く文字列を含む。

                                                        wrap-off
'wrap' オプションがオフの場合、長い行は折り返されない。画面に収まる部分だけが
表示される。行の表示されていない部分にカーソルが移動された場合、画面は水平にス
クロールされる。この方法の利点は、桁がそのまま表示され、画面に収まらない行を編
集できることである。欠点は、行の全ての文字を一度に見ることができないことであ
る。'sidescroll' オプションに、スクロールする最小の桁数を設定できる。

全ての通常の ASCII 文字は画面に直接表示される。<Tab> は、それが表す数のスペー
スで置き換えられる。他の印字不可能文字は "^{char}" で置き換えられる。ここで
{char} は、印字不可能文字に 64 を足したものである。したがって、文字 7 (ベル)
は "^G" と表示される。127 と 160 の間の文字は "~{char}" で置き換えられる。ここ
で {char} は、その文字から 64 を引いたものである。これらの文字は画面上で 2 つ
以上の位置を占める。カーソルは最初の位置にしか置けない。

'number' オプションを設定した場合、全ての行の前にその行番号が付く。ヒント: 折
り返される行が行番号と混ざるのが好きでない場合は、'showbreak' オプションを 8
つのスペースに設定すること:
        ":set showbreak=\ \ \ \ \ \ \ \ "

'list' オプションを設定した場合、<Tab> 文字はいくつかのスペースとしてではなく、
"^I" として表示される。行末に '$' が置かれるので、末尾の空白を見つけることがで
きる。

コマンドラインモードでは、コマンドライン自体だけが正しく表示される。バッファの
内容の表示は、コマンドモードに戻るとすぐに更新される。

ウィンドウの最後の行は、ステータスおよび他のメッセージに使用される。ステータス
メッセージは、オプションがオンの場合にのみ使用される:

ステータスメッセージ            オプション   デフォルト Unix デフォルト
現在のモード                    'showmode'      on          on
コマンド文字                    'showcmd'       on          off
カーソル位置                    'ruler'         off         off

現在のモードは "-- INSERT --" または "-- REPLACE --" である。'showmode' を参
照。コマンド文字は、タイプしたがまだ使用されていないものである。

遅い端末を使用している場合は、編集を速くするためにステータスメッセージをオフに
できる:
        :set nosc noru nosm

エラーがある場合、エラーメッセージが少なくとも 1 秒間表示される (反転表示で)。

いくつかのコマンドは、何行が影響を受けたかを表示する。どのしきい値を超えるとこ
れが起こるかは、'report' オプション (デフォルト 2) で制御できる。

Amiga では、Vim は CLI ウィンドウで動作する。Vim という名前およびカレントファ
イル名のフルネームがタイトルバーに表示される。ウィンドウのサイズが変更される
と、Vim は自動的にウィンドウを再描画する。ウィンドウは好きなだけ小さくできる
が、小さくなりすぎると 1 行も収まらなくなる。最後の行のほとんどのメッセージを
読めるように、少なくとも 40 文字の幅にすること。

ほとんどの Unix システムでは、ウィンドウのサイズ変更は Vim によって認識され、
正しく処理される。

8. 定義                                                 definitions

  バッファ              テキストの行を含む。通常はファイルから読み込まれる。
  スクリーン            Vim が作業に使用する領域全体。これは端末エミュレータの
                        ウィンドウであることもある。"Vim のウィンドウ" とも呼
                        ばれる。
  ウィンドウ            バッファのビュー。1 つのバッファに対して複数のウィンド
                        ウがあり得る。

スクリーンは 1 つ以上のウィンドウを含み、それらはステータス行で区切られ、下端
にコマンドラインがある。

        +-------------------------------+
screen  | window 1      | window 2      |
        |               |               |
        |               |               |
        |= status line =|= status line =|
        | window 3                      |
        |                               |
        |                               |
        |==== status line ==============|
        |command line                   |
        +-------------------------------+

コマンドラインはメッセージにも使用される。コマンドラインに十分な余地がない場
合、スクリーンを上にスクロールする。

4 種類の行が区別される:

  バッファ行            バッファ内の行。これはファイルから読み込まれた/ファイ
                        ルに書き込まれたままの行と同じである。数千文字の長さに
                        なり得る。
  論理行                折り畳みが適用されたバッファ行。閉じた折り畳み内のバッ
                        ファ行は、1 つの論理行に変更される:
                        "+-- 99 lines folded"。数千文字の長さになり得る。
  ウィンドウ行          ウィンドウに表示される行: 折り返し、改行などが適用され
                        た論理行の範囲。ウィンドウの幅が許す長さまでにしかなら
                        ず、それより長い行は折り返されるか、または切り詰められ
                        る。
  スクリーン行          Vim が使用するスクリーンの行。全てのウィンドウのウィン
                        ドウ行に、ステータス行およびコマンドラインを加えたもの
                        で構成される。スクリーンの幅が許す長さまでにしかならな
                        い。コマンドラインが長くなると、折り返され、余地を作る
                        ために行がスクロールされる。

バッファ行      論理行          ウィンドウ行    スクリーン行

1. one          1. one          1. +-- folded   1.  +-- folded
2. two          2. +-- folded   2. five         2.  five
3. three        3. five         3. six          3.  six
4. four         4. six          4. seven        4.  seven
5. five         5. seven                        5.  === status line ===
6. six                                          6.  aaa
7. seven                                        7.  bbb
                                                8.  ccc ccc c
1. aaa          1. aaa          1. aaa          9.  cc
2. bbb          2. bbb          2. bbb          10. ddd
3. ccc ccc ccc  3. ccc ccc ccc  3. ccc ccc c    11. ~ 
4. ddd          4. ddd          4. cc           12. === status line ===
                                5. ddd          13. (command line)
                                6. ~
