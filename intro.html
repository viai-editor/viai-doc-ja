1. はじめに                                             intro

ViAI は Vim を改変したものである。viai を参照。このマニュアルの以降の部分は、
Vim と書かれている箇所も含めて ViAI に当てはまる。

Vim は Vi IMproved (Viの改良版) である。かつては Vi IMitation (Viの模造品) だっ
たが、多くの改良が加えられたので適切な名前に変更された。Vim はテキストエディタ
である。Unix のプログラム "Vi" のほとんどのコマンドと、さらに多くの新しいコマ
ンドを備えている。プログラムを書いたりテキストを編集するのにとても便利である。
すべてのコマンドはキーボードから入力する。そのため、キーボードから手を離す必要
も、スクリーンから目を離す必要もない。お望みなら、マウスを使うこともできるし、
GUIではスクロールバーやメニューを使うこともできる (gui.txt参照)。

このマニュアルの概要は help.txt にある。Vim から <Help> や <F1> キー、
:help コマンドで開くことができる (単に :help と入力すること。引用符もバーも
必要ない)。
ヘルプファイルが標準の位置にインストールされていない場合は、ヘルプファイルの名
前をオプション 'helpfile' に設定すること。タグでジャンプするのと同じようにヘル
プの項目へジャンプできる。ジャンプしたい項目にカーソルを合わせて CTRL-] でジャ
ンプできる。CTRL-T で元の場所に戻れる。

Vi と Vim の違いは vi_diff.txt に記載されている。

このマニュアルの内容は Vim が実行されるほとんどの環境で通用するが、コンピュー
タや端末によって、少し違う動作をする場合がある。このドキュメントから外れる内容
については、システムごとに個別の説明がある。sys-file-list を参照。

                                                        pronounce
ViAI は "vee-eye" と発音する。viai を参照。GUI 版の ViAI は "GViAI" と表記さ
れる。
Vim は vi-ai-em ではなく、Jim のように一語として発音する。Vim はまた Jim のよ
うに名称なので、(最初の文字を) 大文字で書く。GUI 版の Vim は "gVim" (文頭の場
合は "GVim") と表記される。

このマニュアルは全ての Vim コマンドとオプションのリファレンスである。Vi や Vim
の入門書ではない (それを入れるとあちこちで説明が込み入ってしまうので)。初心者
には、実習 tutor がある。Vim の使い方を身につけるにはユーザーマニュアル
usr_toc.txt を読むこと。

                                                        book books
ViとVimに関するほとんどの本には初心者向けのセクションがある。その他、特定の機
能についてより多くの言葉を費やしている。Vimの本の概要はここにある:
        http://iccf-holland.org/vim_books.html

バグレポート:                           bugs bug-reports bugreport.vim

                                                        viai-bugs
ViAI のバグがどう扱われるかは、それがどこで起きるかによる:
- ViAI でだけ起きるバグ: 報告するには ViAI のリポジトリで issue を作成すること:
        https://github.com/viai-editor/viai/issues
  メンテナーが ViAI 側でプルリクエストにより修正する。
- Vim でも起きるバグ: 報告するには ViAI のリポジトリで issue を作成すること。
  メンテナーが ViAI 側で修正し、Vim に報告する。後で Vim が修正した場合は、
  ViAI は Vim の修正を取り込む。
- Vim でだけ起きるバグ: 以下に説明するように Vim に報告すること。

Vim にバグを報告するには3つの方法がある:
1. ランタイムのファイルについてのissueは、ヘッダにある email アドレス宛てか他
   の方法でメンテナーにレポートを送ること。
2. GitHub に issue を立てること: https://github.com/vim/vim/issues 文章は
   vim-dev メーリングリストにも転送される。
3. バグレポートは Vim 開発陣 <vim-dev@vim.org> に送ること。
   これはメーリングリストである。最初にメンバーになる必要がある。たくさんの人
   がそのメッセージを見る。もしセキュリティ上の問題などの理由でそれを望まない
   のであれば、電子メールアドレス <vim-security@googlegroups.com> で現在の Vim
   メンテナーに連絡するか、Github でセキュリティアドバイザリを作成すること:
   https://github.com/vim/vim/security/advisories

メッセージは簡潔にお願いする。メールに回答する時間は、Vim を改良する時間から消
費されている! 常に再現可能な例をつけること。そして、バグを引き起こす設定やその
他のものを探すこと。

なるべくなら Vim を次のように起動すること:
        vim --clean -u reproduce.vim
ここで、reproduce.vim は問題を再現するスクリプトである。関連があるならば (もし
かしたら MS-Windows 固有のバグかも？)、違うマシンでも試してみること。

可能ならばパッチを送ること！ https://github.com/vim/vim でプルリクエストを作成
すると、自動チェックが実行され、明らかな問題があれば報告される。ただし、パッチ
を電子メールで送信することもできる (空白文字の変更を避けるために添付ファイルを
使用すること)。
{訳注: 本家へのレポートは英語でお願いする}

Vim のバージョンや設定情報を含めてくれると助かる。次のコマンドで情報を得ること
ができる:
   :so $VIMRUNTIME/bugreport.vim
このコマンドはカレントディレクトリにあなたの環境に関する多くの情報を持った
"bugreport.txt" というファイルを作る。このファイルを送る前に、そこにいかなる秘
密の情報も含まれていないことを確認すること!

Vim がクラッシュした場合は、クラッシュした場所を探してみること。詳しくは
debug.txt を参照すること。

よく分からなかったり、その問題がすでに解決済みかどうか知りたい場合には、
vim-dev メーリングリストで質問すること。maillist

                                                        year-2000 Y2K
Vim の内部では、テキストの編集に日付を使っていないので、2000 年問題はない。Vim
は 1970 年 1 月 1 日 (正午) からの秒形式で時間を使う。これは、開いているファイ
ルとスワップファイルのタイムスタンプをチェックするために使われるが、致命的な問
題は起きない。ただ警告メッセージが表示されるだけだろう。

しかし、32bit 整数で秒があふれてしまう 2038 年問題はあるかもしれない。この問題
は、コンパイラ、ライブラリ、オペレーティングシステムに依存している。
time_t、ctime() 関数が使われているときは特にそうである。time_t はスワップファ
イル内に 4 バイトで格納されるが、これはファイルの回復時にファイルの日付、時間
を求めるために使われるだけなので、通常の編集作業には決して影響しない。

Vim の strftime() 関数は strftime() システムコールを直接使う。localtime() は
time() システムコールを、getftime() は stat() システムコールで返される時間をそ
れぞれ使用する。システムライブラリが 2000 年対応なら、Vim もそうである。

ユーザーは外部コマンドを使用する Vim script を作るかもしれない。このことが Y2K
問題を招くかもしれないが、Vim 自身の問題ではない。

4. ヘルプの表記法                                       notation

この文章を構文強調を使って表示すると、見たままの意味ではないテキストは特別に強
調表示される。[]、{}、<>、で囲まれた項目や CTRL-X などである。

Note: Vim は入力可能な文字はすべてコマンドで使う。実際に、[]、{}、<> を入力す
る場合もある。それは文脈によって判断できるだろう。


[]              角カッコで囲まれた文字は省略可能。

                                                    count [count]
[count]         コマンドに前置して、そのコマンドを繰り返したり、反復したりする
                ための省略可能な数字。省略した場合、特に注意が無ければ 1 を指
                定したのと同じになる。Note: このマニュアルでは、[count] はコマ
                ンドの説明では言及されない。解説する場合だけ説明する。これはコ
                マンドを調べ易くするためである。'showcmd' オプションが有効だ
                と、(部分的に) 入力されたカウントがウィンドウの下の方に表示さ
                れる。<Del> を使って末尾の数字を削除できる (N<Del>)。

                                                        [quotex]
["x]            テキストの保管場所として、任意のレジスタを指定できることを示
                す。registers を参照。x は 'a' から 'z'、'A' から 'Z'、'"'、
                のどれか一文字である。場合によっては (put コマンドで使うときな
                ど)、'0' から '9'、'%'、'#'、その他の文字も使える。大文字でも
                小文字でも同じレジスタを指すが、小文字を使ったときはレジスタの
                内容が上書きされ、大文字を使ったときはレジスタの内容に追加され
                る。"x を指定しなかった場合や、"" を指定した場合は、無名レジス
                タが使われる。

                                                        {}
{}              中括弧の表記は、コマンドの一部として入力する必要があって、そこ
                には、いろいろな値を入力することができるときに使われる。Vim と
                Vi の違いを示す場合も中括弧で表記される (これは文脈から区別で
                きる)。

                                                        {char1-char2}
{char1-char2}   char1 から char2 の範囲のどれか一文字。例えば、{a-z} は小文字
                一文字。複数の範囲が指定される場合もある。例えば、{a-zA-Z0-9}
                は英数字のどれか一文字である。

                                                {motion} movement
{motion}        カーソル移動コマンド。これらは、motion.txt で説明されている。
                例:
                        w               次の単語の最初に移動
                        b               現在の単語の最初へ
                        4j              4行下に移動
                        /The<CR>        つぎの "The" が、ある場所に移動
                オペレータコマンド (operator) を入力した後で、対象のテキスト
                を選択するため使われる。
                - 移動コマンドがカウントを含み、オペレータコマンドもカウントを
                  含むときは、二つのカウントが掛け合わされる。例えば、"2d3w"
                  は 6 単語を削除する。
                - 移動はバックもできる。例えば、"db" は単語の最初までを削除す
                  る。
                - 移動はマウスのクリックでもできる。ただし、マウスをサポートし
                  ていない端末もある。
                - ":omap" コマンドを使って、オペレータコマンドに対して移動コマ
                  ンドを入力しているときに働くマップを定義できる。
                - Ex コマンドを使ってカーソルを移動できる。関数を使って複雑な
                  移動をすることもできる。どの ":" コマンドが使われても、移動
                  は常に文字単位で排他的である。そのため、改行を含めずに行末の
                  文字を選択することはできない ('virtualedit' を設定すれば可
                  能)。
                  Ex コマンドで、オペレータコマンドを使った場所より前にあるテ
                  キストを変更したり、他のバッファに移動した場合、結果は予測で
                  きない。オペレータコマンドを使った場所以降のテキストなら変更
                  できる。カレントバッファがアンロードされないなら、他のバッ
                  ファにジャンプすることも可能である。

                                                        {Visual}
{Visual}        選択されたテキストの範囲。"v"、"V"、CTRL-V コマンドで選択を開
                始し、カーソル移動コマンドで選択範囲を変更できる。
                オペレータコマンド (operator) を実行する前に使って、対象のテ
                キストを選択することができる。Visual-mode を参照。

                                                        <character>
<character>     下記の表に示した特殊文字。修飾キーが付くこともある。修飾
                キーと ASCII 文字の組合せもこのように表記される。

                                                        'character'
'c'             ASCII 文字 1 文字。

                                                        CTRL-{char}
CTRL-{char}     制御文字として入力された文字 {char}。CTRL キーを押しながら
                {char} を押す場合である。{char} は大文字でも小文字でも区別され
                ない。CTRL-A と CTRL-a は同じである。SHIFT キーを使うと別のコー
                ドを生成する端末もあるため、シフトキーは使わないこと。

                                                        'option'
'option'        オプション (設定) はシングルクォートで囲んで表記される。オプ
                ションは設定値を変更できる。options を参照。

                                                        quotecommandquote
"command"       説明の中にでてくる入力可能なコマンドは、ダブルクォートで囲んで
                表記される。
command       コマンドの新しい表記法である。他のクォート表記のテキストや文字
                列と区別するために使われる。

                                        key-notation key-codes keycodes

例ではよく <> 表記が使われる。これは、何を入力すべきかを明確に表記するために使
われるが、文字どおりに入力する必要がある場合もある。例えば、":map" コマンドで
使う場合など。規則は以下のとおりである:
 1.  バックスラッシュと '<' 以外の印字可能文字はそのまま表記される。
 2.  バックスラッシュは "\\" (ダブルバックスラッシュ)、または "<Bslash>" と表
     記される。
 3.  実際の '<' は "\<"、または "<lt>" と表記される。混乱を招く恐れがなけれ
     ば、'<' はそのまま使われる。
 4.  "<key>" は特殊キーを打つことを示す。これは上記の表で説明している表記であ
     る。いくつか例を挙げる:
           <Esc>                エスケープキー
           <C-G>                CTRL-G
           <Up>                 上カーソルキー
           <C-LeftMouse>        コントロール + 左マウスクリック
           <S-F11>              シフト + ファンクションキー11
           <M-a>                Meta + a  ('a' with bit 8 set)
           <M-A>                Meta + A  ('A' with bit 8 set)
           <t_kd>               "kd" termcapエントリ(下カーソルキー)
    マルチバイト文字である{char}を使用して <M-{char}> を指定できるが、Vimはど
    のバイトシーケンスであるかを認識できないため、動作しない。

<> 表記を使うには、'cpoptions' から '<' フラグを除く必要がある
('compatible' がオフのときは、初期設定でそうなっている)。
        :set cpo-=<
> 表記の特別な意味をなくすには <lt> を使う。バックスラッシュを使う方法も機能
するが、それは 'cpoptions' が 'B' フラグを含んでいないときだけである。

CTRL-H を "<Home>" の 6 文字にマップする例:
        :imap <C-H> \<Home>
        :imap <C-H> <lt>Home>
最初の例は 'cpoptions' に 'B' フラグが含まれていない場合のみ機能する。2 番目の
例は常に機能する。
マップで "<lt>" を文字どおりに使うには 次のようにする:
        :map <C-L> <lt>lt>

マップ、短縮入力、メニューコマンドについては、例をコピー＆ペーストして、そのま
ま使うことができる。あるいは、'<' と '>' も含めて、そのまま入力すること。
これは ":set" や ":autocmd" などの他のコマンドでは機能しない！

この表記は、ダブルクォートで囲んだ文字列の先頭に "\<" を付けて使用することがで
きる。例えば "\<C-Space>"。この結果、特殊なキーコードが生成される。これを読み
やすいテキストに戻す変換には、keytrans() を使用する。

5. モードの紹介                                 vim-modes-intro vim-modes

Vim には 7 つの基本モードがある。

                                        Normal Normal-mode command-mode
ノーマルモード          ノーマルモードでは普通の編集コマンドを全て入力できる。
                        エディタをスタートするとこのモードに入る (オプション
                        'insertmode' を設定しているときは違う。以下を参照)。こ
                        れはコマンドモードとも呼ばれる。

ビジュアルモード        ノーマルモードに似ているが、移動コマンドで選択領域が拡
                        大される。移動コマンド以外のコマンドを使うと、選択領域
                        に対してそのコマンドが実行される。Visual-mode を参
                        照。
                        オプション 'showmode' がオンなら、"-- VISUAL --" がウィ
                        ンドウの最下部に表示される。

選択モード              これは、MS-Windows でテキストを選択するときの動作に似
                        ている。印字可能文字が入力されると、選択範囲を削除し、
                        挿入モードに入る。Select-modeを参照。
                        オプション 'showmode' がオンなら、"-- SELECT --" がウィ
                        ンドウの最下部に表示される。

挿入モード              挿入モードでは、タイプされたテキストはバッファに挿入さ
                        れる。Insert-modeを参照。
                        オプション 'showmode' がオンなら、"-- INSERT --" がウィ
                        ンドウの最下部に表示される。

コマンドラインモード    コマンドラインモードでは、ウィンドウの下部に 1 行のテ
                        キストを入力できる。これは Ex コマンド、":"、パターン
                        検索コマンド、"?"、"/"、そしてフィルタコマンド、"!" で
                        使用する。Cmdline-modeを参照。

Ex モード               コマンドラインモードに似ているが、コマンド入力後も Ex
                        モードに留まる。コマンドライン編集は、かなり制限され
                        る。Ex-modeを参照。

Terminal-Job モード     ターミナルウィンドウの中でジョブと相互作用する。入力さ
                        れたキーはジョブに渡され、ジョブの出力はターミナルウィ
                        ンドウに表示される。他のモードへの移行の仕方は
                        terminal を参照。

加えて、7 つのモードがある。これらは基本モードの変種である。

                                Operator-pending Operator-pending-mode
オペレータ待機モード    ノーマルモードに似ているが、オペレータコマンドが実行さ
                        れた後で、その適用範囲を決定するための移動コマンド
                        ({motion}) を得るために、Vim が待機している状態である。

置換モード              置換モードは挿入モードの特別版である。挿入モードと同様
                        のことができるが、一文字入力するごとに、その場所にある
                        文字が一つ削除される。Replace-modeを参照。
                        オプション 'showmode' がオンなら、"-- REPLACE --" が
                        ウィンドウの最下部に表示される。

仮想置換モード          仮想置換モードは置換モードに似ているが、ファイルの文字
                        の上ではなく、画面上の任意の位置を置換できる。
                        Virtual-Replace-mode を参照。'showmode' がオンな
                        ら、"-- VREPLACE --" がウィンドウの最下部に表示される。

挿入ノーマルモード      挿入モードで CTRL-O を入力したときにこのモードに入る
                        (i_CTRL-O を参照)。ノーマルモードに似ているが、1つの
                        コマンドを実行した後、Vimは挿入モードに戻る。オプショ
                        ン 'showmode' がオンなら、"-- (insert) --" がウィンド
                        ウの最下部に表示される。

Terminal-Normal モード  ターミナルウィンドウでノーマルモードを使う。変更はでき
                        ないようになっている。ターミナルジョブモードに戻るに
                        は、"a" や "i" のような挿入コマンドを使う。

挿入ビジュアルモード    挿入モードでビジュアル選択を開始すると、このモードに入
                        る。例えば、CTRL-O を使い, その後 "v"、"V"、CTRL-V を
                        使ったときである。
                        ビジュアル選択が終了すると、挿入モードに戻る。
                        オプション 'showmode' がオンなら、
                        "-- (insert) VISUAL --" がウィンドウの最下部に表示され
                        る。

挿入選択モード          挿入モードで選択モードを開始すると、このモードに入る。
                        例えば、マウスをドラッグしたり、<S-Right> を押したとき
                        である。
                        選択モードが終了すると、挿入モードに戻る。オプション
                        'showmode' がオンなら、"-- (insert) SELECT --" がウィ
                        ンドウの最下部に表示される。

6. モードの切り替え                                     mode-switching

何らかの理由で、現在のモードがわからなくなったときは、<Esc> を 2 度押すことで
常にノーマルモードに戻ることができる。Ex モードでは機能しないので、その場合は
":visual" を使うこと。
<Esc> を押したとき、スクリーンフラッシュや、ベルの音で、ノーマルモードに戻った
ことを知ることができる。挿入モードで CTRL-O の後に <Esc> を押した場合、ビープ
音は鳴るが、まだ挿入モードの中なので、もう一度 <Esc> を押すこと。

                                                        i_esc
                移動先のモード                                     
                Normal  Visual  Select  Insert    Replace   Cmd-line  Ex

*1 ノーマルモードから挿入モードへは、コマンド "i"、"I"、"a"、"A"、"o"、"O"、
   "c"、"C"、"s"、"S" で入る。
*2 ビジュアルモードからノーマルモードへは非移動コマンドで入れるが、そのコマ
   ンドは実行されてしまう。<Esc>、"v"、"V"、"CTRL-V" (v_vを参照) を入力すれ
   ば、副作用なしにビジュアルモードから出られる。
*3 コマンドラインモードからノーマルモードへ移行するには次のようにする:
   - <CR> か <NL> を入力する。入力途中のコマンドは実行される。
   - 行の全てを削除し (例、CTRL-Uを使う)、そして、<BS> を入力する。
   - CTRL-C または <Esc> を入力する、入力途中のコマンドを実行せずに終了できる。
   最後の方法だが、<Esc> が 'wildchar' に設定されている場合がある。その場合、
   コマンドライン補完が実行されるが、それを無視して、再び <Esc> を入力するこ
   と。
*4 ノーマルモードから選択モードに移行するには次のようにする:
   - 'selectmode' が "mouse" を含んでいるときは、マウスでテキストを選択する。
   - 'selectmode' が "key" を含んでいるときは、シフトキーを押しながら、特殊キー
     でカーソルを動かす。(:set keymodel+=startsel が必要)
   - 'selectmode' が "cmd" を含んでいるときは、"v"、"V"、"CTRL-V" を使う。
   - "gh"、"gH"、"g CTRL-H" を使う。g_CTRL-H
*5 選択モードからノーマルモードに移行するには、シフトキーを押さずに特殊キーで
   カーソルを動かす。(:set keymodel+=stopsel が必要)
*6 選択モードから挿入モードへ移行するには、印字可能文字 (普通の文字) を入力す
る。選択範囲は削除され、入力した文字が挿入される。

'insertmode' がオンのときは、編集作業は挿入モードで始まる。

        CTRL-\_CTRL-N i_CTRL-\_CTRL-N c_CTRL-\_CTRL-N v_CTRL-\_CTRL-N
CTRL-\ CTRL-N と <C-\><C-N> を使って、どのモードからでもノーマルモードに移行で
きる。このコマンドを使えば、確実にノーマルモードになることができる。<Esc>
のときのようにビープ音はならない。ただし、Ex モードでは機能しない。fや mの
ように引数をとるコマンドの後で使われたときは、'ttimeoutlen' で設定されたタイム
アウトが適用される。
フォーカスがターミナルウィンドウにあるとき、CTRL-\ CTRL-N は編集コマンドが入力
されるまでの間ノーマルモードに移行する。t_CTRL-\_CTRL-N を参照。

        CTRL-\_CTRL-G i_CTRL-\_CTRL-G c_CTRL-\_CTRL-G v_CTRL-\_CTRL-G
'insertmode' がオンのときは、CTRL-\ CTRL-G や <C-\><C-G> で挿入モードに移行で
きる。オフのときはノーマルモードに移行する。このコマンドを使えば、現在どのモー
ドにいるのかにかかわらず、'insertmode' に設定されたモードに移行することができ
る。

                                    Q mode-Ex Ex-mode Ex EX E501
Q                       "Ex" モードに切り替える。このモードは ":" コマンドを続
                        けて入力するようなものだが、次の点が違う:
                        - 毎回 ":" を押す必要がない。
                        - コマンドを実行するごとに画面が更新されない。
                        - 通常のコマンドライン編集機能は使えない。
                        - マップと短縮入力は使えない。
                        つまり、"標準の" 行編集コマンドだけを使って入力する
                        (削除に<Del>または<BS>、行削除に CTRL-U を使用する)。
                        Vim が "ex" という名前かコマンドライン引数 -e を使用
                        して実行された場合には、このモードで起動する。
                        "Ex" モードを抜けるには、":vi" コマンド :visual を使
                        う。
                        Note: Vim の昔のバージョンでは "Q" がテキストを整形す
                        るコマンドだったが、いまは gq になっている。ただし
                        vimrc_example.vim あるいは defaults.vim を使ってい
                        る場合は、"Q" と "gq" は同じ動作をする。ただし選択モー
                        ドを除く。

                                        gQ
gQ                      "Ex" モードに切り替える。"Q" と同じだが、実際に ":" コ
                        マンドでコマンドを入力するのと同じように動作する。コマ
                        ンドライン編集や補完などがすべて利用可能である。"Ex"
                        モードを抜けるには、:vi コマンド (:visual) を使う。

7. ウィンドウに表示される内容                           window-contents

ノーマルモードと挿入/置換モードでは、スクリーンに現在のバッファの内容が表示さ
れる。つまり、見ているものが得られるもの (WYSIWYG) である。しかし、例外が二つ
がある:
- オプション 'cpoptions' が '$' を含んでいて、一行に収まる範囲を変更 (c) す
  るときは、テキストはすぐに削除されず、削除される文字の最後の位置に '$' が表
  示される。
- あるウィンドウでテキストを挿入していて、別のウィンドウでも同じテキストを表示
  しているとき、挿入を完了するまでそのウィンドウの表示は更新されない。
  {訳注: 確認できず}

ウィンドウの幅より長い行は、折り返して表示される。'wrap' がオフのときは折り返
されない (下記参照)。'linebreak' を設定すると空白文字で折り返すことができる。

ウィンドウ内でバッファの最終行より下に表示領域がある場合、以下のように、それら
の行の始めに '~' が表示される:

        +-----------------------+
        |some line              |
        |last line              |
        |~                      |
        |~                      |
        +-----------------------+

このように、'~' はバッファの最後に到達したことを示す。

ウィンドウに表示されている最後の行が表示しきれない場合、以下のように、最終行の
場所に '@' が表示される:

        +-----------------------+
        |first line             |
        |second line            |
        |@                      |
        |@                      |
        +-----------------------+

このように、'@' はウィンドウに収まりきらない行があることを示す。

'display' に "lastline" フラグが含まれている場合、'@' はウィンドウの左側に表示
されない。最終行がウィンドウに完全に収まらない場合は、収まる部分のみが表示さ
れ、最後の 3 文字が次のように "@@@" で置き換えられる:

        +-----------------------+
        |first line             |
        |second line            |
        |a very long line that d|
        |oesn't fit in the wi@@@|
        +-----------------------+

長すぎてウィンドウに収まりきらない単一の行があるときは、特別な場合として扱われ
る。Vim はカーソルのある場所付近のみを表示する。特殊記号は表示されない。
その行のどの部分でも編集できる。

'@' と '~' の強調表示を設定するには、オプション 'highlight' の '@' を設定する。
それらの文字と、バッファの中の本物の文字を区別することができる。

折り返された行の先頭には 'showbreak' に設定した文字が表示される。

                                                        wrap-off
'wrap' がオフの場合、長い行は折り返されない。スクリーンに収まる分だけ表示され
る。カーソルが表示されていない部分に移動すると、スクリーンは水平方向にスクロー
ルする。この方法の利点は、縦の列がありのままに表示されること、スクリーンに収ま
らない行も編集できることである。欠点としては、一行の全ての文字を一度に見ること
ができないことが挙げられる。'sidescroll' にはスクロールする最小の列 (カラム)
数を設定する。

全ての普通のASCII文字はスクリーンに直接表示される。<Tab> は、それが表現する数
のスペースに置き換えられる。他の非表示文字は、"^{char}" に置き換えられる、この
とき {char} には、その非表示文字に 64 を足した文字が入る。つまり、文字 7 (ベル
文字) は "^G" と表示される。127 から 160 までの文字は "~{char}" で置き換えられ
る、このとき {char} には、その文字から 64 を引いた文字が入る。これらの文字はス
クリーン上では複数幅で表示される。カーソルはその複数幅の先頭にのみ移動させるこ
とができる

'number' がオンの場合、全ての行の先頭に行番号が表示される。
Tip: 行を折り返したときに、行番号と行の表示を混ぜたくないときは、'showbreak'
に 8 つのスペースをセットする:
        ":set showbreak=\ \ \ \ \ \ \ \ "

'list' がオンの場合、<Tab> 文字はいくつかのスペースとしてではなく、"^I" として
表示される。'$' が行末に表示されるので、行の最後についた空白を見つけることがで
きる。

コマンドラインモードでは、コマンドラインのみが正しく表示される。バッファの内容
の表示は、コマンドラインモードから抜けたときに更新される。

ウィンドウの最下行はステータスやその他のメッセージのために使われる。ステータス
メッセージが使われるのは、オプションがオンのときのみである:

ステータスメッセージ            オプション     初期設定  Unixの初期設定
現在のモード                    'showmode'      on          on
コマンドの文字                  'showcmd'       on          off
カーソルの位置                  'ruler'         off         off

現在のモードとは、"-- INSERT --" や "-- REPLACE --" のことである、'showmode'
を参照。コマンドの文字とは、入力されて、まだ実行されていないコマンドのことであ
る。

遅い端末を使っている場合は、ステータスメッセージをオフにすることで編集のスピー
ドを上げることができる:
        :set nosc noru nosm

エラーが起きたとき、エラーメッセージは少なくとも一秒間は表示される (反転表示
で)。

いくつかのコマンドでは、そのコマンドが作用する行数が表示される。何行以上でその
表示をするかは、'report' で設定できる (初期設定は 2)。

Amiga 上では、Vim は CLI ウィンドウで実行される。Vim の名前と現在のファイル名
の絶対パスがタイトルバーに表示される。ウィンドウがリサイズされると、Vim は自動
的にウィンドウを再描画する。ウィンドウは好きなだけ小さくできるが、小さすぎると
1行のみで収まりきらなくなる。最下行に表示されるメッセージが読めるように、最低
でも40文字の幅を取ること。

ほとんどの UNIX システム上で、Vim はウィンドウのリサイズを正しく認識、把握でき
る。

8. 用語の定義                                           definitions

  バッファ              テキスト行が入っている。一般にファイルから読み込む。
  スクリーン            Vim が使う領域全体。端末ウィンドウを指す場合もある。
                        "Vimウィンドウ" とも呼ばれる。
  ウィンドウ            バッファが表示される場所。1 つのバッファが複数のウィ
                        ンドウを持つことが可能。

一つのスクリーンは一つ以上のウィンドウを内包し、それらはステータスラインで区切
られ、最下行にはコマンドラインが表示される。

        +-------------------------------+
screen  | window 1      | window 2      |
        |               |               |
        |               |               |
        |= status line =|= status line =|
        | window 3                      |
        |                               |
        |                               |
        |==== status line ==============|
        |command line                   |
        +-------------------------------+

コマンドラインはメッセージを表示するためにも使われる。コマンドラインに十分な表
示領域がない場合はスクリーンがスクロールする。

行には 4 種類あり、次の違いがある:

  バッファ行            バッファ内の行。ファイルに読み書きする行のこと。
                        行の長さは制限なし。
  論理行                折り畳みが適用されたバッファ行。複数のバッファ行が折り
                        畳まれ論理行 1 行となり、次のように表示される:
                        "+-- 99 lines folded"。
                        行の長さは制限なし。
  ウィンドウ行          ウィンドウに表示される行: 折り返し、ラインブレークなど
                        が適用された後の論理行の一部。長さはウィンドウの幅以
                        下。それ以上長い行は折り返されるか切り詰められる。
  スクリーン行          Vim が使うスクリーンの行。全てのウィンドウのウィンドウ
                        行とステータスライン、コマンドラインからなる。長さはス
                        クリーンの幅以下。コマンドラインがそれ以上長くなったと
                        きは折り返して表示され、表示領域を作るために行がスク
                        ロールされる。

バッファ行      論理行          ウィンドウ行    スクリーン行

1. one          1. one          1. +-- folded   1.  +-- folded
2. two          2. +-- folded   2. five         2.  five
3. three        3. five         3. six          3.  six
4. four         4. six          4. seven        4.  seven
5. five         5. seven                        5.  === status line ===
6. six                                          6.  aaa
7. seven                                        7.  bbb
                                                8.  ccc ccc c
1. aaa          1. aaa          1. aaa          9.  cc
2. bbb          2. bbb          2. bbb          10. ddd
3. ccc ccc ccc  3. ccc ccc ccc  3. ccc ccc c    11. ~ 
4. ddd          4. ddd          4. cc           12. === status line ===
                                5. ddd          13. (command line)
                                6. ~
