                  VIAI リファレンスマニュアル


このファイルには、Vim が出すメッセージとエラーメッセージの、アルファベット順の
一覧が含まれている。メッセージの意味が分からない場合に、これを使うことができ
る。ただし、完全ではない。

1. 古いメッセージ       :messages
2. エラーメッセージ     error-messages
3. メッセージ           messages

==============================================================================
1. 古いメッセージ               :messages :mes message-history

":messages" コマンドを使うと、以前に出されたメッセージを見ることができる。これ
は、メッセージが上書きされたり切り詰められたりした場合に特に役に立つ。これは
'shortmess' オプションに依存する。

        :mes[sages]             すべてのメッセージを表示する。

        :{count}mes[sages]      最新の {count} 件のメッセージを表示する。

        :mes[sages] clear       すべてのメッセージをクリアする。

        :{count}mes[sages] clear
                                最新の {count} 件だけを残して、メッセージをク
                                リアする。

記憶されるメッセージの数は、'messagesopt' オプションで決まる。

                                                                g<
"g<" コマンドを使うと、前のコマンドの出力の最後のページを見ることができる。こ
れは、hit-enter プロンプトで誤って <Space> をタイプした場合に特に役に立つ。そ
うすると hit-enter プロンプトに戻り、さらに前にスクロールできる。
Note: more プロンプトで "q" によって出力が止められた場合は、この時点までしか表
示されない。
別のコマンドが出力を出すと、前のコマンドの出力はクリアされる。"g<" の出力はリ
ダイレクトされない。

翻訳されたメッセージを使っている場合、最初に表示される行に、誰がメッセージまた
は翻訳をメンテナンスしているかが書かれている。誤りを見つけたときに、これを使っ
てメンテナーに連絡できる。

特定の (エラー) メッセージについてのヘルプを見つけたい場合は、メッセージの最初
の ID を使う。例えば、このメッセージについてのヘルプを得るには:

        E72: Close error on swap file

または (翻訳されたもの):

        E72: Errore durante chiusura swap file

これを使う:

        :help E72

面倒な場合、シフトキーを使わなくても動作する:

        :help e72

この ID の番号には意味はない。

==============================================================================
2. エラーメッセージ                             error-messages errors

エラーメッセージが表示されたが、読む前に消えてしまった場合は、これでもう一度見
ることができる:
  :echo errmsg
または、最近のメッセージの一覧をこれで見る:
  :messages
上の :messages を参照。

                                                        E1513

ウィンドウで 'winfixbuf' が有効になっている場合、そのウィンドウのカレントバッ

                                                        E72
  Close error on swap file

編集したテキストのコピーを保持するのに使われる swap-file を、正しく閉じるこ
とができなかった。ほとんど無害である。

                                                        E169
  Command too recursive

これは、Ex コマンドが Ex コマンドを実行し、それがまた Ex コマンドを実行し、な
どという場合に起こる。上限は 200 か 'maxfuncdepth' の値のどちらか大きいほうで
ある。それより多い場合は、おそらく無限ループがある。おそらく :execute か
:source コマンドが関係している。

                                                        E254
  Cannot allocate color {name}

色の名前 {name} が分からない。ほとんどのシステムで利用できる色の一覧は
gui-colors を参照。

                                                        E1244
  Bad color string: {str}

提供された色が、パターン #rrggbb に合っていなかった

                                                        E458
  Cannot allocate colormap entry, some colors may be incorrect

これは、Vim で利用できる色が足りないことを意味する。Vim は動作し続けるが、いく
つかの色は指定された色で表示されない。多くの色を使う他のアプリケーションを止め
てみるか、gvim を起動した後でそれらを起動すること。
ブラウザーは多くの色を消費することが知られている。netscape では、独自のカラー
マップを使うように指示することで、これを避けることができる:
        netscape -install
または、特定の数の色に制限するように指示する (64 でうまくいくはずである):
        netscape -ncols 64
これは、Xdefaults ファイルの行でも行うことができる:
        Netscape*installColormap: Yes
または
        Netscape*maxImageColors:  64

                                                        E79
  Cannot expand wildcards

ファイル名に変な文字の組み合わせが含まれていて、それにより Vim がワイルドカー
ドを展開しようとしたが、これが失敗した。これは、マッチするファイル名が見つから
なかったという意味ではなく、パターンが不正だったという意味である。

                                                        E459
  Cannot go back to previous directory

ファイル名を展開している間に、Vim は以前使っていたディレクトリに戻るのに失敗し
た。使われているファイル名は、今はすべて無効かもしれない! カレントディレクトリ
に対する実行権限が必要である。

                                                        E190 E212
  Cannot open "{filename}" for writing
  Can't open file for writing

何らかの理由で、書き込もうとしているファイルを作成または上書きできない。理由と
しては、ディレクトリに書き込む権限がないか、ファイル名が有効でないことが考えら
れる。

                                                        E166
  Can't open linked file for writing

上書きできないファイルに書き込もうとしており、そのファイルはリンク (ハードリン
クかシンボリックリンク) である。リンクまたはファイルを含むディレクトリが書き込
み可能な場合、書き込みはまだ可能かもしれないが、Vim には、リンクを削除してその
場所にファイルを書き込みたいのか、ファイル自体を削除してその場所に新しいファイ
ルを書き込みたいのかが分からない。本当にこの名前でファイルを書き込みたい場合
は、手動でリンクかファイルを削除するか、Vim が上書きできるように権限を変更する
必要がある。

                                                        E46
  Cannot change read-only variable "{name}"

読み取り専用の、関数の引数 a:var または Vim の内部変数 v:var に値を代入し
ようとしている。

                                                        E90
  Cannot unload last buffer

Vim は常に 1 つのバッファが読み込まれていることを必要とする。そうでないと、ウィ
ンドウに表示するものが何もなくなってしまう。

                                                        E40
  Can't open errorfile <filename>

":make" または ":grep" コマンドを使っている場合: エラーメッセージや grep の出
力を保存するのに使われるファイルを開くことができない。これにはいくつかの原因が
ありうる:
- 'shellredir' の値が間違っている。
- シェルがディレクトリを変更し、エラーファイルが別のディレクトリに書き込まれ
  る。これは 'makeef' を変更することで修正できるが、それでも make コマンドは間
  違ったディレクトリで実行される。
- 'makeef' の値が間違っている。
- 'grepprg' または 'makeprg' を実行できなかった。これは常に検出できるわけでは
  ない (特に MS-Windows では)。$PATH を確かめること。


  Can't open file C:\TEMP\VIoD243.TMP

MS-Windows では、このメッセージは、外部コマンドの出力を読み込もうとしたが、そ
のコマンドが正常に実行されなかったときに表示される。これは多くの原因で起こりう
る。'shell'、'shellquote'、'shellxquote'、'shellslash' と関連するオプションを
確かめること。外部コマンドが見つからなかったのかもしれないが、そのための別のエ
ラーメッセージはない。

                                                        E12
  Command not allowed from exrc/vimrc in current dir or tag search

いくつかのコマンドは、セキュリティ上の理由で許可されていない。これらのコマンド
は、ほとんどの場合、カレントディレクトリの .exrc または .vimrc ファイルか、
tags ファイルから来る。'secure' も参照。

                                                        E74
  Command too complex

マッピングがとても長いコマンド文字列になった。マッピングが間接的に自分自身を呼
び出すことが原因かもしれない。


  CONVERSION ERROR

ファイルを書き込むときに "CONVERSION ERROR" というテキストが現れた場合、これ
は、内部で使われている UTF-8 からファイルの形式にテキストを変換するときに、い
くつかのビットが失われたことを意味する。ファイルは未変更とはマークされない。情
報の損失が気になる場合は、'fileencoding' オプションを、バッファ内の文字を扱え
る別の値に設定して、もう一度書き込むこと。気にならない場合は、バッファを破棄す
るか、'modified' オプションをリセットすることができる。
'writebackup' か 'backup' が設定されているときに、バックアップファイルがある場
合、それは削除されないので、変更を捨てたい場合は、それを元の場所に戻すことがで
きる。

                                                        E302
  Could not rename swap file

ファイル名が変わったとき、Vim は swap-file の名前も変更しようとする。
これに失敗し、古いスワップファイルがまだ使われている。ほとんど無害である。

                                                        E43 E44
  Damaged match string
  Corrupted regexp program

Vim の内部で何かがおかしくなり、壊れた正規表現になった。この問題を再現する方法
が分かっている場合は、報告してほしい。bugs

                                                        E208 E209 E210
  Error writing to "{filename}"
  Error closing "{filename}"
  Error reading "{filename}"

これは、Vim がファイルの名前を変更しようとしているが、ファイル名の単純な変更が
うまくいかない場合に起こる。その場合、ファイルはコピーされるが、なぜかこれが失
敗した。
結果として、元のファイルとコピー先のファイルの両方が存在し、コピー先のファイル
が不完全になっているかもしれない。


  Vim: Error reading input, exiting...

これは、入力が必要なときに、Vim がタイプされた文字を読み込めない場合に起こる。
Vim は動けなくなり、できるのは終了することだけである。これは、stdin と stderr
の両方がリダイレクトされ、Vim を終了しないスクリプトを実行している場合に起こり
うる。

                                                        E47
  Error while reading errorfile

エラーファイルを読み込むことができなかった。これは、認識されなかったエラーメッ
セージが原因ではない。

                                                        E80
  Error while writing

ファイルの書き込みが正常に完了しなかった。ファイルはおそらく不完全である。

                                                        E13 E189
  File exists (add ! to override)
  "{filename}" exists (add ! to override)

誤ってファイルを上書きしないように保護されている。それでも書き込みたい場合は、
同じコマンドを使い、コマンドのすぐ後に "!" を付ける。例:
        :w /tmp/test
これをこう変える:
        :w! /tmp/test

                                                        E768
  Swap file exists: {filename} (:silent! overrides)

Vim で編集されているファイルを上書きしないように保護されている。これは、
":w! filename" を使い、スワップファイルが見つかった場合に起こる。
- スワップファイルが、以前にクラッシュした編集セッションの残りである場合は、ス
  ワップファイルを削除したいかもしれない。スワップファイルについての情報を調べ
  るには、{filename} を編集する。
- それでも書き込みたい場合は、コマンドの前に ":silent!" を付ける。例えば:
        :silent! w! /tmp/test
  ! はすでに既存のファイルを上書きするために付けているので、この特別なコマンド
  が必要である。

                                                        E139
  File is loaded in another buffer

別のバッファでも使われている名前で、ファイルを書き込もうとしている。そうする
と、同じファイルの 2 つのバージョンができてしまう。

                                                        E142
  File not written: Writing is disabled by 'write' option

'write' オプションがオフになっている。これにより、ファイルを書き込もうとするす
べてのコマンドがこのメッセージを出す。これは -m コマンドライン引数が原因かも
しれない。":set write" で 'write' オプションをオンにできる。

                                                        E25
  GUI cannot be used: Not enabled at compile time

GUI のコードを含まないバージョンの Vim を実行している。そのため、"gvim" と
":gui" は動作しない。

                                                        E49
  Invalid scroll size

これは、'scroll'、'scrolljump' または 'scrolloff' オプションに無効な値を設定し
たことが原因である。

                                                        E17
  "{filename}" is a directory

ディレクトリの名前でファイルを書き込もうとした。これはできない。おそらくファイ
ル名を付け加える必要がある。

                                                        E19
  Mark has invalid line number

存在しない行番号を持つマークを使っている。これは、別のファイルにマークがあり、
他のプログラムがそのファイルから行を削除した場合に起こりうる。

                                                        E219 E220
  Missing {.
  Missing }.

ファイル名で {} 構文を使っているが、対応する } のない { があるか、その逆であ
る。これはこのように使うべきである: {foo,bar}。これは "foo" と "bar" にマッチ
する。

                                                        E315
  ml_get: invalid lnum: {number}

これは Vim の内部エラーである。どうすれば再現できるかを調べて、バグ報告を送っ
てほしい bugreport.vim。

                                                        E173
  {number} more files to edit

引数リストの最後の項目が編集されていないのに、終了しようとしている。これは、ま
だ作業するファイルが残っているのに誤って終了してしまうことを防ぐ。
argument-list を参照。本当に終了したい場合は、もう一度やればうまくいく。

                                                        E23 E194
  No alternate file
  No alternate file name to substitute for '#'

代替ファイルがまだ定義されていない。alternate-file を参照。

                                                        E32
  No file name

カレントバッファに名前がない。書き込むには ":w fname" を使う。または
":file fname" でバッファに名前を付ける。

                                                        E141
  No file name for buffer {number}

変更されたバッファの 1 つにファイル名がない。そのため、書き込むことができない。
バッファにファイル名を付ける必要がある:
        :buffer {number}
        :file {filename}

                                                        E33
  No previous substitute regular expression

パターンで '~' 文字を使うと、":substitute" コマンドで以前に使われたパターンで
置き換えられる。そのようなコマンドがまだ使われていない場合は、これが失敗す
る。/~ を参照。これは ":s/pat/%/" を使ったときにも起こる。ここで "%" は以前
の置換文字列を表す。

                                                        E35
  No previous regular expression

空の検索パターンを使うと、以前の検索パターンが使われる。しかし、以前の検索がな
かった場合は、それはできない。

                                                        E24
  No such abbreviation

既存の短縮入力ではない引数で ":unabbreviate" コマンドを使った。このコマンドの
すべての変種が同じメッセージを出す: ":cunabbrev"、":iunabbrev" など。末尾の空
白を確かめること。


  /dev/dsp: No such file or directory

Gnome サポート付きの GTK GUI でのみ出る。Gnome がオーディオデバイスを使おうと
したが、それが存在しない。このエラーは無視してよい。

                                                        E31
  No such mapping

既存のマッピングではない引数で ":unmap" コマンドを使った。このコマンドのすべて
の変種が同じメッセージを出す: ":cunmap"、":unmap!" など。いくつかのヒント:
- 末尾の空白を確かめること。
- マッピングがバッファローカルの場合は、":unmap <buffer>" を使う必要がある。
  :map-<buffer>

                                                        E37 E89
  No write since last change (add ! to override)
  No write since last change for buffer {N} (add ! to override)

変更のあるファイルを abandon しようとしている。Vim は作業が失われないように
保護している。変更されたファイルを ":w" で書き込むか、確かな場合は、とにかく
abandon して、すべての変更を失うことができる。これは、使ったコマンドのすぐ後
に '!' 文字を付けることで行える。例:
        :e other_file
これをこう変える:
        :e! other_file

                                                        E162
  No write since last change for buffer "{name}"

これは、いくつかのバッファが変更されているときに Vim を終了しようとすると表示
される。変更されたバッファを (:w で) 書き込むか、例えば ":qa!" で、バッファ
を強制的に破棄するコマンドを使う必要がある。本当に残したい変更を捨ててしまわな
いように注意すること。特に 'hidden' が設定されている場合は、バッファのことを忘
れているかもしれない。


  [No write since last change]

これは、少なくとも 1 つのバッファが変更されている状態でシェルコマンドを実行し
たときに表示される。このメッセージを避けるには、'warn' オプションをリセットす
る。

                                                        E38
  Null argument

Vim の内部で何かがおかしくなり、NULL ポインタになった。この問題を再現する方法
が分かっている場合は、報告してほしい。bugs

                                                E41 E82 E83 E342
  Out of memory!
  Out of memory!  (allocating {number} bytes)
  Cannot allocate any buffer, exiting...
  Cannot allocate buffer, using other one...

おっと。何か複雑なことをしていたか、他のプログラムがメモリを消費しているに違い
ない。気をつけること! Vim はメモリ不足の状況に完全には備えていない。まず、すべ
ての変更が保存されていることを確かめること。それからメモリ不足を解決しようとす
ること。安全のために、Vim を終了して、もう一度起動すること。

Vim がまだ初期化中にこれが起こった場合は、ファイルの編集はまず動作しないので、
Vim は値 123 で終了する。

バッファは部分的にしかメモリに保持されないので、とても大きなファイルを編集して
も、メモリ不足の状況が起こることはまずない。アンドゥ情報は完全にメモリ内にあ
り、これらのオプションでそれを減らすことができる:
- 'undolevels'  低い値に設定するか、アンドゥを完全に無効にするには -1 に設定す
  る。これは、すべての行に影響する変更に役に立つ。
- 'undoreload' 無効にするにはゼロに設定する。

                                                        E339
  Pattern too long

これは 16 ビットの int を持つシステムで起こる: コンパイルされた正規表現パター
ンが約 65000 文字より長い。より短いパターンを使ってみること。
ルールのオフセットが利用可能な領域に収まらない場合にも起こる。パターンを単純に
してみること。

                                                        E45
  'readonly' option is set (add ! to override)

読み取り専用とマークされたファイルを書き込もうとしている。それでもファイルを書
き込むには、'readonly' オプションをリセットするか、使ったコマンドのすぐ後に
'!' 文字を付ける。例:
        :w
これをこう変える:
        :w!

                                                        E294 E295 E301
  Read error in swap file
  Seek error in swap file read
  Oops, lost the swap file!!!

Vim は swap-file からテキストを読み込もうとしたが、何かがおかしくなった。関
連するバッファのテキストは、今は壊れているかもしれない! バッファを書き込む前に
注意深く確かめること。別のファイルに書き込んで、違いを確かめたいかもしれない。

                                                        E192
  Recursive use of :normal too deep

引数がまた ":normal" コマンドを再帰的に使う ":normal" コマンドを使っている。こ
れは 'maxmapdepth' レベルに制限されている。この例は、このメッセージが出る様子
を示している:
        :map gq :normal gq<CR>
"gq" とタイプすると、このマッピングが実行され、それがまた "gq" を呼び出す。

                                                        E22
  Scripts nested too deep

スクリプトは "-s" コマンドライン引数と :source! コマンドで読み込むことができ
る。そのスクリプトがまた別のスクリプトを読み込むことができる。これは約 14 レベ
ルまで続けることができる。それ以上ネストすると、Vim は再帰ループがあるとみな
し、このエラーメッセージで止まる。

                                                        E319
  Sorry, the command is not available in this version

使っている Vim のバージョンには存在しないコマンドを使った。Vim をコンパイルす
るとき、多くの異なる機能を有効または無効にできる。これは、Vim がどれだけ大きく
なるように選ばれたかと、オペレーティングシステムに依存する。どの機能がいつ利用
可能かは +feature-list を参照。:version コマンドは、Vim がどの機能付きでコ
ンパイルされたかを表示する。

                                                        E300
  Swap file already exists (symlink attack?)

このメッセージは、Vim がスワップファイルを開こうとして、それがすでに存在する
か、その場所にシンボリックリンクがあるのを見つけたときに表示される。Vim はファ
イルが存在しないことをすでに確かめているので、これは起こるべきではない。誰か他
の人がまったく同じ瞬間に同じファイルを開いたか (とてもありそうにない)、誰かが
symlink 攻撃を試みている (/tmp にあるファイルを編集しているときか、'directory'
が "/tmp" で始まっている場合に起こりうる。これは悪い選択である)。

                                                        E432
  Tags file not sorted: {file name}

Vim (と Vi) は、tags ファイルが ASCII 順でソートされていることを期待する。そう
すると二分探索を使うことができ、線形探索よりずっと速い。tags ファイルが正しく
ソートされていない場合は、'tagbsearch' オプションをリセットすること。
このメッセージは、タグを検索するときに Vim が問題を検出した場合にのみ出る。
tags ファイルが正しくソートされていなくても、このメッセージが出ないこともある。

                                                        E424
  Too many different highlighting attributes in use

Vim は約 223 種類の異なるハイライトしか扱えない。この上限に達した場合は、異な
る引数で :highlight コマンドを使いすぎている。":highlight link" は数えられな
い。

                                                        E77
  Too many file names

ファイル名を展開するときに、2 つ以上のマッチが見つかった。使われたコマンドに
は、マッチは 1 つしか許されない。

                                                        E303
  Unable to open swap file for "{filename}", recovery impossible

Vim はスワップファイルを作成できなかった。ファイルを編集することはできるが、
Vim が予期せず終了すると、変更は失われる。また、大きなファイルを編集するとき
に、Vim が多くのメモリを消費するかもしれない。このエラーを避けるために、
'directory' オプションを変更したいかもしれない。'directory' が空の場合は、この
エラーは出ない。swap-file を参照。

                                                        E140
  Use ! to write partial buffer

範囲を使ってバッファの一部を書き込むとき、元のファイルを上書きすることは普通で
はない。おそらく誤りである (例えば、":w" を使ったときにビジュアルモードがアク
ティブだった)。そのため Vim は、コマンドの後に ! を使うことを要求する。例:
":3,10w!"。


  Warning: Cannot convert string "<Key>Escape,_Key_Cancel" to type
  VirtualBinding

このようなメッセージが起動時に現れる。これは Vim の問題ではなく、X11 の設定が
間違っている。これを解決する方法のヒントはここで見つけられる:
http://groups.yahoo.com/group/solarisonintel/message/12179.
[この URL はもう有効ではない]

                                                        W10
  Warning: Changing a readonly file

ファイルは読み取り専用だが、それでも変更を加えようとしている。このメッセージを
避けるには、FileChangedRO 自動コマンドイベントを使うことができる (自動コマン
ドは 'readonly' オプションをリセットしなければならない)。ファイルへの変更を完
全に禁止するには、'modifiable' を参照。
このメッセージは、'readonly' が設定された後の最初の変更に対してのみ出る。

                                                        W13
  Warning: File "{filename}" has been created after editing started

Vim でファイルを編集しているとき、それは存在しなかったが、今は存在する。
Vim の中のバージョンを残したいのか、新しく作成されたファイルを残したいのかを決
める必要がある。'buftype' が空でない場合、このメッセージは出ない。

                                                        W11
  Warning: File "{filename}" has changed since editing started

編集を始めたファイルのタイムスタンプが変わり、内容が変更された (より正確には:
現在のオプション設定と自動コマンドでファイルを再び読み込むと、異なるテキストに
なる)。これはおそらく、他のプログラムがファイルを変更したことを意味する。何が
起こったのかを調べ、どのバージョンのファイルを残したいのかを決める必要がある。
これを自動的に行いたい場合は、'autoread' オプションを設定すること。
'buftype' が空でない場合、このメッセージは出ない。
FileChangedShell 自動コマンドも参照。

以下の選択肢を持つダイアログが表示される:

"OK":           警告を消して、編集を続ける。変更は読み込まれず、バッファはその
                ままである。

"Load File":    ディスクからファイルを再読み込みし、現在のバッファの内容を置き
                換える。Vim で行った変更のうち、保存されていないものはすべて失
                われる。

"Load File and Options":
                ディスクからファイルを再読み込みし、さらに、インデント、構文ハ
                イライト、テキスト幅、その他のファイルタイプ固有のオプションな
                ど、関連するファイル設定を適用する。これにより、現在の設定と自
                動コマンドに従って、バッファがファイルの意図した構成に一致する
                ことが保証される。

何も間違っていないのに、このメッセージが出る状況が 1 つある: 夏時間が始まる日
に Windows でファイルを保存した場合である。これは、これらの方法のどれかで修正
できる:
- この行を autoexec.bat に追加する:
           SET TZ=-1
  "-1" をタイムゾーンに合わせる。
- "automatically adjust clock for daylight saving changes" を無効にする。
- 単に次の日にもう一度ファイルを書き込む。または、時計を次の日に設定し、ファイ
  ルを 2 回書き込み、時計を戻す。

W11 がいつも出る場合は、"Acronis Active Protection" を無効にするか、Vim を信頼
できるサービス/アプリケーションとして登録する必要があるかもしれない。

                                                        W12
  Warning: File "{filename}" has changed and the buffer was changed in Vim as well

上と同様だが、ファイルのバッファもこの Vim の中で変更された。この Vim の中の
バージョンを残したいのか、ディスク上のものを残したいのかを決める必要がある。
'buftype' が空でない場合、このメッセージは出ない。

                                                        W16
  Warning: Mode of file "{filename}" has changed since editing started

バッファのタイムスタンプが変更され、内容は同じままだが、モード (権限) が変わっ
たとき。これは通常、バージョン管理システムからファイルをチェックアウトしたとき
に起こり、それにより読み取り専用ビットがリセットされる。ファイルを再読み込みし
ても安全なはずである。ファイルを自動的に再読み込みするには、'autoread' を設定
すること。

                                                        E211
  File "{filename}" no longer available

編集を始めたファイルが消えたか、もうアクセスできない。変更を失わないように、
バッファをどこかに書き込むようにすること。'buftype' が空でない場合、このメッ
セージは出ない。

                                                        W14
  Warning: List of file names overflow

とてもたくさんのバッファを使っているに違いない。今は 2 つのバッファが同じ番号
を持つ可能性があり、それはさまざまな問題を引き起こす。Vim を終了して再起動した
いかもしれない。

                                                        E931
  Buffer cannot be registered

メモリ不足か、重複したバッファ番号。W14 の後に起こるかもしれない。バッファの検
索は常に動作するとは限らないので、Vim を再起動したほうが良い。

                                                        E296 E297
  Seek error in swap file write
  Write error in swap file

これはほとんどの場合、ディスクがいっぱいのときに起こる。Vim は swap-file に
テキストを書き込めなかった。直接害はないが、Vim が予期せず終了すると、リカバ
リーができずにテキストが失われるかもしれない。この問題が続くと、Vim はメモリ不
足になるかもしれない。

                                                connection-refused
  Xlib: connection to "<machine-name:0.0" refused by server

これは、Vim が X サーバーに接続しようとしたが、X サーバーが接続を許可しない場
合に起こる。X サーバーへの接続は、タイトルを復元するためと、xterm クリップボー
ドのサポートのために必要である。残念ながら、このエラーメッセージは、
+xterm_clipboard と +X11 機能を無効にする以外に避けることはできない。

                                                        E10
  \\ should be followed by /, ? or &

コマンドラインがバックスラッシュで始まったか、コマンドの範囲に間違った場所に
バックスラッシュが含まれていた。これは、コマンドライン継続が無効になっているこ
とが原因であることが多い。それを有効にするには、'cpoptions' オプションから 'C'
フラグを取り除く。または ":set nocp" を使う。

  Argument required

必須の引数を持つ Ex コマンドが実行されたが、引数が指定されていない。

                                                        E474 E475 E983
  Invalid argument
  Invalid argument: {arg}
  Duplicate argument: {arg}

Ex コマンドか関数が実行されたが、無効な引数が指定された。

                                                        E488

  Trailing characters: {text}

引数を許さない Ex コマンドに引数が追加された。
または、引数に無効な文字があり、認識されなかった。

                                                        E477 E478
  No ! allowed
  Don't panic!

"!" を許さない Ex コマンドの後に "!" を追加した。

                                                        E481
  No range allowed

                                                        E482 E483
  Can't create file {filename}
  Can't get temp file name

Vim は一時ファイルを作成できない。

                                                        E484 E485

                                                        E464
  Ambiguous use of user-defined command

これは、ソースコードを変更しているとき、src/ex_cmds.h にコマンドを追加している

3. メッセージ                                           messages

これは、Vim が出すさまざまなメッセージの (不完全な) 概要である:

                        hit-enter press-enter hit-return
                        press-return hit-enter-prompt

  Press ENTER or type command to continue

このメッセージは、画面に読むべきものがあり、画面が再描画されようとしているとき
に出る:
- 外部コマンドを実行した後 (例えば ":!ls" と "=")。
- ウィンドウの幅より長いものがステータスラインに表示されたか、'showcmd' か
  'ruler' の出力にまで達した。

-> 画面を再描画して続けるには、<Enter> か <Space> を押す。そのキーが他に使われ
   ることはない。
-> そのコマンドを開始するには、':' か他のノーマルモードコマンドの文字を押す。
   Note 外部コマンドの後では、端末がまだ外部コマンドを実行するための状態に設定
   されているため、カーソルキーなどのいくつかの特殊キーが正常に動作しないかも
   しれないことに注意。
-> メッセージを前にスクロールするには、'k'、<Up>、'u'、'b' か 'g' を押す。これ
   は more-prompt と同じように動作する。'compatible' がオフで 'more' がオン
   のときだけ動作する。
-> メッセージが画面の上端からスクロールして消え、'compatible' がオフで 'more'
   がオンのときは、'j'、'f'、'd' か <Down> を押しても無視される。これは、'j'
   か 'f' を 1 回余計にタイプしたことでメッセージが消えてしまうのを避けるため
   である。
-> モードレスセレクションをクリップボードレジスタにコピー (ヤンク) するには、
   <C-Y> を押す。
-> メニューを使う。コマンドラインモード用に定義された文字が使われる。
-> 'mouse' に 'r' フラグが含まれている場合、マウスの左ボタンをクリックすると、
   <Space> を押すのと同じように動作する。ただし、これによりテキストを選択でき
   なくなる。
-> GUI では、最後の行でマウスの左ボタンをクリックすると、<Space> を押すのと同
   じように動作する。
-> q はレジスタへの記録を開始しない (根拠: ユーザーによって "quit" プロンプ
   トキーとしてよく使われる)

誤って <Enter> か <Space> を押してしまい、表示されたテキストを見たい場合は、
g< を使う。これは 'more' が設定されている場合のみ動作する。

タイプされていないキーは、プロンプトを閉じ、通常のコマンドとして扱われる。

hit-enter プロンプトの数を減らすには:
- 'messagesopt' を設定する。
- 'cmdheight' を 2 以上に設定する。
- 'shortmess' にフラグを追加する。
- 'showcmd' と/または 'ruler' をリセットする。
- :echo のテキストが v:echospace 画面セル以下になるようにする。

スクリプトが hit-enter プロンプトを出し、その理由が分からない場合は、
v:scrollstart 変数が役に立つかもしれない。

'mouse' も参照。hit-enter メッセージは hl-Question グループでハイライトされ
る。


                                                more-prompt pager
  -- More --
  -- More -- SPACE/d/j: screen/page/line down, b/u/k: up, q: quit

このメッセージは、画面がメッセージでいっぱいになったときに出る。'more' オプショ
ンがオンのときだけ出る。これは hl-MoreMsg グループでハイライトされる。

タイプ                                          効果
     <CR> か <NL> か j か <Down>                もう 1 行
     d                                          1 ページ下 (半画面)
     <Space> か f か <PageDown> か CTRL-F       1 画面下
     G                                          ずっと下まで、hit-enter
                                                プロンプトまで

     <BS> か k か <Up>                          1 行戻る
     u                                          1 ページ上 (半画面)
     b か <PageUp> か CTRL-B                    1 画面戻る
     g                                          最初に戻る

     q、<Esc> か CTRL-C                         一覧表示を止める
     :                                          一覧表示を止めてコマンドライン
                                                に入る
    <C-Y>                                       モードレスセレクションを
                                                クリップボード
                                                ("* と "+ レジスタ) にヤンク
                                                (コピー) する
    {menu-entry}                                メニューがコマンドラインモード
                                                で定義されているもの。
    <LeftMouse>                                 次のページ (*)

その他のキーを押すと、キーの意味が表示される。

(*) マウスの左ボタンのクリックは、以下の場合のみ動作する:
     - GUI の場合: 画面の最後の行で。
     - 'mouse' に 'r' が含まれている場合 (ただし、テキストの選択は動作しなくな
       る)。


Note: タイプされたキーは端末から直接得られ、マップされず、先行入力は無視され
る。

g< コマンドを使うと、前のコマンドの出力の最後のページを見ることができる。こ
れは、hit-enter プロンプトで誤って <Space> をタイプした場合に特に役に立つ。
