1. コマンドラインの編集                                 cmdline-editing

通常、文字はカーソル位置の前に挿入される。コマンドラインの中では左右のカーソル
キーで移動できる。<Insert> キーで、文字の挿入と上書きの間で切り替えられる。

Note キーボードに機能するカーソルキーまたはその他の特殊キーのいずれかが無い場
合、":cnoremap" を使ってそれらの代わりに別のキーを定義できることに注意。
例えば、tcsh スタイルの編集キーを定義するには:          tcsh-style 
        :cnoremap <C-A> <Home>
        :cnoremap <C-F> <Right>
        :cnoremap <C-B> <Left>
        :cnoremap <Esc>b <S-Left>
        :cnoremap <Esc>f <S-Right>
(<> 記法 <>。これら全てを文字どおりにタイプする)

                                                        cmdline-too-long
コマンドラインが画面に収まる長さより長くなった場合、収まる部分だけが表示され
る。カーソルはこの見える部分の中でしか移動できないので、それを越えて編集するこ
とはできない。

                                                cmdline-history history
入力したコマンドラインは履歴テーブルに記憶される。それらは上下のカーソルキーで
呼び出せる。実際には 5 つの履歴テーブルがある:
- ':' コマンド用
- 検索文字列用
- 式用
- input() 関数のためにタイプされた入力行用。
- デバッグモードのコマンド用
これらは完全に別々である。各履歴は、同じ種類の行を入力しているときにのみアクセ
スできる。
記憶される行数を設定するには 'history' オプションを使う (既定値: 200)。
Notes:
- 古いものと全く同じコマンドラインを入力したとき、古いものは削除される (繰り返
  されたコマンドによって古いコマンドが履歴から押し出されるのを避けるため)。
- タイプされたコマンドのみが記憶される。完全にマッピングから実行されたコマンド
  は履歴に入らない。
- "*" および "#" のようなコマンドから来るものを含め、全ての検索は検索履歴に入
  る。しかしマッピングでは、最後の検索だけが記憶される (長いマッピングが履歴を
  荒らすのを避けるため)。
{Vim が +cmdline_hist 機能付きでコンパイルされたときのみ有効}

コマンドライン上には名前の自動補完がある。cmdline-completion を参照。

                                                        c_CTRL-V
CTRL-V          次の数字以外の文字を文字どおりに挿入する。最大 3 桁の数字が 1
                バイトの 10 進数の値を形成する。数字以外の文字および 3 桁の数
                字はマッピングの対象にならない。これは挿入モードと同じように動
                作する (上記の i_CTRL-V を参照)。
                Note: MS-Windows では、CTRL-V はしばしばテキストの貼り付けに
                マップされている。その場合は代わりに CTRL-Q を使う。
                modifyOtherKeys が有効なとき、Shift キーも押されていない限
                り、特殊なエスケープシーケンスは modifyOtherKeys が無い場合
                のものに変換して戻される。
                                                        c_CTRL-Q
CTRL-Q          CTRL-V と同じ。しかし一部の端末ではフロー制御に使われており、
                その場合は動作しない。

CTRL-SHIFT-V                            c_CTRL-SHIFT-V c_CTRL-SHIFT-Q
CTRL-SHIFT-Q    modifyOtherKeys が有効でない限り、CTRL-V と全く同じように動
                作する。有効な場合は、修飾キー付きのキーのエスケープシーケンス
                を挿入する。GUI では、key-notation が簡略化されずに挿入され
                る。Note: CTRL-SHIFT-V がシステムに横取りされるとき (例えば、
                テキストを貼り付けるため)、多くの場合、代わりに CTRL-SHIFT-Q
                を使える。ただし、一部の端末 (例: GNOME Terminal) では、
                CTRL-SHIFT-Q は確認なしに端末を終了する。

                                                        c_<Left> c_Left
<Left>          カーソルを左へ。ワイルドメニュー補完モード中の動作については
                'wildmenu' を参照。
                                                        c_<Right> c_Right
<Right>         カーソルを右へ。ワイルドメニュー補完モード中の動作については
                'wildmenu' を参照。

<S-Left> または <C-Left>                                c_<C-Left>
                カーソルを 1 WORD 左へ
                                                        c_<S-Right>
<S-Right> または <C-Right>                              c_<C-Right>
                カーソルを 1 WORD 右へ
CTRL-B または <Home>                            c_CTRL-B c_<Home> c_Home
                カーソルをコマンドラインの先頭へ
CTRL-E または <End>                             c_CTRL-E c_<End> c_End
                カーソルをコマンドラインの末尾へ。ワイルドメニュー補完モード中
                の動作については 'wildmenu' を参照。

                                                        c_<LeftMouse>
<LeftMouse>     マウスでクリックした位置へカーソルを移動する。

                                                        c_<MiddleMouse>
<MiddleMouse>   クリップボードの内容を貼り付ける (X11 ではプライマリセレクショ
                ン)。これは CTRL-R * を使うのと似ているが、行の間に CR 文字が
                挿入されない。

CTRL-H                                          c_<BS> c_CTRL-H c_BS
<BS>            カーソルの前の文字を削除する (<BS> キーが望みどおりに動作しな
                い場合は :fixdel を参照)。
                                                        c_<Del> c_Del
<Del>           カーソルの下の文字を削除する (行末では: カーソルの前の文字)
                (<Del> キーが望みどおりに動作しない場合は :fixdel を参照)。
                                                        c_CTRL-W
CTRL-W          カーソルの前の word を削除する。これは 'iskeyword' オプショ
                ンに依存する。
                                                        c_CTRL-U
CTRL-U          カーソル位置と行頭の間の全ての文字を削除する。以前のバージョン
                の vim は行の全ての文字を削除していた。その動作が好ましい場合
                は、以下を .vimrc に追加する:
                        :cnoremap <C-U> <C-E><C-U>

                                                c_<Insert> c_Insert
<Insert>        挿入と上書きの間で切り替える。

{char1} <BS> {char2}    または                          c_digraph
CTRL-K {char1} {char2}                                  c_CTRL-K
                ダイグラフを入力する (digraphs を参照)。{char1} が特殊キーの
                場合、そのキーのコードが <> 形式で挿入される。

CTRL-R {register}                                       c_CTRL-R c_<C-R>
                番号付きレジスタまたは名前付きレジスタの内容を挿入する。CTRL-R
                をタイプしてから 2 文字目をタイプするまでの間は、レジスタの名
                前を入力することが期待されていることを示すために '"' が表示さ
                れる。
                テキストはタイプしたかのように挿入されるが、マッピングおよび短
                縮入力は使われない。ただし、'wildchar' によるコマンドライン補
                完は発動しない。また、コマンドラインを終了させる文字は文字どお
                りに挿入される (<Esc>、<CR>、<NL>、<C-C>)。ただし、<BS> または
                CTRL-W は依然としてコマンドラインを終了させることがあり、その
                場合、残りの文字は別のモードで解釈され、それは意図したものでは
                ないかもしれない。
                特殊レジスタ:
                        '"'     無名レジスタ。最後の削除またはヤンクのテキスト
                                を含む
                        '%'     カレントファイル名
                        '#'     代替ファイル名
                        '*'     クリップボードの内容 (X11: プライマリセレクショ
                                ン)
                        '+'     クリップボードの内容
                        '/'     最後の検索パターン
                        ':'     最後のコマンドライン
                        '-'     最後の小さな (1 行未満の) 削除
                        '.'     最後に挿入されたテキスト
                                                        c_CTRL-R_=
                        '='     式レジスタ: 式を入力するよう促される
                                (expression を参照) (式プロンプトでは動作し
                                ない。副作用を避けるため、バッファまたはカレン
                                トウィンドウの変更などの一部のことは許可されて
                                いない) 結果が List の場合、その要素が行とし
                                て使われる。要素の中に改行を含めることもでき
                                る。
                                結果が Float の場合、自動的に String に変換さ
                                れる。
                                Note カーソルを移動するだけで何も挿入したくな
                                い場合、式が空文字列に評価されるようにしなけれ
                                ばならないことに注意。例:
                                        <C-R><C-R>=setcmdpos(2)[-1]<CR>
                レジスタについては registers を参照。
                実装の詳細: expression レジスタを使用し setcmdpos() を呼び出
                すとき、これは結果の文字列を挿入する前に位置を設定する。後で位
                置を設定するには CTRL-R CTRL-R を使う。

CTRL-R CTRL-F                           c_CTRL-R_CTRL-F c_<C-R>_<C-F>
CTRL-R CTRL-P                           c_CTRL-R_CTRL-P c_<C-R>_<C-P>
CTRL-R CTRL-W                           c_CTRL-R_CTRL-W c_<C-R>_<C-W>
CTRL-R CTRL-A                           c_CTRL-R_CTRL-A c_<C-R>_<C-A>
CTRL-R CTRL-L                           c_CTRL-R_CTRL-L c_<C-R>_<C-L>
                カーソルの下のオブジェクトを挿入する:
                        CTRL-F  カーソルの下のファイル名
                        CTRL-P  カーソルの下のファイル名。gf と同様に 'path'
                                で展開される
                        CTRL-W  カーソルの下の単語
                        CTRL-A  カーソルの下の WORD。WORD を参照
                        CTRL-L  カーソルの下の行

                'incsearch' が設定されているとき、現在表示されているマッチの末
                尾のカーソル位置が使われる。CTRL-W では、既にタイプされた単語
                の部分は再度挿入されない。

                                        c_CTRL-R_CTRL-R c_<C-R>_<C-R>
                                        c_CTRL-R_CTRL-O c_<C-R>_<C-O>
CTRL-R CTRL-R {register CTRL-F CTRL-P CTRL-W CTRL-A CTRL-L}
CTRL-R CTRL-O {register CTRL-F CTRL-P CTRL-W CTRL-A CTRL-L}
                カーソルの下のレジスタまたはオブジェクトを挿入する。c_CTRL-R
                と同じように動作するが、テキストを文字どおりに挿入する。例え
                ば、レジスタ a が "xy^Hz" を含んでいる場合 (^H はバックスペー
                ス)、"CTRL-R a" は "xz" を挿入するが、"CTRL-R CTRL-R a" は
                "xy^Hz" を挿入する。

CTRL-\ e {expr}                                         c_CTRL-\_e
                {expr} を評価し、コマンドライン全体をその結果で置き換える。式
                の入力を促されるので、<Enter> をタイプして終了する。とはいえ、
                これが最も役に立つのはマッピングの中である。expression を参
                照。
                式の結果を挿入するには c_CTRL-R_= を参照。役に立つ関数は
                getcmdtype()、getcmdline()、および getcmdpos() である。
                カーソル位置は変わらない。ただし、カーソルが行末にあった場合を
                除く。その場合は末尾に留まる。カーソル位置を設定するには
                setcmdpos() を使える。
                厄介な副作用を避けるため、式の評価には sandbox が使われる。
                例:
                        :cmap <F7> <C-\>eAppendSome()<CR>
                        :func AppendSome()
                           :let cmd = getcmdline() .. " Some()"
                           :" カーソルを ) の上に置く
                           :call setcmdpos(strlen(cmd))
                           :return cmd
                        :endfunc
                これは再帰的には動作しないので、既に式を編集しているときは動作
                しない。しかし、マッピングの中で使うことはできる。

                                                        c_CTRL-Y
CTRL-Y          モードレスセレクションがあるとき、そのセレクションをクリップ
                ボードにコピーする。modeless-selection
                セレクションが無い場合、CTRL-Y が文字として挿入される。ワイル
                ドメニュー補完モード中の動作については 'wildmenu' を参照。

CTRL-M または CTRL-J            c_CTRL-M c_CTRL-J c_<NL> c_<CR> c_CR
<CR> または <NL>        入力されたコマンドを開始する

CTRL-[                                          c_CTRL-[ c_<Esc> c_Esc
<Esc>           タイプされ、'cpoptions' に 'x' が含まれていないとき、コマンド
                ラインモードを実行せずに終了する。それ以外の場合は、入力された
                コマンドを開始する (これは vi 互換である)。コマンドラインを放
                棄するには、マッピングの中で CTRL-C を使う (以下を参照)。
                Note: キーボード上で <Esc> キーが押しにくい場合、CTRL-[ を使う
                ように自分を訓練する。
                                                        c_CTRL-C
CTRL-C          コマンドラインを実行せずに終了する

<Up>            先頭が現在のコマンドラインにマッチする、より古いコマンドライン

                の動作については 'wildmenu' を参照。
                {Vim が +cmdline_hist 機能付きでコンパイルされたときのみ有効}
                                                        c_<Down> c_Down
<Down>          先頭が現在のコマンドラインにマッチする、より新しいコマンドライ
                ンを履歴から呼び出す (以下を参照)。ワイルドメニュー補完モード
                中の動作については 'wildmenu' を参照。
                {Vim が +cmdline_hist 機能付きでコンパイルされたときのみ有効}

                                                        c_<S-Up> c_<PageUp>
<S-Up> または <PageUp>

                コマンドライン補完 (cmdline-completion を参照)

                                                        c_CTRL-_
CTRL-_          a - ヘブライ語と英語のキーボードモードの間で切り替える。これは
                コマンドラインに固有で、hkmap とは関係ない。
                これは、コマンドライン、検索、短縮入力などでヘブライ語のテキス
                ト入力が必要なときに便利である。Vim が +rightleft 機能付きで
                コンパイルされ、'allowrevins' オプションが設定されている場合に
                のみ適用される。
                rileft.txt を参照。

                b - ペルシア語と英語のキーボードモードの間で切り替える。これは
                コマンドラインに固有で、fkmap とは関係ない。ペルシア語キーボー
                ドモードでは、文字は逆挿入の方法で挿入される。これは、コマンド
                ライン、検索、短縮入力などでペルシア語のテキスト入力が必要なと
                きに便利である。Vim が +farsi 機能付きでコンパイルされている
                場合にのみ適用される。farsi.txt を参照。

                                                        c_CTRL-^
CTRL-^          言語 :lmap マッピングおよび/またはインプットメソッドの使用を
                切り替える。
                検索コマンドのパターンをタイプしていて 'imsearch' が -1 でない
                とき、VAL は 'imsearch' の値で、それ以外の場合 VAL は
                'iminsert' の値である。
                言語マッピングが定義されているとき:
                - VAL が 1 の場合 (langmap マッピングが使われている)、0 になる
                  (langmap マッピングは使われない)。
                - VAL が 1 でなかった場合、1 になり、従って langmap マッピング
                  が有効になる。
                言語マッピングが定義されていないとき:
                - VAL が 2 の場合 (インプットメソッドが使われている)、0 になる
                  (インプットメソッドは使われない)
                - VAL が他の値の場合、2 になり、従ってインプットメソッドが有効
                  になる。
                これらの言語マッピングは通常、キーボードが生成するものとは異な
                る文字をタイプするのに使われる。'keymap' オプションを使って、
                それらを丸ごといくつもインストールできる。コマンドラインに入る
                とき、コマンドをタイプすることが期待されるので、langmap マッピ
                ングはオフになる。CTRL-^ でオンにした後、新しい状態は次のコマ
                ンドまたは検索パターンには再び使われない。

                                                c_CTRL-]
CTRL-]          文字を挿入せずに短縮入力を発動する。

コマンドラインでの Emacs スタイルの編集については emacs-keys を参照。

<Up> キーおよび <Down> キーは、現在のコマンドラインを検索文字列として使う。次/
前のコマンドラインの先頭がこの文字列と比較される。マッチした最初の行が新しいコ
マンドラインになる。これら 2 つのキーを繰り返しタイプするとき、同じ文字列が再
度使われる。例えば、これは前の置換コマンドを見つけるのに使える: ":s" とタイプ
し、それから <Up> をタイプする。目的のコマンドラインが表示されるまで <S-Up> を
何回かタイプしても、同じことができる。(Note: シフト付きの矢印キーは全ての端末
で動作するわけではない)

                                                        :his :history
:his[tory]      最後に入力されたコマンドの履歴を表示する。
                {Vim が +cmdline_hist 機能付きでコンパイルされたときのみ有効}

:his[tory] [{name}] [{first}][, [{last}]]
                履歴 {name} の内容を一覧表示する。{name} には以下が使える:
                c[md]    または :               コマンドライン履歴
                s[earch] または / または ?      検索文字列履歴
                e[xpr]   または =               式レジスタ履歴
                i[nput]  または @               入力行履歴
                d[ebug]  または >               デバッグコマンド履歴
                a[ll]                           上記の全て

                数値 {first} および/または {last} が与えられた場合、履歴から該
                当する範囲のエントリが一覧表示される。これらの数値は以下の形式
                で指定できる:
                                                        :history-indexing
                正の数は、:history の一覧の最初の列に表示されるエントリの絶対
                インデックスを表す。この番号は、他のエントリが削除されても固定
                されたままである。(E1510 を参照)

                負の数はエントリの相対位置を意味し、最新のエントリ (インデック
                ス -1 を持つ) から後方へ数える。

                例:
                検索履歴からエントリ 6 から 12 を一覧表示する:
                        :history / 6,12

                全ての履歴から最後から 2 番目のエントリを一覧表示する:
                        :history all -2

                全ての履歴から最新の 2 つのエントリを一覧表示する:
                        :history all -2,

:keepp[atterns] {command}                       :keepp :keeppatterns
                検索履歴に何も追加せずに {command} を実行する。また、:s また
                は :& の場合は、最後の置換パターンまたは置換文字列を変更せず
                に実行する。

2. コマンドラインの補完                                 cmdline-completion

コマンドラインを編集しているとき、カーソルの前の単語を補完するためにいくつかの
コマンドが使える。これは以下に対して使用可能である:

- コマンド名: コマンドラインの先頭で。
- ++opt の値。
- タグ: ":tag" コマンドの後でのみ。
- ファイル名: ファイル名を受け付けるコマンドの後、またはファイル名を設定できる
  オプションの設定の後でのみ。これはファイル名補完と呼ばれる。
- シェルコマンド名: ":!cmd"、":r !cmd"、および ":w !cmd" の後。$PATH が使われ
  る。
- オプション: ":set" コマンドの後でのみ。
- マッピング: ":map" または類似のコマンドの後でのみ。
- 変数名および関数名: ":if"、":call"、または類似のコマンドの後でのみ。

マッチが非常に多いときに長い遅延が起きるのを避けるため、ヘルプ項目のマッチ数は
制限されている (現在は 300)。

タイプ中の自動補完 (<Tab> のようなキーを押さずに) については、
cmdline-autocompletion を参照。

使用できるコマンドは以下である:

                                                        c_CTRL-D
CTRL-D          カーソルの前のパターンにマッチする名前を一覧表示する。ファイル
                名を表示するとき、ディレクトリはハイライトされる ('highlight'
                オプションを参照)。'suffixes' がマッチする名前は末尾に移動され
                る。
                マッチするタグのファイルを一覧表示するために、'wildoptions' オ
                プションを "tagfile" に設定できる。
                                c_CTRL-I c_wildchar c_<Tab> /_<Tab>
'wildchar' オプション
                カーソルの前のパターンでマッチが行われる。マッチ (複数ある場合
                は最初のマッチ) がパターンの代わりに挿入される。(Note: マクロ
                の中では動作しない。なぜなら、<Tab> または <Esc> がたいてい
                'wildchar' として使われ、それらは一部のマクロで特別な意味を持
                つからである。) 再度タイプされ、複数のマッチがあったとき、次の
                マッチが挿入される。最後のマッチの後は、再び最初のマッチが使わ
                れる (折り返し)。

                検索コンテキストでは、補完を発動する代わりに文字どおりの <Tab>
                を検索するには、<CTRL-V><Tab> または "\t" を使う。

                動作は 'wildmode' オプションで変更できる。
                                                        c_<S-Tab>
<S-Tab>         'wildchar' または <Tab> と同様だが、最後のマッチから始めて、そ
                れから前のマッチへ移動する。
                <S-Tab> はどこでも動作するわけではない。
                                                        c_CTRL-N
CTRL-N          複数のマッチを得た 'wildchar' を使った後は、次のマッチへ移動す
                る。それ以外の場合は、より新しいコマンドラインを履歴から呼び出
                す。
                                                        c_CTRL-P
CTRL-P          複数のマッチを得た 'wildchar' を使った後は、前のマッチへ移動す
                る。それ以外の場合は、より古いコマンドラインを履歴から呼び出
                す。
                                                        c_CTRL-A
CTRL-A          カーソルの前のパターンにマッチする全ての名前が挿入される。
                                                        c_CTRL-L
CTRL-L          カーソルの前のパターンでマッチが行われる。マッチが 1 つの場合、
                それがパターンの代わりに挿入される。複数のマッチがある場合、最
                も長い共通部分がパターンの代わりに挿入される。結果がパターンよ
                り短い場合、補完は行われない。
                                                        /_CTRL-L
                'incsearch' が設定されていて、"/" または "?" の検索パターンを
                入力していて、現在のマッチが表示されているとき、CTRL-L は現在
                のマッチの末尾から 1 文字を追加する。'ignorecase' および
                'smartcase' が設定されていて、コマンドラインに大文字が無い場
                合、追加された文字は小文字に変換される。
                                                    c_CTRL-G /_CTRL-G
CTRL-G          'incsearch' が設定されていて、"/" または "?" の検索パターンを
                入力していて、現在のマッチが表示されているとき、CTRL-G は次の
                マッチへ移動する。search-offset は <CR> が押されたときに適用
                されるが、マッチハイライトには影響しない。
                前のマッチへ移動するには CTRL-T を使う。ヒント: 通常のキーボー
                ドでは G は T の下にある。
                                                    c_CTRL-T /_CTRL-T
CTRL-T          'incsearch' が設定されていて、"/" または "?" の検索パターンを
                入力していて、現在のマッチが表示されているとき、CTRL-T は前の
                マッチへ移動する。search-offset は <CR> が押されたときに適用
                されるが、マッチハイライトには影響しない。次のマッチへ移動する
                には CTRL-G を使う。ヒント: 通常のキーボードでは T は G の上に
                ある。

'wildchar' オプションの既定値は <Tab> である (Vi 互換モードでは CTRL-E。以前の
バージョンでは <Esc> が使われていた)。パターンの中では、ファイル名をマッチする
ときに標準の wildcards が受け付けられる。

'wildchar' または CTRL-N を繰り返すと、マッチを巡回し、最終的にタイプしたもの
に戻ってくる。最初のマッチが望んだものでない場合、<S-Tab> または CTRL-P を使っ
て、タイプしたものへ直接戻れる。

'wildmenu' オプションを設定すると、コマンドラインのすぐ上にマッチを表示できる。

'wildoptions' オプションは、'wildmenu' でポップアップメニューを使うため、およ
びファジーマッチを使うための追加の設定を提供する。

'wildignorecase' オプションを設定すると、ファイル名の大文字と小文字を無視でき
る。その他のテキスト (例: コマンド名) の補完には、代わりに 'ignorecase' オプ
ションが使われる (ただし、ファジーマッチは常に大文字と小文字を無視する)。

tcsh の autolist 補完が好きな場合、このマッピングを使える:
        :cnoremap X <C-L><C-D>
(X は使用するコマンドキーで、<C-L> は CTRL-L、<C-D> は CTRL-D である)
これは最も長いマッチを見つけ、それからマッチする全てのファイルを一覧表示する。

tcsh の autolist 補完が好きな場合、'wildmode' オプションを使ってそれをエミュ
レートできる。例えば、これは autolist=ambiguous を模倣する:
        :set wildmode=longest,list
これは最初の 'wildchar' で最も長いマッチを見つけ、それからその次でマッチする全
てのファイルを一覧表示する。

                                        complete-script-local-functions
ユーザー関数の名前を補完するとき、スクリプトローカル関数を見つけるには "s:" を
前に付ける。

                                                        suffixes
ファイル名補完では、'suffixes' オプションを使って、ほぼ同じ名前のファイル間の
優先順位を設定できる。複数のマッチがある場合、'suffixes' オプションにある拡張
子を持つファイルは無視される。既定値は ".bak,~,.o,.h,.info,.swp,.obj" で、これ
は ".bak"、"~"、".o"、".h"、".info"、".swp"、および ".obj" で終わるファイルが
時々無視されることを意味する。

空のエントリ、つまり 2 つの連続したコンマは、"." を含まない、つまり拡張子が無
いファイル名にマッチする。これは "prog" を無視して "prog.c" を優先するのに役立
つ。

例:

  パターン:     ファイル:                       マッチ:
   test*        test.c test.h test.o            test.c
   test*        test.h test.o                   test.h および test.o
   test*        test.i test.h test.c            test.i および test.c

2 つのドットを持つ拡張子を無視することはできない。

複数のマッチするファイルがある場合 ('suffixes' オプションにマッチするものを無
視した後)、最初のファイル名が挿入される。'wildchar' を 2 回タイプして、補完さ
れたマッチが同じままのとき、マッチが 1 つだけであることが分かる。'wildchar'、
CTRL-N、または CTRL-P を入力することで、他のマッチに移動できる。全てのファイル
が含まれ、'suffixes' オプションにマッチする拡張子を持つものも含まれる。

ある拡張子を持つファイルを完全に無視するには 'wildignore' を使う。

タイプしたテキストの末尾で終わるファイルのみにマッチさせるには "$" を追加する。
例えば、".c" で終わるファイルのみにマッチさせるには:
        :e *.c$
これは ".cpp" で終わるファイルにはマッチしない。"$" が無い場合はマッチする。

xterm で CTRL-P のために <S-Tab> を使いたい場合は、このコマンドを .cshrc に入
れる:
        xmodmap -e "keysym Tab = Tab Find"
そしてこれを .vimrc に:
        :cmap <Esc>[1~ <C-P>
                                                complete-set-option
:set= を使ってオプションを設定するとき、'=' の直後で 'wildchar' を押すこと
で、オプションの古い値を得られる。例えば、":set dir=" の後で 'wildchar' をタイ
プすると、'dir' の現在の値が挿入される。これは、ファイル名を取るオプションに対
するファイル名補完より優先される。

:set=、:set+=、または :set^= を使うとき、定義済みの名前または構文を持つ
か (例: 'diffopt'、'listchars')、または 1 文字のフラグのリストである (例:
'shortmess') 文字列オプションも、'wildchar' を使うと補完のための可能な値のリス
トを表示する。

:set-= を使うとき、'diffopt' または 'backupdir' のようなコンマ区切りのオプ
ションは、各項目を個別に表示する。'shortmess' のようなフラグリストのオプション
は、古い値全体および個々のフラグの両方を表示する。それ以外の場合、補完は単に古
い値全体で埋められる。

るには CTRL-V CTRL-J を使う。"^@" が表示される。'|' を使うのが好ましい方法であ
る。しかし外部コマンドでは <NL> を使わなければならない。なぜなら '|' は外部コ
マンドに含まれるからである。<NL> の特別な意味を避けるには、その前にバックスラッ
シュを置かなければならない。例:

いことに注意。

        :3                      3 行目へ移動する

換である)。例えば:

トファイル名および代替ファイル名に展開される ("editing files" の章 :_% :_#
を参照)。

Amiga では、1 つのファイル名が引数として期待される場合、ファイル名に埋め込まれ
た空白が許可される。末尾の空白は、バックスラッシュまたは CTRL-V でエスケープさ
れない限り無視される。Note ":next" コマンドはファイル名を区切るのに空白を使う
ことに注意。ファイル名に空白を含めるには、空白をエスケープする。例:
        :next foo\ bar goes\ to school\
3 つのファイル "foo bar"、"goes to"、および "school " の編集を開始する。

コマンドの中で特殊文字 '"' または '|' を使いたい場合、またはファイル名の中で
'%' または '#' を使いたい場合、それらの前にバックスラッシュを置く。範囲の中お
よび ":substitute" コマンドの中では、バックスラッシュは必要ない。
`= も参照。

                                                        :_!
Ex コマンドの後の '!' (バング) 文字は、そのコマンドを異なる方法で動作させ
る。'!' はコマンドの直後に、間に空白を入れずに置かなければならない。空白を入れ
た場合、'!' はコマンドの引数とみなされ、それは異なる意味を持つ。例えば:
        :w! name        カレントバッファをファイル "name" に書き込み、既存の
                        ファイルを上書きする
        :w !name        カレントバッファを標準入力としてコマンド "name" に送る

4. Ex コマンドラインの範囲      cmdline-ranges [range] E16

一部の Ex コマンドはその前に行範囲を受け付ける。これは [range] と表記される。
それは ',' または ';' で区切られた 1 つ以上の行指定子で構成される。

基本はユーザーマニュアルの 10.3 節で説明されている。

Vim9 script では、継続行との曖昧さを避けるため、範囲の前にコロンを付ける必要
がある。例えば、"+" は範囲に使えるが、式の継続でもある:
        var result = start
        + print
ここでのように "+" が範囲である場合、Vim9 script ではその前にコロンを付けなけ
ればならない (そうしないとエラー E1050 になる):
        vim9script
        :+ print

                                                                :, :;
';' で区切られているとき、次の行指定子を解釈する前に、カーソル位置がその行に設
定される。',' ではこれは起こらない。
例:
   4,/this line/
        4 行目から、カーソル行の後で "this line" にマッチするところまで。
   5;/that line/
        5 行目から、5 行目の後で "that line" にマッチするところまで。

ほとんどのコマンドの既定の行指定子はカーソル位置だが、コマンド ":write" および
":global" は既定でバッファ全体 (1,$) を持つ。

コマンドに必要な数より多くの行指定子が与えられた場合、コンマで区切られていると
きは、左端の 1 つまたは複数のものが無視される。例えば、この中の -2,+:
        :-2,+,-2,. print
セミコロンで区切られているときは、左端の指定子から最後から 2 番目のものまでが
合計される。例えば、この中では -4 + 3 - 1 = -2:
        :-4;+3;-1;+2 print

行番号は以下で指定できる:                       :range {address}
        {number}        絶対行番号  E1247
        .               現在の行                                   :.
        $               バッファの最終行                           :$
        %               1,$ と同じ (バッファ全体)                  :%
        *               '<,'> と同じ (最後に選択されたビジュアル領域の行。
                        以下の :star を参照)
        'x              マーク x の位置の行                        :'x
                        (x は任意の {a-z} のマーク)
        'X              マーク X の位置の行                        :'X
                        (X は任意の {A-Z0-9} のマーク。ただし X が別の
                        バッファにあるときは範囲には使えない)
        '[              最も最近の変更またはヤンクの最初の行       :'[
        ']              最も最近の変更またはヤンクの最後の行       :']
        '<              最も最近選択されたビジュアル領域の         :'<
                        最初の行
        '>              最も最近選択されたビジュアル領域の         :'>
                        最後の行
        ''              最後のジャンプの前の位置の行、             :''
                        または最後に "m'"/"m`" コマンドが与えられた位置の行
                        (ただし、それがカレントバッファに無い場合、'' は 1)
        '"              最後にバッファを抜けたときの               :'quote
                        カーソル位置の行
        '^              最後に挿入モードが停止したときの           :'^
                        カーソル位置の行
        '.              最後にバッファが変更されたときの           :'.
                        カーソル位置の行
        '(              現在の文の最初の文字の行                   :'(
        ')              現在の文の終わりの後の最初の文字の行       :')
        '{              カーソルを含む段落の前の最初の空行         :'{
        '}              カーソルを含む段落の後ろの最初の空行       :'}
        /{pattern}[/]   {pattern} がマッチする次の行               :/
                                以下の :range-pattern も参照
        ?{pattern}[?]   {pattern} がマッチする前の行               :?
                                以下の :range-pattern も参照
        \/              最も最近の検索パターンがマッチする次の行
        \?              最も最近の検索パターンがマッチする前の行
        \&              最も最近の置換パターンがマッチする次の行

        Note: "次の行" および "前の行" は、現在の行に現れるマッチを含まない。

                                                :range-offset
各行指定子の後には、1 つ以上の '+' または '-' および省略可能な数値を続けること
ができる。その値は前の行番号に加算または減算される。従って、例えば、'x+2 はマー
ク x を含む行の 2 行後ろの行である。数値が省略された場合、各 '+' に対して +1、
各 '-' に対して -1 が使われるので、例えば、'x++ と 'x+2 は同義である。'+' また
は '-' の前に何も無い場合、[range] の最初の行番号については、現在の行が相対的
な開始点として使われる。従って、-,. は
"現在の行の前の行から現在の行まで" を意味する。[range] の 2 番目の行番号の値
は、コンマまたはセミコロンのどちらで行番号が区切られているかによって決まる
(:, および :; を参照)。
例: カーソルがこの行の下の行の中にある場合、これらのコマンドのどれも、タグ行
":range-offset" および行 "各行指定子..." を表示する:
        :-11;+1 print
        :-----------,-10 print
        :?各行指定子?-;+ print
        :'{+,'{+2 print
        :'{+1;')-1 print
                                                :range-closed-fold
コンマの後の行番号が閉じた折り畳みの中にあるとき、それは折り畳みの最後の行に調
整されるので、折り畳み全体が含まれる。

数値が加算されるとき、これは折り畳みの最後の行への調整の後で行われる。これは、
これらの行が追加で範囲に含まれることを意味する。例えば:
   :3,4+2print
このテキストに対して:
        1 one
        2 two
        3 three
        4 four FOLDED
        5 five FOLDED
        6 six
        7 seven
        8 eight
4 行目および 5 行目が閉じた折り畳みである場合、最終的に 3 行目から 7 行目が表
示される。7 は範囲の "4" から来ており、それは閉じた折り畳みの終わり、つまり 5
に調整され、それからオフセット 2 が加算される。

減算の例 (あまり役に立たない):
   :2,4-1print
このテキストに対して:
        1 one
        2 two
        3 three FOLDED
        4 four FOLDED
        5 five FOLDED
        6 six FOLDED
        7 seven
        8 eight
3 行目から 6 行目が閉じた折り畳みである場合、最終的に 2 行目から 6 行目が表示
される。6 は範囲の "4" から来ており、それは閉じた折り畳みの終わり、つまり 6 に
調整され、それから 1 が減算され、それでもまだ閉じた折り畳みの中にあるので、そ
の折り畳みの最後の行、つまり 6 が使われる。

                                                        :range-pattern
{pattern} の後の "/" および "?" は、パターンをその後に続くものから区切るために
必要である。

"/" および "?" の前に別のアドレスを置くことができる。検索はそこから開始す
る。';' を使う場合との違いは、カーソルが移動しないことである。
例:
        /pat1//pat2/    カーソルを移動せずに、"pat1" を含む行の後で
                        "pat2" を含む行を見つける。
        7;/pat2/        7 行目の後で "pat2" を含む行を見つけ、
                        カーソルは 7 行目に残す。

{number} は 0 とファイルの行数の間でなければならない。0 (ゼロ) を使うとき、ほ
とんどのコマンドでは、これは 1 と解釈される。それをカウントとして使うコマンド
は、実際にゼロとして使う (:tag、:pop など)。一部のコマンドは、ゼロを
"最初の行の前" と解釈する (:read、検索パターンなど)。

例:
        .+3             カーソルの 3 行下
        /that/+1        "that" を含む次の行の 1 行下
        .,$             現在の行からファイルの終わりまで
        0;/that         "that" を含む最初の行。最初の行でも
                        マッチする。
        1;/that         1 行目の後の "that" を含む最初の行

一部のコマンドでは、コマンドの後にカウントを指定できる。このカウントは、最後の
行指定子で与えられた行 (既定はカーソル行) から始まる、使用する行数として使われ
る。カウントを受け付けるコマンドは、範囲を使うがファイル名の引数を持たないもの
である (ファイル名も数値になりうるため)。カウントは負にはできない。

例:
        :s/x/X/g 5      現在の行およびそれに続く 4 行で 'x' を 'X' で
                        置換する
        :23d 4          23、24、25、および 26 行目を削除する


折り畳みと範囲

折り畳みが有効なとき、行番号は閉じた折り畳み全体を含むように丸められる。
fold-behavior を参照。


逆順の範囲                                              E493

範囲は小さい方の行番号を先にするべきである。そうでない場合、Vim は行番号を入れ
替えるかどうか尋ねる。
        Backwards range given, OK to swap
これはグローバルコマンド ":g" の中では行われない。

質問を避けるには、コマンドの前に ":silent" を使える。その場合、範囲は常に入れ
替えられる。


カウントと範囲                                          N:

":" を入力する前にカウントを与えると、これは以下に変換される:
                :.,.+(count - 1)
言葉で言うと: カーソル位置およびその後ろの "count" 行。例: 3 行を削除するには:

                3:d<CR>         は以下に変換される: .,.+2d<CR>


ビジュアルモードと範囲
                                                        v_:
{Visual}:       ビジュアル選択された行を範囲としてコマンドラインを開始する。こ
                の範囲にはコード :'<,'> が使われ、これにより、異なるビジュア
                ル選択された行に対してコマンドを繰り返すために、コマンドライン
                履歴から類似の行を選択することが可能になる。

:*                                              :star :star-visual-range
                ビジュアルモードが既に終了しているとき、ビジュアル領域を範囲と
                して使う短い方法は :* である。これには、"*" が 'cpo' に現れ
                ないことが必要である。cpo-star を参照。そうでない場合は
                :'<,'> をタイプしなければならない
                'cpo' に "*" が含まれているときについては、:star-compatible
                を参照。

5. Ex コマンドラインのフラグ                            ex-flags

これらのフラグは Ex コマンドの一部でサポートされている。それらは、コマンドを実

6. Ex の特殊文字                                        cmdline-special

Note: これらは実行されるコマンドラインにおける特殊文字である。タイプ中に特殊な
ものを挿入したい場合は、CTRL-R コマンドを使える。例えば、"%" はカレントファイ
ル名を表すが、CTRL-R % はカレントファイル名をすぐに挿入する。c_CTRL-R を参
照。

Note: Vim script で特殊文字の効果を避けたい場合は、fnameescape() を使うとよ
いだろう。`= も参照。


Ex コマンドでは、ファイル名を使える場所で、以下の文字が特別な意味を持つ。これ
らは式関数 expand() でも使える。
        %       カレントファイル名に置き換えられる。              :_% c_%
        #       代替ファイル名に置き換えられる。                  :_# c_#
                これはウィンドウごとに記憶される。
        #n      (n は数値) バッファ n のファイル名に置き換え      :_#0 :_#n
                られる。"#0" は "#" と同じ。                             c_#n
        ##      引数リストの全ての名前を空白で区切って            :_## c_##
                連結したものに置き換えられる。名前の中の各空白の
                前にはバックスラッシュが置かれる。
        #<n     (n は数値 > 0) 古いファイル名 n に置き換え        :_#< c_#<
                られる。番号を得るには :oldfiles または
                v:oldfiles を参照。                                   E809
                {Vim が +eval および +viminfo 機能付きでコンパイル
                されたときのみ有効}
Vim9-script では # はコメントを開始するのに使われるので、代替ファイル名には
%% を使う:
        %       カレントファイル名に置き換えられる。
        %%      代替ファイル名に置き換えられる。                :_%% c_%%
        %%n     (n は数値) バッファ n のファイル名に置き換え    :_%%0 :_%%n
                られる。"%%0" は "%%" と同じ。                           c_%%n
        %%%     引数リストの全ての名前を空白で区切って          :_%%% c_%%%#
                連結したものに置き換えられる。
        %%<n    (n は数値 > 0) 古いファイル名 n に置き換え      :_%%< c_%%<
                られる。

Note "#<n" を除くこれらは、タイプされたとおりのファイル名を与えることに注意。
絶対パスが必要な場合 (別のディレクトリからファイル名を使うとき)、":p" を追加す
る必要がある。filename-modifiers を参照。

"#<n" 項目は絶対パスを返すが、ホームディレクトリの下のファイルについては "~/"
で始まる。

Note コマンドがファイル名を正しく解釈するように、空白の前にバックスラッシュが
挿入されることに注意。しかしシェルコマンドではこれは起こらない。それらについて
は、おそらく引用符を使う必要があるだろう (これは引用符およびワイルドカードを含
むファイルでは失敗する):
        :!ls "%"
        :r !spell "%"

'%' および '#' の特別な意味を避けるには、その前にバックスラッシュを挿入する。
詳細: その前にバックスラッシュがあるとき、バックスラッシュがいくつあっても、特
別な意味は常にエスケープされる。
        入力するもの:           結果
           #                    alternate.file
           \#                   #
           \\#                  \#
`= も参照。

                                                        E499 E500
Note: これらは文字どおりにタイプするもので、特殊キーではない!
                                                        :<cword> <cword>
        <cword>    カーソルの下の単語に置き換えられる (star と同様)
                                                        :<cWORD> <cWORD>
        <cWORD>    カーソルの下の WORD に置き換えられる (WORD を参照)
                                                        :<cexpr> <cexpr>
        <cexpr>    カーソルの下の単語に、C の式を形成するためにさらに含めたも
                   のに置き換えられる。例えば、カーソルが "ptr->arg" の "arg"
                   の上にあるとき、結果は "ptr->arg" になる。カーソルが
                   "list[idx]" の "]" の上にあるとき、結果は "list[idx]" にな
                   る。これは v:beval_text に使われる。
                                                        :<cfile> <cfile>
        <cfile>    カーソルの下のパス名に置き換えられる (gf が使うものと同様)
                                                        :<afile> <afile>
        <afile>    自動コマンドを実行しているとき、操作されているバッファのファ
                   イル名、または読み込みまたは書き込みのためのファイルに置き
                   換えられる。 E495
                                                        :<abuf> <abuf>
        <abuf>     自動コマンドを実行しているとき、現在有効なバッファ番号に置
                   き換えられる。全てのイベントで設定されるわけではない。
                   bufnr() も参照。":r file" および ":so file" では、それは
                   カレントバッファであり、読み込まれているファイルはバッファ
                   の中には無い。 E496
                                                        :<amatch> <amatch>
        <amatch>   自動コマンドを実行しているとき、この自動コマンドが実行され
                   る原因となったマッチに置き換えられる。 E497
                   ファイル名がマッチに使われないとき (FileType、Syntax、およ
                   び SpellFileMissing イベントの場合)、<afile> とは異なる。
                   マッチがファイル名に対するものであるとき、それはフルパスに
                   展開される。
                                                        :<sfile> <sfile>
        <sfile>    :source コマンドを実行しているとき、読み込まれたファイル
                   のファイル名に置き換えられる。 E498
                   旧来の関数を実行しているとき、<stack> と同様に、コールスタッ
                   クに置き換えられる (これは後方互換性のためであり、<stack>
                   または <script> を使うのが好ましい)。
                   Vim9 script では、関数の中で <sfile> を使うとエラー E1245
                   になる。
                   Note <sfile> がスクリプトの中で使われていないとき、
                   filename-modifiers は役に立たないことに注意。
                                                        :<stack> <stack>
        <stack>    コールスタックに置き換えられる。関数行については "function
                   {function-name}[{lnum}]"、スクリプト行については "script
                   {file-name}[{lnum}]" を使い、項目の間には ".." を使う。例:
                   "function {function-name1}[{lnum}]..{function-name2}[{lnum}]"
                   コールスタックが無い場合、エラー E489 になる。
                                                        :<script> <script>
        <script>   :source コマンドを実行しているとき、読み込まれたファイル
                   のファイル名に置き換えられる。関数を実行しているとき、それ
                   が定義されているスクリプトのファイル名に置き換えられる。
                   ファイル名を決定できない場合、エラー E1274 になる。
                                                        :<slnum> <slnum>
        <slnum>    :source コマンドを実行しているとき、行番号に置き換えられ
                   る。 E842
                   関数を実行しているとき、それは関数の開始からの相対的な行番
                   号である。
                                                        :<sflnum> <sflnum>
        <sflnum>   スクリプトを実行しているとき、行番号に置き換えられる。
                   <sflnum> はどんな状況でもスクリプトの行番号に置き換えられる
                   点で、<slnum> と異なる。 E961
                                                        :<client> <client>
        <client>   server2client() で最後に受信したメッセージの {clientid}
                   に置き換えられる

                                                         filename-modifiers
:_%: ::8 ::p ::. ::~ ::h ::t ::r ::e ::s ::gs ::S
     %:8 %:p %:. %:~ %:h %:t %:r %:e %:s %:gs %:S
ファイル名修飾子は "%"、"#"、"#n"、"<cfile>"、"<sfile>"、"<afile>"、または
"<abuf>" の後で使える。それらは fnamemodify() 関数でも使われる。

これらの修飾子を、この順序で与えることができる:
        :p      ファイル名をフルパスにする。最初の修飾子でなければならない。ま
                た、"~/" (および Unix および VMS では "~user/") をホームディレ
                クトリのパスに変更する。名前がディレクトリの場合、末尾にパス区
                切りが追加される。存在せず、絶対パスを持たないファイル名につい
                ては、結果は予測できない。MS-Windows では、8.3 ファイル名が長
                い名前に展開される。
        :8      パスを 8.3 短縮形式に変換する (現在は MS-Windows でのみ)。パス
                のうち、既存のパスである部分にできるだけ多く作用する。
        :~      可能な場合、ファイル名をホームディレクトリからの相対パスにす
                る。ファイル名がホームディレクトリの下に無い場合、ファイル名は
                変更されない。
        :.      可能な場合、ファイル名をカレントディレクトリからの相対パスにす
                る。ファイル名がカレントディレクトリの下に無い場合、ファイル名
                は変更されない。
                最大限に短くするには ":~:." を使う。
        :h      ファイル名の先頭部分 (最後の要素および全ての区切りが除去され
                る)。:e、:r、または :t と一緒には使えない。
                繰り返して、末尾のいくつかの要素を除去できる。
                ファイル名がパス区切りで終わっているとき、パス区切りだけが除去
                される。従って、ディレクトリ名に対する ":p:h" は、ディレクトリ
                名そのものになる (末尾のスラッシュ無し)。
                ファイル名が絶対パス (Unix では "/"、Win32 では "x:\"、Amiga
                では "drive:" で始まる) のとき、その部分は除去されない。先頭部
                分が無いとき (パスがカレントディレクトリからの相対である)、結
                果は空になる。
        :t      ファイル名の末尾部分 (名前の最後の要素)。:r または :e より前に
                置かなければならない。
        :r      ファイル名のルート (最後の拡張子が除去される)。拡張子だけのと
                き ('.' で始まるファイル名、例: ".vimrc")、それは除去されない。
                繰り返して、いくつかの拡張子を除去できる (最後のものが先)。
        :e      ファイル名の拡張子。単独で使われたときのみ意味がある。拡張子が
                無いとき、結果は空になる。
                拡張子だけのとき ('.' で始まるファイル名)、結果は空になる。繰
                り返して、より多くの拡張子を含めることができる。十分な拡張子が
                無い場合 (ただし少なくとも 1 つはある)、可能な限り多くが含まれ
                る。
        :s?pat?sub?
                "pat" の最初の出現を "sub" で置換する。これは :s コマンドと
                同様に動作する。"pat" は正規表現である。'?' の代わりに任意の文
                字を使えるが、それは "pat" または "sub" の中に現れてはならな
                い。
                この後、前の修飾子を再び使える。例えば ":p" で、置換の後でフル
                パスにする。
        :gs?pat?sub?
                "pat" の全ての出現を "sub" で置換する。それ以外は ":s" と同様
                に動作する。
        :S      シェルコマンドで使うために特殊文字をエスケープする
                (shellescape() を参照)。最後のものでなければならない。例:
                    :!dir <cfile>:S
                    :call system('chmod +w -- ' .. expand('%:S'))

ファイル名が "src/version.c"、カレントディレクトリが "/home/mool/vim" のときの
例:
  :p                    /home/mool/vim/src/version.c
  :p:.                                 src/version.c
  :p:~                           ~/vim/src/version.c
  :h                                   src
  :p:h                  /home/mool/vim/src
  :p:h:h                /home/mool/vim
  :t                                       version.c
  :p:t                                     version.c
  :r                                   src/version
  :p:r                  /home/mool/vim/src/version
  :t:r                                     version
  :e                                               c
  :s?version?main?                     src/main.c
  :s?version?main?:p    /home/mool/vim/src/main.c
  :p:gs?/?\\?           \home\mool\vim\src\version.c

ファイル名が "src/version.c.gz" のときの例:
  :p                    /home/mool/vim/src/version.c.gz
  :e                                                 gz
  :e:e                                             c.gz
  :e:e:e                                           c.gz
  :e:e:r                                           c
  :r                                   src/version.c
  :r:e                                             c
  :r:r                                 src/version
  :r:r:r                               src/version

                                        extension-removal :_%<
"%"、"#"、"#n"、または "CTRL-V p" に "<" が追加された場合、ファイル名の拡張子
(ファイル名の最後の '.' を含めて、その後の全て) が除去される。これはバージョン
3.0 との後方互換性のために含まれており、":r" 形式が好ましい。例:

        %               カレントファイル名
        %<              拡張子無しのカレントファイル名
        #               カレントウィンドウの代替ファイル名
        #<              同上、拡張子無し
        #31             代替ファイル番号 31
        #31<            同上、拡張子無し
        <cword>         カーソルの下の単語
        <cWORD>         カーソルの下の WORD (|WORD| を参照)
        <cfile>         カーソルの下のパス名
        <cfile><        同上、拡張子無し

Note: ファイル名が期待される場所では、ワイルドカードの展開が行われる。Unix で
は、内部で行える場合を除き (速度のため)、これにシェルが使われる。
restricted-mode でない限り、以下のようにバッククォートも動作する
        :n `echo *.c`
しかし、展開は、'%'、'#' などを展開する前にワイルドカードがある場合にのみ行わ
れる。これにより、ファイル名の中のワイルドカードを展開するのを避ける。<cfile>
の結果を展開したい場合は、それにワイルドカード文字を追加する。例: (代替ファイ
ル名は "?readme?")
        コマンド        展開結果 
        :e #            :e ?readme?
        :e `ls #`       :e {"?readme?" にマッチするファイル}
        :e #.*          :e {"?readme?.*" にマッチするファイル}
        :cd <cfile>     :cd {カーソルの下のファイル名}
        :cd <cfile>*    :cd {カーソルの下のファイル名に "*" を加え、それから展開したもの}
`= も参照。

展開された引数が "!" を含み、それがシェルコマンド (":!cmd"、":r !cmd"、または
":w !cmd") に使われるとき、以前に使われたコマンドに展開されるのを避けるた
め、"!" はバックスラッシュでエスケープされる。'shell' オプションが "sh" を含む
とき、シェルが "!" を展開しようとするのを避けるため、これは 2 回行われる。

                                                        filename-backslash
ディレクトリ区切りとしてバックスラッシュを使うファイルシステム (MS-Windows) で
は、次の文字の特別な意味をエスケープするのに使われるバックスラッシュを認識する
のは少し難しい。一般的な規則は以下である: バックスラッシュの後に通常のファイル
名の文字が続く場合、それは特別な意味を持たない。従って "\file\foo" は有効なファ
イル名であり、バックスラッシュを 2 回タイプする必要はない。

例外は '$' 記号である。それはファイル名の中で有効な文字である。しかし "$home"
のようなファイル名が環境変数として解釈されるのを避けるため、その前にバックス
ラッシュを置く必要がある。従って、ルートディレクトリのファイル "$home" には
"/\$home" を使う必要がある。いくつかの例:

        ファイル名      解釈
        $home           環境変数 $home の値に展開される
        \$home          カレントディレクトリのファイル "$home"
        /\$home         ルートディレクトリのファイル "$home"
        \\$home         ファイル "\\"、その後に展開された $home が続く

`= も参照。

7. コマンドラインウィンドウ                     cmdline-window cmdwin
                                                        command-line-window
コマンドラインウィンドウでは、任意のウィンドウでテキストを編集するのと同じよう
に、コマンドラインを編集できる。それは通常の方法で抜けることができないので、特
殊な種類のウィンドウである。

:q のつもりでよく q: とタイプしてしまう場合、q をマップして、記録中のと
きは記録を終了しつつ、コマンドラインウィンドウを開く代わりにコマンドラインに
":q" を置くようにできる:

        nnoremap <expr><script> q reg_recording() != '' ? 'q' : '<SID>_qmode_'
        nnoremap <SID>_qmode_: :<C-U>q
        nnoremap <SID>_qmode_  q

Note q が長いマッピングの開始になったため、qa で記録を開始すると
'timeoutlen' を待つようになることに注意。

開く                                           c_CTRL-F q: q/ q?

コマンドラインウィンドウを開くには 2 つの方法がある:
1. コマンドラインモードから、'cedit' オプションで指定されたキーを使う。
   既定値は、'compatible' が設定されていないときは CTRL-F である。
2. ノーマルモードから、"q:"、"q/"、または "q?" コマンドを使う。
   これは Ex コマンドライン ("q:") または検索文字列 ("q/" または "q?") の編集
   を開始する。Note 記録中はこれはできないことに注意 (その場合、"q" が記録を停
   止する)。

ウィンドウが開くとき、それはコマンドライン履歴で満たされる。最後の行には、それ
までにタイプされたコマンドが含まれる。左の列には、編集されているコマンドライン
の種類を示す文字が表示される。cmdwin-char を参照。

'insertmode' が設定されている場合を除き、エディタが開かれたとき、Vim はノーマ
ルモードになる。
                                                                E1292
一度コマンドラインウィンドウが開くと、別のコマンドラインウィンドウを開くことは
できない。

ウィンドウの高さは 'cmdwinheight' で指定される (または余裕が無い場合はより小さ
くなる)。ウィンドウは常に全幅で、コマンドラインのすぐ上に配置される。


編集

これで、コマンドを使ってウィンドウ内を移動し、テキストを編集できる。ノーマル
モードおよび挿入モードの両方で。

":"、"/"、およびその他のコマンドラインを使うコマンドを使えるが、その場合、別の
コマンドラインウィンドウを開くことはできない。入れ子は無い。
                                                        E11 E1188
コマンドラインウィンドウは通常のウィンドウではない。別のウィンドウへ移動するこ
と、または別のバッファを編集することはできない。これを行う全てのコマンドは、コ
マンドラインウィンドウでは無効になっている。もちろん、コマンドラインウィンドウ
で入力した任意のコマンドを実行することは _可能_ である。その他のテキスト編集
は、ウィンドウを閉じるときに破棄される。


閉じる                                         E199

コマンドラインウィンドウを抜けるにはいくつかの方法がある:

<CR>            カーソルの下のコマンドラインを実行する。挿入モードおよびノーマ
                ルモードの両方で動作する。
CTRL-C          コマンドラインモードで続行する。カーソルの下のコマンドラインが
                コマンドラインとして使われる。挿入モードおよびノーマルモードの
                両方で動作する。再描画は無いので、ウィンドウは表示されたままに
                なる。
:quit           コマンドラインを破棄し、ノーマルモードに戻る。":close"、CTRL-W
                c、":exit"、":xit"、および CTRL-\ CTRL-N も動作する。
:qall           いずれかのバッファに変更がない限り、Vim を終了する。
:qall!          全てのバッファの変更を破棄して、Vim を終了する。

コマンドラインウィンドウが閉じられると、古いウィンドウサイズが復元される。実行
されたコマンドは、コマンドラインが開始されたウィンドウおよびバッファに適用され
る。これは、余分な画面再描画があることを除いて、コマンドラインウィンドウが無
かったかのように動作する。
コマンドラインウィンドウに使われたバッファは削除される。<CR> で実行される行以
外の行への変更は全て失われる。

カーソルの下のコマンドを実行し、その後コマンドラインウィンドウを再び開きたい場
合、このマッピングが役に立つだろう:

        :autocmd CmdwinEnter * map <buffer> <F5> <CR>q:


いろいろ

コマンドラインウィンドウは以下では使えない:
- 既にコマンドラインウィンドウがあるとき (入れ子は無い)
- 暗号化キーを入力するため、または inputsecret() を使うとき

コマンドラインウィンドウが開かれるとき、いくつかのオプションが設定される:
'filetype'      "vim"、Ex コマンドラインを編集しているとき。これは、有効になっ
                ていた場合、Vim の構文ハイライトを開始する
'rightleft'     オフ
'modifiable'    オン
'buftype'       "nofile"
'swapfile'      オフ

バッファの内容をファイルに書き込むことは許可されている。これはコマンドライン履
歴を保存し、後で読み戻す簡単な方法である。

'wildchar' オプションが <Tab> に設定されていて、コマンドラインウィンドウが Ex
コマンドに使われる場合、コマンドラインウィンドウで補完に <Tab> を使うための 2
つのマッピングが、このように追加される:
        :inoremap <buffer> <Tab> <C-X><C-V>
        :nnoremap <buffer> <Tab> a<C-X><C-V>
Note ノーマルモードで <Tab> を押すと、次の文字で補完を行うことに注意。そうする
ことで、行末で動作する。
これらのマッピングが不要な場合、以下で無効にする:
        au CmdwinEnter [:>] iunmap <Tab>
        au CmdwinEnter [:>] nunmap <Tab>
これらの行を vimrc ファイルに入れてもよい。

コマンドラインウィンドウにいる間は、マウスを使ってカーソルを別のウィンドウに置
くこと、または他のウィンドウのステータスラインをドラッグすることはできない。コ
マンドラインウィンドウ自身のステータスラインおよびその上のステータスラインはド
ラッグできる。従って、コマンドラインウィンドウのサイズは変更できるが、他のもの
は変更できない。

getcmdwintype() 関数は、cmdwin-char で説明されているように、編集されている
コマンドラインの種類を返す。


自動コマンド

2 つの自動コマンドイベントが使われる: CmdwinEnter および CmdwinLeave。
Cmdwin イベントを使って、コマンドラインウィンドウ専用の設定を行うことができる。
副作用を起こさないように注意すること!
例:
        :au CmdwinEnter :  let b:cpt_save = &cpt | set cpt=.
        :au CmdwinLeave :  let &cpt = b:cpt_save
これは i_CTRL-N で、カレントウィンドウでの補完を使うように 'complete' を設定
する。別の例:
        :au CmdwinEnter [\/\?]  startinsert
これにより、コマンドラインウィンドウで Vim が挿入モードで開始する。
Note: これは file-pattern なので、"/" および "?" はエスケープする必要がある。
cmdline-autocompletion も参照。

                                                cmdwin-char
パターンに使われる文字は、コマンドラインの種類を示す:
        :       通常の Ex コマンド
        >       デバッグモードのコマンド debug-mode
        /       前方検索文字列
        ?       後方検索文字列
        =       "= の式 expr-register
        @       input() の文字列
        -       :insert または :append のテキスト

8. コマンドラインの自動補完                      cmdline-autocompletion

自動補完は、検索 (/ または ?) またはコマンドの入力 (:) のどちらでも、タイプ中
に候補のポップアップメニューを自動的に表示することで、コマンドラインをより効率
的にし、操作しやすくする。

基本的な設定は以下である:
        autocmd CmdlineChanged [:\/\?] call wildtrigger()
        set wildmode=noselect:lastused,full
        set wildoptions=pum

この設定では、候補がすぐに表示され、<Tab> または矢印キーでそれらの間を移動でき
る。

<Up>/<Down> で通常のコマンドライン履歴のナビゲーションを維持するには:
        cnoremap <expr> <Up>   wildmenumode() ? "\<C-E>\<Up>"   : "\<Up>"
        cnoremap <expr> <Down> wildmenumode() ? "\<C-E>\<Down>" : "\<Down>"

オプションは、特定のコマンドラインに対してのみ適用することもできる。例えば、検
索中にのみ、より低いポップアップメニューの高さを使うには:
        autocmd CmdlineEnter [\/\?] set pumheight=8
        autocmd CmdlineLeave [\/\?] set pumheight&

おまけ                         fuzzy-file-picker live-grep

コマンドライン自動補完は、高度な用途のために拡張することもできる。
例えば、組み込みの :find コマンドを、ファジーで対話的なファイルピッカーに変
えることができる:

        set findfunc=Find
        let s:filescache = []
        func Find(arg, _)
          if empty(s:filescache)
            autocmd CmdlineLeave : ++once let s:filescache = []
            let s:filescache = expand('**', 1, 1)
            call filter(s:filescache, '!isdirectory(v:val)')
          endif
          return empty(a:arg) ? s:filescache : matchfuzzy(s:filescache, a:arg)
        endfunc

:Grep コマンドは、パターンにマッチする行を検索し、タイプに合わせて結果を動的
に更新する (2 文字の後に発動する。note: 次のセクションの CmdlineLeavePre 自
動コマンドが必要):

        command! -nargs=+ -complete=customlist,<SID>Grep
                \ Grep call <SID>VisitFile()

        func s:Grep(arglead, cmdline, cursorpos)
          if match(&grepprg, '\$\*') == -1 | let &grepprg ..= ' $*' | endif
          let cmd = substitute(&grepprg, '\$\*', shellescape(escape(a:arglead, '\')), '')
          return len(a:arglead) > 1 ? systemlist(cmd) : []
        endfunc

        func s:VisitFile()
          let item = getqflist(#{lines: [s:selected]}).items[0]
          let pos  = '[0,\ item.lnum,\ item.col,\ 0]'
          exe $':b +call\ setpos(".",\ {pos}) {item.bufnr}'
          call setbufvar(item.bufnr, '&buflisted', 1)
        endfunc

コマンドラインを抜けるときに補完リストの最初の項目を自動的に選択し、:Grep で
は、タイプしたパターンをコマンドライン履歴に追加する:

        autocmd CmdlineLeavePre :
              \ if get(cmdcomplete_info(), 'matches', []) != [] |
              \   let s:info = cmdcomplete_info() |
              \   if getcmdline() =~ '^\s*fin\%[d]\s' && s:info.selected == -1 |
              \     call setcmdline($'find {s:info.matches[0]}') |
              \   endif |
              \   if getcmdline() =~ '^\s*Grep\s' |
              \     let s:selected = s:info.selected != -1
              \         ? s:info.matches[s:info.selected] : s:info.matches[0] |
              \     call setcmdline(s:info.cmdline_orig) |
              \   endif |
              \ endif

挿入モードでの自動補完については、ins-autocompletion を参照。
