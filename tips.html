C プログラムを編集する                                  C-editing

Vim には C プログラムファイルの編集を助ける機能がかなりたくさんある。ここに、
ジャンプ先のタグ付きの概要を示す:

usr_29.txt            ユーザーマニュアルの「プログラムの中を移動する」の章。
usr_30.txt            ユーザーマニュアルの「プログラムの編集」の章。
C-indenting           テキストをタイプしている間、行のインデントを自動的に設
                        定する。
=                     数行を再インデントする。
format-comments       コメントを整形する。

:checkpath            再帰的にインクルードされたファイルをすべて表示する。
[i                    カーソル下の識別子を、現在のファイルとインクルードされ
                        たファイルから検索する。
[_CTRL-I              "[i" のマッチへジャンプする
[I                    カーソル下の識別子がマッチする、現在のファイルとインク
                        ルードされたファイル内のすべての行を一覧表示する。
[d                    カーソル下の define を、現在のファイルとインクルードさ
                        れたファイルから検索する。

CTRL-]                カーソル下のタグへジャンプする (例: 関数の定義)。
CTRL-T                CTRL-] コマンドの前へジャンプして戻る。
:tselect              マッチするタグのリストから 1 つのタグを選択する。

gd                    カーソル下のローカル変数の宣言へ移動する。
gD                    カーソル下のグローバル変数の宣言へ移動する。

gf                    カーソル下のファイル名へ移動する。

%                     対応する ()、{}、[]、/* */、#if、#else、#endif へ移動
                        する。
[/                    前のコメントの開始へ移動する。
]/                    次のコメントの終了へ移動する。
[#                    閉じていない #if、#ifdef、または #else へ戻る。
]#                    閉じていない #else または #endif へ進む。
[(                    閉じていない '(' へ戻る
])                    閉じていない ')' へ進む
[{                    閉じていない '{' へ戻る
]}                    閉じていない '}' へ進む

v_ab                  "[(" から "])" までの "ブロック" を、括弧を含めて選択
                        する
v_ib                  "[(" から "])" までの "内部ブロック" を選択する
v_aB                  "[{" から "]}" までの "ブロック" を、括弧を含めて選択
                        する
v_iB                  "[{" から "]}" までの "内部ブロック" を選択する

識別子が使われている場所を見つける                      ident-search

関数や変数が定義されている場所へジャンプするのに tags が使えることは、おそら
くすでに知っているだろう。しかし、関数や変数が使われているすべての場所へジャン
プできればと思うことがある。これは 2 つの方法で可能である:
1. :grep コマンドを使う。これはほとんどの Unix システムで動作するはずだが、
   遅いことがあり (すべてのファイルを読む)、1 つのディレクトリ内しか検索しな
   い。
2. ID utils を使う。これは高速で、複数のディレクトリで動作する。位置を保存する
   のにデータベースを使う。これを動作させるにはいくつかの追加のプログラムが必
   要になる。また、データベースを最新に保つ必要がある。

GNU id-tools を使う:

必要なもの:
- インストールされた GNU id-tools (ID の作成には mkid が必要で、マクロの使用に
  は lid が必要である)。
- カレントディレクトリにある "ID" という名前の識別子データベースファイル。シェ
  ルコマンド "mkid file1 file2 .." で作成できる。

これを .vimrc に入れる:
        map _u :call ID_search()<Bar>execute "/\\<" .. g:word .. "\\>"<CR>
        map _n :n<Bar>execute "/\\<" .. g:word .. "\\>"<CR>

        function! ID_search()
          let g:word = expand("<cword>")
          let x = system("lid --key=none " .. g:word)
          let x = substitute(x, "\n", " ", "g")
          execute "next " .. x
        endfun

使うには、カーソルを単語の上に置いて "_u" とタイプすると、vim はその単語を含む
ファイルを読み込む。同じファイル内で単語の次の出現を "n" で検索する。"_n" で次
のファイルへ行く。

これは id-utils-3.2 (最寄りの gnu-ftp-mirror にある id-tools のアーカイブファ
イルの名前) でテストされている。

[このアイデアの元は Andreas Kutschera である]

xterm でスクリーンを切り替える          xterm-screens xterm-save-screen

(comp.editors より、Juergen Weigert による、ある質問への返答)

:> もう 1 つの質問は、vim を終了した後、スクリーンがそのままの状態で残される、
:> つまり、閲覧 (編集) していたファイルの内容がスクリーンに残されることである。
:> "ls" のような以前の出力は失われた、つまり、もうスクロールバッファにはない。
:> vim や他の vi のようなエディタを終了した後にスクリーンを復元する方法がある
:> ことは知っているが、ただやり方が分からない。助けてもらえるとありがたい。よ
:> ろしく。
:
:これには他の誰かが答えられると思う。とはいえ、ある xterm の設定に対しては、
:vim と vi は互いに同じことをすると思う。

それらは必ずしも同じことをするわけではない。これは termcap 対 terminfo の問題
かもしれないからである。特定の種類の端末の属性を記述するデータベースが 2 つあ
ることに注意すべきである: termcap と terminfo である。これは、エントリが異な
り、かつ、問題のプログラムのうち一方が terminfo を使い、もう一方が termcap を
使う場合に違いを生じうる (+terminfo も参照)。

あなたの具体的な問題では、探しているのは制御シーケンス ^[[?47h と ^[[?47l であ
る。これらは xterm の代替スクリーンバッファとメインスクリーンバッファを切り替
える。手早い回避策としては、このようなコマンドシーケンスが
        echo -n "^[[?47h"; vim ... ; echo -n "^[[?47l"
望むことをしてくれるかもしれない。(私の表記の ^[ は ESC 文字を意味する。さらに
下では、データベースが代わりに \E を使っているのが分かるだろう)。

起動時、vim は termcap 変数 ti (terminfo: smcup) の値を端末に出力する。終了時
には te (terminfo: rmcup) を出力する。したがって、これら 2 つの変数が、上記の
制御シーケンスを置くべき正しい場所である。

xterm の termcap エントリ (/etc/termcap にある) を xterm の terminfo エントリ
("infocmp -C xterm" で取得する) と比較すること。どちらにも、これと同様のエント
リが含まれているはずである:
        :te=\E[2J\E[?47l\E8:ti=\E7\E[?47h:

PS: 何か違いが見つかったら、誰か (あなたのシステム管理者?) が termcap と
    terminfo のデータベース全体の整合性をチェックしたほうがよい。

NOTE 1: feature.h で FEAT_XTERM_SAVE を定義して Vim を再コンパイルすると、組み
込みの xterm に前述の "te" と "ti" エントリが含まれるようになる。

NOTE 2: スクリーンの切り替えを無効にしたく、termcap を変更したくない場合
は、.vimrc にこれらの行を追加できる:
        :set t_ti= t_te=

挿入モードでスクロールする                              scroll-insert

挿入モードにいて、スクリーンのすぐ外にある何かを見たい場合は、CTRL-X CTRL-E と
CTRL-X CTRL-Y を使ってスクリーンをスクロールできる。
                                                i_CTRL-X_CTRL-E

これを簡単にするために、これらのマッピングを使うことができる:
        :inoremap <C-E> <C-X><C-E>
        :inoremap <C-Y> <C-X><C-Y>
(これを文字どおりにタイプし、'<' フラグが 'cpoptions' に含まれていないことを確
認すること)。
そうすると、カーソルの上/下の行からテキストをコピーする機能が失われる
i_CTRL-E。

また、カーソルの周りの文脈が常にいくらか見えるように、'scrolloff' をより大きな
値に設定することも検討すること。'scrolloff' がウィンドウの高さの半分より大きい
場合、カーソルは常に中央にあり、カーソルが上下に移動するとテキストがスクロール
する。

単語、行などを数える                                    count-items

カレントバッファ内で任意のパターンが何回現れるかを数えるには、substitute コマ
ンドを使い、置換を避けるために 'n' フラグを付ける。報告される置換の数がアイテ
ムの数である。例:

        :%s/./&/gn              文字
        :%s/\i\+/&/gn           単語
        :%s/^//n                行
        :%s/the/&/gn            任意の場所の "the"
        :%s/\<the\>/&/gn        単語としての "the"

'hlsearch' をリセットするか、":nohlsearch" を実行するとよいだろう。
マッチがないときにエラーを出したくない場合は 'e' フラグを追加する。

代わりの方法は、ビジュアルモードで v_g_CTRL-G を使うことである。

複数のファイル内でマッチを見つけたい場合は :vimgrep を使う。

                                                        count-bytes
バイト数を数えたい場合は、これが使える:

        文字をビジュアル選択する (ブロックも可能)
        "y" を使って文字をヤンクする
        strlen() 関数を使う:
                :echo strlen(@")
改行は 1 バイトとして数えられる。

カーソル位置を復元する                                  restore-position

ファイル内のどこかを変更し、テキストをスクロールせずにカーソル位置を復元する
マッピングを書きたいことがある。例えば、ファイル内の日付マークを変更するには:

   :map <F2> msHmtgg/Last [cC]hange:\s*/e+1<CR>"_D"=strftime("%Y %b %d")<CR>p'tzt`s

位置の保存を分解すると:
        ms      カーソル位置を 's' マークに格納する
        H       ウィンドウの最初の行へ移動する
        mt      この位置を 't' マークに格納する

位置の復元を分解すると:
        't      以前ウィンドウの先頭にあった行へ移動する
        zt      スクロールしてこの行をウィンドウの先頭に移動する
        `s      カーソルの元の位置へジャンプする

より高度なものについては winsaveview() と winrestview() を参照。

ファイルをリネームする                                  rename-files

例えば、以下のファイルが入ったディレクトリがあるとする (ディレクトリは無作為に
選んだ :-):

buffer.c
charset.c
digraph.c
...

そして *.c を *.bla にリネームしたい。私はこのようにするだろう:

        $ vim
        :r !ls *.c
        :%s/\(.*\).c/mv & \1.bla
        :w !sh
        :q!

複数のファイル内の名前を変更する                        change-name

スクリプトファイルを使って、いくつかのファイル内の名前を変更する例:

        置換コマンドと :update コマンドを含むファイル "subs.vim" を作成する:
                :%s/Jones/Smith/g
                :%s/Allen/Peter/g
                :update

        変更したいすべてのファイルに対して Vim を実行し、各引数に対してスクリ
        プトを読み込む:

                vim *.let
                argdo source subs.vim

:argdo を参照。

外部コマンドを高速化する                                speed-up

状況によっては、外部コマンドの実行が非常に遅くなることがある。これは Unix での
ワイルドカード展開も遅くすることがある。ここに、速度を上げるためのいくつかの提
案を挙げる。

.cshrc (または使っているシェルによっては他のファイル) が非常に長い場合は、それ
を対話的な使用のためのセクションと、非対話的な使用 (しばしばセカンダリシェルと
呼ばれる) のためのセクションに分けるべきである。Vim から ":!ls" のようなコマン
ドを実行するとき、対話的なもの (例えば、プロンプトの設定) は必要ない。必要ない
ものは、これらの行の後に置くこと:

        if ($?prompt == 0) then
                exit 0
        endif

別の方法は、'shell' オプションに "-f" フラグを含めることである。例:

        :set shell=csh\ -f

(オプションに空白を含めるにはバックスラッシュが必要である)。
これにより、csh は .cshrc ファイルの使用を完全にスキップする。ただし、これによ
り一部のものが動作しなくなるかもしれない。

便利なマッピング                                        useful-mappings

ここに、一部の人が好んで使ういくつかのマッピングを示す。

                                                        map-backtick 
        :map ' `
シングルクォートをバッククォートのように動作させる。行の最初の非空白文字へ移動
する代わりに、マークの桁にカーソルを置く。

                                                        emacs-keys
コマンドラインでの Emacs スタイルの編集のために:
        " 行頭
        :cnoremap <C-A>         <Home>
        " 1 文字戻る
        :cnoremap <C-B>         <Left>
        " カーソル下の文字を削除
        :cnoremap <C-D>         <Del>
        " 行末
        :cnoremap <C-E>         <End>
        " 1 文字進む
        :cnoremap <C-F>         <Right>
        " より新しいコマンドラインを呼び出す
        :cnoremap <C-N>         <Down>
        " 前の (より古い) コマンドラインを呼び出す
        :cnoremap <C-P>         <Up>
        " 1 単語戻る
        :cnoremap <Esc><C-B>    <S-Left>
        " 1 単語進む
        :cnoremap <Esc><C-F>    <S-Right>

NOTE: これには '<' フラグが 'cpoptions' から除外されている必要がある。<>

                                                        format-bullet-list
このマッピングは、任意の箇条書きリストを整形する。各リスト項目の上下に空行があ
る必要がある。マッピングの各部分にコメントを付けられるように、式コマンドが使わ
れている。

        :let m =     ":map _f  :set ai<CR>"   " 'autoindent' の設定が必要
        :let m ..= "{O<Esc>"                  " 項目の上に空行を追加
        :let m ..= "}{)^W"                    " 行頭記号の後のテキストへ移動
        :let m ..= "i     <CR>     <Esc>"     " インデントのための空白を追加
        :let m ..= "gq}"                      " 行頭記号の後のテキストを整形
        :let m ..= "{dd"                      " 空行を削除
        :let m ..= "5lDJ"                     " 行頭記号の後にテキストを置く
        :execute m                            |" マッピングを定義する

(<> 表記 <>。Note これはすべて文字どおりにタイプされることに注意。^W は "^"
"W" であり、CTRL-W ではない。'<' が 'cpoptions' に含まれていなければ、これを
Vim にコピー/ペーストできる。)

Note ":execute" コマンドはコメントを直接受け付けないため、最後のコメントは |"
で始まっていることに注意。

また、'textwidth' をゼロ以外の値に設定する必要もある。例:
        :set tw=70

ほぼ同じことをするが、リストのインデントを最初の行から取るマッピング (Note: こ
のマッピングは多くの空白を含む 1 つの長い行である):
        :map _f :set ai<CR>}{a                                                          <Esc>WWmmkD`mi<CR><Esc>kkddpJgq}'mJO<Esc>j

                                                        collapse
これら 2 つのマッピングは、空 (;b) または空白のみ (;n) の行の連続を 1 行にまと
める
    :map ;b   GoZ<Esc>:g/^$/.,/./-j<CR>Gdd
    :map ;n   GoZ<Esc>:g/^[ <Tab>]*$/.,/[^ <Tab>]/-j<CR>Gdd

ヘルプファイルを圧縮する                                gzip-helpfile

ディスクスペースが本当に不足している人は、ヘルプファイルを圧縮しても、なお Vim
でそれらを閲覧できる。これにより、ヘルプファイルへのアクセスが少し遅くなり、
"gzip" プログラムが必要になる。

(1) すべてのヘルプファイルを圧縮する: "gzip doc/*.txt"。

(2) "doc/tags" を編集して ".txt" を ".txt.gz" に変更する:
        :%s=\(\t.*\.txt\)\t=\1.gz\t=

(3) この行を vimrc に追加する:
        set helpfile={dirname}/help.txt.gz

{dirname} はヘルプファイルがあるディレクトリである。gzip プラグインがファイ
ルの解凍を処理する。
他の Vim ファイルが圧縮された "doc" ディレクトリと同じ場所にない場合は、
$VIMRUNTIME が他の Vim ファイルのある場所に設定されていることを確認しなければ
ならない。$VIMRUNTIME を参照。

ウィンドウ内でシェルコマンドを実行する                  shell-window

terminal を参照。

別の解決策は、"splitvt" プログラムで端末の画面またはディスプレイウィンドウを分
割することである。おそらくどこかの ftp サーバーで見つけられるだろう。これにつ
いてよりよく知っている人は Sam Lantinga <slouken@cs.ucdavis.edu> である。

別の選択肢は、BSD Unix システムにある "window" コマンドで、複数の重なり合うウィ
ンドウをサポートしている。あるいは、www.uni-erlangen.de にある "screen" プログ
ラムで、ウィンドウのスタックをサポートしている。

16 進編集                                       hex-editing using-xxd

ユーザーマニュアルの 23.4 節を参照。

バイナリファイルに使う特定の拡張子 (exe、bin など) がある場合は、<.vimrc> 用の
以下の自動コマンドで処理を自動化すると便利かもしれない。その "*.bin" を、編集
したいと思う拡張子のコンマ区切りのリストに変更すること:

        " vim -b : xxd 形式を使ってバイナリを編集する!
        augroup Binary
          autocmd!
          autocmd BufReadPre  *.bin set binary
          autocmd BufReadPost *.bin
            \ if &binary
            \ |   execute "silent %!xxd -c 32"
            \ |   set filetype=xxd
            \ |   redraw
            \ | endif
          autocmd BufWritePre *.bin
            \ if &binary
            \ |   let s:view = winsaveview()
            \ |   execute "silent %!xxd -r -c 32"
            \ | endif
          autocmd BufWritePost *.bin
            \ if &binary
            \ |   execute "silent %!xxd -c 32"
            \ |   set nomodified
            \ |   call winrestview(s:view)
            \ |   redraw
            \ | endif
        augroup END

自動コマンドで <> 表記を使う                            autocmd-<>

<> 表記は :autocmd の引数では認識されない。特殊文字を使わなくて済むように、自
己破壊するマッピングを使って <> 表記を得て、自動コマンドからそのマッピングを呼
び出すことができる。例:

                                                map-self-destroy 
 " これはファイル名をメニューリストに自動的に追加するためのものである。
 " 自己破壊するマッピングを使う!
 " 1. バッファ内の行を使って、ファイル名の 'dots' を \. に変換する
 " 2. それをレジスタ '"' に格納する
 " 3. その名前を Buffers メニューリストに追加する
 " WARNING: これには、現在のレジスタの内容を上書きしたり、"i" コマンドの
 " マッピングをすべて削除したりといった、いくらかの副作用がある。
 "
 autocmd BufNewFile,BufReadPre * nmap i :nunmap i<CR>O<C-R>%<Esc>:.g/\./s/\./\\./g<CR>0"9y$u:menu Buffers.<C-R>9 :buffer <C-R>%<C-V><CR><CR>
 autocmd BufNewFile,BufReadPre * normal i

別の方法は、おそらくこちらのほうが良いが、":execute" コマンドを使うことである。
文字列の中では、<> 表記の前にバックスラッシュを置くことで <> 表記を使うことが
できる。既存のバックスラッシュの数を 2 倍にし、'"' の前にバックスラッシュを置
くのを忘れないこと。

  autocmd BufNewFile,BufReadPre * exe "normal O\<C-R>%\<Esc>:.g/\\./s/\\./\\\\./g\<CR>0\"9y$u:menu Buffers.\<C-R>9 :buffer \<C-R>%\<C-V>\<CR>\<CR>"

本物のバッファメニューには、ユーザー関数を使うべきである (:function を参照)。
しかし、そうすると <> 表記は使われないので、ここで例として使う意味がなくなる。

対応する括弧をハイライトする                                    match-parens

この例は、いくつかの高度なトリックの使い方を示す:
- CursorMoved 自動コマンドイベントを使う
- searchpairpos() を使って対応する括弧を見つける
- synID() を使ってカーソルが文字列内かコメント内かを検出する
- :match を使って何かをハイライトする
- pattern を使ってファイル内の特定の位置にマッチさせる。

スクリプトローカル変数を使っているので、これは Vim script ファイルに入れるべき
である。カーソルが文字列またはコメントの中で始まったのでない限り、文字列やコメ
ント内のマッチはスキップする。これには構文ハイライトが必要である。

もう少し高度なバージョンが matchparen プラグインで使われている。

        let s:paren_hl_on = 0
        function s:Highlight_Matching_Paren()
          if s:paren_hl_on
            match none
            let s:paren_hl_on = 0
          endif

          let c_lnum = line('.')
          let c_col = col('.')

          let c = getline(c_lnum)[c_col - 1]
          let plist = split(&matchpairs, ':\|,')
          let i = index(plist, c)
          if i < 0
            return
          endif
          if i % 2 == 0
            let s_flags = 'nW'
            let c2 = plist[i + 1]
          else
            let s_flags = 'nbW'
            let c2 = c
            let c = plist[i - 1]
          endif
          if c == '['
            let c = '\['
            let c2 = '\]'
          endif
          let s_skip ='synIDattr(synID(line("."), col("."), 0), "name") ' ..
                \ '=~?  "string\\|comment"'
          execute 'if' s_skip '| let s_skip = 0 | endif'

          let [m_lnum, m_col] = searchpairpos(c, '', c2, s_flags, s_skip)

          if m_lnum > 0 && m_lnum >= line('w0') && m_lnum <= line('w$')
            exe 'match Search /\(\%' .. c_lnum .. 'l\%' .. c_col ..
                  \ 'c\)\|\(\%' .. m_lnum .. 'l\%' .. m_col .. 'c\)/'
            let s:paren_hl_on = 1
          endif
        endfunction

        autocmd CursorMoved,CursorMovedI * call s:Highlight_Matching_Paren()
        autocmd InsertEnter * match none

カレントウィンドウでヘルプを開く                        package-helpcurwin

デフォルトでは、ヘルプは分割ウィンドウに表示される。状況によっては、ヘルプをカ
レントウィンドウで開きたいこともあるだろう。オプションの helpcurwin パッケージ
はこれを可能にする。パッケージを手動で、または vimrc で、以下のように読み込
む:

    packadd helpcurwin

読み込まれた後:
- コマンド :HelpCurwin {subject} を使って、カレントウィンドウでヘルプを開く
  ことができる。
- カレントウィンドウに変更されたバッファが含まれている場合、プラグインはそれを
  置き換える前に確認を求める。確認されると、バッファは隠れ状態になる
  hidden-buffer。
- ヘルプファイル helpcurwin.txt が使用可能になり、プラグインをより詳しく説明
  している。

 vim:tw=78:ts=8:noet:ft=help:norl:
