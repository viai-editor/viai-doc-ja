                           クラッシュからの復旧


コンピュータがクラッシュしましたか?  そして、何時間も編集したばかりですか?  慌
てないでください!  Vim は作業のほとんどを復元できるだけの十分な情報を保存して
います。この章では、作業を取り戻す方法を示し、スワップファイルがどのように使わ
れるかを説明します。

11.1  基本的な復旧

ほとんどの場合、どのファイルを編集していたかが分かっていれば (そしてハードディ
スクがまだ動いていれば)、ファイルを復旧するのはとても簡単です。"-r" 引数を追加
して、そのファイルで Vim を起動します:

        vim -r help.txt

Vim はスワップファイル (編集していたテキストを保存するのに使われる) を読み込
み、元のファイルの断片を読み込むかもしれません。Vim が変更を復旧したら、これら
のメッセージが表示されます (もちろん、異なるファイル名で):

        Using swap file ".help.txt.swp"
        Original file "~/vim/runtime/doc/help.txt"
        Recovery completed. You should check if everything is OK.
        (You might want to write out this file under another name
        and run diff with the original file to check for changes)
        You may want to delete the .swp file now.

安全のために、このファイルを別の名前で書き込みます:

        :write help.txt.recovered

ファイルを元のファイルと比べて、期待したとおりの結果になったかを確認します。こ
れには Vimdiff がとても便利です 08.7。例えば:

        :write help.txt.recovered
        :edit #
        :diffsp help.txt

元のファイルの方が新しいバージョンを含んでいないか (コンピュータがクラッシュす
る直前にファイルを保存した) に気を付けてください。そして、行が欠けていないか
(Vim が復旧できなかった何かがうまくいかなかった) を確認してください。
   復旧のときに Vim が警告メッセージを出したら、注意深く読んでください。ただ
し、これはまれです。

復旧の結果のテキストがファイルの内容とまったく同じ場合は、このメッセージが表示
されます:

        Using swap file ".help.txt.swp"
        Original file "~/vim/runtime/doc/help.txt"
        Recovery completed. Buffer contents equals file contents.
        You may want to delete the .swp file now.

これは通常、すでに変更を復旧した場合か、または変更をした後でファイルを書き込ん
だ場合に起きます。もうスワップファイルを削除しても安全です。

最後のいくつかの変更が復旧できないのは普通のことです。Vim は、約 4 秒間タイプ
しなかったとき、または約 200 文字タイプした後に、変更をディスクに書き出します。
これは 'updatetime' および 'updatecount' オプションで設定されます。そのため、
システムがダウンしたときに Vim が自分自身を保存する機会が無かった場合は、最後
の書き出しより後の変更は失われます。

ファイル名なしで編集していた場合は、引数として空文字列を指定します:

        vim -r ""

正しいディレクトリにいなければなりません。そうでないと、Vim はスワップファイル
を見つけられません。

11.2  スワップファイルはどこにあるか?

Vim はスワップファイルをいくつかの場所に保存できます。通常は元のファイルと同じ
ディレクトリにあります。それを見つけるには、ファイルのディレクトリに移動して、
これを使います:

        vim -r

Vim は見つけられたスワップファイルを一覧表示します。カレントディレクトリのファ
イルのためのスワップファイルが置かれているかもしれない、他のディレクトリも調べ
ます。ただし、それ以外のディレクトリにあるスワップファイルは見つけられません。
ディレクトリツリーは検索しません。
   出力は次のようになるでしょう:

        Swap files found:
           In current directory:
        1.    .main.c.swp
                  owned by: mool   dated: Tue May 29 21:00:25 2001
                 file name: ~mool/vim/vim6/src/main.c
                  modified: YES
                 user name: mool   host name: masaka.moolenaar.net
                process ID: 12525
           In directory ~/tmp:
              -- none --
           In directory /var/tmp:
              -- none --
           In directory /tmp:
              -- none --

使いたいものかもしれないスワップファイルがいくつかある場合は、それらのスワップ
ファイルのリストが表示され、使いたいものの番号を入力するよう求められます。どれ
を使いたいかを決めるために、日付を注意深く見てください。
   どれを使えばよいか分からない場合は、1 つずつ試してみて、結果のファイルが期
待したものかを確認してください。


特定のスワップファイルを使う

どのスワップファイルを使う必要があるかが分かっている場合は、スワップファイル名
を指定して復旧できます。そうすると、Vim はスワップファイルから元のファイルの名
前を見つけ出します。

例:
        vim -r .help.txt.swo

これは、スワップファイルが予想と別のディレクトリにある場合にも便利です。Vim
は、パターン "*.s[uvw][a-z]" に合うファイルをスワップファイルとして認識します。

これでもうまくいかない場合は、Vim が報告するファイル名を見て、それに合わせて
ファイル名を変更してください。Vim がどこにスワップファイルを置いたかもしれない
かを見るには、'directory' オプションを確認してください。

        Note:
        Vim は、'dir' オプションのディレクトリを検索して、"filename.sw?" に一
        致するファイルを探すことで、スワップファイルを見つけようとします。ワイ
        ルドカード展開がうまくいかない場合 (例えば、'shell' オプションが不正な
        とき)、Vim はファイル "filename.swp" を見つけようと必死の試みをします。
        それも失敗した場合は、ファイルを復旧できるようにするために、スワップ
        ファイルそのものの名前を指定しなければなりません。

11.3  クラッシュしたかどうか?                         ATTENTION E325

Vim はあなたが愚かなことをしないように守ろうとします。ファイルの内容が表示され
るのを期待して、何気なくファイルの編集を始めたとします。ところが、Vim はとても
長いメッセージを出します:

                E325: ATTENTION
        Found a swap file by the name ".main.c.swp"
                  owned by: mool   dated: Tue May 29 21:09:28 2001
                 file name: ~mool/vim/vim6/src/main.c
                  modified: no
                 user name: mool   host name: masaka.moolenaar.net
                process ID: 12559 (still running)
        While opening file "main.c"
                     dated: Tue May 29 19:46:12 2001
 
        (1) Another program may be editing the same file.
            If this is the case, be careful not to end up with two
            different instances of the same file when making changes.
            Quit, or continue with caution.
 
        (2) An edit session for this file crashed.
            If this is the case, use ":recover" or "vim -r main.c"
            to recover the changes (see ":help recovery").
            If you did this already, delete the swap file ".main.c.swp"
            to avoid this message.

このメッセージが出るのは、ファイルの編集を始めるとき、Vim がそのファイルのス
ワップファイルがすでに存在するかをチェックするからです。もし存在する場合、何か
がおかしいはずです。これらの 2 つの状況のどちらかかもしれません。

1. 別の編集セッションがこのファイルで有効になっています。メッセージの中の
   "process ID" のある行を見てください。次のようになっているかもしれません:

                process ID: 12559 (still running)

   テキスト "(still running)" は、このファイルを編集しているプロセスが同じコン
   ピュータ上で動いていることを示します。Unix 以外のシステムで作業しているとき
   は、この追加のヒントは得られません。ネットワーク越しにファイルを編集してい
   るときは、プロセスが別のコンピュータ上で動いているかもしれないので、このヒ
   ントが見えないかもしれません。これらの 2 つの場合は、状況がどうなっているか
   を自分で調べなければなりません。
      同じファイルを編集している別の Vim がある場合、編集を続けると同じファイ
   ルの 2 つのバージョンができてしまいます。最後に書き込まれた方がもう一方を上
   書きし、その結果、変更が失われます。この Vim は終了した方がよいです。

2. スワップファイルは、以前の Vim またはコンピュータのクラッシュの結果かもしれ
   ません。メッセージに書かれている日付を確認してください。スワップファイルの
   日付が編集していたファイルより新しく、かつこの行が表示されている場合:

                modified: YES

   その場合、復旧する価値のある、クラッシュした編集セッションがある可能性が非
   常に高いです。
      ファイルの日付がスワップファイルの日付より新しい場合は、クラッシュの後に
   ファイルが変更されたか (もしかすると以前に復旧したが、スワップファイルを削
   除しなかった?)、またはクラッシュの前、ただしスワップファイルの最後の書き込
   みの後にファイルが保存されたかのどちらかです (その場合は運がよいです: その
   古いスワップファイルは必要すらありません)。Vim はこの追加の行で、これについ
   て警告します:

      NEWER than swap file!


NOTE 以下の状況では、Vim はスワップファイルが役に立たないことを知っていて、自
動的に削除することに注意してください:
- ファイルが正当なスワップファイルである (マジックナンバーが正しい)。
- ファイルが変更されたことを示すフラグがセットされていない。
- プロセスが動いていない。

FileChangedShell 自動コマンドイベントを使って、この状況にプログラムで対処で
きます。


読めないスワップファイル ~

ときどき、次の行が

        [cannot be read]

スワップファイルの名前の下に表示されます。これは状況によって、よいこともあれば
悪いこともあります。

以前の編集セッションが、ファイルに何も変更をしないままクラッシュした場合はよい
ことです。その場合、スワップファイルのディレクトリリストは、それが 0 バイトで
あることを示します。それを削除して先に進んでかまいません。

スワップファイルの読み込み権限が無い場合は少し悪いことです。ファイルを読み込み
専用で見るか、または終了するとよいでしょう。マルチユーザーシステムでは、最後の
変更をあなた自身が別のログイン名で行った場合、ログアウトしてからその別の名前で
ログインすると "read error" が治るかもしれません。あるいは、誰が最後にファイル
を編集したか (または編集しているか) を調べて、その人と話をするとよいでしょう。

スワップファイルを含むディスクに物理的な読み込みエラーがあることを意味する場合
は、とても悪いことです。幸い、これはほとんど起こりません。
最初は (できる場合) ファイルを読み込み専用で見て、"忘れられた" 変更の範囲を確
認するとよいでしょう。あなたがそのファイルの担当者の場合、最後の変更をやり直す
覚悟をしてください。


どうするか?                                    swap-exists-choices

ダイアログがサポートされている場合は、6 つの選択肢から 1 つを選ぶよう求められ
ます:

  Swap file ".main.c.swp" already exists!
  [O]pen Read-Only, (E)dit anyway, (R)ecover, (Q)uit, (A)bort, (D)elete it:

O  ファイルを読み込み専用で開きます。ファイルを見たいだけで、復旧する必要がな
   い場合にこれを使います。誰か他の人がファイルを編集していることが分かってい
   て、中を見たいだけで変更はしない場合に、これを使うとよいでしょう。

E  とにかくファイルを編集します。これは注意して使ってください!  ファイルが別の
   Vim で編集されている場合、ファイルの 2 つのバージョンができてしまうかもしれ
   ません。こうなったときは Vim が警告しようとしますが、後悔するより安全な方が
   よいです。

R  スワップファイルからファイルを復旧します。スワップファイルに復旧したい変更
   が含まれていることが分かっている場合に、これを使います。

Q  終了します。これはファイルの編集を始めることを避けます。同じファイルを編集
   している別の Vim がある場合に、これを使います。
      Vim を起動したばかりの場合は、これは Vim を終了します。複数のウィンドウ
   でファイルを開いて Vim を起動したときは、最初のファイルにスワップファイルが
   ある場合にだけ Vim は終了します。編集コマンドを使っているときは、ファイルは
   読み込まれず、以前に編集していたファイルに戻ります。

A  中断します。Quit と同様ですが、それ以降のコマンドも中断します。これは、複数
   のウィンドウを持つセッションのような、いくつかのファイルを編集するスクリプ
   トを読み込んでいるときに便利です。

D  スワップファイルを削除します。それがもう必要ないことが確かな場合に、これを
   使います。例えば、それに変更が含まれていない場合、またはファイル自体がスワッ
   プファイルより新しい場合です。
      Unix では、この選択肢は、スワップファイルを作成したプロセスが動いていな
   いように見える場合にだけ提供されます。

ダイアログが出ない場合 (ダイアログをサポートしていないバージョンの Vim を実行
している場合) は、手動で行わなければなりません。ファイルを復旧するには、このコ
マンドを使います:

        :recover


Vim は、ファイルのスワップファイルがすでに存在することを常に検出できるとは限り
ません。これは、別の編集セッションがスワップファイルを別のディレクトリに置いて
いる場合、または別々のマシンで編集するときにファイルのパス名が異なる場合です。
したがって、Vim が常に警告してくれることを当てにしないでください。

このメッセージを本当に見たくない場合は、'shortmess' オプションに 'A' フラグを
追加できます。しかし、これが必要になることはとてもまれです。

暗号化およびスワップファイルについての注意は、:recover-crypt を参照してくだ
さい。
スワップファイルへのプログラムからのアクセスは、swapinfo() を参照してくださ
い。

11.4  さらに読む

swap-file     スワップファイルがどこに作成され、その名前が何になるかについて
                の説明。
:preserve     スワップファイルを手動でディスクに書き出す。
:swapname     カレントファイルのスワップファイルの名前を見る。
'updatecount'   スワップファイルがディスクに書き出されるまでのキーストロークの
                数。
'updatetime'    スワップファイルがディスクに書き出されるまでのタイムアウト。
'swapsync'      スワップファイルが書き出されるときにディスクを同期するかどう
                か。
'directory'     スワップファイルを保存するディレクトリ名のリスト。
'maxmem'        スワップファイルにテキストを書き込む前のメモリ使用量の上限。
'maxmemtot'     同じだが、すべてのファイルの合計に対して。
